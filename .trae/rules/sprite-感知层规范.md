# memora-sprite · 感知层规范

> **核心原则**：精灵知道你在做什么，不知道你在打什么。
> **决策追溯**：ADR-SP-004

## 1. 感知层级

| 层级 | 能力 | 阶段 | 示例 |
|------|------|------|------|
| L1 热键 | 用户主动召唤 | 一 | Ctrl+Shift+M |
| L2 定时 | 周期性检查触发条件 | 一 | 每分钟检查 insight/profile |
| L3 文件变化 | 监听项目文件修改 | 二 | chokidar on change |
| L4 窗口上下文 | 获取活跃窗口标题/进程名 | 二 | active-win |
| L5 日程模式 | 基于时间的主动问候 | 二 | 每日早安/工作日提醒 |

## 2. 永远禁止的感知方式

以下感知方式**在任何阶段都不允许引入**：

| 禁止方式 | 原因 |
|---------|------|
| 全局键盘钩子（iohook 等） | 本质是 keylogger |
| 屏幕截图/OCR | 视觉内容可能包含隐私 |
| 网络流量监听 | 超出本机边界 |
| 任意输入框内容读取 | 侵犯用户隐私 |

**剪贴板感知的例外（Phase 3，三重保护）**：

剪贴板感知采用三重保护方案，**不是被动监听内容**，而是用户主动触发：

1. **被动检测（不读取内容）**：只检测剪贴板"是否有变化"，不读取内容，不存储，不发送给 LLM
2. **主动触发（用户点击）**：浮窗提示"剪贴板有新内容，需要分析吗？"，用户点击后才读取
3. **敏感内容过滤**：检测到密码/Token/信用卡模式时静默忽略，不提示分析
4. **用户确认写入**：读取的内容经输入护栏检查后展示给用户确认，确认后才写入记忆

详见 [迭代规划-v0.3-to-v1.0.md](../../docs/迭代规划-v0.3-to-v1.0.md) §Phase 3.1

## 3. 唤醒触发器设计约束

### 触发器接口

```ts
interface SpriteTrigger {
  /** 触发器名称（用于日志和调试） */
  name: string;
  /** 启动触发器 */
  start(callback: () => void): void;
  /** 停止触发器 */
  stop(): void;
}
```

### 触发器实现要求

1. **只传递信号，不传递内容**：触发器回调只通知"有事发生了"，不携带用户输入内容
2. **可停止**：所有触发器必须实现 `stop()`，精灵休眠时停止所有监听
3. **降级友好**：触发器不可用时不阻断精灵运行（如 active-win 未安装则跳过 L4）

### 主动唤醒的判断逻辑

精灵主动发起对话前，必须同时满足：

1. 至少一个触发器发出信号
2. 距上次主动对话 ≥ 30 分钟（避免打扰）
3. 有实质内容可分享（insight/profile 变化，非空触发）

## 4. 上下文感知的数据边界

| 可以感知 | 不可以感知 |
|---------|----------|
| 活跃窗口的标题 | 窗口内的文字内容 |
| 活跃窗口的进程名 | 进程内的用户输入 |
| 文件是否被修改 | 文件被修改的具体内容 |
| 用户是否在线（有交互） | 用户具体在做什么操作 |
| 当前时间/日程 | 用户的浏览器历史 |

**文件内容感知的例外**：精灵通过 memora 的 work-projection 机制感知文件——Agent 读取文件时生成摘要（source:work-projection），这是用户主动触发的，不是后台监听。
