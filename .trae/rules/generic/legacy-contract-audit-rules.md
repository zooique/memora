# 带伤设计审查规则（Legacy Contract Audit）

> **适用**：Memora 全库（`src/` 内核 + `hosts/` 宿主）。**触发**：全库 SSOT 排查 / 大改前带伤审查 / 新模块反模式自检。
> **定位**：[single-truth-source-mindset.md](./single-truth-source-mindset.md) 的实证落地（把「最小单元 / 单一真理源」转成可执行的带伤识别标准）；与 [comment-doc-slimming-rules.md](./comment-doc-slimming-rules.md) 互补（前者收代码残痕，后者收注释残痕）。

## 1. 定义

> **带伤设计 = 看似符合直觉、跑起来也正常，但"从零新写时绝不会这么写"的设计。**
> 不是 bug，是历史演进的折衷——为兼容旧契约 / 旧数据 / 旧调用被迫多绕的一层。

## 2. 判别标准（命中 ≥1 即疑似）

| 标准 | 说明 | 项目实例 |
| ----------- | ---------------------------------------------------- | --------------------------------------------- |
| **同语义多实现** | 同一逻辑在 ≥2 处各自实现：一处是 SSOT、另一处是绕过它的手写，且 SSOT 明文"禁止"却被违反 | `SESSION_ID_PATTERN` 正则 vs `splitSessionId` |
| **绕一层才能接上** | 因历史包袱保留旧字段；正常设计让消费方走真源方法，带伤处却用旧契约凑合 | `meta.roundIds` 双轨 + `getRoundIds` 降级兜底 |
| **靠业务差异撑着** | ≥2 处调用对同一校验有不同失败语义（一处报错、一处兜底），统一函数不敢替换 | openSession 抛错 vs markSessionTimedOut warn 兜底 |

> **反模式自问三题**（偏离则回到正常设计）：① 从零设计会这样写吗？② 去掉"兼容旧 XX"这层，核心是否仍完整？③ 是否在 SSOT 边界之外另开手写通道？

## 3. 五类带伤模式

| 模式 | 识别信号 | 已收敛实例 |
| ----------- | --------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| **双轨镜像** | 两处存同一份状态，靠 `sync*` / `synchronize` / 双写对齐；两字段语义重叠需保持一致 | `meta.roundIds` + `roundIdsStore`（已删字段，收敛到 `getRoundIds()` 真源） |
| **降级兜底残留** | "优先 X、否则降级 Y"而 Y 永不触达；`??` 回退恒右、`\|\|` 回退恒死；**布尔式恒真**（如 `!aborted && !paused` 正常轮恒 true）导致"想干活却一步没干成"被当成功 | ViewLoader 优先真源 / 降级 `meta.roundIds`（已删降级分支） |
| **类型 hack** | `as unknown as` / `as any` / `@ts-ignore` 侥幸绕过类型约束（生产代码多处） | 多为良性（库类型缺口），如 DOMPurify 参数桥接 —— **但新写代码仍受 [project-rules.md §7.1](../project-rules.md) 零容忍禁止**，本表仅用于存量审计分类，不授权新写 |
| **重复实现** | 同语义不同名的函数 / 正则 / 常量散落；相同魔法数 / 哈希硬编码多处 | `SESSION_ID_PATTERN` vs `splitSessionId`（已收敛到 `isValidSessionId`） |
| **僵尸声明** | 宣称"能力 / 事实"却生产代码零消费：注释宣称零实现的能力、能力位恒 false 零消费、派生字段零消费者、对外宣告通道零验收。**识别关键**：该通道不可观测、不设防、失败被静默（验收位问"跑完没有"而非"干成没有"） | `provider.ts` "fallback 到纯文本 tool_call" 注释（null 实现了静默降级）→ 已纠为中实注释 |

### 3.1 僵尸声明判据的层级（堵 「导出即算活」的滥用缝）

判据落点在**内核公开导出面**，**不是**端到端消费面。

| 情形 | 判定 | 理由 |
| ------------------------------------------------------------------------- | -------- | ----------------------------------------- |
| 进入公开导出面（经 `src/index.ts` 导出的类型 + 公开读方法，如 `AgentMetrics` 与 `getMetrics()`） | **活** | 「能否被读到」在内核即可判定；宿主是否消费属**宿主生长缺口**（宿主有权不消费） |
| 未进入任何公开导出面，仅内核内部自增 / 派生 | **仍为僵尸** | 没人能读 = **假出闸**：「记了却不外露」与「没记」对宿主完全等价 |

这层区分把「代码里出现过」与「外部读得到」分开：原表述只写「零消费者」会被「我导出了」挡回；新表述要求**可被读到的落点**。

### 3.2 「多余导出面」判据（堵「未过 `index.ts` 即多余」的误报）

§3.1 问**可观测性**（数据 / 能力位能否被读到）；本条问**代码符号的可见性**（`export` 修饰符是否多余）——**两个问题不可互换，判据不可互相借用**。

| 情形 | 判定 | 理由 |
| ------------------------------ | ------------- | --------------------------------------------------------- |
| 有**模块内**消费者（含 `__tests__/` 直测） | **活，不是多余导出面** | 测试是同包消费者（同 tsconfig、走 `@/` 别名）；删 `export` 会让该判据点**无法被断言** |
| 连测试都零消费 | **死导出**，可收窄 | 无任何消费者 |

前提：包公开面已被 `package.json#exports`（仅 `"."`，**深导入不可达**）+ `src/index.ts` 白名单**双重封死** → 「未过 `index.ts`」只说明它**不在包公开面**，**不等于**它多余。

⚠️ **反向陷阱**：把「测试缝」收窄只逼出两条更差的路——① 丧失函数级判据点（覆盖质量下降）② 把内部符号塞进 `index.ts`（**真实**公开面扩大）。纯函数解析器（`resolve*` 一类）单测直打函数是**正确设计**：判据单点、失败定位精确。

**「可收窄」≠「必须收窄」**：是否**必须**修，取决于该冗余**是否会造出伤害**——不带伤约束的是「**会造成伤害的不一致**」，**不是**「消灭一切冗余」。

| 冗余性质 | 裁定 | 实例 |
| ----------------------------- | --------------------------- | -------------------------------------------------------------------------------- |
| 会误导实现决策 / 让接入者写出幽灵代码 / 造成双源漂移 | **必须修** | 零消费者的**运行时符号或能力函数**（宣称不存在的能力：`cosineSimilarity`、`isToolInCapabilities`）；注释谎报 |
| 纯 no-op：包外不可达、运行时零影响、无人可命名 | **不作修复**，记入台账「已关闭决策」**防重提** | 零消费者、且被同文件导出类型结构引用的**类型**修饰符（`AskOnTrigger` / `SkillResource` / `SkillScript` 等） |

区分要点：**符号活着 ≠ 需要 `export`**。被同文件导出类型结构引用的类型，收窄后消费者所见**完全一致**（深导入已被封死，无人能命名它）→ 收窄只是表述整洁，**不构成伤**。

### 3.3 退役概念回扫清单（7 处）

删除 / 退役任何功能后，残留表述会散落全库——回扫必须逐层覆盖，缺一层即漏网：

| # | 回扫层 | 说明 |
| - | -------------------- | ---------------------------------------------------------------------- |
| 1 | `docs/` | 含 `docs/architecture/` 活跃架构文档 |
| 2 | 代码注释 | 含注释生成的 `.d.ts`（发布面，接入者会读到） |
| 3 | 测试文件头注释 | 每轮实证的惯常漏网点（如 TRACE_SPANS 数量、退役符号点名） |
| 4 | README 中英双版 | 双语需各扫一遍 |
| 5 | `package.json#files` | 发布白名单：已删文件是否仍在清单 |
| 6 | `.trae/rules/` | alwaysApply 规则每轮注入 Agent 上下文，最易被忽略 |
| 7 | `.trae/decisions/` | **ADR 层是盲区**（实证：ADR-008 / ADR-VC-001 残留 embedding / recall 表述，非清单触发发现） |
| 8 | `tasks/` 台账 | **验收标准的落点**（2026-09-28 实证新增）：台账会写「销项前须复验 X 形态」，形态回滚后若不同步 ⇒ 照单验收会把**正确实现判成不合格**，比 docs 失真更致命。关键词同第 1 层 |

**ADR 层纪律**：ADR 属历史留档——**不重写正文**（改写即篡改决策历史），只在头部加退役注记指向后继 ADR / 删除提交。

**第 8 层（`tasks/`）的观测依据与退出条件**（新增判据，按 §7 带观测 + 退出条件方可动）：
- **观测（2026-09-28 实证）**：台账 DIFF-1 的销项验收标准写「对照页是否**单列上下排列**」，而该形态已于同日回滚为 `vscode.diff` 左右分栏 ⇒ 照单验收会把刚通过真机的实现判为不合格；同批 DIFF-6 行仍描述已删的 `formatUnifiedDiff`。前 7 层全扫过都未覆盖此处。
- **退出条件**：若 `tasks/` 台账不再承载验收标准（改由 CI 或别处承载），本层即失效，可删。
- **边界**：本层只扫「**验收标准 / 现状断言**」类表述，历史过程记录（某轮做过什么）不动——与 ADR 层同理。

## 4. 实证判定流程（先读码，再定类）

**不是所有"怪"都是带伤**——审查须读码确认「真带伤 vs 良性 vs 已收敛」，不能只看表象：

| 判定 | 判断依据 | 处置 |
| ------- | -------------------------------------------------------- | --------- |
| **真带伤** | 上述 5 类模式 + ≥1 处历史折衷证据（SSOT 明文禁止却被绕过 / 兼容旧契约字段 / 靠业务差异撑着） | 走收敛流程（§5） |
| **良性** | 有明确设计意图注释（如库类型缺口桥接）、有单一真源且全库无重复、有独立测试 | 不处理，记录判定 |
| **已收敛** | SSOT 清理已覆盖（镜像已删、降级已删、导出已收回） | 跳过，避免重复劳动 |

## 5. 收敛流程（改造约束）

1. **每可疑点先 grep / 读码实证**，定类后再动刀
2. **优先在最小单元（SSOT 源）收敛**，不破坏原契约边界（如 `splitSessionId` 纯拆解语义保持，另加 `isValidSessionId` 作校验互补）
3. **保留两处失败语义**：带伤点若有"报错 / 兜底"两种结局，收敛后须逐一保留（openSession 抛错的 + markSessionTimedOut 兜底的）
4. **验证**：内核 + 宿主 `tsc` + 全量 `vitest` 全绿
5. **炼化归元**：规则对齐（命名 / 注释 / SSOT 声明一致）→ 剪枝（无"不是 XX 而是 XX"、无修复思路旁白、无修改痕迹）→ 提交前审查
6. 用 `refactor:` 提交，经 pre-commit（lint-staged + typecheck + commitlint）后推送

## 6. 已收敛残留清单（避免重复审查）

新审查直接跳过。**按「模式级」记录**：同时登记「已收敛的模式」与其「复发识别信号」，信号再现（即使字段名不同）即按同一模式收敛，不另起炉灶。

## 7. 待验证带伤候选与预警信号（探索期登记，未固化）

> 与 §6 不同：这里是**尚未定类 / 尚未复现、仅登记待查**的候选与可观测预警信号。
> **原则：先记录，再动手；动得起，也收得回。**
> 探索期**不设「不动内核」的禁区**——根因未明不等于不能试，试本身就是探索手段。把「不动」当纪律只会让候选长期悬空、且规则字面被反复绕过（实例：为补 ADR-031 漏记，某次动了内核 22 行而判据零分叉——字面违规、意图合规，说明旧表述管不住真实行为）。真正要守的是三条，**缺一即降级为带伤**：
> ① **可追溯**——每一动对应本节已登记的候选或已复现的真机现象，不拍脑袋；
> ② **可观测**——改动带可量化计数 / 留痕，能判断它「有效」还是「过度」（没观测的改动 = 盲人打靶）；
> ③ **可退出**——写明真机定类后是收敛、降级回 docs/ 还是回退，**不留悬空特判**。
>
> **判别（与 §5 互补）**：**改「判据」＝造伤的高风险动作；改「喂给判据的事实」＝止血。** 后者随时可做；前者探索期也允许，但必须带 ②③。反例（真带伤）：往判据塞 `if (某场景) return true` 式场景特化——不可退出，会在下一场景变新折衷。

### 7.1 复查节律（给 §7 装「消费机制」）

> §7 曾**有登记、无消费**——候选登记完即悬空，没有任何机制推向结案。这正是 §3「僵尸声明」在**规则层**的复现：**登记了却不被任何流程消费 = 假登记**。本小节回答「谁在什么时候、按什么条件、把它推到哪去」。

| 项 | 约定 |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **登记日期** | 必填，精确到日。真机现象取**首观测日**，其余取登记日。缺登记日期**不得登记** |
| **复查触发** | 必填，满足任一即复查：① **到期**（默认 = 登记日期 + 60 天）② **事件**（信号再现 / 依赖项变动 / 版本切档）。纯远期方向可写「事件驱动」，须注明不参与到期 |
| **复查动作** | 四选一并写结论、更新本行：**复现 / 收敛 / 降级回 docs / 回退**。样本不足无法定类时取「**降级回 docs**」并注明缺口，**不得停留原状** |
| **挂载节律** | 随**发版前 Go/No-Go 检查清单**执行：发布前逐行核对触发条件，**到期行强制结案**。<br />**结论落点 = 本表末列「上次核对」**（写「核对日期 + 维持 / 复现 / 收敛 / 降级 / 回退 + 依据」），历史报告不重写。<br />**优先级**：核对与结案是两件事——**核对恒为强制**（与到期无关），**结案只在到期或事件触发后强制**；「版本切档」是否含发版本身处解释边界，故未触发时写「维持登记 + 已核对」，仍满足「不得停留原状」 |
| **不得** | 不得只更新日期而不写结论（= 续命，即 §3 的假出闸）；不得把「未复现」当结案理由（未复现只支持「降级回 docs」） |
