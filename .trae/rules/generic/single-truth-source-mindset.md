# 单一真理源思维模型

> 遇到复杂问题，先回到最小单元。**能在最小单元层面解决，就不引入新机制。** 完整推导见 `docs/architecture/agent-design-philosophy.md`。

## 核心公理

**最小单元 = 一次输入 → 一次执行 → 一次交接判断**：自足、可重复、可观察。它是系统的「细胞」；复杂结构是它的组合与重复，不是另造更大的细胞。

**SSOT 不是「只有一个文件/模块」，而是「只有一个设计原点」**：一套最小单元承载全部复杂行为；同套逻辑多场景复用、不做场景特化；复杂度向外生长、核心保持简单。

## 活跃设计口径（审计 / 剪枝四层，缺一即未收口）

1. `src/`（代码真理源）
2. `.trae/rules/`（alwaysApply 规则，每轮注入，最易被忽略）
3. `.trae/documents/`（过程方案文档；🔴 **术语定义不在此处**——唯一定义处 = `terminology-anchor-rules.md`）
4. `docs/architecture/`（活跃架构文档）

## 关键推导

- **turn 的重复 = 闭环的重复，非独立引擎**：每次续跑都是完整 turn，无需第二套引擎。
- **召回由触发源决定**：仅外部输入触发 → `recall()`。（旧 Handoff 自动续跑已废，无「Loop 模式跳过召回」开关）
- **摘要 + 归档 = turn 后处理**：Reflect 阶段天然承载；无独立定时任务。

## 解题步骤

遇复杂问题：① 找最小单元 → ② 定位问题在单元内 / 间 → ③ 能否在单元内加参数或策略解决 → ④ 能则在单元层解决（最小改动、最大复用）→ ⑤ 否则单元间经接口协作，不引入新单元。

**补丁思维信号**：「这个场景需要特殊处理」/「再加个模块/引擎/系统」/「先加个 flag 控制一下」。

**自问三题**（偏离则回到最小单元）：① 该逻辑是否只在某场景生效？② 去掉特殊处理核心是否仍完整？③ 是否需在最小单元外引入新机制？任一「是」即可能偏离。

**补充判断**：**逻辑下沉**——多模块复用须下沉到单一真理源，不硬编码到调用方；**预留键 vs 僵尸键**——schema 未消费字段须区分「预留」（设计空间，不承诺）与「僵尸」（技术债，应清理）。

## 设计陷阱

- **循环依赖**（A ↔ B）：插入一个确定性步骤（如关键词精确匹配），让一个方向变确定性，打破死锁。
- **隐式切换**：重配置对象只被显式调用。**角色包只能手动切换**（v0.13 定案，唯一入口）。
- **措辞折叠（2026-10-03 实锤，本仓血训级）**：文档里写「A 与 B **共用**裁决链 / **统一**判据 / **一致**处理」时，
  必须先回核**实现的调用点分布**——一个词往往同时指向**两个不同层面**，折叠后读者会以为覆盖面比实际更大。
  实锤样本：方案文档写「run_command 与脚本工具共用裁决链」，实际只有 `confirmCommandRun` 调了 `classifyCommand`，
  而 `confirmScriptRun` 只判权限档位、**不看执行内容**——「确认通道共用」为真、「命令内容裁决共用」为假。
  **纪律**：① 断言「共用/统一」前 grep 该判据的**全部调用点**，逐个核对入参形态；
  ② 若只有部分调用点接入，文档必须**分两层写**（哪一层共用 / 哪一层不共用）并给出未覆盖面的**风险登记**；
  ③ 措辞禁止把两个层面折叠为一个词——折叠即等于对读者撒谎，且**没有任何测试会红**（读者信了，测试不会拦）。
  同源推论：**定长/上限类真源必须放在所有消费面的下游**，放在任一消费方的私有常量里 ⇒ 第二个消费面天然漏配且无测试报警。
- **不变式措辞外溢（2026-10-03 第二发实锤）**：措辞折叠订正一次，同文档里**同型的全称词**往往还在。
  样本：订正了「共用裁决链」，却留下「deny 在任何档位 × 任何权限模式下**恒拦**」——
  实际作用域只有 `run_command` 的**命令字面量**（`classifyCommand` 唯一调用点是 `confirmCommandRun`，
  唯一消费面是 `run_command` 分支）；`run_code` / `run_project_script` / `run_skill_script` 走 `confirmScriptRun`，
  只判权限档位、**不看执行内容**——而 `run_code` 连「脚本内容」都不是（内联代码，一次调用即可到达任意 Node 能力）。
  **三条纪律**：
  ① **不变式的措辞宽度必须与其最大作用域齐宽**——全称句（恒拦 / 不可绕过 / 全部）后面挂⚠️脚注不算改对，主句就得是限定句；
  ② **订正措辞前先全库 grep 该措辞的全部出现**（docs + 代码注释 + 测试名 + 工具描述 + 设置文案 + 协议注释），**一次改齐**，不接受「先订正查到的那处」——那是同一刀的第二次复发；
  ③ **登记未覆盖面时必须穷举同类面**（「脚本工具执行文件内容」漏了 run_code 这个既非文件也不同质的最短旁路）；
      并把**风险等级建立在最小可执行路径**上（实测：绕过 deny 的真实成本 = **一次工具调用**，不是「写→执行→删三步」——
      路径闸只判「是否在项目根内」，项目根内**已有**文件即可执行，零写文件）。
  ④ 复核「刻意不修」的边界时，先问：**这个判据挡的是什么层？** deny 是**字符串形态判据**，
      只挡得住「直白写出的危险命令」；经间接载体（文件内容 / 内联代码 / 变量展开 / 编码）表达的同一意图结构性穿过去
      ⇒ 它该重新定位为「命令字面量护栏」，语义防护交给**用户审批 + 审计溯源**，别再当「危险执行总闸」。
- **谎报位点复发（2026-10-03 第三发实锤，本仓最贵的一类伤）**：**「消灭谎报」是一类，不是一处。**
  同一会话里 CMD-1 刚消灭「`run_code` 描述声称支持 python 而宿主只支持 JS」的假话，
  CMD-2 转头就在**同一个 prompt 注入位置**造了「shell 是什么」的假话
  （宿主报 `PowerShell`，内核 `resolveShellCommand` 实际派发 `cmd /c`，工具描述亦自认 `cmd /c` ⇒ 三方矛盾）。
  **该字段唯一用途就是「供模型避坑」，模型按 PowerShell 语法写命令却由 cmd 执行 = 每次必败。**
  **纪律**：
  ① **审查谎报要按「谎报位点」扫全，不是按「已修的那条」验收**——同一位点（模型可见的事实面）修一处、
     另一处仍谎，是这类伤的典型形态；
  ② **新增 prompt 注入段必做「三方对照」**：段内每个字段 ↔ **内核实际执行路径** ↔ 工具描述文案。
     三者任一不一致 = 假事实（本刀 shell 字段正是三方全不一致）；
  ③ **推广判据**：凡「宿主上报给模型看」的事实，其值必须与**内核实际执行路径同源**——
      上报的是「**执行器用什么**」，不是「**用户环境里有什么**」。
      实例：报「集成终端默认 shell / 登录 `$SHELL`」是谎（内核恒定映射 `cmd` / `sh -c`，不读环境变量），
      报「本会话命令执行器实际派发的 shell」才是事实。**推导链一律如此，不止于 shell 一项**。
- **台账销项的括号折叠（2026-10-03 第三发实锤，纪律自己被违反）**：把**未做项**与**已做项**写进**同一对括号**
  （如「② 后台任务列表（收尾报告上屏 ✅ 已落地）」）——读起来像 ② 已完成，实际「列表」完全未做
  （实锤：宿主对注册表零消费面）。**这是本日新立「措辞折叠」纪律的同型复发，折叠形态从
  「共用裁决链」变成了「剩余项②括号里已落地」。**
  **纪律**：① **未做项与已做项必须各自独立成行**，禁止「未做项名（已做项 ✅）」这种写法；
  ② 台账写「剩余」段落时，**先问「这条 ⬜ 的名字与括号里 ✅ 的是不是同一件事」**——不是就拆开；
  ③ 这类伤**没有任何测试会红**（读者信了，测试不会拦），只能靠写台账时的固定检查动作拦住
     ⇒ 纪律必须落成动作，不能只落成文字。
- **描述性计数 = 时点快照（2026-10-06 实锤，「措辞折叠」同族第四发）**：文档里写死的**数量 / 规模数字**
  （「N 个 ADR」「当前零在册条目」「目录共 N 篇」）**在写下的那一刻就开始过期**，且**没有任何测试会红**——
  与「括号折叠」同型：读者信了，测试不拦。
  **本仓实证**：ADR 计数**四次漂移**（37 → 25 → 26 → 30），而每一次写的人都是「刚实测过」的
  ⇒ **实测数字仍然是快照，用新数字替换旧数字只是把快照刷新一轮，机制未变**。
  **两条纪律（按计数的作用分野，勿一刀切）**：
  ① **无判据作用的描述性计数 → 一律不落账**，改为指向真源的**指针写法**
     （「见 `X/README.md` 索引」/「以各条目自身的 `｜状态` 段为准」）。
     已订正的反例：`project-rules.md` §6「决策记录（26 ADR）」、README 中英「26 个 ADR」、
     台账 `Unreleased` 区头「当前零在册条目」（与同区实际内容矛盾 ⇒ 把未销项条目整体隐掉）。
  ② **有判据作用的计数（阈值 / 容量 / 规模闸）→ 必须写，但须带「时点 + 重算指引」三件套**
     范式见 `project-rules.md` §7.6 IPC 通道条（「当前 107 条，2026-10-04 实测……⚠️ 该计数每次增删
     通道即过期，引用前须按守卫同源判据重算」）——**数字 + 何时测的 + 怎么重算**，缺一即裸快照。
  **自检动作（落成动作）**：写下任何数字前先问「这个数字是**判据**还是**描述**？」——
  描述即删（改指针），判据即补三件套。
