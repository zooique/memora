# 单一真理源思维模型

> 遇到复杂问题，先回到最小单元。**能在最小单元层面解决，就不引入新机制。** 完整推导见 `docs/architecture/agent-design-philosophy.md`。

## 核心公理

**最小单元 = 一次输入 → 一次执行 → 一次交接判断**：自足、可重复、可观察。它是系统的「细胞」；复杂结构是它的组合与重复，不是另造更大的细胞。

**SSOT 不是「只有一个文件/模块」，而是「只有一个设计原点」**：一套最小单元承载全部复杂行为；同套逻辑多场景复用、不做场景特化；复杂度向外生长、核心保持简单。

## 活跃设计口径（审计 / 剪枝四层，缺一即未收口）

1. `src/`（代码真理源）
2. `.trae/rules/`（alwaysApply 规则，每轮注入，最易被忽略）
3. `.trae/documents/`（过程方案文档；🔴 **术语定义不在此处**——唯一定义处 = `terminology-anchor-rules.md`）
4. `docs/architecture/`（活跃架构文档）

## 关键推导

- **turn 的重复 = 闭环的重复，非独立引擎**：每次续跑都是完整 turn，无需第二套引擎。
- **召回由触发源决定**：仅外部输入触发 → `recall()`。（旧 Handoff 自动续跑已废，无「Loop 模式跳过召回」开关）
- **摘要 + 归档 = turn 后处理**：Reflect 阶段天然承载；无独立定时任务。

## 解题步骤

遇复杂问题：① 找最小单元 → ② 定位问题在单元内 / 间 → ③ 能否在单元内加参数或策略解决 → ④ 能则在单元层解决（最小改动、最大复用）→ ⑤ 否则单元间经接口协作，不引入新单元。

**补丁思维信号**：「这个场景需要特殊处理」/「再加个模块/引擎/系统」/「先加个 flag 控制一下」。

**自问三题**（偏离则回到最小单元）：① 该逻辑是否只在某场景生效？② 去掉特殊处理核心是否仍完整？③ 是否需在最小单元外引入新机制？任一「是」即可能偏离。

**补充判断**：**逻辑下沉**——多模块复用须下沉到单一真理源，不硬编码到调用方；**预留键 vs 僵尸键**——schema 未消费字段须区分「预留」（设计空间，不承诺）与「僵尸」（技术债，应清理）。

## 设计陷阱

- **循环依赖**（A ↔ B）：插入一个确定性步骤（如关键词精确匹配），让一个方向变确定性，打破死锁。
- **隐式切换**：重配置对象只被显式调用。**角色包只能手动切换**（v0.13 定案，唯一入口）。
- **措辞折叠（2026-10-03 实锤，本仓血训级）**：文档里写「A 与 B **共用**裁决链 / **统一**判据 / **一致**处理」时，
  必须先回核**实现的调用点分布**——一个词往往同时指向**两个不同层面**，折叠后读者会以为覆盖面比实际更大。
  实锤样本：方案文档写「run_command 与脚本工具共用裁决链」，实际只有 `confirmCommandRun` 调了 `classifyCommand`，
  而 `confirmScriptRun` 只判权限档位、**不看执行内容**——「确认通道共用」为真、「命令内容裁决共用」为假。
  **纪律**：① 断言「共用/统一」前 grep 该判据的**全部调用点**，逐个核对入参形态；
  ② 若只有部分调用点接入，文档必须**分两层写**（哪一层共用 / 哪一层不共用）并给出未覆盖面的**风险登记**；
  ③ 措辞禁止把两个层面折叠为一个词——折叠即等于对读者撒谎，且**没有任何测试会红**（读者信了，测试不会拦）。
  同源推论：**定长/上限类真源必须放在所有消费面的下游**，放在任一消费方的私有常量里 ⇒ 第二个消费面天然漏配且无测试报警。
