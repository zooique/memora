# 通用编码约束规则

> **适用**：Memora 内核（`src/`）+ 插件宿主全部 TS/JS 代码。
> **与现有规则关系**：与 [backend_layers_rules.md §分层职责](../backend_layers_rules.md) 互补（前者定边界，本文件定写法）；与 [security_rules.md](./security_rules.md) 正交（前者管权限，本文件管健壮性）。

## 1. 契约与入参校验

> **核心原则**：校验只在入口做一次，内部信任契约。

| 类型 | 规则 |
| ---- | ---- |
| DO | 仅在函数入口做完整参数校验，函数内部不再重复判空、判类型 |
| DO | 优先用类型、接口、泛型约束合法入参，类型无法覆盖的边界再做运行时校验 |
| DO | 通用校验逻辑（空值、ID 格式、数值范围、必填字段）统一抽公共工具函数 |
| DO | 可选参数、可选对象字段用 `??` 兜底展示值 |
| DON'T | 非法参数静默返回默认值——抛带明确提示的业务异常，阻断非法流程 |
| DON'T | 用 `??` 篡改核心业务标识类字段（主键、状态码、来源标记） |
| DON'T | 复制粘贴 `if` 判断——相同校验出现 2 次即抽工具函数 |

**Memora 适配**：`src/utils/` 集中存放纯函数工具；记忆模型 `source` 属核心标识，禁止兜底覆盖（[ADR-004](../../decisions/ADR-004-memory-unification.md)）。

**DOM 元素校验决策标准**：
- `instanceof` + `console.error`：`getElementById()` 取的静态元素（缺失即 bug，需留日志）
- `!` 断言：已确认存在的容器内的子元素（如 `dialog` 已确认，则其子元素必定存在）
- `instanceof` 前置判断：`closest()` / `previousElementSibling` 等动态遍历（元素可能不存在）

## 2. 异常处理

> **核心原则**：区分业务异常与系统异常，不吞异常。

| 类型 | 规则 |
| ---- | ---- |
| DO | 两类异常分开：业务预期异常（参数错、数据不存在）、底层系统 IO 异常（DB / 文件 / 网络 / 子进程） |
| DO | `try/catch` 仅包裹纯 IO 操作，不整函数包裹 |
| DO | 捕获底层异常后补上下文日志，包装成业务异常向上抛 |
| DO | 用统一的 `MemoraError` 体系（错误码 + 上下文），不用裸 `Error` |
| DON'T | 吞异常返回空对象 / 空数组——问题必须显性抛出 |
| DON'T | 嵌套多层 `try/catch`——单一异常来源只配一层捕获 |

**Memora 适配**：内核 `MemoraError` 统一错误体系（零裸 `Error`，见 [project-rules.md §7.1](../project-rules.md)）；AgentLoop 的 LLM 指数退避重试是此规则的典型应用。

## 3. 代码简洁与复用

> **核心原则**：一个函数只做一件事。**通用 / 领域原语逻辑在首次实现时即抽取为公共方法**（ADR-017 Scenario A：代码库即协调媒介，已存在的公共原语会被自然复用，缺失则 AI 就地复制）。纯臆测复用（"以后可能用到"）不抽；2+ 处重复作为"该抽却漏抽"的回溯信号，非唯一触发条件。
> **AI 编程范式补充**：首次实现新功能时判断该逻辑是否具**领域原语特征**（三项同时满足），是则设计期直接抽取，不等 2+ 处：
> - **领域动词测试**：能否用一个领域动词命名（归档 / 去重 / 召回 / 匹配）？能 → 天然是领域基本操作单元
> - **接口稳定性测试**：输入输出是否明确稳定？接口仍在探索（"输入多种格式、输出看情况"）→ 暂缓
> - **独立语义测试**：是否有独立领域语义，而非"凑巧相同的几行代码"？
>
> 范例：✅ `deduplicateMemories()`、`assembleContext()`（三项全√）；❌ 两模块偶遇相同的 `if (a > b)` 交换（凑巧相似，等 2+ 处）；❌ 输入输出每周变的处理流程（接口不稳，过早抽象增加修改成本）。

| 类型 | 规则 |
| ---- | ---- |
| DO | 单一职责：校验、查询、格式化、存储拆独立方法 |
| DO | 消除重复分支，相同判断、转换、兜底统一抽工具 |
| DO | 控制 `if` / `for` 嵌套不超过 3 层，深层分支提前 `return` 扁平化 |
| DO | 常量、枚举、错误码统一存放公共文件 |
| DO | **抽象基类方法提供默认空实现**：非所有子类都需实现的方法（如 `createEntry`）返回 `null` 默认实现，不强制覆写或抛错（防呆设计） |
| DON'T | 无差别全量防御——契约约定合法入参后，内部不再冗余校验 |
| DON'T | 魔法数字、魔法字符串散落业务代码 |
| DON'T | 用 `export { x } from '...'` 透传导出后又在模块内使用 `x`——透传不创建模块作用域绑定，会抛 `ReferenceError`。正解：先 `import { x } from '...'` 再 `export { x }` |
| DON'T | 复制粘贴 `if` 判断——相同校验出现 2 次即抽工具函数（对齐 ADR-017 Scenario A） |

**Memora 适配**：禁止 `@ts-ignore` / `as any`（[project-rules.md §7.1](../project-rules.md)）；常量全大写下划线（`BLOCKED_PATTERNS`、`CHAT_LOCK_TIMEOUT_MS`）。

## 4. 日志与可观测

> **核心原则**：废弃原生 `console`，统一分级日志。

| 类型 | 规则 |
| ---- | ---- |
| DO | 用统一 `ILogger` 接口（`info` / `warn` / `error` / `debug`），不直接 `console.log` |
| DO | 正常流程 `info`，可预期边界 `warn`，崩溃 / IO 故障 `error` |
| DO | 异常日志带关键上下文：入参、操作 ID、错误堆栈 |
| DO | 开发环境打印完整详情，线上精简脱敏 |
| DON'T | 打印完整数据库实体、API Key、用户隐私内容 |
| DON'T | 用 `info` 记异常——异常必须 `error` |

**Memora 适配**：内核 `src/logging/` 提供 `ILogger` + console fallback；可观测性经 `ITracer` / `ISpan` 埋点。

## 5. 数据与存储

> **核心原则**：DAO 层隔离 SQL，业务层不裸写数据库操作。`better-sqlite3` 由宿主注入，内核零 native 依赖（[ADR-002](../../decisions/ADR-002-storage-layer.md)）。

| 类型 | 规则 |
| ---- | ---- |
| DO | DB 操作统一封装 DAO 层，业务层经 `IMemoryStorage` 接口访问 |
| DO | SQL 全部参数预编译，禁止字符串拼接 |
| DO | 查询无数据属业务边界，主动抛"数据不存在"异常（视场景也可返回空数组） |
| DO | 大批量数据分页 / 流式读取 |
| DO | 数据库模型单独定义 TS 类型，隔离存储结构与业务返回结构 |
| DON'T | 业务层裸写 SQL 或直接操作数据库实例 |
| DON'T | 在 SQLite 中存原始工作内容（仅存投影 / 摘要，[project-rules.md §7.3](../project-rules.md)） |
| DON'T | 一次性全量加载大数据集 |

**Memora 适配**：`memora.db` 是 Agent 级共享资源，不随子项目切换重建；配置文件是真理源，SQLite 是运行时索引（[project-rules.md §1](../project-rules.md)）。

## 6. 函数与变量规范

> **核心原则**：小函数、语义命名、按需定义。

| 类型 | 规则 |
| ---- | ---- |
| DO | 函数参数 ≤ 4 个，多参数改用对象入参 |
| DO | 单函数 ≤ 60 行，超长直接拆分 |
| DO | 变量语义化命名，布尔值统一 `is` / `has` / `should` 前缀 |
| DO | 优先用解构、可选链（`?.`）简化判空 |
| DON'T | 简写、无意义命名（`a` / `b` / `tmp` / `data2` / `data` / `info`）——`data` / `info` 零语义，应换为领域名词（`memories` / `snapshot` / `config`） |
| DON'T | 提前声明大量无用兜底变量——临时中间变量按需定义 |
| DON'T | 堆砌多层 `if` 替代可选链 |

**Memora 适配**：命名规范见 [project-rules.md §4](../project-rules.md)。CSS 作用域与命名**权威定义**在 [ADR-018](../../decisions/ADR-018-css-scoping-convention.md)，本文件不重复。

## 7. 分支与兜底取舍

> **核心原则**：能提前 `return` 就不写 `else`，兜底不掩盖问题。

| 类型 | 规则 |
| ---- | ---- |
| DO | 能提前 `return` 就不写 `else` |
| DO | 仅展示层、UI 渲染字段允许默认兜底 |
| DO | 逻辑上 100% 不可能出现的边界，不加冗余判断 |
| DON'T | 核心业务主键、状态用兜底默认值覆盖——问题显性抛出 |
| DON'T | 滥用兜底默认值掩盖参数错误、数据缺失 |

**Memora 适配**：`archiveMode` 二态（full / manual）属核心状态，禁止兜底为 `full`（[ADR-015](../../decisions/ADR-015-archive-mode.md)）。

## 8. 工程分层

> **核心原则**：下层不可感知上层，禁止跨层调用。**详细分层职责**见 [backend_layers_rules.md §分层职责](../backend_layers_rules.md)。

| 类型 | 规则 |
| ---- | ---- |
| DO | 分层隔离：工具层（`utils/`）→ 数据 DAO 层（`memory/`）→ Service 业务层（`agent/`）→ 界面 / 主进程控制器（宿主） |
| DO | 每层出入参用独立类型，不透传数据库原始实体 |
| DO | 通用能力（校验、日志、错误、文件工具）统一抽全局公共模块 |
| DON'T | 下层感知上层——禁止跨层直接调用 |
| DON'T | 业务代码重复实现通用能力 |

## 9. 稳定性隐性约束

> **核心原则**：IO 必须有超时，异步必须处理异常。

| 类型 | 规则 |
| ---- | ---- |
| DO | 文件、数据库操作加超时控制，禁止无限阻塞 |
| DO | 外部依赖、本地文件读写加最小范围异常捕获 |
| DO | 异步统一 `async` / `await`，所有 `Promise` 处理异常或向上抛 |
| DON'T | 裸 `Promise` 不处理 `catch` |
| DON'T | 异步操作忽略返回值 |
| DON'T | `await` 后不捕获异常（除非确定上层有统一兜底） |

**Memora 适配**：`chat()` 并发锁超时（`CHAT_LOCK_TIMEOUT_MS = 180_000`）与 AgentLoop 指数退避重试是典型应用。

## 10. 源码文本卫生

> **核心原则**：源码是**纯文本**——需要控制字符时写**转义**，不得嵌入裸控制字节。

| 类型 | 规则 |
| ---- | ---- |
| DO | 控制字符一律写转义（`'\u0000'`，运行期仍是同一字符） |
| DO | 提交前扫一遍**已跟踪文件**的裸控制字节（`git ls-files -z` 逐个读字节统计 `0x00`） |
| DON'T | 在源码 / 配置 / 文档里直接嵌入裸 `0x00`、`0x1B` 等控制字节 |

**为什么单列（工具链整体失明）**：裸 `0x00` 会让 git / ripgrep 把文件判为**二进制**——
`git diff` 只显示 `Bin`（看不到改了什么）、`grep` 只回 `binary file matches`（搜不到行）；
而 `tsc` / 单测 / 各门禁**全部通过**（它们不读字节）。**四层验证全绿，坑仍在地里。**

**Memora 适配**：块指纹分隔符需用 NUL 时**必须写转义**——`'\u0000'` 与裸字节在**运行期等价**
（hash 与断言结果不变），但前者保持源码纯文本。注意 git 的二进制判定看**索引与工作区两侧**：
改完须**重新 `git add`**，否则 diff 仍显示 `Bin`。
