# 测试规范

> 详见 [ADR-007 · 测试策略](../../decisions/ADR-007-testing-strategy.md)

## 1. 三层金字塔

| 层级 | 目标占比 | 范围 | 速度 |
| -------- | -------- | ------------ | ---------- |
| 单元测试 | 50% | 单个函数/类 | < 1s/用例 |
| 集成测试 | 35% | 多个模块协同 | < 5s/用例 |
| E2E 测试 | 10% | 完整链路 | < 30s/用例 |
| 基准测试 | 5% | 性能数据 | 视场景 |

## 2. Mock LLM 策略

**绝对禁止**：

- ❌ 在测试中调用真实 LLM API（昂贵、慢、非确定性）
- ❌ Mock 整个 LLM SDK（脆弱，与实现耦合）

**正确做法**：

- ✅ 用 MSW（Mock Service Worker）拦截 HTTP 请求
- ✅ 测试中 `LlmProvider` 注入 `MockProvider`
- ✅ 准备多种 fixture 场景：纯文本响应 / 工具调用 / 流式中断

详见 `src/llm/__tests__/` 下的 Mock Provider 实现

## 3. 覆盖率目标

> 阈值的**判据 SSOT = `vitest.config.ts` 的 `coverage.thresholds`**（机器只执行此处的量）。
> 本表与之同源对齐；**冲突时以 config 为准并回填本表**，不得反向（反向 = 拿描述性文字给判据自我授权）。
> 本表的「1.0 发布阈值」是**意图来源**：提升 config 阈值属「改判据」动作，须带观测 + 退出条件后方可落 config。

| 指标 | 目标 | 备注 |
| ---- | ----- | ----------------------------------------------------- |
| 行 | ≥ 80% | CLI 入口已移出至宿主项目，不计入内核覆盖率 |
| 函数 | ≥ 88% | 核心逻辑函数覆盖率要求更高（1.0 发布阈值） |
| 分支 | ≥ 75% | loop.ts/factory.ts 的条件分支较难在单元测试中完全覆盖 |
| 语句 | ≥ 80% | 与行覆盖率保持一致 |

**不计入覆盖率**：

- `src/index.ts`（库导出入口，纯重导出）
- `src/**/*.d.ts`（类型声明）
- `src/**/*.test.ts`（测试自身）

## 4. 测试反模式

- ❌ `expect(true).toBe(true)` 占位
- ❌ 测试间共享可变状态
- ❌ 用 sleep 等待异步（用 `vi.waitFor` 替代）
- ❌ 在测试中调真实文件系统的项目目录（用 `mkdtempSync`）
- ❌ 单元测试依赖网络
- ❌ 仅断言 mock 自身被调用（如 `expect(mockFn).toHaveBeenCalled()`），不验证被测对象的实际行为变化——此类测试无回归保护价值，应删除或补充行为断言
- ❌ 闪烁测试（intermittent failures）：因 timing/并发/环境差异偶发失败的测试必须立即修复或删除，不允许用 `test.retry` 掩盖。闪烁测试比缺失测试更危险——它侵蚀整个测试套件的信任基础
- ❌ **新增分支零测试覆盖**（2026-10-03 实锤，自审抓出）：修一处判定逻辑时若新分支没有任何用例走到，
  该修复**既无回归保护、也无人验证过它是否真的生效**——「全绿」只证明没跑到。
  本仓样本：webview 审批卡去谎新增「无 diff 域」分支，但 305 个宿主用例**全部是 write_file 场景**，
  命令场景一条没有 ⇒ 分支从未执行；而生产链路的 `beforeContent` 被协议层归一为 `null`（`info.beforeContent ?? null`），
  判据用 `!== undefined` ⇒ **修复完全失效，假 diff 照旧显示**，测试却全绿。
  **纪律**：① 改判定逻辑必须同时补「该分支被走到」的用例；② fixture 形态取**生产真实形态**，
  禁止手写理想化 mock（`undefined` vs `null` vs 缺字段是三种不同形态，判据必须对**生产实际发出的那一种**成立）；
  ③ 断言要落在**用户可见后果**（渲染出的文本），不是落在判据表达式本身。
- ❌ **为测试而存在的产品代码**（2026-10-03 实锤）：为了让某个分支「有测试可测」而写的窄 `as unknown as` cast，
  等于把生产代码当测试脚手架。正解 = **把守卫移到能自然触达的位置**（本仓：把 `none` 档的拦截从路由函数
  移到取登记处的 `requireConfirmingEntry`，路由函数因入参类型收窄而无僵尸分支，测试也无需 cast）。
- ❌ **改用户可见文案只改产品那一处**（2026-10-03 实锤，同型第三次复发）：一次「去谎」订正改了产品 HTML 模板，
  却漏了**测试夹具**（`chatViewTestEnv` 的 summary）与**两侧代码注释**（`chatPanel.bindWriteConfirmation`、
  `pathGuard.confirmGate` / `confirmViaHandler` / `WriteConfirmationRequest` 都声称「只管写入确认」），
  而协议类型名 `WriteConfirmation*` 本身就是历史命名。**纪律**：改任何用户可见文案，grep 范围必须同时覆盖
  **产品模板 + 测试夹具 + 两侧代码注释 + 协议注释**；类型/协议的历史命名**不因语义变化而改名**（breaking 收益不抵），
  改用注释声明「历史命名 + 实际承载 N 类」。**判别信号**：注释里出现「唯一 / 全部 / 只」这类全称词时，
  必须回核实现调用点分布——全称词是「声称」，不是描述。

## 5. 源码扫描型守卫（守卫硬化 + 变异验证）

> **适用**：以「扫描生产源码文本」实现不变量的守卫——判据单源、SSOT 收口、禁自写反模式。
> **范例**：`src/memory/__tests__/roundStore.test.ts` 的「isRoundSettled 判据单源守卫」（豁免表 + 三闭环 + 注释感知）。
> **与 §4 的关系**：§4 管「测试怎么写」，本节管「**守卫本身是不是真闸门**」——两者不可互相替代。
> **触发**：新增/修改任何扫描型守卫；或给守卫加豁免时。

### 5.1 豁免必须收窄到最小单元

| 做法 | 判定 | 理由 |
| ---- | ---- | ---- |
| 整文件豁免 | ❌ | 该文件其余位置再犯即被静默放行；**文件越大口子越宽**（最大文件 = 最宽后门） |
| 行号豁免 | ❌ | 无关改动致行漂移即误红 |
| **行内容精确匹配** | ✅ | 只有「正是那一行」放行；同文件新增同类写法仍会命中 |

- 每条豁免**必须写明「为何不是同类判据」**——写不出理由 = 该收口而非豁免。
- 判据**定义体自身**也要豁免时，按**行区间**（进入定义体 → 退出定义体），不按文件、不按行号。

### 5.2 豁免的三闭环（防僵尸）

| 闭环 | 断言 | 防的是什么 |
| ---- | ---- | ---- |
| **僵尸豁免** | 登记片段必须在目标文件中真实存在 | 判据被删/改写而豁免仍在 = 敞开的后门（豁免理由已与事实脱节） |
| **未使用豁免** | 登记片段必须被至少一行判据消费（`usedAllowed`） | 判据行被注释/改为不消费 = 豁免成了对该文件的**空白通行证** |
| **定义唯一性** | 判据「恰好定义一处」 | `0` = 判据被删/改名；`>1` = 又长出并列判据 |

> 闭环断言必须能**独立报警**：单独删除判据（而非改坏）时它仍要红。若它只在主断言变红时陪跑，就只是影子。

### 5.3 扫描前必须先剥注释（两层）

1. **整行注释**跳过——SSOT 文档自身会引用该反模式作反面说明。
2. **行尾注释必须剥**，且需**引号感知**（跳过 `'` / `"` / `` ` `` 内的 `//`，处理 `\` 转义）。

**为什么行尾注释必须剥**（实测假阴性）：判据行被写成 `assistant: undefined, // <旧判据>` 时，该行**已不再消费**判据，但豁免片段文本仍在行内 → `includes` 通过 → 静默放行。此洞由变异验证实测暴露，修后转红。

### 5.4 守卫自带的「测量工具」先自证

守卫若含解析辅助（如 `stripTrailingLineComment`），**先给它自己写单测**：引号内的 `//` 不得误剥、普通行原样返回。纪律 =「先验证测量工具本身，再信它的结论」。

### 5.5 变异验证成对设计（四组，缺一不可）

| # | 变异 | 期望 | 证明什么 |
| - | ---- | ---- | -------- |
| 1 | 注入真实缺陷（新写一处同类代码 / 判据变质） | **红** | 守卫有效 |
| 2 | **同一变异施加给旧实现** | **绿** | **守卫比旧实现强**——无此组则无法证明新守卫不是装饰性改写 |
| 3 | 令守卫失明（摘掉判定条件） | 绿 | 不是假闸门（若仍红 = 红在别处，与守卫无关） |
| 4 | 判据行被**行尾注释**掉 | 红 | 注释感知生效（§5.3） |

- **「变异必红」≠ 够了**：须确认红的**正是**你想证明的那条断言（拿掉该断言后应变绿）。
- 变异后**逐个还原并复核现场**（`git diff --stat` + Read 目标行），别把变异留在盘上。
