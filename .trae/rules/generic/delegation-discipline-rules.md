# 托管执行纪律（Delegation & Receipt Discipline）

> **适用对象 = 接了托管任务的会话**（把活派出去、等回执、汇总回报的那一方），而不是被执行方。
> **一句话**：只有拿到**回执**的事才算「发生了」；只有**别人复核过**的事才算「完成了」。
> **第三列读法**：A–G 的第三列是**反例 / 后果**；**查法只在 H 节**；A–G 属自觉纪律，无机械查法（违规靠汇报文本自查，不设闸）。
> **顺序规则只有两条**：H = 有活时一笔任务怎么走完；I = 推演出的活全都要拍板时，按什么顺序找活。
> **不重复登记**：门禁怎么判 → [testing_rules.md](./testing_rules.md) §7.8 / §8；不许绕闸 → [project-rules.md](../project-rules.md) §5.2；改措辞扫同族 → [single-truth-source-mindset.md](./single-truth-source-mindset.md)「不变式措辞外溢」纪律② + [pre-release-audit.md §2.3](../../skills/memora-kernel-release/references/pre-release-audit.md)。本文件只补「托管方这一侧」的纪律，不复述它们的判据文字。

## A 派发与回执

| # | 判据 | 反例 / 证据 |
| --- | --- | --- |
| A1 | **三态分开说**：已投递（消息发出）≠ 已开始（对端受理）≠ 已完成（有终态回执）。三者不得递推，汇报里必须写明是哪一态。 | 「已经让另一条线去发版了」= 用投递态冒充完成态。 |
| A2 | **被切到后台或超时的命令 = 没有结果。** 派发方必须二选一：① 阻塞等到结束并回报退出码；② 自己设一个明确复查点（何时、用什么命令、看什么）去取结果。**禁止拿「已发起」当推进下一环的依据。** | 失败形态：推送扔进后台就不再取回执 ⇒ 整夜空转。同源判据见 [testing_rules.md](./testing_rules.md) §7.8「命令被移入后台 ≠ 结束」。 |

> **调度建议（排序建议，不是判据，不参与违规判定）**：长链条先起跑——跨越「内核改动 → 内核发版 → 宿主产物同代 → 宿主发版」这类长链的先动，短平快的排后面。理由：长链是串行等待，压到窗口末尾等于把全部等待一次性暴露。

## B 并发与互斥

| # | 判据 | 反例 / 证据 |
| --- | --- | --- |
| B1 | **同一仓库同一时刻只允许一条写盘线**；发版期间由该线独占仓库（含改源码、构建、打包、打 tag、上传）。 | 发版中途另一条线改 `src/` ⇒ 产物代次与源码不对应，且事后无从判断哪份产物对。 |
| B2 | **并行只允许只读线**，且只读线**禁止跑测试 / 构建 / 门禁**。锁只罩两处：`local-ci` 整体（`acquireGateLock({ kind: 'gate' })`）与 `npm test` 全量；**单文件复核、直接手跑单个门禁步骤不取锁 ⇒ 仍会真并发**——该豁免是**设计内、代价已知**（不取锁正是为保住单跑复核手段）。（锁与单文件豁免真源：`docs/测试并发确定性与flake判定SOP.md` §7；`acquireGateLock` 实现见 `scripts/local-ci.mjs:656`） | 同 head 两份收据耗时差 **>30%** ⇒ 至少一份被并发污染，**两份都不得**充当耗时 / 归因证据；超时类还会变假红，假红又会被当成真问题去「修」。数字与判据真源：[testing_rules.md §7.8](./testing_rules.md)。 |
| B3 | **两条线同时做 git 写操作禁止**（`add` / `commit` / `stash` / `rebase`），**即使改的文件不重叠**——两者共享同一份索引与工作树（工作树 / stash 互踩见 [project-rules.md §5.2](../project-rules.md)；`index.lock` 现场见 [testing_rules.md §7.8](./testing_rules.md)）。 | 冲突现场会伪装成「无关的偶发失败」；`stash` 互踩会静默吞掉对方改动。动手前先问「现在谁在写盘」。 |

## C 判据与闸门

| # | 判据 | 反例 / 证据 |
| --- | --- | --- |
| C1 | **禁止主动绕闸**（`--no-verify` / 关闸或跳过门禁步骤 / 降阈值或放宽断言——清单与判据真源 → [project-rules.md §5.2](../project-rules.md)）。托管侧增量三条：① 闸红了先判「**是改动错了，还是闸错了**」，判完再动手；② 改闸必须留理由与依据（提交正文或台账）；③ 托管期间的射程见下方。 | 绕闸那笔会在远端留下一个单独 checkout 也红的提交，破坏后续按提交验证与 bisect。 |
| C2 | **不改历史**：已推送的提交不 `amend`、不 `rebase`。订正另起一笔，并在提交正文写清「原判断错在哪、正确依据是什么」。**「同轮订正合并再提交」只约束提交前**；已推送后才发现第二个待改点，按本行另起一笔，不许回头合。 | amend 掉已推的错误结论 ⇒ 远端与别人基于它的工作全部对不上，证据链也被抹掉。 |

> **显式豁免（设计内路径，不算绕闸）**：tag 推送时 `gate-full` 被 skip（日志原文 `no matching push files`），属 [lefthook.yml](../../../lefthook.yml) 的设计内路径（口径见 [project-rules.md §5.2](../project-rules.md)）。判定口径：本次推送**落不进该步的判据面**，**不是**「门禁红了所以跳过」。**但本节只回答「这次推送为什么不跑 full」，不回答「发版要不要 full」**——发版提交与 tag 的 full 证据缺口，按 [memora-kernel-release/SKILL.md Step 4.0](../../skills/memora-kernel-release/SKILL.md) 四项硬判据补（被 tag 的 commit 须有一份 `head=` 等于它的 full 实跑收据）；本文件不复述那四项。
>
> **托管期间的射程**：托管 = 用户不在场，「用户显式授权」这个前提没人能给 ⇒ **C1 禁止的这三项在托管场景没有例外通道**。本文不新增绕行权限，也不改既定口径——「推送可绕过 `full`，但禁止把它修成强制」写在 [lefthook.yml:21-22](../../../lefthook.yml) 与 [project-rules.md §5.1](../project-rules.md) 末条（[ADR-032](../../decisions/ADR-032-gate-ownership-loop.md) 原话是「明确不追求强制」，不是「禁止修成强制」），那条讲的是上面的**设计内路径**，与本节不是同一件事。自检动作：问「用户此刻能不能当场给出原话授权」——能，按既有例外口径走；不能，三项一律不做。

## D 自证与审查

| # | 判据 | 反例 / 证据 |
| --- | --- | --- |
| D1 | **写盘方不得自证**。落地后另派只读会话复核，复核方 ≠ 写盘方。自跑门禁仍必须做（那是机械证据），但**自跑结果不能当复核结论**。 | 作者自判「我看过没问题」= 零独立证据；[testing_rules.md §8](./testing_rules.md) 要求收据写明**档位与规模**；**本文另加一条：收据 ≠ 独立复核**。 |
| D2 | **只读任务不许写盘**，包括「顺手改个 typo」、格式化、往受管目录写临时文件。需要改就退回派发方。 | 只读复核顺手改了断言 ⇒ 复核对象已不是被复核的那份代码。 |

> ⚠️ **托管期间的汇报分档（D1 的闭合面）**：**过了独立复核才允许说「完成」；没复核只能说「待复核」。** 两种状态必须在措辞上一眼可分，禁止用「已发起 / 已推送 / 已改好 / 已落地」这类**只描述执行动作**的词冒充终态。理由：只说执行动作而不说复核状态，等于把未验证的东西包装成结论。

## E 证据与汇报

| # | 判据 | 反例 / 证据 |
| --- | --- | --- |
| E1 | 说「完成」必须带**可核对**证据：提交号、退出码、原文数字、文件与行号。禁止只说「已通过」「已完成」「已修复」。 | 「测试全绿」不可复核；必须写清跑的是哪一档、多少文件 / 多少用例（[testing_rules.md §8 纪律一](./testing_rules.md)）。 |
| E2 | **里程碑即报**：里程碑 = 一个有终态回执的交付单元（拿到提交号 / 退出码 / 行号那一步）。同一里程碑不报两遍；中途报告必须自称「中途」，不得冒充终态结论。 | 攒到最后一次汇报 ⇒ 中途的错判无人纠，返工面被放大。 |
| E3 | 失败要报**原文 + 你的判断 + 处置**；不许只报「失败了」，也不许用重试掩盖。 | 「重跑一次过了」抹掉了失败事实，下一轮还会以同样方式失败。 |

## F 交付边界

| # | 判据 | 反例 / 证据 |
| --- | --- | --- |
| F1 | **必须人工的步骤要明确留出口**（如市场手工上传）：写到哪一步、交给谁、自动化部分照常完成不阻塞、也不许替用户代做。 | 替用户登录市场点上传 = 越权；反之「等人工上传」阻塞整条自动化线 = 白等。 |
| F2 | 「只提交不推送」「只读」「不碰某目录」这类边界**逐条列明**，不能靠默认理解。 | 边界没写清 ⇒ 执行方按自己的理解越界，事后无法判谁错。 |
| F3 | 用户不在场时，**停在阻塞处报清楚**，不许自己绕过去（含「先临时改一下、稍后再回滚」）。 | 临时改动留在工作树 ⇒ 下一个接手的人把它当成正式改动。 |

## G 事实纪律（真源在别处，这里只补检索手法）

| # | 判据 | 反例 / 证据 |
| --- | --- | --- |
| G1 | 改事实性措辞前**全库 grep 同族句**，用两组关键词：① **原句片段**（如「示例角色包不参与分发」）② **反义表述**（如「参与分发」「分发」）。命中逐条判「改 / 不改 + 理由」，一次收全。只改一处 = 同一句假话换个地方继续活着。 | 同一句「示例角色包不参与分发」在三个载体里只改了一个。判据真源：[single-truth-source-mindset.md](./single-truth-source-mindset.md)「**不变式措辞外溢**」纪律② + [pre-release-audit.md §2.3](../../skills/memora-kernel-release/references/pre-release-audit.md)「修一处必扫同族」。 |
| G2 | **事实性表述必须带可核对的形：文件名 + 行号 + 原文片段。** 删 / 改 / 新增前先回源核实（常量、代码、实测）；贴不出原文就写「构造性风险」或「推断」，不许借用实证语气。「本仓实证」「我觉得没依据」这类不带行号、无从复核的判断都不算证据——判据是有没有可核对的形，不是有没有出现某个词。 | **正例（可核对的形）**：`WRITE_TIMEOUT_MS = 5000`（仓库根相对 `hosts/memora-vscode/src/extension/settingsWrite.ts:32`）↔ 读取路径复用同一常量（`hosts/memora-vscode/src/extension/host/secretsAccess.ts:53-54` 导出、`:108` 用于 secret 读取）↔ 文档侧 `hosts/memora-vscode/README.zh-cn.md:213`「钥匙串 5 秒没响应」——三边都能点开，这才算证据。**反例**：本条规则自己曾写「本仓实证：图片入口四路汇流旧分支未删」，回源后原文是「旧形态**全量退役**」——既无行号、方向还相反（可用 `git log -S"旧分支未删"` 复核）。 |

## H 迭代流程（推演 → 排雷 → 执行 → 复核 → 提交）

> **三原则不在此定义**：SSOT / 自然生长 → [single-truth-source-mindset.md](./single-truth-source-mindset.md)；不带伤 → [pre-release-audit.md §2.3](../../skills/memora-kernel-release/references/pre-release-audit.md)。复述即第二真源。
> **排雷** = 方案定稿后、写盘前的**对抗性只读核查**（撞不撞既有契约 / 死代码 / 不可达路径 / 台账冲突），不是「再看一遍方案」。

| # | 触发 → 动作 | 违反了怎么被发现 |
| --- | --- | --- |
| H1 | **要提下一轮方案** → 每个「下一步」挂到**四种**可指认依据之一，并写出引用位置：① **台账现状**（在册 / 观察区条目）；② **代码事实**（read / grep 命中的文件行）；③ **上次结论**（已归档 ADR 或上一轮复核回执）；④ **用户原话**（**引原句**并指明是哪条请求；若其后有更新的用户指令或新事实，须先判该原话**是否仍有效**，失效则不得作依据）。 | 出现「应该 / 大概 / 一般来说」且指不到这四者 = 凭记忆推演。查法：逐条问「这条的依据在第几行 / 哪句话」。 |
| H2 | **方案定稿** → 按 [single-truth-source-mindset.md](./single-truth-source-mindset.md)「自然生长」的**五步逐条过**（判据在那边，本文件不复述）。 | 检查动作：把方案里每个新增文件 / 新增机制对着既有真源**逐个点名**，再搜一遍被接管路径的旧分支与旧文案还在不在。点名答不出「哪一项真源不覆盖」却说「这个场景特殊、单独再写一份」= 堆砌（构造性风险：接管后旧形态未退役 ⇒ 两份语义从落笔起漂移，且多数漂移没有测试会红）。 |
| H3 | **方案定稿后** → 排雷派**另一条只读会话**（主体约束沿用 D1：**排雷方 ≠ 设计方**），产出**三选一**：`可执行`（附复现路径 / 文件行）、`有条件可执行`（附必改项清单；必改项须是**原地修正**——不新增机制、不扩大范围、不换形态；若必改项导致方案换形，回 H3 重排，不适用「无需再排一次雷」；另：**「无需再排」= 检查延后到 H5，不是取消检查**）、`推翻`（附反证）。**无方案文档的小修免此条（此类无 H3 / H4 前置）；H4 / H5 的复核边界不放宽。** | 排雷与设计出自同一会话 ⇒ **未排雷**。查法：报告须写明排雷方是谁、读了哪些文件。 |
| H4 | **排雷回「可执行」或「有条件可执行」** → 才动第一笔写盘（后者先按清单改完再开工）；回「推翻」→ 停手，先报冲突或改方案，**不许边执行边改方案**。 | 结论字段必须落在三态之一；落在三态之外（如「存疑」「待确认」）= 回执不合格，退回重出，不得据此开工。查法：看回执的结论字段。 |
| H5 | **写盘完成** → 回顾审查（**主体见 D1；措辞分档见 D 节 ⚠️**）：**复核方 ≠ 写盘方，也 ≠ 排雷方**。**落位与分档是两条独立要求：结论是「待复核」不豁免落位。** 本条只加差异段：结论必须落到**具体位置**——文件 + 行号 / 判据名 / 复核命令；**提交时机由写盘线之外的人定**。 | 只有「我检查过了 / 整体没问题」⇒ 无法复核。查法：审查结论里没有任何行号或判据名 = 未审查。 |

## I 缺省任务（托管空转时的执行序）

> **与 H 的分工**：H 管**有活时**一笔任务怎么走完；I 管**没活干时**按什么顺序找活。三者判据（SSOT / 自然生长 / 不带伤）与注释三分法真源在别处（→ 上文 H 节首行、[comment-doc-slimming-rules.md](./comment-doc-slimming-rules.md) §2），本节只写执行顺序与射程。

**I1 前置判据（什么才算「要拍板」）**：只有推演出的**全部候选都落在拍板清单里**，才进缺省任务。清单是**枚举式、不许扩**：

- 产品取舍（做什么、不做什么、交互长什么样）
- 删历史、删归档、动已发布内容
- 改判据（抬阈值、放宽断言、开白名单、降覆盖）
- 版本槽与发版时机
- 用户偏好（文案、命名、风格）

**纯技术缺陷、明显的注释与实现相反、过时事实订正，一律不算拍板**——这些自己就做，不得以「要拍板」为由转进缺省任务。

**I2 三条缺省任务**（无优先级，按当轮情况择一）：

1. 台账核实与整理、文档整理、删除过时文档
2. 注释检查与剪枝
3. 用 SSOT 自然生长 + 不带伤原则回顾最近提交质量

每条带**射程**，防走形：

1. **删任何文档或台账条目前，先 `grep -rn '<目标>' .` 清算 docs / ADR / 源码注释里的引用；删与补引用不得分开做。**（本规则的明文要求，不因出处的覆盖范围而放宽。）出处分两句：台账条目 = [tasks/archive/README.md:9](../../../tasks/archive/README.md) 纪律 3 末条原文「从主台账**删 / 折任一顶层条目**前，先 `grep -rn '<ID>' .` 清算 docs / ADR / 源码注释里的引用，再跑 `npm run ledger:fold`」；**文档删除 = 本条自立的明文要求**，不冒充该 README 的覆盖范围。注释侧的过程稿指针清算 → [comment-doc-citation-rules.md](./comment-doc-citation-rules.md) §3「清算义务」。
2. **只删两类注释**：与实现相反的、纯复述代码的。「为什么这么做」的历史决策注释一律保留——那是资产，不是噪音（其余分拣 → 三分法 §2）。
3. 只看**最近 10 笔提交**，只找「带伤」与「拼凑」；默认产出结论，要改代码走 H 节的四出口（H1 依据 → H2 自然生长 → H3 独立排雷 → H4 才写盘），不许顺手重构。

**I3 收敛闸**（缺省任务不是无限矿）：

- 同一轮托管里缺省任务**连续不超过 3 笔**；第 3 笔收完必须停下汇报，并附「下一批需要用户拍板的事项清单」。
- 每笔开工前先答一句：**这一笔能删掉或订正哪个具体的假事实？** 答不出就不做。
- 连续两笔的结论都是「仍成立 / 无需处置」⇒ 判定该面已收敛，停手，不换角度继续挖。

**I4 产出纪律**：缺省任务不得为了显得有产出而新立台账条目；确需新立的，必须有可判的完成判据与到期复查日。
