# 单一真理源思维模型

> 遇到复杂问题，先回到最小单元。**如果一个问题能在最小单元层面解决，就不需要引入新机制。** 完整推导见 `docs/architecture/agent-design-philosophy.md`。

## 核心公理

**最小单元 = 一次输入 → 一次执行 → 一次交接判断**：自足（内部完整）、可重复（独立调用）、可观察（可记录可测）。它是系统的"细胞"，所有复杂结构都是它的组合与重复，不是另造更大的细胞。

**SSOT 不是"只有一个文件/模块"，而是"只有一个设计原点"**：一套最小单元承载全部复杂行为；同一套逻辑多场景复用、不做场景特化；复杂度向外生长、核心保持简单。

## 关键推导（证明"闭环自然生长出全部复杂度"）

- **Loop = 闭环的重复，非独立引擎**：Loop 每轮是完整单轮闭环，只在 Handoff 处选 `continue`。无需第二套引擎。
- **召回 = 由触发源决定**：外部输入触发 → `recall()`；Loop 自循环 → 不触发。不是"Loop 模式跳过召回"的开关。
- **摘要 + 归档 = 闭环后处理**：Reflect 阶段天然承载；无独立定时任务/后台系统。

## 解题步骤与补丁识别

**遇到复杂问题**：① 找到最小单元 → ② 定位问题在单元内/间 → ③ 检查能否在单元内部加参数/策略解决 → ④ 可以则在单元层面解决（最小改动、最大复用）→ ⑤ 否则单元间经接口协作，不引入新单元。

**补丁思维信号**："这个场景需要特殊处理" / "再加个模块/引擎/系统" / "这个场景和那个不一样" / "先加个 flag 控制一下"。

**自问三题**（偏离则回到最小单元）：① 这套逻辑是否只在某场景生效？② 去掉该场景特殊处理，核心是否仍完整？③ 实现是否需在最小单元之外引入新机制？任意"是"即可能偏离。

**补充判断**：**逻辑下沉**——多模块复用一段逻辑须下沉到单一真理源（工具类/管理器），不硬编码到调用方；**预留键 vs 僵尸键**——schema 定义未消费字段须区分"预留键"（设计空间，不承诺）与"僵尸键"（技术债，应清理）。

## 设计陷阱

- **循环依赖**（A 依赖 B、B 依赖 A）：解法是**中间插入一个确定性步骤**（如关键词精确匹配），让一个方向变确定性而非语义匹配，打破死锁。
- **隐式切换**（系统偷偷换配置）：**重配置对象只被显式调用**。角色包是"自洽完整人格"（含行为配置），自动替换属于配置抖动，砍。**角色包只能手动切换**（v0.13 定案，唯一入口）。
