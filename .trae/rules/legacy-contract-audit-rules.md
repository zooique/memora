# 带伤设计审查规则（Legacy Contract Audit）

> **适用范围**：Memora 全库审查（`src/` 内核心 + `hosts/` 下宿主），用于识别"从零新写绝不会这么写"的历史折衷设计
> **触发**：全库 SSOT 排查、大改前对既有模块的带伤审查、新模块设计时的反模式自检
> **与现有规则关系**：本文件是 [single-truth-source-mindset.md](./single-truth-source-mindset.md) 的实证落地维度（把"最小单元/单一真理源"转成可执行的带伤识别标准）；与 [comment-doc-slimming-rules.md](./comment-doc-slimming-rules.md) 互补（前者收代码残痕，后者收注释残痕）
> **关联决策**：[决策 README](../decisions/README.md)

## 1. 一句话定义

> **带伤设计 = 看似符合直觉、跑起来也正常，但"从零新写时绝不会这么写"的设计。**
> 它不是 bug，是历史演进留下的折衷——为兼容旧契约/旧数据/旧调用而被迫多绕的一层，正常设计本不需要它。

## 2. 判别标准（三条核心，命中 ≥1 即疑似）

| 标准 | 说明 | 项目实例 |
| ---- | ---- | ---- |
| **同语义多实现** | 同一逻辑/格式/规则在 ≥2 处各自实现：一处是 SSOT、另一处是绕过它的手写，且 SSOT 明文"禁止"却被历史代码违反 | `SESSION_ID_PATTERN` 正则 vs `splitSessionId` |
| **绕一层才能接上** | 某接口/字段因历史包袱保留，正常设计让消费方走"真源方法"，带伤处却直接用旧契约/旧字段凑合 | `meta.roundIds` 双轨 + `getRoundIds` 降级兜底 |
| **靠业务差异撑着** | ≥2 处调用对同一校验有不同失败语义（一处报错、一处兜底），统一函数不敢替换，手写逻辑得以旁生 | openSession 抛错 vs markSessionTimedOut warn 兜底 |

> **反模式自问三题**（偏离则回到正常设计）：
> ① 这套逻辑从零设计会这样写吗？
> ② 去掉"兼容旧 XX"这一层，核心是否仍完整？
> ③ 是否在 SSOT 边界之外另开了一条手写通道？

## 3. 五类带伤模式（模块级识别信号）

| 模式 | 识别信号 | 已收敛实例 |
| ---- | ---- | ---- |
| **双轨镜像** | 两处存同一份状态，靠 `sync*`/`synchronize`/双写函数对齐；两字段语义重叠需保持一致 | `meta.roundIds` + `roundIdsStore`（已删字段，收敛到 `getRoundIds()` 真源） |
| **降级兜底残留** | "优先 X、否则降级 Y"，而 Y 永不触达；或 `??` 回退恒右侧、`||` 回退恒死；或**布尔式恒真**（如 `!aborted && !paused` 正常轮恒 true）导致"想干活却一步没干成"被当成功 | ViewLoader 优先真源/降级 `meta.roundIds`（已删降级分支） |
| **类型 hack** | `as unknown as` / `as any` / `@ts-ignore` 侥幸绕过类型约束（生产代码多处） | 多为良性（库类型缺口），如 DOMPurify 参数桥接 |
| **重复实现** | 同语义不同名的函数/正则/常量散落；相同魔法数/哈希硬编码多处 | `SESSION_ID_PATTERN` vs `splitSessionId`（已收敛到 `isValidSessionId`） |
| **僵尸声明** | 宣称"能力/事实"却生产代码零消费：注释宣称零实现的能力、能力位恒 false 零消费、派生字段零消费者、对外宣告通道零验收。**识别关键**：该通道不可观测、不设防、失败被静默（验收位问"跑完没有"而非"干成没有"） | `provider.ts` "fallback 到纯文本 tool_call" 注释（null 实现了静默降级）→ 已纠为中实注释 |

> **僵尸声明判据的层级（2026-09-16 补，堵「导出即算活」的滥用缝）**：
> 判据落点在**内核公开导出面**，**不是**端到端消费面。
>
> | 情形 | 判定 | 理由 |
> | ---- | ---- | ---- |
> | 进入公开导出面（经 `src/index.ts` 导出的类型 + 公开读方法，如 `AgentMetrics` 与 `getMetrics()`） | **活** | 「能否被读到」在内核即可判定；宿主是否消费属**宿主生长缺口**（宿主有权不消费，非用户功能缺口） |
> | 未进入任何公开导出面，仅内核内部自增 / 派生 | **仍为僵尸** | 没人能读 = **假出闸**：「记了却不外露」与「没记」对宿主完全等价 |
>
> 这层区分的价值：把「代码里出现过」与「外部读得到」分开。原表述只写「零消费者」，
> 会被「我导出了」一句挡回；新表述要求**可被读到的落点**，否则一律算僵尸。

> **「多余导出面」判据（2026-09-18 补，堵「未过 `index.ts` 即多余」的误报）**：
> 上一条问的是**可观测性**（数据 / 能力位能否被读到）；本条问的是**代码符号的可见性**
> （`export` 修饰符是否多余）——**两个问题不可互换，判据不可互相借用**。
>
> | 情形 | 判定 | 理由 |
> | ---- | ---- | ---- |
> | 有**模块内**消费者（含 `__tests__/` 直测） | **活，不是多余导出面** | 测试是同包消费者（同 tsconfig、走 `@/` 别名）；删 `export` 会让该判据点**无法被断言** |
> | 连测试都零消费 | **死导出**，可收窄 | 无任何消费者 |
>
> 前提：包公开面已被 `package.json#exports`（仅 `"."`，**深导入不可达**）+ `src/index.ts`
> 白名单**双重封死** → 「未过 `index.ts`」只说明它**不在包公开面**，**不等于**它多余。
>
> ⚠️ 反向陷阱：把「测试缝」收窄掉只会逼出两条更差的路 —— ① 丧失函数级判据点（覆盖质量
> 下降）② 把内部符号塞进 `index.ts`（**真实**公开面扩大）。纯函数解析器（`resolve*` 一类）
> 单测直打函数是**正确设计**：判据单点、失败定位精确。
>
> **「可收窄」≠「必须收窄」（2026-09-18 补）**：是否**必须**修，取决于该冗余**是否会
> 造成伤害** —— 不带伤约束的是「**会造成伤害的不一致**」，**不是**「消灭一切冗余」：
>
> | 冗余性质 | 裁定 | 实例 |
> | ---- | ---- | ---- |
> | 会误导实现决策 / 让接入者写出幽灵代码 / 造成双源漂移 | **必须修** | 零消费者的**运行时符号或能力函数**（宣称不存在的能力：`cosineSimilarity`、`isToolInCapabilities`）；注释谎报 |
> | 纯 no-op：包外不可达、运行时零影响、无人可命名 | **不作修复**，记入台账「已关闭决策」**防重提** | 零消费者、且被同文件导出类型结构引用的**类型**修饰符（`AskOnTrigger` / `SkillResource` / `SkillScript` 等） |
>
> 区分要点：**符号活着 ≠ 需要 `export`**。被同文件导出类型结构引用的类型，收窄后消费者
> 所见**完全一致**（深导入已被 `package.json#exports` 封死，无人能命名它）→ 收窄只是
> 纯表述整洁，**不构成伤**。

> **退役概念回扫清单（7 处，2026-09-19 第 11 站固化）**：删除/退役任何功能后，残留表述
> 会散落在全库多处——回扫必须逐层覆盖以下 7 处，缺一层即可能漏网：
>
> | # | 回扫层 | 说明 |
> | ---- | ---- | ---- |
> | 1 | `docs/` | 含 `docs/architecture/` 活跃架构文档 |
> | 2 | 代码注释 | 含注释生成的 `.d.ts`（发布面，接入者会读到） |
> | 3 | 测试文件头注释 | 每轮实证的惯常漏网点（如 TRACE_SPANS 数量、退役符号点名） |
> | 4 | README 中英双版 | 双语需各扫一遍 |
> | 5 | `package.json#files` | 发布白名单：已删文件是否仍在清单 |
> | 6 | `.trae/rules/` | alwaysApply 规则每轮注入 Agent 上下文，最易被忽略 |
> | 7 | `.trae/decisions/` | **ADR 层是盲区**（2026-09-19 实证：ADR-008/ADR-VC-001 残留 embedding/recall 表述，非清单触发发现） |
>
> **ADR 层纪律**：ADR 属历史留档——**不重写正文**（改写即篡改决策历史），只在头部加
> 退役注记指向后继 ADR / 删除提交（2026-09-19 第 11 站已按此形态落地两条注记）。

## 4. 实证判定流程（关键：先读码，再定类）

**不是所有"怪"都是带伤**——审查必须读码确认"真带伤 vs 良性 vs 已收敛"，不能只看表象：

| 判定 | 判断依据 | 处置 |
| ---- | ---- | ---- |
| **真带伤** | 上述 5 类模式 + 有 ≥1 处历史折衷证据（SSOT 明文禁止却被绕过 / 兼容旧契约字段 / 靠业务差异撑着） | 走收敛流程（§5） |
| **良性** | 有明确设计意图注释（如库类型缺口桥接）、有单一真源且全库无重复、有独立测试 | 不处理，记录判定 |
| **已收敛** | SSOT 清理已覆盖（镜像已删、降级已删、导出已收回） | 跳过，避免重复劳动 |

## 5. 收敛流程（改造约束）

1. **每可疑点先 grep/读码实证**，判定真带伤/良性/已收敛后再动刀
2. **优先在最小单元（SSOT 源）收敛**，不破坏原契约边界（如 `splitSessionId` 纯拆解语义保持，另加 `isValidSessionId` 作校验互补）
3. **保留两处失败语义**：若带伤点有"报错/兜底"两种结局，收敛后须逐一保留各自语义（openSession 抛错的 + markSessionTimedOut 兜底的）
4. **验证**：内核 + 宿主 `tsc` + 全量 `vitest` 全绿
5. **炼化归元**：规则对齐（命名/注释/SSOT 声明一致）→ 剪枝（无"不是XX而是XX"、无修复思路旁白、无修改痕迹）→ 提交前审查
6. 用 `refactor:` 提交，经 pre-commit（lint-staged + typecheck + commitlint）后推送

## 6. 已收敛残留清单（避免重复审查）

以下为已收敛的带伤点，新审查直接跳过。**按「模式级」记录**：同时登记「已收敛的模式」与其「复发识别信号」，当信号再次出现（即使字段名不同）即按同一模式收敛，而不是当作新 bug 另起炉灶。

| 模式 | 已收敛实例 | 复发识别信号（信号再现即按本模式收敛） |
| ---- | ---- | ---- |
| **双轨镜像** | `SessionMeta.roundIds` 双轨镜像 → 已删字段，收敛到 `ISessionStore.getRoundIds()/setRoundIds()` 真源；`trace_summary` schema 双真源 → 已收敛 `BUILTIN_TOOLS` 引用 `TRACE_SUMMARY_TOOL` | 出现新字段与某真源同时存同一份状态、靠 sync 对齐；同一 schema/常量被两处各自 import |

## 7 待验证带伤候选与预警信号（探索期登记，未固化）

> 与 §6 不同：这里是**尚未定类/尚未复现、仅登记待查**的带伤候选与可观测预警信号。
>
> **原则：先记录，再动手；动得起，也收得回。**
> 探索期**不设「不动内核」的禁区**——根因未明不等于不能试，试本身就是探索的手段。把「不动」当纪律，
> 只会让候选长期悬空、且规则字面被反复绕过（实例：为补 ADR-031 漏记，`193e0a4d` 动了内核 22 行而
> 判据零分叉——字面违规、意图合规，说明旧表述管不住真实行为，只会让后人按字面误判合规动作）。
> 真正要守的是三条，**缺一即降级为带伤**：
> ① **可追溯**——每一动对应本节已登记的候选或已复现的真机现象，不拍脑袋；
> ② **可观测**——改动必须带可量化计数 / 留痕，能判断它「有效」还是「过度」
> （没有观测的改动 = 盲人打靶，下次仍要从头重来）；
> ③ **可退出**——写明真机定类后是收敛、降级回 docs/ 还是回退，**不留悬空特判**。
>
> **判别（与 §5 收敛流程互补）**：**改「判据」＝造伤的高风险动作；改「喂给判据的事实」＝止血。**
> 后者随时可做；前者在探索期**也允许做**，但必须带 ②③。
> 反例（真带伤）：往判据里塞 `if (某场景) return true` 式场景特化——它不可退出，
> 会在下一个场景变成新的折衷。

### 7.1 复查节律（2026-09-16 补：给 §7 装上「消费机制」）

> **为什么补**：§7 此前**有登记、无消费**——候选登记完即悬空，没有任何机制把它们推向结案。
> 这正是 §3「僵尸声明」在**规则层**的复现：**登记了却不被任何流程消费 = 假登记**。
> 故本小节回答「谁在什么时候、按什么条件、把它推到哪去」。

| 项 | 约定 |
| ---- | ---- |
| **登记日期** | 必填，精确到日。真机现象取**首观测日**，其余取登记日。缺登记日期**不得登记** |
| **复查触发** | 必填，满足任一即复查：① **到期**（默认 = 登记日期 + 60 天）② **事件**（信号再现 / 依赖项变动 / 版本切档）。纯远期方向可写「事件驱动」，须注明不参与到期 |
| **复查动作** | 四选一并写结论、更新本行：**复现 / 收敛 / 降级回 docs / 回退**。样本不足无法定类时取「**降级回 docs**」并注明缺口，**不得停留原状** |
| **挂载节律** | 随**发版前 Go/No-Go 检查清单**执行：发布前逐行核对触发条件，**到期行强制结案** |
| **不得** | 不得只更新日期而不写结论（= 续命，即 §3 的假出闸）；不得把「未复现」当结案理由（未复现只支持「降级回 docs」） |
