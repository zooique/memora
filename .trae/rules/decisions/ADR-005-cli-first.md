# ADR-005 · CLI 优先于 Web 形态（阶段一交付）

> **状态**：✅ 已接受 **日期**：2026-06-02 **播种批次**：Memora 模式 A v1
> **来源**：[土壤分析报告.md §二](../../docs/土壤分析报告.md)

## 背景

Memora 作为本地 Agent，需要选择交付形态：CLI / 本地 Web / IDE 插件 / 多端。

## 决策

**阶段一交付 CLI 形态（命令行 REPL）**。其他形态作为后续阶段的可选扩展。

## 理由

- **目标用户是开发者**：习惯 CLI；接受配置文件手动编辑
- **零部署成本**：`npm install -g memora` + `memora` 命令即可
- **单进程简单**：CLI 启动 = 主进程 = Agent Loop
- **可作为其他形态的内核**：未来 Web 形态 = 在 CLI 外套一层 Web UI
- **设计文档 §1.1** 明确"自研可控、本地私有化"——CLI 是这一哲学的最直接体现

## 替代方案

| 方案           | 放弃原因                                               |
| -------------- | ------------------------------------------------------ |
| 本地 Web 服务  | 阶段一不必要；增加前端复杂度；端口冲突；用户要开浏览器 |
| IDE 插件       | 强绑定 IDE；插件审核；版本同步问题                     |
| 多端协同       | 违反"单机本地"定位；隐私风险                           |
| CLI + Web 都做 | 阶段一过载；测试矩阵翻倍                               |

## 影响

- 阶段一专注 CLI：readline + commander.js
- 阶段二可选升级到 ink 富交互
- 阶段三可选扩展 Web 形态（不破坏 CLI 兼容性）
- 所有功能必须有 CLI 入口（不能只能在 Web 触发）

## 何时回顾

- 当用户强烈要求 Web 形态
- 当 CLI 交互复杂度超 readline 能力
- 当需要可视化记忆/话题结构时
