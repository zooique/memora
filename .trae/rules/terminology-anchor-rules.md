# 领域术语锚点（唯一定义处）

> **全库领域术语只在此定义**，常驻加载。命名 / 注释 / UI 文案 / 方案写作前必读。
> **收敛纪律**：他处一律不得重复定义，只放指针 `→ 术语锚点`。发现他处有定义 = 并入本文件 + 该处改指针。
> **分工**：`project-rules.md §4` 管**怎么写**（大小写/分隔符），本文件管**指什么**（语义归属）。

## 1. `step`（唯一定义 · 红线）

> **step = loop 内一次迭代 = 一次 LLM 调用 + 该次调用触发的工具执行。**

- 🔴 **重试算同一步**（真源 `AgentLoop.roundStepIndex` 递增点在 `callLlmWithRetry` **之外**）。不得把「一次 HTTP 请求 / 一次重试」当成一步。
- 编号真源 = `AgentLoop.roundStepIndex`（轮内单调：续跑续号、新轮起数）。
- step **不是**任务表的一行，也**不是**一次工具调用（一次 step 可触发多个并发工具调用）。

## 2. 任务表阵营（与 `step` 严格分离）

| 概念 | 现行名 | 含义 |
| ---- | ------ | ---- |
| 任务表一行 | `PlanItem` / `planItem` | 任务条目；UI 显示「**任务项 N**」 |
| 任务项推进信号 | `plan_item_boundary` | 任务项级边界（**不**叫 step 边界） |
| 任务表工具参数 | `plan_item_id` / `items` | LLM 可见契约面：`task_table_update` 寻址用 `plan_item_id`、`task_table_write` 列表用 `items`（旧名 `step_id` / `steps`，2026-09-25 改名） |
| 迭代边界信号 | `step_boundary` | step 级边界（落盘点） |

**判定口诀**：「第几步」= step 阵营；「第几项 / 任务项 N」= planItem 阵营。不可互换，不可同屏用同一个词。

## 3. 冻结例外（存量不可改，且不得据此推论）

| 名字 | 实际含义 | 为何不动 |
| ---- | -------- | -------- |
| `stepBudget` / `multiStepReasoning` / `toolStepLimit` | loop 迭代相关（**属 step 阵营，语义合法**） | v3.0.0 冻结策略键 |
| `handoffPrompt`（角色包 manifest 字段） | **角色接手话术**（装载角色时预填的开场提示），与已废弃的「Handoff 衔接决策」（turn 出口 wait/loop/end）**同名异义** | 角色包对外契约键（宿主与 schema 消费），改名破坏兼容 |

> `handoffPrompt` 是**同名异义**：其 `handoff` = 英文「交接/接手」，与 §5 废弃的「Handoff 衔接决策」无关；见到它**不得**推论 Handoff 机制复活。

## 4. 增量纪律（违反即伤）

1. 新增标识符（含**工具参数名**）/ 事件名 / CSS 类 / DOM 属性：**不得**用 `step` 表示任务表语义（一律 `planItem`）。
2. 新增 UI 文案：**不得再造「第 N 步」**——屏上已有一个「步」属 step 阵营；工具类用「第 N 批」或纯计数（如「读取 3 个文件 · 搜索 2 次」）。
3. 方案 / 注释 / 台账里的「步骤」，凡指任务表一律写「**任务项**」。
4. 新术语先自查是否与已有词撞车；无撞车则登记进 §5。

## 5. 完整术语表（现行定义 · 唯一）

| 术语 | 含义 |
| ---- | ---- |
| **turn（问答闭环，Round）** | 最小完整单元：一次「用户输入 → 最终回答」，三阶段闭环，分配 roundId；记忆摘要在其级产出 |
| **step** | 一次 LLM 调用 + 可选工具执行（`runIterationLoop` 内循环体） |
| **loop（Agent Loop）** | 对 step 的编排：反复拉起 step（推理 → 工具 → 回填 → 再推理）直至可输出最终回答（代码 `runIterationLoop`；决定「一轮有多深」） |
| **round** | **turn 的落盘形态**（同 roundId，非独立层）——「这一轮」=「这个 turn」 |
| **气口** | **step 之间的暂停点**（LLM 提问 / 用户插话 / 暂停续跑）。🔴 turn 边界是**新的问答闭环**，不是气口 |
| **Trigger** | 外部驱动，拉起一个 turn 的入口 |
| **回答前（Prepare）** | turn 第一阶段：理解触发、召回、装配上下文 |
| **回答中（Act）** | turn 第二阶段：由 loop 驱动生成回答、执行工具 |
| **回答后（Reflect）** | turn 第三阶段：提炼记忆、生成摘要 |
| **thought** | 模型思考流（CoT，不进正文），按 **step** 归属（`thought.stepIndex`） |
| **PlanItem（任务项）** | 任务表一行；UI 显示「任务项 N」。**不属 step 阵营** |
| **目标模式（G-Mode，远期）** | 对多个 turn 的编排：只给目标文档、全自动至达成（未实现） |
| **角色包（Role Pack）** | 角色为单位的固定范式：L1 内容 + L2 行为策略（+远期 L3），可插拔整体 |
| **角色池（Role Pool）** | 角色包集合：可下载、可共享，手动装载 |
| **插卡式** | 内核提供固定卡槽，角色包自含内容，换卡即变 |
| **行为策略** | L2 策略层枚举项：角色的行为开关（理解确认 / 工具权限 / 记忆模式） |
| **预检停顿** | 回答前确认点：总结输入 → 提问确认 → 确认后进入回答中 |
| **验收锚点** | 目标文档中的确定性检查项（文件存在 / 测试通过 / 清单勾选） |
| **远期锚点** | 不实现、但约束接口形状的未来目标 |
| ~~多 turn 任务编排~~ | ~~对多个 turn 的编排（`externalTaskLoop`）~~ **已废弃（2026-09-04）**：复杂度在单 turn 内生长 |
| ~~Handoff（衔接决策）~~ | ~~turn 的出口（wait/loop/end）~~ **已废弃（2026-09-05）**：turn 结束即 done |

### 5.1 存储层术语

| 术语 | 含义 |
| ---- | ---- |
| **Round** | 问答闭环（= turn 的落盘形态），含一轮完整 User + AI 对话 |
| **Round ID** | 问答闭环的**全局唯一物理存储标识**（SSOT：跨会话溯源全靠它） |
| **Session** | 会话：Round ID 的**有序列表**（不持有内容，只持引用） |
| **Session ID** | 会话的唯一标识 |
| **Memory（记忆）** | 以 Round ID 为核心标识的摘要（`Memory ID` = `round-summary:{roundId}`） |
| **SessionView** | 会话的逻辑视图：展开后的完整对话 |
| **引用计数** | 一个 Round 被多少个 Session 引用 |
| **GC** | 垃圾回收：清理无引用的孤立 Round |

### 层级关系（勿并列）

- **向下**：`step`（原子）⊂ `loop`（turn 内 Act 阶段的 step 编排）⊂ `turn`（Prepare + Act + Reflect）。**loop 不构成新层**。
- **向上**：`turn` ⊂ ~~多 turn 编排~~（已废）⊂ `目标模式`（远期）。
- **`round` 与 `turn` 是同一实体两种说法**（运行时 / 存储），**不参与层级比较**。
- **阶段 ≠ step**：一个 turn 只有一个 Act 阶段，但可有多个 step。

## 6. 历史别名对照（读旧文档时用）

| 现行名 | 历史别名 |
| ------ | -------- |
| turn（问答闭环） | 执行闭环、单轮闭环、单轮执行闭环、最小执行闭环 |
| step | 迭代、iteration、内循环 |
| loop（step 编排） | 内循环、迭代循环 |
| ~~多 turn 任务编排~~ | Loop 编排、外循环（已废） |
| 气口 | 闭环边界暂停点（旧称 Handoff 出口，已废） |
| 任务表工具参数 `plan_item_id` / `items` | `step_id` / `steps`（任务表语义的旧参数名，2026-09-25 正名；旧名只可用于读懂历史记录） |

> 代码标识符不改：`runIterationLoop` / `currentIteration` / `AgentLoop` / `Round` 保持原名。别名只用于**阅读理解**，不用于改名。

## 7. 违反后果

`step` 若被复用于「任务表一行」，连带产生**一整条链**的错位：事件名撞车（`step_boundary` 该归谁）→ 落盘时机挂错分支 → 无任务表的长工具循环零增量落盘 → UI 两套编号同屏（「任务项 3」与「第 3 步」）→ 用户与 LLM 各自误读。
