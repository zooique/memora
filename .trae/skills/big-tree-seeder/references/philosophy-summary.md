# 大树模型哲学摘要

> 大树模型是一种项目工程指导思想，其核心观点：任何项目像一棵树——先扎好根（规则框架），再长好干（抽象工具），最后生枝叶（业务功能）。
>
> 它是多个成熟软件工程理论（分层架构、DDD、清洁架构、约定优于配置、演进式架构）的有机整合与隐喻化表达。

---

## 三层定义

```
                        ┌─────────────────────────┐
                        │    🌿 枝叶层（Leaves）    │
                        │  具体页面、业务逻辑、    │
                        │  独特功能，各自生长      │
                        ├─────────────────────────┤
                        │    🌳 躯干层（Trunk）     │
                        │  抽象方法、通用模式、    │
                        │  通用组件、工具函数      │
                        │  从根汲取养分，茁壮成长  │
                        ├─────────────────────────┤
                        │    🌱 根系层（Roots）     │
                        │  .trae/rules/ 项目规则   │
                        │  分层规范、命名约定、    │
                        │  安全策略、架构决策      │
                        │  扎得越深越广，树越茂盛  │
                        └─────────────────────────┘
```

---

## 核心主张

1. **根系优先**：先建立牢固的规则框架，再开始写业务代码
2. **自然生长**：躯干从根系自然派生，枝叶从躯干自然生长
3. **各层独立**：根系稳定但可演化，躯干渐进增强，枝叶自由迭代
4. **普适哲学**：不绑定特定语言或框架

---

## 大树模型宣言

> - **扎根深广** 重于 快速交付
> - **自然生长** 重于 强行拼凑
> - **躯干强壮** 重于 枝叶繁茂
> - **规则可见** 重于 口头约定
>
> 也就是说，虽然右项也有价值，但我们更重视左项的价值。

---

## 自然生长质量标准

好的产出应该**看起来像从架构中长出来的**，而非强行拼凑的

- 好的抽象应该**从多个产出单元中提取共性**，而非凭空设计
- 好的规则应该**能支撑躯干和枝叶的生长**，而非阻碍
- 抽象提取原则：**出现 3 次以上相同模式才提取**，不提前抽象

---

## 三层健康度指标

### 根系健康度

- 关键架构决策是否有对应规则文档
- 规则之间是否存在矛盾
- 新成员是否能通过阅读规则理解项目结构

### 躯干健康度

- 可复用模式的复用率（多少个产出单元使用了同一个躯干组件）
- 是否有重复造轮子
- 框架的扩展性（添加新产出单元是否需要修改框架）

### 枝叶健康度

- 新增一个标准产出单元需要的工作量（越少越好）
- 产出中是否有违反规则的"越权调用"
- 产出单元之间的一致性

---

## 关键概念

### 剪枝（Pruning）

定期审视项目，清理：
- 不再使用的产出（枯枝）
- 重复的抽象（徒长枝，删一个保留更好的）
- 过时的规则（根系腐化）

### 年轮（ADR）

架构决策记录，记录：
- 为什么这样选择
- 考虑过哪些替代方案
- 选择的后果（正面和负面）

### 反馈回路

虽然养分从根到干到叶单向流动，但：
- 枝叶层的创新可以反过来要求躯干层的重构
- 躯干层的优化可以揭示根系层的缺陷
- 样板枝叶（第一个最小产出单元）可以帮助验证根系是否可用

---

## 三层对应关系

| 树的部位 | 通用含义 |
|----------|---------|
| 根系 | 项目规则与架构约束 |
| 躯干 | 可复用的模式与框架 |
| 枝叶 | 具体产出单元 |

---

## 新项目播种流程（简版）

```
第一阶段：扎根
├── 确定核心矛盾与领域方向
├── 编写 .trae/rules/ 根规则体系
├── 设计分层架构与数据流
├── 制定命名规范、目录结构、导入约定
├── 建立质量保障与追溯体系
└── 用最小产出单元作为"样板枝叶"验证根系

第二阶段：壮干
├── 提取可复用模式（出现 3+ 次才提取）
├── 构建领域基础设施
├── 搭建核心框架
└── 建立产出规范

第三阶段：生叶（持续迭代）
├── 基于躯干快速生成具体产出
├── 每个产出单元遵守根系规则
├── 定期回顾：躯干/根系是否需要调整
└── 执行剪枝
```

> 壮干阶段：提取出现 3+ 次的重复模式，构建可复用框架。生叶阶段：基于躯干快速生成具体产出。
