# 退出话术指南

> 定义各入口在"不适用场景"被触发时的标准退出语言。AI 在检测到不适用场景时，应直接使用本指南中的话术告知用户，而非临时组织语言。

---

## big-tree-seeder 退出话术

### 场景 1：已有成熟 rules 体系的项目

**判断标准**：当前项目 `.trae/rules/` 目录存在且包含 `project-rules.md`

**退出话术**：
> 本 Skill 适用于新项目扎根，当前项目已使用 seeder 完成初始化，建议使用 big-tree-grower 进行日常开发。如需诊断项目健康度，可说"检查大树健康"。

---

### 场景 2：单文件项目 / 探索性原型

**判断标准**：用户描述的任务是单次执行脚本、数据分析、一次性数据处理，且无持久化需求

**退出话术**：
> 本 Skill 适用于需要建立完整项目架构的新项目，单文件项目或探索性原型直接开始编写即可，无需完整规则体系。

---

### 场景 3：已有项目仅需补充单一规则

**判断标准**：用户明确说"帮我补充某一条规则"，而非启动新项目

**退出话术**：
> 本 Skill 负责从零搭建项目规则体系。如需补充单一规则，建议直接编辑 `.trae/rules/` 下对应文件，或使用 big-tree-grower 的"规则对齐"入口。

---

### 场景 4：无法建立项目架构的任务

**判断标准**：用户只需单次操作或单次产出，不需要持续迭代的项目结构。例如：单次数据分析报告、一次性 PPT 生成、单次翻译任务。大树模型是领域无关的项目工程方法论，对任何需要持续迭代的项目都适用。

**退出话术**：
> 本 Skill 适用于需要建立项目规则体系、持续迭代的任务。单次操作/产出的任务不需要完整规则体系，直接执行即可。

---

### 场景 5：纯信息查询

**判断标准**：用户问的是概念、术语解释、框架原理等，且不涉及项目启动或规则设计

**退出话术**：
> 这是知识查询类问题，不涉及项目启动或架构设计，本 Skill 不适用。如需了解大树模型原理，可阅读 seeder/references/philosophy-summary.md。

---

## 使用原则

1. **直接使用，不临时发挥**：识别到不适用场景时，从本指南中选取对应话术直接输出
2. **如有必要，补充一句后续行动**：在标准话术后追加一句建议，例如"建议使用 big-tree-grower 进行日常开发"
3. **不说话术以外的内容**：退出时不要展开解释为什么 skill 不适用，不要列举其他选项让用户选择
4. **跨 Skill 建议要具体**：当建议用户使用另一个 Skill 时，应给出具体的触发短语
