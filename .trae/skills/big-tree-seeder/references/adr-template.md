# ADR 模板（年轮记录）

> 用于第 4 步"ADR 记录"
>
> ADR 模板遵循标准架构决策记录格式：背景 → 决策 → 替代方案 → 后果

---

## ADR 文件命名规范

```
{序号}-{短横线分隔的描述}.md

示例：
001-core-choice.md
002-architecture-pattern.md
003-naming-organization.md
004-quality-strategy.md
```

## ADR 决策维度引导

新项目启动时，需要为关键决策创建年轮。决策维度分为两类：

### 通用决策（任何领域都需要）

| 序号 | 决策维度 | 触发条件 | 重要性 |
|------|---------|---------|--------|
| 001 | 领域核心选择 | 总是需要 | 🔴 必写 |
| 002 | 分层/结构架构 | 总是需要 | 🔴 必写 |
| 003 | 命名与组织约定 | 总是需要 | 🟡 推荐 |

> **核心选择**因项目类型而异，由第 3 步项目适配决策决定。常见核心选择包括：技术栈选型、架构模式、质量标准等。

> 播种机在第 4 步时，根据第 3 步确定的关键决策，为每个决策创建 ADR。通用决策（核心选择 + 分层架构 + 命名约定）每个项目都必须有 ADR。

## ADR 质量检查清单

每个 ADR 生成后自检：

- [ ] 是否说清楚了"为什么"而不仅仅是"选了啥"？
- [ ] 是否列出了至少 2 个替代方案？
- [ ] 是否说明了放弃替代方案的具体原因？
- [ ] 是否记录了正面和负面影响？
- [ ] 是否有明确的后续行动项？
- [ ] 语言是否简洁（不超过 200 行）？
- [ ] 新加入的开发者能否通过这个 ADR 理解决策原因？
