# 聚焦测试建议 — 公共规则

> **适用范围**：所有涉及代码修改的 grower 入口（方案生长、速修、提交前审查、新枝破土、神木回天、斩木除根、翠幕天罗、种木成林）。
> **硬约束**：以上入口在退出声明中**必须**输出此格式的测试建议，不可跳过。

---

## 输出格式

```markdown
🧪 聚焦测试建议

基于本轮修改：
- 修改文件：{文件列表}
- 影响功能：{一句话概括}

## 建议测试

1. {操作路径} — 验证 {具体功能点}
2. {操作路径} — 验证 {具体功能点}
...

## 不需要测试

- {功能 A} — 原因：{本轮未修改相关代码}
- {功能 B} — 原因：{修改仅影响 C 模块，与 B 无关}
```

---

## 生成原则

1. **推理影响链**：修改了哪个文件 → 影响了哪个前端页面/后端接口 → 用户能看到什么变化
2. **聚焦用户可感知**：测试项聚焦在按钮是否可点击、数据是否正确显示、弹窗是否正常弹出、API 是否返回正确数据
3. **操作路径一句话**：每个测试项一句话描述完整操作路径，如「编辑基元 → 修改类型字段 → 确认下拉框正常弹出并可选」
4. **明确测试边界**："不需要测试的"不是冗余——它帮助用户聚焦，避免浪费时间测无关功能
5. **数量根据变更规模**：
   - 速修（单文件、<30 行）：2-4 条
   - 方案生长（多文件）：按功能点分组，每组 2-5 条
   - 批量变更模式：按模块分组汇总

---

## 不需要测试的判断标准

以下情况可明确标注为"不需要测试"：

- 本轮未修改的功能模块
- 修改仅涉及内部重构、不影响外部行为
- 修改仅涉及样式微调（如间距、颜色），且不影响交互逻辑
- 修改仅涉及注释或文档

以下情况**不可**标注为"不需要测试"：

- 修改涉及数据流（如 API 参数变更、数据库查询逻辑变更）
- 修改涉及用户交互（如按钮行为、表单校验、弹窗逻辑）
- 修改涉及权限或安全逻辑
