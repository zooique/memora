# 提交前审查模式 — 审核标准与执行指南

本文档为提交前审查模式（入口 5）提供统一的审核标准，与方案生长模式的审核清单（grow-plan-template.md）保持一致。

> 本文档只定义审核维度框架和审查流程。各维度的具体检查项（如具体规则文件名、具体阈值、具体命名约定）由领域枝干提供。trunk 不硬编码领域专属检查项。

## 审核维度（与方案生长模式统一）

### 维度 1：分层规范

- [ ] 入口层（展示层/路由层）是否保持薄层（只做参数接收、请求转发、响应封装，不含业务逻辑）？
- [ ] 处理层（业务逻辑层）是否持有全部核心处理逻辑？
- [ ] 数据层（持久化层/映射层）是否只负责数据存取和基础映射？
- [ ] 键名/格式转换是否只在数据层发生（从 `.trae/rules/` 中读取转换约定）？
- [ ] 事务操作是否使用了事务安全方法而非常规方法（从 `.trae/rules/`
      中读取具体方法名）？
- [ ] 错误处理是否使用了统一错误处理机制（从 `.trae/rules/`
      中读取具体处理方式）？
- [ ] 错误码/错误标识是否在项目约定的正确范围内？

### 维度 2：展示层规范

- [ ] 新产出单元是否使用项目约定的创建入口（从 `.trae/rules/`
      中读取具体入口名）？
- [ ] 列表/集合型产出是否使用统一工厂模式（从 `.trae/rules/`
      中读取具体工厂名）？
- [ ] 操作后刷新列表是否使用了刷新方法而非重新加载方法（从 `.trae/rules/`
      中读取方法差异）？
- [ ] 所有展示单元是否遵循响应式约定（从 `.trae/rules/` 中读取具体规范）？
- [ ] 新增样式/格式是否在正确入口文件中注册（从 `.trae/rules/`
      中读取入口文件和注册方式）？

### 维度 3：产出简洁性

> 以下检查项中的具体阈值（最大行数、重复次数等）以 `architecture-quickref.md`
> 中的"健康阈值表"为准。AI 通病提示以"AI 通病提示表"为准——审查时需对照通病表逐项自检。

- [ ] 是否有超过健康阈值中"最大行数"的产出单元（读取 architecture-quickref.md 确认具体数值，考虑拆分）？
- [ ] 是否有超过健康阈值中"重复次数阈值"的重复模式（读取 architecture-quickref.md 确认具体数值，考虑提取）？
- [ ] 是否有不足 3 次重复就被提前抽象的产出？（违反自然生长阈值——宁可重复，不提前提取）
- [ ] 是否有未被使用的引用、变量、标识符？（健康阈值中此项为零容忍）
- [ ] 是否有注释掉的产出块？（健康阈值中此项为零容忍）
- [ ] 是否有硬编码的魔法值（应考虑提取为常量/配置）？
- [ ] 是否有调试痕迹残留（健康阈值中此项为零容忍）？
- [ ] 是否对照 AI 通病提示表逐项检查了本项目对应的系统性盲区（读取 architecture-quickref.md 确认具体通病列表）？

### 维度 4：引用规范

- [ ] 跨目录引用是否使用了项目约定的引用别名系统（读取 project-rules.md 确认别名约定），而非相对路径引用？
- [ ] 同目录引用是否使用 `./` 相对路径？

### 维度 5：自然生长原则

- [ ] 修改是否在现有规则约束下生长（未破坏架构分层）？
- [ ] 修改是否优先使用现有产出单元（未重复创建等价物）？
- [ ] 修改是否遵循自底向上的顺序（先改底层再改上层）？
- [ ] 是否有"顺手优化"的范围外修改？（生长器禁止速修模式外的范围蔓延）

## 关联产出检查指南

提交前审查第 3 步"检查关联产出"的具体方法：

1. **契约变更检查**：如果修改了公开接口/契约，搜索所有引用方
2. **数据结构变更检查**：如果修改了数据层的字段映射或新增了字段，检查数据定义和迁移
3. **公共单元变更检查**：如果修改了公共产出单元或通用抽象，搜索所有引用方
4. **同名问题检查**：如果修复了一个问题，用搜索工具搜索同名字段/标识符，确认同类问题不存在于其他位置
5. **格式影响检查**：如果修改了样式变量或通用格式定义，搜索所有使用方

---

## 修复优先级

当审查发现多个问题时，按以下顺序修复：

1. **安全漏洞**（P1）— 立即修复
2. **架构违规**（P2）— 优先修复（分层越权、引用别名违规）
3. **自然生长违规**（P3）— 修正过度抽象或范围蔓延
4. **产出冗余**（P4）— 清理废弃内容、调试残留
5. **风格问题**（P5）— 命名、格式等

---

## 清理旧产出检查清单

提交前审查第 6 步"清理旧产出"的具体检查项：

1. **废弃引用**：产出单元修改后仍保留不再使用的引用语句
2. **废弃内容**：重构后旧内容仍保留
3. **废弃样式**：结构修改后未清理对应的旧样式/格式
4. **废弃标识符**：声明后不再使用的变量/字段
5. **调试痕迹**：临时调试信息残留
6. **重复逻辑**：与现有公共单元重复的内联实现

**清理原则**：

- 使用搜索工具确认零引用后再删除
- 不确定的内容先标记而非删除
- 一次清理一个类型（入口、展示、数据分开处理）
