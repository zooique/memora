# 体验评审指南

> 用于入口 11"体验评审"，从用户视角对前端交互质量、视觉一致性、用户心智匹配度进行全面评审

---

## 评审前置准备

1. 加载 `.trae/rules/frontend_architecture_rules.md` 了解前端技术栈、组件规范、样式入口文件
2. 加载 `.trae/rules/project-rules.md` 了解项目整体约定
3. 加载 `.trae/rules/architecture-quickref.md` 了解前端工厂模式、通用组件等约定名称
4. 浏览前端页面目录结构，了解实际页面数量和组件分布
5. 如果存在 `docs/创意设计单页纸.md`，加载以了解项目的核心矛盾（有助于判断 UX 设计是否匹配用户心智）

## 评审维度

1. **视觉一致性** — 设计语言是否统一（颜色/字体/间距/圆角/阴影）
2. **交互模式一致性** — 相似场景的操作行为是否可预测
3. **操作路径与心智模型** — 用户完成任务的路径是否顺畅、符合直觉
4. **状态覆盖** — 所有界面状态是否都有合理视觉反馈
5. **认知负荷** — 信息密度是否合理，用户能否一眼理解页面意图
6. **导航与信息架构** — 页面间导航和信息查找是否高效
7. **视觉审美** — 是否千树一面，缺乏项目个性
8. **Agent 信任设计** — Agent 界面的信任机制是否健全（仅适用于 Agent 产品）

> 维度 7（视觉审美）的检查清单详见 [frontend-aesthetics-guide.md](frontend-aesthetics-guide.md) 中的"千树一面检测"章节。
> 维度 8（Agent 信任设计）的规则依据详见 [ui-design-philosophy-rules.md §七](../../../rules/ui-design-philosophy-rules.md) 与 [visual-design-philosopher/SKILL.md §四](../../visual-design-philosopher/SKILL.md)。仅在 Agent 产品评审时启用。

### 维度 1：视觉一致性

**目标**：设计语言统一——颜色、字体、间距、圆角、阴影有一致规范

#### 1.1 颜色体系

- 主色 ≤3、辅色 ≤5、中性色 ≤5，同一语义使用同一颜色
- 功能色统一：绿=成功、红=错误、黄/橙=警告，不混用
- 颜色优先来自 CSS 变量/设计令牌，不大量硬编码

#### 1.2 字体与排版

- 全局统一字体族，不混用多套
- 字号层级 ≤5 级（标题/正文/辅助文），正文行高 ≥1.5

#### 1.3 间距与布局

- 使用固定间距尺度（4/8/12/16/24/32），同类型容器内边距一致
- 页面最大宽度合理（内容页 ≤1200px，详情页 ≤800px）

#### 1.4 圆角与阴影

- 小圆角（按钮/输入框）统一，大圆角（卡片/弹窗）统一
- 不同层级元素（卡片/弹窗/下拉）使用不同深度阴影

---

### 维度 2：交互模式一致性

**目标**：相似场景的交互行为可预测——A 页面学会的操作在 B 页面同样有效

#### 2.1 按钮行为规范

- 主按钮（提交/确认）与次按钮（取消/返回）视觉区分明确
- 删除、清空、不可逆操作有确认弹窗
- 提交中按钮显示 loading + 禁止重复点击

#### 2.2 表单交互规范

- 必填项有明确标识（`*` 或文字标注）
- 失焦校验 + 提交校验，错误信息显示在对应字段旁
- 选择器行为一致：下拉触发、搜索、多选操作各页面统一

#### 2.3 弹窗与对话框

- 同类型操作使用相同的弹窗打开方式，支持遮罩/ESC/关闭按钮关闭
- 宽度合理：表单弹窗 500-700px，确认弹窗 400-500px

#### 2.4 表格与列表交互

- 分页位置、每页条数、跳转行为统一
- 排序指示器位置、筛选条件布局统一
- 行操作按钮位置一致

---

### 维度 3：操作路径与心智模型

**目标**：用户完成任务的最短路径顺畅、符合"肌肉记忆"

#### 3.1 核心路径走查

- CRUD 闭环：创建→列表确认→编辑→删除，每步 ≤3 次点击
- 表单提交：成功后明确提示并回到合理页面，失败后保留已填数据
- 搜索/筛选：触发不超过 2 步，结果即时刷新，可清空

#### 3.2 路径效率

- 核心任务 ≤5 步，高频任务 ≤3 步
- 每个页面都有明确的返回/关闭路径，不存在"死胡同"
- 不出现不必要的回环跳转

#### 3.3 心智模型匹配

- 命名匹配用户语言，不使用技术术语（如"commit""persist""fetch"）
- 操作顺序符合用户心理预期，最常用信息在最显眼位置
- 图标语义准确：编辑=铅笔、删除=垃圾桶、搜索=放大镜

---

### 维度 4：状态覆盖

**目标**：所有界面状态都有合理的视觉反馈

#### 4.1 数据状态

- **加载中**：骨架屏或 loading 指示器，不"空白然后突然出现"
- **空数据**：空状态插图 + 引导文案
- **数据过多**：分页/虚拟滚动/懒加载
- **数据异常**：错误提示 + 重试按钮，不静默失败

#### 4.2 操作反馈

- **成功**：Toast/消息提示，自动消失或手动关闭
- **失败**：错误提示说明原因，保留已输入数据
- **进行中**：按钮 loading 态，禁用重复操作

#### 4.3 权限与边界

- 无权限功能不展示（而非展示后报错）
- 数值有范围限制，文本有长度限制
- 多人编辑场景有冲突提示（如项目涉及协作）

---

### 维度 5：认知负荷

**目标**：信息密度合理——用户一眼理解"页面干什么、我该做什么"

#### 5.1 信息密度

- 首屏关键元素 ≤7±2 个
- 表单 ≤15 个字段（超过时分组或分步），表格 ≤8 列
- 非列表页不超过 3 屏滚动

#### 5.2 视觉层级

- 最重要信息有最大视觉权重（大小/颜色/位置）
- 相关内容视觉聚合（卡片/分隔线/间距）
- 高级设置折叠，次要信息按需展开

#### 5.3 文案质量

- 提示文案具体（"请输入正确的手机号"而非"输入错误"）
- 按钮使用动词（"保存""删除""取消"）而非名词或模糊词汇
- 页面标题准确，面包屑路径完整

---

### 维度 6：导航与信息架构

**目标**：用户能高效地在页面间导航、找到所需信息

#### 6.1 导航结构

- 导航层级 ≤4 层，最深页面有路径指示
- 所有页面导航结构一致，当前页有高亮/激活状态
- 面包屑路径正确，可点击返回上级

#### 6.2 信息查找效率

- 数据较多的系统有全局搜索，结果可快速跳转
- 筛选条件不冗余，筛选项 ≤6 个
- 列表可跳转详情，详情可返回列表（保持筛选状态）

#### 6.3 响应式与跨设备

- 移动端（375px）：不水平溢出，关键操作可触达
- 平板端（768px）：布局合理利用空间
- 可点击区域 ≥44×44px，相邻元素间距充足

---

### 维度 8：Agent 信任设计（仅适用于 Agent 产品）

**目标**：Agent 产品的信任机制设计——确保用户敢让 Agent 做事，信任是增量建立的，不是二元授予的

#### 8.1 置信度可视化

- Agent 输出带置信度标记：高=🟢可执行 / 中=🟡需确认 / 低=🔴标注不确定
- 置信度标记位置统一（如消息右上角、工具调用卡片旁）
- 用户能根据置信度判断"什么时候该放手，什么时候该介入"

#### 8.2 逃逸舱三通道

- 每个 Agent 操作提供三条逃生通道：
  - **撤销**：30s 内可软回滚破坏性操作（操作完成后短时间内可见撤销按钮）
  - **中断**：Agent 执行中随时可停止（停止按钮常驻可见，非隐藏）
  - **覆盖**：用户可在 Agent 输出基础上修改再执行（AI 是协作者，不是决策者）
- 三通道不齐全 = 用户被迫"要么全信要么全不信"

#### 8.3 自主等级显式化

- 当前 Agent 模式（建议/执行/审批）以视觉徽章形式显示在任务旁，不埋在设置里
- 用户能扫一眼就知道 Agent 现在能做什么、不能做什么
- 信任等级与自主权限绑定：首次默认建议模式，成功 N 次后自动升级

#### 8.4 上下文感知

- Agent 建议/操作出现在正确的上下文中（inline 形式），而非凭空出现在对话框
- 例如：编辑文件时 Agent 建议出现在文件旁，而非聊天框里
- Agent 输出是"补充"而非"干扰"——不抢用户当前操作的主焦点

#### 8.5 过程透明

- Agent 执行过程有进度提示（如"3 of 7 步完成"），非黑盒
- Agent 使用的工具/上下文对用户可查（可展开查看详情）
- Agent 决策可追溯——用户能查看"为什么这么决定"的推理摘要

#### 8.6 审批三档强度

- 可逆操作（写文件/改配置）→ 软确认（30s undo）
- 破坏性操作（删除/覆盖）→ 硬确认（明确确认按钮）
- 灾难性操作（推送/部署）→ 二次确认（需打字确认）
- 不要所有操作同权重——一刀切审批 = 用户点穿所有确认

## 评审阶段聚焦

| 项目阶段 | 当前特征 | 评审侧重 | 评审深度 |
|---------|---------|---------|---------|
| 🏗️ 建设期 | 页面快速增加，组件库仍在搭建 | **维度 1（视觉一致性）+ 维度 3（操作路径）** | 严格 |
| 🌿 生长稳定期 | 核心页面完成，以优化和新增为主 | **维度 2（交互模式）+ 维度 6（导航架构）** | 严格 |
| 🍂 成熟期/维护期 | 功能稳定，历史页面积累多 | **维度 4（状态覆盖）+ 维度 5（认知负荷）** | 严格 |
| 🔄 重构期 | 大规模 UI 变更 | **维度 1+2+3** | 正常 |
| 🤖 Agent 产品 | 含 Agent 交互的产品 | **维度 2（交互模式）+ 维度 8（Agent 信任）** | 严格 |

## UX 体验问题严重程度分级

### 🔴 严重（阻塞用户操作）

- 操作路径中断，"回不去"的页面
- 提交/删除无任何反馈，用户不知道操作是否成功
- 错误提示模糊，用户无法知道怎么修正
- 关键 CTA 按钮不可见或无法点击
- 核心数据展示错误（张冠李戴）
- **[Agent] Agent 操作无中断通道**——用户被迫等待 Agent 跑完，无法中途停止
- **[Agent] Agent 操作无确认/撤销**——不可逆操作执行后无回滚可能

### 🟡 中等（影响用户体验）

- 同类型操作在不同页面交互不一致
- 空状态缺少引导，用户不知道下一步做什么
- 表单校验在提交时才触发（而非即时）
- 加载时间过长且无反馈
- 关键操作步骤过多（>5 步）
- 移动端布局断裂
- **[Agent] Agent 输出无置信度标记**——用户不知道该信还是该查
- **[Agent] Agent 执行过程黑盒**——用户焦虑"它在干嘛"
- **[Agent] Agent 建议脱离上下文**——凭空出现在对话框，与用户当前操作无关

### 🟢 轻微（影响精致度）

- 间距在相似场景中不统一
- 按钮样式在各页面有微小差异
- 图标语义勉强可用但不够精准
- 文案措辞不够友好
- 动画缺失（过渡生硬）
- **[Agent] 置信度标记位置不统一**——不同面板标记位置不同
- **[Agent] 自主等级徽章不够醒目**——用户可能漏掉当前模式

## 体验评审报告字段

报告包含以下字段，AI 根据评审结果自动生成：

- **头部**：评审日期、项目名称、评审范围（全站/指定模块）、项目阶段
- **总体评分表**：8 个维度各一个评分（/10）+ 状态标识（✅/⚠️/❌），综合评分 8+=优秀、6-7=良好、4-5=需关注、<4=需重点改进。维度 8 仅在 Agent 产品中评分
- **问题清单**：按严重程度分三组（🔴严重/🟡中等/🟢轻微），每项含问题、维度、位置、影响/建议
- **各页面评审详情**：每个被评审页面按维度给出 ✅/⚠️/❌ + 一句话小结（Agent 产品需覆盖维度 8）
- **优先行动**：按严重程度排序的改进建议列表
- **UX 亮点**：值得保留的优秀设计记录

## 评审执行策略

- **全站评审**：先全局检查维度 1（视觉一致性）+ 维度 6（导航架构）——需跨页面对比；再按页面走查维度 2-5，核心页面 100% 覆盖，次要页面抽取样本。Agent 产品额外走查维度 8（Agent 信任设计）
- **模块聚焦评审**：只评审指定模块页面，视觉一致性仍做全局检查，其他维度聚焦模块内部
- **页面抽样原则**：每种页面类型至少 1 个样本，最新修改和最常访问的页面优先。Agent 产品需覆盖至少 1 个 Agent 交互面板
