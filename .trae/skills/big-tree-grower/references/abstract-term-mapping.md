# 前置约定映射表

> 生长器各模式中使用抽象术语描述操作（如"产出单元""分层结构"），执行前必须将这些术语翻译为项目实际实现。本表定义翻译规则：抽象术语 → 查找哪个规则文件 → 映射为项目的具体名称。

---

## 核心抽象术语

| 抽象术语 | 查找规则文件 | 说明 |
|---------|------------|------|
| 产出单元 | 项目结构规范 | 项目中的最小交付单元（代码项目是文件/模块，写作项目是章节/段落，策划项目是设计文档） |
| 分层结构 | 项目分层规范 | 项目的层级组织方式（代码项目是路由→业务→数据层，写作项目是章→节→段，策划项目是系统→模块→功能） |
| 质量验证方法 | 质量保障规则 | 项目中验证产出质量的具体方法 |
| 发布流程 | 版本发布规则 | 项目发布最终产物的流程和前置条件 |
| 安全边界 | 安全规则 | 项目定义安全边界的方式和需保护的资产类型 |
| 命名约定 | project-rules.md | 项目中文件/产出单元的命名规范 |
| 版本标识 | 版本管理规则 | 项目标记版本号/版次的具体方式 |
| 任务跟踪方式 | project-rules.md | 项目中记录和跟踪待办/已完成任务的方式 |

---

## 使用方式

1. 读取 `.trae/rules/` 下的规则文件，找到上表"查找规则文件"列对应的文件
2. 在该规则文件中定位抽象术语对应的具体名称或方法
3. 后续所有操作步骤中，将抽象术语替换为项目的实际名称

> 抽象术语确保生长器流程是领域无关的——同一个"质量验证方法"在代码项目中是测试命令，在写作项目中是审稿清单，在策划项目中是评审会纪要。项目 Rules 定义"怎么做"，Skill 定义"做什么"。

---

## 领域覆盖

> 枝干 Skill 可以通过同名覆盖的方式，用本文件提供领域专属的详细映射表。当前各枝干均使用本通用版；若某枝干的领域术语差异显著（如代码项目的路由层/业务层/数据层），可创建同名文件覆盖。
