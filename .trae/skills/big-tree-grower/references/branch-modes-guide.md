# 匠码领域专属模式

以下为 codecraft 分支特有的模式入口，补充基础树 16 个通用模式之外的能力。

---

## 入口：补测试（test-coverage）

**触发**：用户说"补测试/测试覆盖/补充测试"

**目的**：扫描当前代码变更或指定模块，自动生成/补充单元测试，遵循项目已有的测试分层策略。

**前置约束**：
- 必须先读取 `.trae/rules/architecture-quickref.md` 了解项目的测试分层策略
- 必须先读取项目约定的测试目录下的现有测试文件了解测试模式和约定

**执行步骤**：

1. **加载规则上下文**：读取 `.trae/rules/architecture-quickref.md` 中"单元测试"和"测试分层策略"部分
2. **扫描变更范围**：未指定模块则扫描未暂存变更，指定模块则聚焦该模块
3. **读取现有测试模式**：扫描 `tests/` 目录了解文件命名、描述风格、导入方式、断言模式
4. **生成测试代码**：遵循项目现有测试的命名约定、描述风格和导入方式；针对业务逻辑层创建完整数据链，验证业务逻辑和错误码，每个测试函数应有明确断言
5. **运行验证**：执行项目的测试命令，确认所有测试通过；如果测试失败：区分是测试代码问题还是业务代码问题，修复后重跑
6. **生成聚焦测试建议**：输出新生成的测试文件和覆盖的功能点摘要

**输入格式**：`补测试` 或 `补测试：productService`

## 入口：测试回归（test-regression）

**触发**：用户说"测试回归"

**目的**：运行项目全部测试，对失败用例做三分类处理，修复代码回归和测试过期问题。

**执行步骤**：

1. **加载上下文**：读取项目规则了解测试策略
2. **运行全部测试**：执行项目测试命令，收集失败用例
3. **分析失败用例**：三分类——测试过期（更新测试）、代码回归（修复业务代码）、环境问题（修复测试辅助代码）
4. **修复问题**：按分类逐个修复，测试过期不改业务代码，代码回归追溯变更恢复逻辑
5. **重跑验证**：修复后重新运行全部测试，确认无新增失败
6. **归档**：无法修复的问题写入 `tasks/待完成任务.md`

**输入格式**：`测试回归`

## 入口：数据库迁移（db-migration）

**触发**：用户说"数据库迁移/加字段/改表"

**目的**：安全执行数据库结构变更，确保迁移幂等，同步更新全量建表脚本。

**执行步骤**：

1. **加载上下文**：读取项目规则了解数据库约定
2. **设计迁移方案**：分析变更需求，设计幂等迁移语句（addColumnIfNotExists 模式）
3. **执行迁移**：执行迁移语句，确认执行成功
4. **同步全量建表脚本**：更新全量建表脚本以反映最新结构
5. **生成验证步骤**：输出手动验证步骤确认迁移正确

**输入格式**：`数据库迁移：给 users 表加 status 字段`

**安全边界**（不可违反）：
- 迁移必须幂等（可重复执行不报错）
- 必须同步更新全量建表脚本
- 不删除已有字段（只新增或修改）

## 入口：排雷（plan-audit）

**触发**：用户说"排雷/沙盘推演/方案排雷"

**目的**：对已有方案文档进行逐步骤推演，识别遗漏、重复定义、冗余、覆盖遗漏、依赖顺序、边界盲区等雷区，产出优化方案。

**前置条件**：必须已有方案文档（方案更新产出或用户提供的方案文档）

**执行步骤**：

1. **加载方案文档**：读取用户指定的方案文档或最近一次方案更新产出
2. **加载项目规则**：读取 `.trae/rules/` 了解项目架构和约定
3. **逐步骤推演**：按方案中的步骤顺序逐个推演，不可跳过任何步骤
4. **识别雷区**：遗漏（缺少必要步骤/边界处理）、重复定义（多步定义相同函数/组件）、冗余（重复代码未提取）、覆盖遗漏（前后端不一致）、依赖顺序（隐式依赖导致执行失败）、边界盲区（空状态/并发/极限数据量）
5. **产出优化方案**：对每个雷区给出修正建议，产出可直接执行的优化方案（不可只报告不修正）
6. **归档**：将优化方案写入 `docs/` 或直接衔接方案更新执行

**输入格式**：`排雷` 或 `排雷：path/to/plan.md`

**安全边界**（不可违反）：
- 必须基于已存在的方案文档执行
- 排雷后必须产出优化方案（不可只报告不修正）
- 排雷不可跳过方案的任何步骤
