# 台账归档纪律（内核发版 Step 3 详解）

> 真源 = `tasks/archive/README.md`（七条纪律，2026-10-09 确立 · 用户拍板）。本文件是其针对「内核发版」的提炼版，冲突以真源为准。

## 七条纪律（一发一版，归一次档）

1. **一发一版，归一次档**：每真发一版（内核 `npm publish` / 宿主 `vsce publish` + tag 跑完）后，把该版**已关闭**项迁入 `tasks/archive/` 目录。
2. **内核 / 宿主分离**：文件名 `<version>-<kernel|host>.md`，双线互不混（ADR-033 双轨）。
3. **只迁已关闭项**：主台账（`待完成任务.md`）的开放项、观察项、明确不做项**一律留主台账**；只搬 ✅ 销项 / 证伪关闭 / 全案闭合 的收据，不丢「开放信号」。
4. **版本号以真值为准**：以 `package.json` / `CHANGELOG` / registry 实值为准。条目 **ID 沿用不改**（防跨文档引用断裂），文件头注明「ID → 版本」映射即可。
5. **未真发标「待上架」**：版本已定档但未实际上架时标「待上架」而非「已发布」，发版动作跑完后再订正（实证：0.1.0 宿主曾标「待上架」，真发后随归档一并订正）。
6. **单台账 + 按版本归档**：主台账唯一 = `待完成任务.md`；条目销项后标 ✅ 留原区在册，**每真发一版**时随版本号整区迁入 `tasks/archive/<version>-<kernel|host>.md`。销项不即迁、发版才归档；新销项**不再写入**历史合集。
7. **主台账留指针**：迁出后在原位置留一行 `→ 见 tasks/archive/<file>.md`，保留「曾经在此」的溯源。

## 归档机械化（scripts/archive-kernel-release.mjs）

手工逐条剪切易漏字、易错 ID。该脚本按 `^- **<ID>**` 锚点从 `待完成任务.md` 切块迁移：

- 输入：`--version X.Y.Z` + `--ids ID1,ID2,...`（**关闭项 ID 由人判，脚本只做机械切块**）。
- 行为：① 把命中的 ✅ 条目整块搬到 `tasks/archive/<X.Y.Z>-kernel.md`；② 主台账原位替换为指针行 `→ 见 tasks/archive/<X.Y.Z>-kernel.md`；③ 归档文件头写「待上架」。
- 安全：默认 `--dry-run` 只打印将迁移的条目与替换后的主台账预览；加 `--apply` 才落盘。**首次使用须 `git diff` 人工核对逐字节无损后再提交**。
- 边界：条目块 = 从 `- **<ID>**` 行到下一个 `- **` 行（列 0）或文件末；子缩进 `-` 属条目内容，一并搬走。

## 区级完整性自检（归档纪律之上的操作闸，2026-10-23 增补）

> 七条纪律的真源 README 不动；本节是脚本白名单模式的**配套人工闸**，内核 / 宿主两线通用。

- **成因**：`archive-kernel-release.mjs` 按 **ID 白名单**跑——白名单靠人肉编，版本区是**混合工作区**（功能批之外常混入审计批 / 发布链缺陷批 / 旧纪法规遗留原文），只扫功能段必漏。实证：0.2.0 宿主区漏 45 条、5.0.0 内核区收口无指针 22 条（欠账 `ARCH-DRAIN-1`）。
- **操作**（apply 后、commit 前必做）：扫该版本区**全部**条目行逐条三态分诊——有 `→ 见 tasks/archive/` 指针 = 已迁 ✓；开放态（⏳ / ⏸ / 🟡 / 👁 / 📝）= 留册 ✓；**已收口（✅ / ❌ / 🟢 / 证伪）无指针 = 欠账** ⇒ 当场补进 `--ids` 重跑或登记欠账，**禁止沉默跳过**。
- 🔴 **计数判据 = 当场重扫实测**，不采信此前任何清点快照：快照自身会算术不闭合（`ARCH-DRAIN-1` 实证：「收口无指针 45」vs 分诊 A5 + B38 = 43 差 2 条），且落定后台账继续编辑即漂移（2026-10-23 当日实测与快照差 ~11 条）。欠账条目里的分诊数字只当**线索**，不当**判据**。

## 主台账状态词口径

- 归档时（tag 前）：写「待上架」。
- 发版跑完（Step 5）：订正为「已发布」。
- 绝不写「已发布」于未真发状态（tarball 不可变，写错即永久瑕疵）。
