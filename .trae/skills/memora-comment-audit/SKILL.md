# memora 注释审查与剪枝

> **本文件只放可复用方法**。批次状态、提交号、文件清单、行数一律不写在这里——
> 那是进度台账的内容，落在 `.trae/documents/` 的 `注释线进度-<范围>-<YYYYMMDD>.md`。
> 台账会过期，方法不会。引用任何「当前还剩几批 / 几处」必须现场实测，本文件不提供。

> **与 `memora-doc-reality-audit` 的分界**（真源：`.trae/skills/memora-doc-reality-audit/SKILL.md`）：
> 那个技能审「文档主张 vs 仓库事实」，本技能审「代码注释 vs 代码事实」。
> 交汇处是它的 E 类（注释声称「已持久化 / 已落盘」但承载结构不存在）——遇到这类直接按 E 类判据走，不要在本技能另立一套。

## 何时用

- 全库或按模块的注释审查、注释剪枝
- 怀疑注释与代码不符：断言了不存在的行为、归属、条件、范围、时序
- 注释复述代码，噪音大到影响阅读
- 要给注释线切领域、分批、排期，或每批结清后收尾
- 交接给零上下文的新会话：先读本技能拿方法，再读台账拿进度

**不适用**：删死代码、去重、提取公共层（那是代码剪枝，走 `.trae/skills/big-tree-grower/references/pruning-guide.md`）；纯文档/README 校对（走 `.trae/skills/memora-doc-reality-audit/SKILL.md`）。

## 四类判据

判别顺序只有一句：**删掉这条注释，读者会失去什么？**

| 类别 | 一句话判据 | 处置 | 真实案例 |
| --- | --- | --- | --- |
| **可删·复述代码** | 注释只是把下一行代码翻译成人话，删掉后信息零损失 | 删；但保留 JSDoc 里的契约部分（参数语义、抛错、副作用） | 内核 `src/utils/`、provider 四件套、`src/logging/` + `src/config/` 的批量复述注释 |
| **必改·假事实** | 注释断言了一个**可验证的事实**，取证不成立 | 不删，按代码改写；保留原句想表达的意图 | `D29 唯一生产点就是这里`（真正唯一生产点是 `resolveImageName`，且是无条件调用）；`upgradePendingRow` 符号不存在，实为 `upgradePendingToolRow` |
| **必须留·why / 边界 / 踩坑** | 解释为什么这样写、边界在哪、踩过什么坑，代码本身表达不了 | 一字不动；缺边界的可补，但不重写 | `commentHygiene` 头部「行号没有 SSOT，失效是必然」；「内核 5.0.0 整删」核到 CHANGELOG 与 tag 后保留；双层判空的分工（原注释没写，属于该补的边界） |
| **待定** | 事实核不动：涉及外部历史、产品意图、口径未拍板 | 不猜、不删、不硬改；进台账「待拍板」，保持原文或只做最小改写 | 墓碑注释（`constants.ts` / `protocol.ts` 若干处）；历史计数保留数字还是删数字 |

补充判据：

- **「看起来更准确」不是改写理由**。改写必须能指向代码里的落点（定义、调用点、配置值、测试断言），指不到就归「待定」。
- **必改项优先于可删项**。同一段里既有复述又有假事实，先订正事实，再决定剩下的复述是否删。
- **不要为了删而删**。删注释不产生行为收益，收益是「读者不被误导」；删不出这个收益就不动。

## 三档取舍

**为什么必须有这一档**：全库逐行排不完。体量以万行计、注释行占比很高，逐行审的成本远超收益；
低风险区（纯 DOM、CSS）的主要问题是噪音（复述），不是误导（假事实）。把预算压到「必排」档，才能把假事实清零。

| 档位 | 覆盖对象 | 排法 |
| --- | --- | --- |
| **必排** | 跨层契约（protocol / DTO / host↔kernel）、状态机与取消、上限与阈值、跨进程消息形状、持久化格式、错误分类与文案归属 | 逐行排，每条事实都要取证 |
| **抽查** | 纯 DOM 构造、CSS、纯格式化、字符串拼接 | 抽读 + 只查事实性断言（数字、来源、条件），不逐行抠措辞 |
| **跳过** | 生成物（dist / 构建产物）、纯类型再导出、测试夹具 | 不排；改了也会被生成覆盖，夹具注释不是产品契约 |

分档发生在**排雷阶段**，不是写盘阶段。分错档的代价是漏掉契约区的假事实，或把预算烧在 CSS 上。

## 线数选择

| 风险 | 线数 | 形态 |
| --- | --- | --- |
| 高风险（必排档） | **三线** | 排雷（只读盘点、取事实）→ 写盘（只改注释，不动代码/测试/文档）→ 独立复核（只读核每条事实到行，**复核方 ≠ 写盘方**，另开会话） |
| 低风险（抽查档） | **两线** | 只读线（排雷 + 复核合并）+ 写盘线；复核仍由**非写盘会话**做，只是降为抽查 |

### 排雷与复核可以合成一环

两者都**不写盘**：同一个只读会话可以先读完 A 批 diff 出复核结论，顺手出 B 批排雷清单。
合并没有产生「自己给自己签字」——签字的是写盘方，复核方仍然是另一个会话。

### 复核不能省

实证规律：**本轮已结清的每一批，写盘方都新造了 1 到 3 处「看起来更准确」的假事实**，全部由独立复核抓出。已发生的形态包括：
字段归属写错（把宿主派生说成内核字段）、否定式断言写反（「无 aborted 生产者」）、
引用不存在的符号、把无条件调用写成兜底、把另一条消息通道的来源安到当前字段上。

写盘方自证不算证据。仓库守卫只拦「行号引用」，`tsc` 只拦代码里的符号；注释里写一个不存在的符号名，两者都不会红。
而「符号存在但归属错」更没有任何自动闸能拦——这一类比符号拼错更危险，因为它能编译、能过测试、能骗过读者。

## 单批作业循环

1. **切领域 + 实测体量**：按目录/职责切，行数用 `(Get-Content <file>).Count` 现场量。
2. **排雷**：逐文件出清单——符号、当前注释、判据归类、拟处置、取证命令/落点。
3. **写盘**：只改注释。一次一批（1–3 个文件，按逻辑单元切，不硬凑），批太大复核会失焦。
4. **复核**：逐条事实回源，不读写盘方的说明，直接看 diff 与代码。低风险批可把本步并进只读线。
5. **提交**：逐文件 `git add <path>`，提交信息不写处数统计。
6. **更新台账**：该批状态改结清，记「抓到了什么」；新发现的不属于本线的挂账单列。

## 硬纪律

1. **任务书里的符号名也按待核处理**。找不到定义就报「符号不存在」，不要照着写。实例：`upgradePendingRow` 实为 `upgradePendingToolRow`。
2. **符号存在但归属错更危险**。发现指令与代码不符时，**直接按代码写**，并在回报里说明「原话是 X、改成 Y、依据是 Z」；不要照抄错误原话再附一段说明。
3. **行数口径**：用 `(Get-Content <file>).Count`，不用 `Measure-Object -Line`（后者不计空行，同一文件可差出上百行，排雷方曾因此把 4,122 行读成 3,997 行）。
4. **注释引内核实现**：写符号名 + 文件，不写行号。内核守卫 `src/__tests__/commentHygiene.test.ts` 扫**注释位**，禁三类形式（跨文件 `文件.ts:行号`、文件名 + 空格 + 行号、裸写 `L` + 两位以上数字）；宿主守卫 `hosts/memora-vscode/src/webview/__tests__/commentHygiene.test.ts` 扫宿主 `src/` 的**全部位置（含字符串）**，禁 `.ts:行号`。
5. **提交信息不写处数 / 条数统计**；commitlint 正文单行 ≤ 100 字符。
6. **逐文件 `git add <path>`**；禁 `git add -A` / `git add .` / `git commit -a` / `git stash`；禁 `--no-verify` / `LEFTHOOK=0` / 降覆盖 / 加 skip / 放宽断言 / 改阈值。闸红就查原因。
7. **写盘边界**：只改注释，不动代码 / 测试 / 文档；不碰 `lefthook.yml`、`.github/workflows/**`、`.trae/rules/**`、`role-packs/**/manifest.json`。
8. **共享工作区**：多线并行时 `index.lock` 与门禁可能互相干扰；发现锁先等释放，没有进程证据不删锁。

## 假事实高发模式

按出现频率与危害排序。每条都要能指出「断言 → 代码事实 → 取证动作」。

| # | 模式 | 真实案例 | 取证动作 |
| --- | --- | --- | --- |
| 1 | **唯一来源说过头** | `D29 唯一生产点就是这里`——实际唯一生产点是 `resolveImageName`，且是无条件调用 | grep 全部构造/写入点，确认有没有重放、中断、兜底等旁路 |
| 2 | **条件说窄** | 「仅未保存修改」——实为脏 / 未命名 / 工作区外三分支 | 把 if 链每个分支列出来，逐支对照 |
| 3 | **范围说大** | 「代码内出现即红」——实为仅字符串字面量 | 确认守卫的扫描面（注释位 / 代码位 / 字符串）与正则本身 |
| 4 | **引用不存在的符号** | `upgradePendingRow` | grep 定义；找不到就写「符号不存在」，不要顺着编 |
| 5 | **引用存在但归属错** | `chatPanel.mustInjectDocBody` 实为 `activeFileTracker` 的；`hasFailure` 把宿主派生说成内核字段 | 跳到定义处，确认所属模块与依赖方向 |
| 6 | **功能时态错** | 「等正式版接入落盘与预览后」——实际已接入 | grep 生产调用点；有调用点就是已接入，不看注释自述 |
| 7 | **配置数字过期** | 「`max-lines` 基线 6694」——实为 4,200，已过期两代 | 读当前配置/脚本，不抄旧注释 |
| 8 | **终态 / 幂等说过头** | 终态写入点不止收场消息（还有重放与中断轮）；「`seq` 幂等」被扩到 metrics（段级求和不可重复调用） | 列出全部写入点与调用点，不只看出现在主路径的那一处 |
| 9 | **自指断言** | 「没有任何现有测试会红」 | 跑测试，或去掉断言验证；自证不算 |
| 10 | **所有权误导** | 「内核镜像」把宿主派生说成内核产出 | 看定义位置 + 依赖方向；跨包时看 import 边界 |

共性：**假事实通常不是凭空编的，而是把一个局部观察放大成全局结论**。
所以取证动作统一是「把观察面扩到全库，再决定这句话能不能写」。

## 收尾

- **进度台账**落在 `.trae/documents/`，命名 `注释线进度-<范围>-<YYYYMMDD>.md`，形态与既有托管进度文档一致：
  任务口径 → 领域推进表 → 批次表 → 每批抓到什么 → 实证规律 → 待拍板 → 挂账 → 踩坑与新增纪律 → 收尾状态。
- **每批结清后**更新台账：该批标 ✅、记提交号、记抓到的假事实类型；不要攒到最后一次性补。
- 台账里出现行号、提交号、体量数字时标注**落笔时的 HEAD**，明示是历史快照；引用前重新实测。
- 新踩到的坑先写进台账「踩坑与新增纪律」；**只有可复用的方法才回写本技能**，一次性的现场细节留在台账。
