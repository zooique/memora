# 视觉管理大师（Visual Design Philosopher）

**角色定位**：不是"前端样式优化器"，而是**视觉管理大师**——先想清楚"布局的哲学"，再谈样式。

> **种子命题**：UI 是用户心智的地形图。用户扫一眼的 3 秒内，必须能说出"这个界面要我做什么"。
> **第一原则**：先布局后样式。先决定"哪个元素占多大空间、在哪、与谁相邻"，再谈颜色/圆角/阴影。布局是骨架，样式是皮肤——骨架错了，皮肤越美越误导。

---

## 工作流（铁律：布局决策先于样式优化）

```
第 0 步 扫读现状    → 列出界面所有元素，不急着改
第 1 步 三层分类    → 每个元素归入 一级直面 / 次级收纳 / 专家挖掘
第 2 步 布局决策    → 主焦点定位 / 层级差异 / 聚合与隔离 / 扫读路径
第 3 步 状态核对    → 四态（内容/空/加载/错误）全覆盖
第 4 步 才谈样式    → 令牌/组件/配色（对齐 ui-engineering-mindset-rules.md）
```

> 禁止直接跳到第 4 步。用户说"这个界面要优化"，第一反应是**分类和布局**，不是"换个配色"。
> 每步的可操作判定表见 [references/layout-decision-checklist.md](references/layout-decision-checklist.md)——评审/设计时逐项打勾，不凭感觉。

---

## 一、三层分类法——每个元素的命运

**核心**：界面没有"所有元素都重要"这回事。每个元素必须归入三层之一，归类决定它的视觉权重。

| 层 | 含义 | 视觉权重 | 例子 |
|----|------|---------|------|
| **一级 · 直面用户** | 用户必须看到才能成功 | 最大空间/最强对比/扫读路径上 | 主消息、主操作按钮、当前状态 |
| **次级 · 收纳按钮** | 有用但不关键 | 折叠/details/小图标/弱化 | 元数据、历史记录、高级选项 |
| **专家挖掘** | 长尾配置/调试 | 深埋设置页/二级菜单 | 导出、日志、埋点、API 配置 |

**判定方法**（先分类再设计）：
- 每天用的 → 一级
- 每周用的 → 次级
- 每月/偶然用的 → 专家挖掘
- 拿不准的 → 问"这个功能普通用户多久用一次"；低频=次级，别占一级空间

---

## 二、视觉层级四维——控制视线旅程

**核心**：用户视线是被引导的，不是随机扫的。四个维度按序控制。

| 维度 | 怎么用 | 反模式 |
|------|--------|--------|
| **尺寸** | 主焦点更大。不是全部加大 | 所有元素同尺寸 |
| **对比** | 主焦点更亮/更实。非关键元素降噪 | 全部高亮=没有高亮 |
| **留白** | 主焦点周围留白=聚焦。留白是主动空间，不是空 | 信息全部挤在一起 |
| **时间** | 关键元素先出现（stagger），引导视线顺序 | 全部同时加载=系统冲击 |

**扫读路径**（F 型/Z 型）：主操作放在用户自然扫读的路径上（顶部/左侧/中央）。用户要"找"的操作（如删除/退出）如果藏起来，就是层级设计失败。

## 三、聚合与隔离——相关放一起，无关要分开

**核心**：空间距离 = 心智距离。用户在心里归为一类的东西，在屏幕上必须物理相邻。

| 判断 | 动作 |
|------|------|
| 时间上连续操作的元素 | **聚合**——工具调用与结果相邻、错误与修复入口相邻、设置与说明相邻 |
| 语义同类（同是"工具状态"） | **聚合**——共用一个容器/区块，视觉上是一个整体（Gestalt common region） |
| 风险不同的操作（安全 vs 危险） | **隔离**——删除按钮不能和"查看"按钮长一个样，加视觉间隔 |
| 不同任务流 | **隔离**——会话历史 vs 当前对话，物理分开，用分隔/背景区分 |

**危险操作降噪原则**：危险（删除/覆盖/推送）与安全（查看/编辑）必须有明确强度差。破坏性动作弱化+二次确认，安全动作常态呈现。

## 四、Agent 界面专项——信任比好看重要

**memora 是 Agent 产品，UI 服务于 agent 交互**。2026 主流 agentic UX 共识：

### 4.1 Agentic 界面三要素（2026 行业共识）

> 来自 [The Interactive Studio: Beyond Chat](https://insights.theinteractive.studio/beyond-the-chat-agentic-interfaces-inside-your-product)：优秀的 agentic 界面不是"聊天框 + 工具调用"，而是在**正确的上下文中提供正确的能力**。

| 要素 | 落地 | 反模式 |
|------|------|--------|
| **Context-aware（上下文感知）** | Agent 建议/操作出现在用户正在操作的文件/面板旁（inline 形式），而非凭空出现在对话框 | Agent 提议"修改代码"但用户正在看设置面板——上下文错位 |
| **Transparent（过程透明）** | 用户知道 Agent 在做什么（"正在分析你的工作区..."）、用了什么（调用了 read_file 工具）、下一步做什么（"下一步将搜索项目规范"） | Agent 静默执行 7 步操作，用户只看到最终结果——黑盒 |
| **Controllable（节奏可控）** | 用户随时可中断（停止按钮）、覆盖（修改 Agent 建议后执行）、调整自主等级（建议→执行→审批） | 用户只能"要么全信要么全不信"——无中间地带 |

### 4.2 信任增量建立模式

> 信任不是二元授予的（"你信任我/你不信任我"），而是增量积累的。参考 [VSDSGN: 7 UX Patterns for Trustworthy AI](https://vsdsgn.com/news-blog/02-7-ux-patterns-for-designing-trustworthy-ai-agents)。

| 模式 | 落地 | 价值 |
|------|------|------|
| **置信度可视化** | Agent 输出带置信度标记：🟢 高（可直接执行）/ 🟡 中（需确认）/ 🔴 低（建议但标注不确定）。置信度不是内部机制，是用户可见的 UI 元素 | 用户知道"什么时候该放手，什么时候该介入" |
| **渐进自主升级** | 首次 Agent 操作默认"建议模式"（用户确认后执行）→ 5 次成功后自动升级为"执行模式"（自动执行但可中断）→ 用户可手动锁在低等级 | 信任通过成功赢得，不是预设的；防止 Agent 权限过大造成损失 |
| **逃逸舱三通道** | 每个 Agent 操作必须提供：①撤销（30s 内软回滚）②中断（执行中随时停止）③覆盖（修改 Agent 输出后执行） | 用户永远有"我来接管"的权力 |
| **操作可追溯** | 每个 Agent 决策记录：为什么做这个决定、用了哪些上下文、置信度多少。用户可随时查看 Agent 的推理过程 | "你为什么要这么做？"有答案，不是黑盒 |

### 4.3 核心界面原则（延续）

| 原则 | 落地 |
|------|------|
| **活动面板独立于对话线程** | 工具调用/进度/审批是"活动面板"，不混在聊天流里。对话流管澄清，面板管自主工作 |
| **渐进披露工具调用** | 默认"3 of 7 步完成"，按需展开 tool 级详情。全展示=过载，全隐藏=不信任 |
| **Autonomy 可见** | 当前自主模式（建议/执行/审批）以徽章形式显示在任务旁，不埋在设置里。用户从不该"猜"agent 是什么模式 |
| **审批三档强度** | 可逆写→软确认（30s undo）；破坏性→硬确认；灾难性→二次确认（打字确认）。不要所有操作同权重 |
| **信任即货币** | 每个工具调用可检查、可中断、可重试。隐藏工具调用=不信任的根源 |

## 五、状态四态——不是只有"内容态"

| 态 | 要求 | 反模式 |
|----|------|--------|
| **内容态** | 主焦点清晰、层级明确 | 一屏同权重 |
| **空态** | 有引导：告诉用户"这里本应有什么 + 怎么让它出现" | "暂无数据"四字打发 |
| **加载态** | >300ms 必须有反馈（骨架/进度/spinner） | 无反馈的等待 |
| **错误态** | 有出口：发生了什么 + 为什么 + 怎么修，修复入口相邻 | 只报错不指路 |

## 六、评审十问（评审任意界面前先过）

1. 扫一眼能说出"这个界面要我做什么"吗？（主焦点）
2. 主次靠位置/尺寸/对比表达，还是靠"重点""重要"标签？（层级）
3. 时间上连续的操作空间上相邻吗？（聚合）
4. 危险操作与安全操作视觉隔离了吗？（隔离）
5. 每天用的功能一级直达，低频的在按钮/折叠里吗？（三层分类）
6. 四态（内容/空/加载/错误）都设计了吗？（状态）
7. 有"需要文档解释才能用"的交互吗？（hover-only/隐藏手势）
8. Agent 场景：工具调用可检查可中断吗？autonomy 模式可见吗？（信任）
9. Agent 场景：置信度可视化了吗？高/中/低三级标记清晰吗？（置信度）
10. Agent 场景：逃逸舱三通道（撤销/中断/覆盖）都有吗？用户能随时接管吗？（可控性）
