# 删除会议确定性预置，任务表收敛归 LLM 通道

## Context

用户提出：任务表是**通用能力**（多步任务 / 会议 / 续跑），小组会议只是借用它。当前 `prepare.ts` 用确定性守卫（`hasInflightPlan`）+ `tryBuildMeetingPlan` 自动预置会议任务表，这造成两个问题：

1. **两个写点对「覆盖」语义不一致**：LLM `task_table_write overwrite` 无条件覆盖；而 prepare 会议预置在残留任务表时会拦截，导致「开会不建表」（用户实测痛点）。
2. **场景特化补丁**：预置机制是会议专属越权，违背 SSOT 与自然生长。

**决策**：删除「小组会议」的确定性任务表自动预置，改由 LLM 经 `task_table_write` 自主建表/覆盖——写点收敛到唯一 LLM 通道。（用户已确认**接受回归风险**：ADR-028 前次补记曾记软指令触发「时灵时不灵」，本次彻底删确定性。）

**删除边界（用户已确认：只删自动建表层）**：保留 `PlanStep.rolePack` 表层装配 + `buildTeamContextBlock` 组员名单注入 + `refreshAssemblyForRolePack`（会议执行骨架）；删 prepare 预置块 + `tryBuildMeetingPlan` + `taskLoopLimit` 链。

## 二、`buildTeamContextBlock()` 新文案

方法体与上方注释统一改为「指挥 LLM 用 task_table_write 自主建表」，给出强指令 + 明确示例（比软指令强、可复现）：

```
【小组会议角色（组长：${activePackName}；组员：${members.join(' / ')}）】
用户以「小组会议：主题」发起时，系统不再自动预置任务表：
请立即用 task_table_write 为本次会议自主建表——每位组员各建一步发言，并在此步声明 rolePack=对应组员（执行到该步时切换为该组员视角作答）；
最后额外建一步汇总，不声明 rolePack（回到组长视角收尾）。
建表示例（主题为 X）：
  1. description='组员A 发言：X'  rolePack=组员A
  2. description='组员B 发言：X'  rolePack=组员B
  3. description='汇总各方观点：X'（无 rolePack）
随后按任务表逐项执行，每完成一步用 task_table_update 将该步标记 done 或 blocked。
```

要点：把「rolePack=组员」与「逐成员视角切换」因果写进提示，避免模型只建表不声明 rolePack 导致装配不切换（对抗 ADR-028 软指令失败的关键）。
