# 草稿页加载模型列表与技能清单 —— 实现方案

## Context（为什么改）

真机现象：VS Code 启动后若落在**草稿页**（`lastDraftPage` 标记为真，或本工作区无任何历史会话），底部模型选择器与输入区技能下拉都是空的；切到任一历史会话立刻恢复。

根因（已核实，不需再排查）：

- `chatPanel.replaySession()` 在 `isDraft` 分支只调 `this._draft.replay(true)` 就 `return`，跳过了 `pushProviders()` / `pushSkillList()` / `pushRolePacks()` 等推送。
- 草稿态**按设计不装配 Agent**（`ensureAgent()` 与 `performAgentAssembly()` 在 `isDraft` 时早退；红线见 `webview/helpers/draftSession.ts` 头注释）。而技能清单的唯一聚合入口 `listVisibleSkills` 入参是 `agent`，因此"不装配 Agent"直接把技能清单也挡掉了。
- 模型列表 `pushProviders()` 只读 `ProviderStore`，**不依赖 Agent** —— 它为空纯粹是"没被调用"。

目标：草稿页同样显示「设置里已配置的 LLM」+「草稿默认/已选角色包的内置技能 + 全局技能（内置/用户/项目）」，供用户选完再开正式会话。

红线（不改）：草稿仍不装配 Agent（无会话可绑，装配会带锁/写盘/绑错会话的副作用）；不在草稿分支复制一份推送逻辑。

## 方案（SSOT / 自然生长）

把「配置面」与「会话面」拆开：配置面（模型 / 技能 / 角色包目录）**不依赖会话**，草稿与真会话各自用**同一份聚合函数**，差异只在"技能源从哪来"。

### 1. 内核：导出一个既有类（一处）

- `src/index.ts`：新增 `export { SkillManager } from '@/skill/skillManager.js';`
  - 先例：`RolePackManager` 已为「宿主独立编目」导出，宿主 `extension/host/rolePackCatalog.ts` 已在用 `new RolePackManager(configDir)` 做无 Agent 目录读取。
  - 不改任何内核行为，只开放构造面。

### 2. 宿主：把"无 Agent 技能源"做成可注入能力

- `src/extension/host/rolePackCatalog.ts`
  - 抽 `createRolePackLoader(dirs)`：返回 `(activeName?: string) => Promise<RolePackManager | null>`，加载序列与现有 `createRolePackCatalogReader` **完全一致**（内置 → 用户 → 项目，最后 `load(activeName)` 激活草稿角色包）。
  - `createRolePackCatalogReader` 改为复用该 loader（消除同一加载序列的第二份拷贝）；`attachRolePackCatalog` 形状不变，loader 由装配点的 `DraftConfigSurface` 直接使用。
- `src/extension/host/skillAggregation.ts`
  - `SkillAggregateContext.agent: Agent` → `Pick<Agent, 'skills' | 'rolePackManager'>`。
  - 调用点零改动（真 Agent 天然满足），草稿可传 `{ skills, rolePackManager }`；`resolveSkill` / `skillPromptFor` 等仍只收完整 `Agent`，不扩散。
  - 模块头补一句：草稿页（无 Agent）用独立管理器提供同一份聚合源。

### 3. 宿主：新增草稿配置面聚合 helper

- 新增 `src/webview/helpers/draftConfigSurface.ts`
  - `buildDraftSkillList(deps): Promise<SkillDto[]>`：
    - 用内核 `SkillManager(configDir)` → `load()`（内置）→ `setDisabledSkills(disabledSkills)` → `loadExtraDir(userSkillsDir,'user')` → `loadExtraDir(projectSkillsDir,'project')`（顺序与 `extension/host/assemble.ts` 装配期逐字一致，后加载者胜）。
    - 用注入的 `loadRolePackManager(rolePackName)` 取草稿角色包管理器。
    - 调 `listVisibleSkills({ agent: { skills, rolePackManager }, configDir, userSkillsDir, projectSkillsDir })`（**同一个去重/排序/禁用标注真源**）。
  - 依赖全部注入（dirs / 角色包加载器由宿主装配点提供；禁用集走 `skillSync.readDisabledSkills` 唯一读点）。
  - 失败降级：任一源构造失败时该源为空，不清屏、不报错（配置面读不到 ≠ 会话坏了）。
  - 另导出 `DraftConfigSurface` 控制器（代际守卫 + 是否草稿判定都在此），面板只持一个 `push` 回调。

### 4. 宿主：面板与装配点接线（面板只加薄接线）

- 装配点 `extension.ts`：构造 `DraftConfigSurface`（草稿态与角色包名读面板两个既有 public 方法，目录每次现读信任门），`chatProvider.setDraftSkillPush(...)` 注入。
- 面板 `chatPanel.ts`：新增 `setDraftSkillPush` / `postSkillList`（唯一投递口）、`_pushConfigSurface`（模型列表 + 技能清单）；`replaySession()` 草稿分支与 `newSessionFromCommand()` 都不再各写推送，统一走 `DraftSessionController.project()` 的 `pushConfigSurface` dep。
- `setDraftRolePack()`（设置页把角色包设为当前）：选中后补一次 `_pushDraftSkills()`，让技能清单跟随角色包切换。
- `refreshSkillList()`：草稿且无 Agent 时补走 `_pushDraftSkills()`（否则在草稿页改 `memora.disabledSkills` / 重载技能，下拉不刷新）。
- 会话态 `pushSkillList()` / `pushRolePacks()` / `pushProviders()` **一行不改**。

### 5. 文档与台账

- `CHANGELOG.md` 的 `[Unreleased] · 内核` 与 `[Unreleased] · 宿主` 区各登记一条（内核记"导出 SkillManager"，宿主记"草稿页加载模型与技能"）。
- `hosts/memora-vscode/CHANGELOG.md` 是生成物（不入库），发版/打包时由 `scripts/gen-changelog.mjs` 从根 CHANGELOG 再生，不手工编辑。

## 明确的边界（不做）

- 不为草稿装配 Agent，不自动创建空会话记录（2026-11-07 用户拍板）。
- 不改草稿页的 `chat_role_packs`（角色切换入口在独立「角色」视图；本次只补模型 + 技能两条清单）。
- 不动 `postCapabilityBadge` / 历史占用环的草稿归零语义。
- 不新增协议 op / 消息类型：复用既有 `chat_providers` / `skills_loaded`。

## 验证

1. 内核构建（宿主 test/runtime 读的是内核 `dist`）：仓库根 `npm run build`。
2. 新增单测 `src/webview/__tests__/draftConfigSurface.test.ts`：临时目录造内置/用户/项目技能 + 角色包技能桩，断言四源合并、同名去重顺序（角色包 > 项目 > 用户 > 内置）、禁用标注、角色包缺失时降级为空而不抛。
3. 扩 `src/webview/__tests__/chatPanelHistory.test.ts` 的草稿用例：注入 `setSkillDirs` + `setRolePackLoader` 桩，驱动 `newSessionFromCommand()` 与 webview ready，断言草稿态收到 `chat_providers`（非空）与 `skills_loaded`（非空），且 `agentFactory` 仍零调用（红线不破）。
4. 宿主受影响测试：`hosts/memora-vscode` 下 `npm run test -- src/webview/__tests__/chatPanelHistory.test.ts`（或 `npm run test`）。
5. 编译与门禁：宿主 `npm run compile`、`npm run lint`（`chatPanel.ts` 有效行须仍 ≤ 2200）。
6. 真机（可选）：F5 启动 → 停在草稿页 → 底部模型下拉有设置里的 LLM、技能下拉含草稿默认角色包技能与全局技能；切历史会话后清单仍正确；点「＋」回草稿后清单不丢。
