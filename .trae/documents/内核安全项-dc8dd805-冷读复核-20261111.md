### 2. fail-closed 真生效 —— **不通过（必改）**

`src/agent/builtinTools.ts:1006-1009` 原文：

```ts
const declared =
  definitions?.find((t) => t.name === name)?.diskWrite ??
  ALL_BUILTIN_TOOL_DEFS.find((t) => t.name === name)?.diskWrite;
return declared ?? 'opaque';
```

- 未知工具（两处都找不到）⇒ `'opaque'`：成立。
- **漏声明的自定义工具，若名字与条件内置工具重名 ⇒ 回落取到内置声明 `'none'`**，不是 `'opaque'`。
  条件内置仍为 `'none'` 的三个：`web_search`（`builtinTools.ts:212`）、`web_fetch`（`:371`）、`search_project`（`:462`）。
  （`run_code` 是 `'opaque'`，回落也安全。）

该分支**可达**，证据链：
1. `builtinTools.ts:985-990`：这三个工具在 `BUILTIN_TOOLS` **之外**，只在 `ALL_BUILTIN_TOOL_DEFS` 里。
2. `src/agent/toolExecutor.ts:838` 只拦 `BUILTIN_TOOLS.some(...)`；`845-849`/`851-855` 只在 provider 已注入时拦 `web_search`/`web_fetch`；**`search_project` 无任何重名拦截**。
   即 `843-844` 注释明写「未注入时宿主可自由注册自己的 `web_search` 实现」——这是被鼓励的路径。
3. `src/agent/assembler.ts:646`：`toolDefinitions: toolExec.list`；provider 未注入时 `list` 里就是那条**未声明**的自定义定义。
4. 于是 `definitions.find(...)` 命中它、`?.diskWrite` 为 `undefined`，`??` 继续回落 `ALL_BUILTIN_TOOL_DEFS.find(...)` → `'none'`。

后果：该自定义工具被当作只读 ⇒ 绕过写串行闸、写后缓存失效、宿主写前快照，且 `tool_start` 不带 `diskWrite` 字段（`loop.ts:2202`）。

### 3. 19 个 `'none'` 逐个核 —— 通过（无一个写项目磁盘）

口径说明：`WriteCapability` 的定义是「不改**项目磁盘**」（`builtinTools.ts:12-16`），不是「零 fs 系统调用」——日志、provider 内部缓存对所有工具都写，按「任何 fs 写」判会让 19 个全不合格，不是该能力位的作用域。

- `task_table_write`（`toolExecutor.ts:1547-1579`）→ `sessionManager.writePlan`（`sessionManager.ts:546-581`）；`task_table_update`（`1581-1615`）→ `updatePlanItemStatus`（`589-597`）→ `touchCheckpoint()`。
  `touchCheckpoint` 原文（`sessionManager.ts:366-369`）：`this.checkpoint.lastHeartbeat = Date.now();`——纯内存；`731` 行注释亦写「纯内存态无磁盘残留」。落盘在 step/turn 边界由 loop 做，不在工具执行内。⇒ `'none'` 成立。
- `trace_summary`（`builtinToolHandlers.ts:1301-1345`）：只读记忆索引 + 原始对话，返回文本。
- `remember_intel` / `compress_context` / `ask_user`：loop 专有通道（`toolExecutor.ts:512-517` 注释），纯内存。
- `run_team_meeting`（`toolExecutor.ts:2058-`）：一次 LLM 调用返回文本。
- `web_search` / `web_fetch` / `search_project`：provider 调用；内核侧无盘写。
- `read_file` / `list_dir` / `search_memories` / `list_sessions` / `read_skill` / `read_resource` / `list_resources` / `list_skills`：读。
- `kill_command`（`1936-1968`）：只杀自家后台任务，不写盘。

**未发现任何一个 `'none'` 实际改工作区** ⇒ 不触发退回。
