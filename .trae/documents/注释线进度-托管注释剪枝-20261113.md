## 五、本轮实证的规律

**每一批写盘方都会新造一到三处「看起来更准确」的假事实，全部由独立复核抓出。** 已发生的例子：

1. `workProjectionDto`：`hasFailure` 归属、`tooltip` 成分；
2. `processFlowModel`：「当前无 aborted 生产者」；
3. `processEventText`：`upgradePendingRow`（符号不存在）；
4. `imageCapture`：「无名时由 `resolveImageName` 兜底」（实际无条件调用）；
5. `protocol.ts`：「文件选择用 `file.name`」（实际走 `image_pick_request`，名称由宿主 `basename` 产出）；
6. `rolePackListView` / `capabilityChips` 抓出**层归属错**（不是冗余）：把「唯一出口」写成 `host`，而 `deriveCapabilityState` 定义在 `webview/helpers/capabilityState.ts`；`capabilityChips` 又把「`label` 已本地化」说成事实，实际 `list` 分支未过 `t()`。**复核标准**：凡「谁是谁的唯一出口 / 谁已翻译 / 谁已判定」这类断言，必须落到定义位置与调用链，不能因为是既有注释就默认它对。

结论：**三线不能省**。写盘方自证不算证据；守卫与测试只能拦「符号不存在 / 行号引用 / 结构」，拦不住「符号存在但归属错」——这一类比符号拼错更危险。

## 八、本段踩过的坑与新增纪律

1. **任务书里的符号名也按待核处理**：定义处找不到就报「符号不存在」。符号存在但归属错更危险（守卫和测试都拦不住），发现指令与代码不符时**直接按代码写**，并在回报里说明「原话是 X、改成 Y、依据是 Z」——不要照抄错误原话再附一段说明。
2. **行数口径**：判断「余量」这类与基线比大小的数，用 `(Get-Content).Count`；不要用 `Measure-Object -Line`（后者不计空行，同一文件可差出上百行，排雷方曾因此把 4,122 行读成 3,997 行）。
3. **注释引内核实现**：仓库守卫 `commentHygiene.test.ts` 禁止 `src/` 下任何 `.ts:行号` 引用，只写符号名 + 文件；写盘时按符号引用，否则该守卫必红。
4. **共享工作区纪律**：多线并行时指数与门禁可能互相干扰；提交用路径限定、逐文件暂存，发现 `index.lock` 先等释放，不在没有进程证据时删锁。
