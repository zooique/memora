**分档纪律**：分档在排雷阶段定；写盘阶段一旦发现命中必排项（协议 / 状态 / 持久化 / 安全）立即升档并改走三线，不按原批次硬写。

**剪枝第一判据（2026-11-13 用户定 · 优先于「有没有信息量」）**：逐句问三句——

1. **这行说的话现在还成不成立**（数字 / 路径 / 归属 / 调用关系，逐项落到代码或 git 物证）；
2. **不成立的原因是哪一类**（三类处置不同，先用 `git log -S` 查它是否曾经成立）：
   - **冗余**：信息量不足 / 只复述代码 → 删；
   - **过期**：曾经成立、现在不成立（文件瘦身后回落、字段被删后未跟改）→ 能改真就改真，并注明「过期于哪一笔」，**不得指控为编造**；
   - **失实 / 编造**：引入时就不符合代码。多数是误述（把「映射」写成「翻译」），改真即可；只有无法改成真（纯口号、指向不存在的符号或测试）才删，并在回报里单列。
3. **不成立时是删掉，还是改成真的**（能改真就改真；只有「历史指认对读者无信息价值」才删，且删的理由必须写明，不得写成「无法取证」）。

顺序不能反：先判真假，再判类型，最后谈留删。只反问「有没有信息量」会放过可一眼证伪的失实断言；把「过期」一律说成「假事实」则会夸大问题——当初并不是凭空编的。

## 五、本轮实证的规律

**每一批写盘方都会新造一到三处「看起来更准确」的假事实，全部由独立复核抓出。** 已发生的例子：

1. `workProjectionDto`：`hasFailure` 归属、`tooltip` 成分；
2. `processFlowModel`：「当前无 aborted 生产者」；
3. `processEventText`：`upgradePendingRow`（符号不存在）；
4. `imageCapture`：「无名时由 `resolveImageName` 兜底」（实际无条件调用）；
5. `protocol.ts`：「文件选择用 `file.name`」（实际走 `image_pick_request`，名称由宿主 `basename` 产出）；
6. `rolePackListView` 抓出**调用点/单点命名不精确**（不是冗余，也不是层归属错），`capabilityChips` 则是**失实**（误把映射当翻译）：原文把「唯一出口」写成 `host`，未落到符号与直接调用点；`capabilityChips` 把「`label` 已本地化」说成事实，实际 `list` 分支未过 `t()`。**依据**：`esbuild.config.mjs` 把 `dist/webview/panels/*.js` 打进 extension host——`deriveCapabilityState` 虽定义在 `webview/helpers/capabilityState.ts`，仍由 `chatPanel` / `rolePackListView` 在 extension host 执行；**定义在 `webview/helpers/` 不等于不在 extension host**，后续不得按源码目录判层级。**复核标准**：凡「谁是谁的唯一出口 / 谁已翻译 / 谁已判定」这类断言，必须落到定义位置与调用链，不能因为是既有注释就默认它对。

结论：**三线不能省**。写盘方自证不算证据；守卫与测试只能拦「符号不存在 / 行号引用 / 结构」，拦不住「符号存在但归属错」——这一类比符号拼错更危险。

1. **任务书里的符号名也按待核处理**：定义处找不到就报「符号不存在」。符号存在但归属错更危险（守卫和测试都拦不住），发现指令与代码不符时**直接按代码写**，并在回报里说明「原话是 X、改成 Y、依据是 Z」——不要照抄错误原话再附一段说明。
