# 托管会话中断通知（第三切片）实施计划

## Context

托管模式 v0 里，主控会话（managed 装配）会派发/创建子会话（`SessionMeta.origin='hosted'`）。子会话被用户停掉或异常终止后，主控**完全不知道**：它空闲时不会刷新，也没有任何终态回传（台账 B6 已登记）。本切片让这条事实以「下次主控说话时能在上下文里看到」的方式送达，并说清**哪条会话、被谁停的**。

约束（用户原话）：在现有终态投影上长，不造第二个状态源；原因只写真实可测的，取不到就如实标取不到；只通知代理开出去的会话；复用现有历史通道；不做自动唤醒 / UI / 跨窗口；测试钉住五条。

## 调查结论（已核实）

- 终止原因**已经落盘**：`Round.processEvents` 里的 `aborted{payload:{reason,stopReason?}}` 与 `error{payload:{message,category?}}` 互斥，分别回答「谁让它停」与「出了什么错」。不需要给 `Round` 加字段。
- 现有宿主终态投影 = `webview/helpers/processFlowModel.ts` 的 `decideTerminus(events)`：error 优先，`aborted.stopReason==='user'` → user-interrupted，否则 error-interrupted，**无事件时兜底 user-interrupted**（这是展示口径，不能拿来当事实，否则会伪造「用户停」）。
- 现有可达的「空闲期留存、下次说话可见」通道 = 内核 `AgentLoop.enqueueCommandResult(content)`：入 `interruptQueue` 的 `command-result` 条目，**不占插话额度、跨 turn 留存**（`processUserInput` 入口只清 interject），下个 step 边界经 `appendSystemMessage(executionTemp)` 以 **system 角色**注入上下文。宿主可经公开 getter `Agent.agentLoop` 调用；`AgentLoop` 公共成员已在 `publicMemberSurfaceGuard` 基线中，**复用它不改内核、不动公开面基线**。
- 落点：`chatPanel.consumeFlow` 流尾同时握有 `latestRoundId`、盘上 `settledRound`、`eventsByRound.get(latestRoundId)`、`controller.signal.aborted`；`runFlow` 的 catch 覆盖同步抛错；`chatRunControlOps.handleStop` 覆盖 paused 态用户停止（生产唯一 abort 调用点）。
- **判据缺口（必须如实处理）**：`originForMode(managed)` 让「用户自己选托管新建的会话」与「代理创建的子会话」**都**是 `origin='hosted'`。单靠来源标记无法区分二者。本切片仍以 `origin==='hosted'` 为出生判据，另加一条**进程内**「谁创建了它」的路由记录（不落盘、不是新标记）来定位通知对象；用户自己新建的托管会话没有这条记录 ⇒ 不会向任何代理发通知。

## 实施

### 1. 共享原因投影：`hosts/memora-vscode/src/shared/interruptReason.ts`（新增，纯函数）

- `export type InterruptStopper = 'user' | 'timeout' | 'error' | 'unavailable'`。
- `export function deriveInterruptReason(events: readonly ProcessEvent[], opts?: { hostAborted?: boolean }): { stopper: InterruptStopper; errorMessage?: string; stopReason?: string; abortReason?: string }`。
  - `error` 事件 → `error`，带回**原始** `message`（不用 `friendlyErrorMessage`，不吞细节）。
  - `aborted.stopReason==='user'` → `user`；`'timeout'` → `timeout`；其余/缺省 → `unavailable`（保留原值，不新增编造档）。
  - 无事件：`hostAborted===true` → `user`（宿主唯一 abort 点 = 用户停止，这是可测事实）；否则 `unavailable`。
  - **不**复刻 `decideTerminus` 的展示兜底（无事件 ≠ 用户停）。
- 让 `processFlowModel.decideTerminus` 改用本函数取分类，`kind` / `reason` 的对外输出保持**逐字不变**（error→error-interrupted；aborted user→user-interrupted；aborted 其他→error-interrupted；无事件→user-interrupted 展示兜底保留）。这样原因只有一份推导，展示口径不动。

### 2. 通知器：`hosts/memora-vscode/src/webview/helpers/hostedSessionNotice.ts`（新增）

- `class HostedSessionNotifier`，依赖盒（全部由面板注入闭包，帮助器不持有面板）：
  - `readSessionMeta(sid): SessionMeta | undefined`
  - `isManaged(sid): boolean`
  - `getAgent(sid): Agent | undefined`（面板用 `_sessionAgents.get`，同步取，不 await 装配）
- 状态（都只在内存，进程内有效）：
  - `childToCreator: Map<string, string>`：**只**在代理建会话成功后写入（见 §3.1）。
  - `notified: Set<string>`：键 = `${sid}:${roundId}`；`roundId` 为空时**不参与去重键**（不写 `sid:undefined` 这种会永久吞后续失败的键），该次直接投递。
- `noteFlowEnd({ sessionId, roundId, events, hostAborted }): boolean`：
  1. `meta?.origin !== 'hosted'` → false（用户自己的会话/旧会话不通知）。
  2. `creator = childToCreator.get(sessionId)` 缺失，或 `!isManaged(creator)` → false（代理不在了就不打扰普通会话）。
  3. `roundId` 非空且 `${sessionId}:${roundId}` 已在 `notified` → false（同一会话停两次只一条）。
  4. `deriveInterruptReason(events, { hostAborted })` → 文案：
     - `user` → `用户主动停止`
     - `timeout` → `请求超时`
     - `error` → `异常终止：${errorMessage}`
     - `unavailable` → `原因不可知（本轮以中断收场，但未收到停止原因）`
  5. 正文：`[托管会话已停止] 会话《${title}》（sid=${sid}${roundId ? `，round=${roundId}` : ''}）：${原因}`；`title` 取 `getSessionDisplayName(meta) || sid`（标题和停的人都在，不能只有 id）。
  6. 投递：`getAgent(creator)?.agentLoop?.enqueueCommandResult(text)`；**成功压入队列才记 `notified`**，取不到 agent/loop 时不标记（如实不投，不装作已送达）。
- `noteSyncThrow({ sessionId, error })`：供 `runFlow` 的 catch 用，原因归 `error`（异常原文），无 roundId。

### 3. 面板薄接线（`webview/panels/chatPanel.ts`，遵守 2200 有效行上限）

1. **创建时登记 creator（必须先于首轮流）**：在 `helpers/hostedSessionCreate.ts` 的依赖盒加可选 `onCreated?: (sid, creatorSid) => void`，在 `createBackgroundSession` 成功之后、`startFlow` 之前调用；`chatPanel.createHostedSession` 注入 `(sid, creator) => this._hostedNotifier.remember(sid, creator)`。**不在面板包装返回后登记**——那时首轮可能已失败。
2. **流尾**：`consumeFlow` 在 `settledRound` / `eventsByRound` 就绪后、`controller.signal.aborted` 分支之前，调用一次：
   - 条件 = `latestRoundId` 存在、`pausedOnPurpose === false`、`isRoundSettled(status) && !isRoundSuccessful(status)`（`interrupted` 收场；用内核判据，不自写状态字面量比较）。
   - 传 `events: eventsByRound.get(latestRoundId) ?? []`、`hostAborted: controller.signal.aborted`。
   - paused 轮盘上是 `pending`，被 `isRoundSettled` 天然排除，不会误报暂停。
3. **同步抛错**：`runFlow` 的 catch 里调用 `noteSyncThrow`（仅当该会话是 hosted 且有 creator；帮助器内部判）。
4. **paused 态用户停止**：`chatRunControlOps` 依赖盒加 `onUserStopped?: (agent: Agent) => void`，在 paused 分支 `ask.abandonOnStop()` **之后**调用；面板注入闭包：**先把 `agent.currentRoundId()` 取到局部变量**（abandon 后可能已变/被清），再读 `this._eventLogRoundStore?.getById(roundId)?.processEvents ?? []`，`hostAborted: true` → 原因归用户。
5. 不新增命令、不改协议、不改会话列表 UI。

### 4. 投递通道说明（为什么不是写历史）

- 不写 `MessageHistory.appendUser`：那会凭空造一条「用户说过」的轮，污染会话历史与界面，违反「系统事件不伪装用户发言」的既有纪律。
- 复用 `enqueueCommandResult` 的系统事件注入队列：主控空闲时入队、下次说话的第一个 step 边界以 system 消息进上下文；正在跑时在下一个 step 边界看到。方法名沿袭其首个生产者（后台命令回流），**本切片不新增 kind、不改内核**。

## 测试

1. `shared/__tests__/interruptReason.test.ts`（新增）：user / timeout / error / 其它 stopReason→unavailable / 无事件+hostAborted→user / 无事件→unavailable；断言 error 带回原文。
2. `webview/helpers/__tests__/processFlowModel.test.ts`（补）：`decideTerminus` 既有 kind/reason 逐字不变。
3. `webview/__tests__/hostedSessionNotice.test.ts`（新增，钉五条）：
   - 用户停（aborted.stopReason=user）→ 原因归用户，且只投给 creator 的 `agentLoop.enqueueCommandResult`；
   - error 事件 → 原因归异常，正文含原始错误；
   - 用户自己的会话（`origin='user'`；以及 `origin='hosted'` 但无 creator 记录）→ 零投递；
   - 同一 `sid+roundId` 调两次 → 只一条；
   - interrupted 但无任何事件且 `hostAborted=false` → 正文为「原因不可知」，且**不含「用户」**；
   - 附带：creator 已非 managed → 不投；标题缺失回退 sid。
4. `webview/__tests__/chatPanelSessionAgents.test.ts`（补一条接线）：托管子会话流被 abort 后，creator 桩的 `agentLoop.enqueueCommandResult` 被调用且只有一次。

## 覆盖不到 / 明确不做（做完一并如实报告）

- 崩溃、重载、跨进程重启后的打捞轮：没有活着的面板钩子，且 creator 记录是进程内的 ⇒ **不通知**（不伪造原因）。
- 本功能上线前已存在的 hosted 子会话、或重启后仍在的：无 creator 记录 ⇒ 不通知。
- 通知队列在进程内存里：主控还没开口就重启 ⇒ 丢失；不落盘（本切片不扩历史格式）。
- 不做自动唤醒一轮、不做工作台 UI、不做跨窗口。
- `handleStop` 之外的内核自主 `abandonTurn`（如 ask 超时不可续跑）不在本切片射程。
