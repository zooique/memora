# 助手窗会话绑定（HOSTED-SEAT-SESSION-1）实施方案

## Context

托管编辑器页（`hostedPanel`）注册进 `chatPanel` 的广播器后，收到的是按 `_currentSessionId` 产生的会话级消息，
于是侧栏切到哪条工作会话，助手窗就显示哪条——两页成了同一份记录的两个视图（真机截图实锤）。

目标形态（2026-11-17 定案）：助手只有一个、入口只有一个「打开助手窗」；助手窗固定绑定**助手会话**
（`workspaceState` 持久导航指针，`assistantSession.ts` 已是唯一身份真源）。工作会话仍是普通会话、出现在
侧栏列表、可被侧栏打开看过程；**助手会话是助手专属记录，不进工作会话列表、也不当侧栏导航目标**
（2026-11-17 真机实锤后订正：混在列表里会被误读成「助手拿工作会话回话」）。助手会话的角色包固定为内置
`memora助手`（用户级「新建会话默认角色包」只作用于工作会话，不得顶替助手人格）。
窗口只收**气泡级**消息，输入按**用户发起**（`origin='user'`）进助手会话，不改变侧栏当前会话。

已落地前置：`HOSTED-IDENTITY-PERSIST-1`（指针身份真源、`SessionModeStore` 现读指针、`isManaged` 单一口）。
本次只补「视图 → 会话」的绑定与投递分离，不新建第二套 agent 状态机（台账边界）。

## 设计（最小改造面）

### 1. 广播器按会话路由 + 按视图取景

`hosts/memora-vscode/src/webview/helpers/viewBroadcaster.ts`：

- 注册从 `register(webview)` 改为 `register(webview, binding)`：
  - `binding.sessionId: () => string | undefined`（现场读取——助手会话可后建 / 指针可失效）；
  - `binding.bubbleOnly: boolean`（助手窗 = true）。
- `post(msg, primary, target?)`：`target` 省略 = 全局（保持旧行为，老测试零改）；
  给定 = 会话级——主视图只在 `target === primarySession` 时收（`primarySession` 由调用方现场传），
  附加视图只在 `target === binding.sessionId()` 时收。
- 气泡过滤：投给 `bubbleOnly` 视图时丢弃 `process_event` / `tool_pending` / `step_boundary`
  （+ `plan_update` / `background_tasks` / `context_occupancy` / `injection_summary` / `narrate_withdraw`
  这类过程面消息，同一张表定义、注释写清）。**只在投递层过滤**——`consumeFlow` 照常缓冲/落盘，
  侧栏打开助手会话时仍是完整过程。
- 新增 `hasSession(sessionId)`（判断某会话是否有视图在显示，供 `postTurnUpdateFor` 早退）。
- `postRaw` 保持全局广播（`session_activity` 语义不变）。

### 2. 面板投递收敛为三种口

`hosts/memora-vscode/src/webview/panels/chatPanel.ts`：

- `post(msg)` → 会话级，目标 = `_currentSessionId`（侧栏行为零回归：主视图恒收）。
- `postToSession(sessionId, msg)` → 会话级指定目标（流内 / 回放 / turn 投影用）。
- `postGlobal(msg)` → 全局广播（`chat_providers` / `skills_loaded` / `chat_role_packs` /
  `file_changes` / `session_list` 这类配置面与跨会话面）。
- `registerAdditionalView(webview, binding)` 原样转发广播器；
  `viewsMayShow(sessionId)` = 侧栏正在看它，或某个附加视图绑定了它。

### 3. turn 状态按会话分片

- 删除单份 `_turnState`，改 `_turnStates: Map<string, TurnState>` + `turnStateFor(sessionId)`。
- `postTurnUpdate(live?, replay?)` 保留为当前会话薄包装；新增
  `postTurnUpdateFor(sessionId, live?, replay?)`：历史 / 流态 / 暂停态 / 待答 / 待发送队列全部按
  `sessionId` 取（`loadRoundBasedHistory`、`runtimeFor(sid)`、`askFor(sid)`、`_sessionAgents.get(sid)`），
  投影写回 `_turnStates`，最后走 `postToSession(sessionId, …)`。
- `consumeFlow(sessionId)` 内所有 UI 投递改 `postToSession(sessionId, …)`，`postTurnUpdate()`
  改 `postTurnUpdateFor(sessionId, …)`；`runFlow` 的 catch 同理。
  `syncPendingQueue` 仍只服务当前会话（长度缓存单份，助手流直接跳过，理由写进注释）。

### 4. 输入按视图寻址

- `sendInput(...)` → `sendInputFor(sessionId, ...)`：实例、运行态、ask、`runFlow(..., sessionId)`、
  `postToSession` 全部参数化；`sendInput` 保留为当前会话包装。
- `handleInput(msg, sessionId = this._currentSessionId)`：
  - 草稿分支、`!this._currentSessionId` 守卫只对当前会话生效；
  - agent 取 `_sessionAgents.get(sid)`（目标非当前且未装配时 `await agentForSession(sid)`）；
  - `answer` → `_answerOps.answerInput(answers, sid)`（增加可选会话参数，复用同一条执行链）；
  - `resume` → `_runOps.resumeInput(sid)`；`pause` / `stop` 同法补可选会话参数
    （`handleStop` 已支持）；
  - `regenerate` / 结构写操作仍只对当前会话（助手窗不暴露）。
- `routeHostedMessage(msg)`：
  - 先取助手会话 id（`sessionModes.listManagedSessionIds()[0]`，复用已有唯一真源）；
  - `ready` → `handleHostedReady()`：指针无效 ⇒ 清指针 + 只向助手窗投空态（`clear_ok` +
    标题「助手」+ 配置面），有效 ⇒ 只回放该会话；
  - `input` → 目标 = 助手会话；无助手会话且 `kind==='send'` 且有文本 ⇒
    `createSession(newSessionId(), undefined, { background: true, assistant: true, title: 助手 })`
    （后台建 = 不抢侧栏显示源），随后 `sendInputFor`；
  - `composer_state` 仅当目标会话 = 当前会话时写 `_composerHasText`（单份字段不跨会话污染）；
  - `stop` / `pause` / `resume` / `clear_pending_queue` / `remove_pending_item` 的目标 = 助手会话；
  - 其余（`composer_draft` / `write_confirm_answer` / `auth_answer` / `open_ref` / 图片 / 设置导航）
    本就按载荷会话或全局动作走，原样转发。

### 5. 回放参数化

- `replaySession()` → `replaySessionFor(sessionId)`：草稿分支只在当前会话；会话级推送走
  `postToSession`，配置面（providers / skills / role packs）走 `postGlobal`；角色名 / 能力徽章
  按**该会话的 agent** 取（给 `postCapabilityBadge` / `getActiveTraits` 加可选 agent 参数），
  不拿侧栏投影冒充。
- `replayHistory(sessionId)` / `buildLiveTurnFromBuffer(sessionId)` 同步参数化
  （缓冲归属校验改成该 sessionId）。
- 助手窗 `ready` 只回放助手会话；侧栏 `ready` 行为不变。

### 6. 确认卡单一真源、两页都能裁决

`hosts/memora-vscode/src/extension/host/confirmCoordinator.ts`：

- `_foreground` 之外增加 `_additionalForeground`（助手窗绑定的会话），
  `setAdditionalForeground(sid | undefined)`；判据统一为 `_isVisible(sid)`
  （替换现有 `=== this._foreground` 的 5 处），上屏条件 = 当前屏或助手窗可见。
- `_show(sessionId, entry)` 带上会话，投递改 `deps.post(msg, sessionId)`；
  `deps.post` 签名加可选 `sessionId`，面板接到 `postToSession`。
- `answer(requestId, approved)` 改为**按 requestId 在 `_sessions` 中定位所属会话**再 `answerFor`
  （两页都能裁决、不重复；不再只认 `_foreground`）。
- `repostFor(sessionId)`：助手窗 ready / 助手会话建立后补推该会话在途卡。
- chatPanel：`_hostedOpen` 布尔 + `syncConfirmVisibility()`，在注册 / 注销 / 助手会话建立时调
  `setAdditionalForeground`。

### 7. 托管页接线

`hosts/memora-vscode/src/webview/panels/hostedPanel.ts`：

- 注册时传 `{ sessionId: () => chatProvider.getAssistantSessionId(), bubbleOnly: true }`；
- 删除文件头「现行实现与形态不符」的临时说明（问题已修），改为新口径；
- `openHosted.ts` 头注释同步（不再说「当前会话的取景」）。

## 新增小模块（守 max-lines）

## 边界与已知取舍（写进注释，不假装已解决）

- 不新建第二个 Agent 实例或第二套状态机；`_agent` 仍是侧栏显示投影。
- 助手窗不显示任务看板 / 后台任务条 / 占用环 / 过程轨迹；这些消息仍按当前会话投递，
  气泡层过滤保证不串到助手窗。
- 助手窗的待发送插话队列不渲染（`syncPendingQueue` 单份缓存不跨会话）；
  若后续需要，另立条目，不在本次偷做。
- 授权卡随 `HOSTED-CONFIRM-AUTH-1` 退役，本次不接。
