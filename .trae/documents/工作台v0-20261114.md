# 工作台 v0（第四切片）实施计划

## Context

托管模式已有「主控会话 + 代理开出的子会话 + 中断通知」，但用户缺少一个**看的地方**：代理此刻替你在办哪些活、各自是什么状态。本切片补上编辑器区只读工作台 v0，两个块：

1. **代理是谁**（座位身份区）
2. **最近在办什么**（在管会话清单）

第三块「交出了什么」本轮**不做**：产物登记表已退役，唯一沾边的是文件变更视图（编辑级不是产物级），硬做等于拿不可靠数据充数。不放假数据、占位符、0 与破折号。

## 已确认的现状（探索结论）

- HTML 头骨架已有唯一共享件：`webview/helpers/htmlShell.ts` 的 `buildHtmlHead`（CSP / lang / l10n bundle 单点）。聊天面板与设置面板都复用它 ⇒ **工作台只复用它，不复制骨架**。
- 编辑器区面板唯一先例：`webview/panels/settingsPanel.ts` 的 `createWebviewPanel + retainContextWhenHidden: true`。工作台是**第三种组合**：面板对象存活、webview 上下文不保活 ⇒ 隐藏即销毁、`reveal()` 重载、脚本重发 `ready`、`ready` 时全量回放。
- 运行态事实只在 `chatPanel` 内：`_runtime`（`SessionRuntimeStates.streaming`）、`_asks`（待答提问）、`_confirm`（待确认）、`_sessionAgents`（实例 → `sessionManager.status === 'paused'`）。`chatPanel.ts` 有效行已 ≈2197（上限 2200）⇒ **不能直接加代码**，必须先外置同域计算。
- 创建者关系只在内存：`HostedSessionNotifier.childToCreator`（`remember` 写入）。`SessionMeta.origin === 'hosted'` 只说明「托管通道出生」，**不能区分代理开的子会话与用户自己选的托管会话** ⇒ 清单只能用创建者账本。
- 终态事实：`SessionMeta` + 会话 `roundIds` + `RoundStatus`（`isRoundSettled` / `isRoundSuccessful` 单点判据）+ `Round.processEvents`；原因判定复用 `shared/interruptReason.ts` 的 `deriveInterruptReason`（已落地的 `aborted{stopReason}` / `error{message}`）。
- 命令入口：`package.json` 的 `contributes.commands` + `%command.*%`（`package.nls*.json`）；侧栏标题栏按钮走 `menus.view/title`，`memora.chat` 的 viewType 已存在，**不改聊天面板布局**。

## 设计裁决

### 1. 工作台的座位 = 一条托管会话

不造「全局代理」新对象。每次打开绑定一个 `orchestratorSessionId`：

- 命令面板：当前会话是托管 → 用它；否则列出本进程的托管会话：0 条 → 如实提示「当前没有在替你安排的代理」；1 条 → 直接用；多条 → QuickPick 选一条。
- 主控会话入口：`view/title` 上加一个「工作台」图标按钮（`when: view == memora.chat`），点击走同一命令。**不改聊天面板 webview 布局**。
- 工作台里的「去这个会话」= `chatProvider.switchToSession(sid)` + 聚焦侧栏视图。

理由：`origin='hosted'` 无法区分「用户自己选的托管新建」与「代理开的」，只有创建者账本才是既有事实；而创建者账本是「某会话 → 它开出去的子会话」，天然以座位为单位。重启后 mode 与账本都归零 ⇒ 如实没有代理、没有清单，不自造恢复。

### 2. 状态只从既有事实推

每个子会话按优先级投影：

| 展示 | 判据（既有事实） |
| --- | --- |
| 等你 | `_asks` 有待答提问 或 `_confirm` 有待确认 或 该会话实例 `sessionManager.status === 'paused'` |
| 在跑 | `_runtime.peek(sid)?.streaming === true` |
| 完成 | 最后一轮 `isRoundSuccessful(status)` |
| 被中止 | 最后一轮 `isRoundSettled && !isRoundSuccessful`；原因 = `deriveInterruptReason(round.processEvents)` |
| 上次未正常结束 | 最后一轮未收场（`pending`/`error`，崩溃残留且未被打捞）——如实说「没收到停止原因」，不冒充被中止 |
| 已交给助手，还没开始 | 无任何一轮（首轮同步失败窗口）——不冒充在跑/完成 |

- 被中止原因只写真实可测的四档：用户停止 / 请求超时 / 异常终止（带原始错误文本）/ 原因不可知。**不用 `unknown` 兜底，不补默认值**。
- 不新增任何状态源；`SessionRuntimeStates`、ask/confirm、`RoundStatus`、`deriveInterruptReason` 全部复用。

### 3. 不保活（第三种组合）+ 测试钉住

- 创建面板时**不设** `retainContextWhenHidden`（默认 false）。
- `ready` → 置就绪 → **全量重发**一个 `workbench_snapshot`（无增量、无缓存状态）。
- 隐藏后 `reveal()` 会重载 webview，新脚本重发 `ready` ⇒ 同一路径恢复现场；`onDidDispose` 只清面板引用与就绪位。
- 面板对象存活期间（可见时）每 3s 读一次既有事实重发快照；隐藏/销毁即停。轮询只是刷新触发，不是状态源。
- 测试必须覆盖：销毁后重开 = 新面板 + `ready` 后全量快照；`ready` 连发两次 = 两次都全量（证明不依赖旧 webview 内存）；`createWebviewPanel` 选项里 `retainContextWhenHidden` 不是 `true`；`ready` 之前不投递。

### 4. 空态

`childrenOf(orchestratorId)` 为空 ⇒ 第二块只显示「还没有交给助手的活」，**不摆表格、不显示 0、不显示破折号**。

## 验证

在 `hosts/memora-vscode` 下：

```
npm run typecheck
npx eslint --max-warnings 0 .
node scripts/verify-nls.mjs
npm run test
```

重点看：

- `chatPanel.ts` 有效行未超 2200（若超，继续外置活动快照相关计算，不抬阈值）。
- `protocolGuard.test.ts` 新阈值与实测计数一致。
- 新增两个测试文件全绿；既有 `chatPanel*` / `settingsPanel*` 无回归。
- `verify-nls` 无孤儿键/漏译。

手工自检（无法自动化的部分）：命令面板「工作台」在无托管会话时给出如实提示；从托管会话打开后两块可见；点「去这个会话」切回聊天并定位；关闭标签重开、隐藏再显示均能全量恢复。

## 明确不做

- 第三块「交出了什么」。
- 工作台聊天输入框、任何跨会话汇总/任务对象/中间层。
- 自动唤醒、跨窗口、实时流式推送（v0 只在可见时定时刷新）。
- 新状态源、`unknown` 兜底、假数据/占位符/0/破折号。
