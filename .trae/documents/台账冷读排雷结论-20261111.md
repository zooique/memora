## 一、`LEDGER-ARCHIVE-CONFLICT-1` 选 C（永不折叠非已关闭区）

### 结论

C 是**判据零改动**，不是文档零改动。fold 脚本从设计上就不区分关闭状态：

- `scripts/verify-ledger-fold.mjs:50` `function topLevelIds(text)` —— 只匹配 `^- **ID**` 形态，不解析状态段。
- `scripts/verify-ledger-fold.mjs:69` `export function auditFold({ baseText, headText, archives })` —— 入参只有两份文本 + 归档，无「状态」概念。
- `scripts/verify-ledger-fold.mjs:72` `const gone = base.filter((id) => !head.has(id));` —— 纯 ID 集合差。

因此「永不折叠非已关闭区」在脚本层**本来就成立**：它对所有条目一视同仁地只做「消失 ID 是否在 archive 有副本」判定。

纪律唯一真源应为 `tasks/archive/README.md:7` 纪律 3（「只迁已关闭项……开放项、观察项、明确不做项一律留主台账」）。台账头部 `tasks/待完成任务.md:5` 已是指针式表述，不得再抄一份正文。

残余风险 = **手工删开放条目**：`verify-ledger-fold.mjs:72` 只判「消失 + 归档无副本」，若归档里恰好存在同名副本（或有人手工补一条），开放条目被删也会绿。

C **覆盖不了「只查副本、不查残余引用」盲区**：fold 的判据终点是「archive 里有该 ID」，它不扫 docs / ADR / 源码注释里对该 ID 的引用点。缺口 = 全仓没有任何闸检查「被删 ID 的跨文件引用」。

### 必改项

1. `tasks/archive/README.md:7`（纪律 3）末尾追加删除前置动作：删除/折叠任一顶层条目前先 `grep -rn '<ID>' .` 清算 docs / ADR / 注释引用，再跑 `npm run ledger:fold`。这是唯一纪律真源。
2. `tasks/待完成任务.md:66`（「迁档前必跑 `ledger:fold`」）补第 ② 步「grep 清算残余引用」，或改为指向 README 纪律 3（二选一，禁止双写）。
3. `scripts/verify-ledger-fold.mjs:148` 加一行注释：`// 本门不判关闭状态（口径见 tasks/archive/README.md 纪律 3）`。

### 风险 / 不该做

- 不要在 fold 里加「什么算关闭」的解析——会复制 hygiene 的 `CLOSED_RE`，形成第二真源。
- 不要把 C 描述成能解决残余引用盲区；那是检索面问题，需独立的 grep 前置动作。

⇒ ④ 永远无法满足，条目被永久钉在 📌。删除正确。

### 风险 / 不该做

## 三、`verify-ledger-fold.mjs:148-149` 判红提示改两分支

### 结论

该位置**判不了状态**：`auditFold` 返回只有 `gone / lost / baseCount / headCount`（`:72`），`topLevelIds`（`:50`）不解析状态段，`run()` 内无「该 ID 当前是否已关闭」的数据来源。

两分支文案**不会让判据不可判**：判据是 `:139` `if (r.lost.length === 0)`，提示仅 `:147-150` 打印，退出码 `:151 return 1` 不变。

最小改法 = 只改字符串，加「本门不判状态，两条路只有一条合法」并分叉。

### 必改项

- `scripts/verify-ledger-fold.mjs:148-149` 改为两分支文案：
  - ① 该条已关闭 → 补进 `tasks/archive/<version>-<kernel|host>.md`；
  - ② 该条未关闭 → 移回主台账（引 `tasks/archive/README.md` 纪律 3）；
  - 收尾保留「本门不接受口头结论」。

### 风险 / 不该做

- 不要在脚本里加关闭状态解析（第二真源）。
- 不要改判据或退出码，只改提示文案。
