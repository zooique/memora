# 手机联调首切片（真桥 + 真 mTLS + 假宿主数据）

## Context

手机仓 `F:\zooique\memora-mobile` 已完成壳首切片与契约层（`parseFrame` / `PinnedTlsClient`），
但传输层只有 HTTP GET，没有任何一条真实链路走过「连接 → hello → 订阅 → 收 snapshot」。
本切片的目的是**让手机端代码与主仓真桥握上手**，用真实帧验证契约层没有脱节。

诚实口径：本切片验证的是「与真 `RemoteBridge` 实现联调（宿主数据为夹具假数据）」，
不等于「与真实 VS Code 宿主集群联调」，也不构成手机端（Android/iOS）验收。

不引入第二份协议实现：手机端仍只消费 `parseFrame` 与既有 mTLS 固定逻辑；
桥侧完全复用 `RemoteBridge` / `createRemoteSecureServer` / `RemotePairing` / `RemoteFailureLimiter`，
夹具只提供假 ports、真证书与自动批准。

## 已确认的事实（不再查证）

- 宿主：`"type":"module"`、Node16 / ES2022，`ws` 与 `esbuild` 已是依赖，脚本用 esbuild 现打包后 import（范式见 `scripts/gen-remote-fixtures.mjs`）。
- TLS：`createRemoteSecureServer` 要求客户端证书、不做链校验；无证书直接 destroy。
- 握手：`hello.phoneFp.trim().toUpperCase()` 必须等于 TLS 证书 DER 的 SHA-256（全大写 hex）。
  未配对 → 限流 → `verifyPasscode(pid)` → `requestApproval` → `registerDevice('observe')`。
- 订阅：`sub` 命中 `hasSession` 即同步推一帧 `evt{kind:'snapshot', seq:0}`。
- 手机端：Dart `WebSocket.connect(url, customClient: HttpClient)` 可复用 `PinnedTlsClient.createHttpClient()` 的证书与 DER 固定。
- 现有证书脚本 `tool/dev/gen_certs.mjs` 生成 PC(server) + 手机(client) 两套自签证书，并写 `server-der.b64`。

## 改动清单

### A. 主仓（开发夹具，仅开发、不接产品路径）

1. **新增 `hosts/memora-vscode/scripts/dev-bridge.mts`**
   - 读 `--certs <dir>`（缺省 `../../../memora-mobile/tool/dev/certs`）里的 `server-cert.pem` / `server-key.pem` / `client-cert.pem`。
   - 从 `client-cert.pem` 算手机指纹（`node:crypto` 的 `X509Certificate.raw` → `fingerprintOfCertDer`），用于自检/打印。
   - `createRemoteSecureServer({ identity: {keyPem, certPem, fingerprint, shortFp} , security: {isBlocked, noteFailure, audit} })`；
     identity 直接由文件 PEM 构造，**不走** `remoteIdentity`（那块会拖入 `@peculiar/x509`，且 SecretStorage 在 CLI 下无意义）。
   - 假 `RemoteBridgePorts`：1 个会话 `s-dev-1`、1 个轮次（userMessage + assistantMessage）、`phase:'idle'`、`pendingQueue:[]`。
   - `RemoteBridgeSecurity`：`fingerprintOf` 取 secureServer；`tierOf` 查内存 Map；`verifyPasscode` 用真 `RemotePairing`（`start()` 生成并打印）；
     `requestApproval` 恒 `true` 并打印；`registerDevice` 写 `observe`；`rateLimit` 直接复用真 `RemoteFailureLimiter`；`audit` 打日志。
   - `new RemoteBridge(ports, { pcId:'pc-dev', host, port, server: secure.server, security, log })` + `start()`。
   - 打印单行 `BRIDGE_READY {"host":...,"port":...,"phoneFp":"<HEX>","passcode":"...","sessionId":"s-dev-1"}`；
     SIGINT/SIGTERM 时 `bridge.stop()` + `secure.close()`。
   - 文件头必须写明「仅开发联调，不参与扩展激活路径」。
2. **新增 `hosts/memora-vscode/scripts/dev-bridge.mjs`**：照抄 `gen-remote-fixtures.mjs` 的 esbuild → 临时目录 → `import()` 范式，
   不吞掉进程（server 持有事件循环）；`--certs` 等参数原样透传。
3. **`hosts/memora-vscode/package.json`**：新增脚本 `"dev:bridge": "node scripts/dev-bridge.mjs"`（一行，方便手工联调）。
4. `tsconfig.scripts.json` 只 include `scripts/**/*.mts` —— 用 `.mts` 命名即可自动进 typecheck 门，无需改配置。

### B. 手机仓（真链路客户端 + 端到端冒烟）

5. **新增 `lib/src/contract/handshake.dart`（`part of 'frame.dart'`）**
   - 上行构造：`buildHelloFrame`（`t/v/deviceId/nonce/phoneFp/[pid]`）、`buildSessionListFrame`、`buildSubFrame`，各自 `toWireJson()`。
   - 下行解析：`HelloOkFrame`（`serverTime/pcId/caps/limits/assistantSid?`）、`SessionListOkFrame`（`sessions/archivedIds/assistantSid?`）+ `SessionSummary`。
   - 缺必填字段抛 `FrameFormatException`（与既有纪律一致：认识的封套缺字段 = 契约违规）。
   - 文件头按既有格式标注真源（宿主 `remoteBridgeProtocol.ts` 符号名 + 主仓 §6 章节，禁写行号）。
6. **`lib/src/contract/frame.dart`**：`parseFrame` 的 switch 增加 `hello_ok` / `session_list_ok` 两个 case（其余不变）。
7. **新增 `lib/src/transport/bridge_client.dart`**
   - 复用 `PinnedTlsClient.createHttpClient()`，`WebSocket.connect('wss://host:port/', customClient: client)`。
   - API：`open()`（连 + 发 hello + 等 hello_ok）、`requestSessionList()`、`subscribe(sid)`（发 sub + 等该 sid 首帧 snapshot）、
     `Stream<WireFrame> frames`、`close()`。
   - `phoneFp` 由外部传入（联调期由夹具从 client 证书 DER 计算并注入；手机端自取身份材料的切片不在本轮）。
   - 不做重连、不做水位恢复（`resume`）、不发写命令——都在本轮边界外，注释写清。
8. **`lib/memora_mobile.dart`**：导出 `src/transport/bridge_client.dart`。
9. **新增 `tool/bridge_smoke.dart`**
   - 参数：`<host> <port> <pinFile> <certsDir> <phoneFp> <passcode> <sessionId>`。
   - 断言链：`hello_ok.pcId/caps` → `session_list_ok` 含目标 sid → `subscribe` 得到 `SnapshotFrame`（sid 一致、`phase` 可读）。
   - 失败原因必须区分「连不上 / 握手被拒 / 帧契约违规」，逐条打印 `RESULT ...` 并非零退出。
10. **新增 `tool/check_bridge.dart`**
    - 编排（照 `check_mtls.dart` 范式）：`gen_certs` → 起 `node ../memora/hosts/memora-vscode/scripts/dev-bridge.mjs`（cwd=宿主目录，`--certs` 传绝对路径）
      → 读 `BRIDGE_READY` → 跑 `bridge_smoke.dart`（pin 文件 + phoneFp + passcode）→ 杀子进程。
    - 独立于 `check_all`（需要 node + 主仓宿主依赖），与 `check_mtls` 同性质。
11. **`.trae/rules/verification.md`**：在「涉及 mTLS 的改动」后补一段「涉及桥 / 传输 / 帧形状的改动必须跑 `dart run tool/check_bridge.dart`」，
    并注明它的外部依赖（node + 主仓宿主 `ws`/`esbuild`）与「验证的是真桥 + 假数据」的口径。

### C. 明确不做（本轮边界）

- 不把 `sessions_page` 接真实数据：没有真宿主时只能塞 mock，违反本仓「不放假数据」原则。
- 不做 `resume` 水位恢复、不做写命令、不做重连与配对 UI。
- 不动内核，不改 `remoteBridge` 生产代码（夹具只消费它）。

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| esbuild 把 `ws` / 内核依赖打进临时包失败 | 先 `bundle:true`（同 `gen-remote-fixtures.mjs`）；失败则把 outfile 落到宿主目录内让 Node 走 `node_modules`，仍失败则 `external:['ws']` + 目录内产物 |
| Dart `WebSocket.connect` 未走 customClient 的 TLS | 先以 `badCertificateCallback` 打印命中情况取证；失败则改 `SecureSocket` + `WebSocket.fromUpgradedSocket`（同一份 HttpClient 配置） |
| 证书 24h 过期导致假红 | `check_bridge` 每次先重跑 `gen_certs`（与 `check_mtls` 一致） |
| 夹具被误读成产品能力 | 文件头与 `verification.md` 双重写明「开发联调夹具 / 假宿主数据」 |
