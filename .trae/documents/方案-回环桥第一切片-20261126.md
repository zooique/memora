# 回环桥第一切片（profile 2 · 开发验证）实施方案

> **定位**：本文件是执行方案，不是判据真源。判据真源仍是
> [方案-手机远程控制-20261110.md](../../docs/方案-手机远程控制-20261110.md)（下称「方案」）与
> [施工单-手机远程控制-20261124.md](../../docs/施工单-手机远程控制-20261124.md)。
> 本文件只回答「这一刀切哪里、按什么顺序、怎么验」。

## 1. Context（为什么是这一刀）

- 方案 §19.3 profile 2（`loopback`）定义：只绑 `127.0.0.1`、只读 + 可答、**仅开发验证不交付**，
  销项证据 = 本地客户端跑通 `hello / session_list / evt / cmd`，端口占用显式报错。
- 代码现状（本轮核实）：`host/remote/` 下只有 `remoteCommandPolicy.ts` + `remoteAnswerRouter.ts`
  两个纯函数件与单测，**没有桥骨架、没有 server、没有协议类型**；宿主 `package.json` 无 `ws`。
- 投影面现状：`chatPanel.postTurnUpdateFor()` 已按 sid 取素材并调用 `deriveSessionProjection`，
  但开头 `if (!this.viewsMayShow(sessionId)) return;`——**没有视图在看就不算**。桥需要的
  「任意 sid 只读投影」入口仍缺（方案 §8 P0-3 明写仍缺）。
- 因此这一刀的自然生长顺序是：**先补只读投影入口（有真实消费方），再让桥消费它**，
  而不是让桥自己拼第二份投影素材。

## 3. 切片范围

### 做
1. 方案与施工单的上述三处文档订正。
2. 宿主新增运行时依赖 `ws`（+ devDependency `@types/ws`），并保证 esbuild 能干净打进
   `dist/extension/extension.js`。
3. `host/remote/remoteBridgeProtocol.ts`：封套类型 + 帧解析（纯函数，零 IO）。
4. `host/remote/remoteBridge.ts`：WS server 核心（端口驱动），实现
   `hello → hello_ok`、`session_list → session_list_ok`、`sub/unsub → evt(snapshot)`、
   `cmd(answer) → routeRemoteAnswer → deliverAnswer`、`err`（固定错误码）。
5. `chatPanel.ts` 两个窄公开口：只读投影 + 远程输入投递；把投影素材装配抽成一个私有方法
   （`postTurnUpdateFor` 与新口共用，避免第二份素材装配）。
6. `host/remote/remoteBridgeHost.ts`：把 `chatPanel` / `sessionStore` / `l10n` 适配成桥端口。
7. `extension.ts`：**默认不监听**；仅当 `process.env.MEMORA_REMOTE_BRIDGE === '1'` 时启动，
   模块级引用交给 `deactivate` 停止。
8. 单测：协议解析表、桥端到端（真 `ws` 客户端连 `127.0.0.1:0`）。

### 不做（明确留给后续）
- 六项安全底线（配对 / 指纹 / E2EE / 限流 / 审计 / 权限三档 UI）——profile 3 的事，本轮不碰。
- 实时 `delta` 推送与水位补洞（`seq`/`recvSeq`/`sentSeq`、`resume` 回放）——需要 P0-1
  「webview 与 bridge 各自订阅」，本轮只发 `snapshot`。
- `attention`（需要 P0-4 审批/提问双投递）。
- `send` / `interject` / `pause` / `stop` / `confirm_answer` 的投递——profile 2 权限档是
  「只读 + 可答」，其余命令一律回 `err{code:'forbidden'}`。
- `blob` 通道、`host_state`、`resume_ok`、配对 `pid`、手机端任何代码。

### 4.4 桥核心 `src/extension/host/remote/remoteBridge.ts`
```ts
export interface RemoteBridgePorts {
  listSessions(): { sessions: BridgeSessionSummary[]; archivedIds: string[]; assistantSid?: string };
  hasSession(sid: string): boolean;
  phaseOf(sid: string): RemotePhase;
  snapshot(sid: string): { state: TurnState; rounds: RoundView[]; pendingQueue: string[] };
  deliverAnswer(sid: string, answers: readonly string[]): void;
}
```
- `start({ port = 0 })`：**强制 `host: '127.0.0.1'`**（非回环直接抛错，fail-closed）；
  监听失败**显式 reject**并保持未监听态（端口占用用例）。
- `stop()`：关闭全部连接 + 关 server。
- 每连接解析 `hello` → 回 `hello_ok { serverTime, pcId, caps, limits, assistantSid? }`；
  未 hello 的帧一律 `err{code:'forbidden'}`。
- `sub {sid}`：校验 `hasSession` → 回 `evt{kind:'snapshot', seq:0}`；缺失会话回
  `err{code:'no_session'}`。
- `cmd`：
  - 先按 `evaluateRemoteCommand(kind, phaseOf(sid))` 判准入（**真值表只此一份**）；
  - `answer` 交 `routeRemoteAnswer`（定址 + 查表 + 投递三件事都不在桥里重写）；
  - 非 `answer` 一律 `err{code:'forbidden', ch:'cmd', rid}`；
  - 受理后重发该 sid 的快照（让开发客户端立刻看到相位变化）。
- 快照里的 `rounds` **剥掉 `attachmentUris`**（webview 专属 URL，远端必 404）；其余字段
  原样，`assistantLog` 裁剪留 profile 3（注释写明这是 dev profile 的简化）。
- 不调 `post()`、不 `switch_session`、不 import `chatPanel`。

### 4.5 宿主接线
- `chatPanel.ts`

    否则 `chatPanelFlowIntegrity` 的机械登记会红）；`postTurnUpdateFor` 改为调用它后再盖章/投递。
  - 新增 `public projectSessionForBridge(sid)`：返回 `{ state, rounds, pendingQueue }`，
    **不盖章附件 URL、不 post、不受 `viewsMayShow` 限制**。
  - 新增 `public async submitBridgeInput(sid, msg)`：薄包装 `this.handleInput(msg, sid)`。
- `host/remote/remoteBridgeHost.ts`：`createRemoteBridgePorts({ panel, sessionStore, l10n })`
  - `listSessions` 复用 `webview/helpers/sessionList.ts` 的 `buildSessionListMessage`
    （`currentSessionId` 传 `''` = 不排除任何会话；助手会话仍按其参数排除）；
  - `hasSession` = `sessionStore.listSessions().includes(sid)`；
  - `phaseOf` = `remotePhaseOf(panel.projectSessionForBridge(sid).state, false)`；
    注释写明 profile 2 不判 `confirmPending`，且对 `answer` 是**保守**的（审批中相位是
