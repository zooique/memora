# ADR-021 · 记忆冲突消解（写路径取代检测）与闭环透明契约

> **状态**：✅ 已接受
> **日期**：2026-08-13
> **来源**：架构文档第三轮对抗性审查（第一性原理 + SSOT 自检），依据拍板方案落地
> **依赖**：[ADR-004](./ADR-004-memory-unification.md)（记忆 source 基元模型）、[memory-as-summary.md](../../docs/architecture/memory-as-summary.md)（摘要即记忆）、[agent-design-philosophy.md](../../docs/architecture/agent-design-philosophy.md)（单轮闭环公理）

## 背景

对抗性审查（第一性原理）暴露三类问题，需做架构决策收敛：

| # | 问题 | 本质 |
|---|------|------|
| G2 | "摘要即记忆"是 append-only，长期运行出现**重复 / 旧决策被新覆盖 / 过时事实仍被召回**；时间排序只解决"呈现顺序"，**解决不了"哪个决策覆盖哪个"**（覆盖是结构信息，非时序信息） | **信息模型缺陷**——冲突消解当前靠 LLM 召回时按时间序猜，违反"确定性优先" |
| G5 | "主动提问"声称避免不可靠启发式，落地却靠宿主从 text chunk 猜"是不是提问" | **逻辑矛盾**——启发式没消除，只是从内核移到宿主 |
| G9 | Trigger 预留 `{来源,意图,载荷}` 三元组，但载荷本就是闭环入参（冗余）、意图应由闭环"理解输入"统一识别（双源冲突） | 违反"不预埋接口"原则 |

## 决策

### 核心决策：G2 记忆冲突消解 = 写路径取代检测

把冲突消解从"**读时猜**"移到"**写时定**"，落在**闭环后处理（Reflect）**层面：

1. 每轮闭环完成后，生成摘要的同时，**检测新摘要与近期同类摘要（主题相关）是否疑似覆盖**；
2. 若覆盖，给旧摘要打确定性 `superseded` 标记并指向新摘要（**非删除**，保留可回溯）；
3. 读时（召回）按确定性过滤：`superseded` 摘要不再作为当前事实注入；需要历史时经 `traceSummary` 回溯；
4. 判断只在"新摘要与同会话旧摘要主题相关"时触发，非每轮必做。

#### 取代检测算法：加权 Jaccard 相似度（2026-08-18 优化）

**算法选择**：采用加权 Jaccard 相似度（而非标准 Jaccard），提升「多轮逐步细化」场景下的主题延续识别准确度。

**标准 Jaccard**（原始实现）：
```
Jaccard(A, B) = |A ∩ B| / |A ∪ B|
```

**加权 Jaccard**（2026-08-18 优化）：
```
WeightedJaccard(A, B) = Σ(交集关键词权重) / Σ(并集关键词权重)
```

**关键词权重策略**：
- **动作/意图词**（如「创建」、「删除」、「优化」）：权重 **2.0**
- **实体/对象词**（以「器/表/函数/模块」等后缀结尾）：权重 **1.5**
- **其他词汇**：权重 **1.0**

**实现函数**（`src/utils/segmenter.ts`）：
- `extractEnhancedKeywords(text)`：提取带权重的关键词列表
- `calculateWeightedJaccard(keywordsA, keywordsB)`：计算加权 Jaccard 相似度

**阈值**：`SUPERSEDE_OVERLAP_THRESHOLD = 0.5`（硬编码，确定性承诺）

**SSOT 合规**：
- ✅ 不引入动态阈值——阈值保持硬编码，保证写时判定结果的确定性
- ✅ 算法本身智能化——通过权重设计提升核心词的区分度，而非叠加外部判断规则
- ✅ 下沉到工具层——关键词提取和相似度计算统一在 `segmenter.ts` 工具层实现

**SSOT 自检（决策成立的前提）**：
- ✅ 不新增存储层——仍复用 round-summary；
- ✅ 不新增后台系统——是 Reflect 的一步，与"生成摘要"同构，fire-and-forget；
- ✅ 不新增记忆关系图——仅一个布尔标记 + 指针；
- ✅ 效率挪移——冲突消解从读路径（高频、每次召回都猜）移到写路径（低频、每轮一次判断），写一次定、读时确定性过滤。

**附带收益**：写时取代压缩同类摘要后，读路径聚合量更少，**缓解高频召回场景的重复聚合成本**（G7）。

### 配套决策

| # | 决策 | 落点 |
|---|------|------|
| G5 | **结构化提问事件**：LLM 以 `[ASK]` 结构化形式输出问题 → 内核**确定性解析**为 `question_pending` 事件（问题文本 + 挂起原因），宿主渲染；非启发式（约定优于检测） | mvp-scope §三 / philosophy §13.x / §14.3 |
| G9 | **删 Trigger 三元组预埋**：删除 `{意图,载荷}` 字段，保留一句"A2A/事件触发可按需扩展"（留生长点意识、删字段形状） | philosophy §2.1 |
| G3 | **串行边界声明**：串行是单 Agent 阶段的刻意约束、非普适真理，化解与多 Agent 愿景的张力 | philosophy §13 |
| G4 | **对话记录定位统一**：从"展示层"改为"展示层 + 溯源兜底的运行依赖"（召回/聚合不依赖，traceSummary 依赖） | memory-as-summary §5.2 |
| G1 | **摘要保真声明**：摘要是"有损线索"，保真由 traceSummary 兜底，诚实声明 | memory-as-summary §5.4 |
| G6 | **角色包差异化边界**：L2 枚举只承诺行为参数，价值分层 = L1 专业性 / L2 行为偏好 / L3 能力扩展 | role-pack-spec §三 L2 |

## 考虑的替代方案

- **方案 A·读时靠 LLM 时间序聚合（维持现状）**：零实现，但冲突消解依赖运行时判断，违反"确定性优先"，同类摘要长期冗余。**放弃**：信息模型缺陷是结构性的。
- **方案 B·独立 merge/supersede 状态机 + 后台任务**：彻底解决但引入记忆关系图 + 独立维护系统。**放弃**：违反单一真理源，超出最小单元边界。
- **方案 C（采纳）·写路径取代检测**：不新增存储/系统/关系图，效率挪移（写低频、读高频），同时满足 SSOT 与确定性优先。

## 后果

### 正面影响

- 记忆冲突从"读时猜"变为"写时定"，恢复"确定性优先"
- 消除 G5 启发式矛盾、G9 预埋接口
- 活动事件流落地首个真实用例（question_pending）

### 负面影响

- 取代检测引入逐轮一次 LLM 判断成本（仅同类相关时触发控制）
- 取代判断非纯确定性，存在误判/漏判风险，需实测收敛

## 何时回顾

- "新决策压制旧偏好"实测误判/漏判显著时，收紧同类相关性判据
- 宿主需要非自然语言 A2A 触发载荷时，评估 Trigger 是否扩展字段
- 进入多 Agent（异步 fork）时，审视 §13 串行边界是否升级为隔离模型
- 取代检测成本成为读路径负担时，回顾"摘要 + 原始对话"双轨召回
