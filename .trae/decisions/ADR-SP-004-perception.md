# ADR-SP-004 · 感知原则

> **状态**：✅ 已接受（2026-06-16）
> **依赖**：[ADR-006](./ADR-006-security-model.md)（安全模型）

## 背景

精灵的"主动进化"需要感知用户行为才能决定何时主动唤醒。但感知的粒度决定了隐私边界——监听键盘内容本质上是 keylogger。

## 决策

**上下文感知，非内容感知。精灵知道你在做什么，不知道你在打什么。**

### 分阶段实现

| 阶段 | 感知能力 | 唤醒方式 | 状态 |
|------|---------|---------|------|
| 阶段一 | 热键 + 定时 | Ctrl+Shift+M 召唤 + 每分钟检查主动触发条件 | ✅ 已完成 |
| 阶段二 | + 窗口上下文 + 文件变化 | active-win 窗口标题/进程名 + fs.watch 项目文件监听 | ✅ 已完成（FileWatcherTrigger） |

### 永远不做

- **全局键盘钩子**（iohook 等）：捕获任意按键内容 = keylogger
- **剪贴板监听**：可能包含密码等敏感信息
- **屏幕截图/OCR**：视觉内容可能包含隐私信息
- **网络流量监听**：超出本机边界

## 理由

- **隐私优先**：memora 的核心定位是"本地、私有"（project-rules.md），精灵的感知层不能破坏这个承诺
- **信号 > 内容**：精灵只需要行为信号（"用户切回了 VSCode"）而非内容信号（"用户在 VSCode 里打了什么"），足以做出合理的主动唤醒决策
- **安全审计友好**：感知层不接触任何用户输入内容，安全审计时无需额外审查

## 替代方案

| 方案 | 放弃原因 |
|------|---------|
| 全局键盘钩子 | 本质是 keylogger，与隐私原则冲突 |
| 剪贴板监听 | 可能包含密码、私钥等敏感信息 |
| 仅被动响应 | 无法实现"主动进化"，退化为普通聊天机器人 |
| 用户手动触发 | 可行但体验差，精灵应该"主动关心" |

## 影响

- 精灵的 `triggers.ts` 只实现信号级感知，不接触任何用户输入内容
- `FileWatcherTrigger` 使用 `fs.watch` 实现零依赖文件监听，只感知文件名变化，不读取文件内容
- 主动唤醒的判断逻辑基于 memora 的 insight/profile 记忆，不基于实时输入
- 阶段二引入 active-win 时，只读取窗口标题和进程名，不读取窗口内容
- 精灵主动行为（`proactivePrompt` 事件）基于 Agent 事件累积（memoryAdded/insightExtracted/personaSwitched），不基于用户输入内容
- 静默模式（`silentMode`）可完全关闭主动提示，用户始终拥有控制权
