一、为什么是 Codespaces（网络根因）

发布流程主文档（marketplace-publish-flow.html）阶段 1–2 的两步——注册 Publisher 与创建 PAT——都在 Microsoft / Azure DevOps 的网页上完成。这些登录页的人机验证组件（reCAPTCHA）需要从 google.com / gstatic.com 拉取脚本，在受限网络下被墙，导致登录卡死（台账缺口 7）。

GitHub Codespaces = 微软云（Azure）上的一台 Ubuntu 机器，预装网页版 VS Code。你的代码、终端、网络出口全在那台云机器上。reCAPTCHA 资源在 Azure 出口下是直通的——这是它解决本问题的唯一理由。Publisher 与 PAT 按主文档定性是「一次性前置」，做完即删机，不需要任何长期通道。

关键区分 github.dev（网页编辑器）网络仍走你本地，不解决；必须开真正的 Codespaces（拉起一台云主机，终端里 curl -sI https://www.google.com/recaptcha/api.js 返回 200 才对）。

三、操作步骤（命令复制即用）

  1. 建 Codespaces

    仓库页 → 绿色 Code → Codespaces 标签 → Create codespace on main。2 核默认机足够。区域按 IP 自动分配（东南亚或美东），Google 均通。

  2. 验证网络确实通

    curl -sI https://www.google.com/recaptcha/api.js | head -1   # 期望 200

  3. 装桌面 + 浏览器（整段复制即可）

    sudo apt-get update
sudo apt-get install -y xfce4 tigervnc-standalone-server novnc websockify dbus-x11 fonts-noto-cjk
curl -fsSL https://dl.google.com/linux/linux_signing_key.pub | sudo gpg --dearmor -o /usr/share/keyrings/google-chrome.gpg
echo "deb [arch=amd64 signed-by=/usr/share/keyrings/google-chrome.gpg] http://dl.google.com/linux/chrome/deb/ stable main" | sudo tee /etc/apt/sources.list.d/google-chrome.list
sudo apt-get update && sudo apt-get install -y google-chrome-stable
    snap 坑 apt 直接装 chromium 在官方源里是指向 snap 的桩包，Codespaces 没有 systemd，snapd 起不来。Chrome 必须走上面临时加的 Google 官方 .deb 源。

  4. 起 VNC 桌面 + noVNC 网页

    mkdir -p ~/.vnc
cat > ~/.vnc/xstartup <<'EOF'
#!/bin/sh
unset SESSION_MANAGER
unset DBUS_SESSION_BUS_ADDRESS
export XKL_XMODMAP_DISABLE=1
exec startxfce4
EOF
chmod +x ~/.vnc/xstartup
vncserver :1 -geometry 1600x1000 -depth 24
websockify -D --web=/usr/share/novnc/ 6080 localhost:5901
    密码双问（核心坑） vncserver :1 首次运行会要你设密码，紧接着问 「是否设置 view-only（只读）密码」。全程只用第一问的常规密码登录 noVNC。view-only 密码登录 = 仅浏览权限，鼠标键盘全部禁掉。最省事：第二问直接 n 跳过，根本不设只读密码。详见第四节。

  5. 端口转发 + 打开

    VS Code PORTS 面板 → 转发端口 6080 → 右键可见性设为 Private（默认即 Private）。复制转发地址，在本地真实浏览器打开，末尾加 /vnc.html → Connect → 输入常规密码。

    可见性 不要设 Public：Public 链接谁拿到谁就能操作你的云桌面，而你正在上面登录微软账号。Private 仍要你的 GitHub 登录态，外人打不开。

  6. 桌面内完成注册

    点底部 Dock 第一个图标（终端），或 Applications → Internet → Google Chrome 打开浏览器，访问： 

    https://marketplace.visualstudio.com/manage      # 登录 → Create Publisher，ID 照抄 zooique
https://dev.azure.com                          # User settings → Personal access tokens → New Token
                                                #   Organization = All accessible organizations
                                                #   Expiration = 1 year
                                                #   Scopes = Show all scopes → Marketplace → Manage

    PAT 只显示一次，当场复制，存进本地密码管理器（不落云机器任何文件、不进 git）。

  7. 回本地收尾

    cd hosts/memora-vscode
npx vsce login zooique   # 粘贴 PAT

    之后按主文档走阶段 3–5。最后 github.com/codespaces → 该机 ... → Delete，清掉微软登录态与 VNC 密码。

四、根因澄清：鼠标失控 = view-only 密码

✅ 实测根因（2026-10-14） 桌面能显示、但鼠标键盘完全无响应，原因是 vncserver 设密码时误用了 view-only（只读）密码登录 noVNC。view-only 模式天然只授予屏幕观看权限，输入被禁。改用第一问的常规密码登录，鼠标键盘即正常。

早期关于「VS Code 内置预览 / 网页版 VS Code 的 iframe 拦截指针事件」的猜测，在本次实测中被推翻——真正的拦截来自 VNC 的只读密码，与浏览器打开方式无关。结论：环境卡顿先查密码类型，再查别的。

顺带：noVNC 永不锁住你的本地鼠标——本地光标永远在你这边，网页画布里那个是 noVNC 驱动的远端光标。远端光标不动 = 远端 X 会话没收到输入（只读密码），不是你鼠标坏了。

坑 表现 / 判据 处理

六、更省的先手

本方案是计划 B。先花 5 分钟试手机热点——reCAPTCHA 不一定每次都加载，热点能过则上面这整套命令一行都不用敲。若热点不行，再上 Codespaces。

补充观察：Open VSX 的登录走 GitHub 账号，天然没有这个卡点；但按主文档定性，Open VSX 是 0.1.0 的非阻塞可选项，不改变主路径。
