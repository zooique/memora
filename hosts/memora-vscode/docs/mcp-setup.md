# MCP 工具接入（把外部工具服务器接进对话）

Memora 是一个 **MCP 客户端**：你告诉它有哪些「工具服务器」（MCP server），它把这些
服务器暴露的工具注册进 Agent——模型在对话里能像调用内置工具一样调用它们，工具名形如
`mcp__<服务器名>__<工具名>`。

> 方向说明：本文讲的是 **Memora 消费外部工具**。Memora 自身作为 MCP server 对外暴露
> 记忆能力是另一个方向（独立仓库 `hosts/memora-mcp`），两者互不相干。

## 快速开始（5 分钟跑通全流程）

1. 打开设置面板（`Ctrl+Shift+P` → `Memora: 打开设置面板`）→ **MCP** 选项卡，点右上角「添加服务器」：

   | 表单字段 | 本例 |
   |----------|------|
   | 名称 | `everything` |
   | 命令 | `npx` |
   | 参数 | `-y` 与 `@modelcontextprotocol/server-everything`（一行一个） |

   点「保存」即写入用户级 `memora.mcpServers` 并**立即生效**（无需重载窗口）。表单里
   清空「参数 / 环境变量 / 工作目录」再保存 = **真的删掉这三项**（不是"保持原值"）；表单
   不认识的字段（例如将来新增的 `timeout`）会原样保留，不会被编辑动作冲掉。想手写 JSON
   走页脚「高级：在 settings.json 中编辑」。

2. 打开 Memora 对话面板，问一句「你有哪些工具」——列表里出现 `mcp__everything__*`
   即接入成功（工具清单每轮重建，改完配置**即时生效**，无需重载窗口）。
3. 让模型调一个工具（如 `echo`）：首次调用会弹确认框——这是**设计行为**，不是故障。
4. 信任某个工具、不想每次都被问：在 MCP 页该工具行勾上「免确认」（或直接写
   `memora.mcpToolAllowlist`，见下文），立即免确认（仍写审计）。

排障入口：服务器起不来 / 工具没出现 / 调用异常，先看 **输出面板 → Memora**
（server 的 stderr 与宿主的接入告警都打在这里）。

## 配置服务器（`memora.mcpServers`）

用户级设置（随用户、不随项目）。**只认用户级**：工作区级配置可被他人提交进仓库、
等于让任意仓库自动拉起任意命令——**已定案不开放**（2026-10-25），不是暂缓。
作用域为 `machine`（2026-10-25 拍板）：只写用户设置、**不随 VS Code Settings Sync 同步**
——`headers` 里的明文令牌与免确认批准都留在本机，不会被带到同账号的其他设备（跨机同步
等于替另一台机器点同意）。代价 = 每台机器各配一次。

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | ✅ | 服务器名（唯一）。进工具名前缀 `mcp__<name>__<tool>`，也是停用与日志的寻址键 |
| `command` | ✅ | 拉起的**可执行程序**：PATH 里的名字（`node` / `npx` / `python`）或可执行文件的绝对路径。脚本文件本身不能当命令（见下） |
| `args` | | 命令参数；第一项若是路径形态（绝对路径或以 `./` `../` 开头），按 `cwd`（填了的话）否则工作区根解析 |
| `env` | | 追加的环境变量（与默认安全环境合并，同名键以此处为准；不写也能拿到 PATH） |
| `cwd` | | 子进程工作目录；相对值按**工作区根**解析，缺省继承扩展宿主 |
| `enabled` | | 缺省 `true`；`false` = 不拉起、工具对模型不存在 |

多条配置按 `name` 寻址；重名**先到先得**（后者跳过并告警）；缺 `name`/`command`
的条目跳过并告警——不猜意图。

### 命令与路径（最常见的坑）

不要「把脚本丢到某个约定目录再填文件名」——本项目**不规定脚本放哪**，MCP server 就是
一个普通子进程，位置由 `command` + `args` 决定。三种合法写法：

```jsonc
// ① PATH 里的可执行程序（推荐：跨机器可移植）
{ "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/dir"] }

// ② 绝对路径的可执行文件
{ "command": "C:/tools/my-mcp-server.exe", "args": [] }

// ③ 本地脚本：命令填解释器，脚本路径放进参数（脚本本身不能直接当命令）
{ "command": "node", "args": ["F:/work/my-mcp/server.js"] }
```

三条容易踩的：

- **脚本当命令**：`"command": "./server.js"` 在 Windows 上起不来（不认 shebang），要写
  `"command": "node", "args": ["./server.js"]`；macOS/Linux 只有「可执行位 + shebang」
  齐全时才能这么写，否则同样要填解释器；
- **相对路径的基准**：`./server.js` 按 `cwd`（填了的话）否则**工作区根**（你打开的那个项目）
  解析，不是按 `settings.json` 所在目录，也不是按扩展安装目录；
- **PATH 里没有**：`"command": "node"` 要求 node 真的在 PATH 里（Windows 上装完 node
  需要重开终端/编辑器才会生效）。

启动前会做一次**静态预检**（命令是否存在、路径是否指向脚本、工作目录是否存在）：不通过
就不拉起子进程，原因直接显示在该服务器的卡片上（`启动失败：找不到可执行文件：…`）。
注意预检只管「必然失败」，通过预检不等于一定能跑通——依赖缺失、握手失败、权限问题仍要
看卡片上的失败原因与输出面板。

### 在设置面板里管理（推荐）

MCP 页每台服务器一张卡片，卡片上给出这一台的**真实状态**（不是「我以为连上了」）与
可做的动作：

| 状态 | 含义 | 可做的事 |
|------|------|----------|
| **已连接** | 子进程已起、工具已注册 | 重启 / 编辑 / 停用 / 删除 / 逐工具勾「免确认」 |
| **启动失败** | 拉起失败（命令不存在、退出码非 0、握手超时…） | 卡片直接显示失败原因；改完配置点「重启」重试 |
| **待接入** | 配置已存，但**运行态还没追平**（该名没进 applied：Agent 尚未装配，或装配 / 热更没跑到它） | **接入**（按当前配置追平一次，未装配会先完成装配）/ 编辑 / 停用 / 删除；打开对话面板也会自动连接并转「已连接」 |
| **已停用** | `enabled: false`，不拉起、工具对模型不存在 | 启用 / 编辑 / 删除 |
| **配置不完整** | 缺 `command`，启动侧会跳过 | 编辑补全 / 删除（配置不完整时不给「启用」——那是假动作） |

> **「待接入」不是故障**：它只表示「配置在这儿、还没连」。点卡片「接入」或开一次对话面板即可；
> 连不上会自己转成「启动失败」并给原因。

- **名称是身份**：它同时是工具名前缀与免确认寻址键 ⇒ 编辑已有服务器时名称只读；
  改名 = 删除后重建。
- **参数 / 环境变量按行编辑**：参数一行一个（**不做 shell 解析**，参数里的空格不被
  拆引号）；环境变量一行一个 `KEY=VALUE`（按第一个 `=` 切分，值里可含 `=`）。
- **有损形态只禁编辑、不禁查看**：`args` 含空项或换行、`env` 键为空 / 含 `=` / 含
  换行、值含换行时，文本表单无法无损表达——该台「编辑」置灰并指路 settings.json。
  面板不改写它呈现不了的字符（静默改写用户配置比不能编辑严重得多）。
- **删除要二次确认**（改配置不可撤销）；删除**不联动**清免确认记录——那是逐条授予的
  信任记录，重新添加同名服务器时档位自动恢复。
- **不乐观翻转**：保存 / 停用 / 勾免确认都只上报，界面等配置回推后更新。卡片上看到的
  状态即持久化真值；写入或校验失败会在页顶弹失败回执，不会「点了没反应」。

### 手写 JSON（高级）

示例（文件系统服务器，只放开一个目录）：

```json
"memora.mcpServers": [
  {
    "name": "fs",
    "command": "npx",
    "args": ["-y", "@modelcontextprotocol/server-filesystem", "D:\\笔记"]
  }
]
```

## 免确认白名单（`memora.mcpToolAllowlist`）

默认**每次调用都弹确认**（MCP 工具来源不可信，宁多弹窗，不静默放行）。白名单命中
= 免弹窗，**但仍写审计**（`write-auto`，可在审计记录里回查）。

最省事的做法是在 MCP 页的工具行勾「免确认」——它写的就是下面这个键，不用你手拼名字
（勾选/取消都以配置回推为准，写不进去会在页顶弹回执）。手写 JSON 的规则如下：

- 键格式有两种，都按**原始名**寻址——配置里写的 `name` 和 server 的工具名，
  **不是**模型列表里那个显示名：
  - 工具级 `mcp__<服务器名>__<工具名>`：只放行这一个工具；
  - 整台级 `mcp__<服务器名>__*`：放行这台服务器的**全部**工具（一次勾选，免掉逐个点）。
- 没有「一次放行所有服务器」的写法：server 位不通配，`mcp__*` 不是合法键。放行几台
  就要显式写几条键（防「自动化默认」）。
- 原名含 `-` / `.` 等字符时显示名会被清洗成 `_`（如 `my-tool` → `mcp__fs__my_tool`），
  按显示名写**不命中**、回落为每次确认（防呆：写错的表现是「还在问」，不是「悄悄放行」）。
- 读不到合法值（非数组 / 空串项）⇒ 全部按每次确认处理（fail-closed）。

```json
"memora.mcpToolAllowlist": ["mcp__fs__read_file", "mcp__everything__*"]
```

> 上例第一条只放行 `fs` 的 `read_file`；第二条放行 `everything` 这台的**全部**工具。

## 改配置后多久生效

「配置没变」的服务器**不重连**——进行中的调用不被打断。同一台服务器改了参数是
**先停后起**（不会两套工具并存）。

配置**没变**但连接已经坏了（子进程被外部杀掉、server 启动即崩）时，热更不会触发——
用卡片上的「重启」按名字重建连接，这是变了配置之外的唯一恢复路径。

| 改动 | 生效方式 |
|------|----------|
| 新增服务器 | 立即拉起并注册（当前对话下一轮即可见） |
| 停用（`enabled: false`）/ 删除 / 改命令参数 | 立即停旧连接、注销其工具 |
| 改白名单 | 立即重算档位（不重连服务器） |
| 点「重启」 | 不看配置有没有变，直接停旧起新（失败原因回卡片与页顶） |
| Agent 未装配时改配置 | 下次打开面板装配时生效（不为改一次设置付整个装配成本）；面板会立即推出配置真值，不显示过期状态 |

## 安全说明

- **子进程**：每条配置拉起一个本地子进程，只填你信任的服务器；停用/删除即杀进程。
- **审批**：MCP 工具与内置工具走**同一条确认链**（内核单路径），没有第二套审批；
  白名单只关弹窗、不关审计。
- **只读标记不作信任依据**：服务器自称「只读」不改变审批档位。
- **写盘不被 diff 追踪**：经 MCP 工具写文件**不进**「文件改动」确认/回退链
  （该链的覆盖面按**内置**工具定义的 `diskWrite` 声明在构造期派生；MCP 工具的写目标
  无法静态判定，宿主不给它声明该字段）——审查流看不见它改的文件，风险由审批 +
  审计承担。需要追踪的写操作请用内置 `write_file`。
- **不做检索式加载**：工具全量进上下文。服务器很多时（合计 > 64 个工具）会在输出
  面板告警——工具过多会降低模型选对工具的准确率，可停用部分服务器收敛。

## 已知边界（如实登记）

- **图片 / 音频 / 资源内容**会被丢弃并注明类型（内核工具结果只收文本）；
- **结构化输出**（`structuredContent`）在无文本正文时降级为 JSON 文本；
- **超长结果会被截断**：单条结果超过 20,000 字符即截断并附原长说明（模型可改用分段
  参数重取；上下文硬闸在内核，与此处软闸不互替）；
- **取消不传播**：确认拒绝 / 调用超时不会通知 server 中止在途请求（超时不断连接，
  server 侧请求继续跑）；
- **跨服务器撞名**：两个不同服务器的工具清洗后同名时，后注册者接入失败并告警
  （改其中一个的服务器名即可绕过）；
- **工作区级 `.mcp.json` 不读取**（见上）；
- **缺 `name` 的条目不在面板列**：`name` 是唯一寻址键（工具名前缀、删除/停用/免确认
  都按它定位），没有名字的条目面板既不认识也无法安全地改——启动侧会告警跳过，请去
  settings.json 补上名字或删掉（面板只列「有名字但缺 command」这一类可修复的）；
- **面板保存与手改 JSON 并发**：每次保存前会重读配置做基底（把覆盖窗口从「人编辑的
  分钟级」压到毫秒级），但读-写仍**非原子**——同一时刻在 settings.json 里手改，仍
  可能被面板的整数组写入覆盖（已登记台账）。改配置以一处为准。

## 排障速查

| 现象 | 先看 |
|------|------|
| 卡片显示「启动失败」 | 卡片上的失败原因；输出面板 Memora 的 server stderr（`[DEBUG] [MCP:名字]` 行，脚本自身崩溃的原因只在这里）；`command` 在 PATH 里吗 |
| 失败原因只有 `Connection closed`（-32000） | 子进程启动即崩（连握手都没到）：在终端直跑一遍该命令看真实报错——最常见是脚本 `import` 的包在**它所在目录**解析不到（ESM 按脚本路径找 `node_modules`，与面板里填的 `cwd` 无关） |
| 卡片显示「待接入」 | 点卡片「接入」（按当前配置追平一次），或开一次对话面板；连不上会转「启动失败」并给原因 |
| 工具没出现 | 输出面板 Memora：握手失败 / 「本宿主当前只接 tools 能力」（该 server 只提供 resources / prompts，非故障）/ 分页异常收口 / 顶层 `anyOf` 剔除（该工具形态本期不支持） |
| 调用没反应然后报错 | 60s 转发超时（server 卡死）——连接不断，其余工具照常可调 |
| 配置没改但连接坏了 | 点该卡片「重启」（配置未变时热更不会重连） |
| 一直弹确认 | 白名单键写的是显示名？按原名（`mcp__<服务器名>__<工具名>`）写，或直接用工具行的「免确认」勾选 |
| 保存后没反应 | 页顶 toast 有无失败回执（写入失败 / 校验不通过会明说）；卡片状态点是否变化 |
| 改了配置没生效 | 已支持即时热更；若 Agent 未装配（面板没开过），打开面板即生效 |
