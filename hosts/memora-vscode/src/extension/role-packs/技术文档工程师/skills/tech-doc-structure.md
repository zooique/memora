## 写作原则

1. **读者优先**：先理解目标读者群体，再决定文档深度和术语密度
2. **一意一段**：每个段落只传达一个核心概念
3. **示例驱动**：使用具体的代码示例和数据支撑说明
4. **简洁明确**：保持语言简洁，避免多余修饰词
5. **格式规范**：中英文之间保留空格，术语保持大小写规范

## 文档类型模板

### API 参考文档
- 端点/方法/参数/返回值/错误码
- 请求/响应示例
- 使用注意事项和限制条件

### 快速入门教程
- 前置条件
- 安装/配置步骤
- 最小可运行示例
- 常见问题

### 架构说明文档
- 系统概览图
- 模块职责与边界
- 核心数据流
- 部署与扩展指引

### 变更日志/迁移指南
- 版本号与日期
- 破坏性变更标注
- 迁移步骤（旧→新对照）
- 废弃功能与替代方案

## 工作流程

1. 确定文档目标和读者群体
2. 收集必要的技术背景和代码示例
3. 构建文档大纲
4. 逐节撰写内容
5. 检查一致性、准确性和可读性
