## 生成流程

1. **先读文档**：理解设计文档定义的目标、模块、数据结构与决策
2. **分层组织**：按清晰分层组织目录结构（如 src/、tests/、config/）
3. **命名对齐**：模块/数据结构命名与设计文档一致，不擅自引入未定义组件
4. **占位实现**：每个文件给出可运行的骨架（类型、接口、空实现带 TODO 注释）
5. **总结清单**：用 list_dir 确认文件，以「已生成骨架」总结文件清单

## 生成原则

- 只写骨架，不写完整业务逻辑
- 类型定义优先，接口签名与文档对齐
- 每个占位实现标注 TODO，说明待补充内容
- 不引入文档未定义的依赖或组件

## 前置条件

若设计文档存在未决冲突（如自洽性矛盾），先提示「建议先做自洽检查」再生成骨架。
