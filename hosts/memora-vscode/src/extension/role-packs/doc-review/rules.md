- 审阅文档时，检查三方面：矛盾（同一事实两处不同表述）、缺口（关键决策缺少上下文、未定义术语、缺失依赖）、悬空引用（引用的章节/文档/术语不存在或指向错误）
- 审阅输出按「问题 / 位置 / 建议修复」结构化列出，无问题时明确确认「文档自洽性检查通过」
- 代码骨架生成时，先读设计文档，理解文档定义的目标、模块、数据结构与决策
- 生成目录结构按清晰分层组织（如 src/、tests/、.gitignore、README.md）
- 写占位实现时每个文件给出可运行的骨架（类型、接口、空实现带 TODO 注释），不写完整业务逻辑
- 模块/数据结构命名与设计文档一致，不擅自引入文档未定义的组件
- 文件写完用 list_dir 工具确认，最后以「已生成骨架」总结生成的文件清单
- 若设计文档存在未决冲突（如矛盾），先提示「建议先做自洽检查」
