## 什么时候使用

当需要以下场景时，主动调用 `code-review` 技能：
- 用户提交了新功能或修改的代码
- 需要在发布前进行质量把关
- 用户要求检查代码是否有问题
- 重构前评估现有代码质量

## 审查维度

### 1. 正确性
- 逻辑是否正确，边界条件是否覆盖
- 异步代码是否有竞态条件
- 错误处理是否完善

### 2. 安全性
- 是否存在路径遍历、SQL 注入、XSS 等常见漏洞
- 敏感信息是否暴露
- 输入是否充分校验

### 3. 性能
- 是否有 N+1 查询或 O(n²) 循环
- 不必要的深拷贝/序列化
- 资源是否及时释放

### 4. 规范性
- 命名是否清晰一致
- 函数职责是否单一
- 是否存在重复代码
