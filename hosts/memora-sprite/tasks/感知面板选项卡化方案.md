## 1. 问题分析

### 1.1 现状

感知面板（`#perception-panel`）是 overlay 弹出层，从消息区顶部 slide-down，最大高度 400px，内部滚动。当前 6 个 section 平铺：

| Section | 内容 | 数据密度 |
|---------|------|----------|
| 情感基调 (affect) | 四维进度条（温暖/直接/主动/调皮） | 中 |
| 默契度 (rapport) | 等级徽章 + 2 进度条 + 描述文本 | 中 |
| 对话上下文 (context) | 三列指标（节奏/话题/深度） | 低 |
| 叙事摘要 (narrative) | 段落文本 | 低 |
| 模式洞察 (patterns) | 动态列表（重复/缺口/漂移） | 中 |
| 运行指标 (metrics) | 9 项 dash-item 网格 + 里程碑（默认折叠） | 高 |

### 1.2 核心矛盾

- **信息密度 vs 视觉空间**：6 个 section 平铺在 400px 高度内，每个 section 可用空间不足 60px，进度条和文字挤在一起
- **主次不分**：情感基调（高频查看）与运行指标（低频查看）占据同等视觉权重，用户扫视时无法快速定位关心内容
- **滚动疲劳**：400px 装不下全部内容，需要滚动，但 overlay 滚动体验差（滚轮事件可能穿透到消息区）

### 1.3 用户心智模型

用户打开感知面板的意图通常是：
1. "精灵现在感觉怎样？" → 情感基调 + 默契度（关系状态）
2. "精灵理解到什么程度？" → 对话上下文 + 叙事摘要（理解状态）
3. "精灵学到了什么？" → 模式洞察 + 运行指标（学习成果）

三种意图对应三种查看场景，但当前平铺设计强迫用户一次性面对全部信息。

## 2. 设计方案

### 2.1 选项卡分组

采用 **3 选项卡** 方案，按用户心智模型分组：

```
┌─────────────────────────────────────────────┐
│  精灵感知状态                          [✕]   │
├─────────────────────────────────────────────┤
│  [ 关系 ]  [ 理解 ]  [ 洞察 ]                │  ← 选项卡栏
├─────────────────────────────────────────────┤
│                                             │
│  （当前选项卡内容，仅显示 2 个 section）      │
│                                             │
└─────────────────────────────────────────────┘
```

| 选项卡 | 包含 Section | 设计理由 |
|--------|-------------|----------|
| **关系** | 情感基调 + 默契度 | 关系状态是最高频查看项，两者都描述"精灵与用户的关系"，进度条视觉风格统一 |
| **理解** | 对话上下文 + 叙事摘要 | 描述精灵对当前对话的理解，文字类内容为主，节奏紧凑 |
| **洞察** | 模式洞察 + 运行指标 | 分析类信息，低频但信息量大，运行指标保持折叠交互 |

### 2.2 选项卡交互设计

- **默认选中**：关系（最高频查看场景）
- **切换动画**：无（保持简洁，避免 overlay 内动画 jank）
- **记忆选中**：不记忆（每次打开回到"关系"，降低认知负担）
- **键盘导航**：左右方向键切换选项卡，Tab 键聚焦选项卡
- **视觉反馈**：
  - 选中项：底部 2px accent 色下划线 + text 主色
  - 未选中项：text-3 次要色，hover 时 text-2 + 浅背景
  - 选项卡栏底部 1px surface2 分割线

### 2.3 空间利用优化

选项卡化后，每个选项卡仅需展示 2 个 section，可用空间翻倍：

| 选项卡 | 原可用高度 | 现可用高度 | 提升 |
|--------|-----------|-----------|------|
| 关系 | ~133px (400/3) | ~340px (400-60) | 2.6x |
| 理解 | ~133px | ~340px | 2.6x |
| 洞察 | ~133px | ~340px | 2.6x |

> 60px = header(32) + 选项卡栏(28) 的估算值

进度条间距可从当前紧凑值放宽，文字可使用更大字号，整体呼吸感提升。

### 2.4 响应式考虑

- 选项卡栏在窄窗口下保持单行（3 个选项卡宽度足够）
- 不需要横向滚动（与 6 section 选项卡的方案相比，这是 3 选项卡的优势）
- 选项卡文字使用 `font-xs`，与现有 section-title 一致

> 实际实现采用"紧凑化重构 + 折叠区"方案（见待完成任务.md 2026-07-02 记录）：
> - 2×2 情感网格 + 默契度一行 + 上下文内联 + 叙事概览 + 拆分折叠区
> - 运行指标紧凑网格采用 `.perception-metrics-grid.collapsed` 折叠（max-height + opacity 过渡，迭代二引入，替代 `display:none` 硬切）；模式洞察 / 主动提示等分区显隐用 `.hidden` 类（由 `relatedBtn` 等点击触发）
> - 核心从 ~270px 压缩至 ~150px，未引入选项卡切换 TS 逻辑
> 下方代码保留作为方案设计参考，如后续需切换为选项卡模式可参考此实现。

```typescript
// 选项卡切换逻辑
private bindPerceptionTabs(): void {
  const tabs = document.querySelectorAll('.perception-tab');
  const panes = document.querySelectorAll('.perception-tab-pane');
  tabs.forEach((tab) => {
    this.events.addEventListener(tab as HTMLElement, 'click', () => {
      const target = (tab as HTMLElement).dataset.tab;
      tabs.forEach((t) => {
        t.classList.remove('active');
        t.setAttribute('aria-selected', 'false');
      });
      panes.forEach((p) => p.classList.remove('active'));
      tab.classList.add('active');
      tab.setAttribute('aria-selected', 'true');
      const targetPane = document.querySelector(`.perception-tab-pane[data-pane="${target}"]`);
      if (targetPane) targetPane.classList.add('active');
    });
  });

  // 键盘导航：左右方向键切换
  const tabList = document.querySelector('.perception-tabs');
  if (tabList) {
    this.events.addEventListener(tabList as HTMLElement, 'keydown', (e: Event) => {
      if (!(e instanceof KeyboardEvent)) return;
      const tabsArray = Array.from(document.querySelectorAll('.perception-tab'));
      const currentIndex = tabsArray.findIndex((t) => t.classList.contains('active'));
      let newIndex = currentIndex;
      if (e.key === 'ArrowRight') newIndex = (currentIndex + 1) % tabsArray.length;
      else if (e.key === 'ArrowLeft') newIndex = (currentIndex - 1 + tabsArray.length) % tabsArray.length;
      else return;
      e.preventDefault();
      (tabsArray[newIndex] as HTMLElement).click();
    });
  }
}
```

## 5. 风险评估

| 风险 | 影响 | 缓解 |
|------|------|------|
| 选项卡栏占用垂直空间 | 每个选项卡可用高度减少约 28px | 400px - 28px = 372px，仍远大于原来的 133px/section |
| 选项卡切换打断用户查看 | 用户需多次切换才能看全信息 | 3 选项卡是平衡点；关系/理解为高频，洞察为低频，切换频率低 |
| 运行指标折叠状态在选项卡内仍有效 | 用户切换到洞察选项卡时 metrics 可能已展开 | 保持现有折叠逻辑不变，无额外问题 |
| 主题切换时选项卡样式适配 | 暗色模式下选项卡可读性 | 全部使用 CSS 变量，自动适配 |

## 6. 备选方案对比

| 方案 | 选项卡数 | 优点 | 缺点 | 结论 |
|------|---------|------|------|------|
