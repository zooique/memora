#### 排雷结论

| 风险点 | 等级 | 归属 | 缓解措施 |
|--------|------|------|----------|
| F1 跨层数据依赖 | 🔴 高 | F1 | BM25 的 IDF 需全量文档集统计，searchSessionMessages IPC 仅返回 20 条匹配结果，渲染层无法获取完整 IDF；放弃 BM25，改用渲染层多关键词匹配（如需做） |
| F1 与内核 DRY | 🟡 中 | F1 | 内核 searchHybrid 已实现 BM25 类似的混合搜索（hybridMerge.ts），渲染层再实现一份违反 DRY |
| F1 过早优化 | 🟡 中 | F1 | 无数据支撑的算法升级。Top-5 排序差异在 0.05-0.1 之间用户基本无感；真正影响用户的是"是否有相关候选"而非"候选排序" |
| F2 隐私泄露 | 🔴 高 | F2 | 只记 query 长度 + hash，不记原文；用户输入可能含敏感信息 |
| F2 localStorage 膨胀 | 🟡 中 | F2 | LRU 淘汰上限 500 条（约 50KB），与 adoptedTexts 同策略 |
| F2 数据消费缺失 | 🟡 中 | F2 | 强制配套：记忆管理面板新增"补全统计"section，否则埋了点没人看 |

#### 方案方向

| 顺序 | 任务 | 理由 |
|------|------|------|
| 1 | **F2 先做**（埋点 + 统计面板） | 数据驱动决策，无数据则 F1 是盲投 |
| 2 | 观察 1-2 周补全数据 | 收集"展示→采纳"转化率、Top-1 命中率、平均采纳位置 |
| 3 | 根据数据决定 F1 | 若 Top-1 命中率 > 60% → F1 不需要做；若 < 40% → 做轻量多关键词匹配（渲染层独立完成，不跨层） |

#### F2 埋点 schema 设计（待方案设计阶段细化）

```
localStorage key: memora-completion-metrics
{
  events: Array<{
    queryLen: number,              // 查询长度（不记原文）
    queryHash: string,             // 查询文本 hash（短 hash，用于聚合相似查询）
    shownCount: number,            // 展示候选数
    adoptedPosition: number | null,// 采纳位置（-1=未采纳）
    adoptedTextHash: string | null,// 采纳文本 hash
    timestamp: string,
  }>,
  aggregated: {                    // 定期从 events 计算
    totalShown: number,
    totalAdopted: number,
    adoptionRate: number,          // 采纳率
    top1HitRate: number,           // Top-1 命中率
    avgAdoptedPosition: number,
  }
}
```

容量治理：events 数组上限 500 条，LRU 淘汰；aggregated 每次写入时重算。
消费路径：记忆管理面板新增"补全统计"section，展示采纳率/Top-1 命中率/平均位置 + 最近 50 条事件的查询长度分布。

#### F1 替代方案（暂缓，待 F2 数据验证后决定）

放弃 BM25，改用渲染层可独立完成的轻量改进：
- 多关键词匹配：将 query 分词，统计匹配词数 + 平均位置
- 词频加权：匹配词出现次数越多 score 越高
- 长度归一化：短文本中匹配比长文本中匹配更相关

这是 BM25 的"轻量降级版"，无需跨层数据。但**仍建议暂缓**，等 F2 数据验证排序策略是否真有问题。

| COMP-0715-F1 | 对话 score 用朴素 indexOf 位置匹配，语义相同但位置不同的文本分数差距大 | quickInputCompletion.ts L349-354 | **暂缓**，待 F2 数据验证后决定是否做轻量多关键词匹配（放弃原 BM25 方案，跨层 DRY 风险） |
| COMP-0715-F2 | 无使用数据度量，无法回答"排序策略是否最优" | quickInputCompletion.ts | **优先做**：埋点 + 统计面板。隐私优先（只记 hash 不记原文），LRU 500 条上限，强制配套消费路径（记忆管理面板新增统计 section） |
