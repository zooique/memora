#### 设计决策

1. **H2 渲染器归属**：新建独立渲染器（非扩展 healthDashboardRenderer）。理由：healthDashboardRenderer 职责是"展示健康度快照"（被动消费 payload），LLM 治理结果是"展示操作结果"（主动注入报告），职责不同。复用 G3 已预留的 `#health-llm-result` 容器。

2. **H2 结果持久化范围**：只展示最近一次，不存 localStorage。理由：治理操作低频（手动触发），历史价值低；若未来需要趋势分析，再考虑持久化（ADR-017 枝叶层 2 次触发）。

3. **H2 冲突详情"恢复"入口**：L1/L2 降级列表提供"恢复"入口（调用 `boostMemory` IPC，score +0.05/次），L3 冲突检测不提供"修复"入口（仅检测不修复，需用户手动消歧）。理由：与内核 L1~L3 设计语义一致，boostMemory 与降级语义对称（降级=score 降低，恢复=score 提升）。

4. **H1 数据点展示形态**：追加文本（最小侵入），不新增卡片结构。理由：payload 字段已有，只需在现有 DOM 元素 textContent 追加，符合 ADR-017 枝叶层最小化原则。

#### 排雷结论

| 风险点 | 等级 | 归属 | 缓解措施 |
|--------|------|------|----------|
| H1 DOM 结构不足 | 🟢 低 | H1 | 现有 `#health-duplicates`/`#health-stale` 单行展示可能溢出；先读 HTML 确认容器，不足则改 title 属性悬停展示 |
| H1 字段空值边界 | 🟢 低 | H1 | `similarity` 可选字段，`staleMemories` 可能为空；渲染前判空，空值不追加文本 |
| H2 渲染器职责膨胀 | 🟡 中 | H2 | 严格限定职责为"渲染最近一次报告 + 单条恢复入口"，历史/批量需求等枝叶层 2 次触发再做 |
| H2 冲突对展示信息不足 | 🟡 中 | H2 | 执行前先读内核 `ConflictReport` 类型定义，若信息不足则渲染"点击查看详情"复用 showMemory IPC |
| **H2 恢复入口语义冲突** | 🔴 高 | H2 | **重要修正**：原设计用 restoreMemory 错误（降级非软删除）。改用 `boostMemory`（score +0.05），与 L2 采纳反哺同语义 |
| H2 渲染时机 | 🟢 低 | H2 | 结果渲染到持久 DOM 容器，切换面板不丢失；不主动清空 |
| H2 测试 mock 复杂度 | 🟢 低 | H2 | 渲染器通过依赖注入或全局函数 mock，复用 G3 测试已有 mock 模式 |
| H2 CSS 类名冲突 | 🟢 低 | H2 | 命名前 Grep 确认无冲突，遵循现有 `health-*` 前缀模式 |
| H1+H2 并行风险 | 🟢 低 | H1/H2 | H1 改 healthDashboardRenderer，H2 新建渲染器 + 改 memoryController，无文件交叉，可并行 |
| 向后兼容 | 🟢 低 | H1/H2 | 纯渲染层变更，不碰 IPC/内核，无跨层兼容风险 |

#### 执行顺序

1. **H1 先做**（极低成本，4 字段消费，预计单批次完成）
