# 剪贴板模块重思方案

> **状态**：📐 设计方案（待方案生长执行）
> **日期**：2026-07-18
> **来源**：用户反馈"复制就触发提示打扰使用体验" + 模块重思（big-tree-grower 模式 4）
> **范围**：剪贴板闭环（闭环 6）的 UI 触发方式重构——从"主动打扰"改为"被动等待 + 保护性主动"
> **架构归属**：渲染进程 `renderer/panels/clipboardPanelManager.ts`（新增）+ `renderer/panels/clipboardManager.ts`（改造）

## 1. 聚焦模块

**模块名称**：剪贴板保护闭环（Clipboard Protection Loop）

**模块范围**：

| 层 | 文件 | 本方案是否改动 |
|----|------|----------------|
| 主进程 | `src/electron/clipboardHandler.ts` | ❌ 保持原状（轮询/哈希/敏感检测/护栏不变） |

| IPC | `src/electron/ipc/channels.ts`（CLIPBOARD_* 通道） | ✅ 新增 2 通道（CLIPBOARD_PENDING_LIST / CLIPBOARD_DISMISS） |
| 渲染进程 | `src/electron/renderer/panels/clipboardManager.ts` | ✅ 改造（Toast 提醒 → 角标更新 + 敏感内容保护性主动） |
| 渲染进程 | `src/electron/renderer/panels/clipboardPanelManager.ts` | ✅ 新增（待处理列表面板） |

- 输入护栏（inputValidation.ts）——保持原状

## 2. 分析现状

### 2.1 当前实现链路

```
用户 Ctrl+C
  → ClipboardHandler.checkChange()（2s 轮询哈希检测）
  → emit('changed')
  → main.ts: webContents.send(CLIPBOARD_CHANGED)
  → ipcListeners.ts: uiManager.showClipboardChangedToast()
  → clipboardManager.ts: ToastManager.showToast('剪贴板有新内容', duration=0)
  → 用户点击"分析"按钮
  → window.electronAPI.clipboardAnalyze()
  → ClipboardHandler.analyze()（读取内容 + 敏感检测 + 护栏检查）
  → emit('analysis-ready', { content })
  → ipcListeners.ts: uiManager.showClipboardConfirmDialog(content)
  → 用户确认 → addMemory({ source: 'clipboard' })
```

### 2.2 存在的问题

| ID | 问题 | 严重度 |
|----|------|--------|
| P1 | **打扰式提醒**：每次 Ctrl+C 都弹不自动消失的 Toast（duration=0），打断用户当前工作流 | P0（用户痛点） |
| P2 | **敏感内容无感知**：当前敏感内容"静默忽略"，用户复制了密码完全不知道被检测过——失去"三重保护"的感知价值 | P1 |
| P3 | **无累积机制**：用户连续复制多条内容时，每条都弹 Toast，Toast 堆叠混乱 | P1 |
| P4 | **无批量处理**：只能逐条分析归档，无法一次性浏览多条内容选择性归档 | P2 |
| P5 | **无历史回溯**：错过的 Toast 无法找回，用户不知道之前复制过什么被检测到 | P2 |

### 2.3 与整体架构的关系

- **与闭环 1（输入补全）联动**：程序写入剪贴板时通过 `suppressNextChange()` 抑制检测——本方案保持不变
- **与闭环 4（主动提示）职责区分**：闭环 4 是"精灵事件驱动主动"（横幅），闭环 6 改为"用户内容驱动被动"（角标）——两个闭环职责清晰
- **与感知系统解耦**：剪贴板闭环不依赖默契度/感知面板，独立运作

## 3. 理解用户心智

### 3.1 用户期望

| 期望 | 当前 | 目标 |
|------|------|------|
| 复制时不被打断 | ❌ 每次 Toast | ✅ 静默累积 |
| 知道有内容待处理 | ✅ Toast 提示 | ✅ 角标数量提示 |
| 主动决定何时处理 | ❌ Toast 强迫立即决策 | ✅ 用户空闲时点开面板 |
| 批量浏览选择归档 | ❌ 逐条处理 | ✅ 列表批量操作 |
| 敏感内容有保护感知 | ❌ 静默忽略无感知 | ✅ 保护性主动提醒 |

### 3.2 同类产品参考

| 产品 | 剪贴板处理方式 |
|------|----------------|
| VS Code | 剪贴板历史面板（Ctrl+Shift+V），无主动提醒 |
| Alfred（Mac） | 剪贴板历史面板（Cmd+Shift+C），无主动提醒 |
| Raycast | 剪贴板历史面板，无主动提醒 |
| 1Password | 敏感内容（密码）复制后主动提醒"已复制，30s 后清除" |

**共性**：成熟产品均采用"被动等待 + 面板浏览"模式，不打断用户。1Password 对敏感内容有保护性主动提醒。

### 3.3 使用者角度思考

**典型场景**：

1. **研究资料收集**：用户阅读文档时复制多段文本，希望稍后统一浏览归档
   - 当前：每段都弹 Toast，用户要么被迫逐条决策，要么不断关闭 Toast
   - 目标：静默累积，用户完成阅读后打开面板批量归档

2. **代码片段收集**：用户复制多个代码片段，希望选择性归档有价值的
   - 当前：Toast 堆叠混乱，难以区分
   - 目标：面板列表清晰展示，用户勾选归档

3. **误复制敏感内容**：用户不小心复制了密码/API Key
   - 当前：静默忽略，用户不知道发生了什么
   - 目标：保护性主动提醒"检测到敏感内容，已为你忽略"，让用户感知到保护

4. **快速复制粘贴**：用户只是复制粘贴一段文本，不需要归档
   - 当前：Toast 打断，用户必须关闭
   - 目标：静默累积，角标 +1，用户可随时忽略

## 4. 设计需求方案

### 4.1 核心设计原则

**被动等待 + 保护性主动**

| 场景 | 行为 | 设计理由 |
|------|------|----------|
| 普通内容复制 | 静默累积到待处理列表，角标 +1 | 不打断用户工作流 |
| 敏感内容复制 | **保护性主动提醒**（唯一主动场景） | 安全保护感知，非打扰性主动 |
| 用户点开面板 | 展示待处理列表，支持单条/批量操作 | 用户主导决策 |
| 角标溢出 | FIFO 淘汰，角标显示 `99+` | 避免视觉噪音 |
| 长期未处理 | 24h 标记"较旧"，保留不自动清理 | 允许用户事后回溯 |

### 4.2 待处理列表数据结构

```typescript
/** 剪贴板待处理条目（会话级内存态，不持久化） */
interface ClipboardPendingItem {
  /** 唯一 ID（时间戳 + 随机数） */
  id: string;
  /** 内容预览（前 100 字符，完整内容按需读取） */
  preview: string;
  /** 内容哈希（用于去重，与 ClipboardHandler 的哈希一致） */
  hash: string;
  /** 检测时间戳 */
  detectedAt: number;
  /** 是否较旧（>24h 未处理） */
  isStale: boolean;
  /** 内容长度 */
  length: number;
}

/** 待处理列表上限（FIFO 淘汰） */
const MAX_PENDING_ITEMS = 20;

/** 角标显示上限（超过显示 99+） */
const BADGE_MAX_DISPLAY = 99;
```

**设计决策**：

- **不持久化**：待处理列表是会话级状态，重启清空。理由：剪贴板内容有时效性（如验证码），持久化反而堆积无用数据
- **不存储原文**：仅存预览（前 100 字符）+ 哈希。原文在用户点"分析"时从剪贴板读取（此时剪贴板内容可能已变化，需通过哈希校验）
- **FIFO 淘汰**：上限 20 条，超出丢弃最旧的。理由：20 条已足够覆盖一次工作会话的复制量
- **去重**：相同哈希不重复添加（用户重复复制同一内容不堆积）

### 4.3 面板 UI 设计

```
┌─ 剪贴板待处理 ──────────────────────────────┐
│  [全部归档] [全部忽略]    [角标: 5]         │
├─────────────────────────────────────────────┤
│ ☐ [较旧] 研究资料片段预览... 100字  2天前   │
│ ☐ 代码片段：function foo() {...}  3小时前   │
│ ☐ 会议纪要要点... 80字           1小时前    │
│ ☐ 链接：https://example.com      30分钟前   │
│ ☐ 待办事项：1. 完成文档 2. ...   刚刚       │
└─────────────────────────────────────────────┘
```

**交互细节**：

- **单条操作**：每条支持「归档」「忽略」两个按钮
- **批量操作**：顶部「全部归档」「全部忽略」按钮（需二次确认）
- **归档流程**：点击「归档」→ 读取剪贴板内容 → 哈希校验（防止内容已变化）→ 敏感检测 → 护栏检查 → 确认对话框预览 → 写入 `source:clipboard` 记忆
- **内容已变化处理**：哈希不匹配时提示"剪贴板内容已变化，无法归档此条目"，自动从列表移除
- **空状态**：列表为空时显示"暂无待处理内容，复制内容后会出现在这里"

### 4.4 角标设计

**位置**：左侧导航栏剪贴板图标的右上角

**样式**：

- 待处理数 0：不显示角标
- 待处理数 1-9：显示数字
- 待处理数 10-99：显示数字
- 待处理数 >99：显示 `99+`
- 有较旧内容：角标边框变橙色（视觉提示）

**首次引导**：首次出现角标时，显示一次性气泡"剪贴板有新内容待处理，点击这里查看"——引导用户发现新入口

### 4.5 敏感内容保护性主动

**触发条件**：`ClipboardHandler.analyze()` 检测到敏感内容时

**当前行为**：`emit('sensitive-ignored', { type })` → ipcListeners 接收 → 静默

**新行为**：`emit('sensitive-ignored', { type })` → ipcListeners 接收 → **主动 Toast 提醒**

```
Toast: "检测到敏感内容（API Token），已为你忽略"
       [知道了]
```

**设计理由**：

- 敏感内容主动提醒是**安全保护**，不是**体验打扰**
- 让用户感知到"三重保护"的价值——精灵帮你挡掉了危险
- Toast 自动消失（5 秒），不打断工作流
- 只有一条按钮「知道了」，不需要用户决策（已自动忽略）

**注意**：此场景下剪贴板内容**不进入待处理列表**（敏感内容不存储）

### 4.7 架构归属评估（ADR-017 架构先行）

| 判断问题 | 答案 |
|----------|------|
| 1. 该功能归属哪个模块？ | 渲染进程 `renderer/panels/`（与 memoryPanelManager/dashboardPanelManager 同层） |
| 2. 是否引入新的依赖方向？ | 否。新增 clipboardPanelManager 依赖 UIManager（已有依赖方向），不引入新方向 |
| 3. 是否需要新增模块？ | 是，新增 `clipboardPanelManager.ts`。符合 ADR-008 目录结构（panels/ 目录已有 10+ Manager） |
| 4. 是否影响现有架构边界？ | 否。clipboardManager.ts 改造（Toast → 角标）是内部行为变更，不改变对外接口 |

**结论**：架构归属清晰，不违反 ADR-008 / ADR-017。

## 6. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 剪贴板内容在待处理期间被覆盖，归档时哈希不匹配 | 哈希校验失败时提示"内容已变化"，自动移除该条目 |
| 用户长期不清理，列表堆积 | FIFO 上限 20 条 + 24h 标记"较旧" + 角标 `99+` |
| 首次使用不知道角标含义 | 首次引导气泡（一次性） |
| 敏感内容保护性主动提醒可能被误认为打扰 | Toast 自动消失（5s）+ 只有一条按钮「知道了」+ 仅敏感内容触发（频率极低） |
| 与闭环 1（输入补全）suppressNextChange 联动失效 | suppressNextChange 逻辑不变，程序写入仍被抑制，不进入待处理列表 |

## 7. 何时回顾

- 用户反馈"待处理列表上限 20 条不够" → 评估提升上限或引入持久化
- 用户反馈"24h 标记较旧不准确" → 评估调整阈值或改为相对时间
- 敏感内容保护性主动提醒频率过高 → 评估是否降级为被动（但需保留敏感检测日志）
- 待处理列表归档率过低 → 评估是否需要主动提醒（但需与闭环 4 主动提示区分）
