## 勘误 v1.4（2026-07-18 闭环 11 R1 修复）

> 来源：[问诊：自动迭代] 闭环 11 跨会话对话检索 v1 落地后体验评估
> 评估方法：长期使用走查 + 体验评审 + 健康度诊断（防抖时序 / 并发搜索防护 / isSearching 状态机）
> 结论：v2 升级路径 3 项触发条件均未达成；发现 1 项 P1 状态机断点已直接修复

### R1 P1 断点修复

**断点描述**：搜索期间用户输入新关键词时，新调度的 `performSearch` 会被 `isSearching` 守卫拦截并直接 `return`，导致 `lastKeyword` 未更新；用户停止输入后 `scheduleSearch` 不会再被触发（仅 `input` 事件触发），最新关键词永远搜不到。

**触发条件**：用户连续快速输入 + 搜索 IPC 响应时间 > 300ms 防抖时长（本地 SQLite LIKE 通常 < 50ms，触发概率较低，但用户感知到"输入了但没搜索"会困惑）。

**修复策略**：`performSearch` 的 `finally` 块中检查输入框当前值是否与 `lastKeyword` 不同，不同则重新调用 `scheduleSearch()`，确保用户最终能看到最新关键词的搜索结果。

**影响文件**：
- `src/electron/renderer/panels/searchMessagesManager.ts`（performSearch finally 块新增 7 行检查逻辑）
- `src/__tests__/electron/renderer/searchMessagesManager.test.ts`（新增 2 个回归测试：R1 修复正向 + 防死循环反向）

**验证**：`tsc -p tsconfig.electron.json --noEmit` 0 errors；36/36 测试通过（原 34 + 新增 2）

### v2 触发判定

| v2 升级路径项 | 触发条件 | 评估结论 |
|--------------|---------|---------|
| 跳转后不滚动到匹配消息 | 用户反馈"跳转后找不到匹配位置" | 未收到反馈，**不触发 v2** |
| 搜索结果上限 50 条 | 用户反馈"搜不到旧内容" | 未收到反馈，**不触发 v2** |
| 仅支持关键词匹配 | 用户反馈"想按时间/角色过滤" | 未收到反馈，**不触发 v2** |

## 闭环 6：剪贴板保护 → 分析 → 写入（✅ v2 已闭环）
