## 闭环 1：输入补全模块（✅ v1 已闭环）

## 闭环 2：日常对话 → 记忆沉淀（✅ v1 已闭环）

> **用户画像**：已配置 Agent 的日常用户。
> **入口**：对话面板输入框。
> **核心路径**：对话 → 流式回复 → Agent 内部记忆管道自动提取 → memoryAdded 事件 → memoryNoticed IPC → 仪表盘计数脉冲 + 记忆面板自动刷新 + 感知面板情感/默契度更新。
> **完成标志**：记忆面板出现新记忆条目（source 正确）、感知面板情感维度数值更新、仪表盘统计数字递增。
> **为什么是 v1 已闭环**：最高频路径 + 记忆沉淀是产品核心价值 + 与闭环 0 直接衔接（新用户首次对话后立即体验）。v1 已修复 3 个体验断点（P0×1 + P1×2），完成标志全部达成。

## 闭环 3：记忆召回 → 编辑 → 关系建立（✅ v1 已闭环）

> **用户画像**：积累了一定量记忆的用户。
> **入口**：`Ctrl+Shift+R` 全局快捷键 / `Ctrl+K` 命令面板"搜索记忆" / 记忆面板搜索框。
> **核心路径**：召回 → 搜索 → 详情 → 编辑 → 图谱拖拽建立关系。
> **完成标志**：搜索结果高亮排序、详情弹窗显示编辑后内容、图谱视图显示新关系连线、演化脉络显示编辑历史。
> **为什么是 v1 已闭环**：记忆召回是 Memora 差异化护城河（vs 通用 LLM 聊天工具）。v1 已修复 8 个体验断点（P1×7 + P2×1），完成标志全部达成。

### 切换流程走查基线

| 场景 | 反馈路径 | 走查前 | 走查后 |
|------|----------|--------|--------|
| 手动切换 | UI 点击 → IPC → Agent.switchPersona → emit personaSwitched → 渲染层刷新 | ❌ AgentLoop systemPromptPrefix 不刷新；不发射事件 | ✅ F1 统一走 Agent.switchPersona，刷新 prompt + 发射事件 |
| auto 模式 | postProcessInner → personaMatcher → pm.switchPersona → emit personaSwitched | ❌ 渲染层不监听 personaChanged，UI 零反馈 | ✅ F2 渲染层监听事件，刷新顶栏 + 下拉 + 感知面板 |
| 切换后立即对话 | AgentLoop 使用新 systemPromptPrefix | ❌ 手动切换后下一次对话仍用旧角色 prompt | ✅ F1 调用 loop.refreshPersonaPrefix 立即生效 |
| 首次启动 + defaultPersona | start() → switchPersona → emit personaSwitched（from=null） → 渲染层刷新 | ❌ from=null 被 isPersonaChangedPayload 拒绝 | ✅ 代码审查 P1-1 修复：from 类型放宽为 string \| null |
| 第二次启动 + defaultPersona 同名 | start() → switchPersona 同名幂等路径 → 不触发事件 | ❌ personaSwitched 变量误判，感知推导遗漏 | ✅ 代码审查 P1-2 修复：改为追踪事件实际发射 |
| personas/*.md 编辑 | fs.watch → 防抖 → agent.reloadConfig('persona') | ❌ 无热重载，需重启 | ✅ F5 热重载（configDir 注入时启用） |
| personaMode 切换 | setPersonaMode → configManager.updateConfig 持久化 | ❌ 重启回到默认 'auto' | ✅ F3+F4 持久化到 sprite.json |

### 不再打磨的判定（v1）

- 完成标志（侧边栏显示新角色 + 对话回复符合新角色设定 + 感知面板沟通风格指标更新 + auto 模式正确匹配）已全部达成。
- 切换流程走查结论：7 种切换场景（手动/auto/切换后对话/首次启动/第二次启动/personas 编辑/personaMode 切换）反馈均清晰准确。
- 健康度诊断结论：auto 与手动优先级（统一事件链路）、并发切换保护（chatBusyError 守卫 + 同名幂等）、角色配置热重载（fs.watch + 防抖 + 优雅降级）三维度均设计正确。
- 代码审查结论：4 项 P1 问题（类型守卫拒绝 null / 感知推导遗漏 / watcher 句柄泄漏 / DRY 违反）+ 2 项 P2 问题（fs.watch error 处理 / configVersion 未递增）全部修复。
- P2 观察项 3 项（toast 信息丰富度 / auto 匹配 UI 反馈 / 锁定状态可见性）均为设计权衡保留，待自然生长触发。
- 后续如出现新断点，按"自然生长触发"补丁式打磨或触发 v2 升级路径。
