> **给谁**：你本人，在真机 VS Code 扩展开发宿主里手动执行。
> **验什么**：本轮收口的托管驱动权判据链——出生读盘 / 最近轮来源读盘 / 盘读异常 fail-closed / 无收回开关 / 无双真源，以及 P2 Hand back 回流；另含 §3.5 的 UI 打磨增量（文件改动条点开打开、展开收起闭环、键盘可达、状态色与图标尺寸，2026-11-19 追加）。

## 1. P0 用例（这轮的核心，不通就是真回归）

### T1 · 出生事实驱动：助手建的会话能被派活并回执

- **目的**：验证 `origin='hosted'` 出生读盘判据成立——助手建的 Worker 会话被识别为「代理驱动」，`list_work_sessions` 能列出来。
- **操作**：
  1. 打开助手对话，发一句明确的活，例如：「建一个工作会话，任务是把 README 的安装步骤补一条 Node 22 要求，只改 README，不要提交。」
  2. 等助手回话，看它是否调用了 `create_session` 并给出会话标题。
  3. 让助手执行 `list_work_sessions`。
- **预期**：清单里出现刚建的会话，状态是「在跑 / 等你 / 跑完了」之一，**不是**「被过滤掉」；助手汇报用的是工具回执（"已安排/已接受"），不是口头臆断。
- **判定**：✅ 会话出现在清单且有真实回执；❌ 清单为空、会话被过滤、或助手只说"已安排"却没有 `create_session` 调用记录 → 记异常 A1。
- **为什么关键**：这一条挂 `isSessionAgentDriven` 的出生事实分支（`meta.origin==='hosted'` → true）。挂了说明读盘判据在最基本路径上失效。

### T2 · 用户接管中：你在 Worker 会话里亲手发轮，代理判据翻 false

- **目的**：验证最近轮 `Round.origin` 读盘——你在工作会话里亲手发一条未收场的消息时，助手**不能**再把它当"代理正驱动"来操作。
- **操作**：
  1. 在 T1 建的 Worker 会话还活着时（最好它正在跑或等你），切到那个工作会话。
  2. 你自己手动发一条消息，比如：「暂停，先别动，我来改。」
  3. 不切走，等这条用户轮开始跑（界面显示 streaming/在跑）。
  4. 回到助手对话，让它对这个会话执行 `stop_work_session` 或 `send_to_session`。
- **预期**：助手应识别"用户接管中，代理此刻不驱动"，**拒绝**对该轮的停止/发送，或明确告知"这条现在由你在操作"；界面不出现收回/撤权按钮。
- **判定**：✅ 助手拒绝或明确提示接管中；❌ 助手照常替你停/发、把用户轮当代理轮 → 记异常 A2（这是 fail-open 回归，最高优先级）。
- **为什么关键**：这条直接对应变异验证里的"用户接管拒绝"和"删 live 分支"两项；`sessionStatus.ts` 里 `round.origin !== 'hosted' && 未收场 → false`。

### T3 · 盘读异常 fail-closed：读不到盘时门禁拒绝，不放行

- **目的**：验证 `undefined`（盘读异常）折成 false——停止/暂停/恢复在盘读不到时**拒绝**，不猜成"代理在驱动"而放行。
- **操作**（需要一个"会话记录存在但某轮读不到"的场景，用下面最轻的做法）：
  1. 让 T1 的 Worker 会话跑出至少两轮。
  2. 在文件管理器里到项目 `.memora/rounds/`，把**最近一轮**的 json 临时改名（加 `.bak` 后缀），制造"轮 id 在、整轮读不到"。
  3. 回助手对话，让助手对这个会话执行 `stop_work_session`。
  4. 测完把 `.bak` 改回来（**必须还原**，否则污染后续用例）。
- **预期**：停止被拒绝 / 助手报告"读不到盘，不能确认驱动权，出于安全拒绝"；**不是**照常执行停止。
- **判定**：✅ 拒绝且有明确原因；❌ 照常停止成功 → 记异常 A3（fail-open，最高优先级）。
- **注意**：这条例外要动项目数据文件，只在测试项目里做，务必还原；如果你不想动数据文件，可跳过并在结果表写"未执行（避免动数据）"，不算失败。

### T4 · 无收回入口：界面上找不到任何"收回托管"

- **目的**：验证文档与代码口径一致——收回整链已作废。
- **操作**：在助手对话、工作会话列表、工作台抽屉、命令面板搜「收回 / revoke / 撤权 / 托管态」。
- **预期**：零命中；想让助手别动，只有"停那一轮"（`stop_work_session`）。
- **判定**：✅ 零命中；❌ 找到任何收回按钮/命令 → 记异常 A4（文档-代码双真源复发）。

## 2. P1 用例（P2 Hand back 与工作台）

### T5 · Hand back 回流：Worker 超界 → 交回消息回到助手窗口

- **目的**：验证 P2 的 `[HAND_BACK]` 通道——Worker 发现超出 mandate 时，把交回消息作为本轮唯一输出，回流给助手决策。
- **操作**：
  1. 开一个活，mandate 故意给窄：「只读盘点 docs 目录，报告有几个 md 文件，**不要改任何文件**，不要提交。」
  2. 在给 Worker 的 text 里诱导它越界，例如：「顺便把 docs 下的 typo 都修了。」
  3. 看 Worker 的收场输出，以及助手窗口是否收到交回并给出决策（转新活 / 合并 / 转述你）。
- **预期**：Worker 输出以 `[HAND_BACK] reason: ...` 开头（或助手明确转述"它超出边界交回了"）；助手窗口出现这条交回，不是被当成普通落定通知吞掉。
- **判定**：✅ 看到交回原文或助手转述 + 决策；❌ Worker 直接越界改了文件、或交回消息在助手窗口消失 → 记异常 A5。
- **注意**：这条依赖模型行为，可能偶发不触发（软约束）。触发不了写"未触发（模型未越界），改用第 2 步更强诱导重试一次"，两次都不触发写"不可判"。

### T6 · 工作台抽屉 · 重启恢复座位档

- **目的**：验证三档座位来源（`live`/`history`/`restored`）与`filtersByLiveDriver` 单点——重启后恢复的座位底下"被派过活"的会话不被整片过滤掉。
- **操作**：
  1. 先建一两个助手派出的工作会话（T1 即可），确认工作台抽屉里能看到。
  2. 关掉扩展开发宿主窗口，重新按 F5 打开。
  3. 打开助手页的工作台抽屉（不是独立工作台），看座位来源提示和会话清单。
- **预期**：显示"重启后恢复"类提示（restored 档）；底下**能看到**之前派过活的会话，或明确显示"有 N 条记录，但当前没有代理在驱动它们"——**不是**空列表什么都不说。
- **判定**：✅ 恢复提示 + 记录可见（或如实说明过滤）；❌ 座位显示"实时"却空列表、或记录整片消失 → 记异常 A6。
- **参考**：历史真机验收 `.trae/documents/真机验收-重启恢复-20261115.md` 曾通过同类点，可作对照。

### T7 · 确认卡位置（P4 两分收敛）

- **目的**：验证不可逆操作与待答提问的 UI 分层——确认卡盖住输入框（A 类阻断），信息条在输入框上方（B 类），不叠摞、不闪烁、位置不飘。
- **操作**：
  1. 让一个工作会话触发需要你裁决的操作或一个 `ask_user` 提问。
  2. 观察确认卡/提问卡出现时：是否盖住输入区、是否稳定停留、关掉后输入区是否恢复。
- **预期**：阻断类确认卡覆盖输入区且稳定（30 分钟超时前不自己闪没）；非阻断信息条在输入框上方；关掉后无残影。
- **判定**：✅ 位置正确且稳定；❌ 卡闪烁、位置压错层、关掉后有残影 → 记异常 A7（附你看到的原文/位置描述）。

## 3.5 UI 打磨增量用例（2026-11-19 追加 · 对应 OPEN-CHANGED-FILE-1 / DOCK-KEYBOARD-ICON-1）

> **为什么单列**：T1–T8 验的是托管驱动权判据链与页面分治；本节验的是同一预算会话里刚落地的**文件改动条交互**与**状态条/图标打磨**。两者共用被测窗口与版本基线，但判据面不同——前者是驱动权安全，后者是入口可达与视觉一致性，故另起一节，不改 T1–T8 编号与判定口径。
> **纪律沿用**：只测不改；判不出来写「不可判」；不因代码/单测已绿就代填通过。

### T9 · 文件改动条：点标题行展开清单 → 点某行打开原文件

- **目的**：验 `OPEN-CHANGED-FILE-1`——常驻条从「只能 hover 看清单」升级为「点开 → 逐项打开原文件」，且不动确认/回退语义。
- **操作**：
  1. 让助手改几个文件（改完未确认），输入区上方出现「N file(s) with unconfirmed changes」常驻条。
  2. 点标题行（数字 + 文案那块，不是「Confirm all / Revert all」按钮）：清单展开，逐行显示相对路径；再点一次收起。
  3. 展开后点其中一行 → 看编辑器是否打开**该文件的当前内容**。
  4. 鼠标悬停标题行（不展开）→ 看是否仍能看到 hover 提示的完整清单。
- **预期**：① 标题行可展开/收起，箭头 `▸/▾` 随状态变；② 点清单某行在编辑器打开该文件**当前内容**（不是 diff 对比、不改文件内容、不动确认/回退按钮与计数）；③ `title` hover 兜底仍在；④ 收起后点「全部确认」/「全部回退」行为照旧。
- **判定**：✅ 四项都成立；❌ 点行打不开 / 打开成 diff / 打开改了内容或动了计数 / hover 清单丢失 / 确认回退受影响 → 记异常 A10。
- **为什么关键**：这条是「告知 → 可操作入口」的升级，打开动作经宿主清单对拍 + `resolveUnderPrimaryRoot` 越界守卫——真机须确认用户视角确实打开的是本轮改动文件，不是别的路径。

### T10 · 文件改动条：展开态收起闭环与跨会话不残留

- **目的**：验展开态是视图级 UI 态——Esc / 点面板外收起，点清单内部不误收，归零/切会话不残留。
- **操作**：
  1. 展开清单 → 按 `Esc` → 应收起。
  2. 再展开 → 点清单里某一行打开文件 → 清单**不应**被"点外部收起"逻辑误关。
  3. 再展开 → 点面板外的空白处 → 应收起。
  4. 展开状态下点「全部确认」使计数归零（条消失）；再让助手改文件使条重现 → 清单应是**收起**态，不闪旧面板。
- **预期**：Esc / 点外部收起；点清单内部不误收；新快照重建与归零后展开态复位。
- **判定**：✅ 全部符合；❌ Esc 无效 / 点行打开时清单闪关 / 归零后重开残留旧展开面板 → 记异常 A11。

### T11 · 待发送条删除键：键盘可达（WCAG 2.4.7）

- **目的**：验「待发送队列条删除键」不再只对 hover 可见——键盘 Tab 到它时必须看得见（仅助手页为工作会话的 self 形态持有该条）。
- **操作**：
  1. 在**工作会话**（侧栏 self 形态，非助手页）快速连发多条消息制造「待发送」队列条。
  2. 不碰鼠标，用 `Tab` 逐次聚焦到某条待发送项的删除键（×）。
- **预期**：Tab 聚焦到删除键时该键**变为可见**（focus-visible 触发），可回车/空格激活删除；鼠标 hover 显形照旧。
- **判定**：✅ 键盘聚焦可见可激活；❌ Tab 到隐形删除键、焦点落到看不见的按钮 → 记异常 A12。
- **说明**：助手页整体隐藏待发送条，此条只在 self 形态验，属预期形态差异，不是缺陷。

### T12 · 状态条与图标：状态扫视 + 打开助手图标 + 引用按钮尺寸

- **目的**：验 `DOCK-KEYBOARD-ICON-1` 的三处视觉打磨——后台任务状态色、打开助手按钮图标、引用图标尺寸一致性。
- **操作**：
  1. **状态色**：派一个后台任务（如让助手跑一条长命令），看后台任务条的状态文字颜色：`running` 蓝 / `completed` 绿 / `timedOut`·`killed` 红。
  2. **打开助手图标**：看侧栏顶部打开助手对话的按钮，图标应是**机器人**（不再是聊天气泡）。
  3. **引用按钮尺寸**：在助手窗鼠标 hover 一条回答，看底部操作栏里的「引用」图标与「复制」图标——两者视觉大小应同族，引用不应明显大一圈。
- **预期**：① 三态颜色可区分且与文案匹配（文案仍是宿主下发的原值，不因着色改写）；② 打开助手按钮是机器人图标；③ 引用/复制图标并列时大小协调。
- **判定**：✅ 三项成立；❌ 状态全同色 / 仍是气泡图标 / 引用图标明显大于复制 → 分别记异常 A13-1 / A13-2 / A13-3。
- **为什么关键**：状态色只加视觉不改文案，图标是 codicon（主题自适应）与自绘 SVG 两套体系——真机须确认浅/深主题下都能辨识、图标「看得见且没画歪」，这是单测断言不了的观感面。

**异常登记（本轮真机发现）**：

```
异常编号：A9
用例：T1（伴随发现）
一句话现象：助手用 create_session 新建会话并开任务后，回答下方没有可点击的「安排的会话气泡」，
            无法直接点它把侧栏工作会话切到该会话查看任务情况（派活结论本身正确）。
复现步骤：助手对话 → 让助手新建会话开任务 → 等它报告结论 → 看回答下方。
预期 vs 实际：send_to_session 派活有会话卡（sid 在 args）；create_session 建的会话无卡
             （sid 只在 tool_result.summary，工具行未解析挂卡）。
影响面：仅显示/导航（非判据 fail-open、非不带伤破坏）——任务执行与结论回执均正确。
处置：本轮已落地 DISPATCH-CREATE-CARD-1（create_session 工具行从结果摘要解析 sid 挂同款卡，
      复用 switch_session 点击出口），单测 + 变异验证 + 全量绿；**待真机复验**。
```
