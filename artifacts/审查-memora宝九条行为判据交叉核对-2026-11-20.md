> **核什么**：拿 `docs/参考-TRAE宝设计观察-20261114.md` §三.1 新增的 P1–P9 九条行为判据，逐条核对 memora 宝**现在真实的样子**。
> **不做什么**：不改任何业务代码（`src/`、`hosts/*/src/` 一行未碰），不给改进建议，不排期。
> **证据口径**：代码符号（文件 + 行号 + 原文）= 硬证据；台账与真机文档 = 别人写的结论，**未独立复跑的一律标「按台账/真机文档记载，未独立核实」**；只读命令 = 现状基线。
> **基线**：HEAD `a9f9dc99`；内核 `7.3.0`；宿主 `0.11.0`。工作树另有会话在改 `hosts/`、`artifacts/`、`tasks/`（`git status --porcelain` 可见），本次未触碰、未提交他人文件。

## 一、九条逐条

### P1 任务分解

**判据**：复合请求 → 显式子任务清单 + 依赖顺序 + 每项独立可验收；不把多个独立结果塞进同一条执行线。

**memora 现状**

- 宝的工具面是 allow-only 九件（`hosts/memora-vscode/src/extension/host/workSessionTools.ts:151-161`）：`list_work_sessions` / `send_to_session` / `create_session` / `stop_work_session` / `pause_work_session` / `resume_work_session` / `answer_session_question` / `list_role_packs` / `read_memory_summary`。**没有** `task_table_write` / `task_table_update` / `delegate_task`。而任务表在内核是默认常驻集，原文「task_table_write / task_table_update **直接暴露**：任务表是内核 agent 完成多步任务的**必要基建**」（`src/agent/toolExecutor.ts:605-607`）。也就是说，宝不是没有可用工具，而是被白名单挡在任务表之外。
- 分解的载体是**会话**：`create_session` 强制 `rolePack` / `title` / `text` / `paths`，`mandate` 可选；原文「`paths` **必填**：声明这条活打算动的文件或目录」（`workSessionTools.ts:729-741`）。
- 顺序与依赖：唯一相关机制是范围冲突——「与当前在跑的活的声明范围有交集时返回 `E_SCOPE_CONFLICT`，并告诉你撞上哪条活、撞在哪」（`workSessionTools.ts:735-738`）。这是「别同时动同一片文件」，不是「按依赖排先后」；没有阻塞态，也没有「等 A 收场再做 B」的字段。
- 台账 `GOAL-DRIFT-2` 记「目标偏离引导当前**零配置**（全仓角色包 rules.md 无此规则）」，建议修法是补一句角色包规则（`tasks/待完成任务.md:1081-1082`）——即「拆完之后跟住目标」目前靠模型自觉。

**归类：表面像底子不同。** 界面（多条会话 + 派活卡）看起来像任务管理，底子是会话容器：没有任务表、没有依赖图、没有阻塞态。**差在「依赖/阻塞」这一层**——`E_SCOPE_CONFLICT` 只解决撞车，不解决先后。

### P2 委派与复用

**判据**：最少会话数；上下文高度重叠时优先续用；一条会话只装一个连贯目标。

**memora 现状**

- 委派是**真机制**：`send_to_session` 的返回面是结构化的 `{ ok:true, accepted:true }` 或 `E_DENIED` / `E_BUSY` / `E_LOCKED` / `E_UNREADABLE`，码集按产生位置分三层（`workSessionTools.ts:176-191`）。真机 N1（`create_session` + 派活 + 回执）、N2（运行中派发被 `E_DENIED` 拒）通过——**按 `artifacts/真机测试交接-2026-11-19.md:30-31` 记载，未独立复跑**。
- 复用有**真源和明文判据，但没有闸**：`list_work_sessions` 描述写「用于判断是否已有相关会话、避免重复新建」，`summary` 是「判断复用与否的主依据」，`title` 只用于初筛且「首轮生成后永不更新的旧标题，任务漂移后会误导」（`workSessionTools.ts:573-586`）。判据源存在；但宝连开三条同目标会话，没有任何机制会拒绝。
- 「一条会话一个连贯目标」无字段、无校验；会话数与层级限制被**明确砍掉**：「不需要关系表 / `E_LIMIT` / 深度闸 / 父字段 / 层级树（这些已被明确砍掉，不要复活）」（`workSessionTools.ts:16-18`）。标题永不更新这一点，文档自己知道漂移风险，但没有机制处理。

**归类：委派 = 机制一致；复用与「单目标」= 表面像底子不同。** 真源在、判据写在工具描述里、闸不在。**差在「硬约束」这一层**：复用是可被忽略的建议，不是门禁。

### P3 决策边界

**判据**：用户给的事实/条件 ≠ 对另一个选择的授权；只有歧义会实质改变交付物时才回头问。

**memora 现状**

- 提问与确认通道是真实的：`ask_user` 在 step 边界挂起、答案作为工具结果回填（`src/agent/builtinTools.ts:305-331`）；`confirm` 超时**自动拒绝**（fail-closed），注释明写「不批准 = 不执行」（`hosts/memora-vscode/src/extension/host/confirmCoordinator.ts:7-21`）。这两条是**执行安全**边界。
- 托管链对「替用户拍板」是**明确授权**的：`hostedSessionNotice.ts` 头注释写「2026-11-18 用户拍板：正文指令为『按判断拍板继续、不阻塞任务』（可代答 / 转述 / 换活）——助手是判断者，不是被绑定的答题器」（`hosts/memora-vscode/src/webview/helpers/hostedSessionNotice.ts:29-34`）；`answer_session_question` 让宝按位代答，且要求「题面与选项必须由宿主如实带回，代理不能凭空编答案」（`hosts/memora-vscode/src/extension/host/answerSessionQuestionTool.ts:10-18`）。即：Worker 的提问，**默认允许宝答**；只有宝判断需要用户时才转述。
- 不可逆操作的硬门禁被有意降级：台账 `HOSTED-CONFIRM-AUTH-1` 记「🚫 已被取代（2026-11-17 定案：带戳轮确认统一不弹卡，改软约束 + 授权识别）」，`HOSTED-CONFIRM-SOFT-1` 记「④ 载体改岗位三层」（`tasks/待完成任务.md:482-492`）——**按台账记载，未独立核实全部判据落地**。
- 「只有歧义会实质改变交付物才问」：没有判据、没有计量，完全落在模型判断里。

**归类：表面像底子不同。** 界面呈现像「不替你决定」（有等你处理的卡），底子是「可代答 + 软约束」：拍板权在提示词和模型判断里，不在门禁里。**差在「授权范围如何被约束」这一层**。

### P4 回报节奏

**判据**：里程碑即报；只报结论与证据；同一件事不重复报。

**memora 现状**

- 机制在 `hostedSessionNotice.ts:1-39`：Worker 一轮落定就**不等用户开口**、立刻替创建者起一轮（「读结果 → 整理 → 汇报」，5–6 行）；结论三档 `success` / `failed` / `interrupted`，且「失败与中断刻意分开：『跑挂了』和『被叫停』是两种结论」（8–9、143 行）；通知「只带身份 + 结论（+ 失败 / 中断原因），**不带正文**」（26–27 行）；「同一会话同一轮只写一条」（23 行）；「不抢 / 不打断」（24、73 行）；Hand back 同投递器、去重键隔离（36–38 行）。
- 这三条与判据逐项对上：里程碑即报 / 只报结论 / 不重复报。
- 缺口在呈现：真机 N16「派活回声气泡」**不通过**——派发成功、轮已落盘，但侧栏没有「Sent by Memora」气泡（`artifacts/真机测试交接-2026-11-19.md:37`，按该文档记载；台账 `DISPATCH-SESSION-CARD-1` 已落地待真机，`tasks/待完成任务.md:634`）。

**归类：机制一致。** 九条里复刻得最实的一条。差只在「回显」这一层（数据对、回声气泡缺），不在判据本身。

### P5 纠错方式

**判据**：先承认再改、不辩解；能分清「我判断错」与「用户改了要求」。

**memora 现状**

- 人格层没有任何纠错条款：默认助手包 persona 只有「诚实、清晰、简洁……不编造」「尊重用户的判断与决定」（`role-packs/memora助手/persona.md:3-11`），rules 六条是「诚实回答 / 简洁优先 / 工具优先 / 安全边界 / 增量写入」（`role-packs/memora助手/rules.md:1-6`）。
- 记录层没有可区分的类型：轮只有 `origin`（`user` / `hosted`）这一个来源戳（`hosts/memora-vscode/src/shared/sessionStatus.ts:82-99` 的判据注释）；落定通知只有 `success` / `failed` / `interrupted` 三档，没有「判断错」或「需求变更」档（`hostedSessionNotice.ts:8-9`）。
- 台账 `GOAL-DRIFT-2` 同样记录「引导零配置」（见 P1）。

**归类：表面像底子不同。** 对话里看得到宝改口，但载体分不出是哪一种改口。**差在「会话记录没有变更类型」这一层**。

### P6 诚实边界

**判据**：不伪造；贴不出文件 + 符号一律标「推断」；失败说失败，部分完成说部分完成。

**memora 现状**

- 强机制（硬证据）：驱动权判据是**三态**，`undefined` = 盘读异常，停止/暂停/恢复门禁必须据此**拒绝**（`hosts/memora-vscode/src/shared/sessionStatus.ts:101-118`，原文「不得复用……把它解释成驱动中，那是把 fail-closed 改成 fail-open」）；三个工具描述都写「状态读不到（unreadable）时返回 `E_UNREADABLE`，不猜着停/暂停/恢复」（`workSessionTools.ts:640-703`）；`list_work_sessions` 明说「unreadable、unknown、或顶层 coverage 不为 complete 都表示『不确定』，不得当成『这条活没在跑』」（`workSessionTools.ts:585-586`）；岗位纪律写「派活 / 开活的状态以工具成功回执为准……未拿到时是已发起、等待受理」（`workSessionTools.ts:59-69`）。
- 子 agent 终态头由**内核**写、不由子模型自封：「头部绝不由子模型写——否则模型可以自封『完成』骗过队长」（`src/agent/builtinTools.ts:554-558`）。
- 反向证据（真机）：N3 盘读异常 fail-closed **不通过**——移走轮文件后 `send_to_session` 仍 `accepted:true`，根因记为内存缓存无失效（`artifacts/真机测试交接-2026-11-19.md:32`，按该文档记载）。当前代码已加「派发受理前轮引用完整性自检：外部移走轮文件 = 会话历史已残缺……⇒ 拒收，不落任何新轮」（`hosts/memora-vscode/src/webview/helpers/hostedDispatchRun.ts:152-157`）；**真机复验未做**，所以现状是「代码已补、真机未复验」。
- 「推断标注」缺位：宝没有读文件工具（白名单，见 P1），拿到的是 summary / 结果摘要；通知刻意不带正文（`hostedSessionNotice.ts:26-27`）。所以宝**结构上给不出「文件 + 符号」**，转述 Worker 结论时也没有携带证据等级的字段。

**归类：机制一致（主判据：失败/不确定可判读、不伪造终态）；子项「证据分级随结论流动」= 表面像底子不同。** 差在「结论没有证据等级字段」这一层——宝只能说「它说做完了」，没有通道说「这句话是实证还是推断」。

### P7 身份隔离

**判据**：出方案与挑毛病发生在可区分的主体/上下文里（排雷方 ≠ 设计方）。

**memora 现状**

- 仓库有真正的只读顾问角色包：`readonly-advisor` 明确「你只做阅读、检索、分析与建议……不修改用户的任何项目文件」，并要求「区分『事实』与『推断』，推断须标明依据」（`role-packs/readonly-advisor/persona.md:9-31`）。宝能通过 `create_session` 选它当 Worker（`rolePack` 必填，取自 `list_role_packs`）。
- 但「分线」是**可选动作，不是机制**：没有任何地方要求设计会话与复核会话必须不同；同一条 Worker 完全可以自己写完自己审。
- `run_team_meeting` 在同一次 LLM 调用里注入「组长 + 组员」多 persona，看起来像多方评审，底子是同一上下文里的多段人设（`src/agent/builtinTools.ts:615-631`）；且它不在宝的白名单里（见 P1），宝自己开不了会。
- 项目规则里「写盘方不得自证」「复核方 ≠ 写盘方」约束的是写代码的 agent（`.trae/rules/generic/delegation-discipline-rules.md:52`），不是 memora 宝的运行时。

**归类：表面像底子不同。** 有「只读顾问」这张皮，没有「换线」的骨架。**差在「上下文隔离」这一层**：换人格 ≠ 换会话，复核方的输入并不独立。

### P8 不带伤

**判据**：改动面 = 任务声明面；不为过限制删注释 / 压平代码；不顺手重构无关代码。

**memora 现状**

- 宝这一层是**结构性安全**：白名单里没有 `write_file` / `delete_file` / `run_command`（`workSessionTools.ts:151-161`），想伤项目文件也伤不到。
- 委派层有真机制：`paths` 必填，与在跑活的范围有交集即 `E_SCOPE_CONFLICT`（`workSessionTools.ts:735-738`）；文件改动有常驻条 + 全部确认 / 全部回退（真机 N7 通过——按 `artifacts/真机测试交接-2026-11-19.md:35` 记载；`OPEN-CHANGED-FILE-1` 已落地待真机复验，`tasks/待完成任务.md:1483`）。
- Worker 层没有载体：「不为过 max-lines 删注释 / 不顺手重构」是仓库构建纪律，没有下发给 Worker；`GOAL-DRIFT-2` 说明连目标对齐的引导都零配置。

**归类：宝层 = 本来就该不一样（形态：宝是操作人，不亲手改）；Worker 层 = 表面像底子不同。** 范围声明防的是**撞车**，不是「顺手重构」。**差在「改动面与声明面的比对」这一层**：目前只检测路径交集，没有比对实际 diff 面与声明面。

### P9 事实与重放

**判据**：关键事实落在可离线重建的载体，且重建结果与当时一致。

**memora 现状**

- 设计原则明文：运行时展示的一切是落盘内容的**投影**，Round 文件承载正文 + `processEvents`，「任何时间和状态，都能由落盘日志按序重放重建出与运行时一致的 UI 状态」（`docs/architecture/process-event-log-replay-design.md:27-33`）。
- 落地侧：会话文件 `roundIds` 是引用真源，派发前核对「引用的轮文件在不在盘上」（`hosts/memora-vscode/src/webview/helpers/hostedDispatchRun.ts:152-157`）；重启恢复读盘（真机 T6 部分覆盖、N6 记「形态待按抽屉入口重验」——按 `artifacts/真机测试交接-2026-11-19.md:34` 记载）。
- 刻意不落盘的项**写明了理由**：落定通知的待办队列只在进程内，「重启后内存队列随之丢失，**刻意不补发**（宁可漏报一条旧落定，也不在重启后刷一屏历史）」（`hostedSessionNotice.ts:15-16`）。

**归类：机制一致。** 且这一层比参照对象更硬：明文 JSON + 轮级事件 + 读盘判据。

## 三、总结：哪一层真复刻到了，哪一层只是长得像

**真复刻到的（能用代码符号指过去的机制层）**

1. **派活—回执—状态这条链**：真工具、结构化错误码、受理即可判读、落定即唤醒汇报、同一事实去重、失败与中断分档、`unreadable` 三态与 fail-closed 门禁。这几条不是话术，是 `workSessionTools.ts` / `sessionStatus.ts` / `hostedSessionNotice.ts` 里的判据。
2. **事实与重放**：轮落盘、`processEvents`、重启读盘、派发前核对轮引用完整性。这一层 memora 比参照对象更硬。
3. **诚实边界里的「失败 / 不确定要说出来」**：失败、被叫停、读不到各有各的码与档，且「完成」由内核终态标志写，不由模型自封。

**只是长得像的（皮在、骨不在）**

1. **任务分解**：界面上是多条活、多张卡，底下只有会话，没有任务表、没有依赖图。共享的是「看起来分了工」，不是「拆解与排序的机制」。
2. **复用**：`list_work_sessions` 的摘要与「避免重复新建」的判据是真的，但它们停在工具描述里；没有任何东西阻止宝重开。
3. **决策边界**：「等你拍板」的卡是真的，但托管通道默认允许宝代答，不可逆确认的硬门禁又被有意降级成软约束——「不替用户拍板」目前靠模型自觉，不靠机制。
4. **纠错**：只有人格，没有记录类型；「我判断错」和「你改了要求」在落盘数据里长得一样。
5. **身份隔离**：有只读顾问这张皮，但隔离靠挑选角色包，不靠上下文分线；同一条线可以自审自签。
6. **证据分级**：宝只能转述结论，结论不携带「实证 / 推断 / 不可判」的等级，所以「贴不出文件 + 符号就标推断」在宝身上没有承载面。
7. **不带伤**：宝层是形态带来的结构性豁免（不亲手改），不是复刻出来的纪律；Worker 层只有路径撞车检测，没有「改动面 = 声明面」的比对。

一句话收口：**复刻到的是「派活—回执—落盘」这条骨架；没复刻到的是「怎么拆、怎么收、怎么自证」这三层——它们目前都还停在提示词与模型自觉里。**
