## 一、需求理解

### 1.1 核心诉求

1. **通用侧栏**：右侧新增可折叠通用侧栏，承载感知+仪表盘（信息展示型面板）
2. **剪贴板保留 nav**：剪贴板是主动操作型，保留左侧 nav 一键可达，不藏到侧栏
3. **单图标 toggle**：侧栏开关使用 PanelRight 面板图标（用户提供），单图标不切换，通过 active 态（绿色高亮）表示打开状态
4. **顶部 tab 切换**：侧栏顶部 2 个图标 tab 切换感知/仪表盘
5. **最小化迁移**：PanelManager 数据层零改动，只动 DOM 挂载点 + CSS + 路由层

### 1.2 面板分类（信息架构根本）

| 面板 | 本质类型 | 触达模式 | 安置位置 | 心智模型 |
|------|---------|---------|---------|---------|
| 对话 | 工作区（主任务） | 持续使用 | 主面板 | 我在和精灵聊天 |
| 记忆 | 工作区（主任务） | 持续使用 | 主面板 | 我在管理记忆 |
| 剪贴板 | 工作区（辅助操作） | 触发即高频 | 主面板 nav | 我复制了东西要立刻处理 |
| 设置 | 系统配置 | 低频 | 主面板 nav | 我要改配置 |
| 感知 | **信息展示** | 低频但持续可见 | 右侧栏 tab | 精灵状态如何？瞄一眼 |
| 仪表盘 | **信息展示** | 低频但持续可见 | 右侧栏 tab | 运行数据如何？瞄一眼 |

**核心原则**：工作区面板占主区域（大面积操作空间），信息展示面板占侧栏（窄条持续可见，不打断主任务）。

## 二、资深程序员排雷（v3 新增）

> 应用心智模型：**怀疑前提 → 区分症状与根因 → 向源头追溯 → 绕过而非修补 → 方案复杂度匹配**
> 参考主流：VSCode / Trae IDE / Cursor / Figma / Discord / Chrome DevTools

### 雷区 1：双图标 toggle 是反模式 ⚠️（已修正）

**原方案**：侧栏打开时显示 PanelRightClose（收起图标），关闭时显示 PanelRightOpen（展开图标）——两个图标切换。

**排雷**：
- VSCode/Cursor/Trae 的面板 toggle 全部使用**单图标 + active 态**，不做图标切换
- 图标切换让用户困惑："这个图标到底是什么意思？是当前状态还是可执行的动作？"
- 双图标还需要维护两套 SVG + 状态同步，增加无谓复杂度
- 参考 Discord 频道列表 toggle、VSCode 二级侧栏 toggle、Figma 图层面板 toggle——全部单图标 + active 态

**修正**：使用单个 PanelRight 面板图标，侧栏打开时按钮处于 active 态（`--active-bg/--active-fg` 绿色高亮，复用 CSS-R8 刚建立的激活态令牌体系），关闭时 default 态。用户学习成本最低。

### 雷区 2：侧栏 header 内关闭按钮冗余 ⚠️（已修正）

**原方案**：侧栏 header 右侧放一个 `.aux-collapse-btn` 收起按钮，左侧 nav 也有 toggle 按钮——两个关闭入口。

**排雷**：
- VSCode 的 Activity Bar 图标本身就是 toggle（点击打开，再点关闭），侧栏内部不需要额外关闭按钮
- 两个关闭入口 = 两个需要维护的状态 + 用户犹豫"该点哪个关"
- 唯一需要侧栏内部关闭按钮的场景是"用户找不到左侧 toggle"——但 toggle 始终可见在 nav 底部
- Figma/Discord 的面板关闭按钮在面板右上角是因为它们没有 Activity Bar toggle，memora 有

**修正**：**移除侧栏 header 内的关闭按钮**。唯一开关入口是左侧 nav 的 toggle 图标。侧栏 header 只放 2 个 tab 图标。关闭路径只有一个：点击 toggle（再点一次），与 VSCode 行为一致。

### 雷区 3：width 动画性能问题 ⚠️（已修正）

**原方案**：`transition: width 0.2s` 从 0 到 280px。

**排雷**：
- `width` 过渡触发每帧 layout reflow（重排），性能差，在 Electron 低端设备上可能卡顿
- 但 `transform: translateX()` 是 overlay 模式（覆盖在主面板上），不符合"push 内容"的设计意图
- 主流 IDE 实际用什么？VSCode 用的是即时切换（无动画）！Cursor/Trae 同
- 原因：开发者工具类应用以效率为先，面板开关是高频操作，动画反而打断心流

**修正**：
- **侧栏开关无动画**（instant toggle，0ms）——对齐 VSCode 行为，性能零开销
- 侧栏打开/关闭是布局变化，不是装饰性效果，不需要动画
- 如果未来要加动画，使用 `grid-template-columns` 过渡（现代浏览器已优化）而非 `width`

### 雷区 4：侧栏与主面板视觉割裂 ⚠️（已修正）

**原方案**：侧栏独立 `border-radius` + `box-shadow` + `margin-left: 8px`，看起来像浮在主面板旁边的独立卡片。

**排雷**：
- VSCode/Figma 的主面板和侧栏是**同一容器的两个区域**，用 1px 分隔线区分，不是两张独立卡片
- 两个圆角+阴影卡片并置 = 视觉噪音（"两个窗口"的错觉）
- memora 现有的 `#panel-chat` 等面板已经用 `--window-bg` + `--radius-window` + `--shadow-window` 做了窗口级样式

**修正**：
- 主面板区域和侧栏**共享外框**：`.main-panel-area` 负责左侧圆角，`#aux-sidebar` 负责右侧圆角，中间用 1px `var(--surface2)` 分隔
- 两者共同组成一个 `#main-content` 整体窗口，而不是两个独立卡片
- `margin-left: 0`，用 `border-left: 1px solid var(--surface2)` 做分隔
- 阴影只在 `#main-content` 外层，不在侧栏单独加阴影

### 雷区 5：.main-panel-area 包裹层的 CSS 选择器影响 ⚠️（已标注实施验证点）

**排雷**：
- 现有 `.panel` 绝对定位基于 `#main-content` 作为 `position: relative` 容器
- 新增 `.main-panel-area` 包裹层后，主面板区的 panel 需要以 `.main-panel-area` 为定位上下文
- 需要验证现有 CSS 是否有 `#main-content > .panel` 直接子选择器——如有需改为 `.main-panel-area .panel` 或保持直接子选择器但迁移 DOM
- 这是 P1 骨架阶段的核心验证点

### 雷区 6：侧栏关闭时的可见入口不足 ⚠️（已补充入口路径）

**排雷**：
- 侧栏关闭后，用户如何知道感知/仪表盘存在？
- 原方案只有 toggle 按钮，但新用户可能不知道 toggle 是什么
- 主流应用的做法：**相关上下文入口自动打开侧栏**

**修正**：补充 3 条自动打开路径（对齐 VSCode 从其他入口打开面板的行为）：
1. 点击 chat toolbar 的精灵状态条 → 自动打开侧栏 + 切换到感知 tab
2. 命令面板（Ctrl+K）选择"感知"/"仪表盘" → 自动打开侧栏 + 切换到对应 tab
3. 记忆面板"健康度诊断"按钮 → 自动打开侧栏 + 切换到仪表盘 tab

toggle 按钮 tooltip 显示"信息面板（感知 / 仪表盘）"帮助新用户理解。

### 雷区 7：tab 切换动画多余 ⚠️（已修正）

**原方案**：未明确说明，但容易直觉加淡入/滑动动画。

**排雷**：
- VSCode/Figma/Discord 的侧栏 tab 切换全部**即时切换**（0ms）
- tab 切换是"换内容"不是"转场"，动画是多余的视觉噪音
- 侧栏本身宽度仅 280px，内容区域小，淡入动画反而造成闪烁感

**修正**：tab 切换即时，不加动画。侧栏开关也不加动画（雷区 3）。唯一保留动画的是 hover/active 状态变化（150ms，走 `--transition-fast`）。

### 雷区 8：侧栏宽度选择 ⚠️（确认 280px）

**排雷**：
- VSCode 默认侧栏：~250px，但可拖拽 resize
- Figma 右侧属性面板：240-320px
- Discord 成员列表：240px
- Chrome DevTools 侧面板：~300px
- memora 感知面板有四维雷达图（需 100px 直径 + 标签），仪表盘有 7 天柱状图（需至少 240px 才能显示 7 根柱子）
- 280px 是平衡值：雷达图 100px + 两侧 padding 各 16px + 标签 = ~132px 够用；7 天柱状图每根 32px × 7 = 224px + padding 16px × 2 = 256px < 280px

**确认**：280px 合理。resize 能力列为 v3+ 未来增强（非 2.1 范围）。

### 雷区 9：侧栏默认状态 ⚠️（建议默认打开）

**排雷**：
- VSCode 侧栏默认打开（Explorer 可见）
- Figma 右侧属性面板默认打开
- 新用户第一次打开 memora，如果侧栏默认关闭，他们永远不会发现感知/仪表盘的存在
- 但 v1 升级用户已经习惯全宽主面板，突然多了侧栏可能"面板变小了"
- 折中：默认打开，但首次显示时给一个轻微的视觉引导（如 toggle 按钮 pulse 一次，仅首次启动）

**确认（2026-07-22）**：默认打开（`auxSidebarOpen: true`），持久化用户手动关闭的偏好。默认 tab 为感知。

### 雷区 10：小窗口自动收起逻辑简化 ⚠️（已修正·智能决策）

**原方案**：< 900px 自动收起 + userTouched 标志 + 恢复窗口时恢复状态——复杂状态机。

**排雷 + 代码验证**：
- 主窗口 `minWidth` 为 640px（[windowManager.ts:28](file:///f:/zooique/memora/hosts/memora-sprite/src/electron/windows/windowManager.ts#L28)），侧栏 280 + 主面板 360 = 640，恰好卡在极限
- 用户把窗口缩到 640px 是主动选择——不应替用户做爹味自动决策（"我怎么刚打开的侧栏不见了？"）
- 如果侧栏确实挤占了主面板，用户会：调大窗口 / 或点一下 toggle 关闭侧栏（操作成本极低）
- 参考 VSCode/Cursor：面板开关也完全由用户手动控制，不因窗口大小自动收起

**智能决策**：**完全移除自动收起逻辑——连 CSS `@media` 也不加。** 侧栏打开/关闭完全由用户手动 toggle 控制。主窗口 minWidth 保持 640px 不变（侧栏 280 + 主面板 360 = 640，刚好。如果反馈不够用，再调整 minWidth）。信任用户，不做隐性自动化。

### 雷区 11：Canvas resize 时机 ⚠️（补充细节）

**排雷**：
- 仪表盘 Canvas 图表在侧栏打开时从全宽变为 280px 窄宽度，需要 resize
- Canvas resize 不能在 CSS 动画帧中做（如果有动画），必须在布局稳定后
- 既然侧栏开关是即时的（无动画，雷区 3），Canvas resize 可以在 toggle 后直接 requestAnimationFrame 执行
- 需要确保侧栏内 panel 的 `aux-active` 状态设置和 Canvas resize 在同一帧，避免闪烁

### 雷区 12：.aux-active vs .active 类名冲突 ⚠️（已明确方案）

**排雷**：
- 现有 `.panel.active` 选择器控制主面板区 panel 可见性
- 侧栏内 panel 不能用 `.active`，否则会被主面板区 CSS 误匹配
- 引入 `.panel.aux-active` 独立状态类，但需要确保两个状态互斥（一个 panel 不能同时在主面板和侧栏显示）
- 由于感知/仪表盘 DOM 迁移到侧栏后**永远不会出现在主面板区**，不存在冲突——它们的 class 从 `.active` 变为 `.aux-active` 即可
- PanelRouter 需要明确区分 `switchPanel()`（主面板区，设置 .active）和 `switchAuxTab()`（侧栏区，设置 .aux-active）

### 3.2 图标定义

**侧栏 toggle 图标**（新增 `#icon-panel-right`）：

```svg

  <rect x="3" y="3" width="18" height="18" rx="2" fill="none" stroke="currentColor" stroke-width="1.5"/>
  <line x1="15" y1="3" x2="15" y2="21" stroke="currentColor" stroke-width="1.5"/>
```

- 视觉：24×24 圆角矩形 + 右侧 1/3 处纵向分隔线（用户提供图标的标准 Lucide PanelRight 样式）
- 风格对齐：stroke-width="1.5"、rx="2"，与现有图标（#icon-maximize、#icon-folder 等）完全一致
- 单图标不切换，按钮 active 态表示侧栏打开

**Tab 图标**（复用现有 SVG）：
- 感知：`#icon-heart`（沿用）
- 仪表盘：`#icon-chart`（沿用）

### 3.3 状态机

```typescript
/** spriteConfig 持久化字段 */
interface SpriteConfigAuxSidebar {
  /** 侧栏是否打开（默认 true，持久化用户偏好） */
  auxSidebarOpen: boolean;
  /** 侧栏当前激活 tab（默认 'perception'） */
  auxSidebarTab: 'perception' | 'dashboard';
}

/** 运行时状态（PanelRouter 管理） */
interface RouterState {
  /** 主面板区当前面板 */
  activePanel: 'chat' | 'memories' | 'clipboard' | 'settings';
  /** 侧栏当前 tab */
  activeAuxTab: 'perception' | 'dashboard';
  /** 侧栏是否打开（同步到 spriteConfig） */
  auxSidebarOpen: boolean;
}
```

### 3.4 交互规格

| 操作 | 行为 | 动画 |
|------|------|------|
| 点击 toggle（侧栏关闭时） | 打开侧栏，恢复上次 tab，toggle 变 active | **即时（0ms）** |
| 点击 toggle（侧栏打开时） | 关闭侧栏，toggle 变 default | **即时（0ms）** |
| 点击 .aux-tab | 切换 aux-active 状态，侧栏保持打开 | **即时（0ms）** |
| 主面板切换 | 切换 .active 面板，侧栏状态不变 | 即时 |
| 点击精灵状态条 | 打开侧栏 + 切换到感知 tab | 即时 |
| Ctrl+K 选感知/仪表盘 | 打开侧栏 + 切换到对应 tab | 即时 |
| 点击"健康度诊断" | 打开侧栏 + 切换到仪表盘 tab | 即时 |
| toggle hover | background 变化 | 150ms（--transition-fast） |
| .aux-tab hover/active | background/color 变化 | 150ms（--transition-fast） |

## 五、设计决策记录

| # | 决策 | 理由 | 备选方案 |
|---|------|------|---------|
| D1 | 单图标 toggle + active 态 | 主流 IDE 标准模式；最低学习成本；避免双图标困惑 | ❌ 双图标切换（已排除，雷区 1） |
| D2 | 侧栏 header 无关闭按钮 | 唯一开关入口是 toggle，避免冗余入口 | ❌ 两个关闭入口（已排除，雷区 2） |
| D3 | 侧栏开关无动画 | VSCode 标准行为；性能零开销；效率优先 | ❌ width 动画（性能差，雷区 3）/ transform overlay（不符合 push 模式） |
| D4 | tab 切换无动画 | 侧栏面积小，动画是噪音 | ❌ 淡入/滑动（多余，雷区 7） |
| D5 | grid 布局（非 flex + absolute） | grid-template-columns 天然支持 0→280px 切换，无 width 动画问题 | flex + width transition（性能差） |
| D6 | 主面板+侧栏共享外框 | 同一容器用 1px 分隔线，非两张独立卡片 | ❌ 各自圆角+阴影（视觉割裂，雷区 4） |
| D7 | 剪贴板保留主面板 nav | 主动操作型面板，一步可达 | ❌ 三合一（操作链路变长，v1 已排除） |
| D8 | 侧栏默认打开 | 新用户可见性优先；持久化用户关闭偏好 | 默认关闭（功能不可发现，雷区 9） |
| D9 | 自动打开路径 3 条 | 相关上下文入口自动打开侧栏，降低发现成本 | 仅 toggle（雷区 6 入口不足） |
| D10 | 280px 宽度 | 雷达图+柱状图+padding 计算后最小可用宽度 | 240（太紧）/ 320（占太多主面板空间） |
