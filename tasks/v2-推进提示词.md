## 提示词 D · UI 质量打磨（Q-UI）

> **范围**：视觉一致性 + 令牌化 + 动画精修
> **执行模式**：方案更新 → 提交前审查
> **触发时机**：UI 模块改动时 / 定期视觉审查

### 触发提示词

```
你是一名资深前端工程师，对 sprite 进行 UI 质量打磨。执行模式：方案更新 → 提交前审查。

【v2 基调】
从"能用"到"好看"——不新增 UI 元素，聚焦现有 UI 的视觉一致性打磨。

【任务清单】
详见 f:\zooique\memora\tasks\待完成任务.md §四、UI 质量。

检查清单（每次打磨必查）：
1. 令牌合规：间距/圆角/颜色是否走 tokens.css 令牌，禁止裸 px
2. 对齐一致性：面板内元素对齐、列表项间距是否统一
3. 状态反馈：激活/hover/disabled/loading 四种状态风格是否一致
4. 操作可见性：常用操作按钮是否"主动可见"（非 hover-only）
5. 动画自然度：过渡动画时长 150-300ms，缓动函数统一

【关键约束】
- 令牌单一真理源：foundation/tokens.css 是唯一定义处
- 不引入新的颜色/字体/间距——扩展 tokens.css 需评估全局影响
- 禁止内联 `<style>` 块——CSP 已收紧为 `style-src 'self'`
- 不添加纯装饰性元素——不增加无功能价值的动画/图标/分割线

【输出要求】
- 按检查清单逐项输出扫描结果
- 发现的问题分级（P0 视觉bug/P1 不一致/P2 建议）
```

## 提示词使用指南

### 何时触发哪个提示词

| 场景 | 推荐提示词 | 执行模式 |
|------|-----------|---------|
| 每次改动前 | A（代码质量） | 剪枝 → 审查 → 测试 |
| 定期（每月） | B（设计质量） | 年轮审判 |
| 用户反馈体验问题 | C（功能质量）+ E（用户体验） | 问诊 → 方案 → 审查 |
| UI 模块改动时 | D（UI 质量） | 方案 → 审查 |
| 定期全量诊断 | F（全维度） | 神木回天 |

### 执行顺序建议

1. **F（全维度诊断）**：v2 启动时先跑一次，建立基线快照
2. **A（代码质量）**：每次改动前扫描，渐进式清理
3. **B（设计质量）**：每月一次，架构层审查
4. **C/D/E**：按需触发，自然生长

- 每个提示词可直接复制到新会话使用
- 提示词中的 `【关键约束】` 部分根据 project-rules.md §7.6 自动生成
- 如果多个维度的修改涉及同一文件，建议合并到一次会话处理
- 每次执行后需更新 `tasks/待完成任务.md` 和 `tasks/已完成任务.md`
- 健康度快照统一放在 `tasks/健康度快照/` 目录
