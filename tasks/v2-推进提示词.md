## 提示词使用指南

### 何时触发哪个批次

| 场景 | 推荐批次 |
|------|---------|
| 空闲时想清理代码 | A（斩木除根，最机械） |
| v2 开发涉及控制器层 | B + D |
| v2 开发涉及渲染层/UI | C |
| 打包前 / 规则变更 | D |
| 用户反馈体验问题 | E（复制模板 + 填写反馈） |
| 健康度快照发现阈值 | F（复制模板 + 填写触发） |

### 执行顺序建议

1. **批次 A**：随时可做，最机械，适合碎片时间
2. **批次 B/C/D**：v2 开发中遇到时顺手做
3. **批次 E**：用户反馈驱动，按优先级选择
4. **批次 F**：阈值驱动，不主动触发

### 注意事项

- 每个提示词可直接复制到新会话使用
- 提示词中的 `【关键约束】` 部分根据项目规则自动生成，无需修改
- 如果多个批次的修改涉及同一文件，建议合并到一次会话处理
- LONG 系列任务的触发提示词需要填写具体的触发原因
