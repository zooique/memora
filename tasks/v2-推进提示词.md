## 提示词使用指南

### 何时触发哪个批次

| 场景 | 推荐批次 | 执行模式 |
|------|---------|---------|
| v2 开发涉及渲染层/UI | A | 方案更新 → 提交前审查 |
| 对应功能模块大改时 | B | 方案更新 → 提交前审查 |
| 定期依赖复核 / 上游修复 | C | 规则对齐 |
| 用户反馈体验问题 | D | 问诊 → 方案更新 → 提交前审查 |
| 健康度快照发现阈值 | E | 神木回天 |

### 执行顺序建议

1. **批次 C**：定期复核（每月一次），低成本高价值
2. **批次 A/B**：v2 开发中遇到时顺手做，自然生长触发
3. **批次 D**：用户反馈驱动，按优先级选择高频候选
4. **批次 E**：阈值驱动，不主动触发

### 注意事项

- 每个提示词可直接复制到新会话使用
- 提示词中的 `【关键约束】` 部分根据项目规则自动生成，无需修改
- 如果多个批次的修改涉及同一文件，建议合并到一次会话处理
- LONG 系列任务的触发提示词需要填写具体的触发原因
- 每次执行后需更新 `tasks/待完成任务.md` 和 `tasks/已完成任务.md`
