# 审查报告 · 发版就绪与版本号裁定（2026-10-07）

> 范围：内核 `@zooique/memora` + 宿主 `hosts/memora-vscode` 双轨。
> 方法：SSOT 原则 + 不带伤原则 + 实锤验证（grep / git / mtime / node require，非二手结论）。
> 结论先行：**同意内核改 4.0.0**；但 4.0.0 不是"改个数字"，它暴露出三项必须同步收口的伤，其中宿主的发布阻断（icon/版本线）比内核版本号更紧急。

---

## 一、核心裁定：memora 版本号改 4.0.0 —— 同意，且是 SemVer 强制而非可选

| claim | evidence | conclusion |
|---|---|---|
| 内核已 ≥1.0，SemVer 全量生效 | `package.json:2` `"version": "3.0.1"` | MAJOR 增量门槛已开启 |
| 内核 Unreleased 含破坏性变更 | `CHANGELOG.md` 内核区 **9** 个 `⚠️ Breaking` 标记（awk 精确计数）；宿主区 3 个 | 破坏性变更属实且量大 |
| 公共导出面真实收缩 | `src/index.ts` 抽样 7/7 符号（`DefaultDuplicateCallInterceptor`/`IdempotencyLevel`/`InMemoryRoundStore`/`generateRoundId`/`COMPRESS_TARGETS`/`RolePack`/`PlanItem`）已不在公共面；CHANGELOG 记移除 53+3=56 个 | 移除已落地，非纸面 |
| 属于"不兼容 API 变更" | SemVer §8：MAJOR 当且仅当不兼容 API 修改；公开 npm 包（latest=3.0.1）对外承诺 SemVer | **任何 `^3.0.1` 外部消费者会被静默破坏** |
| 真实消费者仅宿主 | 宿主 `dependencies`: `"@zooique/memora": "file:../.."`（line 214），esbuild 内联内核 | 实际零破坏影响，但**公开契约仍须守 SemVer** |

**对抗式反方（为何有人主张 3.1.0）**：真实消费者只有宿主且版本不耦合 → 无外部影响；ADR-033 + CHANGELOG 已"定档 3.1.0"。
**反驳**：公开 npm 包一旦发版即对外承诺 SemVer；"当前无外部消费者"是现状不是契约。坚持 3.1.0 = 主动违约，且未来有真实外部消费者时无法回头。

**裁定**：`3.0.1 → 4.0.0`。发版前必须把 CHANGELOG/台账里"随 3.1.0 发版"的措辞改写为 4.0.0（见缺口 C1），否则文档与发版事实不符（不带伤违规）。

## 三、下一个迭代方向推演

用户计划：**先发内核 4.0.0 → 再发宿主**。据此分阶：

**阶段 0 · 发版前置（P0，内核/宿主可并行）**
- 内核：bump 4.0.0 → CHANGELOG 头改写 → tsc+eslint(`--max-warnings 0`)+vitest 全绿 → dist 新鲜 → `npm publish`（gitee+github 双 push）。
- 宿主：补顶层 `icon.png`（B1）、定版本线（B2，建议与内核解耦走独立线或同步 4.0.0）、补截图（B3）、加内核版本内联断言（C2）。
- 注意：`file:../..` 在 `vsce package` 下会触发 `npm install` 拉内核 → 须确保内核已 build 且 `../..`/dist 新鲜（已验证）。

**阶段 1 · 宿主发版（P0）**
- `vsce package` + publish。需先过 B1/B2/C2，否则市场页残缺或装到 stale 内核。

**阶段 2 · 下一功能迭代（P1/P2）**
- 用户 memory 中 P4（A 类阻断面板/B 类信息条/顶部任务表 UI 两分收敛）为最高优先 → 继续**真机视觉验收闭环**（闪烁/位置/覆盖），测试通过≠完成。
- 宿主 100 条未发版里大量 Fixed/Added 已落地，下一迭代应聚焦真机验收而非再加功能。
- 内核侧：导出面收敛后，长期债在"角色包键面 SSOT 收口 + 宿主编辑 UI 双向同步"。

## 四、对"同意 4.0.0 吗"的最终回答

**同意。** 理由：SemVer 强制（公开 npm 包 + 9 个 Breaking + 56 公共符号移除 = 不兼容 API 变更）+ 对外契约诚信。
但 4.0.0 暴露三项须同步修的伤，优先级排序：
1. **B1/B2（宿主 icon PNG + 版本线）** — 比内核版本号更紧急，是发版真正卡点，且与内核 4.0.0 解耦可并行动手。
2. **C1（CHANGELOG/台账 3.1.0→4.0.0 改写）** — 不带伤合规，发版前必做。
3. **C5（发版脚本固化）** — 防重复踩坑，建议阶段 0 收口。
