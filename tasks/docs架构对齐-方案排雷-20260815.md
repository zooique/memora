## 二、逐项排雷推演（不可跳过）

### 雷-1 · C-3 roundId 双重分配 → 修复推演

**修复方案**：`AgentLoop.processUserInput` 增加可选第 4 参 `roundId`；[agent.ts:574](file:///f:/zooique/memora/src/agent/agent.ts#L574) 传入 prepareChatContext 生成的 R1；[loop.ts:375](file:///f:/zooique/memora/src/agent/loop.ts#L375) 改为 `this.currentRoundId = roundId ?? \`round-${Date.now()}\``。

**雷区推演**：
- ✅ **内部递归排除**：[loop.ts:442/458](file:///f:/zooique/memora/src/agent/loop.ts#L442-L458) 是 `processEvent` 的分支委托，非 processUserInput 内部递归；不传参 → 自生成，行为不变。
- ✅ **测试兼容**：`loop.test.ts` / `metrics.test.ts` 直接调 processUserInput 不传参 → 每轮独立生成 roundId，现有断言不受影响。
- ✅ **单一写入点**：appendUser（agent.ts:554，R1）与 appendAssistant（agent.ts:584/594/855 等，getCurrentRoundId）统一到 R1；roundSummaryGenerator 经 `getCurrentRoundId()` 同取 R1。
- ✅ **SSOT**：roundId 分配职责保留在 agent 层（prepareChatContext，作为"外部输入"入口），loop 以传入为准，不再双源。
- ⚠️ **接口漂移**：改 processUserInput 签名（可选参，向后兼容）。需同步检查所有调用点（agent.ts:574 + loop.ts:442/458 + 测试，均为可选参不受影响）。
- **结论**：方案成立，可执行。风险低。

**雷区推演**：

- ✅ **护栏本体不受影响**：`guardrail.ts` 执行逻辑不变，仅规则池不再含无效自然语言项。
- ⚠️ **接口清理**：`assembleAgent`/`createAgentLoopAndDeps` 参数签名变更，需同步更新调用点与相关测试（若有）。
- **结论**：方案成立。符合"不预埋半实现"纪律。风险中低（涉及 assembler 内部接口）。

### 雷-3 · C-1 role-packs 迁移 → 修复推演（含 schema 配套，雷区最多）

**修复方案**：将 `role-packs/` 下 5 个单文件 .md（写作助手/代码助手/技术文档工程师/翻译助手/项目总监）迁移为文件夹形态：`<名>/manifest.json` + `<名>/persona.md` + `<名>/rules.md`；同步更新 role-pack-spec §九 与 mvp-scope 的样例描述。

**雷区推演（关键）**：
- ❌ **雷-3a · skills 纯能力声明被静默丢弃**：[parseManifestSkills](file:///f:/zooique/memora/src/role-pack/rolePackManager.ts#L175-L194) 要求 `file` 非空，缺省直接 `continue` 丢弃整项；[schema](file:///f:/zooique/memora/docs/role-pack/role-pack.schema.json#L190) `skills[].file` 必填。而示例包的 skills 是**纯 capability 声明**（如 `- capability: file:read`，无实际技能文件）。若按现 schema 迁移 → 能力声明全部丢失。
  **修正**：`skills[].file` 改为条件可选——"file（生态指针）或 capability（能力声明）至少其一"。同步改 `parseManifestSkills`（无 file 但有 capability 时保留）与 schema `oneOf`。这是对角色包标准的合理修订，需同步 spec 文档 §四。
- ❌ **雷-3b · schema/validator 的 reflect 缺 loopContinue/userFollowup**：schema `strategy.reflect` 只有 summary/handoff；validator `STRATEGY_KEY_RULES` 只有 summary/handoff/userFollowup（无 loopContinue）。但 `reflect.loopContinue` 与 `reflect.userFollowup` 均是**已消费冻结键**（[agent.ts:525-534](file:///f:/zooique/memora/src/agent/agent.ts#L525-L534) / [types.ts:626](file:///f:/zooique/memora/src/role-pack/types.ts#L626)）。迁移示例包若含 loopContinue → schema 拒、validator 报未知键。
  **修正**：schema + validator 的 reflect 段补 `loopContinue`（number，0=关）与 `userFollowup`（enum: ask/silent）。
- ❌ **雷-3c · askOn/askLimit 状态标注三处打架**：[types.ts:216-221](file:///f:/zooique/memora/src/role-pack/types.ts#L216-L221) 诚实化声明"global: askOn/askLimit 被消费"；[schema](file:///f:/zooique/memora/docs/role-pack/role-pack.schema.json#L166-L172) 标 [草案]；spec §六 标 [草案]。需统一为"冻结-条件消费（userFollowup=ask 时生效）"。
  **修正**：spec §六 + schema 描述同步改标注。
- ✅ **雷-3d · configDir 与运行时激活**：`rolePackManager` 扫描 `<configDir>/role-packs/`，宿主 configDir 各自指向宿主目录 → 仓库根 role-packs/ 默认不被扫描。迁移目标是**资产/文档一致性**（让样例真实可装载、文档诚实），不追求默认运行时激活。迁移后更新 spec §九 与 mvp-scope 描述即可。
- ⚠️ **雷-3e · 内容拆分**：每个 .md 的 frontmatter（meta + strategy）→ manifest.json；`## Persona` → persona.md；`## Rules` → rules.md；`## Skills` → manifest.skills 数组。注意：代码助手.md 的 skills 是 `- web_search: 描述` 旧格式（无 capability 前缀），需归一为 `capability: web:search`；项目总监.md 已是 `- capability: file:read` 新形状。key 归一：`act.toolMode` 保持标准键；示例里 `prepare.recentRounds: 5`、`memoryRecall: full` 等保留。
- **结论**：方案成立，但**依赖 schema/validator 先修订（雷-3a/3b/3c）**，否则迁移产物无法通过机检。排序在代码修复之后。
