# 任务清单双轨呈现——UI 体验升级（2026-09-05，Phase 4.1 收敛后自然生长）

> **设计原点**：memora 内核已具备完整任务清单能力（task_table_write/update 工具 →
> checkpoint.plan 持久化 → 宿主 postPlanUpdate 推送 plan_update 协议消息），webview 目前
> 只有**顶部独立面板**一种呈现方式。参考 Trae Work 的双轨呈现（独立清单面板 + 对话流内嵌
> step 折叠），memora 需要在**不动内核、不动协议、不动宿主**的前提下，仅在 webview 层
> 增加对话流内嵌进度条 + 当前 step 高亮 + round-block step 标签。
>
> **排雷结论**：所有任务全部落在 webview + styles 层（chatView.ts + chatStyles.ts），
> 零内核改动、零协议改动、零宿主改动。证据链见下方 § 0 排雷。
>
> **哲学锚点**：单一真理源（plan 数据由内核 checkpoint 驱动，宿主只做只读快照推送，
> webview 只做只读渲染）+ 自然生长（UI 层的呈现方式变化不影响数据层的单一真理源）。

### T4 — P1：round-block summary 前加 step 标签

**改动文件**：chatView.ts renderRoundBlock（~15 行 TS）+ chatStyles.ts（~5 行 CSS）

**TS 逻辑**：

```
function renderRoundBlock(events, finalize) {
  const rb = ensureRoundBlock();
  // ... 现有逻辑 ...
  
  // 新增：如果有 active step，在 summary 前 prepend 一个标签
  const activeStep = currentPlanSteps.find(s => s.status === 'active');
  if (activeStep) {
    // 确保标签只渲染一次（不重建 details 时不重复 prepend）
    if (!rb.querySelector(':scope .round-block__plan-tag')) {
      const tag = document.createElement('div');
      tag.className = 'round-block__plan-tag';
      tag.textContent = `📍 执行 step-${activeStep.order + 1}: ${activeStep.description.slice(0, 40)}`;
      rb.prepend(tag);
    }
  }
}
```

**零新增消息类型**——webview 自己缓存 `currentPlanSteps`（从 plan_update 消息存），完全在 webview 内闭环。

## § 5 不在范围内（自然生长原则：先落地后固化）

| 不在本次 | 原因 |
|---|---|
| 耗时显示（globalPlanBoard header 加 "4m 9s"） | 当前 agent.getCheckpoint 不含 startTime；宿主需额外推送 timing。用户需求没明确要，先不动 |
| step 粒度独立 round-block（Trae Work 截图那种一个 step 一个折叠块） | 需要内核 loop 事件产出粒度改动（done chunk 带 planStepId），跨三层成本。用户没明确要，先不动 |
| plan step 手动排序/拖拽 | 内核 checkpoint.plan 按 order 排，webview 只读。排序需宿主 + 协议 + 内核全链路改，用户没要 |
| 侧边栏独立任务清单页面（Trae Work 左栏） | VSCode TreeViewProvider 体系，需要独立宿主注册，成本中等。globalPlanBoard 已在消息区顶部覆盖独立清单功能 |
