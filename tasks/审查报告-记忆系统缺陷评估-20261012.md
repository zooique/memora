## 〇、一句话判据

**内核记忆系统当前没有架构级的「明显设计缺陷」。**

初版评估曾把两处定性为「名义能力 ≠ 实际能力的落差（接近缺陷）」，经回源排雷**均被推翻**——
一处是**按设计休眠**的扩展位，一处是**已被移除/显式否认**的能力。
真正的遗留项是**已论证的设计边界/取舍**，不是缺陷，且全部「触发驱动、不预支」。

## 一、排雷过程与订正（对抗式核心）

| # | 初版断言 | 回源核验 | 订正结论 |
|---|---|---|---|
| ① | `GOVERNANCE_SOURCES=[]` = 「治理门面空转的缺陷」，跨源冲突检测停在能力层 | [governance.ts](../src/memory/governance.ts) 的 `GOVERNANCE_SOURCES` 空数组；[dedupManager.ts](../src/agent/managers/dedupManager.ts) 的 `DedupManager.sources` 构造默认参数 / [memoryAdvisor.ts](../src/agent/managers/memoryAdvisor.ts) 的 `MemoryAdvisor.sources` 构造默认参数均默认吃该数组；[types.ts](../src/memory/types.ts) 的 `SOURCE_LABELS` 文档注释 + `GOVERNANCE_SOURCES` 自身文档注释明载「round-summary 的治理由 superseded 写时取代承担，不入本数组；content 历史残留 source 无生产写入路径」；`MemoryAdvisor.detectConflicts` / `DedupManager.deduplicateMemories` 是**完整且被测**的 L3 冲突检测 / L1 语义去重实现，经 [memoryGovernance.ts](../src/agent/managers/memoryGovernance.ts) 的 `MemoryGovernance.deduplicate` / `detectConflicts` 委托接进 [agent.ts](../src/agent/agent.ts) 的 `_governance` 组装点生产路径 | **推翻「缺陷」定性**。`GOVERNANCE_SOURCES` 空是**按设计**：当前唯一自动写入源 round-summary 的治理由写时取代（supersede）承担，本数组只治理「实际写入记忆库的其他 source」——现阶段无第二源可治理。L1/L3 管理器是**刻意休眠**，待多源记忆（persona/rule/skill）接入才激活。属**潜伏接线风险**，非当前缺陷 |
| ② | 语义（向量）通道是「僵尸能力、假宣称」 | [memoryInspector.ts](../src/agent/managers/memoryInspector.ts) 的 `searchByKeyword` 文档注释**曾自陈**「embedding 写端缺失导致语义通道在生产从未生效，属于宣称能力零消费的僵尸」（该措辞已随本报告同批订正为「历史说明」）；而 [loader.test.ts](../src/config/__tests__/loader.test.ts) 的「空缺编号位」留痕表明该段已随 **embedding 段整体移除**；[builtinTools.ts](../src/agent/builtinTools.ts) 的 `search_memories` 工具描述已**明文「纯关键词通道，无语义向量通道」「语义近义/换说法不会命中」**；[memoryInspector.test.ts](../src/agent/managers/__tests__/memoryInspector.test.ts) 文件头覆盖清单标注「语义通道已收编移除」 | **推翻「僵尸假宣称」定性**。语义向量通道**不是当前生效的假宣称**——它已从配置段移除、从工具描述显式否认。初版据该注释误判，原措辞沿用 ADR-016 当时对『能力在、但零消费』的实锤判定，如今能力已删除，继续称「僵尸」即为过时表述（同批订正为「历史说明、非现行能力宣称」）。它指出「为何没有向量通道」，不构成「声称有却没有」 |

> 排雷纪律落点：两条初版结论都犯了「转述失真」——把**历史解释性注释**或**按设计空的扩展位**当成了**当前生效的缺陷**。这正是上一轮（`memory-governance-design.html` §8 排雷对质）已订正过的同类错误，本次在缺陷评估里重犯，已就地纠正。

## 二、最终分类评估

### 2.1 非缺陷的设计取舍（优点 / 已论证权衡）🟢

| 取舍 | 真源证据 | 判定 |
|---|---|---|
| 拒绝「暗排序」：accessedAt 只作事实揭示、不引入时间主序 | [memoryInspector.ts](../src/agent/managers/memoryInspector.ts) `searchByKeyword` 截断段注释「不引入 accessedAt 时间主序（§5.2 定案）」 | 优点。避免假「重要度」幻觉，优先级交 LLM 结合任务定夺 |
| 无衰减 / 无自然遗忘 | [governance.ts](../src/memory/governance.ts) 文件头治理模型说明 | 刻意。记忆≠缓存，有效性由 superseded 写时取代判定 |
| 纯关键词单通道（无向量） | `searchByKeyword` 文档注释的「无语义（向量）通道」段、引 Anthropic Memory tool / Claude Code / Librarian Pattern 实证「LLM 消费者 + 小语料下纯关键词足用」 | 在「小语料 + LLM 自主改述重试」场景成立（前提见 2.3 ③） |
| 写时取代（确定性加权 Jaccard）优于读时猜测 | [roundSummaryGenerator.ts](../src/agent/managers/roundSummaryGenerator.ts) `supersedeSimilar` 设计取舍「确定性启发式代替额外 LLM 判断，零成本可测」 | 好设计。冲突消解前置到写入期，读路径确定性过滤 |
| 角色-记忆分离 / 工具化召回 | `searchByKeyword` 文档注释的边界声明（搜索工具不是召回管线，无 L1/L2 分层） | 边界清晰，符合 SSOT 纪律 |

### 2.2 真实遗留：已论证的设计边界（非缺陷，触发驱动）🟡

| 边界 | 真源证据 | 性质 | 触发升档条件 |
|---|---|---|---|
| ③ 跨 session 取代语义缺口：supersedeSimilar 仅同 session | [roundSummaryGenerator.ts](../src/agent/managers/roundSummaryGenerator.ts) `getSessionCandidates` 文档注释「跨 session 长期历史不参与取代判定，无跨 session 覆盖语义」；该方法刻意收敛到同 session 近期 | 真实边界。同主题**跨会话**冲突（如「上周定 A」「这周定 B」且不同会话）不被治理，召回期靠 LLM 自行分辨；语料增长后此类冲突放大 | 真实「该想起旧决策却召回冲突版本」反馈，或库存跨会话同主题显著 |
| ④ 写入态② LLM 单点无补救链：summary=null / parse 失败即静默漏记 | `RoundSummaryGenerator.generate` 内 LLM 返回校验段（无效 JSON、summary=null 均直接 `return`）；同方法的 catch 兜底仅记 warn（fire-and-forget 不阻塞主流程） | 真实脆弱点。原料已落盘（对话独立存），但「是否沉淀」这步若 LLM 抖动即**静默跳过**，无重试 / 无回补通道。是刻意的「容错优先于完整」，但缺 fallback | 真实「某轮本该记却没记」反馈，或想补一条「可重试/可回补」的沉淀通道 |

> 边界③/④ 与 `docs/architecture/memory-governance-design.html` §9 的对抗式张力一致，并向后延伸——它们是**已论证的权衡**，不是「烂设计」。

### 2.3 与产品层叠加的缺口（非内核缺陷，影响「记忆系统」整体交付）🟡

| 缺口 | 说明 | 标记 |
|---|---|---|
| 无 MCP 化 | 治理层是内核内部机制，外部 agent 无法消费「跨工作区 + 有治理」的记忆。战略建议最高优先 = 内核 MCP 化（local-first 治理型 memory server） | 产品层 P1（台账 `D1-MCP`） |
| 跨重启恢复退役 | `SessionCheckpoint` 同进程内存态不落盘（见 `CHKPT-1/2/3`），记忆库本身落盘但「会话连续性」不跨重启续跑 | 产品层 P2 |
| 单 Agent 无并行 | 记忆积累串行，无并行子 agent 分摊沉淀（`agent-design-philosophy.md` §14.1 子 Agent：turn 的递归 已规划「异步 fork + 独立副本」正解形态，见台账 `Step 3`） | 产品层 P2 |

## 三、与护城河论述的对齐（防过度自信）

此前横向对比把「唯一跨工作区 + 交互积累 + 有治理」列为 memora 护城河。本次排雷要求收紧表述：

- **「有治理」的硬货 = 写时取代（supersede）**，它**不依赖** `GOVERNANCE_SOURCES` 门面，单源世界下独立成立 → 护城河核心成立。
- **「有治理」的门面层（L1 去重 / L3 冲突检测）当前休眠**，仅当多源记忆接入才激活。对外宣称「治理」时，应区分「已落地的写时取代」与「待多源激活的跨源治理」，**勿把休眠门面算进当前护城河**。
- **语义通道已显式移除/否认**，对外文档与工具描述均已对齐「纯关键词」，无假宣称残留 → 对外表述诚实。
