- **UI-CONFIRM-P10B** — 活动详情未读判据 · metrics 路径残余常驻（终版 = 诊断信号量，连修三版）｜✅ 已落地（2026-10-05 补审）
  **根因（对抗式审查实锤，非假绿）**：P10 的判据写成 `!activityUnread && activityMetrics.hidden`，把 `activityMetrics.hidden` 当「有没有指标要看」的事实喂进显隐决策。但它是**渲染结果**（指示指标块画不画），且 `renderMetrics` 里**只置 false、从无复位路径** ⇒ 首次 metrics 之后该字段恒 `false` ⇒ 整个 `&&` 恒 `false` ⇒ 详情区**恒显形**，「读完即收起」在 metrics 路径上完全失效。**症状只在开 `memora.showMetrics` 时出现**（活动路径本就正常），属「换壳后的常驻」——比原bug 更靠后、更难发现。**为何 347 全绿没抓住**：既有 metrics 用例只断言 `metrics.hidden === false` 与 `textContent` 内容，**无一条断言 `activityDetail.hidden` 在 metrics 路径上的行为** ⇒ 覆盖缺口，非假绿。
  **修法三版迭代（前两版当日被否，勿再回退）**：
  ① v2（同日早时，**已废弃**）：`metricsSeen` 渲染全文快照，按 `next !== seen` 标未读。错在宿主 `postMetrics` **每轮都推**，而 `llmCallCount`/token 是**累计计数、每轮必涨** ⇒ 全文每轮不同 ⇒ 退化成「每轮弹一次」，换壳不换病。
  ② v3（**已被 v3.1 收窄**）：改诊断信号量，但误把**安全审计总数 total** 收入信号。
  ③ **v3.1（落地版）**：信号 = 系统提示指纹 / 工具失败数 / 截断数 / 未解析工具意图数 / 安全审计**拒绝数 denied**。判据精确化为「**正常轮次这个值会不会变**」——fail/trunc/unparsed/denied 只在异常时涨；llmCallCount/token/budget/trace 与**审计 total** 不入信号。状态位 `metricsSignalLatest` / `metricsSignalSeen`：收起态信号变化才置 `metricsUnread`；**展开中到达的新信号当场消费**（seen=latest），收起后不反标。
  **🔴 v3 的 total 漏网（v3.1 实锤链，防再犯）**：内核 `SecurityGuard.assertPathAllowed` 对**白名单正常放行也 emit `path-allow`**（`src/security/pathGuard.ts`），宿主 `guard.onAudit` 回调对 total **无条件 +1**（`chatPanel.ts bindSecurityAudit`）⇒ AI 真实编码每轮读文件 ⇒ total 每轮必涨，与 llmCallCount **同病**；开 `showMetrics` 真机照样每轮弹。v3 变异测试漏网原因：构造的审计数没逐轮增长。**发现时机也留痕**：准备真机验收提示词、顺触发链 grep「什么操作产生 audit」时捞出——静态测试全绿仍须沿真实调用链复核。
  **变异验证**：把 `llmCallCount` 纳入信号 ⇒ **2 条红**；信号 audit 退回 total ⇒ **审计守卫 1 条红**（红在「path-allow 累计后不得重弹」断言）；v1 旧判据形态由「同信号不重显/新活动唤起」等用例间接兜住。**测试**：「P4 补审 A」**7 条**；`chatView.test.ts` 全文件 **358 passed**；宿主全量 **1011 passed / 2 skipped**。**未变的东西**：指标块仍正常展示 total（仪表盘读数职责不变，只是不入信号），首推 metrics 仍显形（既有早期断言保持）。完整推导见 `docs/方案-提示UI两分收敛-20261005.md` §九教训 10。

  **⚠️ 余留**：jsdom 证不了计算样式，本条曾需真机复验。**✅ 真机已过（2026-10-05，扩展开发宿主打开 `Desktop\小说项目`）**：①展开不消失 ③info 条 2500ms 撤后展开中详情存活 ④文件改动条+后台 ping 条同屏 `+N` 浮层显隐正确（待发送队列激活时 background 被收纳入浮层=优先级设计行为）；②纯计数/正常 path-allow 累计不重弹（v3.1 生效）。denied 真机触发被模型安全对齐挡住（模型直接拒绝读 win.ini、未发起工具调用 ⇒ 无 path-deny 事件），该路径由变异守卫覆盖，不阻塞验收。契约文档见 `docs/方案-底部状态条收纳-20261001.md` §三。
