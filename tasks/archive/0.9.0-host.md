  **用户两问（原话意）**：①「用户无法自定义语言了，加个设置项：自动跟随 vscode，也支持手动指定；而且这项是给 LLM 看的，能不能直接打字，比如『日语』」；②「或者干脆取消强制设定？主流是不是用户输入中文就中文、输入英文就英文，自动适配才是最佳答案」。
  **拍板：不取消，改成两级语义 + 可覆盖**。① **软默认**（默认路径）：界面语言只作锚点，指令同时写「若用户本轮用其他语言提问则跟随」——只靠模型自己猜不可靠（本仓 system prompt 的角色包 / 工具描述 / UI 消息整体中文，`ok`、贴一段英文报错、只给路径这类「没表态」输入会被拉回中文）；只写「请用 X 回答」又会把用户主动改用英文的提问拽回 X（=「被强制」感的来源）。② **硬指定**：`memora.answerLanguage` 自由文本（默认空 = 不覆盖；`auto` 同义），填了即优先于界面语言且不再让位。
  **自由文本 vs 枚举**：语言是开放集合，枚举每加一种都要改代码 + 翻标签 + 补测试，与「未来加语言只改一处」相反 ⇒ 选自由文本。代价如实记：无语法校验、拼错只能靠模型理解兜；缓解 = 设置描述给示例 + `maxLength: 60` 防长文本灌 prompt + 判定层折叠空白（换行可伪造段落标题，属结构注入面）。
  **ADR-042 边界**：`memora.answerLanguage` **不是** UI 语言开关（不改任何界面文案，UI 真源仍唯一 = 显示语言）；ADR-042 决策 1 的「不做 `memora.language`」已写明区分，manifest 守卫改为允许表且**仅此一项**放行（其余 language / locale 键仍红）。
  **实现**：判定唯一在 `responseLanguage.ts`（软默认表 + 让位条款 + 覆盖清洗）；`answerLanguageConfig.ts` 唯一读取点 + 装配参数；`environmentProvider` 改为**每次 `getEnvironment()` 现算**指令（内核每轮重建前缀时现读 ⇒ 改设置下一轮即生效，不重启 / 不重装配）；`extension.ts` 净增 0 行（行数闸门 1000/1000）。
