## 二、风格统一缺口（SSOT 视角）

### F1 🔴 动画/过渡时长无统一源（且我刚引入 dock 动画是违规源）
- **evidence**：
  - tokens.ts:176 `--trae-duration-fast: 120ms; /* 全库唯一动画时长源 */`
  - chatStyles.ts:187/190 dock 动画 `200ms`/`220ms` 裸值（**我本轮所加**）
  - 过渡裸时长遍布：977/1016/1041/1092/1122/1145 `transition: …0.12s`、276/322/389/610/1236/1398/1545/1594 `0.15s`、1682 `width .3s`、settingsStyles.ts:293/297 `transition: .2s`
  - **反例对照**：chatStyles.ts:1362 `.team-meeting-icon` 正确写了 `var(--trae-duration-fast, 120ms)`
- **conclusion**：注释自称「唯一源」与实际矛盾。dock 动画没用 token = 自我回归。
  建议：保留 `--trae-duration-fast`（统一所有 hover/即时过渡），新增
  `--dur-open: 200ms`、`--dur-open-delay: 40ms` 两个令牌专用于展开，dock 动画改引用；
  所有 `0.12s/0.15s` 过渡统一引用 `--trae-duration-fast`（数值等价，写法归一）。

### F2 🟡（可见，1px 错位）常驻条家族按钮裸 `border-radius:3px` vs 条身 token `2px`
- **evidence**：chatStyles.ts:1009/1035/1117/1139 裸 `border-radius:3px`
  （pending-queue-bar__item-del / __clear / background-tasks-bar__kill / __dismiss）；
  条身 `.pending-queue-bar:923`/`.background-tasks-bar:1062` 用 `var(--radius-sm,3px)` → 解析到 token 值 2px；
  同区域 `.team-meeting-icon:1360`/`.polish-btn-icon:1395` `var(--radius-sm,4px)` 也解析 2px。
  rolesStyles.ts:69/122 同样裸 `3px`。
- **conclusion**：裸 `3px` 不解析 token → 与全库 `2px` 可见 1px 不齐。改 `var(--radius-sm,2px)`。

### F3 🟡 胶囊/徽章圆角裸 `999px`（且两 pill 令牌冗余）
- **evidence**：chatStyles.ts:415/944/1080/1804 裸 `border-radius:999px`
  （msg-user-more、pending-queue-bar__badge、background-tasks-bar__badge、pending-wait）；
  tokens.ts:30 `--radius-pill:999px` 与 :166 `--radius-full: var(--radius-pill,999px)` **完全同值重复**。
- **conclusion**：裸值改 `var(--radius-pill,999px)`；合并 `--radius-full`→`--radius-pill`（消除重复 SSOT）。

### F4 🟡 裸 `font-size:12px`（常驻条三兄弟）
- **evidence**：chatStyles.ts:877/924/1063 裸 `font-size:12px`
  （file-changes-bar / pending-queue-bar / background-tasks-bar）——三者是最该统一的「同构组件」。
  token 有 `--font-md:12px`。
- **conclusion**：改 `var(--font-md,12px)`。

### F5 🟡（低可见度，SSOT 卫生债）同 token fallback 字面量漂移
- **evidence**：`--radius-sm` token=2px，但 fallback 出现 4px(226/249/1360/1395)、3px(454/500/572/923/976/1062/1091)；
  `--accent` fallback 有 #0e639c(多数)/#4fc1ff(350/353)/#4c8dff(325)；
  `--text-secondary` fallback 有 #9aa0a6/#b0b0b0(954)/#cccccc(1085)。
- **conclusion**：正常 VS Code 主题下 fallback 不触发（var 解析 token），**视觉无差异**；
  但违反 tokens.ts 注释「引用即契约、fallback 须与定义一致」。机械统一 fallback 字面量到 token 定义值即可（低风险）。

## 三、视觉体验打磨（复用 dock 修复思路）

### P1 🟡（高，复用主线范式）输入框上方 4 条常驻条无统一收起/展开
- **evidence**：输入框上方有 4 类常驻条——status-dock chip（**已做**小气泡+左展）、
  pending-queue-bar(915)、background-tasks-bar(1051)、file-changes-bar(869)。
  后三者仍是**全宽常驻条**，无 dock chip 那种「收起=左侧小气泡/细条 + 点击左展」体验；
  且 pending/background 条 items>0 即显示、**占整排**——与用户最初抱怨的 dock chip「出现后一直碍事」同构。
- **conclusion**：把 dock chip 已验证的「收起态小气泡 / 展开从左扩展」纯 CSS 范式
  **直接迁移**到 pending/background/file-changes 三条。这是零 JS、已上线验证的成熟方案，
  可一次性消除「输入框上方常驻条拥挤」整类体验债。建议作下一迭代统一推进。

### P2 🟡 常驻条家族缺进场动画
- **evidence**：dock 有 dockChipOpen/dockPanelOpen（左展），pending/background/file 条出现即跳变。
- **conclusion**：随 P1 一并加左展 keyframes（复用已验证范式）。

### P3 🟡（真实可读性问题）暗色 `--surface-code: rgba(0,0,0,0.08)` 过浅
- **evidence**：tokens.ts:107 `--surface-code: var(--vscode-widget-shadow, rgba(0,0,0,0.08))`；
  chatStyles.ts:742/747/763 代码块底/行内代码/表头底用此值。
  在 #1e1e1e 暗背景上黑 8% 几乎不可见 → 暗色下代码块与正文背景无区分。
- **conclusion**：暗色体验缺陷。建议改为浅提亮 `rgba(255,255,255,0.04)` 或跟随
  `--vscode-editorWidget-background`，保证暗/亮均可辨。

### P4 🟢（低）圆点/徽章尺寸无令牌化
- **evidence**：呼吸点/状态点尺寸散落：5px(1792/1810/1836/2004)、6px(122/1344)、8px(147)、徽章 16px(936/1072)，无 `--dot-*` 令牌。
- **conclusion**：建议增设 `--dot-sm/md` 统一圆点尺寸，消除「圆点大小看心情」。

### P5 ✅（已核实 NON-issue）reduced-motion 无障碍
- **evidence**：chatStyles.ts:2178-2184 全局 `@media (prefers-reduced-motion){
  *,*::before,*::after{animation-duration:0.01ms!important; …}}` 兜底层，
  覆盖 spin(1410)/selfReviewPulse(699/1796/1812/1838/2006)/dock(192) 全部。
- **conclusion**：覆盖充分，局部守卫（701/1814/1840 等）冗余但无害。**不列为缺口**（避免过度申报）。
