## 0.13.1 补丁发版（2026-11-25 · 补齐 Marketplace 通道）

> **0.13.0 三个出口的实际落态（全程只读核验）**：GitHub Release ✅（`api.github.com/.../releases/tags/vscode@0.13.0` 返回 asset `memora-vscode-0.13.0.vsix`，`size=3053677`）；Open VSX ✅（`open-vsx.org/api/zooique/memora-vscode` 返回 `version=0.13.0`，反证请求 `0.9.9` 返回 404 ⇒ 端点按版本真实应答）；VS Marketplace ❌（run `45593091319` step 21「发布到 VS Code Marketplace」`failure`，step 1–20 全 `success`）。

- **VSIX-PATH-COLLAPSE-1** — vsix 中文路径塌缩冲突致 Marketplace 拒包（0.13.0 发版现场定位，0.13.1 修复）
  **根因（实证）**：0.13.0 的 vsix 同时含 `role-packs/共鸣小说家` 与 `role-packs/匠码工程师` 两个各 5 个中文字的目录（UTF-8 各 15 字节）。Marketplace 服务端解析条目路径时按单字节编码解读，非 ASCII 逐字节变成 `?`，两者塌缩为同一个键，服务端抛 `An item with the same key has already been added` 拒绝整包。
  **证据链**：① CI step 21 日志原文报错键 = `extension/dist/extension/role-packs/???????????????/rules.md`（15 个 `?`）；② 下载 Release 该 vsix（3053677 字节）用 .NET 读得 **407 个文件条目**，按「非 ASCII 字节 → `?`」模拟后得 **3 组冲突**，分别是 `rules.md` / `persona.md` / `manifest.json`，两组文件恰为 `匠码工程师` 与 `共鸣小说家`；③ 新增守卫 `hosts/memora-vscode/scripts/verify-vsix-paths.mjs` 对同构样本复现出**逐字相同**的塌缩键并 exit 1。**本地 .NET `ExtractToDirectory` 与本地 `vsce package` 均不报错**（本机 .NET 正确解码 UTF-8 标志位）⇒ 该故障只在 Marketplace 服务端暴露，这是它躲过两轮本地预检的原因。
  **为什么 0.12.0 能过**：`匠码工程师` 由提交 `20cf50be`（2026-11-25）新增，是 `vscode@0.12.0..vscode@0.13.0` 区间内唯一新增的 5 字中文目录；0.12.0 时只有 `共鸣小说家` 一个，不构成碰撞。
  **处置**：`role-packs/匠码工程师` → `role-packs/jiangma-engineer`（`manifest.json` 的 `name: 匠码工程师` 仍是权威身份，角色显示名与已装载状态不变；全库无代码硬编码该目录名，`git grep` 实证）。`memora助手` / `memora宝` 被 `BUILTIN_FALLBACK_PACK` / `ASSISTANT_ROLE_PACK` 及多处测试以路径形式硬编码，且当前不撞车，**保持原名不动**。新增打包期守卫挂在 `npm run package` 末尾（CI step 16 与本地同源），复现同一塌缩判据，撞车即红，把这类故障从「发版时」前移到「打包时」。
  **为何必须升 0.13.1 而非重发 0.13.0**：Open VSX 的 `0.13.0` 已发布且同版本不可重发（删除后版本号仍保留），重打 `vscode@0.13.0` tag 会让流水线必红在 Open VSX 那一步；Marketplace 侧 0.13.0 虽未占用，但修补后重打的 vsix 来自新 commit，若仍叫 0.13.0 则「tag 所指 commit」与「实际上传产物」不对应，可追溯性断裂。
  **不采用方案**：手动上传现有 0.13.0 vsix——冲突在包内部，任何上传通道（网页 / CLI / PAT）都过同一个服务端解析器，必报同一错误。
