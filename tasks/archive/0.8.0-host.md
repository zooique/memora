### 首推 `vscode@0.8.0` 后的 CI 阻断与订正（2026-11-08）

- **现象（实测）**：tag `vscode@0.8.0` → commit `b7cfd389` 推送后，`host-release.yml`（ubuntu）在宿主测试步红，2 条失败：
  1. `codeExecutor.test.ts` → 「TOOL-ABORT-KILL-1：中断 → 终止真实子进程树…」断言 `expect(r.terminationError).toBeUndefined()` 失败，实收 `进程组强杀失败（kill ESRCH），已降级为只杀直接子进程`；
  2. `sessionLockAcceptance.test.ts` → 「② 强杀持锁进程：新进程拿锁耗时 ≤2s」在 20s 测试上限被切断。
  同刻 Open VSX 实查仍为 `0.7.0`（06:44–06:54 连续 20 次 + 23:12Z 复验）⇒ **发布步未执行，0.8.0 未被市场占用**，tag 可删重打。
- **根因（同根：POSIX 上未杀进程组 / 树；实测 + 静态取证）**：
  1. 宿主 `codeExecutor.ts` 的 `spawn` 缺 POSIX `detached` ⇒ 子进程 `pgid ≠ pid` ⇒ `killProcessTree` 的 `process.kill(-pid)` 打到一个**从未存在**的组 ⇒ 每次 ESRCH。**反证**：该用例脚本是 `setTimeout(..., 3000)`、abort 在 1s，进程在 1s 时必定存活 ⇒ 排除「组已消失」的竞态解释。内核 `buildSpawnOptions` 早已在 POSIX 加 `detached: true`（同类实现两处漂移）。
  2. 测试夹具 `spawnLockChild` 的 `spawn` 同样缺 `detached`，且强杀只给**单 pid**（Windows 分支连 `/T` 都没有）⇒ POSIX 上杀死 tsx 主进程后，tsx 经 `cross-spawn` 派生的孙 node 成孤儿并继承 stdout pipe ⇒ `close` 不触发 ⇒ 无超时的 `await holder.done` 挂到 20s。**排除「锁没释放」**：`waitForLine('ACQUIRED', 10_000)` 自带 10s 超时，锁未释放会在 10s 先 reject，不会拖到 20s；`waitForLine('LOCKED')` 有 15s 超时且显然已拿到，否则报错文案会是「等不到 LOCKED」。
- **处置（不加大超时、不放松断言）**：① `codeExecutor.ts` 补 `...(process.platform === 'win32' ? {} : { detached: true })`；② 夹具 `spawnLockChild` 补同款 `detached`，POSIX 强杀改 `kill(-pid)`（组不存在时降级单杀），Windows 强杀补 `/T`；③ 新增静态守卫用例「POSIX 分支必须 detached 自成进程组」（本机 Windows 也能跑，防误删后只有 ubuntu CI 才红）。
- **验证（实测）**：两个定向文件各连跑 3 次全绿（`codeExecutor` 8/8，9.3–12s；`sessionLockAcceptance` 7/7，11.2–12s；② 单用例 2.1–2.2s）；完整宿主套件 `164` 文件 / `2606` passed / `0` failed / `4` skipped（322.4s，exit 0；比改动前 +1 用例 = 新增守卫）；根 `format:check`、宿主 `typecheck` / `lint` 均 exit 0。
- **未做 · 需内核 6.0.1**：把 POSIX `ESRCH` 归类为「已消失」（`alreadyExited: true` 且 `error` 留空）。语义成立（组不存在 ⇒ 组内无进程），但该判定在**内核** `killProcessTree` 里；内核 6.0.0 已发 npm，此刻改 `src/` 会让宿主内联代次与 npm 上 6.0.0 分叉（「随包内核代次 = 6.0.0」将失真）⇒ 不在本版夹带，另行登记。
- **取证局限（如实）**：本机为 Windows，两条失败**本地 0 复现**（均走 `taskkill` 分支）；「修复有效」的依据 = 上述静态根因 + 反证 + §Step 6 的市场产物取证链（上架 vsix 由全新 checkout 构建且包内 changelog 含本条修复说明）。
