## 模块 2 · 记忆·摘要·召回链（`src/memory/` + roundSummaryGenerator · 2026-08-21 审查）

> 审查范围：recall / hybridMerge / reranker / roundSummaryGenerator / governance / contextPreparer.recallAndInject / memoryInspector / memoryAdvisor / memoryDecayScheduler。359 测试全绿。

### 2-1 【已修复·2026-08-21】MemoryDecayScheduler 周期性空转

- **位置**：[memoryDecayScheduler.ts](../src/agent/managers/memoryDecayScheduler.ts#L118) `start()` 空源挂起 + [runOnce()](../src/agent/managers/memoryDecayScheduler.ts#L164) 空源短路
- **说明**：`GOVERNANCE_SOURCES = []`（[governance.ts](../src/memory/governance.ts#L9)）下，`runOnce()` → `decayScores([])` 无对象可衰减，但定时器仍周期性触发、仍发射 `decayCompleted` 事件 + 记录 span + 累加指标。**与已摘除的 guardrail 空转链同模式**（零治理对象 + 保留机制空转）
- **修复**：采纳方案 ②——`start()` 治理源为空时不注册周期 timer（挂起，保留手动 runOnce 能力）；`runOnce()` 空源短路（不发射事件/不记 span/不累指标）。测试显式注入非空 sources，契约不受影响

### 2-2 【已修复·2026-08-21】score 衰减对当前唯一记忆类型 round-summary 不生效

- **位置**：[memory-as-summary.md §4.2](../docs/architecture/memory-as-summary.md) 承诺「score 衰减：久不访问的记忆分数沉底」；实现上 [governance.ts](../src/memory/governance.ts) 治理源为空 → round-summary 不参与 decayScores
- **说明**：当前 round-summary 的 score 只涨不跌（recall 命中 boost +0.05 至顶格 1.0），「自然遗忘」实际只剩 superseded 取代在起作用。影响轻微（hybridMerge 中 vectorScore 占 0.6 主导排序），但文档承诺与实际行为有落差
- **修复**：不将 round-summary 纳入衰减（摘要是事实记录、无"过时"语义，且会引入周期性 LLM 评估成本）；改为文档诚实声明——§4.2 补充「当前形态：round-summary 不参与时间衰减，score 由召回 boost 驱动，治理源回归时恢复」

### 2-3 【观察】MemoryInspector / MemoryAdvisor 是宿主管理面，内核闭环不消费

- **位置**：[memoryInspector.ts](../src/agent/managers/memoryInspector.ts#L128) 19 个方法经 `agent.memory` getter 暴露；[builtinToolHandlers.ts](../src/agent/builtinToolHandlers.ts#L656) `search_memories` 直接用 `memoryIndex.search()`，不经 MemoryInspector
- **说明**：内置工具与内核闭环不消费 MemoryInspector 的 search/searchHybrid；MemoryAdvisor.detectConflicts 当前治理源为空返回空报告。均属宿主按需诊断接口，非周期空转，但需确认 searchHybrid（混合搜索）是否仍有宿主消费者，无则考虑收敛
- **建议**：仅记录，模块 9（managers 专项）时集中核查消费面

### 2-4 【观察·注释与实现出入】supersede 候选扫描实际仍为全库 O(n)

- **位置**：[roundSummaryGenerator.ts](../src/agent/managers/roundSummaryGenerator.ts#L188-L199) `getSessionCandidates` 用 `getBySource(ROUND_SUMMARY)` 全量拉取再 filter 同 session 再 slice 20
- **说明**：注释称「避免全库 O(n) 遍历」，但 `getBySource` 本身是 O(n) 全库扫描，仅是取代判定收敛到 20 条候选。内存实现下影响可忽略，但注释表述有夸大；宿主 SQLite 实现可考虑按 session 前缀查询优化
- **建议**：仅记录，注释措辞可后续校准

## 模块 4 · 工具执行与安全（toolExecutor / toolRunner / builtinTools / pathGuard · 2026-08-21 审查）

> 审查范围：toolExecutor（注册/分发/参数校验/外部工具注入防御）、toolRunner（三重闸门 + 中断竞争）、builtinTools（声明 + 幂等契约 SSOT）、pathGuard（路径白名单 + 写入确认）。281 测试全绿。**发现一处策略断链（4-1）**。

### 4-1 【已修复·2026-08-21】只读闸 toolReadonly 静默失效（builtinTools 未注入）

- **位置**：[toolRunner.ts](../src/agent/toolRunner.ts#L118-L128) 只读闸 `this.deps.builtinTools?.find(...)` 依赖注入；但 [assembler.ts](../src/agent/assembler.ts#L470) 构造 AgentLoop 时**未传 `builtinTools`**（loop.ts L250 直接透传、无默认值）→ `deps.builtinTools = undefined` → 只读闸恒不触发
- **说明**：`toolReadonly` 的运行时消费点仅 ToolRunner 一处（grep 实证）。角色包声明 `act.toolReadonly='readonly'` 后，**内核不阻止 write_file 等写操作**（仅能依赖宿主 preExecutionCheck 兜底）——策略声明与执行载体断链，违反「策略是枚举、检查是载体」设计纪律
- **修复**：① [toolExecutor.ts](../src/agent/toolExecutor.ts#L388) 新增 `builtinDefinitions` getter（全量内置含条件工具，工具定义单一真理源）；② [assembler.ts](../src/agent/assembler.ts#L477) 装配 AgentLoop 时注入 `builtinTools: toolExec.builtinDefinitions` 闭合断链；③ 补 toolRunner 集成测试（readonly 放行 web_search/web_fetch/read_file、阻止 run_code/write_file）+ toolExecutor builtinDefinitions 断言。126 测试全绿 + tsc 通过

### 4-2 【已修复·2026-08-21】WEB_SEARCH_TOOL 未标 readonly

- **位置**：[builtinTools.ts](../src/agent/builtinTools.ts#L124) WEB_SEARCH_TOOL 无 `readonly: true`（web_fetch 有，run_code 无）
- **说明**：web_search 是读操作但未标记。修复 4-1 后若把含 WEB_SEARCH_TOOL 的列表注入 builtinTools，readonly 模式会**误拦** web_search；若只注入 BUILTIN_TOOLS（不含条件工具）则无此问题
- **修复**：给 WEB_SEARCH_TOOL 补 `readonly: true`（与 web_fetch / search_memories 对齐），随 4-1 一并落地

### 4-3 【观察·设计边界】readonly 模式不覆盖条件工具与自定义工具

- **位置**：[toolRunner.ts](../src/agent/toolRunner.ts#L120) 只读闸只查 `builtinTools` 数组
- **说明**：run_code（执行任意代码，有写文件副作用）、run_skill_script、宿主自定义工具均不在只读闸查询范围——readonly 模式对它们无内核级保护，仅靠宿主 preExecutionCheck
- **建议**：仅记录。若需严格覆盖，readonly 语义应扩展到"非内置只读工具一律拒绝"，或由宿主钩子承担；当前依赖宿主属设计边界
