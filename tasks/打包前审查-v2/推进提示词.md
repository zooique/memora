## 使用指南

### 执行顺序

推荐按 A→B→C→D→E→F 顺序执行，但各批次之间无硬依赖，可并行推进。

### 每批执行流程

1. **新对话**：复制对应批次的触发提示词
2. **问诊确认**：AI 先读取 tasks/待完成任务.md 对应章节，确认任务清单
3. **执行修复**：按斩木除根 → typecheck → 测试 流程
4. **更新文档**：修复完成后更新 tasks/待完成任务.md 和 tasks/已完成任务.md
5. **提交推送**：`fix(sprite): ...` 格式，每项独立 commit

### 不宜并行推进的批次

- 批次 C 和 D 都涉及 directory-structure.md，建议顺序执行避免冲突
- 批次 A 涉及内核改动，可能影响精灵测试，建议先执行

### 可延后的批次

以下批次建议 next 版本迭代时再处理，不阻塞当前版本：

| 批次/类别 | 原因 |
|----------|------|
| Step 3 P2 修改痕迹注释（14 项） | 纯文档/注释清理，无功能影响 |
| Step 3 P2 裸 catch 补日志（4 项） | 低风险，可随自然生长触发 |
| Step 5 P3 观察项（3 项） | 已归档，等触发条件 |
| Step 7 P2 观察项（4 项） | 已归档，等自然生长触发 |
