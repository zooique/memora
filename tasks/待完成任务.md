### 记忆衰减机制完善

> 来源：2026-08-23 内核质量评审（对比 LangChain 1.0、Letta/OpenClaw 生产级记忆体系）。

- **问题**：非 round-summary 记忆无衰减机制，score 只涨不跌（recall 命中 boost +0.05 至顶格 1.0）；round-summary 不参与时间衰减（已文档化）；长期运行记忆库将持续膨胀。
- **设计约束**：遵循「单一真理源 + 自然生长」——扩展既有 `memory/governance.ts` + `memoryDecayScheduler` 机制，不新建独立衰减系统；round-summary 保持不衰减（事实记录语义）。
- **实施范围**：
  1. 为非 round-summary 记忆引入指数衰减（30 天半衰期）
  2. 衰减仅降分不删除（score 低于阈值时自然沉底）
  3. 定期（DECAY_INTERVAL_MS）执行，治理源为空时短路
- **验证要求**：衰减回归测试 + 衰减后 recall 排序正确性 + 治理源为空时短路不发射事件

### H2 · 8 个 Agent 事件消费（已核实）

> 代码证据：内核 `AGENT_EVENTS` 定义 26 事件，宿主 `bindAgentNoticeEvents()` 绑定 13 个 + `runFlow()` 内绑定 3 个（questionPending/memoryRecalled/memoryAdded），共 16 个。差集中 8 个事件经核实有实际 emit 路径。

- **动作**：在 `chatPanel.ts` 的 `bindAgentNoticeEvents()` 中补充以下事件监听：
  1. `sessionForked` → 分叉成功后自动切换到新分支 + 推送 `session_title` 更新
  2. `dedupCompleted` → 工具卡片区域提示「已自动优化 N 次重复调用」
  3. `inputTooLarge` → 提示条展示 `hint`（如「建议用 read_file 分段读取」）
  4. `needClarify` → 与 `questionPending` 共享暂停/恢复机制，渲染澄清问题
  5. `goalDriftDetected` → 提示条展示「检测到目标偏移，是否调整方向」+ 确认/忽略按钮

  7. `sessionResumed` → 对话恢复确认反馈
  8. `sessionRecovered` → 对话自动恢复提示
- **验收**：每个事件有对应的 UI 反馈，不静默
- **优先级分层**：

### H3 · Loop handoff wait/end 反馈（已核实）

> 代码证据：[chatPanel.ts:1401-1418](../hosts/memora-vscode/src/webview/panels/chatPanel.ts#L1401) 中 `handoff` chunk 处理仅覆盖 `decision==='loop'` 分支，`wait` 和 `end` 分支静默忽略。

- **内核能力**：handoff chunk 携带三种决策
  - `wait`：Agent 主动等待用户输入（槽位未补全）
  - `loop`：自动续跑（当前唯一处理的分支）
  - `end`：任务完成，终止循环
- **宿主现状**：仅 `loop` 有反馈（loop_count + notice），`wait`/`end` 无特殊提示
- **动作**：
  1. `wait` 决策：展示「Agent 正在等待你的输入」引导提示
  2. `end` 决策：展示「Agent 已完成当前任务」标识 + 自动重置 loop 计数
- **验收**：handoff 三决策均有明确 UI 反馈
