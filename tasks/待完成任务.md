## 设计纪律（防止重复犯错）

> 任何新任务评估必须逐条对照，违反的直接归档「不推进」。

### D1 · 记忆质量 = 内核自动机制，不是用户功能

衰减 / 去重 / 冲突检测 / 时效性评估是内核自主后台机制，用户不需要看/手动触发。禁止暴露为按钮/诊断面板。

### D2 · 用户记忆视图 = 陈述级，不是诊断级

只暴露「记住了什么 + 删除/编辑」。source health / 衰减曲线是 vanity
metric，禁止进用户设置页。

### D3 · 透明性已由明文 JSON 满足

`.memora/memories.json` 明文格式化即透明，无需额外透明面板。

### D4 · 宿主生长缺口 ≠ 用户功能缺口

内核 API 存在 ≠ 宿主必须消费。只消费有明确用户场景的；内部机制 API 不暴露。

### D5 · 安全分级决策必须显式

preExecutionCheck 恒放行属单用户场景可接受，但必须显式标注，未来多用户/服务端再接入真实策略。

### D6 · 触发驱动 > 观察驱动（2026-09-10 补）

有真实用户反馈 / 真实场景触发的才立项；「可能有用」的对称性增强、预留扩展点一律暂缓。**预支复杂度 = 负收益**。
