## 设计纪律（防止重复犯错）

> 任何新任务评估必须逐条对照，违反的直接归档「不推进」。

### D1 · 记忆质量 = 内核自动机制，不是用户功能

衰减 / 去重 / 冲突检测 / 时效性评估是内核自主后台机制，用户不需要看/手动触发。禁止暴露为按钮/诊断面板。

### D2 · 用户记忆视图 = 陈述级，不是诊断级

只暴露「记住了什么 + 删除/编辑」。source health / 衰减曲线是 vanity metric，禁止进用户设置页。

### D3 · 透明性已由明文 JSON 满足

`.memora/memories.json` 明文格式化即透明，无需额外透明面板。

### D4 · 宿主生长缺口 ≠ 用户功能缺口

内核 API 存在 ≠ 宿主必须消费。只消费有明确用户场景的；内部机制 API 不暴露。

### D5 · 安全分级决策必须显式

preExecutionCheck 恒放行属单用户场景可接受，但必须显式标注，未来多用户/服务端再接入真实策略。

## 内核契约演进 · 待拍板（2026-09-01 立项）

> 来源：2026-09-01 角色包实时占用落地后，对抗式审查 `parseSessionId`「脆弱的正确」隐患。
> 结论（2026-09-01 对抗式评审修正）：`parseSessionId` 在 vscode 宿主**非冗余、是必要适配层**——宿主持有的原子 `sessionId`
> 必须拆成 `(date, session)` 才能调内核 `ISessionStore.loadMessages(date, session)` 契约；
> 拆是内核接口强制、非宿主私有格式。**但脆弱点真根治在**内核接口层，属跨三端契约演进，须单独立项。
>
> **评审定论（2026-09-01 内核契约评估，维持挂起）**：K-1 非「去债净减」而是「拆装互换」——改 `loadMessages` 收 `sessionId`
> 确能消除 vscode `parseSessionId` + 内核 `sessionManager` 的正则拆分，但内核 `MessageHistory` 全局以
> `currentDate/currentSession` **双字段为一等状态**（直接持有，非派生），届时反而要反过来拼
> `${date}-${session}` 成原子串再传。「拆的负担」换「拼的负担」，未根除、仅换方向。
> 真正净减须把 `sessionId` 定为唯一真理源、`date/session` 变派生字段——需重构 `MessageHistory` 字段模型，
> 且与跨日重置（`date` 独立存在即为此）、按日归档逻辑纠缠，属**架构级改造**，非清理任务。
> **结论：方向存疑，当前风险零，维持挂起，勿当小债重启。**

| ------- | ----------------------------------------------------------------------------------------- | ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| **K-1** | **`ISessionStore.loadMessages`** **改为收** **`sessionId`（消除** **`(date, session)`** **双参）** | 架构级改造 | 内核 `src/memory/sessionStore.ts:14` 公共契约；当前被内核 messageHistory/sessionManager/sessionArchiver/builtinToolHandlers + sprite 宿主 sessionRoutes/sessionHandlers + vscode 宿主 多端数十处消费。改后宿主不再需要 `parseSessionId` 拆 `sessionId`→`(date,session)` 适配层，根除「日期固定 10 位」隐式格式契约脆弱点；但内核 `MessageHistory` 双字段为一等状态，须重构字段模型（sessionId 升唯一真理源）+ 跨日 reset/按日归档逻辑 + 三端 deprecation 周期 + 测试全绿。**并非去债净减（拆装互换），架构级改造**，须单独规划批次 | ⏳ 维持挂起（方向存疑，当前功能正确零风险） |

### P2/P3 评估结论（2026-08-31，SSOT 实证）

| P2 相关性排序 | 观察      | search\_project 是定位工具（命中后 read\_file 精读），目录序不构成答案偏差；VSCode 原生全局搜索亦不排序；引入打分机制超出"搜索→定位→精读"最小单元，属 D4 宿主生长缺口 ≠ 用户功能缺口 | LLM 因命中过多、分不清相关性而精读过多文件的真实反馈        |
