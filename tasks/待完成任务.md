### 演进方向 · skills 工具化按需加载（渐进披露，对齐 Agent Skills 行业标准）

> **来源**：2026-08-15 设计讨论（用户"把 skills 对齐行业标准，标记指针 + LLM 按需调用"）。**记录为演进方向，当前不动代码**——memora 处于草案演进期（v1 字段冻结延后），先记录设计意图与现状对齐。

**现状（诚实缺口）**：角色包 `manifest.skills` 的 `file` 指针当前**不装载正文**，内核仅消费 `capability`（映射工具白名单）。`file` 是生态兼容指针，非实装载入口。

**演进目标（对齐 Agent Skills 渐进披露）**：
1. **L1 元数据常驻**：`manifest.skills` 的 name + description 暴露给 LLM（一行一个，省 token），复用 `RolePackCapability` 已有数据；
2. **L2 按需装载**：新增 `read_skill` 内核工具，LLM 传入技能名，工具读 `file` 指向的 `skills/*.md` 正文返回——复用 `SkillManager` 装载，不重复造轮子；
3. **职责分离**：`capability` 决定工具白名单，`file` 决定 read_skill 装载路径，`name+description` 是 L1 常驻元数据。

**设计要点**：`file` 指针是"可装载入口"（read_skill 路径），非纯标记——这正是文件夹包（含 skills/*.md 实体）存在的必要性，单文件无法承载"可被工具按需读取的正文"。

**落地前置**：评估与现有 `matchAndInjectSkill`（预匹配注入）的共存/替换策略；对齐 Agent Plugins 骨架（plugin.json + skills/ + mcp.json）。
