## TL;DR

**把运行时输入（ask 问答 `question-answer` / 主动补全 `supplement` / 超时未答 `timeout`）从「消息流平铺 + 事后搬家」双渲染体系，SSOT 收敛为任务折叠块（round-block）/ 运行时过程容器（process-flow）内的过程条目**：与 thought/tool/narrate **同一数据源投影、同一 ts 排序、同一插入通道**。

**统一模型（用户定案）**：step = LLM + 用户 的**混合产物流**——LLM 发送的 step 内容与用户运行时输入**本质同构，仅生产者不同**。补充就是 step 结束间隙插入的内容，渲染时挂在**刚结束的 step 分组末尾**。

**形态（用户拍板）**：**形态甲** —— 运行时 QA **实时插入 process-flow 的 step 分组内**（即时可见硬约束），finalize 由合并流全量重建自然归位（无搬家、无飘忽）。代码已确认 process-flow 含 step 分组结构，形态甲可行。

**删干净**：`.msg-qa` 折叠块 / `.msg-qa--ask` 回顾行 / `moveQaIntoRoundBlock` / `foldPendingQaIntoRoundBlock` / `refreshRoundBlockQaStats` 成对携带与归属过滤。**不改协议、不改落盘、零新增字段。**

## 一、背景与根因（引用设计文档，一句话）

- 运行时 QA 通过 `appendInteractiveInput` → `appendInlineInputRow` 渲染 `.msg-qa` 折叠块插**消息流**（`resolveInteractionAnchor` 之后），round-block 已 finalize（重放）时 `moveQaIntoRoundBlock` **搬运**折入 `[实锤] chatView.ts:2434-2466, 2474-2559`
- 搬运用 `detailsBody.appendChild(el)` **恒追加末尾**，与 finalize 全量重建（`renderRoundBlock(finalize=true)`）时序交错 → 顶部/底部飘忽 `[实锤]`
- 本质：QA 是与 round-block **平行的第二套渲染体系**（运行时平铺 + 事后搬家 + 成对携带 + 收起计数 + 归属过滤），过程条目排序无单一真源

## 二、定案：统一模型 + 形态甲

### 2.1 统一模型（用户定案）

- **step 是时间窗口**：一次 `step_boundary` 到下一次之间发生的一切（LLM 产出的 thought/tool/narrate + 用户注入的运行时输入）都是该 step 的过程记录。
- **产物条目统一、来源区分**：条目 = 产物类型（thought / tool / narrate / input），来源元数据（`llm` / `user`）。LLM 发的是 step 内容，用户输入是同一流的另一来源——**本质同构，仅生产者不同**。
- **补充的定位规则**：补充发生在 step 结束后的间隙 → 渲染挂**刚结束的 step 分组末尾**（不是自成一组）。
- **落盘分源、渲染合并投影**：`processEvents`（内核事件流）与 `interactiveInputs`（用户交互记录）**各自保持真源**；合并只发生在渲染层（每类数据单真源，渲染为统一投影）。

### 2.2 形态甲（用户拍板，2026-09-17）

| 项 | 结论 |
|---|---|
| 运行时可见性 | 用户提交回答 → 宿主 post `user(kind)` → webview **立即**插入 process-flow 对应 step 分组（即时可见，硬约束） |
| 完成态位置 | finalize `renderRoundBlock` 由**同一合并流**全量重建 → QA 按 ts 自然落在正确 step 分组 → 无搬家、无飘忽 |
| 重放 | `loadRoundBasedHistory` → processEvents + interactiveInputs 合并 → 同一渲染器 → 与运行时最终态一致 |

### 2.3 形态甲可行性（代码实证）

- 运行时 process-flow **已有 step 分组结构**：`renderProcessFlow` 经 `stepContainerFor(flow, events, seq)`（seq → 最近 `step_boundary` → `.round-block__step` 折叠块；无边界回退容器顶层）+ `insertStepInOrder`（按序插入）平铺 narrate/thought/tool `[实锤] chatView.ts:962-976, 1048-1068, 1413-1516`
- **finalize/重放共用同一插入通道**：`insertStepInOrder` 注释明示「round-block（finalize/重放）内识别 .round-block__narrate / .round-block__tool——共用同一插入通道」`[实锤] chatView.ts:1049-1051`
- **ts 参数现成**：`appendInteractiveInput(text, ts, kind, roundId, question, options)` 已接收 `ts`（目前只当日期分隔线用）`[实锤] chatView.ts:2434-2440`

## 三、实施设计

### 3.1 合并过程条目流（渲染真源）

```
processItems = sortByTs([
  ...processEvents.map(toItem),      // thought / tool_start+result / narrate / step_boundary
  ...interactiveInputs.map(toItem),  // question-answer / supplement / timeout
])
```

- **排序键 = ts（统一时间键）**；同 ts 稳定序：processEvents 按 seq、interactiveInputs 按写入序。
- **step 归属 = 条目 ts vs `step_boundary` 的 ts**（非 seq）——QA 无 seq，**禁止**用「ts → 锚定最近 processEvent 的 seq」映射（那是带伤：绕一层才能接上）。
- 行上挂 `data-ts`（统一排序属性）；`seq` 仅保留为 processEvents 内部真源与去重键。
- `insertStepInOrder` 候选选择器加入 QA 条目类名（`.process-flow__input` / `.round-block__input`），比较键从 `data-seq` 改为 `data-ts`（同 ts 时 seq 为辅）。

### 3.2 渲染

- 折叠区（`.round-block__details`）与运行时（`.process-flow`）过程条目统一 `renderProcessItems`；QA 条目为 `renderQaItem`：
  - 提问回顾行（仅 question-answer/timeout 带 question 时）：`[问] 问题原文 + 候选选项`（静态文本）
  - 回答/补全/未答行：`[你答] 答案` / `[你补充] 补全文本` / `[未回答]` —— 对齐 thought/tool 行样式（非独立折叠块），tag 语义区分
- 收起态摘要：QA 计数（你答×N · 你补充×N）**从合并流统计**（替代 `refreshRoundBlockQaStats` 的 DOM 扫描）。
- **运行时即时可见**：提交回答 → `insertProcessItem(item, stepGroup)` 增量插入当前 process-flow（幂等：`data-ts` 去重）；finalize 时 `renderRoundBlock` 由合并流重建 → 已插入条目自然归位，无竞态（前提：提交即落盘，见 §5 守住点 2）。

### 3.3 删除清单（删干净，不留僵尸）

| 删除对象 | 说明 |
|---|---|
| `.msg-qa` 折叠块 + `.msg-qa--ask` 回顾行 | 渲染体系本体 |
| `moveQaIntoRoundBlock` | 搬家逻辑 |
| `foldPendingQaIntoRoundBlock` | 完成态批量折入 |
| `refreshRoundBlockQaStats` | DOM 扫描计数 |
| 成对携带 + 归属过滤逻辑 | 提问回顾行与回答块的搬运配对 |
| `chatStyles.ts` 的 `.msg-qa` 系列 CSS | 新增 QA 条目行样式对齐过程行 |

### 3.4 改动面

| 层 | 改动 |
|---|---|
| `chatView.ts` | 新增 `renderQaItem` + `processItems` 合并/排序 + `insertProcessItem(stepGroup)`；`renderProcessFlow`/`renderRoundBlock` 接入合并流；`insertStepInOrder` 比较键改 `data-ts`；删 msg-qa 体系 |

## 四、不带伤核查结论（legacy-contract-audit-rules.md 对齐）

**结论：形态甲符合不带伤原则。** 三题核查：

1. **从零设计会这样写吗？——会**。合并流统一 ts 排序 + 渲染层合并投影 = SSOT 标准形态；**唯一陷阱**：不得实现成「ts → 锚定 seq → 按 seq 归位」映射（QA 无 seq 硬映射 = 「绕一层才能接上」带伤模式），须坚持**统一时间键 ts**（设计文档 3.1 已是此口径）。
2. **去掉兼容层核心是否完整？——是**。删除整个 msg-qa 体系即完整；旧 round 的 `interactiveInputs` 数据结构不变，仅渲染形态替换 = **数据兼容**（必须）而非代码绕层。
3. **SSOT 边界外是否另开手写通道？——否**。运行时 process-flow 与 finalize round-block 共用 `insertStepInOrder`/`stepContainerFor` 同一插入通道；删除后无第二套渲染。

## 五、风险与守住点

1. **ts 时基同源（实施前验证）**：processEvents.ts 与 interactiveInputs.ts 必须同源可比（相对序正确即可）。若验证发现时基不同，需统一转换后再排序。
2. **提交即落盘**：finalize 全量重建靠合并流，QA 必须**提交即落盘**（同步写入 interactiveInputs），否则 finalize 竞态丢条目（现 moveQaIntoRoundBlock 也有此风险，实施时一并确认）。
3. **同 ts 稳定序**：毫秒精度下同 ts 碰撞（罕见）——processEvents 按 seq、interactiveInputs 按写入序，需在比较函数定义稳定序。
4. **finalize 重建衔接**：已插入 process-flow 的 QA 由 finalize 重建自然覆盖，验证无竞态（重放/完成态各跑一遍用例）。
5. **删干净**：`.msg-qa` CSS、`moveQaIntoRoundBlock`、`foldPendingQaIntoRoundBlock`、`refreshRoundBlockQaStats` 全删，不留僵尸类/僵尸导出。

**验收结果**：

- [x] 运行时输入提交（ask 回答 / 主动补全 supplement）→ **即时**显示在 process-flow 对应 step 位置（同形态，不等完成）
- [x] 完成后 round-block 内运行时输入位于正确 step 分组（顶部/底部**不飘忽**）
- [x] 重放与运行时最终态一致（question-answer / supplement / timeout 三类同形态归位）
- [x] 删除 msg-qa 双体系后全量测试绿（tsc 通过；宿主 vitest 487 通过，唯一失败为 host 集成真实 LLM 超时——外部依赖波动，非本改动引入）

**实施要点（与设计差异的落地细节）**：

1. **排序键 = ts 为主、seq 兜底**：真实数据 ts 单调 → 按 ts 排序；历史/测试数据 ts 全空串 → 回落 seq 比较（`insertStepInOrder` 同 ts 比 data-seq；`stepContainerFor` 同 ts 比 boundary.seq ≤ 条目 seq）。QA 无 seq → 同 ts 归最近 boundary，靠写入序稳定。
2. **重放跨重建快照**：重放 seg 消息触发的 `renderRoundBlock` 全量重建会清掉 step 分组内已插入 QA → 重建前快照 `.round-block__input`，重建后按 ts 重插（`existingInputs` + `renderedInputTs` 去重）。
3. **摘要计数**：收起态 QA 计数从合并流统计（快照 + interactiveInputs），**独立去重集合**（复用 renderedInputTs 会在渲染后被误跳过）。
4. **纯问答轮降级**：无过程容器时 QA 落消息流尾（用户输入恒可见纪律）。
5. **commitRoundId 回填删除**：QA 在过程容器内天然归属本轮 assistant 块，无需消息流扫描回填 roundId。

**新增测试**：形态甲位置确定性用例（QA 按 ts 归位 step 分组，防顶部/底部飘忽回归）。
