### P0-G0 模型连通性最小真实调用

- **目的**：证明当前 provider 能真实完成一次 LLM 调用（排除 402 余额不足 / 400 模型不支持）。
- **操作步骤**：
  1. 点「＋」→ 草稿页标题显示「新会话」。
  2. 输入框输入：`回答 ok`，按 Enter。
  3. 等待状态从运行中回到空闲（最多 120 秒）。
- **预期可见结果**：出现一条用户消息「回答 ok」+ 一条助手消息，助手正文含 `ok`（允许前后有标点/空白）。
- **判据**：助手气泡正文（`#messages .msg.assistant .msg-body` 的文本）包含 `ok`；对应 round 文件 `status` 为完成态。
- **失败长什么样**：出现错误气泡，正文含 `insufficient` / `余额` / `402` / `400` / `model` 之类字样；或 120 秒后仍无助手消息。→ **命中终止条件第 3 条，停止整轮**。
- 证据：S1（最新会话）、S2（meta）、界面原文；报错时同时抄「Memora」输出面板中带时间戳的报错行。

### A1 opaque 写后重读（WRITECAP-1）

- **目的**：证明 opaque 写（`run_command` / `run_code` 这类目标不可定位的写）之后，同文件读缓存失效——再读**不被「已读过」拦**且拿到改后内容。
- **操作步骤**：
  1. 确保探针文件已由 §1.3 创建（`e:\ceshi\probe-6.0.0\a1.txt` 内容 `V1-ORIGINAL`）。
  2. 点「＋」新建草稿（角色保持默认，不切换）。
  3. 发送下面这段（原样）：
     `请严格按顺序做三步，不要合并、不要换工具：① 用 read_file 读 probe-6.0.0/a1.txt；② 用 run_command 执行命令 echo V2-MARKER-OPAQUE>probe-6.0.0\a1.txt；③ 再读同一个 probe-6.0.0/a1.txt。最后只回答第二次读到的第一行内容。`
  4. 若出现审批卡（按钮「拒绝」「确认」），点「确认」，并在备注记下。
  5. 等待完成。
- **预期可见结果**：助手最终答复里出现 `V2-MARKER-OPAQUE`；屏上工具卡片依次为 `读取文件` / `运行命令` / `读取文件`（若工具卡文案不同，以实际原文记录）。
- **判据**（全部满足）：
  1. 该 round 的 `tool_start` 序列里出现 `read_file` → `run_command`（或 `run_code`）→ `read_file`；
  2. 第二次 `read_file` 的 `tool_result`：`ok=true` 且 `summary` 以 `V2-MARKER-OPAQUE` 开头；
  3. 该 round 的 `evidence` 里 `read_dedup_block` 计数 = 0；
  4. 磁盘复读：`Get-Content 'e:\ceshi\probe-6.0.0\a1.txt' -Raw` 含 `V2-MARKER-OPAQUE`。
- **失败长什么样**：
  - 第二次读被拦：`tool_result` 为 `ok=false` 且 `summary` 以 `[ALREADY_READ]` 开头；或 `evidence` 出现 `read_dedup_block` 且序列化文本含 `a1.txt`；
  - 拿到旧内容：第二次 `read_file` 的 `summary` 仍是 `V1-ORIGINAL`；
  - 换了工具：第二步实际是 `write_file` → 本条判「不可判（工具形态不符）」，允许按同一提示重发一次；仍不复现记不可判。

### A2 写文件改目录结构后复列

- **目的**：证明路径写（`write_file`）新增文件后，同一目录的 `list_dir` 视图失效——再列能看到新文件，不被判重复读取。
- **操作步骤**：
  1. 确认 `e:\ceshi\probe-6.0.0\a2\` 内只有 `a.txt`、`b.txt`。
  2. 点「＋」新建草稿（默认角色）。
  3. 发送：`请严格按顺序做三步：① 用 list_dir 列出 probe-6.0.0/a2（recursive=false）；② 用 write_file 新建 probe-6.0.0/a2/c.txt，内容 A2-NEW；③ 再列出 probe-6.0.0/a2（recursive=false）。最后只回答第二次列表里有没有 c.txt。`
  4. 等待完成。
- **预期可见结果**：第二次列表结果出现 `c.txt`，标题行显示「共有 3 个条目」；助手回答「有」。
- **判据**（全部满足）：
  1. `tool_start` 序列为 `list_dir` → `write_file` → `list_dir`；
  2. 第二次 `list_dir` 的 `tool_result`：`ok=true`，`summary` 含 `c.txt` 与 `3 个条目`；
  3. `evidence` 中 `read_dedup_block` 计数 = 0；
  4. 磁盘：`Get-ChildItem 'e:\ceshi\probe-6.0.0\a2'` 有 3 个文件。
- **失败长什么样**：第二次 `list_dir` 为 `[ALREADY_READ]` / `ok=false`；或 `summary` 仍是 2 个条目且无 `c.txt`；或 `evidence` 出现 `read_dedup_block` 含 `probe-6.0.0/a2`。工具形态不符（模型没调 `list_dir`）→ 按 A1 同规格重试一次，仍不符记不可判。

### A3 浅列与递归列分开

- **目的**：证明同目录「浅列」与「递归列」是不同的去重主体——第二次递归列不被浅列结果拦住，且能看到更深层内容。
- **操作步骤**：
  1. 确认 `e:\ceshi\probe-6.0.0\a3\inner\deep.txt` 存在。
  2. 点「＋」新建草稿（默认角色）。
  3. 发送：`请严格按顺序做两步：① 用 list_dir 列出 probe-6.0.0/a3（recursive=false）；② 用 list_dir 列出 probe-6.0.0/a3（recursive=true，maxDepth=2）。最后只回答第二次结果里有没有 deep.txt。`
  4. 等待完成。
- **预期可见结果**：第一次结果只有 `inner`（目录项）；第二次结果出现 `deep.txt`；助手回答「有」。
- **判据**（全部满足）：
  1. 两次 `tool_start` 都是 `list_dir`，且第二次参数里 `recursive` 为 `true`（args 原文含 `"recursive": "true"` 或布尔 true 等价形态）；
  2. 第二次 `tool_result`：`ok=true`，`summary` 含 `deep.txt`；
  3. `evidence` 中 `read_dedup_block` 计数 = 0。
- **失败长什么样**：第二次被拦（`[ALREADY_READ]` / `ok=false`）；或 `evidence` 出现 `read_dedup_block` 含 `probe-6.0.0/a3`；或第二次结果只出现 `inner` 而无 `deep.txt`（递归参数被忽略）。模型没按两步调 `list_dir` → 重试一次，仍不符记不可判。
