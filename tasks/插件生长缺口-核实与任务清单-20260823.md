### G2 · 代码执行能力（✅ 已实施，2026-08-23 · 原 P2 待安全决策）

- **锚点**：`ICodeExecutionProvider` + `safeExecuteCode`（src/code-exec/）· `AgentOptions.codeExecutionProvider`（[types.ts:525](../src/agent/types.ts#L525)）· `run_code` 工具条件性包含（[builtinTools.ts:209](../src/agent/builtinTools.ts#L209)，`non-idempotent`）
- **现状**：未注入 → `run_code` 不暴露
- **决策门槛**：沙箱边界（允许 fs/网络/进程/内存上限）。插件为 owner 权限自用宿主，需拍板是否开放——**用户确认实施；安全决策 = 本机 owner 可信模型 + 子进程隔离 + 超时强杀（风险面与已有文件/终端工具同等级）**
- **动作**（决策通过后）：实现宿主 `ICodeExecutionProvider` 受限执行器 → assemble 注入 → `run_code` 出现
- **验收**：对话中 `run_code` 可调用且受沙箱约束
- **实施记录（2026-08-23）**：✅ 已落地。
  - `host/codeExecutor.ts` `createLocalCodeExecutor()`：**子进程执行**（`spawn(process.execPath,['-e',code])`，不经 shell 防注入）→ **进程级隔离**（死循环/崩溃只影响子进程，不卡插件主进程）+ **硬超时强杀**（`child.kill`，防无限执行）+ 输出禁色（NO_COLOR）+ stdout/stderr 收集。语言白名单 javascript/js/nodejs。
  - **安全决策备注**：先前首选 vm 沙箱方案，但实测 vm timeout 对纯 `while(true)` 死循环不可靠（会卡死插件主进程），故放弃 vm 改用子进程。子进程拥有 Node 全能力（可 require fs），fs 破坏风险与已有 write_file/read_file 工具同等级；本层保护是进程隔离 + 超时强杀（防卡死），非 fs/网络沙箱（代码注释已如实声明）。
  - `assemble.ts`：注入 `codeExecutionProvider`（内核 ToolExecutor 条件暴露 `run_code` 工具，含 language/code 长度校验 + safeExecuteCode 超时 + 结果截断）。
  - 测试：新增 `codeExecutor.test.ts` 6 例（语言白名单 / console 捕获 / 语法错误 / 运行错误 / **死循环超时强杀** / Node 环境 require）；全量 162 测试全绿 + typecheck + compile 通过。
  - 交互链路：LLM 调 `run_code`（计算/数据处理/验证）→ 子进程执行 JS → stdout/结果回填 → 超时/失败降级不中断对话。
