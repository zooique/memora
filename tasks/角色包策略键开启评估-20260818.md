## 二、Tier 1 详细方案

### 2.1 act.temperature

**现状**：
- `ChatOptions.temperature` 已存在（`src/llm/provider.ts#L25`）
- 全局温度配置在 `config.example.json`（默认 0.7）
- `buildChatOptions()` 只设置 `tools`，不设置 temperature（`loop.ts#L1404-L1418`）

**开启方案**：
1. Agent 将 `getActiveStrategy()` 传递给 Loop
2. `buildChatOptions()` 读取 `strategy.act.temperature`，若有则覆盖全局默认
3. 优先级：策略声明 > 全局配置 > 代码默认 0.7

**代码改动**：
```
agent.ts → 将 strategy 传入 loop.opts
loop.ts  → buildChatOptions() 注入 temperature
types.ts → 标记为 [已消费]
validator.ts → 保留校验规则（已在）
```

### 2.2 act.outputLimit

**现状**：
- `ChatOptions.maxTokens` 已存在（`src/llm/provider.ts#L26`）
- `buildChatOptions()` 未设置 maxTokens

**开启方案**：
1. 同 temperature 路径
2. `buildChatOptions()` 读取 `strategy.act.outputLimit`，注入 `maxTokens`

**代码改动**：同上

### 2.3 reflect.summary

**现状**：
- `assembleRolePack` 已读取 `reflect.userFollowup` + `global.askOn/askLimit`
- `postProcess` 中 `roundSummaryGenerator` 无条件生成摘要
- `reflect.summary` 声明但未消费

**开启方案**：
1. `postProcess` 读取 `strategy.reflect.summary`
2. 值为 `off` 时跳过 `roundSummaryGenerator` 调用

**代码改动**：
```
agent.ts postProcess() → 读取 strategy.reflect.summary，off 时跳过
types.ts → 标记为 [已消费]
```

### 2.4 act.streaming

**现状**：
- `ChatOptions.stream` 已存在（`src/llm/provider.ts#L58`）
- Provider 始终以 stream:true 发起请求
- 注释已说明"预留字段，当前无消费者"

**开启方案**：
1. `buildChatOptions()` 读取 `strategy.act.streaming`
2. 值为 `non-streaming` 时设置 `stream: false`
3. 注意：非流式模式下宿主 UI 需配合（一次性返回而非流式渲染）

**代码改动**：
```
loop.ts buildChatOptions() → 根据策略设置 stream
types.ts → 标记为 [已消费]
```

## 三、Tier 2 详细方案

### 3.1 act.toolStepLimit

**现状**：
- Loop 已有迭代计数（`iteration` 参数）
- `executeToolCalls` 是工具调用集中入口
- `reflect.loopContinue` 已被消费（自审查轮次控制）

**开启方案**：
1. Agent 将 `strategy.act.toolStepLimit` 传入 Loop
2. 每次迭代检查已执行工具步数，超限则跳过本轮工具调用，直接让 LLM 生成最终回复

**代码改动**：
```
loop.ts → 增加 stepCount 追踪
loop.ts → 在迭代边界检查超限
types.ts → 标记为 [已消费]
validator.ts → 新增校验规则
```

### 3.2 prepare.contextAssembly

**现状**：
- 策略声明但未消费
- Agent 已有固定加载最近 N 轮 + 语义召回的混合模式
- `recentRounds` 已被消费

**开启方案**：
1. 消费 `prepare.contextAssembly` 值
2. `fixed` → 仅使用固定轮次，不做语义召回
3. `query` → 仅做语义召回，不加载固定轮次
4. `hybrid` → 混合模式（当前默认行为）

**代码改动**：
```
agent.ts recallAndInject() → 根据 contextAssembly 分支处理
types.ts → 标记为 [已消费]
```
