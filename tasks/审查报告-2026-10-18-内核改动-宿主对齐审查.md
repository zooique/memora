## 0 结论

**VS Code 宿主完全对齐；MCP 宿主是断的，而且已经断了 24 小时没人知道。**

| 宿主 | 编译面 | 运行时面 | 语义/数据面 | 判定 |
|---|---|---|---|---|
| `hosts/memora-vscode` | ✅ `tsc` 0 错 | ✅ 1240 用例 | ✅ 采样点全对齐 | **通过** |
| `hosts/memora-mcp` | ❌ `TS2724` | ❌ **启动即抛** | ❌ 读已废弃数据源 | **P0 双断** |

三条发现，两条 P0：

- **P0-A**：memora-mcp 引用 `InMemoryStorage`——5.0.0 已不导出 ⇒ 编译失败 **且** 现存的旧 `dist` 一加载就抛。
- **P0-B**：memora-mcp 读 `.memora/memories.json`——VS Code 宿主已无条件迁到 `memories.db` 并把 JSON 改名保留 ⇒ 即便修好 A，检索也恒空。
- **P1-C**：memora-mcp 不在任何门禁里（`local-ci.mjs` 的 `HOST` 只指 memora-vscode）⇒ A/B 都不可能有闸门报警。

**根因不是「后来漂移」，是收面那一刻的判据口径错了**：把「宿主零消费」这句话里的「宿主」当成了单数（见 §5）。

## 2 P0-A：memora-mcp 编译失败 + 运行时启动即崩

**证据链（三锤）**：

1. **源码引用**：`hosts/memora-mcp/src/readOnlyFileStore.ts:32`
   ```ts
   import { InMemoryStorage, hasActiveSuperseder, parseMemory, type Memory } from '@zooique/memora';
   ```
   同一行同时用了 5.0.0 **新增**的 `hasActiveSuperseder` 和 4.x **已删**的 `InMemoryStorage`——
   说明这个文件被「5.0.0 化」过，但漏了 `InMemoryStorage`。

2. **编译**：`cd hosts/memora-mcp && tsc -p tsconfig.json --noEmit`
   ```
   src/readOnlyFileStore.ts(32,10): error TS2724: '"@zooique/memora"' has no exported member named
   'InMemoryStorage'. Did you mean 'IMemoryStorage'?
   ```

3. **运行时**（关键——比编译更硬）：现存 `dist/`（2026-10-16 构建）一加载就抛
   ```
   LOAD_FAIL: The requested module '@zooique/memora' does not provide an export named 'InMemoryStorage'
   ```
   实测包入口导出 `48` 个，`'InMemoryStorage' in m === false`，`hasActiveSuperseder === true`。

⇒ **这不是「编译不过但能跑」，是「连旧的都跑不了」**：MCP 服务器现在起不来。

**为什么这个引用是「有意的」，不能简单删**：该文件头 13–14 行写着

> 为什么不全量实现 `IMemoryStorage`：宿主侧自写第二套 Map + 分词 + 排序 = 与内核并列，
> 两边语义漂移后「同一份 `.memora/` 在插件里和 MCP 里搜出不同结果」。这里用内核容器即零并列。

宿主不复刻检索语义是**正确的架构决定**。内核收面时删掉的正是这个「零并列」的容器。

## 4 P1-C：memora-mcp 在门禁之外，所以断了 24 小时无人知

`scripts/local-ci.mjs:58`：

```js
const HOST = join(ROOT, 'hosts', 'memora-vscode');
```

全部宿主步骤（`host:sync` / `host:typecheck` / `host:lint` / `host:test` / `host:build`）
都锚在这个 `HOST` 上。`grep -n "mcp" scripts/local-ci.mjs` **零命中**。

于是形成一条完整的沉默链：

1. 内核收面 → 删 `InMemoryStorage`；
2. vscode 宿主零消费（它用 `createNodeSqliteStorage`）⇒ 门禁全绿；
3. memora-mcp 编译失败，但没有门禁跑它；
4. 旧 `dist` 还在磁盘上（10-16），**「产物存在」被当成「还能用」**——直到真的加载才炸。

> 同型反模式复现：「闸门有实现 ≠ 闸门会跑」→ 这次是「**宿主有两个，门禁只夹一个**」。

## 5 根因：「宿主零消费」里的「宿主」被当成了单数

`70b33a60`（2026-10-17，`PUB-API-PRUNE-2`）的提交信息自述证据是：

> 宿主侧 **tsc 零错** + **动态 import grep 零消费**（dist 硬链接已刷新）
> …
> 消费面为零（**宿主经包入口零消费已实证**）

而同一时间线：

| 时间 | 事件 |
|---|---|
| 2026-10-16 `78206a00` | memora-mcp 建立，`readOnlyFileStore.ts:32` 引入 `InMemoryStorage` |
| 2026-10-17 `70b33a60` | 内核收回 `InMemoryStorage` 导出，判据写「宿主零消费已实证」 |

⇒ 该「实证」在**写下的前一天就已经不成立**。两处口径漏洞叠加：

1. **「宿主」= `hosts/memora-vscode`**：`tsc 零错` 这句只对一个宿主成立（mcp 从未进 tsc 门）；
2. **「grep 零消费」的语料范围**：若只扫 vscode 目录，mcp 的 import 天然不可见。

⚠ 顺带订正一处我自己的口径：常驻报数脚本 `scripts/report-surface.mjs:101` 扫的是
`join(ROOT, 'hosts')`（**复数，含 mcp**）——所以**脚本口径是对的**，错的是收面时用的证据
没有走脚本、只走了单宿主。这条区别很重要：不要因为这次事故去改脚本，脚本没问题。

## 7 修复建议（需拍板，未动手）

### 首选：让 mcp 换用内核**已经为它准备好的**只读存储

内核 `src/memory/nodeSqliteStorage.ts:25-27` 明写：

> `{ readOnly: true }` 重载返回 `ReadOnlyMemoryStorage`（仅读方法）……**供只读宿主（如 memora-mcp）**
> 零并列复用本实现，避免各宿主自写第二份 SQLite 语义实现（三份并列 = 语义漂移）。

也就是说 **P0-A 和 P0-B 是同一个修法**：

```ts
// 改前：读 JSON 快照灌进内存容器（数据源已死 + 容器已删）
const storage = new InMemoryStorage();
storage.upsert(parseMemory(item));   // 循环

// 改后：直接只读打开活库（结构上无写方法）
const storage = createNodeSqliteStorage(dbPath, { readOnly: true }); // ReadOnlyMemoryStorage
```

方法面核对（`storageInterface.ts:117-128`）：`ReadOnlyMemoryStorage` = `Pick<IMemoryStorage, 9>`，
覆盖 mcp 实际用到的 `getById` / `getBySource` / `search` / `getAllSources` / `close`；
`hasActiveSuperseder(m, lookup)` 只要 `lookup.getById`（`supersedeResolve.ts:35-38`）⇒ 结构兼容。

**需要拍板的两点**（都是产品可见变化，不是纯重构）：

1. `load()` 与 `LoadStats{fileTotal,loaded,skipped}` 会失去意义——只读打开活库没有「装载」这一步。
   是删掉这套诊断，还是改成「库文件是否存在 / 条目数 + 跳过原因」的新形态？
2. 未迁移工作区（`memories.db` 不存在）怎么办：**明确报错**（对齐插件 `memoryDbUnavailableError`
   的「响亮失败」风格），还是回退读 `memories.json`（会形成第二个读入口）？

### 必做（与上条独立，可先落）

- `scripts/local-ci.mjs` 增 `mcp:typecheck`（+ `mcp:build`）：**先修再进门**，否则门是红的会挡住所有提交。
- `hosts/memora-mcp/README.md:3/:54` 的数据源表述随修法同步订正；`hosts/memora-mcp` 依赖
  `file:../..` 在发 npm 前须改 `^5.0.0`（既有登记，勿忘）。
