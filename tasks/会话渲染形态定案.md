## 一、核心形态：两段式组合

每个问答闭环的最终视觉 = **任务折叠块 + 总结（纯文字报告）** 的组合展示：

```
┌─ ▾ 任务过程 ────────────────┐   ← 任务折叠块（round-block，唯一承载容器）
│                             │      路 A：整轮一个折叠，内部扁平平铺
│  📍 执行 step-1: 召回记忆    │   ← 既有「执行 step-N」标签（非按步折叠）
│  正在召回记忆…               │   ← 普通 step（narrate）= 平铺文字
│  ↳ 词向量检索命中 3 条        │
│  ┌─ ▾ 工具：read_file ─────┐ │   ← 特殊 step（工具）= 折叠块
│  │  返回内容摘要…            │ │
│  └─────────────────────────┘ │
│  ┌─ 问：你觉得哪个方案更合理？─┐ │   ← 提问 = 平铺文字（自然记录，非容器）
│  │  ▾ 你回答（折叠）           │ │   ← 回答 = 折叠块
│  │   我选 B，理由 XX           │ │
│  └───────────────────────────┘ │
│  ┌─ ▾ 你补充（折叠）─────────┐ │   ← 补充 = 折叠块
│  │   补充一句：注意预算         │ │
│  └───────────────────────────┘ │
└───────────────────────────────┘
                                 
AI 完整答复（纯文字报告）        ← 总结 = 既有 final 报告正文（round-block 之外，平铺）
```

> 定案：有任务表按 `step_boundary` 分步级折叠组；无任务表整轮一个 round-block。全程「文字 + 折叠块」自然平铺。

### 1.1 折叠单位 = 是否有任务表（定案，2026-09-08）

**任务过程区（round-block）的折叠单位（定案：步进边界标记·路 B′，见 §五 雷-1）：**

- **有任务表**：round-block 内按 `step_boundary` 边界事件切分为「步级组」，每步一个折叠块（summary = `step-N · 步骤名`），步内叙述/工具/问答平铺收纳其下。边界由 loop 迭代边界比对产出，被中断迭代不产边界。
- **无任务表**：退回整轮一个折叠组（内部仍「文字 + 特殊 step 折叠」平铺），即现状单轮折叠。

### 1.2 元素与文字/折叠分档

| 元素 | 形态 | 说明 |
| --- | --- | --- |
| 普通 step（narrate） | **平铺文字** | 任务过程里的说明性叙述，直接铺在折叠块内 |
| 工具调用 | **折叠行** | 既有 `round-block__tool`，摘要 + 可展开结果 |
| 提问（LLM 的 ask） | **平铺文字** | 所提问题自然记录在对话流，无 tag / 无边框容器化 |
| 回答 / 补充（用户输入） | **折叠块** | 统一为同一 `<details>` 结构，仅 summary 标签区分「你回答 / 你补充 N 条」 |
| 最终答复 / 总结 | **平铺纯文字** | 任务折叠块**之外**独立一段，任务完成的「报告」 |

- 折叠块内部 = **文字与折叠块自然交替平铺**（特殊 step 不与叙述混做嵌套的行容器，而是平级平铺）。
- task(折叠) + summary(平铺) 组合 = 折叠承载过程、文字承载结论。

## 二、SSOT 收敛点（对照现状碎片）

### 2.1 杀掉的行容器与硬彩切

| 现状 | 处置 |
| --- | --- |
| `msg-qa--ask`（"问" tag 行） | 提问改平铺纯文字，不作独立样式行 |
| `msg-qa` + `msg-qa__text`（"你答"，60/120 硬截断） | 回答进折叠块，正文**完整显示**，不再截断 |
| `msg-qa__group` / `msg-qa__row`（"你补充 N 条"） | 统一为同一折叠块结构，仅标签区分 |
| ask 内联块（`renderAskInline`） | 保留为**输入交互**，答完销毁；记录形态交给折叠块 |

### 2.2 单一渲染函数

- answer / supplement 统一进**同一个折叠块渲染函数**，kind 只决定 summary 标签与合并行为（补充同轮合并，回答每答一行）。
- **运行时 = 重放同一条路径**：问题（平铺文字）与回答（折叠块）从同一份事件数据渲染，不再有「运行时校验排除回顾行」「问答排序 glue」等分叉逻辑。
- 折叠块默认**展开**（新答完即时可见，可手动收起），保留自然阅读、又天然收住长文本。

### 2.3 与既有实现的关系（自然生长，不重造）

- 任务折叠块 = 现有 `round-block`（已是 `<details>`，内部 narrate 平铺 + tool 折叠行，扁平化平铺已落地于 2026-09-04）。
- 总结纯文字报告 = 现有 final 后的 assistant 正文块（已是折叠块外的平铺正文）。
- 本方案的增量 = **把交互行（qa/supp）从「平铺内联行」收为「折叠块」**，与 tool 折叠行语言统一；其余形态现状已符合。

## 五、排雷结论（2026-09-08）

> 按 SSOT / network-soil 审查逐项实证，**一条致命雷 + 四条加固点**。落地前必须先消化本节。

### 🔴 雷-1（定案）：PlanStep 折叠单位 = 步进边界标记（路 B′ · 方案1）

**最终决策**：采纳**路 B′（步进边界标记）**，实现选**方案1·迭代边界比对**。路 A 降为紧急降级备用，仅在「不愿动内核、只要交互折叠」时启用——本轮默认走路 B′。

> 对话收敛：我方最初评估「只能靠逐事件注入 stepId（P-4）」→ 用户提出「步进时刻记标题边界、事件挂最近边界」→ 实证步进信号现成、loop 可不读 checkpoint，降为边界级可落地。

**原始实证（为何逐事件注入行不通）**：
- 全部 `ProcessEvent`（[roundStore.ts:173-205](../src/memory/roundStore.ts#L173-L205)）只带 `seq`，零 step 归属字段。
- 现有 step 标签（[chatView.ts:1003-1017](../hosts/memora-vscode/src/webview/scripts/chatView.ts#L1003-L1017)）从 `currentPlanSteps` 反推当前 active step，只能对整轮显示，做不到逐事件分组。
- P-4 观察项「chunk 带 planStepId」= 逐事件改 → 重、跨三层。

**用户方案（2026-09-08，采纳）——「步进边界标记」替代逐事件注入**：
> 推进任务时先把当前任务标题记录为一条**边界**，后续 step 都挂到最近这条边界下。被中断的迭代不产边界 → 未落实的任务不会被记录。

**实现（方案1·迭代边界比对，最终排雷后定案）**：
- `onStepBoundary` 是**回调只写 stepLog，不 yield 事件**（[loop.ts:959-963](../src/agent/loop.ts#L959-L963)）。故边界事件必须由 loop 自行 yield。
- 机制：loop 新增**只读注入 `getActiveStepMeta?: () => { stepId; title } | null`**（对齐 `getTaskTable` 装配于 assembler.ts；落地收敛：排雷期曾拟 { id; order; title }，order 实际由宿主按边界序号渲染、不进协议，故定 { stepId, title }）。loop 在**每次迭代产 narrate/tool/问答前**调用它，与 `lastBoundaryStepId` 比对，**变化才 yield `{type:'step_boundary', payload:{stepId,title}}`**；无任务表返回 null → 不产、维持单轮一组。
- 打断语义正确：active step 前进发生在 `completeStep`（迭代完成回调）；被中断迭代不产边界 → 后续事件不错误挂到未落实 step。符合「推进任务时记录标题」。
- 事件流落盘：`step_boundary` 作为 `ProcessEvent` 新变体存入 roundStore → 重放按同一边界分组，运行时=重放同构成立。

**路 A（备用降级，非默认）**：维持整轮一个 round-block + 内部扁平 step 流 + 既有 `执行 step-N` 标签；不动内核。仅当步级折叠因某种原因不在本期接受时启用。

> §2.2/§四 所述「运行时=重放同构」对路 B′ 仍成立：step_boundary 作为事件落盘，重放重建按同一边界分组。

### 🟡 加固-1：「总结」命名与既有 summary/SummarizeStrategy 语义冲突

正文「总结（纯文字报告）」实为**现有 final 后的 assistant body（报告正文）**，本就在 round-block 之外且保持干净，非新增元素。措辞须与内核 `SummarizeStrategy`/`summary` 区分，避免误读为「新加一个总结 step」或触发旧设计。已改为「总结 = 最终报告正文（既有 .msg-body）」。

### 🟡 加固-2：步级折叠块的默认态（落地收敛：恒默认收起）

外层 round-block 进行中自动展开、完成自动收起（`rb.open = !finalize`）。**步级折叠块落地采用恒默认收起**（不随 outer 展开切态，CSS 注释已固化「默认收起——步骤过程属过程明细」）；排雷期曾拟「与 outer 一致（进行中展开）」现收敛为静态交互简化为恒收起，避免每迭代翻转 open 抖动。

### 🟡 加固-3：提问平铺后超长文本防护

移除 60/120 截断后，提问（尤其 ask 多问在一处）平铺会拉长折叠块 body。建议：平铺提问整行显示 + `title` 悬浮全文（沿用既有 `msg-qa` 的 textContent + title 防注入范式），不新增截断魔法数。

### 🟡 加固-4：补充折叠块的多条合并语义保留

现「你补充 N 条」同 roundId 合并为一行（[chatView.ts:2110-2126](../hosts/memora-vscode/src/webview/scripts/chatView.ts#L2110-L2126)）。折叠化后保留该合并语义：折叠块内多行追加，summary 标签仍显示「你补充 N 条」，跨 roundId 不合并（既有 roundId 归元继续生效）。
