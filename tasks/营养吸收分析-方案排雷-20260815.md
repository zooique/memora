## 一、原始结论（输入，摘要）

上一轮分析报告对比了 memora 与 2026 年业界顶尖 agent 设计方案（DeepSeek Harness、Trae、Codex、Claude），识别出以下可吸收方向：

| # | 建议项 | 方向 | 来源洞察 |
|---|--------|------|---------|
| A-1 | 渐进式披露记忆（摘要→手动→证据） | 检索优化 | Claude/Codex 层级记忆访问 |
| A-2 | 上下文检索（命中时扩展相邻摘要） | 检索优化 | 缓解孤立摘要导致的上下文断裂 |
| A-3 | 多阈值压缩（50% 触发 + 85% 兜底） | 上下文工程 | 避免突然大幅截断 |
| A-4 | 高价值记忆摘要层 | 记忆架构 | 高频访问高价值摘要预缓存 |
| A-5 | 背景异步记忆流水线 | 记忆架构 | 后台异步记忆提炼/归档 |

## 二、对照 docs 设计文档逐项排雷

### 排雷-1 · A-1 渐进式披露记忆（摘要→手动→证据）

| 项目 | 内容 |
|------|------|
| **建议内容** | 三层访问：摘要自动注入 → 用户手动展开 → 回溯原始证据 |
| **memora 现状** | 已实现两级：摘要自动注入（memory-as-summary §4.1 召回）+ `trace_summary` 溯源工具（§4.5/§4.6）返回原始对话 |
| **雷区** | ⚠️ **重复定义**：中间"手动展开"层 = 记忆管理面板，属于宿主 UI 职责，MVP 已后置。memora 的两级（自动注入 + 溯源工具）已覆盖"摘要→证据"全链路 |
| **判定** | ❌ **否决**（已覆盖，不新增） |

### 排雷-2 · A-2 上下文检索（命中时扩展相邻摘要）

| 项目 | 内容 |
|------|------|
| **建议内容** | 召回命中某摘要后，若其相邻轮次存在高相关摘要，在预算内一并召回 |
| **memora 现状** | 无此机制。当前召回只返回命中摘要，不扩展相邻轮次 |
| **雷区** | 🟢 **真实缺口**，但需受边界约束：① 不新增存储层（复用 round-summary 按 roundId 邻接查询）；② 扩展条数设上限；③ 总召回受增量召回 token 预算约束；④ 与互斥排除（§4.3）兼容 |
| **判定** | ✅ **采纳（收敛版）**——补入远期候选（memory-as-summary §4.7），明确四条边界约束，不做预埋实现 |

### 排雷-3 · A-3 多阈值压缩（50% 触发 + 85% 兜底）

| 项目 | 内容 |
|------|------|
| **建议内容** | 双阈值：用量达 50% 时触发首次压缩（摘要替换），85% 时强制截断 |
| **memora 现状** | 单阈值（`shouldTruncate`：超上限且消息>3 即截断）。但 ADR-023 C1（`roundSummaryLoader` 截断优先复用已存摘要）+ C2（`minRecentRounds` 强制保留最近轮）已覆盖"避免突然大幅截断"的核心诉求 |
| **雷区** | ⚠️ **重复定义**：`roundSummaryLoader` 确保截断时不必现调 LLM 生成摘要（零成本 + 保真）；`minRecentRounds` 确保最近轮原始对话保留。两个机制等价实现了双阈值想要的效果——"截断但不丢失关键信息" |
| **判定** | ❌ **否决**（现有机制已覆盖等价目标，不引入新机制） |

### 排雷-4 · A-4 高价值记忆摘要层

| 项目 | 内容 |
|------|------|
| **建议内容** | 对高频访问的高价值摘要预缓存，独立于普通摘要存储 |
| **memora 现状** | 记忆即摘要单轨（memory-as-summary §2.3），洞察层已于 2026-08-14 移除；type 差异化召回（preference/decision 不限窗口）已体现"高价值优先" |
| **雷区** | 🚫 **哲学冲突**：预提炼模型（独立摘要层）正是"记忆即摘要"架构主动舍弃的（§1.3 权衡表）。再建高价值层 = 洞察层变体重现，违反 SSOT §1.3"记忆是摘要的按需聚合，而非独立的提炼层" |
| **判定** | ❌ **否决**（哲学硬冲突，洞察层已移除） |

### 排雷-5 · A-5 背景异步记忆流水线

| 项目 | 内容 |

| **建议内容** | 独立后台线程异步执行记忆提炼/归档/衰减 |

## 四、深层洞察

1. **memora 的"记忆即摘要"架构比业界多数方案更前瞻**。2026 年主流 agent 设计（DeepSeek Harness、Codex、Claude）仍以"预提炼 + 独立存储层"为范式，而 memora 已收敛为单轨（round-summary 唯一记忆单元），type 差异化召回 + 写路径取代检测 + 异步衰减构成完整闭环。本次排雷验证了该架构设计的鲁棒性——9 项建议中 7 项否决，均因 memora 已有等价物或哲学层面更优。

2. **唯一真实缺口：上下文检索**。现有召回只返回命中摘要，不扩展相邻轮次，在"摘要高度浓缩信息"的场景下可能导致 LLM 获得碎片化上下文。但该问题目前在写作等轻量场景下未成为瓶颈，归入远期候选是合理选择。

3. **文档-实现不一致是 memora 当前最大的治理风险**。architecture_philosophy_rules.md §8 声称衰减 round-summary 就是一个典型：文档落后于代码演进（洞察层移除后 round-summary 不再参与衰减，但文档未同步更新）。此类问题从 2026-08-14 的 8 项偏移（C-1~C-8）到本次又发现 1 项，说明文档对齐需要持续投入。
