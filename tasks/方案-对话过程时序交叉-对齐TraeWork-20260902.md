# 方案：对话过程时序交叉分布（对齐 Trae Work「任务时 / 结论」）+ 会话记录折叠形态持久化

> 来源：用户实测 VS Code 宿主后发现——所有运行时过程记录被统一规整到会话顶部的折叠块，期望对齐 Trae Work：思考/工具调查（任务时）与结论文字按时间交叉分布，而非收尾汇总。
> 关联规则：[single-truth-source-mindset](../.trae/rules/single-truth-source-mindset.md) · [comment-doc-slimming](../.trae/rules/comment-doc-slimming-rules.md) · visual-design-philosopher 三层分类。

***

## 一、背景：Trae 设计思路 vs Memora 现状

### 1.1 Trae Work 的对话形态（目标态）

```
[用户] 帮我实现 X
[任务时] 思考 → 读文件 → 搜索 → 写代码        ← 流式、按时间插入
[结论] 已实现 X，核心改动如下…               ← 结论正文
[任务时] 继续调试 → 运行测试                  ← 下一轮交叉
[结论] 测试通过，共 2470 绿…
```

- 「任务时」（思考/工具调查）与「结论」（正文）**按时间交叉分布**在会话流中

- 每轮：先任务时、后结论；多轮 loop 自然形成时间交叉

- 工具调用是对话的一部分，不是被收起的「附录」

### 1.2 Memora 当前形态（现状事实，代码定位）

- 过程事件全部汇入 `currentEvents[]`（[chatView.ts#L1643](../hosts/memora-vscode/src/webview/scripts/chatView.ts#L1643)），流式中**只刷新折叠头 summary**，details 要等 `finalize=true`（assistant 正文送达）才一次性渲染

- `renderRoundBlock`（[chatView.ts#L497](../hosts/memora-vscode/src/webview/scripts/chatView.ts#L497)）把思考/召回/工具/自审查/metrics 汇总进 `round-block` 折叠块（§过程轨迹/§召回记忆/§工具调用…）——**这是「顶部统一被规整调用记录」的根因**

- `round-block` 挂在正文之前（[chatView.ts#L425](../hosts/memora-vscode/src/webview/scripts/chatView.ts#L425)），但折叠收尾才展开 → 用户看不到「任务时」

### 1.3 差异定位（一句话）

| <br />  | Trae Work  | Memora 当前    |
| ------- | ---------- | ------------ |
| 工具/思考呈现 | 按时间交叉嵌入正文流 | 收尾汇总进折叠块     |
| 任务时可见性  | 流式中实时可见    | 流式中仅折叠头计数    |
| 一轮结构    | 任务时 → 结论   | 折叠块 + 结论（分离） |

## 二、现状评估（代码事实 + 三层分类）

### 2.1 关键代码事实（评估依据）

- **事件全集**（[roundStore.ts#L135](../src/memory/roundStore.ts#L135)）：`meta/thinking/recall/memory_added/tool_start/tool_result/self_review/text_self_review/aborted/metrics`，全部带 `seq` 序号

- **一轮真实时序**：`meta → thinking → recall → tool_start/result（调查）→ chunk（结论）→ metrics` —— **工具调用天然发生在结论正文之前**

- **重放时序**（[chatPanel.ts#L1721](../hosts/memora-vscode/src/webview/panels/chatPanel.ts#L1721)）：`user → replay_events（整批含 meta）→ assistant`；assistant 正文在事件之后到达

- **assistant 块 DOM**（[chatView.ts#L1150](../hosts/memora-vscode/src/webview/scripts/chatView.ts#L1150)）：`label → [round-block] → msg-content>body → footer`

- **任务看板**：`plan-board` 顶部状态栈，仅 `task_table_write/update` 触发（[chatPanel.ts#L2024](../hosts/memora-vscode/src/webview/panels/chatPanel.ts#L2024)）——普通对话不出现，与「运行时看板」语义一致

### 2.2 三层分类（visual-design-philosopher）

| 层       | 元素                                       | 视觉权重      |
| ------- | ---------------------------------------- | --------- |
| 一级 · 直面 | 正文结论（chunk）                              | 主体最大、最高对比 |
| 次级 · 收纳 | 工具调用行、思考行（**时序嵌入**）、任务看板（顶部状态栈）、召回/沉淀提示条 | 折叠/弱化/徽标  |
| 专家挖掘    | 完整执行档案（recall/自审查/metrics）、执行指标          | 尾部折叠深埋    |

## 三、设计决策（自然生长，单一真理源）

### 3.1 核心决策：`msg-timeline` 时序投影容器

**不做新数据源**：`currentEvents[]` 仍是唯一事件记录源（SSOT），timeline 只是其**时序 DOM 投影**。

- 新增 `.msg-timeline` 容器，置于 assistant 块 label 之后、正文之前，承载「任务时」：

  - `thinking` → 思考行（summary = 相位文案，用户已确认「任务时 = 思考 + 工具调查」）

  - `tool_start` → 工具行（summary = `名称 (进行中)`，**到达即建**）

  - `tool_result` → 全量重建工具行（沿用现有 `renderToolRow`，状态/失败展开由重建天然更新）

- 正文 `.msg-body` 保持独立（结论），**工具行绝不进 body**（避免破坏 markdown 流式渲染）

- 一轮结构 = `任务时（timeline）→ 结论（body）`；多轮 loop 自然形成时间交叉

- **DOM 挂载顺序**（与现有 assistant 块结构对齐）：

  ```
  [label 角色·模型] → [timeline 任务时] → [msg-content>body 结论] → [round-block 执行档案] → [footer 记忆标签]
  ```

  timeline 占原 round-block 位置（label 后、正文前）；round-block 挪至正文后、footer 前。

### 3.2 round-block 降级

- `round-block` 折叠块降级为**尾部「执行档案」入口**：承载 recall/自审查/metrics 小节（专家挖掘），不再主导「任务时」呈现

- **工具调用小节移出**（由 timeline 承接，避免双写）；折叠头保留运行状态（最新相位 + 计数 + 耗时）——移动位置，逻辑复用

- 挂载点：从正文前（[chatView.ts#L425](file:///f:/zooique/memora/hosts/memora-vscode/src/webview/scripts/chatView.ts#L425) `insertBefore(msg-content)`）改为正文后、footer 前

### 3.3 任务看板（运行时）

- **保持现状**：`plan-board` 为运行时看板，`task_table_*` 触发、收敛清空。不并入本方案渲染改造（用户已确认「运行时看板停止清空」理念）

### 3.4 需求 → 代码约束对照表（防偏离，经验 193642）

| 约束                     | 落点                                |
| ---------------------- | --------------------------------- |
| A. 工具/思考必须按时间顺序可见（不汇总） | `renderTimeline` 时序追加，非收尾一次性渲染    |
| B. 事件记录 SSOT 不变        | `currentEvents[]` 保留，timeline 仅投影 |
| C. 工具行不破坏正文 markdown   | timeline 与 body 兄弟节点，绝不嵌套         |
| D. 重放与运行时同形态           | 共用 `renderTimeline`；重放按 seq 逐条投影  |
| E. 正文块未建不得投影           | 复用 ensureRoundBlock 延迟挂载模式        |
| F. 一轮多块（插话）只挂首个        | 复用 roundBlockHostEl 判定            |
| G. 无过程事件轮不产生 timeline  | 空 events 不挂载（保持现状）                |

## 四、实现路径（分阶段，自然生长）

### P1：时序交叉渲染（本轮核心）

1. **chatView\.ts**：`buildAssistantShell` 增 `.msg-timeline` 容器
2. **chatView\.ts**：改造 `renderRoundBlock`（**不新造函数，自然生长**）——工具行/思考行的渲染从「收尾（finalize=true）才执行」提前到「到达即执行」，工具行仍复用 `renderToolRow`

   - `thinking/tool_start` 到达即投影到 timeline（流式中可见，不再等收尾）

   - `tool_result` 到达触发 timeline 工具行**全量重建**（沿用现有「简单确定性——事件量小」哲学，不做增量定位更新）

   - recall/self\_review/metrics 进尾部 round-block 档案折叠（专家挖掘，保持 finalize 后渲染）
3. **chatView\.ts**：`process_event` 分支（L1643）与 `replay_events`（L1679）改走改造后的 `renderRoundBlock`（参数不变，仅渲染时机提前）
4. **chatView\.ts**：`ensureRoundBlock` 拆出两个挂载点——timeline（label 后，即时挂）+ round-block（正文后 footer 前，延迟挂）；复用现有「正文未建返回 null + assistant 送达补挂」机制
5. **chatStyles.ts**：新增 `.msg-timeline` / `.msg-timeline__thinking` / `.msg-timeline__tool` 样式（复用 round-block\_\_tool 视觉，SSOT 令牌）
6. **测试**：chatView\.test.ts 更新 round-block 断言 → timeline 断言（同步，不跳过）
7. **验证**：宿主 vitest 全绿 + typecheck 0 错

### P2：会话记录折叠形态持久化（独立主题，本轮不阻塞）

- 任务结构（步骤标题 + stepRounds）沉淀到 `SessionMeta`（如 `planSnapshot`），`replaySession` 时组装折叠任务节点

- 与 P1 正交：P1 解决「任务时可见」，P2 解决「收敛后可重启组装结构」

- 涉及会话记录存储契约扩展（加字段），需 ADR 论证后独立排期

## 六、验收标准

1. 运行时：多步任务对话中，工具调用/思考按时间顺序可见于正文之前（任务时 → 结论），流式中即实时出现（非收尾展开）
2. 重放：历史会话与运行时同形态复现（timeline 时序投影）
3. 工具失败默认展开、成功/进行中折叠（保留现有可访问性：focus-visible）
4. 宿主 vitest 全绿 + typecheck 0 错
5. 无过程事件轮 / 插话 / clear\_ok 等边界不回归
