# 方案：对话展示「任务过程折叠区 + 报告」（对齐 Trae Work）+ 会话记录持久化评估

> 来源：用户实测 VS Code 宿主后发现运行时过程记录展示形态不理想，期望对齐 Trae Work「任务时 / 结论」——运行时的思考/工具调查统一折叠进「任务过程」，最后汇总一份干净报告给用户；重启后记录结构可复现。
> 关联规则：[single-truth-source-mindset](../.trae/rules/single-truth-source-mindset.md) · [comment-doc-slimming](../.trae/rules/comment-doc-slimming-rules.md) · visual-design-philosopher 三层分类。

***

## 一、设计演进（SSOT 反思）：从「多段交叉」收紧为「单一折叠区」

### 1.1 阶段一：多段交叉（2026-09-02 实施，已废弃）

- 曾为追求「工具/思考与正文按到达时序物理穿插」，引入 `.msg-segments` 段容器 + 5 个段状态变量 + `openSegment / reuseOrOpenTimelineSegment / applyToolResultCrossSegments` 等函数 + 渲染/收尾双模式分支。

- **SSOT 违反**：同一轮过程事件被 `timeline`（工具/思考）与 `round-block`（召回/审查/metrics）**两套容器**投影 → 底部重复折叠、信息双写；正文被工具切碎成多段 → 用户「平铺一大堆、眼花缭乱」。实测否决。

- **废弃**：删除段容器/段状态/增量/跨段局部更新全部机制（净删约 120 行）。

### 1.2 阶段二：单一「任务过程折叠区 + 报告」（当前实现，SSOT 收敛）

回到最小单元：**每轮 AI 回复 = 一个「任务过程」折叠区（统一折叠全部运行时事件）+ 一份干净报告正文**。

```
┌ .msg.assistant
│ [.msg-ai-label            角色·模型]
│ [.round-block             任务过程折叠区（进行中自动展开·实时可见；完成自动收起只留摘要）]
│   ├ summary               进行中呼吸点 + 「工具×N · 耗时」；完成收起
│   └ details               实时相位行 + 工具调用/过程轨迹/召回/已沉淀/自审查/执行指标
│ [.msg-body                报告正文（单一连续 markdown，不被工具切碎）]
│ [.msg-footer              复制/分叉/删除 + 时间戳]
```

- **行为**：进行中 `round-block` 自动展开，实时相位行 + 工具行增量追加（任务过程实时可见）；完成自动收起，用户只看到报告，想翻找细节再展开折叠区。

- **SSOT**：`currentEvents[]` 仍是唯一事件源；`round-block` 是唯一过程容器（timeline 功能并入，不再双容器）；渲染/收尾无双模式分支。

- **自然生长**：复用现有 `round-block / renderToolRow / sectionOf / countEvents`，仅新增 `getOrCreateSection / updateToolRowState` 两个小辅助。

## 二、内核对齐：报告内容由内核汇报闭环生产（不重复造）

- 内核已有**独立汇报闭环** `runReport`（[loop.ts](../../src/agent/loop.ts)）：复杂任务收敛后（[finalizeExternalTask](../../src/agent/seed/orchestrator.ts) / [settle](../../src/agent/seed/orchestrator.ts)）自动跑一轮，产出「目标回顾 + 已完成步骤 + 结果」的结构化总结，作为最终回答（正文）流入。

- 汇报前置 `thinking(reporting)` 相位（webview `phaseLabel` 已映射「收尾汇报中…」）；汇报正文走 `text` chunk + `appendAssistant` 进会话历史。

- **结论**：UI 层只做形态（过程折叠 + 报告展示），报告**内容**由内核汇报闭环唯一生产——SSOT，不另造总结机制。

## 三、会话记录持久化 · 重启复现（P2 评估：已满足，planSnapshot 否决）

### 3.1 核实结论：重启复现已天然满足

过程事件（含 thinking）已持久化到 `Round.processEvents`（v1.5 方案 S1-S4 已落地），完整链路：

| 环节 | 实现                                                                                                                                                                                                                                                                                            |
| -- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 落盘 | 宿主 [consumeFlow](../../hosts/memora-vscode/src/webview/panels/chatPanel.ts) 缓冲全部 `ProcessEvent`（meta 首条 → thinking/recall/memory\_added/tool\_start/tool\_result/self\_review/text\_self\_review/aborted → metrics 末条），流结束「读最新 Round → `round.processEvents = events` → save」一次整写（Write-once） |
| 重放 | [loadRoundBasedHistory](../../hosts/memora-vscode/src/webview/panels/chatPanel.ts) 读 `round.processEvents`，[sendRoundView](../../hosts/memora-vscode/src/webview/panels/chatPanel.ts) 按轮交织发 `replay_events`（user → replay\_events → assistant）                                                |
| 渲染 | webview `replay_events` → `renderRoundBlock(currentEvents, true)` 重建任务过程折叠区——**与运行时同一渲染函数（SSOT）**                                                                                                                                                                                             |

重启后：每个 assistant 块 = 任务过程折叠区（工具/思考/召回/审查/metrics 全复现）+ 报告正文，完整还原「任务 → 过程 → 报告」记录结构。

### 3.2 planSnapshot 否决（ADR 不立项）

- `checkpoint.plan` 是 **多 turn 任务编排的执行态**（运行时任务表）：规划建表 → 步 turn 执行 → 收敛清表（[finalizeExternalTask](../../src/agent/seed/orchestrator.ts) `clearPlan`）。plan 是「正在做」的状态，不是「做过」的记录——持久化到 `SessionMeta` 属**重复存储执行态**，与「turn / loop」哲学冲突（执行态不落会话记录）。

- 「做过」的记录已由**各步 processEvents + 汇报报告**承载，无需额外 plan 快照。

- 任务看板（plan-board）保持运行时语义：`task_table_*` 触发、停止即清空，不参与本方案。

## 四、验收标准

1. 运行时：多工具任务流式中，任务过程折叠区自动展开、工具/思考实时追加可见；正文单一连续不被切碎
2. 完成：折叠区自动收起只留摘要（工具×N · 耗时），用户阅读只看到干净报告；展开可翻找细节
3. 重放/重启：历史会话与运行时同形态复现（`round.processEvents` → `replay_events` → `renderRoundBlock`）
4. 报告内容来自内核汇报闭环（`runReport`），UI 不另造
5. 宿主 vitest 全绿 + typecheck 0 错；无过程事件轮 / 插话 / clear\_ok 等边界不回归
