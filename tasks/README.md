# tasks —— 任务台账与证据附件区

## 目录构成

| 路径 | 性质 | 纪律 |
|---|---|---|
| `待完成任务.md` | **唯一台账**（单台账制，2026-10-10 用户拍板） | 销项标 ✅ 留原区在册；每真发一版随版本号把已关闭项整区迁入 `archive/`；开放 / 观察 / 明确不做项一律留本台账 |
| 根目录其余 `审查报告-*` / `方案-*` / `审查-*` 文件 | 过程产物（**证据附件**形态） | **留原位不移动**：存活判据 = 被真相链任一消费（`archive/` 收据 / 主台账 / `.trae/rules` / `src`），**不限于** archive 收据——存在无 archive 收据但被台账 path 引用的报告（份数以 `npm run scan:docs:refs:check` 实测为准，勿写死），故不写成「全部被收据钉死」 |
| `archive/` | 版本归档 + 历史合集 | 纪律见 [archive/README.md](archive/README.md) |

## 新报告的落点规矩

1. **随版本归档走**：为某版本发版/审查产生的报告，被 `archive/<版本>-<线>.md` 条目以路径引用，
   放本目录根区（证据附件形态）。
2. **过时零引用报告**：全库引用扫描确认零入边（含历史层）且内容过时的，迁 `archive/reviews/`
   （2026-10-22 立的瘦身归档区，纪律见 archive/README.md 末节）。
3. **彻底删除**：删除档（零引用 + 无在途义务 + git 已跟踪）直接删，git 历史即档案——
   2026-10-23 DOC-DRAIN 删 `审查报告-2026-10-22-内核5.0.0发版条件复核.md`（5.0.0 已发布，时点快照失效）；
   2026-11-23 DOC-DRAIN 删 4 份：`审查报告-2026-10-15-会话报告核实与落地质量审查.md`（结论全沉淀：台账登记 + D8 用户拍板）、
   `审查报告-2026-11-19-托管模式模块改动质量审计.md`（结论已落台账，含一条假阳性已撤销）、
   `真机测试方案-6.0.0.md` + `真机测试结果-6.0.0.md`（成对删；结果自述「本条已结」、探针教训已登 `TEST-PROBE-FALSE-GREEN-1`，6.0.0 时点快照）。四份均零真相链消费、无在途义务、git 已跟踪。
4. **降指针档**：零真相链消费、但被多份过程产物以裸名提及的，压成「结论 + 指针 + 历史说明」保留文件名
   （删会制造悬空文本）——2026-10-23 `审查报告-2026-10-11-SSOT审计弧总账.md` 即此档。
   **扩档（2026-11-23）**：被 `archive/` 收据以 path 引用的已完工报告同样走本档——**存活 ≠ 不可压缩**。
   `archive/*` 的 `**报告**：path` 被 `doc-ref-scan` 归为真相链消费（`GOVERNANCE_LEDGER` 只认主台账），
   故这类文件不可删（删则收据 path 悬空、且不得改写历史），但结论既已全部沉淀，过程明细可压掉、git 历史即档案。
   本批 12 份压桩，逐份保留「结论 + 落点（按 ID 检索）+ 历史说明」；`审查报告-2026-10-11-宿主UI质量回顾与优化路线.md`
   与 `审查报告-记忆系统缺陷评估-20261012.md` 另保留**全库唯一出处**的原句（键盘可达性缺口 / 焦点守卫脚本 / 三条明确不做；
   边界③④升档触发），压掉即失去升档判据。配套注释清算：`chatPanel.ts` 对已压桩报告的过程稿指针改指 `ADR-035`（定案锚）。
   **同批 docs 侧 1 份**：`docs/重读永动机-主流收敛与最终落地-方案.md` 原头部「探索中 · 待拍板 B1」被三方推翻
   （`ADR-031` 2026-09-14 已接受 / B1–B3 已在代码 / 2026-09-21 真机复跑通过），头部属谎 ⇒ 降指针档并指 `ADR-031`，
