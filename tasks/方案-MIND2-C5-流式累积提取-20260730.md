# MIND2-C5 流式累积模板提取方案

## 一、现状分析

### 1.1 演进路径

`judgeWithLlm<T>()` 已封装"流式累积 → parseLlmJson → null 检查 → 抛 configError"三件套（严格模式）。
但以下 Manager 仍内联同模式，且各自有**不同的降级策略**——这是半嫁接状态。

### 1.2 调研结论

流式累积模式 `for await (const chunk of provider.chat(...))` 出现在 **5 个 Manager** 中：

| 文件 | 行号 | 模式 | parseLlmJson | null 处理 | provider 异常处理 |
|------|------|------|:------------:|-----------|------------------|
| llmJudgeHelper.ts:51 | 已封装 | ✅ | 抛 configError（严格） | 不捕获（向上抛） |
| workProjection.ts:248 | 内联 | ✅ | 降级返回默认对象 | 不捕获（向上抛） |
| autoConfigRefiner.ts:137 | 内联 | ✅ | 返回 [] | try/catch 返回 [] |
| insightExtractor.ts:319 | 内联 | ✅ | 多字段提取+类型校验 | 不捕获（向上抛） |
| sessionArchiver.ts:194 | 内联 | ❌（不解析JSON） | N/A | 不捕获（向上抛） |
| textPolishManager.ts:118 | 内联 | ❌（不解析JSON） | N/A | 不捕获（向上抛） |

**核心差异**：
- judgeWithLlm 是"严格模式"（null 抛错），4 个内联是"容错模式"（null 降级）
- sessionArchiver/textPolishManager 不解析 JSON，只用流式累积
- autoConfigRefiner 有额外 try/catch 包裹

### 1.3 本轮提取范围

| 提取项 | 类型 | 职责 | 目标 |
|--------|------|------|------|
| `accumulateStream()` | 纯函数 | 累积 LLM 流式响应的 chunk.content | 消除5处重复的3行流式累积代码 |

### 1.4 不提取的归档

| 项 | 理由 |
|----|------|
| parseLlmJson + null 处理 | 各 Manager 业务逻辑差异大（严格/降级/多字段），强行统一会让函数变复杂 |
| judgeWithLlm 扩展 onParseFail | 会让 judgeWithLlm 变成"既严格又容错"双模式，违反 §2.1「用一句话说清核心逻辑」|
| autoConfigRefiner 的 try/catch | provider 异常处理策略是业务决策，不应下沉到工具函数 |

## 二、目标函数设计

### 2.1 accumulateStream 纯函数

```typescript
/**
 * 累积 LLM 流式响应的 chunk.content
 *
 * 纯工具函数，不持有业务逻辑：
 * - 不解析 JSON（由调用方决定用 parseLlmJson 或其他方式）
 * - 不处理 null（由调用方决定降级或抛错）
 * - 不捕获 provider 异常（由调用方决定 try/catch 或向上抛）
 *
 * @param provider LLM Provider 实例
 * @param messages LLM 消息数组
 * @param options 可选的调用参数（maxTokens/temperature/timeoutMs/signal）
 * @returns 累积后的完整字符串
 */
export async function accumulateStream(
  provider: LlmProvider,
  messages: Message[],
  options?: { maxTokens?: number; temperature?: number; timeoutMs?: number; signal?: AbortSignal },
): Promise<string> {
  let result = '';
  for await (const chunk of provider.chat(messages, options)) {
    if (chunk.content) result += chunk.content;
  }
  return result;
}
```

### 2.2 与现有模式的对比

| 模式 | 适用场景 | null 处理 | provider 异常 |
|------|---------|-----------|--------------|
| `accumulateStream()` + 各自 parseLlmJson | 容错模式 | 调用方决定 | 调用方决定 |
| `judgeWithLlm<T>()` | 严格模式 | 抛 configError | 向上抛 |
| `loop.ts` 内联流式 | 主流程（不提取） | N/A（流式 yield） | 重试逻辑包裹 |
