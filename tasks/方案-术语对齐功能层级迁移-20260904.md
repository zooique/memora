## 2. 问题（一句话）

术语统一只改了「名字」，没改「颗粒度」——4 处功能实际挂载层级与其（修正后的）名称声明的层级不一致：**ask 是 step 级气口却实现成 turn 级暂停 + 仅纯文本收尾检测；`onRoundBoundary`/`roundLog`** **是 step 级事件却用 turn 命名并写入 turn 命名的时间轴、被宿主当 turn 摘要消费；停滞检测是多 turn 编排职责却挂在 step 回调；`reflect.loopContinue`** **残留旧「loop=续跑」认识**。

## 3. 对齐原则（名称 ↔ 颗粒度绑定）

**名称必须声明所属层级；功能实现必须落在名称声明的层级。** 三个层级各自收敛：

| 层级                     | 归位职责（唯一真理源）                                                                      | 命名锚                                                         |
| ---------------------- | -------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| **turn（问答闭环）**         | roundId 分配 / 召回注入 / 会话命名 / 答后摘要 reflect / 自审查 / 任务级 SLO / TS-9 交互输入归属            | `processUserInput`/`continueAfterPause`、`Round`（roundStore） |
| **step（一次 LLM 调用+工具）** | LLM 调用+工具执行 / Reflection / 重复拦截 / 气口（提问·暂停·插话）/ 上下文压缩边界 / **stepLog（step 推进记录）** | `runIterationLoop`/`handleIteration`、`stepLog`              |
| **多 turn 编排**          | 难度分级 / 规划 turn / 步 turn 序列 / 收尾汇报 / 任务表 / 会议 S5 / **停滞检测**                       | `externalTaskLoop`/`completeExternalTask`                   |

## 4. 迁移项

### M-A · ask → step 级提问气口（核心）

**现状**：[loop.ts:1156-1191](file:///f:/zooique/memora/src/agent/loop.ts#L1156-L1191) 只在纯文本收尾分支检测 `[ASK]`；工具轮 `[ASK]` 被剥离为 narrate 丢失；暂停以 turn 级穿透宿主 PAUSED。

**迁移目标**：`[ASK]` 在 step 循环任意边界（含工具轮）可识别；提问暂停 = step 级气口（续跑已能回同一 turn 的 step 循环，roundId 不分裂——R2 已证条件具备）。

**落点（最小改动）**：

1. **检测范围前移**：在 `_callAndRoute` 结果路由处统一做 ask 检测（[loop.ts:915-929](file:///f:/zooique/memora/src/agent/loop.ts#L915-L929)）。从 `llmResult.fullContent` **与** `llmResult.pendingNarrate`（工具轮文本）都提取 `[ASK]`，二者取并集。
2. **优先级裁决**：`[ASK]` 优先于工具执行——命中提问先暂停（`question_pending`+`paused`），工具调用保留在 `this.messages`（已有 assistant 消息含 toolCalls），续跑时由 step 循环自然继续执行。**不在提问时丢弃工具调用**。
3. **暂停语义注释收口**：`question_pending`/`onPendingQuestion`/`AskQuestion` 命名保留（已是 step 语义），注释标注「step 级提问气口」，区分「turn 边界=新问答」。
4. **askLimit 口径固化**：明确 askLimit = **每次用户输入（turn）内最多提问次数**（防单次输入被打断过多次），prompt 措辞由「每轮最多提问 N 次」改为「每次回答中最多提问 N 次」，注释标注 turn 粒度（[strategyResolver.ts:500](file:///f:/zooique/memora/src/role-pack/strategyResolver.ts#L500)）。
5. **测试**：新增「工具轮 `[ASK]` + 工具调用并存 → 提问优先、续跑执行工具」用例（[loop.test.ts:2547-2583](file:///f:/zooique/memora/src/agent/__tests__/loop.test.ts#L2547-L2583) 现有纯文本 ask 用例旁）。

### M-B · `onRoundBoundary`/`roundLog` → step 时间轴（`stepLog`）命名 + 颗粒度归位

**现状**：step 级推进事件（每迭代触发）用 turn 命名，写入 turn 命名时间轴，宿主当 turn 摘要消费（R4/R5）。

**迁移目标**：名称对齐颗粒度——LLM 迭代推进记录归 step 命名；turn 级摘要继续由 roundStore（Round 记忆）独立承载，宿主不再从 stepLog 冒充 turn 摘要。

**落点**：

1. **内核命名**：`onRoundBoundary` → `onStepBoundary`（[loop.ts:252](file:///f:/zooique/memora/src/agent/loop.ts#L252)、[loop.ts:908-913](file:///f:/zooique/memora/src/agent/loop.ts#L908-L913)）；`completeRound` → `completeStep`（[sessionManager.ts:1117-1144](file:///f:/zooique/memora/src/agent/managers/sessionManager.ts#L1117-L1144)）；`roundLog` → `stepLog`；`RoundOutcome` → `StepOutcome`（[types.ts:225](file:///f:/zooique/memora/src/agent/types.ts#L225)）。
2. **歧义消解**：roundLog 条目的 `stepId` 字段指向**任务表步骤**（多 turn 编排的步 turn），与「术语 step（LLM 迭代）」同名异义 → 改名 `planStepId`（[types.ts:225](file:///f:/zooique/memora/src/agent/types.ts#L225)、[assembler.ts:330](file:///f:/zooique/memora/src/agent/assembler.ts#L330)）。注释明确两级 step：`stepLog`=LLM 迭代推进；`planStepId`=任务表步骤。
3. **宿主消费**：protocol `stepRounds` → `stepLog`（[protocol.ts:981-982](file:///f:/zooique/memora/hosts/memora-vscode/src/shared/protocol.ts#L981-L982)）；chatPanel/chatView 渲染文案「turn 摘要」→「步骤推进记录」，变量 `stepRounds` → `stepLog`（[chatPanel.ts:2239-2257](file:///f:/zooique/memora/hosts/memora-vscode/src/webview/panels/chatPanel.ts#L2239-L2257)、[chatView.ts:291-307](file:///f:/zooique/memora/hosts/memora-vscode/src/webview/scripts/chatView.ts#L291-L307)、[chatStyles.ts:1158](file:///f:/zooique/memora/hosts/memora-vscode/src/webview/styles/chatStyles.ts#L1158)）。
4. **测试**：更新 [uninterruptedWorkflow.test.ts:469-514 / 1639-1672](file:///f:/zooique/memora/src/agent/__tests__/uninterruptedWorkflow.test.ts#L1639-L1672)、[taskTableRenderer.test.ts:163-199](file:///f:/zooique/memora/src/agent/__tests__/taskTableRenderer.test.ts#L163-L199)、[chatView.test.ts:1474-1527](file:///f:/zooique/memora/hosts/memora-vscode/src/webview/__tests__/chatView.test.ts#L1474-L1527) 的命名与断言。

## 5. 边界（不可破）

| #  | 边界                                                        | 理由                                                                                                              |
| -- | --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| B1 | **不改** **`HandoffDecision='loop'`** **枚举值**               | 代码值非术语，术语统一方案已明确                                                                                                |
| B2 | **不分裂 turn**：ask 续跑延续同一 roundId，不改 TS-9 交互输入归属            | round 记录不因提问/补充分裂（[messageHistory.ts:241-275](file:///f:/zooique/memora/src/agent/messageHistory.ts#L241-L275)） |
| B3 | **不重排已正确层级**：难度分级/会议/任务表/汇报/自审查/暂停插话 全部不动                 | 防过度迁移                                                                                                           |
| B4 | **stepLog 不承载 turn 级摘要**：turn 摘要继续由 roundStore Round 记忆承载 | 两级时间轴职责分离是本方案核心                                                                                                 |
| B5 | **宿主只读消费**：stepLog 语义由内核唯一写入（`completeStep`），宿主只改名不改读法    | 与「plan 是状态真理源，roundLog 是时间轴投影」既有单向引用一致                                                                          |

## 6. 不做的（防过度设计）

- 不做全库逐字替换（沿用术语统一方案纪律）。

- 不把 ask 升级为独立「问题 turn」（提问仍是 step 内气口，不产生 round 分裂）。

- 不为 `understandingConfirm='confirm'` 新建暂停机制（M-D，M-A 后自然复用）。

- 不动 `Round`（roundStore 记忆）命名——它就是 turn 级，命名正确。

- 不引入 step 独立数据结构承载「叙述」——narrate 已有 P2 通道，仅补 `[ASK]` 提取。
