## 二、短板清单（分级）

### 🔴 短板 1 · 装配/配置链路无行为测试（✅ 已补，2026-08-23）

- **证据**：host 侧测试仅 codeExecutor / tracer / workspaceStorage / workspaceSessionStore 四个；[providerStore.ts](../hosts/memora-vscode/src/extension/providers/providerStore.ts)、[llmConfig.ts](../hosts/memora-vscode/src/extension/host/llmConfig.ts)、[assemble.ts](../hosts/memora-vscode/src/extension/host/assemble.ts)、[settingsPanel.ts](../hosts/memora-vscode/src/webview/panels/settingsPanel.ts) 均无单测。
- **影响**：G1 的 `createVectorStore`→注入、G5 的 `createBackgroundProvider`→`setBackgroundProvider`、settingsPanel 的 `cfg_save_embedding` handler——「配置→装配→Agent 生效」链路只被 typecheck/compile 覆盖，未被行为测试锁定。渲染层测得很全，但决定"功能是否生效"的装配层是断言真空。
- **处理**：✅ 已补 `scripts/verifyAssembly.mts`（桩 store + 桩 LLM + 桩 embedding → 真实 Agent 注入验证）。5 项断言全过：`createVectorStore`/`createBackgroundProvider` 配置/未配置分支、以及「无 vectorStore → searchHybrid maxSimilarity=0（纯关键词）」 vs「注入 vectorStore → maxSimilarity≈1（语义路径启用）」。运行：`npx tsx scripts/verifyAssembly.mts`。

### 🟡 短板 2 · G6 安全透明数据源价值偏弱

- **证据**：[chatPanel.ts](../hosts/memora-vscode/src/webview/panels/chatPanel.ts) 的 `bindSecurityAudit` 订阅 `onAudit`；但 `permission=owner + preExecutionCheck 恒放行` 下 `path-deny`/`write-decline` 几乎不触发。
- **影响**：折叠区大概率常年「安全审计 N 次 · 拒绝 0」（全 path-allow），用户无感知增量。属"为对齐而对齐"成分偏多。
- **建议**：可接受（数据源真实存在）；若深入，可改为只在"有拒绝/下降"时突出显示，或补充"本轮文件操作数"而非恒定的通过计数。

### 🟡 短板 3 · G1 向量检索"重启生效"UX 断裂

- **证据**：[settingsPanel.ts](../hosts/memora-vscode/src/webview/panels/settingsPanel.ts) `saveEmbedding` 仅提示"重启插件生效"；vectorStore 装配时注入，无热更新入口（不同于 G5 `setBackgroundProvider`）。
- **影响**：用户保存后无即时反馈，"配置了没生效"困惑；无任何端口确认"是否已生效"（如装配后 vectorSize）。
- **建议**：可接受（Agent 单例重建复杂）；若深入，可在装配成功时提示 `vectorSize`。

### 🟡 短板 4 · ProviderStore 职责膨胀

- **证据**：[providerStore.ts](../hosts/memora-vscode/src/extension/providers/providerStore.ts) 一届 store 累积 provider + backgroundProvider + embedding 三类配置读写 + SecretStorage 多个 key。
- **影响**：`readConfig/writeConfig/SECRET_PREFIX` 耦合加重，结构性累积信号。
- **建议**：当前可接受；若后续再加配置维度应拆工厂而非继续塞。

### 🟢 短板 5 · 后台通道价值无观测

- **证据**：G5 允许选独立后台模型，但无"后台任务实际调用多少次后台模型 / 省多少 token"的观测。
- **影响**：用户难以感知该功能是否兑现（可能选了但后台走缓存几乎不触发）。
- **建议**：UI 有开关、缺"用了没"反馈闭环；可后续补 metrics。

### 🟢 短板 6 · 协议自维护性

- **证据**：六项新增约 10 个协议消息，逐项确认过双向对应，但无一次协议完整性总核对。
- **影响**：靠人工保证两侧（host handler ↔ webview render）一一对应，长期易漂移。
- **建议**：可后续做协议双向消费端核对脚本（非紧急）。
