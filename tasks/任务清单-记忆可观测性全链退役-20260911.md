# 任务清单 — 记忆自动召回可观测性全链退役（纯洁性版）

> 生成时间：2026-09-11
> **设计前提：不考虑历史兼容。** 判据只有一个——
> **代码里是否存在「名字宣称一个机制、而机制已不存在」的结构。** 存在即删，不看谁在读。
> 生成方式：全链 grep + 通读消费点（非推断）。

***

## 零 · 设计公理

清理目标不是「删掉没人用的代码」（那只是副产品），而是：

> **消除「结构性幻觉」——系统的形状在宣称一件已不存在的事。**

三条推论：

1. **「宿主在用」不构成保留理由**，如果它在消费一个恒零值。那叫**幻觉的传播链**，是更该铲的东西。
2. **「以防历史日志看不懂」是伪装成仁慈的技术债**。旧 trace 里出现一个不认识的英文 key，是正确且诚实的行为。
3. **恒零字段的每一层透传都在重复撒谎**。删一半比不删更糟（谎撒到一半，更难察觉）。

***

## B1 · `recalledMemories` 恒空占位符退役

### 目标

删掉一条「四个环节都登记、没有一处读内容」的空信封。

### 实测链路（生产侧全量，非推断）

```
contextPreparer.ts:100   const recalledMemories: Memory[] = [];   ← 定义（恒空）
contextPreparer.ts:187   return recalledMemories;                 ← 原样返回
seed/prepare.ts:93       const recalledMemories = await ...       ← 接收
seed/prepare.ts:96/117   return { input, recalledMemories, ...}   ← 原样透传
seed/orchestrator.ts:83  processUserInput(input, undefined, ...)  ← 传显式 undefined
loop.ts:461              recalledMemories?: readonly Memory[]     ← 声明
loop.ts:466              void recalledMemories;                   ← 读到就扔
```

**关键结构发现**：`orchestrator.ts` 传的是**显式 `undefined`**，不是从 `prepare` 结果取的。
→ **两个占位符从未真正连接**。清理 = **两个独立手术**，不是一条链。

**宿主引用数 = 0**（`grep recalledMemories hosts/ --include=*.ts` 排除 dist）。

### 手术 A · 删 `loop.processUserInput` 第 2 参

| 落点 | 动作 |
| --- | --- |
| `loop.ts:459-466` | 签名 `(userInput, recalledMemories?, signal?, roundId?)` → `(userInput, signal?, roundId?)`；删 `void recalledMemories` 与 4 行注释；类 docstring 删「自动召回注入已退役」段 |
| `loop.test.ts` | 20 处携带第 2 参的调用点重排（7 处纯 `undefined` 占位直接消失） |

**风险控制**：参数重排类型不同（`AbortSignal` vs `string`），**tsc 编译期全量兜底**，不会有漏网。

以下 4 处是「**自动注入退役**」的守卫测试——断言「传入记忆也不会注入」。**删参数后失去被测对象**：

## B3 · `RECALL` / `RECALL_ACTUAL` span 常量退役

### 目标

删掉两个「保留供历史数据显示名」的伪考古资产。

### 实测证据

| 项 | 事实 |
| --- | --- |
| 内核 emit 点 | **零**（`grep TRACE_SPANS.RECALL src/` 非测试 = 0） |
| 宿主消费 | `host/tracer.ts:115/117` switch 标签映射 + `:152` 指纹读取 |
| 宿主测试 | `hostIntegration.test.ts:137` / `tracer.test.ts:17` **刻意构造**该 span 验证标签映射 |

### 纯洁性论证（推翻「保留」结论）

我上一轮建议保留，理由是「跨版本 trace 数据可读性」。**按纯洁性前提，这个理由不成立**：

1. **旧日志里的英文 key 是诚实行为**——它如实反映「当时有这个 span」。映射成中文「记忆召回」反而是在**伪饰**，让用户以为系统在做一件它已不做的事。
2. **span 常量是契约**（`tracer.ts:67` 自述「span 名是宿主监控依赖」）。契约保留一个永不触发的名字，等于**维护一份幽灵 API 清单**。
3. **两处宿主测试在人为制造幻觉**——它们构造一个生产环境永不产生的 span，然后验证它显示成「记忆召回」。**这是自产自销的假测试**。

### 落点

| 层 | 落点 | 动作 |
| --- | --- | --- |
| 内核 | `tracer.ts:69-72` | 删 `RECALL: 'recall.recall'` |

| 内核 | `tracer.test.ts:99/122-123` | 删两处常量断言 |
| 宿主 host | `host/tracer.ts:115/117` | 删两个 switch case（**依赖 B2-a 已删 `:152` 分支**） |
