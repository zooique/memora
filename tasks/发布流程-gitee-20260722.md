# 发布流程文档（闭源分发 · 能用就行版）

> 适用对象：Memora Sprite 宿主（Electron 桌面应用，当前 **Windows 专属**，CI 仅打 Windows 目标；macOS/Linux 暂不打，见 §4 排错）
> 原则：**能用就行** —— 源码可保持私有，**不公开代码也能发版**；不追求代码签名证书、Mac 公证、`electron-updater`、Sentry。
> 第一版目标只有四个：真用户**装得上、打得开、记得住、能更新**。
> 日期：2026-07-22
> 更新：2026-07-29 — 鉴于已跑通 **Gitee→GitHub 私有 push 镜像**，下载与版本检测改走 **GitHub Releases（独立公开发布仓 `memora-sprite-releases`）**：GitHub 单文件 <2GiB 限额对 130MB 充裕、公开仓 `/releases/latest` 免鉴权，无需 Gitee（100MB 卡脖）/ 对象存储。⚠️ 关键约束：push 镜像**只同步 tag 不同步 Releases**（Gitee 官方帮助），且镜像仓必须保持 **private**（否则同步上去的源码泄露、破闭源）；故另建独立公开发布仓只放 exe。详见 §1/§4/§5。此前 2026-07-28 的「对象存储」方案仍可作国内加速备选（见 §4 路线 B）。
>
> 更新：2026-07-29 晚 — 发版已落地 **CI 全自动**：`build.yml` 监听 `v*` tag → **仅 Windows** 构建 → `Publish Release` job 用 `RELEASE_TOKEN` 自动在公开仓建 Release+传 exe，开发者零手动。宿主版本 `1.4.0` / 内核 `2.0.2` 独立维护，发版只升宿主版本。内核改动须先 `npm run sync-memora` 再打包（见 §2.1）。

## 1. 一次性准备（闭源友好，不必开源）

**你不需要公开源码。** 源码留在私有 Gitee 仓库（及其 GitHub 私有镜像），只把构建产物（`.exe`）发到**独立的公开发布仓**。两条承载方式：

**路线 A — GitHub Releases（推荐，承载 exe + 版本检测）**
- 你已有 Gitee→GitHub 的 **私有 push 镜像仓**（代码+tags 自动同步，作备份/同步，**保持 private**）。
- ⚠️ **镜像仓不能设公开**：push 镜像会同步完整源码，一旦公开就泄露闭源代码。
- 因此单独在 GitHub 新建一个 **公开** 仓库（如 `memora-sprite-releases`），**只放 exe + 发布说明，不含源码**。用它的 Releases 做分发与版本检测。
- GitHub Releases 限额（官方）：单个文件 **< 2 GiB**、单 Release 至多 1000 个资产、**总大小/带宽无限制** → 你的 130MB exe 毫无压力（Gitee 的 100MB 卡脖在此消失）。
- 公开仓的 `/releases/latest` API 与附件下载**无需鉴权**，客户端检测+用户下载都不必内嵌 token。

**路线 B — 对象存储直链（可选：国内加速镜像）**
- 若 GitHub 在中国境内下载偏慢，可在腾讯云 COS / 阿里云 OSS / Cloudflare R2 另放一份 exe 直链，作为发布说明里的「国内高速下载」备选。
- 非必须；首版可只用路线 A。

> 闭源下 `PRIVACY.md` 更重要——用户看不到代码，只能靠它 + 运行时证据信你。

2. **填占位符**：下文 `{下载地址}` 换成你的 GitHub 发布页 `https://github.com/{gh-user}/memora-sprite-releases/releases/latest`（路线 A）。
3. **版本号**：沿用宿主 `package.json` 的 `version`（当前 `1.4.0`）。发版升宿主版本（如 `1.4.0`→`1.5.0`）；内核 `2.0.2` 独立维护、无需同步升号。changelog 写明版本说明。

## 2. 构建（本地 Windows）

```bash
cd hosts/memora-sprite
npm install            # postinstall 会跑 electron-builder install-app-deps
npm run package:win    # build:electron + 清理 + 打包
```

- 产物目录：`hosts/memora-sprite/release/`
  - `*.exe` —— NSIS 安装包（给用户）
  - `win-unpacked/` —— 免安装绿色版（备用，上传体积更小但需手动建快捷方式）
- 打包脚本 `scripts/package.mjs` 自带重试与 `win-unpacked.tmp` 残留清理，失败看其输出即可。

> 若只需最快分发，`win-unpacked/` 压缩成 zip 上传也行（用户解压即跑，绕过安装器）。

### 2.1 内核同步（改内核源码后必做 · 极易遗漏）

sprite **不通过 `file:` 依赖**引用内核（避免 Junction 把全量仓库打进 asar）。内核以本地包形式嵌入宿主：

- `scripts/sync-memora.mjs` 负责：编译内核 → 复制 `dist/` + `package.json` + `LICENSE` + `README.md` 到 `hosts/memora-sprite/node_modules/memora/`。
- 修改内核源码后**必须两步**（否则 exe 里是旧内核——`node_modules/memora/dist/` 是独立副本，不随源码自动更新）：
  1. 根目录 `npm run build`（编译内核 dist/）
  2. `node scripts/sync-memora.mjs --no-build`（同步到 sprite 的 node_modules）
  - 或一步完成：`npm run sync-memora`（编译 + 同步）。
- 宿主正常 `npm run build:electron` 也已内含同步内核步骤，可直接用它。

> 发版前若动过内核，务必确认 `hosts/memora-sprite/node_modules/memora/dist/` 是最新编译结果，再 `package:win`。本地 `npm run package:win` 仅作冒烟验证；**真正分发的 exe 由 CI 从 tag 构建**，二者来源不同但产物应一致。

## 3. 发前冒烟测试（关键，别省）

在**另一台**干净 Win 机器（或虚拟机）做，不在开发机：

- [ ] 双击安装 / 解压后能启动，无白屏

本地错误日志建议落到 `userData/logs/`（electron `app.getPath('logs')`），并在"关于"里给个"打开日志目录"按钮。

## 4. 发包（按所选路线）

### 路线 A — GitHub Releases（推荐 · CI 全自动发版）

**架构**：Gitee 主仓 → push 镜像 → GitHub **私有镜像仓**（代码+tags 自动同步，备份，**保持 private**）→ 监听 `v*` tag 触发 `build.yml` → **仅 Windows** 构建 → `Publish Release` job 用 `RELEASE_TOKEN` 把 exe 自动推到 **独立公开仓 `memora-sprite-releases`**（只放 exe，不含源码）。开发者**零手动建 Release**。

**前置（一次性）**
1. GitHub 新建 **Public** 仓库 `memora-sprite-releases`（只放 exe，不要推源码；也不要把私有镜像仓设公开，否则源码泄露）。
2. 在**私有镜像仓** `Settings → Secrets and variables → Actions → New repository secret`：
   - 名 `RELEASE_TOKEN`，值 = **细粒度 PAT**，仅授权 `memora-sprite-releases` 的 `Contents: write`（不要用带完整 `repo` scope 的经典 PAT，否则它也能读写你的私有仓 → 过度授权）。
3. 确认私有镜像仓已有 `build.yml`：`on: push: tags: ['v*']`；job 构建 Windows（`electron-builder --win`）；末尾 `Publish Release` job 用 `RELEASE_TOKEN` 调 GitHub API 建 Release + 上传 `*.exe`。

**每次发版（3 步）**
1. **升宿主版本**：改 `hosts/memora-sprite/package.json` 的 `version`（如 `1.4.0`→`1.5.0`）。
   - ⚠️ 若**改过内核源码**：先 `npm run sync-memora`（编译+同步内核到 sprite 的 node_modules），否则 exe 含旧内核（见 §2.1）。
2. **本地冒烟**（仅验证，分发用 CI 产物）：`npm run package:win` 出 `release/*.exe`，在干净机器装一遍（见 §3）。
3. **提交 + 打 tag + 推 Gitee**：
   ```bash
   git commit -am "release v1.5.0"
   git tag v1.5.0
   git push gitee --tags        # 推 Gitee → 镜像同步 tag 到 GitHub → Actions 自动触发
   ```
   - 无需手动建 Release：镜像同步 tag → `build.yml` 触发 → Windows 构建 → `Publish Release` job 用 `RELEASE_TOKEN` **自动**在公开仓建 Release + 传 exe。
   - 等几分钟（镜像同步最短 5 分钟；或 Gitee「仓库镜像管理」点「更新镜像」立即同步；CI 构建另需数分钟）。
4. **确认发布**：`https://github.com/{gh-user}/memora-sprite-releases/releases/latest` 出现 `v1.5.0` 与新 exe。

> ⚠️ 镜像只同步 **tag**（不同步 Releases 元数据），但 CI 的 `Publish Release` job 会据此**自动**建 Release——开发者无需手动。源码仍在私有 Gitee + 私有镜像仓，**闭源不被破**。

> CI 构建在**私有镜像仓**跑，消耗私有仓 Actions 分钟（GitHub Free 个人账号每月 2000 分钟；当前仅 Windows，单次约 10–20 分钟，余量充足）。公开仓只收最终 exe。

### 路线 B — 对象存储直链（可选：国内加速镜像）
- 若 GitHub 在中国大陆下载偏慢，把同一份 exe 另传到 COS/OSS/R2 设为公开读，在发布说明里加一行「国内高速下载：{直链}」供用户备选。
- 非必须；首版可只用路线 A。

**changelog 模板（用户向，中文）**
```
## 新增
- 本地私有长期记忆：对话自动沉淀，重启不丢
- 输入补全浮窗：打字时召回"你以前说过的"
## 已知问题
- 当前 Windows 体验最佳；macOS 屏幕注入未验证
- 未做代码签名，安装时系统可能提示"未知发布者"，点"仍要运行"即可
- 暂无自动更新，新版本请回发布页（GitHub Releases）
```
> GitHub Releases 单文件 <2GiB、总大小/带宽无限制（官方配额），130MB exe 无压力；"能用就行"，别卡在附件限制上。

### 排错与权限面（CI 全自动发版）

- **RELEASE_TOKEN 权限面**：必须是**细粒度 PAT、仅授权 `memora-sprite-releases` 的 Contents: write**；不要用带完整 `repo` scope 的经典 PAT（会同时获得私有镜像仓读写权 → 过度授权）。只存私有镜像仓的 Actions secret，绝不提交进代码。
- **pino peerDependency（历史 CI 失败）**：`sync-memora` 编译内核时依赖 `pino`（peerDependency），CI 环境若未装会编译失败。确认 `build.yml` 显式安装 pino 或所有 peer deps（`npm ci` 后补 `npm install pino`，或按配置 `--include=optional`）；改内核后若 CI 报找不到 pino，先查这条。
- **Actions 分钟数**：构建在私有镜像仓跑，消耗私有仓配额（GitHub Free 个人账号 2000 分钟/月）。当前仅 Windows，单次约 10–20 分钟，余量充足；若日后加回 macOS（含公证耗时更长）或高频发版，留意配额。
- **macOS / Linux 暂不打**：未签名 macOS 包会被 Gatekeeper 拦截、且屏幕注入未验证；Linux 视需求。等配齐 Apple 开发者证书 + 公证后再在 `build.yml` 加回 macOS 目标（见 §9）。

## 5. 应用内"检查更新"（最小实现 · 2026-07-29 改走 GitHub Releases）

不接 `electron-updater`。下载与版本检测统一走 **GitHub 公开发布仓的 Releases**（路线 A）：GitHub Releases 单文件 <2GiB（130MB 无压力），公开仓 `/releases/latest` API 与附件下载**无需鉴权**，客户端检测不必内嵌 token；同时 Gitee 发行版 100MB 上限、对象存储托管在此都不需要了。

**梯度 A（够用，首版推荐）**：设置/关于里放按钮，直接打开发布页（最新版永远在 `/releases/latest`）：
```ts
import { shell } from 'electron';
shell.openExternal('https://github.com/{gh-user}/memora-sprite-releases/releases/latest');
```
> 不做版本比对——点一下就到最新版页面，用户自行判断是否更新。零风险、零 API。

**梯度 B（比对版本后"有新版才提示"·后续项）** —— 已按「方案A 对抗式评审」修原版坑：

> ⚠️ 修正：
> 1. **版本比较不能用 `!==` 也不能用字符串 `>`**：用下方数值比较器（实测 `"0.10.0">"0.9.0"`=false 漏报、`"1.2.0">"1.10.0"`=true 误报）。
> 2. **只用公开 API，不内嵌 token**：公开发布仓的 `GET /releases/latest` 对匿名用户可用（GitHub 官方：仅请求公开资源时可免鉴权）。在 Node `fetch` 里加 `User-Agent` 头（GitHub API 要求，否则可能 403），无需任何密钥。
> 3. **只打开"发布页"，不解析下载直链**：取到 `html_url` 即 `shell.openExternal(html_url)`，由用户在浏览器里下载（也顺带规避国内 GitHub 直链下载慢的问题——用户可自己选网络）。

```ts
import { app, dialog, shell } from 'electron';

function gtVersion(a: string, b: string): boolean {
  const pa = a.split('.').map(Number), pb = b.split('.').map(Number);
  for (let i = 0; i < 3; i++) {
    const x = pa[i] || 0, y = pb[i] || 0;
    if (x !== y) return x > y;
  }
  return false;
}

const GH_OWNER = '{gh-user}';               // 公开发布仓 owner
const GH_REPO  = 'memora-sprite-releases';
const APP_VERSION = app.getVersion();       // 宿主 package.json version（如 1.4.0）

async function checkClientUpdate() {
  const res = await fetch(
    `https://api.github.com/repos/${GH_OWNER}/${GH_REPO}/releases/latest`,
    { headers: { 'Accept': 'application/vnd.github+json', 'User-Agent': 'MemoraSprite' } }
  );
  if (!res.ok) return;                      // 404=尚无 Release；或匿名限速 60 次/小时/IP（按钮点击足够）
  const rel: any = await res.json();
  const remoteVer = String(rel.tag_name || '').replace(/^v/, '');
  if (!gtVersion(remoteVer, APP_VERSION)) return; // 仅"更新"才提示
  const { response } = await dialog.showMessageBox({
    type: 'info', title: '检测到新版本',
    message: `当前 ${APP_VERSION} → 最新 ${remoteVer}`,
    detail: rel.body || '无更新日志',
    buttons: ['稍后', '前往下载'], defaultId: 1,
  });
  if (response === 1) shell.openExternal(rel.html_url); // 打开 GitHub 发布页
}
```

> **IPC 红线**：复用**已有** `ipcRenderer.invoke` 通道或 `will-navigate` 拦截触发，**不新增** `channels.ts` 条目（见 `STEP-发版前置-PRIVACY与更新检查.md`）。梯度 A 直接用 `<a href>` + `will-navigate`，连 IPC 都免。

**版本策略（桌面客户端 + 内核两层）**
- **桌面客户端（sprite）**：版本号 = 宿主 `package.json` `version`；发版升此版本 + 打 `v{x.y.z}` tag，CI 自动建 GitHub Release 上传 exe（这是端用户看到"有新版"的唯一信号源）。
- **内核（memora）**：走 npm publish（如有）；但**内核打进 asar 随客户端冻结**，端用户要真正用上新内核仍需你出新版 exe（升 sprite 版本 + 新 Release）。
- ⚠️ **"两层更新隔离"是错觉**：仅对**开发者发版流程**成立（改内核只 npm publish）。对**终端用户**，拿内核更新唯一途径仍是重装新版 exe。勿向用户承诺"改内核无需重装"。

> **时效性核验（2026-07-29，联网核实）**：GitHub Releases 限额（单文件 <2GiB、单 Release ≤1000 资产、总大小/带宽无限制，官方文档）对 130MB exe 充裕；`GET /repos/{owner}/{repo}/releases/latest` 对公开仓**可免鉴权**调用（官方：仅公开资源时可不用认证），返回 `tag_name`/`html_url`/`body`，匿名限速 60 次/小时/IP（按钮触发足够）；Gitee→GitHub push 镜像仅同步 分支/标签/提交、**不同步 Releases**（官方帮助），故 Release+exe 须在 GitHub 侧单独建。Electron 40 + electron-builder 26 配置仍适用。

## 6. 反馈与迭代闭环

- **反馈入口**：用 Gitee Issues（私有仓也可开 Issues）或 GitHub 发布仓 Issues；也可加落地页表单 / 邮箱 / 微信群（即时反馈）。
- **首批用户**：5–20 人，从少数派 / V2EX / 即刻 发链接（详见宣发讨论）。
- **必看三数**（验证 R1 前提）：
  - 周激活率（装了且用过 ≥1 次对话）
  - 补全 Top-1 命中率（候选里用户要的那个排第一的比例）
  - 采纳率（唤出补全后真的选了候选）
  - 7 日留存（装后第 7 天还打开）
- 没有这三数，"功能好用"只是自我感觉。

## 7. 隐私白皮书（PRIVACY.md 要点，中文）

下载页 / 落地页放一份，回答用户最大疑虑：

- 所有记忆存**本机 SQLite**，不在任何服务器。
- API Key 只在**你本机**，调用的是**你自己的** LLM 接口。
- 应用**不读取网页内容**，只在你授权时打开浏览器/注入输入。
- 唯一出网：调用你配置的 LLM API（由你的 key，去你的服务商）。
- 可自证：任务管理器/防火墙看进程，除 LLM 域名外无外联。

> 闭源下这是信任命门：用户看不到代码，只能靠它和"进程零外联"的运行时证据信你。可附一张抓包/防火墙截图增强可信度。

## 8. 发版节奏（对抗式）

- **别太碎**：攒一波修一批再发，每次发版写 changelog。手动更新下，发太勤用户懒得回下载页。
- **别 yak-shave**：等签名证书 + 公证 + auto-updater + Sentry 全齐才发 = 永不发版。P0 勾满就发。
- **首版必须含 A1**（冷启动召回），否则首印象崩、R1 验证被污染。
- 真用户数据回来前，**不投**养成脊柱 B 线、主动引擎、persona 影响回复（见方案文件）。
- **闭源信任成本**：隐私定位 + 闭源 = 用户更疑。用 PRIVACY.md + 运行时证据对冲；若验证后要做大，再考虑源码托管/开源。
