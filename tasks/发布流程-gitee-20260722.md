# 发布流程文档（闭源分发 · 能用就行版）

> 适用对象：Memora Sprite 宿主（Electron 桌面应用，当前 Windows 优先）
> 原则：**能用就行** —— 源码可保持私有，**不公开代码也能发版**；不追求代码签名证书、Mac 公证、`electron-updater`、Sentry。
> 第一版目标只有四个：真用户**装得上、打得开、记得住、能更新**。
> 日期：2026-07-22
> 更新：2026-07-28 — ① §5 检查更新已按「方案A 对抗式评审」修正（semver 数值比较替代字符串/不等于、内核层"只通知不送达"illusion 标注、sprite ESM+contextIsolation 适配、零新增 IPC 红线）；② 联网核实 Gitee 发行版单附件 **100MB 硬上限**（官方配额），130MB exe 无法托管其上 → 下载与版本检测改走**对象存储（COS/OSS/R2）** + 极简 `version.json`，删去 Gitee 列表/tag 过滤复杂度。

## 1. 一次性准备（闭源友好，不必开源）

**你不需要公开源码。** 源码留在私有仓库，只把构建产物（`.exe`）发出去。两条路任选：

**路线 A — Gitee 公开"发布专用仓库"（仅反馈 Issues 用，不托管 exe）**
- ⚠️ **Gitee 发行版单附件硬上限 100MB**（官方配额，社区版/企业标准版均 100MB），你的 exe ~130MB **超限、无法作为发行版附件上传**。故 Gitee **只留作反馈 Issues**（见 §6），exe 与 `version.json` 走路线 B。
- 若将来 exe 压到 ≤100MB，可再考虑把发行版附件放回 Gitee。

**路线 B — 对象存储直链（推荐，承载 exe + version.json）**
- 用腾讯云 COS / 阿里云 OSS / 七牛 / Cloudflare R2，上传 `.exe`，设为公开读，拿到直链。
- **无体积上限**、带 CDN、成本极低（几 GB 流量几分钱）。同桶放一个 `version.json`（见 §5）做更新检查。
- 可选：再搞个单页落地页（Vercel / GitHub Pages / 你自己的）放直链 + PRIVACY.md，体验更正式。

> 当前 130MB 体积下**走路线 B**：exe + version.json 同桶，更新检测零 token、零 CORS、无 100MB 限制。Gitee 仅作反馈通道。
> 闭源下 `PRIVACY.md` 更重要——用户看不到代码，只能靠它 + 运行时证据信你。

2. **填占位符**：下文 `{下载地址}` / `{version.json 地址}` 换成你的实际 URL（当前走路线 B：对象存储落地页 / COS-OSS-R2 直链；`version.json` 同桶公开读）。
3. **版本号**：沿用宿主 `package.json` 的 `version`（当前 `1.3.0`）。首版公开 beta 用 `v1.3.0`，changelog 注明"公开测试版"。

## 2. 构建（本地 Windows）

```bash
cd hosts/memora-sprite
npm install            # postinstall 会跑 electron-builder install-app-deps
npm run package:win    # build:electron + 清理 + 打包
```

- 产物目录：`hosts/memora-sprite/release/`
  - `*.exe` —— NSIS 安装包（给用户）
  - `win-unpacked/` —— 免安装绿色版（备用，上传体积更小但需手动建快捷方式）
- 打包脚本 `scripts/package.mjs` 自带重试与 `win-unpacked.tmp` 残留清理，失败看其输出即可。

> 若只需最快分发，`win-unpacked/` 压缩成 zip 上传也行（用户解压即跑，绕过安装器）。

## 3. 发前冒烟测试（关键，别省）

在**另一台**干净 Win 机器（或虚拟机）做，不在开发机：

- [ ] 双击安装 / 解压后能启动，无白屏
- [ ] 能正常对话
- [ ] **重启应用后，上一轮对话仍在**（记忆持久化核心验证）
- [ ] 补全浮窗能唤起、能采纳
- [ ] 人为触发一次错误（如断网调 LLM），确认有本地错误日志落盘，且不闪退

本地错误日志建议落到 `userData/logs/`（electron `app.getPath('logs')`），并在"关于"里给个"打开日志目录"按钮。

## 4. 发包（按所选路线）

**路线 A（Gitee 发布专用仓库 · 仅当 exe ≤100MB 时可用）**
> ⚠️ Gitee 发行版单附件 **100MB 上限**（官方配额），130MB exe 走不了此路线，请直接用路线 B。
1. 在公开仓库 `memora-sprite-releases` 打 tag：`git tag desktop-v1.3.0 && git push origin desktop-v1.3.0`（tag 固定 `desktop-v{a.b.c}` 前缀；推的是**发布仓库**，不是源码私有库）
2. Gitee → **发行版** → **创建发行版**，关联 tag，上传 `release/*.exe` 或 `win-unpacked.zip`，写用户向 changelog（模板见下）
3. 发行版页：`https://gitee.com/{gitee-owner}/memora-sprite-releases/releases`

**路线 B（对象存储直链 · 当前推荐）**
1. 上传 `release/*.exe`（或 zip）到 COS/OSS/七牛/R2，设为公开读，拿到直链
2. 同桶放 `version.json`（更新检测的唯一信号源）：
   ```json
   { "version": "1.3.0", "page": "https://your-cdn.com/download", "notes": "公开测试版" }
   ```
   > `version` 与宿主 `package.json` 对齐；`page` 是用户点击"前往下载"打开的页面（落地页/直链页均可）；`notes` 可选，作更新日志。
3. （可选）落地页放直链 + PRIVACY.md
> 建议在 `hosts/memora-sprite/package.json` 的 `build.win` 设 `"artifactName": "MemoraSprite-Setup-v${version}.exe"`，使产物名含版本、与 `version.json` 对应。

**changelog 模板（用户向，中文）**
```
## 新增
- 本地私有长期记忆：对话自动沉淀，重启不丢
- 输入补全浮窗：打字时召回"你以前说过的"
## 已知问题
- 当前 Windows 体验最佳；macOS 屏幕注入未验证
- 未做代码签名，安装时系统可能提示"未知发布者"，点"仍要运行"即可
- 暂无自动更新，新版本请回下载页
```
> ⚠️ Gitee 发行版单附件硬上限 **100MB**（官方配额），130MB exe 无法作为附件上传——故走路线 B 对象存储（无体积上限）。"能用就行"，别卡在附件限制上。

## 5. 应用内"检查更新"（最小实现 · 2026-07-28 修正）

不接 `electron-updater`。两种梯度，任选。下载与版本检测**统一走对象存储（COS/OSS/R2，公开读）**——Gitee 发行版单附件硬上限 100MB（官方配额，社区版/企业标准版均 100MB），你的 exe ~130MB 超限，不能作为 Gitee 发行版附件托管，故不用 Gitee 托管 exe（Gitee 仅留作反馈 Issues，见 §6）。

**梯度 A（够用，首版推荐）**：设置/关于里放按钮，shell 打开下载页（见 `STEP-发版前置-PRIVACY与更新检查.md` P0-3，零新增 IPC）：
```ts
import { shell } from 'electron';
shell.openExternal('{下载页地址}'); // 对象存储落地页 / 你自己的下载页
```

**梯度 B（比对版本后"有新版才提示打开页"·后续项）** —— 已按「方案A 对抗式评审」修原版坑：

> ⚠️ 修正（2026-07-28）：
> 1. **版本比较不能用 `!==` 也不能用字符串 `>`**：`!==` 会在降级/重装同值不同串时误弹；字符串 `>` 多位数翻车（`"0.10.0">"0.9.0"`=false 漏报，`"1.2.0">"1.10.0"`=true 误报）。用下方数值比较器。
> 2. **只打开"下载页"，不解析下载直链**：用户要的是"有新版→开页"，`version.json` 只放 `version` + `page`，按钮逻辑取到新版就 `shell.openExternal(page)`，比原方案省去资产选择 / CORS / Gitee 列表过滤。

- 对象存储：同桶放 `version.json`（见 §4 路线 B），`GET {version.json 地址}` → 取 `version` / `page` → 数值比对 → 仅当新版才开页。无 token、无 CORS、无 100MB 限制。

```ts
import { app, dialog, shell } from 'electron';

// 数值版本比较器（零依赖，绕开字符串比较坑）
function gtVersion(a: string, b: string): boolean {
  const pa = a.split('.').map(Number), pb = b.split('.').map(Number);
  for (let i = 0; i < 3; i++) {
    const x = pa[i] || 0, y = pb[i] || 0;
    if (x !== y) return x > y;
  }
  return false;
}

const VERSION_URL = '{version.json 地址}'; // 对象存储公开读 URL
const APP_VERSION = app.getVersion();      // 宿主 package.json version（如 1.3.0）

async function checkClientUpdate() {
  const d = await (await fetch(VERSION_URL)).json();
  if (!gtVersion(String(d.version), APP_VERSION)) return; // 仅"更新"才提示
  const { response } = await dialog.showMessageBox({
    type: 'info', title: '检测到新版本',
    message: `当前 ${APP_VERSION} → 最新 ${d.version}`,
    detail: d.notes || '无更新日志',
    buttons: ['稍后', '前往下载'], defaultId: 1,
  });
  if (response === 1) shell.openExternal(d.page || '{下载页地址}');
}
```

> **IPC 红线**：sprite 有「零新增 IPC 通道」治理阈值（129/130）。梯度 B 需渲染层触发主进程检查——务必复用**已有** `ipcRenderer.invoke` 通道或经 `will-navigate` 走 梯度 A，**不要**为更新检查新增 `channels.ts` 条目。首版落地建议先 梯度 A，梯度 B 作为后续项（见 STEP 卡 STEP-3.4）。

**版本策略（桌面客户端 + 内核两层）**
- **桌面客户端（sprite）**：版本号沿用宿主 `package.json` `version`（当前 `1.3.0`）；改 UI/窗口/更新逻辑才升此版本、打包 exe、上传对象存储并更新 `version.json` 的 `version` 字段（这是端用户看到"有新版"的唯一信号源）。
- **内核（memora）**：走 npm publish（如有对外包）；但**内核打进 asar 随客户端冻结**，故内核更新对端用户是**"只通知、不送达"**——要真正用上新内核仍需你出新版 exe（升 sprite 版本 + 更新 `version.json`）。
- ⚠️ **"两层更新隔离"是错觉**：它仅对**开发者发版流程**成立（改内核只 npm publish、不碰 exe）。对**终端用户**，拿到内核更新的唯一途径仍是重装新版 exe。不要向用户承诺"改内核无需重装"。

> **时效性核验（2026-07-28，联网核实）**：Gitee OpenAPI 仍为 v5（spec v5.4.92，2026-07-12 观测），Electron 40 + electron-builder 26 配置（`artifactName` 支持 `${version}`/`${productName}`/`${ext}`）仍适用。但 **Gitee 发行版单附件 100MB 上限**（官方配额）使 130MB exe 无法托管其上 → 下载与版本检测改走对象存储（无体积限制、无 token、无 CORS）。整套比对 + 弹窗逻辑半天搞定。

## 6. 反馈与迭代闭环

- **反馈入口**：路线 A 用 Gitee Issues；路线 B 用落地页表单 / 邮箱 / 微信群（即时反馈）。
- **首批用户**：5–20 人，从少数派 / V2EX / 即刻 发链接（详见宣发讨论）。
- **必看三数**（验证 R1 前提）：
  - 周激活率（装了且用过 ≥1 次对话）
  - 补全 Top-1 命中率（候选里用户要的那个排第一的比例）
  - 采纳率（唤出补全后真的选了候选）
  - 7 日留存（装后第 7 天还打开）
- 没有这三数，"功能好用"只是自我感觉。

## 7. 隐私白皮书（PRIVACY.md 要点，中文）

下载页 / 落地页放一份，回答用户最大疑虑：

- 所有记忆存**本机 SQLite**，不在任何服务器。
- API Key 只在**你本机**，调用的是**你自己的** LLM 接口。
- 应用**不读取网页内容**，只在你授权时打开浏览器/注入输入。
- 唯一出网：调用你配置的 LLM API（由你的 key，去你的服务商）。
- 可自证：任务管理器/防火墙看进程，除 LLM 域名外无外联。

> 闭源下这是信任命门：用户看不到代码，只能靠它和"进程零外联"的运行时证据信你。可附一张抓包/防火墙截图增强可信度。

## 8. 发版节奏（对抗式）

- **别太碎**：攒一波修一批再发，每次发版写 changelog。手动更新下，发太勤用户懒得回下载页。
- **别 yak-shave**：等签名证书 + 公证 + auto-updater + Sentry 全齐才发 = 永不发版。P0 勾满就发。
- **首版必须含 A1**（冷启动召回），否则首印象崩、R1 验证被污染。
- 真用户数据回来前，**不投**养成脊柱 B 线、主动引擎、persona 影响回复（见方案文件）。
- **闭源信任成本**：隐私定位 + 闭源 = 用户更疑。用 PRIVACY.md + 运行时证据对冲；若验证后要做大，再考虑源码托管/开源。
