# 发布流程文档（闭源分发 · 能用就行版）

> 适用对象：Memora Sprite 宿主（Electron 桌面应用，当前 Windows 优先）
> 原则：**能用就行** —— 源码可保持私有，**不公开代码也能发版**；不追求代码签名证书、Mac 公证、`electron-updater`、Sentry。
> 第一版目标只有四个：真用户**装得上、打得开、记得住、能更新**。
> 日期：2026-07-22

---

## 0. 发布就绪清单（P0 勾选）

发第一版前，逐项打勾。未勾满不发。

| ID | 项 | 说明 | 状态 |
|---|---|---|---|
| P0-1 | Win 包可下载 | `release/` 下出 `.exe` 安装包，能通过下载地址装到干净机器 | ☐ |
| P0-2 | 打开不静默崩 | 至少本地错误日志 + 启动自检，杜绝白屏/闪退无提示 | ☐ |
| P0-3 | 手动更新提示 | 应用内"检查更新"按钮 → 打开下载页（见 §4/§5） | ☐ |
| P0-4 | 核心闭环跑通 | 聊天记忆持久化（重启后仍在）+ 补全浮窗可用 | ☐ |
| P0-5 | 隐私白皮书 | 下载页 / 落地页放 `PRIVACY.md`（中文），证明数据不出本机 | ☐ |
| ⚠️ 同乘 | A1 冷启动召回 | **必须随首版一起发**，否则首印象崩、污染前提验证（见 `方案-输入补全加深与记忆养成`） | ☐ |

> 对抗式：P0-1~P0-5 是"能发"的底线；⚠️ 行是"发了不崩首印象"的底线。两者**同时**进第一班构建，不串行排队。

## 1. 一次性准备（闭源友好，不必开源）

**你不需要公开源码。** 源码留在私有仓库，只把构建产物（`.exe`）发出去。两条路任选：

**路线 A — Gitee 公开"发布专用仓库"（推荐，留在 Gitee 生态）**
- 新建一个**公开**仓库（如 `memora-sprite-releases`），里面**只放构建产物 + README + PRIVACY.md**，**不放源码**。
- 源码仍在你的私有仓库。用户能下载、能看到隐私白皮书，但看不到代码。
- 注意 Gitee 发行版附件有单文件体积上限（约百 MB），超限见 §4 兜底。

**路线 B — 对象存储直链（最干净，完全不依赖代码仓库）**
- 用腾讯云 COS / 阿里云 OSS / 七牛，上传 `.exe`，设为公开读，拿到直链直接分享。
- 无体积上限、带 CDN、成本极低（几 GB 流量几分钱）。
- 同桶放一个 `version.json`（见 §5）即可做更新检查。
- 可选：再搞个单页落地页（Vercel / GitHub Pages / 你自己的）放直链 + PRIVACY.md，体验更正式。

> 选哪条都行。路线 A 省事（你已在用 Gitee）；路线 B 更专业、无附件限制、后续自动更新也顺。
> 闭源下 `PRIVACY.md` 更重要——用户看不到代码，只能靠它 + 运行时证据信你。

2. **填占位符**：下文 `{下载地址}` / `{version.json 地址}` 换成你的实际 URL（路线 A = Gitee 发行版页；路线 B = COS/OSS 直链）。
3. **版本号**：沿用宿主 `package.json` 的 `version`（当前 `1.3.0`）。首版公开 beta 用 `v1.3.0`，changelog 注明"公开测试版"。

## 2. 构建（本地 Windows）

```bash
cd hosts/memora-sprite
npm install            # postinstall 会跑 electron-builder install-app-deps
npm run package:win    # build:electron + 清理 + 打包
```

- 产物目录：`hosts/memora-sprite/release/`
  - `*.exe` —— NSIS 安装包（给用户）
  - `win-unpacked/` —— 免安装绿色版（备用，上传体积更小但需手动建快捷方式）
- 打包脚本 `scripts/package.mjs` 自带重试与 `win-unpacked.tmp` 残留清理，失败看其输出即可。

> 若只需最快分发，`win-unpacked/` 压缩成 zip 上传也行（用户解压即跑，绕过安装器）。

## 3. 发前冒烟测试（关键，别省）

在**另一台**干净 Win 机器（或虚拟机）做，不在开发机：

- [ ] 双击安装 / 解压后能启动，无白屏
- [ ] 能正常对话
- [ ] **重启应用后，上一轮对话仍在**（记忆持久化核心验证）
- [ ] 补全浮窗能唤起、能采纳
- [ ] 人为触发一次错误（如断网调 LLM），确认有本地错误日志落盘，且不闪退

本地错误日志建议落到 `userData/logs/`（electron `app.getPath('logs')`），并在"关于"里给个"打开日志目录"按钮。

## 4. 发包（按所选路线）

**路线 A（Gitee 发布专用仓库）**
1. 在公开仓库 `memora-sprite-releases` 打 tag：`git tag v1.3.0 && git push origin v1.3.0`（注意：推的是**发布仓库**，不是源码私有库）
2. Gitee → **发行版** → **创建发行版**，关联 tag，上传 `release/*.exe` 或 `win-unpacked.zip`，写用户向 changelog（模板见下）
3. 发行版页：`https://gitee.com/{gitee-owner}/memora-sprite-releases/releases`

**路线 B（对象存储直链）**
1. 上传 `release/*.exe`（或 zip）到 COS/OSS/七牛，设为公开读，拿到直链
2. 同桶放 `version.json`：
   ```json
   { "version": "1.3.0", "downloadUrl": "https://your-cdn.com/MemoraSprite-1.3.0.exe", "notes": "公开测试版" }
   ```
3. （可选）落地页放直链 + PRIVACY.md

**changelog 模板（用户向，中文）**
```
## 新增
- 本地私有长期记忆：对话自动沉淀，重启不丢
- 输入补全浮窗：打字时召回"你以前说过的"
## 已知问题
- 当前 Windows 体验最佳；macOS 屏幕注入未验证
- 未做代码签名，安装时系统可能提示"未知发布者"，点"仍要运行"即可
- 暂无自动更新，新版本请回下载页
```
> Gitee 发行版附件单文件有体积上限（普通账户约百 MB 级）。超限：改传 `win-unpacked.zip`，或切路线 B 对象存储。"能用就行"，别卡在附件限制上。

## 5. 应用内"检查更新"（最小实现）

不接 `electron-updater`。两种梯度，任选：

**梯度 A（够用）**：设置/关于里放按钮，shell 打开下载页：
```ts
import { shell } from 'electron';
shell.openExternal('{下载地址}'); // 路线A=Gitee发行版页；路线B=COS/OSS直链
```

**梯度 B（稍好，仍简单）**：比对版本号后弹"去下载"：
- 路线 A（Gitee 发布仓库）：`GET https://gitee.com/api/v5/repos/{gitee-owner}/memora-sprite-releases/releases/latest` → 取 `tag_name`
- 路线 B（对象存储）：`GET {version.json 地址}` → 取 `version` / `downloadUrl`

```ts
const APP_VERSION = '1.3.0'; // 取 package.json version
const UPDATE_URL  = '{version.json 地址}'; // 路线A换成 Gitee API 地址
async function checkUpdate() {
  const d = await (await fetch(UPDATE_URL)).json();
  const latest = String(d.version ?? d.tag_name ?? '').replace(/^v/, '');
  if (latest && latest !== APP_VERSION) shell.openExternal(d.downloadUrl ?? '{下载地址}');
}
```
公开仓库 / 公开对象存储均无需 token。比对逻辑几十行，半天搞定。

## 6. 反馈与迭代闭环

- **反馈入口**：路线 A 用 Gitee Issues；路线 B 用落地页表单 / 邮箱 / 微信群（即时反馈）。
- **首批用户**：5–20 人，从少数派 / V2EX / 即刻 发链接（详见宣发讨论）。
- **必看三数**（验证 R1 前提）：
  - 周激活率（装了且用过 ≥1 次对话）
  - 补全 Top-1 命中率（候选里用户要的那个排第一的比例）
  - 采纳率（唤出补全后真的选了候选）
  - 7 日留存（装后第 7 天还打开）
- 没有这三数，"功能好用"只是自我感觉。

## 7. 隐私白皮书（PRIVACY.md 要点，中文）

下载页 / 落地页放一份，回答用户最大疑虑：

- 所有记忆存**本机 SQLite**，不在任何服务器。
- API Key 只在**你本机**，调用的是**你自己的** LLM 接口。
- 应用**不读取网页内容**，只在你授权时打开浏览器/注入输入。
- 唯一出网：调用你配置的 LLM API（由你的 key，去你的服务商）。
- 可自证：任务管理器/防火墙看进程，除 LLM 域名外无外联。

> 闭源下这是信任命门：用户看不到代码，只能靠它和"进程零外联"的运行时证据信你。可附一张抓包/防火墙截图增强可信度。

## 8. 发版节奏（对抗式）

- **别太碎**：攒一波修一批再发，每次发版写 changelog。手动更新下，发太勤用户懒得回下载页。
- **别 yak-shave**：等签名证书 + 公证 + auto-updater + Sentry 全齐才发 = 永不发版。P0 勾满就发。
- **首版必须含 A1**（冷启动召回），否则首印象崩、R1 验证被污染。
- 真用户数据回来前，**不投**养成脊柱 B 线、主动引擎、persona 影响回复（见方案文件）。
- **闭源信任成本**：隐私定位 + 闭源 = 用户更疑。用 PRIVACY.md + 运行时证据对冲；若验证后要做大，再考虑源码托管/开源。
