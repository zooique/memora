## 批2 · 行为修复（改变行为，需测试先行）

### T9 任务表 system 消息迭代累积（P1，已动态实锤）🔴
- **大白话**：每次"调用大模型前"内核都会把任务表塞进上下文，但只有"新一轮问答开始"才打扫卫生。于是一个回合里迭代 5 次 = 上下文里躺着 5 份一模一样的任务表——浪费 token 还给模型灌重复指令。动态验证：迭代 2 次 → 2 条。
- **修法（推荐 A）**：
  - A. 替换式注入：注入前把上一条任务表消息移除（可标记来源或记录引用，同 executionTempSystem 模式——但生命周期是"下一次注入前"而非"turn 入口"）。
  - B. 最小改动：任务表消息标记 executionTemp 且每次注入前先清集合中的任务表条目（注意不要误伤其他 executionTemp 消息）。
- **测试先行**：把临时验证测试转正为回归测试（断言迭代 N 次 → 任务表恒 1 条）。
- **落点**：`src/agent/loop.ts:1094-1098`（注入点）+ `loop.ts:2156-2169` 附近（清理机制）。
- **验收**：新回归测试绿 + 全量测试绿 + `npm run eval:budget:check`（预算快照不漂移）。

### T10 retryable 检测 slice 错位（P2）🟡
- **大白话**：检查"这轮工具有没有可重试错误"时，按"模型原本想调几个工具"来回看消息条数，但实际执行的可能是被截断后的更少数量——多看的那几条会把上一轮的工具结果吸进来，上一轮的错误可能让这轮白多一条反思提示。
- **落点**：`src/agent/loop.ts:1247-1249`：`llmResult.toolCalls!.length` → `effectiveToolCalls.length`。
- **验收**：新增单测（toolStepLimit 截断 + 上轮残留错误 → 本轮不误注入）或变异验证。
