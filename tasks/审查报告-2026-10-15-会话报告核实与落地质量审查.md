### 6.2 真正的缺口只有一个：生命周期

`beforeContent` 在 **confirm / 恢复即注销、扩展重启清空**（`fileChangeTracker.ts:13`）。即：用户一旦点了「确认」，后悔药就没了。主流三家的「改回去」多半发生在确认之后 ⇒ **窗口决策是全部复杂度来源**（台账 405 行已定为唯一拍板点，此判据经本次复核仍然成立）。

### 6.3 三档难度（2026-10-15 用户追问后订正）

> **订正记录**：初稿把「本 turn 内回退（最小形态）」标为**低**，理由是「现有 `revertAll` 已覆盖」——**这个理由是错的**。`revertAll` 的真实语义是「回退**全部未确认**改动、回到**最早**未确认改动之前」，**不是**「回退本 turn」。用户心智（turn = 操作单元）与实现心智（确认 = 批次）**错位**，且 `FileChangeRecord` **根本没有 turn 维度**（字段 = path / relPath / beforeContent / afterContent / mode / writeCount / updatedAt；多 turn 对同文件的写按路径**合并**）⇒「只回退某一个 turn」在现有数据模型里**无法表达**。收回「低」档判定。

| 档位 | 内容 | 难度 |
| --- | --- | --- |
| **A：turn 级分组回退**（用户描述的真实场景） | tracker 加 turn 维度字段 + UI 按 turn 分组 + 单 turn 回退命令。**不解决「确认后仍可回退」** | **中低**（约 1–2 天，纯宿主） |
| **B：确认后仍可回滚** | 加「已确认快照归档轨」，与未确认记录**分离**（防污染现有判据）+ 三方比对（快照 before / 快照 after / 磁盘现状） | 中 |
| **C：跨重启持久化** | 存储轨 + 容量策略 + 清理 | 高；**台账红线明确禁止触发前做**（D6：不预支复杂度） |

**「确认」语义冲突（产品决策，非技术，B 档的真正入口）**：`confirmAll` = 纯内存清理（`discardRecord`，`fileChangeView.ts:912-925`），零成本、无二次确认、用户随手就点 ⇒ 点完快照立即注销。但用户点确认的意图是「这些改动我认可了」，不等于「我担保永不回退」。现状把「我知道了」和「我担保」混为一谈。A 档要么要求用户别点确认（不可靠），要么**重新定义确认语义**（确认 = 我知道了，快照仍保留 N 个 turn）——后者即 B 档入口。

**A 档先决三问**（升档前须答）：① turn 维度字段从哪个事件派生（`step_boundary` / `turn` 边界在宿主侧有现成信号吗）② 同一文件跨多 turn 修改时，「回退 turn N」对 turn N 之前已确认的改动**不碰**、只还原本 turn 引入的部分——按路径合并的记录**拆不出**这个粒度，需 per-turn 记录或 diff 重放 ③ 单 turn 回退的模态确认文案（现有 `revertAll` 的文案是「恢复到尚未接受的改动之前」，turn 级文案语义不同，须重写防误导）。

### 6.4 对抗式提醒：别被「三家都有」带偏

Claude Code / Cline / Cursor 的 checkpoint **多数以 git 仓库为底座**；本项目 tracker 头注释明写设计前提是「**无 git 依赖的文件改动可见性**」。**同样的功能在不同底座上成本完全不同**——要做到主流那种「随时回到任意历史点」，等于自建一个 mini-VCS，与项目「不预支复杂度 / 复杂度守恒」纪律正面冲突。评估难度时**必须扣掉底座差异**，否则会严重低估。

### 6.5 建议（与台账红线一致）

触发（用户真说「改回去」且现有「全部回退」答不了）**之前不动**；触发后第一优先做 **A 档**（turn 维度 + 分组 UI + 单 turn 回退），**同时**把「确认语义」摆上拍板桌（确认是否仍注销快照）——因为它决定 B 档要不要做、以及 A 档的 UI 要不要显示「已确认」分组。升 B 档前须先答三问：① 快照与确认状态如何解耦而不污染现有判据 ② 三方比对不一致时是拒绝还是覆盖 ③ 回滚一个用户已 git 提交的文件如何收场。

> **2026-10-15 拍板结果（用户）**：听完语义澄清与难度评估后，用户明确「**暂时可以不需要这个功能**」⇒ D8 维持观察区**不激活**。原触发条件「用户真实说『改回去』」**作废**（本次对话即反例实证：口头提及后决定不做）；新触发 = 真机使用中出现「全部回退」答不了的回滚需求。台账 D8 条目已同步拍板 + 触发收紧 + §405 失实断言订正。
