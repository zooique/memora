**方案**：
1. 评估 `roundLog` 是否可合并到 `completedToolCalls`
2. 评估 `pauseMeta` 中哪些字段可降级
3. 修改 `constants.ts` 中的 `CURRENT_SCHEMA_VERSION` 和迁移函数

**预估**：-80 行代码，2 小时

## P3 后续（中长期规划）

### 5. MCP 协议支持

**现状**：当前工具注册是硬编码的（`BUILTIN_TOOLS` + `registerTool()`），缺少动态工具发现机制。

**方案**：
1. 设计 `IMCPProvider` 接口
2. 实现 MCP 客户端（通过 stdio/SSE 连接 MCP 服务器）
3. 实现动态工具注册和发现
4. 集成到 AgentLoop 的工具执行管线

**优先级**：高
**预估**：4 小时设计 + 8 小时实现

---

### 6. RAG 管线增强

**现状**：当前召回是简单双通道（语义搜索 + 关键词搜索），缺少：
- 重排序（Re-ranking）
- 上下文压缩
- 多跳推理
- 混合检索的权重调优

**方案**：
1. 设计 `IReranker` 接口
2. 实现上下文压缩模块
3. 实现多跳推理管线
4. 为混合检索添加可配置的权重参数

**优先级**：中
**预估**：6 小时

---

### 7. Agent 可观测性

**现状**：`ITracer` 接口已就绪，但缺少：
- Trace tree（完整调用链追踪）
- LLM token 消耗追踪
- 性能分析（各阶段耗时占比）
- 可视化仪表盘

**方案**：
1. 扩展 `ITracer` 接口，支持 trace tree
2. 在 AgentLoop 关键路径埋点（LLM 调用、工具执行、召回、归档）
3. 实现 token 消耗追踪
4. 提供性能分析报告

**优先级**：中
**预估**：8 小时

### 8. 测试质量审查

**现状**：81 个测试文件，2023 个测试用例。部分测试偏向"覆盖行数"而非"覆盖行为"。

**审查方向**：
1. 识别"纯覆盖行数"的测试（无行为断言）
2. 补充边界条件测试
3. 移除低价值测试（测试实现细节而非行为）
4. 确保核心模块（AgentLoop、SessionManager、ContextManager）的关键路径有完整覆盖

**优先级**：低
**预估**：4 小时
