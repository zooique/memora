# 方案：感知模块与仪表盘模块重整

> **触发**：用户反馈"感知模块和仪表盘模块功能重叠严重"
> **模式**：模块重思（分析 → 设计 → 产出方案文档，不执行代码修改）
> **日期**：2026-07-11

---

## 1. 问题诊断

### 1.1 根因

感知面板从仪表盘中拆分独立时，迁移不彻底，留下三类残留：

| 类别 | 严重度 | 说明 |
|------|--------|------|
| 僵尸 DOM | P2 | 仪表盘 HTML 中 3 个默契度元素永不被 JS 填充 |
| 子渲染器越界 | P2 | DashboardPanelManager 持有 3 个渲染器，DOM 实际在记忆面板 |
| 跨面板副作用 | P3 | 感知面板写对话面板 DOM；状态条跳转目标不匹配 |

### 1.2 功能重叠矩阵

| 重叠点 | 感知面板 | 仪表盘 | 性质 |
|--------|---------|--------|------|
| 默契度徽章 | `#perception-rapport-badge` ✅ 有 JS 填充 | `#dashboard-rapport-badge` ❌ 僵尸 | 迁移残留 |
| 信任度进度条 | `#perception-trust-fill` ✅ | `#dashboard-trust-fill` ❌ 僵尸 | 迁移残留 |
| 熟悉度进度条 | `#perception-familiarity-fill` ✅ | `#dashboard-familiarity-fill` ❌ 僵尸 | 迁移残留 |

> 其余感知功能（情感/上下文/模式/在场/叙事/主动提示）已完全迁移到感知面板，仪表盘无残留。

### 1.3 子渲染器越界详情

DashboardPanelManager 持有 3 个子渲染器，但它们的 DOM 全部在 `panel-memories` 内：

| 子渲染器 | DOM 位置 | 调用入口 | 行数 |
|---------|---------|---------|------|
| PartnerInsightsRenderer | `panel-memories` L518-535 | `memoryController.setupMemoryPanel` L540 | 427 |
| InsightsRenderer | `panel-memories` L498-515 | `memoryController.setupMemoryPanel` L527-540 | 224 |
| HealthDashboardRenderer | `panel-memories` L537-549 | `memoryController.loadHealthDashboard` L560-571 | 195 |

### 1.4 跨面板副作用

| 副作用 | 来源 | 目标 | 问题 |
|--------|------|------|------|
| 精灵状态条文字/颜色 | `perceptionPanelManager.ts` L234-245 | 对话面板 `#sprite-status-text-bar` | 感知面板写对话面板 DOM |
| 状态条点击跳转 | `ui.ts` L621-627 | 跳到仪表盘 | 数据来自感知面板，跳转应去感知面板 |
| 感知面板 CSS | `dashboard.css` L528-813 | 感知面板 DOM | 感知样式错误放在 dashboard.css |
| renderSkills | `dashboardPanelManager.ts` | 设置面板 DOM | 仪表盘管理设置面板 DOM |

## 2. 重整方案

### 2.1 设计原则

- **不做大规模架构重构**：感知面板与仪表盘面板的划分本身合理（感知=精灵对用户的感知，仪表盘=系统运行状态+记忆质量），问题在迁移残留
- **聚焦归位**：清理僵尸 + 越界代码归位 + 副作用修正
- **分阶段独立可回滚**：每个阶段独立提交，可单独回滚

### 2.2 阶段一：僵尸清理（P2，预计变更量小）

**目标**：删除仪表盘中永不被填充的 3 个默契度僵尸 DOM + CSS

| 变更 | 文件 | 内容 |
|------|------|------|
| 删除 HTML | `index.html` L1233-1243 | `#dashboard-rapport-*` 整个 `.overview-rapport` 区块 |
| 删除 CSS | `dashboard.css` L113-171 | `.overview-rapport-*` 58 行样式 |
| 清理测试 | `dashboardPanelManager.test.ts` L109-111 | 移除僵尸 DOM 的测试 setup |

**验证**：TypeScript 编译 + 测试通过 + 仪表盘面板正常渲染

### 2.3 阶段二：子渲染器归位（P2，核心变更）

**目标**：将 PartnerInsightsRenderer / InsightsRenderer / HealthDashboardRenderer 从 DashboardPanelManager 迁出到 MemoryPanelManager

**理由**：这 3 个渲染器的 DOM 全部在 `panel-memories` 内，调用入口在 `memoryController.setupMemoryPanel` 内。归位到 MemoryPanelManager 消除跨面板职责越界。

**变更步骤**：

1. **MemoryPanelManager 新增 3 个子渲染器实例**：
   - `memoryPanelManager.ts` 构造函数中实例化 PartnerInsightsRenderer / InsightsRenderer / HealthDashboardRenderer
   - 复用现有 EventTracker

2. **DashboardPanelManager 移除 3 个子渲染器**：
   - 删除构造函数中的实例化（L186-192）
   - 删除对应的委托方法（`onReloadInsights` / `onReloadHealth` / `repaintOnThemeChange` 中的相关调用）
   - 删除 `cleanup()` 中的相关调用

3. **UIManager 调整委托路径**：
   - `ui.ts` 中将 `this.dashboardPanel.insights.*` 改为 `this.memoryPanel.insights.*`
   - `this.dashboardPanel.healthDashboard.*` 改为 `this.memoryPanel.healthDashboard.*`
   - `this.dashboardPanel.partnerInsights.*` 改为 `this.memoryPanel.partnerInsights.*`

4. **Controller 调整调用路径**：
   - `memoryController.ts` 中原本通过 `uiManager.dashboardPanel` 访问的 3 个渲染器，改为通过 `uiManager.memoryPanel` 访问

**影响文件清单**：

| 文件 | 变更类型 |
|------|---------|
| `memoryPanelManager.ts` | 新增 3 个子渲染器实例 + 委托方法 |
| `dashboardPanelManager.ts` | 移除 3 个子渲染器实例 + 委托方法 |
| `ui.ts` | 调整委托路径（~10 处） |
| `memoryController.ts` | 调整调用路径（~5 处） |

**DashboardPanelManager 行数变化**：962 行 → ~850 行（减少 ~110 行）

**验证**：TypeScript 编译 + 测试通过 + 记忆面板功能正常 + 仪表盘面板功能正常

### 2.4 阶段三：跨面板副作用修正（P3）

**目标**：修正 3 个跨面板副作用

| 副作用 | 修正方案 | 影响文件 |
|--------|---------|---------|
| 状态条跳转目标 | `ui.ts` L624-625 跳转目标从 `'dashboard'` 改为 `'perception'` | `ui.ts` 1 处 |
| 感知面板写对话面板 DOM | 将 `#sprite-status-text-bar/dot-bar` 的写入逻辑提取到 UIManager 统一管理，感知面板通过回调通知 | `perceptionPanelManager.ts` + `ui.ts` |
| 感知面板 CSS 归位 | `dashboard.css` L528-813 的 `.perception-*` 样式迁到 `chat-perception.css`（或新建 `perception.css`） | `dashboard.css` + `chat-perception.css` |

> **排雷修正**：原方案列出 4 项副作用，其中"renderSkills 归位"经验证已由 SettingsPanelManager 承担（`settingsPanelManager.ts` L1531 + `ui.ts` L1216-1217 已正确委托），无需迁移。此项删除。

**验证**：TypeScript 编译 + 测试通过 + 各面板独立渲染正常

### 2.5 阶段四：文档同步（P5）

| 变更 | 文件 | 内容 |
|------|------|------|
| 删除 perceptionRenderer.ts 描述 | `directory-structure.md` | 移除已删除文件的描述，新增 perceptionPanelManager.ts 条目 |
| 修正 dashboardPanelManager 描述 | `directory-structure.md` | 从"持有 4 个子渲染器"改为"概览+运行指标+记忆源健康+增长趋势" |
| 补充子渲染器归属 | `directory-structure.md` | partnerInsights/insights/healthDashboard 补充"由 memoryPanelManager 持有" |
| 修正 chat-perception.css 描述 | `directory-structure.md` | 从"感知面板：情感/默契度/..."改为"对话内嵌感知紧凑布局" |
| 修正 dashboard.css 描述 | `directory-structure.md` | 补充"感知样式已迁至 perception.css" |
| 新增 perception.css 条目 | `directory-structure.md` | 独立感知面板样式（从 dashboard.css 迁出） |

> **排雷修正**：原方案列出"感知面板加入错误体系（`PANEL_IDS` 增加 `'perception'`）"，经验证删除此项。感知面板是推送型数据流（由 IPC 推送 payload，无主动加载失败场景），其他面板（settings/memory/chat/dashboard）需要错误横幅是因为有主动加载数据的失败场景。且感知面板 HTML 无错误横幅 DOM（`perception-error-retry` 不存在），仅改 PANEL_IDS 无实际效果。
