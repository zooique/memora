## T1 🔴 P1 实锤：重放带 question 的 qa 折入残缺（回答块残留消息流）

> **状态：✅ 批次 A 已修复（2026-09-08）**，实测见 ① 执行状态表。

### 现象
重启 / 重放**有任务过程**的轮、且该轮含「LLM ask → 用户答」（G26 带 question 形态）时：
- 折叠块 `.round-block__details` 内只有「问」回顾行（ask 行）；
- 「你答」折叠块 **残留在消息流层**（assistant 块与最终回答之间）→ 两段式「任务折叠块 + 纯文字报告」被污染；
- 折叠摘要缺「你答×N」（refreshRoundBlockQaStats 只数 details 内 `.msg-qa`，details 外不计）；
- 运行时（done 后 foldPending 全量搬）与重放（逐行即时搬）最终 DOM 态不一致——违反定案「运行时 = 重放同构」。

### 复现（已实证，临时用例验证后已删）
构造序列：`user(主) → replay_events(meta+metrics) → assistant(提问段) → user(kind='question-answer', question, options) → assistant(final)`。
断言 `.round-block__details .msg-qa` 长度 = 2（ask 行 + 你答块）→ **实得 1**，红。

### 根因（三层失配，病灶 #1「对称另一半」变体）
1. `appendInlineInputRow`（chatView.ts:2293）带 question 时返回 `qReviewRow ?? details` → 返回的是 **ask 行**；
2. `appendInteractiveInput` 重放即时折入分支（chatView.ts:2169）把 inserted（= ask 行）传给 `moveQaIntoRoundBlock`；
3. `moveQaIntoRoundBlock`（chatView.ts:685-696）成对携带只查「el 的**前**兄弟是 `--ask` 且仍在 messages」（:691-695，注释原文「移动的是回答块」）——传 ask 行时**后置 details 不被带**。

即成对搬运函数的前提是「传入回答块、顺带带前置 ask 行」，而调用方在带 question 时传的是 ask 行 → 方向失配。
无 question 的 qa（inserted = details）天然正确（UX-9 用例绿），恰掩盖了问题。

### 修复（建议方向 b，最小改动，已核对兼容性）
`appendInlineInputRow` 带 question 时也**返回 details**（:2293 恒返回折叠块，不再返回 ask 行）：
- 重放即时折入：`moveQaIntoRoundBlock(rb, details)` 搬 details 时，prev = ask 行且 parentNode === messages → 天然成对搬入（顺序 [ask][details]）✓
- 运行时 done 后 `foldPendingQaIntoRoundBlock` 全量扫路径不依赖返回值：先扫 ask 行搬入（prev 非 ask 不带）→ 再扫 details 时 prev 的 ask 行已在 detailsBody（parentNode ≠ messages）→ 不重复搬，details 自身随后入块（扫描序保序 [ask][details]）✓
- supplement / 无 question qa 返回语义不变 ✓
- 返回值消费者仅 `appendInteractiveInput`（chatView.ts:2164）一处，无其他依赖 ✓

**同步**：`appendInlineInputRow` 顶部返回语义注释（:2198-2199）改为「返回回答折叠块（带 question 时提问行由成对携带一并入块）；supplement 合并进既有块时返回 null」。

### 涉及文件
- `hosts/memora-vscode/src/webview/scripts/chatView.ts`（:2293 + :2198-2199 注释）
- `hosts/memora-vscode/src/webview/__tests__/chatView.test.ts`（补正式用例：复现用例转正）

### 验收
1. 新增用例（转正复现）：重放带 question qa → `.round-block__details .msg-qa` 长度 2、`[0]` 为 `--ask`、`[1]` tag「你答」；`.msg.assistant` 两段相邻（无残留）；折叠摘要含「你答×1」；
2. 既有相关用例全绿：UX-9 重放（:2721）、G26（:2674/:2700）、G31 运行时收敛（:3084）、补充合并（:2759）；
3. 宿主全量 vitest 绿 + `tsc --noEmit` 0 + `eslint --max-warnings 0`。

## T2 🟡 P2 推断成立：同轮连环 ask 的运行时插入倒挂

> **状态：✅ 已修复（批次 C，2026-09-09 落地）。决策拍板：单轮多 ask = 正常需求（用户原话「运行多个 ask，这个是正常需求」）→ 走「允许 → 修复锚」分支。**

> ⚠️ **实证修订（2026-09-09 排雷补证）**：倒挂的直接成因链与排雷推断不同——`resume` 续接**骨架**（prepareFlowShell 建）在用户下次回答提交时被 `user(kind)` 分支 `flowShellEl.remove()`（chatView.ts:3256）移除 → `activeAssistantEl` 悬空回退「最后 .msg.assistant」；而原 fallback 用 `:last-of-type` 选择器受容器 footer（同为 div）干扰**匹配失败 → host=null → 回答行 `appendChild` 消息流尾**——第二轮 QA 散落同轮容器之外（形态断裂），倒挂仅在「无容器/无 footer」轮发生（mutation 实证）。折叠收敛序正确只是「树序巧合」救回。**两类症状同一根因：插入锚静态化、无同轮交互链后移。**

### 现象 / 触发条件
同一 round 内 LLM **多次 ask_user**（连环确认）、用户逐次回答时：第二次问答对经 `host.after()` 插到第一问答对**之前**：

```
运行时：[暂停块][问2][答2][问1][答1]     ← 后插顶前（倒挂，无容器/无 footer 轮）
运行时：[容器][问1][答1] [容器外问2][答2] ← 散落容器外（容器轮，形态断裂）
重放  ：[暂停块][问1][答1][问2][答2]     ← 按 ts 升序（正确）
```

### 实证链（成立性证据）
- 插入锚 `host = activeAssistantEl ?? 最后 .msg.assistant`（chatView.ts:2200-2202）——同 round 连续问答期间 host **不变**（resume 续跑同块，无新 meta 不建新块）→ 二次插入锚仍是首问答对之前；
- `_lastPendingQuestions` 每次 questionPending **覆写**（chatPanel.ts:2194）、handleResume 消费式取最新（:2031-2032）→ 第二次答仍携 question，问答对照常渲染；
- 内核支持同轮多 ask：ask_user 检出 → 整轮挂起（builtinTools.ts:214-221）→ answerQuestion 回填 + resumeExecution 同 round 续跑 → loop 内可再次 ask_user（无单轮上限证据）；
- 重放侧 middle 序列按 ts 升序交织（chatPanel.ts:1848-1864）→ 重放永远有序。

### 修复方向（可选，与 T1 同族但独立）
插入锚从「host 正后」改为「host 后**当前轮最后一个 QA 元素之后**」——维护同轮末位锚（`_lastQaAnchor`，host / roundId / done 变化时重置；与 `_lastInterruptDivider` 同族语义）→ 插入序 = 到达序，天然对齐重放 ts 序。

### ✅ 实施（2026-09-09，落地形态比方向稿更简：**无状态动态锚**）
不引入 `_lastQaAnchor` 维护态（免「对称清理」雷面），改**无状态 helper `resolveInteractionAnchor()`**（chatView.ts:2158-2184）：
- 锚 = assistant 段之后**连续同轮交互元素**末位（问行 `.msg-qa--ask` / 折叠块 `details.msg-qa` / 提问框 `.ask-inline`），遇非交互元素即停；base 失效回退取**最后 `.msg.assistant`**（querySelectorAll 末位——弃用 `:last-of-type`，footer 同为 div 致其恒 null）；
- 消费统一三处（病灶 #2 唯一收口）：`appendInlineInputRow` host（问答/超时行插入）、`renderAskInline` host（**第二次提问框**同样须在首问答对之后）、`resumePending` 骨架 `mountAfter`（取代全范围「最后 .msg-qa」扫描——后者在 QA 已折入 rb / 前轮残留时跨轮误取）；
- 纯 DOM 兄弟链判定、零新状态：运行时 roundId 到 done 才回填不依赖数据；已折入 rb 的 QA 在段内不在兄弟链 → 天然跨轮安全；新正文段渲染后 activeAssistantEl 指向新段即新锚。
- 涉及：`chatView.ts`（helper + 3 消费点）；`chatView.test.ts`（新用例：同轮连环 ask 两问两答——done 前容器归属 4 QA + 消息流层零残留 + done 后 ts 序）。

### 决策前置
先定产品语义：**单轮是否允许多次 ask**（连环确认是否是真实工作流）。
- ✅ 允许（**2026-09-09 用户拍板：单轮多 ask = 正常需求**）→ 按上述修复实施；
- 不允许（产品约束单轮单 ask）→ 内核/宿主补约束 + 本任务降为观察。

### 验收
用例「同轮两问两答」：运行时 DOM 序 = 重放 ts 序 = `[问1][答1][问2][答2]`（含摘要你答×2）。
**实测（2026-09-09）**：新用例先红（容器内 QA 得 2 失 4 → 第二轮散落容器外实锤）→ 修复转绿；mutation（while 恒 false 撤后移）→ 精确转红（问2 顶到问1 前，倒挂实锤）→ 恢复转绿；chatView 175 + chatPanelHistory 29 全绿。

## T4 🟡 设计定案：ask 跳过通道 + 未答可见 + 自动抉择（2026-09-08 用户需求转正）

> 用户需求原话：「ask 的问题**直接文本记录**到对话记录中，然后**记录用户回答情况**，跳过就显示**用户没有回答**就可以了，然后**自动抉择一个最优方案**。」
> 关联：本清单「待决观察 O1」转正（原判设计边界，用户提升为需求）；排雷证据链沿用。

> ⚠️ **实施修订（同日用户第二轮拍板）**：原「跳过**按钮**」通道被否决——「不用加跳过按钮，就是**超时**才触发的选项；当前已经有选项和用户直接输入补充，所以跳过按钮是多余的，只是超时保底」。下文 4.1–4.6 保留为需求演进记录（拍板点 1/2 认可、3 维持边界不变）；**落地形态以 4.7 为准**（kind 命名 `'skipped'` → **`'timeout'`**；宿主 120s 计时兜底；**无任何人工跳过通道**——选项 + 自由输入是仅有的主动通道，超时是保底）。

### 4.1 现状实证（回答「是否已正文记录」）
| 子问题 | 实证结论 | 证据 |
| --- | --- | --- |
| ask 提问正文是否落盘？ | **部分是**：LLM 提问前的正文叙述（说出口的问题）随暂停半截落 `assistantMessage`，续跑后入 `assistantLog`——重放可见 | messageHistory.ts:326-329（appendAssistant 段注释） |
| 结构化 question（提问框显示的那句）？ | **仅在用户回答时**随 `interactiveInputs[].question` 落盘（Round 字段，非正文轨）；**未答 → 不落盘** | roundStore.ts:78-86（question 仅 question-answer 携带）；interruptedWorkflow.test 2854-2859 |
| 显示用户回答情况？ | 答 → 「问回顾行 + 你答折叠块」（运行时/重放同构）；**无「跳过」通道**——只有答 或 停止（停止 = 任务中断，半截正文 + aborted，无「未回答」记录） | renderAskInline（chatView.ts:2418-2490 无跳过按钮）；builtinTools.ts:226-227（ask_user read-only，工具层无 skip 语义） |

### 4.2 设计收敛（第一性裁剪，守 Round 隔离约束）
**载体结论：不改正文轨**（§六完成定义 3：正文不含交互明细；结构化问题不是 LLM 叙述）。「问题直接文本记录」的**用户观感**由「问行渲染」达成——跳过/回答都产生携带 question 的交互记录 → 重放渲染问行于对话流 → 视觉上「问题明文在对话记录中」。单载体 = `interactiveInputs`（自然生长，不新增存储轨）。

**需求 → 机制映射**：
| 需求 | 机制 | 载体/落点 |
| --- | --- | --- |
| 跳过通道 | renderAskInline 增「跳过」按钮（选项区旁）；提交走新 skip 路由 | chatView.ts + protocol |
| 记录「用户没有回答」 | `InteractiveInputKind` 扩 `'skipped'`（roundStore.ts:63）；skip 时内核写一条 kind='skipped' 交互记录（含 question/options，content 空或「未提供回答」） | messageHistory.ts runResume 路径 |
| 自动抉择 | 内核 skip 语义：answerQuestion 同族新分支 `skipQuestion()` → tool result 回填**「用户跳过了此问题，未提供答案；请基于已有信息自行选择最优候选（options 存在时从中选择），并在结果中说明你的选择依据」** → LLM 续跑自动抉择 | agent.ts / builtinTools ask_user 执行路径 |
| 显示形态 | 跳过行 = 与「你答」同构折叠块（tag「你跳过」，body 标注「未提供回答」）；重放 middle 段 `user kind='skipped'` → appendInteractiveInput → 折入 rb（复用 T1 成对搬运） | chatView.ts（appendInteractiveInput 渲染分支） |

**防撒谎红线**：跳过 ≠ 假装用户选了某选项。tool result 必须**明示用户跳过**，由 LLM 自行判断并在结果中交代选择依据——不得注入「用户选择了 X」。这正是用户「自动抉择最优方案」的诚实实现（抉择权在 LLM，但用户未选的事实不伪造）。

### 4.3 边界澄清（跳过 vs 停止 vs 未答）
- **跳过（新通道）**：显式点击「跳过」→ 任务继续，LLM 自动抉择；记录「你跳过了」。
- **停止（现状 interrupted）**：任务中断 → 半截正文 + aborted；**不伪造「未回答」记录**（停止 = 放弃该轮任务，非对单个问题的跳过）。如需「停止后该问仍可回看」，属提问半截正文可见性范围（叙述正文已可见），结构化 question 仍不落盘——维持边界，除非产品要求「停止也补记该问」。
- **未答中止（关会话/切会话）**：同上，pending 轮无 complete 引用，重放按现有孤儿语义处理。

### 4.4 改动面（跨层，批次 C+）
- 内核：`InteractiveInputKind` 扩 `'skipped'`；`skipQuestion()`/resume skip 分支（tool result 注入文案）；messageHistory 写 skipped 交互记录（含 question/options）；类型/契约测试。**涉跨层落盘契约 → 按 ADR 纪律评估补 ADR**。
- 宿主协议：protocol.ts 消息类型（webview → host skip 提交）；chatPanel handleSkip（answerQuestion 同族路由 + post `user kind='skipped'`）。
- webview：renderAskInline 跳过按钮（forceChoose 时也可见——跳过永远可选）；appendInteractiveInput 渲染 skipped 行；chatView.test 用例。
- 文档：SSOT §3.8.5 补跳过形态 + tasks 定案同步。

### 4.5 验收
1. 运行时：提问框有「跳过」→ 点击 → 渲染「问 + 你跳过了」行 → LLM 续跑并在结果说明抉择依据；
2. 落盘：重启/重放后该轮见「问 + 你跳过了」（同构、round-block 内、摘要含跳过计数）；
3. 诚实性用例：tool result 注入含「用户跳过」语义、不含伪造的「用户选择了 X」；
4. 全量内核 + 宿主 vitest 绿、tsc 0、lint 0。

### 4.6 待拍板点（实施前确认）
1. **载体结论**：结构化问题不进正文轨、以「问行渲染」达成可见性（守 Round 隔离）——认可？✅（用户认可）
2. **诚实抉择策略**：跳过时明示 LLM「用户跳过 + 请自行选择并说明依据」，不伪装成用户选了某选项——认可？✅（用户认可；落地为「超时未答」语义，见 4.7）
3. **停止路径**：停止/未答中止不伪造「未回答」记录（维持现有 aborted + 半截正文语义）——认可？✅（维持边界；ask 超时是唯一自动补记「未回答」的通道，停止仍不伪造）

### 4.7 实施修订（2026-09-08 落地，已验收）——超时保底版

**Turn-5 用户拍板**（去跳过按钮）：超时（120s）是唯一兜底触发；选项 + 自由输入为仅有的主动通道；skip 需求语义全部并入超时路径。`skipped` 命名弃用，统一 `timeout`。

### 4.8 遗留观察（超时语义边界，勿过度实现）
- 超时通知文案 `ASK_TIMEOUT_NOTICE` 与 `[ASK_ABORTED]` 占位双份存在（content 落盘 vs tool result）——前者给 LLM 历史上下文、后者是工具回填，语义互补非重复；如需合并须先审 LLM 视角可读性再动。
- `_askTimeout` 仅在 webview 可见期有效（面板关闭无计时）——超时兜底非硬保证，属「尽力而为」UI 保底，符合会话中断孤儿语义；勿升级为内核级超时（跨进程生命周期复杂度不划算）。
