## 1. TL;DR（结论先行）

| # | 现象 | 定性 | 一句话根因 |
|---|------|------|-----------|
| 1 | 任务进度条恒在会话内容底部 | **宿主渲染锚点失效（实锤）** | `mountInlinePlanBoard` 的插入锚点是 `.round-block`，但 v1.8 剪枝后**运行时根本不存在 round-block**（运行时容器是 `.process-flow`），`insertBefore(el, null)` 退化为 `appendChild` → 进度条落到 `.msg-body`/`.msg-footer` **之后** = 助理块最底部 = 会话底部 |
| 2 | 会话结束后光标不消失 | **宿主收口不自足 + 推断：finalizeRound 未跑完** | 光标只有 `finalizeStreaming` ②段会移除，而它有 `if (!streamingActive) return` 前置 guard；且 `onMessage` 无 try/catch，`finalizeRound` 任一步抛错都会让 `finalizeStreaming` 永不执行 |
| 3 | 过程没折进折叠块 | **同上（同源）** | 折叠动作 100% 挂在 `done`/`interrupted` → `finalizeRound()`；只要该链断，运行时平铺容器 `.process-flow` 就留在正文上方不折叠 |

**三现象不是三个独立 bug，是「1 个实锤渲染 bug + 1 条共同的收口链断点」。**

> 用户问「进度条在底部这合理吗？」→ **不合理，是 bug**（实锤，见 §3 P1-01）。设计意图（`chatStyles.ts:1292-1293` 注释）明确写的是「挂在 assistant 块内、**round-block 上方**」，实际行为与之相反。

## 2. Q1 定论（最关键，先钉死）

### 结论：**不能推出。二者不同源，且落盘轨在设计上就不可能含 chunk。**

「落盘 `processEvents` 无 chunk」与「运行时宿主没收到 chunk / 没建 `activeAssistantEl`」是**两条互不相干的轨**。把前者当后者证据，是把「重放轨」误当成「运行时轨」。

#### 2.1 落盘轨：ProcessEvent 联合里**根本没有 chunk 成员**

`src/memory/roundStore.ts:211-276` `export type ProcessEvent =` 全量成员：

```
meta | thinking | memory_added | tool_start | tool_result |
self_review | text_self_review | narrate | thought | step_boundary |
aborted | error | metrics
```

实锤：
- `roundStore.ts:211` 联合起点，`:276` 仍在联合内 → **无 `chunk`、无 `done`、无 `text`**。
- `roundStore.ts:201-202` 注释自陈：「由宿主在 consumeFlow **旁路**从 AgentChunk / 主机事件派生，流结束时附到 `Round.processEvents`」。

#### 2.2 运行时轨：正文 chunk 走 `post({type:'chunk'})`，**从不进 processEvents**

`hosts/memora-vscode/src/webview/panels/chatPanel.ts:2456-2465`：

```ts
if (chunk.type === 'text' && chunk.content) {
  if (chunk.stage === 'self_review') { emitEvent('text_self_review', {...}); continue; }  // :2458-2460
  // 主回答正文 → 走 chunk 消息（markdown 渲染，属内容轨，不属于过程事件）
  this.post({ type: 'chunk', content: chunk.content, ts: firstChunkTs, roundId: chunk.roundId });  // :2465
}
```

实锤：**`text` 类型 chunk 只有 `self_review` 分支会 `emitEvent`，其余一律 `post chunk`，不落盘。**
`emitEvent`（`:2408-2419`）是 processEvents 的唯一入口；`text` 分支从不调它。

#### 2.3 两条轨的映射表（本次实读得出）

| AgentChunk 类型 | → processEvent（落盘） | → postMessage（运行时） | 证据 |
|---|---|---|---|
| `text` (stage=answer) | ❌ 不落 | ✅ `chunk` | `chatPanel.ts:2465` |
| `text` (stage=self_review) | ✅ `text_self_review` | ❌ 不发 chunk（`continue`） | `chatPanel.ts:2458-2460` |
| `tool_start` | ✅ `tool_start` | ✅ `plan_update`（仅任务表工具） | `:2468` / `:2472-2474` |
| `tool_result` | ✅ `tool_result` | ❌ | `:2478` |
| `thinking` | ✅ `thinking` | ❌ | `:2503` |
| `thought` | ✅ `thought`（截断） | ❌ | `:2517-2523` |
| `narrate` | ✅ `narrate` | ✅ `narrate_withdraw`（若 withdrawn） | `:2509-2512` |
| `step_boundary` | ✅ `step_boundary` + 落盘检查点 | ❌ | `:2527-2536` |
| `selfReview` | ✅ `self_review` | ❌ | `:2487` |
| `aborted` | ✅ `aborted` | ❌（流尾统一发 interrupted） | `:2453` |
| `error` | ✅ `error` | ✅ `error` | `:2542-2554` |
| `paused` / `retry` | ❌ | ✅ | `:2499` / `:2490` |
| `done`（内核 `types.ts:109`） | ❌ | ❌ **宿主完全不处理** | for-await 无 `done` 分支 |

#### 2.4 顺带纠正两个「同源误判」

| 团队已有推断 | 判定 | 依据 |
|---|---|---|
| 「落盘 processEvents 没有 chunk → 运行时可能没 chunk」 | ❌ 无效推断 | ProcessEvent 联合无 chunk 成员（`roundStore.ts:211-276`），**任何正常轮都不会有** |
| 「末尾没有 `done` 事件」 | ❌ 同型误判 | `done` 是 `ExtensionToWebviewMessage`（`protocol.ts:422-429`），**不是 ProcessEvent**；宿主在流尾无条件 `post({type:'done'})`（`chatPanel.ts:2626`），落盘轨永远不会有它 |

**Q1 附带结论**：内核 yield 的 `{type:'done'}` AgentChunk 在宿主侧是**完全空转**的（for-await 无分支处理）。宿主自造的 protocol `done` 才是 webview 侧唯一收口信号。这是「同名不同物」的双轨，但**两侧语义一致（都是流结束），不构成 SSOT 违例**，仅建议在 `consumeFlow` 补注释说明「内核 done 由宿主转译为 protocol done」以免后续误读。

## 4. Q3 定论：`text_self_review` 与正文不一致——**设计如此，非 bug**

### 实锤链（三处同向，判据同源）

1. 内核产出：`loop.ts:986-988` — 自审查应答的 text chunk 打 `stage='self_review'`；`types.ts:133` `TextChunkStage = 'answer' | 'self_review'`。
2. 内核持久化：`agent.ts:652-656` —
   ```ts
   // 累积 assistantContent 用于持久化到 history：只累积正常回答（stage≠self_review）。
   if (chunk.type === 'text' && chunk.stage !== 'self_review') {
   ```
   → **自审文本被内核显式排除在 `assistantMessage.content` 之外**。
3. 宿主桥接：`chatPanel.ts:2456-2461` — `stage==='self_review'` → `emitEvent('text_self_review')` + `continue`（**不 post chunk**）。
4. 协议自陈：`protocol.ts:405-406` — 「自审查文本不再走本通道（host 已按 `text_self_review` 过程事件转发，渲染进 round-block § 自审查输出）——chunk 只负责最终答案正文」。

**判定：`chatPanel.ts:2459` 的 emitEvent 与 `protocol.ts:405` 注释完全自洽，二者是同一判据（`stage === 'self_review'`）的写入侧与声明侧，无分裂。**

本轮数据中「917 字符质量评估」vs「3376 字符会议记录正文」= 自审输出与最终答案本就是模型的**两段不同输出**，前者进折叠区、后者进正文。**不是覆盖、不是错配。**

### 这条**不是**现象 3 的根因
现象 3 是「过程（narrate/tool/thought，1356 条中的绝大多数）没折进 round-block」，而 `text_self_review` 只有 1 条、且它在 finalize 后本就落在 round-block 内。二者无关。

## 6. 最小修复建议（只给方案，未改任何代码）

按「不带伤」优先级排序。全部落在**宿主**，内核零改动。

### F1（P0，必做）— 修 inline 看板挂载锚点
- 位置：`hosts/memora-vscode/src/webview/scripts/chatView.ts:248-267` `mountInlinePlanBoard`
- 做法：把 `:262` 的 `const rb = activeAssistantEl.querySelector(':scope .round-block');` + `:263` `insertBefore(inlineEl, rb)`，替换为与 `ensureProcessFlow:748-757`、`ensureRoundBlock:787-796` **字面对齐**的三段式锚点：
  1. `host.querySelector(':scope > .msg-body')` → `insertBefore(inlineEl, msgBody)`
  2. 否则 `host.querySelector(':scope > .msg-ai-label')` → `label.after(inlineEl)`
  3. 否则 `host.prepend(inlineEl)`
- **为什么不带伤**：不新增判据、不新增协议，只是把「插入到正文之前」这一既有意图落到 v1.8 后真实存在的锚点上；且与另外两个容器挂载点收成同一段实现（建议在三处抽一个 `insertBeforeBody(host, el)` 共用，消除第三份漂移）。

### F2（P1）— 让 finalizeStreaming 自足
- 位置：`chatView.ts:2932-2961`
- 做法：把「`body.classList.remove('is-streaming')`」从 ②段（guard 内 `:2950-2955`）提到 ①段（guard 外，与 `:2936-2942` 同级），使 finalizeStreaming 对 done / interrupted / 超时兜底 / 重复调用全部幂等。

### F3（P1）— finalizeRound 结构加固
- 位置：`chatView.ts:3022-3028`
- 做法：`renderRoundBlock(...)` 包 try/catch（catch 记 console.error），`flowEl?.remove()` 与 `finalizeStreaming()` 放 finally，保证「过程平铺必销毁、光标必清」。

### F4（P1）— 收口超时兜底
- 位置：新增，紧邻 `scheduleArchivingFallback`（`chatView.ts:1546-1555`，**已有同构先例**）
- 做法：done/interrupted 之外，对「流已静默 N 秒仍未收口」强制 `finalizeRound()`。语义与既有归档停滞兜底一致，**不引入新的判定真相源**（判定仍是「是否收口」这一既有事实）。

### F5（P1，可观测）— post 丢弃不再静默
- 位置：`chatPanel.ts:1997-1998`
- 做法：`postMessage` 返回 `Thenable<boolean>`；false 或 `_view` 为空时落一条 warn（含 msg.type）。**只加观测，不改任何判据**，用于把 P2-03 从「推断」变成「实锤或排除」。
