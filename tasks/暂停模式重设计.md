# 暂停模式重设计——定版方案（2026-09-05，对抗性收敛）

> 设计原点：暂停的本质是"让我看看清楚再补一句"，不是"中断"。按钮 = 运行模式 flag 的开关，
> UI 直接读 flag 同步视觉，step 边界是 flag 的唯一消费者。零中间态暴露给用户。
>
> 哲学锚点：单一真理源（`loop.pauseRequested` flag）+ 自然生长（复用内核已有能力，宿主层重绑 UI）
>
> 收敛记录：对抗性评估（2026-09-05）收敛了 3 个设计决策——
> 1. paused + 有输入 走 resumeExecution(text) 立即续跑，不走 interject 排队（省待发送区、消除跨 turn 污染）
> 2. 待发送区只在 thinking 态显示（paused 态立即执行无中间态）
> 3. stop 按钮在三个运行态行为一致（thinking=abort / paused=clearCheckpoint / done=无）

---

## 一、状态矩阵（最终收敛版）

二维入口 = **会话状态 × 输入框状态**。6 格覆盖全部交互。

```
                   done（空闲）         thinking（运行中）       paused（已暂停）
               ┌──────────────┬────────────────────┬────────────────────┐
  输入 = 空    │ 发送（禁用）    │ 暂停 · 停止          │ 继续 · 停止          │
               │              │                     │                     │
  输入 ≠ 空    │ 发送（开新turn）│ 发送（排队，待发送区）  │ 发送（立即带补充续跑） │
               └──────────────┴────────────────────┴────────────────────┘
```

### 每格精确语义 + 内核单一路径

| # | 会话态 × 输入 | 按钮组合 | 主按钮行为 | 内核路径 | 备注 |
|---|---|---|---|---|---|
| ① | done + 空 | 发送（disabled） | — | — | syncSendEnabled 加 `done 且 空输入` |
| ② | done + 有 | 发送（实心） | 立即执行开新 turn | `agent.chat(text)` | chatLock 必须空闲 |
| ③ | thinking + 空 | **暂停** / **停止** | 暂停 = toggle flag；停止 = abort 丢弃 | 暂停 `agent.requestPause('user-pause')`；停止 `AbortController.abort()` | flag 翻 UI 立即生效（不等事件） |
| ④ | thinking + 有 | **发送** / 暂停 / 停止 | 进待发送区排队（有窗口） | `agent.interject(text)` → 入 `loop.pendingInterjections[]` | step 边界自动注入为 user 消息；用户撤回 / 修改输入框改内容即可（打字本身就是确认，不需要单独撤回按钮） |
| ⑤ | paused + 空 | **继续** / **停止** | 继续 = 空输入续跑；停止 = 丢弃检查点归回 done | 继续 `agent.resumeExecution(undefined)`；停止 `agent.clearCheckpoint()` + 开新空 turn | 继续 = 翻状态机 PAUSED→RUNNING 后空跑 step |
| ⑥ | paused + 有 | **发送** / 停止 | **立即带补充续跑**（无中间态） | `agent.resumeExecution(text)` | 翻状态机 + 带补充一步到位；补充内容直接注入 runResume input 参数 |

### 三种"发送"路径——语义统一 = 把内容注入执行流

| 运行态 | 发送按钮点击后 | 内核路径 | 注入时机 |
|---|---|---|---|
| done（空闲） | 开新 turn 注入 | `agent.chat(text)` | 立即（chatLock 空闲，直接启动新闭环） |
| thinking（运行中） | 排队等 step 边界注入 | `agent.interject(text)` → push 进 `pendingInterjections` | step 边界消费 splice(0) → appendUserMessage |
| paused（已暂停） | 立即 resume 带补充注入 | `agent.resumeExecution(text)` → runResume(input=text) | resume 入口直接作为 runResume input 参数传递 |

**发送按钮在三种运行态下，语义完全一致 = "把这段内容注入到正在进行的执行流里"。不是"开新 turn"、不是"暂停/继续"——就是注入。**

### 核心设计原则（三条，破则重审）

1. **按钮 = flag 开关，不是闸门**：暂停/继续按钮只写 `loop.pauseRequested` flag，UI 立即读 flag 同步视觉。flag 是单一真理源，没有中间态。
2. **step 边界 = flag 唯一消费者**：loop 在 step 边界读 `pauseRequested` / `pendingInterjections`，读一次清一次。不是按钮控制 step，是 flag 控制下一轮 step 的行为。
3. **发送按钮语义 = "把内容注入执行流"**：done 开新 turn 注入，thinking 排队等 step 边界注入，paused resume 后注入。**三种运行态发送按钮行为语义完全对称**。

## 二、内核现状盘点（零改动承诺）

### 已有能力（100% 复用）

| 能力 | 位置 | 真实方法签名 | 状态 |
|---|---|---|---|
| pauseRequested flag（运行模式单一真理源） | loop.ts L252 | `private pauseRequested = false` | ✅ set true/false 由宿主 requestPause / cancelPauseRequest；step 边界 L745 读一次清一次 |
| requestPause（翻 flag） | agent.ts L757 | `requestPause(reason, source): boolean` | ✅ 置 flag + 注册 pending（SessionStateMachine），返回 false=幂等拒绝 |
| cancelPauseRequest（翻回 flag） | agent.ts L796 | `cancelPauseRequest(): void` | ✅ 清 flag + 清 SessionStateMachine pending |
| isPausePending（宿主可读） | agent.ts L809 | `isPausePending(): boolean` | ✅ 宿主 UI 读此值同步视觉 |
| interject（排队插话） | agent.ts L824 | `interject(content: string): void` | ✅ push 进 loop.pendingInterjections + 持久化 interactiveInputs |
| pendingInterjections 消费（两处） | loop.ts L676 / L753 | `splice(0)` 全清注入 | ✅ L676=LLM done 边界兜底消费；L753=step 边界主动消费；一次性取完所有排队内容 |
| resumeExecution 带输入 | agent.ts L564 | `resumeExecution(input?, signal?, kind?): AsyncGenerator` | ✅ input 非空 = 带补充续跑（作为 runResume input 参数）；input undefined = 纯续跑 |
| resumeExecution 空跑守卫 | agent.ts L580 | `if (resumeStatus !== 'paused') return` | ✅ paused 态才能续跑，避免状态机错配 |
| clearCheckpoint（丢弃检查点） | agent.ts / sessionManager | `sessionManager.clearCheckpoint()` | ✅ 清状态机 + 清 loop.messages + 归回 done |
| AbortController（硬停止） | chatPanel.ts runFlow | `new AbortController()` | ✅ thinking 态 abort 丢弃；paused 态走 clearCheckpoint（因为 _streaming=false，abortController 已释放） |

### 关键内核行为（对抗性评估实锤）

| 行为 | 实锤证据 | 方案影响 |
|---|---|---|
| runResume 复用现有 loop 实例 | agent.ts 用 `this.requireLoop` 同一个 getter；loop 实例从 chat() 到 pause 到 resume 全生命周期不销毁 | pendingInterjections 队列跨 pause-resume 安全（同一个 loop）；**但跨新 turn chat() 会被 resetTurnState 清吗？——核了：resetTurnState 里没有清 pendingInterjections，这是内核已有缺陷，V1 不触（paused 态不走 interject 路径所以零风险）** |
| resetTurnState 不清 pendingInterjections | loop.ts resetTurnState 只清 reflectionCount / lastToolCallsHash / toolResultCache / searchDisabledHintInjected | 内核缺陷（跨 turn 可能残留），但我们 paused 态走 resumeExecution(text) 路径不走 interject，所以**方案零风险** |
| interject 无状态守卫（任何时刻可 push） | loop.ts interject 只做 `this.pendingInterjections.push(content)`，不检查 status | thinking 态 interject 正确（queue 在 step 边界消费）；paused 态我们不走 interject，不用管 |

### 结论：内核零改动。所有重绑在宿主层。

## 三、宿主改动清单（零新文件，自然生长）

### 层 1：协议层（protocol.ts）——零改动

现有 pause / resume / status 消息 + chunk 流完全够用：
- pause / resume：webview→host 双向消息，已有
- status：host→webview `{type:'status', state:'thinking'|'done'|'paused'}`，**继续用三态，不加 pauseRequesting**
- send 按钮点击 → 继续读 input.value → chat / interject / resumeExecution 三选一（宿主侧路由）

### 层 2：chatPanel.ts（宿主面板）——~40 行

#### 2.1 handlePause 变 toggle（改 flag，UI 立即同步）

```typescript
/** 暂停 / 取消暂停 toggle：读 isPausePending 决定行为
 *  flag 驱动 = 单一真理源。点暂停 → flag=true；再点 → flag=false。
 *  step 边界消费 flag 决定挂起还是直接通过。UI 直接读 flag 翻视觉。 */
private handlePause(): void {
  if (!this._agent || !this._streaming) return;
  if (this._agent.isPausePending()) {
    // toggle 回取消（用户反悔）
    this._agent.cancelPauseRequest();
    return;
  }
  const ok = this._agent.requestPause('user-pause', 'user');
  if (!ok) this.post({ type: 'notice', level: 'error', message: '暂停失败' });
}
```

#### 2.2 handleSend 路由升级（三选一分发，语义统一）

现状 handleSend 已经有 interject 分支（L1857-1860）和 paused→resumeExecution 分支（L1865-1870）。**收敛后 pausePending 态 = 覆盖暂停——宿主加 1 行即可**：

```typescript
/** 发送按钮路由（三选一，语义统一 = "把内容注入执行流"）
 *  ① done 有输入 → chat() 开新 turn
 *  ② thinking 有输入 → interject() 排队等 step 边界注入
 *  ③ paused 有输入 → resumeExecution(text) 立即带补充续跑
 *
 *  pausePending 窗口（flag=true 但 step 还没跑完）：
 *  内核 loop._handleInterrupt 顺序 = 先 pauseRequested（挂起）→ 后 pendingInterjections（消费）。
 *  如果 pausePending 期间用户发补充 → interject 入队 + **自动 cancelPauseRequest**（宿主加 1 行）
 *  → step 边界 pauseRequested=false（跳过挂起）→ 直接消费 pendingInterjections → 补充立即注入。
 *  用户发补充 = "我不想暂停了，直接加内容跑"——一行改动覆盖暂停操作，零内核零新机制。
 */
private async handleSend(input: string, skillName?: string): Promise<void> {
  if (!input.trim()) return;
  const agent = this._agent;

  // 已有 interject 分支（L1857）：_streaming=true 时走这个
  // 覆盖 thinking + 有输入 和 pausePending + 有输入 两种场景
  if (this._streaming && this._abortController) {
    this.post({ type: 'user', text: input, ts: new Date().toISOString(), kind: 'supplement' });
    this._agent.interject(input);
    // 新增：pausePending 期间发补充 → 自动取消暂停（一行改动，覆盖暂停操作）
    if (agent.isPausePending()) agent.cancelPauseRequest();
    // 新增：通知 webview 待发送区刷新
    this._pendingQueue.push(input);
    this.post({ type: 'pending_queue_update', items: [...this._pendingQueue] });
    return;
  }

  // 已有 paused→resumeExecution 分支（L1865）
  if (agent.sessionManager?.status === 'paused') {
    this.post({ type: 'user', text: input, ts: new Date().toISOString(), kind: 'supplement' });
    await this.runFlow((signal) => agent.resumeExecution(input, signal, 'supplement'));
    return;
  }

  // 已有 done→chat 分支（原有逻辑不动）
  // ...
}
```

#### 2.3 handleStop 扩 paused 态（硬停止行为一致）

现状 handleStop 被 `_streaming` 门控挡住 paused 态：
```typescript
// 现状：paused 态 _streaming=false → handleStop 空操作
private handleStop(): void {
  if (!this._streaming || !this._abortController) return;
  this._abortController.abort();
}
```

收敛后：thinking 态走 abort（已有），paused 态走 clearCheckpoint：
```typescript
/** 硬停止按钮：三个运行态行为一致
 *  thinking（_streaming=true）→ abort 当前流，丢弃
 *  paused（status=paused, _streaming=false）→ clearCheckpoint 丢弃检查点，归回 done
 *  done → 无停止按钮（UI 隐藏） */
private handleStop(): void {
  // thinking 态：已有路径
  if (this._streaming && this._abortController) {
    this._abortController.abort();
    return;
  }
  // paused 态：新增路径——丢弃检查点 + 归回 done
  if (this._agent?.sessionManager?.status === 'paused') {
    this._agent.sessionManager.clearCheckpoint();
    this.post({ type: 'status', state: 'done' });
    this.post({ type: 'notice', level: 'info', message: '已停止并清空检查点' });
  }
}
```

#### 2.4 handleResumeFromPause 行为不变（空输入续跑）

```typescript
// 现状：handleResumeFromPause 不传 input → resumeExecution(undefined)
// 收敛后：保持不变。paused + 有输入 走 handleSend 里的 resumeExecution(text) 路径，
// paused + 空输入 走 handleResumeFromPause 的 resumeExecution(undefined) 路径
private async handleResumeFromPause(): Promise<void> {
  if (!this._agent) return;
  try {
    await this.runFlow((signal) => this._agent.resumeExecution(undefined, signal));
  } catch (err) {
    this.post({
      type: 'notice',
      level: 'error',
      message: err instanceof Error ? err.message : String(err),
    });
  }
}
```

#### 3.2 syncButtonRow 按钮区域状态机（核心实现）

```typescript
/**
 * 按钮区域 = 输入框状态 × 会话状态 矩阵的 UI 实现
 * SSOT：宿主 status 事件 → setStatus；宿主 postMessage → chatView 同步
 * 输入框状态：chatView 自己维护（syncSendEnabled 已经监听 input 事件）
 */
function syncButtonRow(): void {
  const hasInput = input.value.trim().length > 0;
  const state = currentState;
  const pauseFlag = pauseBtn.dataset.pending === 'true';  // host 通过 post 设置

  // —— 主发送按钮（右侧）——
  if (state === 'done' && !hasInput) {
    // ① done + 空 → 发送禁用
    sendBtn.disabled = true;
    sendBtn.textContent = '发送';
  } else if (state === 'done' && hasInput) {
    // ② done + 有 → 发送（开新 turn）
    sendBtn.disabled = false;
    sendBtn.textContent = '发送';
  } else if (state === 'thinking') {
    // ③④ thinking 态：
    //   hasInput → 发送按钮（排队，带待发送区）
    //   !hasInput → 停止按钮 + 暂停按钮可见
    if (hasInput) {
      sendBtn.disabled = false;
      sendBtn.textContent = '发送';  // 点击 = interject 排队
      stopBtn.style.display = 'none';   // 有输入时隐藏停止（用户想发不想停）
    } else {
      sendBtn.disabled = true;          // 空输入禁用发送
      stopBtn.style.display = '';
    }
    pauseBtn.style.display = '';
    pauseBtn.textContent = pauseFlag ? '取消暂停' : '暂停';
  } else if (state === 'paused') {
    // ⑤⑥ paused 态：
    //   hasInput → 发送按钮（立即 resumeExecution 带补充）
    //   !hasInput → 继续按钮 + 停止按钮
    pauseBtn.style.display = 'none';  // paused 态不需要 toggle（pauseBtn 隐藏）
    if (hasInput) {
      sendBtn.disabled = false;
      sendBtn.textContent = '发送';  // 点击 = resumeExecution(text)
      stopBtn.style.display = 'none';
    } else {
      sendBtn.disabled = false;
      sendBtn.textContent = '继续';  // 点击 = resumeExecution(undefined)
      stopBtn.style.display = '';
      stopBtn.textContent = '停止';
    }
  }
}
```

| A9 | 停止按钮在 thinking/paused 态行为一致 | thinking 点停止 → abort → done；paused 点停止 → clearCheckpoint → done + toast "已停止并清空检查点" |
| A10 | tsc + vitest 全绿 | tsc 0 errors / vitest 101 files / 2602 passed |

## 六、风险点 + 缓解（收敛后）

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | thinking + 有输入时用户想"发送即停止" | interject 排队了，但用户以为是立即执行 | 发送按钮文案 = "发送"，停止按钮单独存在（空输入时可见）。有输入时隐藏停止 = 引导用户先发送补充再决定要不要停 |
| R2 | pausePending 阶段用户 Enter 被挡（并发锁） | flag=true 但 _streaming=true → interject 路径正常。没有问题——status 还没翻到 paused，走 thinking 态路由正确 | 零风险 |
| R3 | resumeExecution 空跑守卫（status !== 'paused' return） | pausePending 阶段 status 还是 running，不会误点"继续"（UI pauseBtn 文案是"取消暂停"不是"继续"） | UI 正确引导，零风险 |
| R4 | pendingInterjections 跨 turn 残留（内核已有缺陷） | resetTurnState 不清 pendingInterjections | **方案零风险**——paused 态走 resumeExecution(text) 路径不走 interject；thinking 态 interject 队列在 step 边界消费后清空（splice(0)），不会残留 |
| R5 | paused 态 clearCheckpoint 后 loop 状态 | clearCheckpoint 会清 sessionManager + 清 loop.messages，但 loop 实例保留。开新 chat() 时用同一个 loop 实例，需要确保 loop 内部状态（messages / pauseRequested）被正确重置 | 核了：chat() 入口会调 resetTurnState() + restoreHistory，messages 会被重建。零风险 |
