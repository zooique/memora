## 一、你现在要做什么（一句话）

**实测跨会话记忆（切片 D）**：让插件 Agent 在 `agent.chat()` 对话结束后，把本轮结论沉淀为摘要记忆（memora"摘要即记忆"），并在**下一次会话/下一次对话**中召回注入，验证"记住设计决策"闭环真实跑通。

## 二、项目架构速览

- **memora = 纯逻辑内核**（Node.js 纯逻辑库，零 native 依赖）。`src/index.ts` 是唯一导出入口，宿主从 `'@zooique/memora'` import。
- **插件 = 薄壳宿主**，在 `hosts/memora-vscode/`。职责：装配（注入 provider + 存储 + 会话）+ Webview UI（只做 UI，走 postMessage）。
- **分层**：extension host（Node）持 Agent；Webview 只渲染；`shared/protocol.ts` 是消息协议单一真理源。
- **依赖方式**：开发期 `"@zooique/memora": "file:../.."`（**不用 npm link**）。

## 三、关键决策（不可违反）

1. **不重复造轮子**：薄壳只做"装配 + UI"，一切 Agent 能力（记忆/召回/摘要）复用内核。
2. **万物皆记忆**：摘要是唯一记忆单元，时间是唯一排序键。
3. **单一真理源**：遇到复杂问题先回到最小单元（单轮问答闭环），不叠加补丁、不引入新机制。
4. **自然生长**：所有改动基于现有文件生长，不推倒重来、不拼凑。
5. **防御式编程反对**：不写掩盖 bug 的容错；系统边界（用户输入/外部 API）才校验。
6. **纪律**：遵循 `.trae/rules/` 下规范；提交前跑 `npm run typecheck` + 相关测试；不做与阶段 1 无关的过度设计。

## 五、memora 关键 API（阶段 1 会用到）

```ts
import { Agent } from '@zooique/memora';

const agent = new Agent({
  projectPath, provider, storage /* IMemoryStorage */, sessionStore /* ISessionStore */,
  permission: 'owner', allowedPaths: [projectPath],
});
await agent.init();

// 流式对话（核心）：内部自动触发召回 + 轮次摘要生成（RoundSummaryGenerator）
for await (const chunk of agent.chat(input) as AsyncIterable<AgentChunk>) {
  if (chunk.type === 'text' && chunk.content) { /* 流式上屏 */ }
}
```

- **召回注入**：`agent.chat()` 内部已按"触发源 = 外部输入"自动执行 recall（单一真理源 §2.2），无需宿主手动调 `recall()`。
- **摘要即记忆**：`RoundSummaryGenerator` 在对话完成后 fire-and-forget 调 LLM 生成轮次摘要并写入 storage（source = `round_summary`，见 `SOURCE_LABELS`）。**这是跨会话记忆的载体**。
- **跨会话召回**：下一次 `agent.chat()`（即使是新会话）会检索已存摘要并注入上下文。
- 更多导出见 `src/index.ts`（`Memory`、`SummaryType`、`SOURCE_LABELS`、`IMemoryStorage`、`ISessionStore` 等）。

## 六、阶段 1 目标与任务（按序执行）

### 任务 A：切片 A 打磨闭环（打开 .md → 侧边栏对话）
- 让面板在打开一个 `.md` 文档时，能感知**当前文档内容**，作为对话上下文（引导 AI 打磨该文档）。
- 参考：`commands/openDocReview.ts` 读取 `vscode.window.activeTextEditor.document` 的 `.md` 内容，注入到对话提示词或 `agent.chat()` 输入。
- 注意 UI 保持现有简洁风格，遵循"主动可见"与激活态反馈。

### 任务 D：切片 D 跨会话记忆实测（本阶段核心）
1. **验证召回注入链路**：首次对话 A 在文档上定下一个设计决策 → 查看 `.memora/memories.json` 是否出现 `source: 'round_summary'` 的记忆条目（说明 RoundSummaryGenerator 生效）。
2. **验证跨会话召回**：新开一个会话/重新对话 B，问一个与决策相关的问题，确认 Agent 能召回 A 的摘要并据此回答（说明摘要即记忆闭环跑通）。
3. **必要缺口才补**：若发现某环节没走通（如摘要未生成、召回未命中），按"最小改动"原则在内核或装配层修复，并记录到 `tasks/已完成任务.md` 与 CHANGELOG。
4. **给跨会话记忆一个可观测的出口**：考虑在面板增加一个"记忆"提示/视图（如显示"本轮已沉淀 N 条记忆"），让开发者**看见**跨会话记忆在工作，而非黑盒。（遵循"主动可见"原则，但不做过度 UI。）

### 出口（完成标准）
- 开发者"打开文档 → 和 AI 聊 → 内容变严谨"闭环跑通（切片 A）。
- 跨会话记得上下文：会话 B 能引用会话 A 沉淀的设计决策（切片 D）。
- `.memora/memories.json` 中确实累积了 `round_summary` 记忆。
- 无回归：`npm run typecheck` 通过，`agent/` 相关测试通过。
