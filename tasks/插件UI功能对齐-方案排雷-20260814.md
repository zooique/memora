## 二、逐步骤排雷推演（不可跳过）

### 步骤 1：P0 模型切换热生效

**推演**：`agent.setProvider()`（[agent.ts](file:///f:/zooique/memora/src/agent/agent.ts#L2187-L2196)）内部有 `assertNotBusy('切换 Provider')` 守卫——**对话进行中（thinking/工具执行/流式生成）调用会抛异常**。原方案未处理此边界。

**雷-1（边界盲区）**：用户在生成中切换模型 → 后端抛错，webview 无提示，且 `pushProviders()` 已把下拉刷成新选中态 → **UI 显示已切换，实际未生效**（重演"UI 误导用户"）。

**雷-2（SSOT/重复定义）**：原方案只说"补调 setProvider"，未指定新 Provider 如何构造。若在 chatPanel 里另写构造逻辑，会与装配时 [assemble.ts](file:///f:/zooique/memora/hosts/vscode-plugin/src/extension/host/assemble.ts) 的 `createDocReviewProvider(providerStore)` 重复——**必须复用同一工厂**，保证装配与热切换单一真理源。

**雷-3（空配置边界）**：用户删光全部 Provider 后切换，工厂可能 throw，需兜底引导。

**修正**：
- `handleSetProvider` 成功后 try/catch 调 `agent.setProvider(await createDocReviewProvider(providerStore))`；
- 失败（busy/无配置）时：webview 提示「对话进行中不可切换模型，请等待完成」/「未配置可用模型」，并**回滚下拉选中态**（恢复切换前 `currentActive` 重新 `pushProviders`）。

### 步骤 2：P1 补可观测性（角色/技能、会话异常、截断、冲突）

**雷-4（设计错位/SSOT）**：原方案拟把 4 类提示统一塞进 memoryBar（2.5s 自动隐藏）。但 memoryBar 语义是「记忆活动提示」，**会话异常是错误级反馈**，混入后：语义混杂 + 2.5s 自动隐藏会吞掉错误信息。

**修正（分级）**：
- **低扰信息**（截断/冲突/归档失败）→ 复用 memoryBar；
- **错误级**（sessionError / resumeFailed / resumeBlocked / pauseTimedOut / guardrailError）→ 独立错误条（复用 error 视觉，但**不插入消息区**，不污染对话历史）。

**雷-5（依赖事实盲区）**：原方案角色标识依赖 `personaSwitched` / `skillMatched` 事件。但插件装配**只用 skill（doc-review/scaffold），不用角色包**——若未启用角色匹配，该事件可能永不触发 → **徽章变死 UI**。

**修正**：角色/技能标识**不依赖事件**，改为从装配的 skill 清单直接渲染静态徽章（doc-review / scaffold），真实可达。

**雷-6（覆盖遗漏）**：`contextTruncated` 常在流式生成中触发，此时 memoryBar 2.5s 会被后续 chunk 渲染覆盖。

**修正**：截断提示放在该轮流式结束后显示，或并入消息区尾部提示。

### 步骤 3：P2 任务表卡片 / 分叉会话

**雷-7（可达性确认）**：task_table_write 由**默认系统提示注入**（[agent.ts](file:///f:/zooique/memora/src/agent/agent.ts#L1022)「如果需要分步完成任务，请使用 task_table_write」）+ 角色包 `task:plan` 映射。插件虽不用角色包，但默认系统提示让 LLM 在复杂任务时**可能**调用 → `taskTableGenerated` 真实可能触发，**非空中楼阁，但频率低**。

**修正**：P2 保留为低优先级；任务表 UI 克制为**只读渲染**（消息区内轻量列表），**不做**接受/丢弃交互（本插件场景无"生成后执行任务"闭环）。

**雷-8（范围蔓延）**：插件会话模型为「当天 main 单会话」，**无日期导航/会话列表 UI**。若硬加分叉入口，用户分叉后**无法在 UI 切回原会话**（只能靠内核 API）→ 死胡同。项目规则「分叉为唯一新会话入口」针对 sprite 主应用（有日期导航），**不必然适用于本插件**。

**修正**：本期**不做**分叉会话；方案中明确「待会话导航能力落地后再评估」。

### 步骤 4：场景外 4 项复核

**雷-9（遗漏-安全）**：`guardrailError` 是安全相关，不应丢进「场景外」。并入 P1 错误级提示通道（规则编译失败时 toast「规则未生效」），低成本高价值。
- `projectSwitched`（单工作区）/ `workProjectionGenerated`（无作品面板）/ `goalDriftDetected`（无暂停确认 UI）确认排除合理。

### 步骤 5：方案级雷区（跨 P0-P2）

**雷-10（合并顺序）**：P0 与 P1 均改 `chatPanel.ts` + `protocol.ts`（可能 + `assemble.ts`）——同文件同编译，**应合并为一个提交**，避免两次重复编译验证。

**雷-11（协议漂移）**：新增消息类型必须集中在 [protocol.ts](file:///f:/zooique/memora/hosts/vscode-plugin/src/shared/protocol.ts) 的联合类型中定义，防止 chatPanel 散落字符串字面量导致漂移；改完跑 `npm run typecheck` 强制对齐。

**雷-12（实现成本递减）**：P1 的 4 类提示中，截断/冲突/归档失败为低频事件，一次性全做收益递减。**P1 分期**：第一波做「角色/技能标识 + 会话异常 toast」（用户最常感知两类）；截断/冲突/归档失败并入后续波次。

## 三、优化后的可执行方案（排雷产出）

### P0 · 模型切换热生效（先做，功能修复）
1. `handleSetProvider` 成功后：`try { await this._agent?.setProvider(await createDocReviewProvider(this._providerStore)); } catch { 提示 + 回滚选中态 }`
2. 复用 [assemble.ts](file:///f:/zooique/memora/hosts/vscode-plugin/src/extension/host/assemble.ts) 的 `createDocReviewProvider`（SSOT，不重复构造）。
3. 失败提示复用 `postMessage` 错误通道，回滚下拉选中态。

### P1 · 补可观测性（第一波：2 类）
1. **角色/技能徽章**：toolbar 标题旁静态渲染当前 skill 名（doc-review / scaffold），装配时确定，不依赖事件。
2. **会话异常错误条**：转发 `sessionError / sessionResumeFailed / sessionResumeBlocked / sessionPauseTimedOut / guardrailError` → 独立错误条（不入消息区）。

### P1 · 后续波（低优先级）
- `contextTruncated` / `conflictDetected` / `archiveFailed` / `boostPersistFailed` → 复用 memoryBar（截断提示流式结束后显示）。

### P2 · 暂缓
- 任务表只读渲染（低频，视真实触发频率再决定）。
- 分叉会话：待会话导航能力落地后评估。

### 验证
- `npm run typecheck`（强制 protocol 联合类型对齐）+ 插件测试；
- 手动：对话中切换模型 → 应提示且回滚；空闲切换 → 生效且后续对话用新模型。
