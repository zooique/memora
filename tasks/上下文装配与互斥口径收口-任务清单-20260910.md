## ③ P0-1 设计（排除集恢复 + 精确化）

**两代既定设计，都指向「动态/精确」，无一代是固定 20**：

* **Gen-1（文档既定）**：`getRecentRoundIds(dialogue.recentRoundCount)` + `getFirstRoundId()` + `getReplacedRoundIds()`
  ——轮数**动态**（预算派生），但仍是「计数 → 取最近 N 轮」，与「视图实际内容」在**截断后**可能不一致。
* **Gen-2（T1，更晚更准）**：`getVisibleRoundIds()` ∪ `getReplacedRoundIds()`（首轮若在视图内已含）
  ——直接取**工作记忆视图**的 `user.roundId` 集合，即「正文已在眼前」的**精确集合**；截断会回写 `messages`，故它天然等于送 LLM 的集合。

**推荐 Gen-2**（精确、零计数、零新常量；Gen-1 是文档最低要求）。若采纳 Gen-2，`getFirstRoundId()` 可随视图自然覆盖（首轮在视图内则已被包含），需实测确认长会话「首轮被截断后显式补入」场景。

**实装方式（候选，执行时定）**：
* **A（推荐）**：provider 改为**无参**，返回 Gen-2 并集；由 loop 维护（loop 是唯一知道「谁在视图」的一方）→ `toolExec.setRecentRoundIdsProvider(() => loop.getExclusionRoundIds())`。
* **B（文档既定口径）**：保留 `(maxRounds) => …` 签名，改传动态 `dialogue.recentRoundCount`（`contextPreparer` 在 prepare 后写入 loop 状态）→ 仍需 `getRecentRoundIds`，精度不及 A。

**连带删除**：`HOT_MEMORY_MAX_ROUNDS` 的排除窗口用法（P1-1 后该常数只剩死用途）。

5. `search_memories` 现有互斥用例测的是**固定 20 口径**，需重写为精确集合口径。

## ⑨ P0-1 执行记录（实锤，2026-09-10）—— 采用 **Gen-2 精确集合**

**方案选择**：§③ 列的 A/B 两案 → 选 **A（Gen-2）**：排除集从「最近 N 轮」（计数代理量）改为**从 loop 工作记忆视图精确派生**。理由：T1（2026-09-01）已是更新的设计意图；零计数、零新常量；`getVisibleRoundIds` 因截断回写 `messages` 天然等于「送 LLM 的集合」。

### 三个必须计入排除的源（不止「视图内」）

1. **视图内轮**（`getVisibleRoundIds`）——正文在眼前。
2. **被替换轮**（`replacedRoundIds`）——正文已被换成摘要，`roundId` 已不在 `messages`，但**摘要已在上下文**；不计则其 round-summary 被二次召回重复返回（P1-2 死写链由此复活为活链）。
3. **在途轮**（`currentRoundId`）——当轮 user 已落 store、尚未进 `messages` 的窗口期。

`getFirstRoundId` **未接线**：其 doc 原语义是 Gen-1 计数口径的补丁（首轮不在「最近 N 轮」内时补入）；Gen-2 下若首轮正文在视图则已被覆盖，**当前无消费者**。保留方法 + doc 说明，不作过度设计（§④ 已要求「改前证明语义」，实测其形态已无消费者）。

### 关键语义（对抗式澄清）

**排除集随截断而变化而非守恒**：轮被截断彻底裁掉 → 退出视图 → 其摘要**重新可召回**（正确：LLM 已看不到该轮任何内容）；轮被第一级替换 → 进 `replacedRoundIds` → 仍排除（正确：摘要已在上下文）。两者共同保证「内容已在上下文 ⇔ 排除」。

## ⑫ P2-3 执行记录（2026-09-10）—— 选 A：双端交叉引用注明

**决策**：萧然选 **A（注明）**，不选 B（统一命名）。理由：两者**基准与语法本不同**（减法预留 vs 乘法保留），强行统一命名是**用一致的命名掩盖不一致的语义**（伪 SSOT）。

**实装**：`budget.ts` `DEFAULT_OUTPUT_RESERVE_RATIO` ↔ `constants.ts` `CONTEXT_TOKENS_BUFFER_RATIO` **双向交叉引用注释**，各写明：
- 所属阶段（装配线 / 截断线）与决策内容（装多少 / 超了砍到多少）；
- 基准（窗口总量）与语法（**预留 15% 减法** vs **保留 90% 乘法**）；
- 明确声明：**二者恰好互余纯属巧合，勿据此推导关联或试图统一**。

**同步文档**：`role-pack-spec.md` 补记 §2「口径分叉（登记）」→「口径分叉（**已注明**，2026-09-10）」，指向源码双向引用。
