# 插件宿主分块生长 · 推进方案（以内核对接面为固定锚点）

> 状态：推进中。本文档定义 VS Code 插件宿主（仓库内唯一宿主）以「内核对接面」为块粒度的自然生长路线，基于当前 v3.0.0 内核现实编写。标注每块「锚点 → 现状 → 生长目标 → 落地动作 → 验收」，作为新对话独立推进的施工依据。
>
> **设计真理源**：[alignment-iteration.md](../hosts/memora-vscode/docs/alignment-iteration.md)（三层对齐种子） · [ADR-VC-001](../.trae/decisions/ADR-VC-001-vscode-plugin-host.md)（薄壳装配边界） · [network-soil-mindset](./..ctios/…) · 内核导出面 [src/index.ts](../src/index.ts)
>
> **天然生长哲学**：**只长「内核已有能力对应」的宿主形态，不凭空加功能、不复刻内核逻辑**。缺点面的补齐顺序由「体验断层 × 内核种子成熟度」决定，每块独立可验证、独立提交。

## 0. 固定锚点：以「内核对接面」为分块粒度

分块的「块」**不按插件文件/UI 界面对分，而按内核导出能力族分**。每一块 = 内核一个可注入/可消费的对接面，宿主只负责薄壳消费它、并将其能力对应地长到 UI。

**为什么按内核对接面分（而非 UI/文件）**：
- 与「内核为种子、插件功能对齐内核、UI 展示对齐插件」三层哲学同构——块天然对齐内核能力，避免按 UI 划分导致的「为凑界面而编造功能」。
- 每块以「内核某个接口已存在」为充分前提，杜绝凭空造轮子。
- 验收可回溯到内核能力本身（该能力是否真实被宿主消费），可量化。

### 三层逐块生长视图

```
网络信息（土壤：搜索最新实现/踩坑）
   ↑ 吸收养分
内核能力族（种子 · 固定锚点 · src/index.ts 导出面）
   ↑ 薄壳消费
插件功能（协议/装配：assemble.ts + chatPanel + protocol.ts）
   ↑ 对齐
UI 展示（webview：chatView/rolesView/memoryView…）
```

## 二、首发块 B8：网页抓取面（补「搜→抓」闭环第二段）

> **✅ 已落地（2026-08-22）**：薄壳装配完成、宿主 typecheck + 132 测试 + 内核 2446 测试全绿。装配时顺手对齐了会话显示名（内核补导出 `getSessionDisplayName`，宿主 `title`→`displayName`）。
>
> **为什么首发**：B8 是 B6（已长成）的**相邻面**，最能体现「内核面相邻自然生长」——搜索面已长成、抓取面正是其天然延伸；零安全边界顾虑、开箱即用（内核内置 `FetchWebFetchProvider`），风险最低，能最快让宿主跑通「搜索→读正文→提炼」完整链路。

### 2.1 当前真实现状（2026-08-22 实测）

| 项 | 现状 |
|---|---|
| 内核接口 | `IFetchProvider.fetch(url, options?): Promise<FetchedPage>`（src/web-fetch/types.ts） |
| 内核默认实现 | `FetchWebFetchProvider`（Node 内置 fetch，10s 超时，50KB 原始截断，8KB 正文截断，零依赖） |
| 内核注入点 | `AgentOptions.fetchProvider?: IFetchProvider`（src/agent/types.ts L523）；未注入则 `web_fetch` 工具不暴露给 LLM |
| 宿主装配 | `assemble.ts` 注入了 `webSearchProvider: new FetchWebSearchProvider()`，**并已注入 `fetchProvider: new FetchWebFetchProvider()`（2026-08-22 落地）** |
| 结果 | 宿主已能 web_search，**web_fetch 亦可用**——「搜→抓」闭环两段走完 |

### 2.2 生长目标

宿主从「能搜索」长成「搜索后能读网页正文」，让 LLM 基于真实页面内容回答，而非仅靠标题/摘要。

### 2.3 落地动作（薄壳装配，零内核改动）

1. **注入默认实现**（src/extension/host/assemble.ts）：`AgentOptions` 增加 `fetchProvider: new FetchWebFetchProvider()`（从 `@zooique/memora` 导入）。
2. **（可选增强，非首发必需）专用实现**：内核注释建议生产宿主用渲染/代理/限流服务。首发用默认实现即可验证闭环；后续如遇站点反爬/JS 渲染需要，再实现宿主专用 `IFetchProvider`。

### 2.4 验收

- 装配后内核暴露 `web_fetch` 工具给 LLM（`ToolExecutor` 工具清单可见）。
- 对话中输入含 URL 的提问（如「打开 xxx.com 并总结」），web_fetch 卡片出现并在 UI 呈现「抓取中 → 成功/失败」。
- 失败降级不中断对话：`safeFetch` 返回降级页文案、UI 提示抓取失败。
- 全量检查通过（typecheck + 测试）。

### 2.5 涉及文件

- 读：`src/extension/host/assemble.ts`（唯一改动点）
- 测：`scripts/verifyDocReview.mts` 或新增 `scripts/verifyWebFetch.mts`（确认 web_fetch 暴露）

## 三、后续块（按优先级推进，每块独立验证）

### B3 会话生命周期分叉（✅ 已长成，2026-08-22）
- **锚点**：`SessionManager.forkSession` → `Agent.forkSession(): Promise<AgentForkResult>`（src/index.ts 已导出类型）。
- **动作**：标题条新增「分叉」入口 → 调 `agent.forkSession()` → 以新会话继续。零内核改动。
- **落地**：协议 `fork_session` + `forkCurrentSession()` + 标题条分叉按钮 + 测试。宿主 `copySession` 已实现，fork 前置就绪。

### B7 代码执行面（待安全决策后推进）
- **锚点**：`ICodeExecutionProvider`（src/code-exec/types.ts）+ `safeExecuteCode`（带超时/限流保护）。
- **决策门槛**：代码执行是**强能力**，需先敲定沙箱边界（允许哪些 fs/网络/进程/内存上限）。可用宿主 Node 环境实现受限执行器，或用 `safeExecuteCode` 包装。**首波不含，待 product 拍板。**

### B9 可观测补齐（✅ 透明面板 trace 展示已落地，2026-08-22）
- **锚点**：`ITracer` + `AgentMetrics` + `trace_summary` 可见性（`TRACE_SUMMARY_TOOL` 已导出）。
- **动作**：透明面板补 `trace` 展示、 trace_summary 工具按需可见性开关。
- **落地**：`vscodeTracer.getRecentTraces()` 暴露 ITracer span 缓冲 → `metrics` 协议加 `trace` → `chatPanel.postMetrics()` 随 `memora.showMetrics` 推送 → `chatView` 渲染「操作流」。零内核改动，typecheck + 139 测试全绿。
- **未长（可回退纪律）**：trace_summary 开关缺内核独立钩子（仅 `setToolWhitelist` 由角色包能力驱动），Anchor 先行不成立，待内核提供对接面后再补。

### B4 记忆语义检索（低优先级，最重）
- **锚点**：`JsonVectorStore` + `EmbeddingProvider`（OpenAI 兼容 /embeddings）+ `recall` 混合权重。
- **门槛**：需用户配置 embedding 端点（新增模型配置维度），改动面广。放最后。

### B-演示 端到端演示链路（✅ 已落地，2026-08-22）
- **锚点**：`Agent.chat()`（AsyncGenerator）流式契约 + `assembleAgent` 薄壳装配 + `ITracer.getRecentTraces`。
- **背景**：用户目标「插件完全对齐内核 + 可测试能展示内核能力」。对账导出面确认功能对齐仅剩 B4/B7 缺失；但展示重构的关键缺口在**无一键触发的端到端链路**（此前只有散点命令，未串起多能力）。
- **落地**：`memora.demo` 命令 → 全局隔离演示区 `~/.memora-demo` 装配独立 Agent（不传 sessionStore，独立 projectPath → 独立 dataDir/记忆/注册表，绝不污染工作区）→ 注入编排提示词 → `for await` 消费 `chat()` 按 chunk 类型写 Output Channel → 结束 dump 操作流。
- **展示覆盖**：角色包（独立装配内置角色）· loop（handoff 续跑）· 记忆（召回 + 收尾沉淀）· 工具（web_search→web_fetch→write_file→read_file 多步）· 可观测（操作流 + 指纹 + 指标）。
- **结果**：typecheck 零错 + 139 测试全绿。零内核改动、零新 UI，符合 ADR-VC-001 薄壳纪律。

## 四、生长纪律（每块统一仪式）

1. **锚点先行**：块的充分前提是「内核某接口已存在」，先对账内核导出面，杜绝造轮子。
2. **薄壳注射验证 → GUI 对齐 → 测试 → 独立提交**：先让内核能力真实被宿主消费，再长对应 UI；任何一块不触碰薄壳装配边界、不复刻内核逻辑。
3. **相邻生长优先**：优先长「已长成面」的相邻缺口（B8←B6），形成自然连贯生长而非跳跃补缺。
4. **克制**：每块只做「内核有、宿主无」的最小补齐，不做范围外"顺手优化"。
5. **可回退**：探索期投票不进 ADR、不占编号；待真实场景稳定消费后再评估是否需要固化（遵循 exploration-decision-sedimentation-rules.md）。
