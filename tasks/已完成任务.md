**关键设计**：

- 文件路径格式：`<dataDir>/topics/<YYYY-MM-DD>-<topic>.md`
- 文件结构：YAML frontmatter（date/topic/summary/keywords）+ `# title` +
  `## [role] timestamp` 消息列表
- 追加策略：读 → 改 → 写（避免文件锁；用 `writeFile` 覆盖）
- 解析策略：零宽先行断言 `split(/(?=^## \[)/m)`——保留 `## [`
  前缀，让正则一次匹配整条消息头+内容
- 多行消息：content 字段允许 `\n`——序列化时靠空行作消息边界，解析时用
  `[\s\S]*` + trim 容错

**文件改动**：

- 新增：`src/memory/topic-store.ts`（200 行）
- 新增：`src/memory/__tests__/topic-store.test.ts`（130 行）
- 修改：`src/memory/types.ts`（抽出 TopicMessageSchema）
- 修改：`src/cli/repl.ts`（接入 TopicStore + 新增 2 个指令 + 用户/Agent 消息追加）

**关键 Bug 修复**：

- `parseMessages` 原实现用 `split(/\n## /)` 分割，首条消息以 `## ` 起头但前面无
  `\n## `，导致整段当成首条消息的一部分被截断或匹配失败
- 改用 `split(/(?=^## \[)/m)` 零宽先行分割 + 整段正则
  `^## \[(role)\]\s+(.+?)\n([\s\S]*)$` 一次匹配，干净利落

**验证证据**：

- 单条 append → 文件包含 frontmatter + 标题 + `## [user] ...` + 内容
- 多条 append → 第二条不被覆盖，2 条消息都正确读取
- 类型校验：TopicMessage 独立可作为 zod schema 复用
- 测试覆盖：创建/追加/读取/不存在/列出/反序列化 frontmatter/多行内容/工具函数
