## 2026-08-28 · 中断轮保存修复（P1：半截回答不落盘 + F-1 分叉点错位同治）

> 来源：用户实测定回归——回答途中点击停止，该问答闭环**未保存**。排查定位为内核 consumeExecutionStream 中断路径返回值错误，与上轮审查归档的 F-1（interrupted 分叉点错位）**同源根因**。

- **根因**：真实 LLM 流式 abort 抛 `AbortError`（fetch stream 中断）→ `consumeExecutionStream` catch 分支返回 `{ aborted: false, failed: true }`（agent.ts catch 中 aborted 未置位）→ `act()` 首行 `if (streamResult.failed) return` 短路 → 专门为中断写的「半截内容 + [已中断] 标记 appendAssistant」分支（orchestrator.ts L240-252）永不执行 → 轮次停在 pending 孤儿（refCount=0）不登记 → 会话无本轮。
- **修复**（agent.ts consumeExecutionStream）：AbortError 分支返回 `{ aborted: true, failed: false }`——中断是用户主动行为非失败，与类型注释语义对齐。修复后中断轮经 `act()` aborted 分支走 appendAssistant 落盘 + roundId 登记。
- **同治 F-1**：中断轮登记后，host 的 `latestRoundId`（sessionRoundIds 末尾）即本轮，interrupted 分叉点从「退到上一闭环」修正为「本轮」。
- **测试**：新增 `AbortThrowingProvider`（chunk 间检测 signal.aborted 抛 DOMException AbortError，模拟真实 fetch stream 中断，区别于既有 `AbortableMockProvider` 的 loop 边界路径）；新用例验证「已产出文本保留 + [已中断] 标记」。修复前该用例必红（history 无 assistant 消息）。
- **验证**：内核 vitest 全量 2485 绿（1 skip）。
