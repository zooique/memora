## 2026-08-26 · 会话管理 + 宿主-内核循环边界 SSOT 收紧

> 复测反馈驱动的根治：VSCode 插件会话管理表现为「历史无名字/无法切换」「普通问答自动续跑 N 轮到触顶」「会话名被命名为『继续任务』」「归档记忆指示灯不停闪烁」。

**根因（SSOT）**：宿主在 `handoff=loop` 时伪造用户输入 `chat('继续任务')` 二次进入 chat 管道——形成第二套循环引擎，且 prepare 把合成输入当真实用户轮，`appendUser('继续任务')` 污染历史 + `ensureSessionTitle('继续任务')` 污染会话命名。角色包 `reflect.handoff` 应该是**只进内核**的自主续跑许可，却被原样 yield 给宿主，属「内核循环引擎漏到宿主层」反模式。

**已完成（24xx 内核 + 232 宿主测试全绿）**：

| 文件 | 改动 |
|------|------|
| `hosts/memora-vscode/src/extension/host/sessionStore.ts` | `getSessionMeta` 仅当会话存在消息时推导占位标题；无 meta 且无消息返回 `undefined`（修正空会话/已删会话「复活」回归，满足 `deleteSession` 契约） |
| `src/agent/managers/sessionManager.ts` | `switchToSession`/`restoreFromCheckpoint` 用统一正则 `/^(\d{4}-\d{2}-\d{2})-(.+)$/` 解析 sessionId，正确处理含连字符会话名 |
| `src/agent/seed/orchestrator.ts` | `handoff()` 内核内部消化 `loop`→对外恒吐 `wait`/`end`；触迭代上限时强制 `wait` |
| `src/agent/seed/types.ts` + `src/agent/loop.ts` + `src/agent/agent.ts` | `StreamConsumeResult.iterationLimitReached` 透出迭代上限终止，供 handoff 决策 |
| `hosts/memora-vscode/src/webview/panels/chatPanel.ts` | 删宿主自动续跑引擎（`_loopCount`/`MAX_LOOP_COUNT`/伪造 `chat('继续任务')`），handoff 降为纯插座原样转发 |
| `hosts/memora-vscode/src/webview/scripts/chatView.ts` + `__tests__/chatView.test.ts` | 移除 `loop_count` 分支；`finalizeTrace()` 在 done/interrupted 把三阶段轨迹摄像头收敛为 ✓，修复「归档记忆」呼吸动画永闪烁 |

**规则对齐（炼化归元）**：`docs/architecture/host-plugin-alignment.md` §6.3「宿主控制循环」改为「宿主纯插座转发，不控制循环」，删除 `setTimeout(() => agent.chat('继续'), 100)` 反模式示例；§6.4 handoff 行同步。`protocol.ts` 移除已无消费者的 `loop_count` 变体（剪枝）。
