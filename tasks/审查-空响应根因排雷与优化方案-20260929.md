## 二、根因链（终版 · 四层）

```
[配置层] per-LLM 面板无「输出上限」字段
    → loop.buildChatOptions() 空对象起步（loop.ts:2261），maxTokens 无注入口
    → 请求体不含 max_tokens → 服务端默认输出上限（值不可见、不可控）
[模型层] mimo 推理模型 thinking 消耗同一输出预算
    → 长 thinking 吃满默认上限 → 正文被挤空（tokenOut 33）
[恢复层] llmCaller 空响应重试存在且工作（MAX_LLM_RETRIES=2，最多 3 次尝试）
    → 但同参重发 → thinking 再次吃满 → 3 连空 → 耗尽放弃（5 分钟白烧）
    → 同参重试只救「瞬态抽风」，救不了「确定性截断」
[诊断层] finishReason 已在流层透传（'length' 等）但空响应判定未消费
    → 「截断型」与「瞬态型」混为一谈；兜底文案单一；metrics.success 语义失真
```

### 7.3 本轮落地的修复（均已变异验证）

1. **P0 · `truncationRecoveryCount` 计数假阳**：`isEmptyResponse` 判据内含 `!aborted`，用户中止时恒为 false ⇒ 「truncatedRetry && !isEmptyResponse」把**用户放弃**记成**救回成功**。修复 = 计数判据补 `!aborted`（单点，兑现原注释已声明而未实现的纪律）。变异验证：去掉 `!aborted` → 新增用例恰红（`expected 1 to be 0`），其余 19 条不受影响。
2. **P1 · 取证面改记生效值**：新增 `AgentLoop.getEffectiveMaxTokens()`（复用 `buildChatOptions` 单点裁决）+ `Agent` 薄委托 + 宿主 `buildRoundMeta` 以它为首选、配置面仅作回落。**为何不让宿主自己算**：优先级规则只在内核一处，宿主重算等于长第二真理源——「配了 64K」被当成「发了 64K」正是此伤。宿主既有 `buildRoundMeta` 用例同步升级为守卫「生效值 ≠ 配置值」（输入 64000 → 取 4096）。变异验证：getter 改直读 `opts.defaultMaxTokens` → 该用例恰红。
3. **P2 · 假 SSOT 声明清除**：`protocol.ts` / `assemble.ts` 中「唯一真理源 = per-LLM maxTokens」是假声明（还有角色包一侧参与裁决），改为「底座值，非最终生效值」（7.4 落地后措辞为「与角色包取更小值」）；`ProcessMetaPayload.maxTokens` 口径同步为生效值（并注明旧数据语义差异）。另发现宿主 min agent 替身缺新方法会让 `consumeFlow` 整条落盘链路空转（8 条连带失败），已在替身工厂单点补齐。

**质量门**：内核 `tsc --noEmit`（含 scripts）干净、改动文件 eslint `--max-warnings 0` 干净；内核全量 2820 passed / 12 failed（**AssertionError = 0，全为 timeout ⇒ 本机环境假红**）；宿主 `tsc -p ./` 干净，宿主相关单测 53/53 通过。

### 7.4 裁决与落地（2026-09-30 · 已实施第一档：取交集 + 默认不限制）

用户拍板：**输出侧对齐输入侧的设计逻辑**（两个来源都是「上限」性质 ⇒ 取交集，谁小听谁的）。已落地两项：

| 改动 | 内容 | 文件 |
| --- | --- | --- |
| ① 取交集 | `buildChatOptions` 末对 `maxTokens` 做 `min(per-LLM, 角色包)` 收敛（仅此键取小；`temperature` 等属「设定值」非「上限」，维持覆盖）。裁决仍在该方法**单点**，宿主仍只读 `Agent.getEffectiveMaxTokens()` | `src/agent/loop.ts` |
| ② 默认不限制 | `DEFAULT_BEHAVIOR_STRATEGY.act.outputLimit` 由 `4096` 改 `undefined`——角色包未声明即不干预（回服务端默认 / 听面板）。旧默认 4096 是**隐形天花板**：未声明的包也被硬限到 4096 | `src/role-pack/strategyResolver.ts` |

**落地后的实际效果（含未采纳方案对照）**：

| 场景 | 旧（角色包覆盖） | 现在（取交集 + 默认不限制） |
| --- | --- | --- |
| 面板 64K + 包显式 4096 | 4096 | **4096**（不变，仍是「包更小」） |
| 面板 2K + 包显式 4096 | 4096（用户收紧不了） | **2K**（用户能收紧了） |
| 面板 64K + 包未声明 | 4096（默认兜底在偷偷限） | **64K**（面板说了算） |

**关键提醒**：取交集只让用户**能收紧**，不能**能调大**——只要角色包显式写了 4096，取小后仍是 4096。想让「共鸣小说家」跑长回答，必须改该包 `manifest.json` 的 `outputLimit`（如 32000）或删掉该行；否则只能选「面板优先」（未采纳，代价：推翻 `loop.test.ts` 既定裁决、角色包作者意图被静默覆盖）。

**未做（缩窄后的 `MAXTOKEN-SSOT-1`）**：①「共鸣小说家」4096 是否调大（内容决策，用户定）；②UI 是否明示「取小关系」（零行为变更的止血）。真机重验 T2 仍须挑「思考峰值确定超界」的任务——短输出轮零信息量。
