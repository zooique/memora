## 二、根因链（终版 · 四层）

```
[配置层] per-LLM 面板无「输出上限」字段
    → loop.buildChatOptions() 空对象起步（loop.ts:2261），maxTokens 无注入口
    → 请求体不含 max_tokens → 服务端默认输出上限（值不可见、不可控）
[模型层] mimo 推理模型 thinking 消耗同一输出预算
    → 长 thinking 吃满默认上限 → 正文被挤空（tokenOut 33）
[恢复层] llmCaller 空响应重试存在且工作（MAX_LLM_RETRIES=2，最多 3 次尝试）
    → 但同参重发 → thinking 再次吃满 → 3 连空 → 耗尽放弃（5 分钟白烧）
    → 同参重试只救「瞬态抽风」，救不了「确定性截断」
[诊断层] finishReason 已在流层透传（'length' 等）但空响应判定未消费
    → 「截断型」与「瞬态型」混为一谈；兜底文案单一；metrics.success 语义失真
```

## 五、任务清单（终版 · 落地顺序 T1 → T3 → T2 → T5 → T4）

| 任务 | 层次 | 改动点 | 验收标准 |
| --- | --- | --- | --- |
| **T1 · per-LLM 输出预算字段** | 配置（根治） | 宿主：面板加「输出上限 (K)」（风格同 contextWindow 字段，护栏 1–65536 为宿主独立 sanity、非与内核对齐——内核上限不裁决，2026-09-29 修订）→ `LlmProviderConfig.maxTokens` → assemble → AgentOptions。内核：AgentOptions 透传 → loop 持有 → `buildChatOptions` 填 `baseOptions.maxTokens`（~3 处小改）。mimo v2.6 建议值 32K–64K | 面板填 64K → 请求体含 `max_tokens: 64000`（**K=×1000 统一口径**，2026-09-29 裁决：厂商口径自相矛盾——gpt-4o 同卡混用 128,000/16,384、Claude 3.7 输出上限 64,000 十进制——「对齐主流」不可裁决，改按误差方向安全性裁决：×1000 低估无害、×1024 高估可致 max_tokens 超厂商上限 400）；真机长思考轮不再空响应 |
| **T3 · 诊断分型** | 检测 | `empty_response` 证据补 `{ finishReason, thinkingChars, attempts }`；兜底文案分型：截断型 =「模型思考过长耗尽输出预算，已自动重试 N 次——建议调大模型输出上限」；瞬态型 = 现有文案；metrics 空响应轮 `success:false` 或加 `degraded` 标记 | 复现时证据含三字段；用户文案可指导动作 |
| **T2 · 截断型换策略重试** | 恢复 | llmCaller 空响应判定消费 finishReason：`'length'` + 正文空 = 截断型 → 重试时 `effectiveOpts.reasoning_effort='low'`（复用 ：194 既有通道）+ 注入一次性系统提示「上一次回复因思考耗尽输出预算被截断，请直接给出结论或工具调用」（双轨：reasoning_effort 为增强、提示注入为保底）；无 finishReason = 瞬态型 → 维持同参重试 | 模拟截断流 → 第 2 次尝试带降思考/提示且救回正文；变异验证：去策略则仍空 |
| **T5 · 文案微打磨**（可选） | 体验 | ①`ALREADY_READ` 回显补「原文已在本次对话上文，可直接引用」；②meta 事件 payload 扩为**关键调用参数包** `{role, llm, contextWindow, maxTokens, reasoningEffort, providerKind}`——让每次真机异常自带取证包，无需截图/口问即可离线破案（2026-09-29 增补：自 contextWindow 单值扩展，来源 = 参照 agent 工作模式自省） | 各一行级 |
| **T6' · 异常收场证据回喂**（**挂观察** · 2026-09-29 增补，来源 = 参照 agent 工作模式自省） | 恢复 | 空响应等异常收场的 `evidence` 个案已按悬案取证轨落盘，但**下一轮装配不消费**——工具结果不跨轮 + 空响应不留工作记忆 → 用户重试说「继续」时 agent 面对空白上下文从零探索（真机 round-1790649685702：19 次工具调用的成果只存在于磁盘副作用与落盘数据中，LLM 侧断片）。**接线形态（触发后）**：prepare 期检测到未消费的异常收场证据 → 注入一条中性系统摘要（中断位置 / 已完成动作计数 / 任务表进度）。**数据已在只差接线**，轻于已按 D6 搁置的「轮内成果保全」全量方案（见 §六.3） | 触发后：模拟异常收场 → 下轮装配含摘要且 agent 能续跑；摘要中性（防失败阴影）、token 计入装配预算 |
| **T4 · thinking 落盘聚合**（低优先） | 成本 | thought 增量按 step 聚合落盘（UI 流式不变，仅持久化层） | 单轮 round 文件 < 200KB |

**依赖与边界**：T1 是根治（无输出预算时 T2 只是缓解）；T3 独立可先行（其证据字段是 T2 验收的观测手段）；T2 依赖 T3 的 finishReason 消费约定。全部改动收敛在**宿主配置 + buildChatOptions/llmCaller + 兜底文案**三处，不碰装配/压缩/防重链——零带伤面。T1 的请求层归一 `normalizeMaxTokens` 只做形态防御（非正整数不传、回服务端默认；正整数 floor 透传），**上限不裁决**（2026-09-29 修订）——与既有 V1 裁决「内核不裁决区间」同哲学，宿主护栏（1–65536）是输入边界的唯一可见裁决点。
