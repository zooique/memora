## 三、🔴 P0 · 设计 SSOT 带伤

### U1 字体栈脱离 VS Code 原生（风格契合首伤）

| 项 | 事实 |
|----|------|
| Claim | 插件 UI 字体与用户的 VS Code 设置完全脱钩 |
| Evidence | `styles/chatStyles.ts:50` `font-family: system-ui, -apple-system, sans-serif;`<br>`styles/settingsStyles.ts:22` **同字符串重复一遍**<br>`grep -c 'vscode-font-family\|vscode-font-size' *.ts` → 无输出（全库零使用）<br>等宽 `chatStyles.ts:645 / 718 / 747 / 1082` — 且存在**两套变体**（`ui-monospace, Consolas, monospace` ×3 vs `ui-monospace, SFMono-Regular, Consolas, monospace` ×1），均未用 `--vscode-editor-font-family` |
| Conclusion | ① 用户在 VS Code 设置的字体（含中文/编程连字字体）对插件无效 → **这是 VS Code 插件最不该违反的原生契约**；② 同一字体栈在两文件各写一遍 = 并列非嫁接；③ 代码块不跟随用户编辑器字体，`Fira Code`/`JetBrains Mono` 用户看到两套字形。 |

**修正方向**：tokens 增设 L2 字体令牌，三条即可：
```css
--font-ui: var(--vscode-font-family, system-ui, sans-serif);
--font-mono: var(--vscode-editor-font-family, ui-monospace, monospace);
--font-size-base: var(--vscode-font-size, 13px);
```
现存 6 处 font-family 全部改为引用，裸字号 12 处改引 `--font-size-base`。

|----|------|

**修正方向**（三选一，需你拍板）：① 复活两份 SSOT 文档并把现状当作 baseline 回填；② 删除全部指向它们的注释，改为指向现存真源（宿主 docs 层的 ui-growth-review.md + 2026-10-07 的宿主 UI 审查报告）；③ 不补文档，仅保留 `tokens.ts` 头部自述作为 SSOT。**推荐 ②**：禁止把文档缺失当技术债长期挂着。

### U3 铁律纹而不守

| 项 | 事实 |
|----|------|
| Evidence | `styles/tokens.ts:5-15` 明文：「裸值只能出现在本文件…其余所有样式文件只能引用令牌，**禁止裸值**」<br>`__tests__/tokensClosure.test.ts:99-114` 三条守卫：提取有效性 / 僵尸令牌 / 幽灵令牌——**全部只比对令牌名**<br>实测：330 裸 px、26 裸色，其中 144–185 处属铁律范畴，测试**全绿** |
| Conclusion | 守卫视而不见。更险的点在 `tokens.ts:149-152` 的自供：「本块定义值与各引用处 fallback 保持一致」——这是**人肉对齐接盘的**代价，`F5 同 token fallback 字面量漂移`（旧报告）从未 closed，只是年年手工对齐。5/7 文件压根不 inject tokens（仅靠 fallback 运行），**改 tokens 值 → 视觉不跟随**。 |

**修正方向**：加「值层面守卫」第 4 条测试——扫一圈 CSS 声明，剔除 `var()` 后若仍剩 `Xpx` / `#hex` / `rgba(`，且属性不在 EXEMPT 白名单内，则报错。白名单先 permissive（warning 档），核实假阳性率可控后再升 fail 门——**勿直接一刀切**（呼应「机械剪枝 = 造伤」教训）。

## 七、确认 NON-issue（已逐一核实，排除 False positive）

- **「7 个文件只有 2 个 inject tokens」≠ 令牌失效**：`settingsStyles.ts:12-15` 已聚合 import rolesStyles / configStyles / memoryStyles / skillsStyles，并在 `:18` 注入 `${tokens}` —— 设置面板侧 5 文件共用同一 `:root`，令牌可达。**✅ 结构正确，非 BUG。**
- **`dropdownStyles` 无自有 tokens**：被 `chatPanel.ts:3950` 紧跟在 `${chatStyles}`（含 tokens）后注入，同文档作用域下变量生效。**⚠️ 属隐性契约（偶发无守卫），记观察项，不立 UB。**
- **穿梭 `!important` 12 处**：`chatStyles.ts:19-47` 有 28 行长注释论证全局 `[hidden]` 兜底之必要性，并核验「全库零处依赖 hidden 做非显隐语义」。**属治病性取舍，非污点，不推荐删除。**

## 十一、第二轮整改（无障碍与国际化批次，2026-10-11 续）

### 落地的三件事

| # | 内容 | 位置 |
|---|------|------|
| U9 | `<html lang>` 由硬编码 `zh-CN` 改为按 `vscode.env.language` 动态取值 | panels 两个 `buildHtml` + 新增 `helpers/htmlShell.ts` |
| U9 | 抽 `<head>` 骨架真源：两份逐字节相同的 head（lang/charset/viewport/CSP/style）收敛为 `buildHtmlHead` | `helpers/htmlShell.ts` |
| U10 | 修 `summary` 焦点环缺失（WCAG 2.4.7） | rolesStyles |

**U9 的关键约束（踩坑面）**：本仓库 **17 个测试的 `vi.mock('vscode')` 全部不提供 `env`**，
直接写 `vscode.env.language` 会 `TypeError` 炸掉全部 panel 测试。因此走
`vscode.env?.language` + `resolveHtmlLang()` 兜底，且刻意不再产出 `<html lang="undefined">`
（浏览器会当未知语言区域处理，比不写 lang 更糟）。
另外 HTML 骨架重构只抽到 `</head>`，**body 与 script 段保持原样**——chatPanel 的 body 是
两百余行的模板字符串，整段重构成参数是高改动面、低边际收益，不符合 Surgical 原则。

**U10 的全库盘点（先盘后改，避免只治一处）**：`outline: none` 全库共 **13 处**，逐一分辨后
**12 处合规**——要么有边框变色替代（`.session-search` / `.search-input` / `.mem-edit-area`），
要么用了更高级的容器级方案 `#inputWrap:focus-within`（主输入框），要么本身就是
`:focus-visible` 规则内的附配替换（`.status-dock__chip` / `.plan-bar__head`）。
**唯 `summary` 一处无任何替代**，故本次单点修复，不扩大改动面。

### 新发现 · 待拍板（本轮刻意未动）

**角色卡片详情无法用键盘打开**：`.roles-card-clickable` 是 `<div>` 上的 click 监听，
而 `roles_detail` 消息全脚本**只有这一个发送点**（`rolesView.ts` 的 card click）。
即：`<div>` 不可 Tab ⇒ 键盘用户不存在打开角色详情的路径。

为何不在本批次顺手修：合规做法是在卡片内补一个真正的 `<button>`（或给 card 加
`tabindex` + `role` + Enter/Space 处理），但 card 内部已嵌套 button / summary / input，
再套一层 `role="button"` 属于 ARIA 反模式（交互容器不可嵌套）。这需要**新增/调整可见 UI 元素**，
属设计层面改动，应经真机视觉确认，不属「无形态变化的修复」范畴。**登记待拍板。**

### 新增工程约束（踩坑实录）
