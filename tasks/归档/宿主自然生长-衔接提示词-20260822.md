## 一、你现在要做什么（一句话）

**按「内核对接面」为块粒度，让 VS Code 插件宿主（唯一宿主）自然生长到"内核已具备、宿主尚未消费"的对接面上**。块 = 内核一个可注入/可消费的能力族，宿主只做薄壳消费 + 对齐 UI，绝不复刻内核逻辑、不凭空加功能。

## 二、项目架构速览（不重做）

- **memora = 纯逻辑内核**（Node 纯逻辑库，零 native 依赖），`src/index.ts` 是唯一导出入口，宿主从 `'@zooique/memora'` import（开发期 `"file:../.."`，不用 npm link）。
- **插件 = 薄壳宿主** `hosts/memora-vscode/`：extension host（Node）持 Agent，Webview 只渲染，`shared/protocol.ts` 是消息协议单一真理源。
- **三层对齐链**：内核能力族（种子·锚点）→ 插件功能（协议/装配：assemble.ts + chatPanel + protocol.ts）→ UI 展示（webview）。

## 四、关键决策 / 纪律（不可违反）

1. **锚点先行**：块以「内核某接口已存在」为充分前提，先对账 `src/index.ts` 导出面，杜绝造轮子。
2. **薄壳注射验证 → GUI 对齐 → 测试 → 独立提交**：先让内核能力真实被宿主消费，再长对应 UI；不触碰薄壳装配边界、不复刻内核逻辑。
3. **相邻生长优先**：优先长「已长成面」的相邻缺口，形成自然连贯生长。
4. **克制**：每块只做「内核有、宿主无」的最小补齐，不做范围外"顺手优化"。
5. **可回退**：探索期投票不进 ADR、不占编号（遵循 [exploration-decision-sedimentation-rules.md](../.trae/rules/exploration-decision-sedimentation-rules.md)）；待真实场景稳定复现消费后再评估固化。
6. **自然生长**：改动基于现有文件生长，不推倒重来、不拼凑；遵守 `.trae/rules/` 下全部规范（单一真理源/分层/命名/注释/代码审查）。

## 五、已长成块的关键落地点（改动参考，勿重做）

- **B8 网页抓取**：`assemble.ts` 注入 `fetchProvider: new FetchWebFetchProvider()`。
- **B3 会话分叉**：协议 `fork_session` + `chatPanel.forkCurrentSession()` 消费 `agent.forkSession()` + 标题条「分叉」按钮 + 单测。
- **会话显示名 SSOT**：内核导出 `getSessionDisplayName`；宿主 `sessionStore` 字段 `displayName`；`thinking` 阶段用内核 `ThinkingPhase`。
- **剪枝先例**：内核停发 `skillMatched` 后宿主残留消费全删（protocol/UI/样式/单测）。
