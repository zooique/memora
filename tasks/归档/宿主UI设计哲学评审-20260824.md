## 二、违反项（哲学审查八问未通过，需设计理由）

### V1 · 删除按钮仅 hover 可见（违反 §二 用户直觉）
- **证据**：`chatStyles.ts:117` `.session-history__item-del { opacity: 0; }`，`:hover` 才 `opacity: 1`（:119）
- **问题**：触摸屏/键盘用户看不到删除入口；屏幕阅读器用户无法发现该操作
- **哲学判定**：§二 DON'T「不要让只有 hover 才出现的操作」——用户永远发现不了
- **生长建议**：删除按钮常驻但弱化（低对比图标），或至少 `:focus-visible` 时显示；对齐 Trae 悬浮删除的设计权衡需显式注释说明理由（硬约束要求）

### V2 · 删除入口层级与「会话历史」主焦点竞争（违反 §一 信息架构）
- **证据**：session-history 列表项同时承载多状态（标题/时间/删除/active），删除按钮是仅有的行级操作
- **问题**：用户对会话历史的主要动作是「点选切换」还是「删除」？删除按钮 hover 可见暗示「切换为主、删除为辅」——但删除在 hover 时与切换同区竞争注意
- **哲学判定**：§一「一屏一个主焦点」——行内主操作（切换）与行内次操作（删除）未做强度差
- **生长建议**：切换=整行可点（强），删除=角落小图标（弱），二者距离拉开

### V3 · 信息密度与主焦点（需人工确认，非代码可判）
- **证据**：chatView 同时承载十余种元素（checkpoint-banner / plan-board / thought-block / trace-step / followup / date-divider / activity-bar / emptyState / restore-banner）
- **问题**：这些元素是否同时出现？若常态同时可见，用户扫一眼能否说出「现在该看哪」？
- **哲学判定**：§一「一屏只讲一件事」——需人工在真实会话中确认各元素是否抢主焦点
- **生长建议**：跑一轮复杂任务，观察 plan-board/thought-block/activity-bar 是否同时可见；若可见，评估是否折叠次级

### V4 · 空态建议卡的触发时机（需人工确认）
- **证据**：`chatView.ts:540` emptySuggestions 存在，但建议内容来源待查
- **问题**：空态建议是静态文案还是按角色包动态生成？若静态，是否符合「教用户怎么开始」的哲学（§四 空态有引导）？
- **生长建议**：确认建议卡是否随 activeRolePack 变化——空态引导应匹配当前角色

## 三、评审结论

- **宿主 UI 设计质量整体高于预期**：空态/加载/错误/键盘/审批五类状态全部有设计，且用 P0/P1/P2 优先级保护错误可见性——这些是普通用户直觉的核心，已达标。
- **真实违反 1 项（V1）**：删除按钮 hover-only，触摸/键盘用户不可发现——低成本可修。
- **待人工确认 3 项（V2/V3/V4）**：均需真实会话视觉确认，非代码可判。
- **工程层无违反**：tokens/组件/生命周期（ui-engineering-mindset-rules）此前已对齐。

> 与功能审查的联动：V1/V2 属「设计决策层」问题，C1（compaction 无事件）属「内核可观测性」问题——两者正交，不冲突。
