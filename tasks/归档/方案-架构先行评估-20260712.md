## 架构归属评估表

### 问题 1：relationGraph.ts 1206 行（HEALTH-0712-1，P3，超阈值 1200）

**现状**：单文件含 5 类职责——布局算法 + Canvas 渲染 + 颜色解析 + 交互处理 + tooltip 管理。

| 评估问 | 结论 |
|--------|------|
| Q1 归属哪个模块？ | sprite renderer components/（Canvas 可视化组件），拆分后仍归属 components/ 同级 helpers/ |
| Q2 新依赖方向？ | ❌ 无新依赖。拆分后 helper 仍纯函数 + Canvas 2D API，无跨层调用 |
| Q3 需新增模块？ | ⚠️ 不新增 src 模块，但新增 helpers/relationGraphLayout.ts + helpers/relationGraphColor.ts 两个文件 |
| Q4 影响架构边界？ | ❌ 不影响。参照 memoryGraphPanel/memoryDetailPanel 已有 6 次成功先例的 helper 提取模式 |

**架构归属结论**：**枝叶层重构**（非架构层变更）。按 ADR-SP-015 PanelManager 组合模式 + F-LINE-2 helper 提取范式执行。
**建议模式**：`模块重思：relationGraph.ts` → 产出拆分方案 → `方案更新` 执行
**拆分建议**（供后续方案设计参考）：
- `helpers/relationGraphLayout.ts`：runInitialLayout + updateLayout + 力导向算法（~150 行）
- `helpers/relationGraphColor.ts`：getNodeColor + getEdgeColor + hexToRgba + getContrastColor + resolveCssVar（~80 行）
- relationGraph.ts 保留：Canvas 初始化 + render 主循环 + 交互事件绑定 + tooltip（~970 行，低于 1200 阈值）

### 问题 3：agent.ts 1347 行 + AUDIT-1-1 ChatLockManager 提取（P3，接近阈值 1500）

**现状**：agent.ts 含 4 个 chat 锁相关字段（`_chatBusy` / `_chatLockToken` / `chatLockTimer` / `chatAbortController`）+ forceReleaseChatLock 方法 + chat() 内联锁逻辑。

| 评估问 | 结论 |
|--------|------|
| Q1 归属哪个模块？ | memora 内核 agent/（Agent 门面层），拆分后归属 agent/managers/（已有 12 个 Manager 范式） |
| Q2 新依赖方向？ | ❌ 无新依赖。ChatLockManager 仍属 agent 层，依赖 utils/safeTimer（已有） |
| Q3 需新增模块？ | ✅ 新增 `agent/managers/chatLockManager.ts`（符合 [new-module-guide.md](../.trae/rules/new-module-guide.md) 流程） |
| Q4 影响架构边界？ | ❌ 不影响。Agent 门面通过委托调用 Manager，符合 ADR-010 God Object 拆分既定路径 |

**架构归属结论**：**架构层执行**（符合 ADR-017 架构先行原则）。
- 新模块 `agent/managers/chatLockManager.ts` 的归属明确：agent/managers/ 目录（12 个 Manager 的第 13 个）
- 依赖方向清晰：仅依赖 utils/safeTimer + utils/errors，不引入新依赖
- 命名遵循既有范式：ChatLockManager（大驼峰，与 ConfigManager/InsightExtractor 等一致）
**建议模式**：直接 `方案更新` 执行（架构归属已明确，无需 `模块重思`）
**提取范围**：
- 4 个字段：`_chatBusy` / `_chatLockToken` / `chatLockTimer` / `chatAbortController`
- 1 个公开方法：`forceReleaseChatLock()`
- chat() 内联的锁获取/释放/超时逻辑（token 校验 + 超时回调）

## ADR-017 架构层原则适用性分析

**ADR-017 架构层原则的核心适用场景**：新功能/新模块加入前的架构归属评估。

本次 6 个问题中：
- **2 个适用架构层原则**：ChatLockManager 提取（Q3 需新增模块）、PostProcessPipeline 评估（Q4 影响架构边界）
- **2 个属于枝叶层重构**：relationGraph.ts 拆分、settingsPanelManager.ts 监控（按枝叶层 2 次提取原则）
- **2 个非架构问题**：pathGuard 环境问题、ADR 数量描述（已修复）

**结论**：ADR-017 架构层原则在本次评估中识别出 2 个真正的架构层任务（ChatLockManager + PostProcessPipeline），其余 4 个应按各自性质分流到枝叶层/环境层/已完成。
