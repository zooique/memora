#### P1 架构层违规（新发现）

| # | 问题 | 位置 | 违反规则 |
|---|------|------|---------|
| 2 | persona 直接调用 LLM | src/persona/personaManager.ts:303 `this.backgroundProvider.chat(...)` | backend_layers_rules §分层职责（persona「不该做什么：直接调 LLM」）+ §依赖方向（persona 未列入 → llm/） |
| 3 | helpers↔components 模块级循环依赖 | helpers/memoryGraphPanel.ts:31 → components/relationGraph.ts → helpers/relationGraphLayout.ts 等 | renderer 分层（helpers 不应依赖 components，且形成环） |

**P1-2 详细分析**：
- personaManager.ts 构造函数接收 `backgroundProvider?: LlmProvider`（line 100-106）
- `matchByLlm()` 方法（line 285-332）在关键词低置信度时用 LLM 做语义级角色匹配
- 规则对 agent 表述是"直接调 LLM HTTP（通过 provider 接口）"——即 agent 应通过 provider 接口；对 persona 表述是无条件"直接调 LLM"
- 正确归属：LLM 辅助角色匹配应在 agent 层（agent 允许通过 provider 调 LLM），由 agent 委托 LLM 后将结果回传 persona
- 缓解因素：backgroundProvider 为可选注入，未注入时降级为纯关键词匹配，未硬编码 HTTP

**P1-3 详细分析**：
- helpers/memoryGraphPanel.ts:31 → components/relationGraph.ts（value import）
- components/relationGraph.ts:32/40/46/55/68/72 → helpers/relationGraphLayout.ts/color/geometry/types/domHelpers.ts
- 形成模块级循环依赖
- helpers/streamingRenderer.ts:23 → components/markdown.ts（单向，无环，但仍属反向）
- 根因：memoryGraphPanel.ts、streamingRenderer.ts 命名虽在 helpers/，但实际承担渲染装配职责，更接近 components/ 或 panels/ 层
