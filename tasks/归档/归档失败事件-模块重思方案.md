## 1. 问题陈述

### 1.1 现状

`agent.ts` `postProcessInner` 中 3 处 fire-and-forget 归档操作（[agent.ts:585-617](../src/agent/agent.ts)）：

| 行号 | 操作 | 失败处理 |
|------|------|---------|
| 585 | `archiveCoordinator.archiveProfileFacts(input)` | `logger.warn({ err }, '用户画像实时归档失败')` |
| 600 | `archiveCoordinator.archiveInsight(input, assistantContent)` | `logger.warn({ err }, 'Insight 提取失败')` |
| 614 | `autoConfigRefiner.analyze(input, assistantContent)` | `logger.warn({ err }, 'AutoConfigRefiner 分析失败')` |

### 1.2 痛点

- **错误吞没**：catch 分支仅记日志，宿主 UI 和用户完全无感知
- **调试困难**：用户反馈"记忆没归档"时，需复现并查日志才能定位
- **数据丢失不可见**：归档失败意味着洞察/画像未持久化，但用户以为已保存

### 1.3 设计约束

| 约束 | 说明 |
|------|------|
| 不阻塞对话 | 归档失败不能影响主对话流（fire-and-forget 语义保留） |
| 噪音控制 | 失败可能连续发生（如 LLM provider 持续异常），需节流 |
| 不新增 IPC 治理压力 | 当前 IPC 通道数 105，接近 150 治理阈值（AUDIT-6-1），避免新增通道 |
| 复用现有事件链路 | 内核 emit → spriteLifecycleManager 转发 → spriteEventBridge IPC → ipcListeners → UI |

## 2. 设计方案

### 2.1 事件 payload 设计

```typescript
// src/utils/eventEmitter.ts AgentEventMap 新增
/** 归档操作失败（fire-and-forget catch 分支发射，宿主可通知用户） */
archiveFailed: {
  /** 失败阶段：profile（用户画像）/ insight（洞察提取） */
  stage: 'profile' | 'insight';
  /** 失败原因摘要（error.message，截断 200 字符避免 payload 过大） */
  message: string;
};
```

**设计理由**：
- `stage` 字段用字符串枚举而非自由文本，便于宿主按阶段分组统计和差异化展示
- `message` 截断 200 字符平衡可读性和 payload 大小
- 不暴露 error.stack（内核不应泄露实现细节给宿主）
- 不含 input/assistantContent（避免泄露用户隐私到事件流）
- **v2 修订**：移除 `'autoConfig'` stage——autoConfigRefiner 是"配置学习"非"归档"（[agent.ts:574](../src/agent/agent.ts) 注释明确），语义不应混淆。autoConfig 失败保留仅日志

### 2.2 发射点设计

**v2 修订**：仅 2 处归档操作发射（profile + insight），autoConfigRefiner 保留仅日志。

2 处 catch 分支改为：

```typescript
// 原：logger.warn({ err }, '用户画像实时归档失败');
// 新：
const message = err instanceof Error ? err.message : String(err);
logger.warn({ err, stage: 'profile' }, '归档失败');
this.emit('archiveFailed', {
  stage: 'profile',
  message: message.slice(0, 200),
});
```

**2 处发射点 stage 映射**：

| 行号 | 操作 | stage | 说明 |
|------|------|-------|------|
| 587 | archiveProfileFacts | `'profile'` | 用户画像归档 |
| 602 | archiveInsight | `'insight'` | 洞察提取归档 |
| 615 | autoConfigRefiner.analyze | —（不发射） | 配置学习非归档，保留仅日志 |

### 2.2.1 close() 顺序调整（v2 新增 P1 修复）

**问题**：[agent.ts:1046](../src/agent/agent.ts) `close()` 先 `removeAllListeners()`，再 `awaitPendingArchives()`。fire-and-forget 的 Promise 在 await 期间才 reject，此时 listeners 已清空，emit 变成 no-op。

**修复**：调整 close() 顺序——先 await pending archives（失败时 emit 能送达），再 removeAllListeners。

```typescript
// close() 修正前
this.removeAllListeners();
if (this.history) {
  await this.history.awaitPendingArchives(AGENT_CONSTANTS.SHUTDOWN_ARCHIVE_TIMEOUT_MS);
}

// close() 修正后
if (this.history) {
  await this.history.awaitPendingArchives(AGENT_CONSTANTS.SHUTDOWN_ARCHIVE_TIMEOUT_MS);
}
// pending archives 完成后再移除监听器，确保归档失败的 emit 能送达
this.removeAllListeners();
```

### 2.4 UI 展示策略

#### 2.4.1 噪音控制

归档失败可能连续发生（如 LLM provider 持续异常），需节流：

```typescript
/** archiveFailed 上次显示时间戳（按 stage 独立节流） */
const lastArchiveFailedNoticeTime: Record<string, number> = {};
const ARCHIVE_FAILED_COOLDOWN_MS = 5 * 60 * 1000; // 5 分钟节流
```

**节流策略**：
- 按 `stage` 独立节流（profile/insight/autoConfig 各自 5 分钟冷却）
- 同一 stage 5 分钟内只通知一次（即使连续失败）
- 静默模式下不弹 toast（与 projectSwitched/skillMatched/memoryRecalled 策略一致）

#### 2.4.2 展示形式

toast 非阻塞通知（非 ProactiveBanner，因为归档失败不需要用户立即操作）：

```typescript
/** archiveFailed 合法 stage 枚举（v2 新增，防止非法 stage 值） */
const ARCHIVE_FAILED_STAGES = ['profile', 'insight'] as const;

/** 校验 archiveFailed payload 结构（含 stage 枚举校验，v2 强化） */
export function isArchiveFailedPayload(value: unknown): value is { stage: string; message: string } {
  return (
    isObject(value) &&
    typeof value.stage === 'string' &&
    (ARCHIVE_FAILED_STAGES as readonly string[]).includes(value.stage) &&
    typeof value.message === 'string'
  );
}

function handleArchiveFailed(
  uiManager: UIManager,
  msg: { type: string; payload: unknown; silent: boolean },
): void {
  if (!isArchiveFailedPayload(msg.payload)) {
    reportError('handleArchiveFailed', msg.payload);
    return;
  }

  // 静默模式：不弹 toast（仅记日志）
  if (msg.silent) return;

  // 按 stage 节流
  const now = Date.now();
  const stage = msg.payload.stage;
  if (now - (lastArchiveFailedNoticeTime[stage] ?? 0) < ARCHIVE_FAILED_COOLDOWN_MS) return;
  lastArchiveFailedNoticeTime[stage] = now;

  // stage 中文映射
  const stageText: Record<string, string> = {
    profile: '用户画像',
    insight: '洞察提取',
  };
  const text = `${stageText[stage] ?? stage}归档失败：${msg.payload.message}`;
  uiManager.showToast(text, 'error');
}
```

**设计理由**：
- toast 非阻塞（不打断用户当前操作）
- 'error' 级别（区别于 'info' 的普通通知）
- 5 分钟节流（避免连续失败轰炸，用户已被告知）

## 4. 替代方案

| 方案 | 放弃原因 |
|------|---------|
| 不新增事件，仅强化 logger.error | 仍然只有开发者可见，用户无感知，未解决核心痛点 |
| 新增 IPC 通道 `archive:failed` | IPC 通道数已 105，接近 150 治理阈值，应复用现有事件链路 |
| ProactiveBanner 展示 | 归档失败不需要用户立即操作，banner 过重 |
| 不节流，每次失败都通知 | LLM provider 持续异常时连续轰炸，体验差 |
| 全局节流（不按 stage） | profile 和 insight 同时失败时只通知一个，信息丢失 |
