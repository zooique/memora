# 项目计划：以插件为北极星的 MVP 落地（2026-08-13）

> **定位**：memora 第一个对外产品——VS Code 插件。本计划是项目的北极星。
> **关联**：[ADR-VC-001](../.trae/decisions/ADR-VC-001-vscode-plugin-host.md)（宿主定位）、[ADR-021/022/023](../.trae/decisions/)（内核决策基线）
> **状态**：✅ 已定案；2026-08-15 架构大改（插件通用化，定位交由角色包承载）

---

## 一、一句话定位

> 在 IDE 里用 AI 把项目设计文档**打磨到自洽**，再动手写代码——消灭"反复拉扯代码导致一团乱"。

## 二、核心判断（纠正思路）

**不"先把 memora 开发完整再做插件"**——memora 已远超 MVP（20 管理器、1983 测试），问题不是"没开发完"而是"没被产品验证"。

**正确**：插件（产品）是唯一北极星。memora 是弹药库，不是产品。**memora 的"完整"是被插件用出来的，不是开发出来的。**

## 三、总体策略

**产品驱动 + 内核按需收敛**。memora 只做两件事：
1. 暴露插件所需的最小 API 面
2. 按插件真实反馈修缺口

**不做**"memora 全功能完整化"。

## 四、阶段计划（solo + AI IDE，每阶段有出口）

### 阶段 0：插件骨架 + 装配跑通
- 建 `hosts/memora-vscode/` 骨架（ADR-VC-001 结构：extension host + webview + 内置角色包）
- 用 memora 稳定核心装配 `new Agent()` + 注入 `IMemoryStorage`（workspace 文件）+ `LlmProvider`
- **出口**：插件在 VS Code 加载、侧边栏弹出、与 Agent 完成一次对话

### 阶段 1：最小闭环（切片 A + D）
- **A** 打开 .md → 侧边栏 AI 对话打磨想法
- **D** 跨会话记忆（memora 摘要即记忆），记住设计决策
- **出口**：开发者"打开文档→和 AI 聊→内容变严谨"，跨会话记得上下文

### 阶段 2：完整闭环（切片 B + C）
- **B** 文档自洽检查（矛盾/缺口/悬空引用）——复用 memora 交叉审查逻辑
- **C** 自洽通过后生成代码骨架
- **出口**：完整价值闭环"想法→自洽文档→代码骨架"
- **注（2026-08-15 起）**：B/C 无专用命令，均由对话面板 + doc-review 角色包承载（砍命令只留面板）

### 阶段 3：真实验证（10 个开发者 + 3 个反馈）
反馈问题：①自洽检查是否指出过"对，我漏了"的问题？②比直接写代码省事还是费事？③生成骨架后改骨架还是重写？
- **出口**：验证唯一验收标准

### 阶段 4（贯穿）：memora 按需收敛
- 暴露插件所需 API 缺口 → 补（最小改动）
- 用不到的多余机制（关系图谱/多跳）→ 标"未验证/内部"，不删不磨
- 稳定核心不动，避免回归

## 八、架构大改：插件通用化 + 角色包承载定位（2026-08-15）

**决策**：插件不再定性地做"文档打磨工具"，而是 memora 内核的**通用落地产品**——定位与功能全部交由**角色包**承载。

- 插件核心代码 = memora 落地实现（通用对话 + 记忆 + 网络搜索 + 安全审计），不硬编码任何功能定位。
- 出厂自带 `role-packs/doc-review/`（manifest + persona + rules），承载文档打磨（自洽审阅 + 骨架生成）；内核 RolePackManager 自动扫描激活。
- **砍专用命令只留面板**：`memora.open`（打开对话面板）+ `memora.configureModel`（配置大模型）两个通用命令；原 `reviewDocument` / `scaffoldProject` 命令删除，对应能力经面板对话触发。
- 前期不做用户自定义/导入角色包；角色包抽象先行，自定义留待后续。
- 实测：四切片（B/C/A/D）在角色包驱动下全部跑通（`count:1 active:doc-review`）。

## 五、里程碑与唯一验收

| 里程碑 | 出口 |
|---|---|
| M1 阶段 0 | 插件能加载 + 和 Agent 对话 |
| M2 阶段 1 | 最小闭环跑通（打磨 + 记忆） |
| M3 阶段 2 | 完整闭环跑通（+自洽 + 骨架） |
| **M4 阶段 3** | **10 人验证，唯一验收标准通过**（真正的终点） |

**唯一验收标准**：一个真实开发者，从"模糊想法"到"自洽设计文档"，能用插件独立完成，且愿再用第二次。

## 七、工程组织定案（ADR-VC-001 决策 6）

- **物理布局**：`hosts/memora-vscode/`（同仓库，与 sprite 并列）
- **依赖**：开发期 `file:` 本地路径指向 memora；**不用 npm link**；发布期切 npm 版本
- **git 拆分**：插件目录保持可独立拆分，需要时单独 init git 仓库
