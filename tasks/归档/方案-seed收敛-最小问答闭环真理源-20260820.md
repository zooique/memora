## 一、现状分析

### 1.1 核心问题

"种子（单轮问答闭环 = 最小单元）"这一概念**没有代码名分**——其三阶段串联逻辑散落在 `agent/agent.ts` 的 4 个私有方法里，与门面职责（生命周期/锁/状态机/会话切换）混居在一个 1721 行的大类中。

| 阶段 | 现状位置 | 现状实现 |
|------|---------|---------|
| 回答前 Prepare | `agent.ts::prepareChatContext` (L419) | 角色匹配(sub)+记忆召回(sub)+技能注入(sub)+会话粘性复位 |
| 回答中 Act | `agent.ts::executeChatLoop` (L485) → `loop.processUserInput` | 流式消费收口 consumeExecutionStream + appendAssistant + postProcess 触发 + Handoff |
| 回答后 Reflect | `agent.ts::postProcess` (L567) / `doPostProcess` (L584) | round-summary 摘要生成(fire-and-forget) |

### 1.2 关键观察

1. **回答前已部分下沉**：`contextPreparer.ts`（tryAutoMatchRolePack / recallAndInject / matchAndInjectSkill）已抽走叶子逻辑，但 `prepareChatContext` 的**编排骨架**（session 粘性复位 → 策略装配 → 角色匹配 → 召回 → 技能 → roundId → appendUser → 会话命名）仍留在 agent.ts。
2. **回答中是链路**：`executeChatLoop` 是纯粹的编排，真正执行在 loop。
3. **回答后是薄壳**：`postProcess` 只做 span + 委托，`doPostProcess` 只生成 round-summary。
4. **门面职责可明确区分**：生命周期（init/close/switchProject）、并发锁（chatLock）、状态机（autoResumeIfPaused）、会话管理访问器——这些**不是种子**，必须留在门面。

### 1.3 不提取的归档（为什么这些不能进种子）

| 聚合方法 | 归属 | 理由 |
|---------|------|------|
| `acquireChatLock` / `autoResumeIfPaused` | 门面 | 并发锁 + 状态机翻转，是门面基设 |
| `consumeExecutionStream` | 门面 | 与 processEvent / resumeExecution 三条路径共用，是门面的流收口协议 |
| `flushPendingConfigReload` | 门面 | 配置热更新协调 |
| `applyRolePackToolExposure` | 门面→已委托 assign | 角色能力决定工具暴露面，仍属门面策略装配 |

## 二、架构决策：归属

**核心决策**：种子**不新建顶层模块**（避免 `seed/ → agent/` 反向依赖违反分层），而是在 **`agent/` 内建聚合目录 `seed/`**。

- 依赖方向不变：`agent/seed/* → agent/loop`（种子消费引擎），`agent.ts → agent/seed`（门面委托种子）
- `seed/` 是 agent 层内部的"概念载体"，不是新分层
- 满足 ADR-017 Q2/Q3：无新依赖方向、无需新顶层模块，只是 agent 内重组

### 核心设计：`orchestrator.ts` = 唯一编排真理源

```typescript
/** 种子闭环编排器 —— 最小问答闭环的唯一编排真理源（prepare → act → reflect） */
export class SeedOrchestrator {
  constructor(private seed: SeedDeps) {}

  /** 运行一次最小问答闭环：回答前 → 回答中 → 回答后 */
  async *run(input: string, signal: AbortSignal): AsyncGenerator<AgentChunk, void, unknown> {
    // 回答前：装配上下文 + 产出 recalledMemories + roundId
    const prepared = yield* this.prepare.run(input, signal);
    if (prepared.aborted) return;

    // 回答中：流式执行（消费 loop.processUserInput）
    const acted = yield* this.act.run(prepared, signal);
    if (acted.failed) return;

    // 回答后：Handoff + 异步沉淀
    yield* this.reflect.run(acted, prepared.sessionId);
    yield* this.handoff.decide(this.seed.getActiveStrategy());
  }
}
```

**设计要点**：
- `orchestrator.run()` 显式表达"一次触发 → 一次性完整闭环"，是`种子自足可重复可观察`三个性质的代码落地
- 门面 `agent.chat()` 退化为 `yield* this.seedOrchestrator.run(input, signal)`（+ 锁/状态机守卫）
- prepare/act/reflect 各自可单独测试（种子三阶段独立验证）
