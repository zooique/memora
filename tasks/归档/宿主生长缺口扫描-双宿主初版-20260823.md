# memora 宿主生长缺口扫描报告

> 方法：以内核 19 模块为种子，逐一核对两个宿主（memora-vscode / memora-sprite）的对齐状态。
> 结论经 grep 实测复核，非凭记忆估算。
>
> 判定三态：
> - ✅ **已对齐**：宿主已接线/转发/暴露该内核能力
> - 🟡 **内核运行但宿主未暴露**：内核 assembler/loop 默认启用，宿主无 UI/接口暴露给用户（隐性缺口）
> - ❌ **未对齐**：宿主完全未接线该内核能力
>
> 核心结论先行：**两个宿主的"内核能力接线"都已基本完成（种子已发芽）。真正的生长缺口分两类——
> (A) 内核有、宿主缺暴露的"隐性缺口"（checkpoint 恢复、memoryAdvisor 提示、compaction 用户可感知）；
> (B) 宿主长出了内核没有、应当回流内核的创新层（perception / proactive / dashboard 可视化）。**

## 二、按模块的生长缺口详析

### ❌ 缺口 1：宿主 assembler 薄壳（模块 12）—— sprite 专属
- **现状**：vscode 有 `assemble.ts` 薄壳（注入 storage/sessionStore/provider/tracer/codeExecutor）。sprite 在 `src/index.ts` 的 `createAgentInstance/setupAgentPostInit/createSpriteAndClose` 三处散落地 `new Agent()`，无独立 assembler。
- **风险**：内核 Agent 构造签名一旦变化，sprite 需改三处（已验证三函数都直接 `new Agent`）。
- **生长点**：抽 `src/sprite/assemble.ts`，与 vscode 同构——单一装配真理源。

### ❌ 缺口 2：会话检查点恢复（模块 6）—— sprite 专属
- **现状**：内核有公开 `agent.restoreFromCheckpoint()` + `getCheckpoint()`（任务看板数据）。vscode 已接线（`chatPanel.ts:1116` 调 restore + 任务看板渲染 `:1706`）。sprite grep `checkpointRestore` **零命中**。
- **生长点**：sprite 的 `chatStreamHandler` / `sessionHandlers` 未暴露检查点恢复入口，用户无法回滚到会话检查点。

### 🟡 缺口 3：compaction 上下文补全（模块 3）—— 双宿主共缺暴露
- **实测**：`loop.ts:231,234` 默认 `new ResultReplacementStrategy()` + `DefaultDuplicateCallInterceptor()` 无条件启用。即内核**已在跑**，无需宿主接线。
- **缺口本质**：这是"内核运行但宿主未暴露"——用户无感知、无干预、无可视化（压缩前后上下文对比、重复调用拦截提示）。
- **生长点**：在宿主 UI 增加"上下文压缩/去重已发生"的可观测提示（复用内核 ITracer 已有 span）。

### 🟡 缺口 4：memoryAdvisor 记忆顾问（模块 16 Manager）—— 双宿主共缺暴露
- **实测**：assembler `createLoopDependentComponents` 强制 `new MemoryAdvisor()`（`:553`），被 recall 内部调用，被动生效。
- **缺口本质**：其 `suggest()` 产出"与你关注相关但未直接搜到的记忆"建议，vscode 仅在注释提及（`:1765`）未真正消费；sprite 同样未消费。
- **生长点**：将 `memoryAdvisor.suggest()` 接入 `suggestionHandlers` / 记忆面板，形成"主动记忆推荐"。

### 🟡 缺口 5：核心工具层（模块 10）—— 双宿主部分对齐
- `configResourceManager` / `scanner` / `segmenter` 是内核内部工具，宿主通过 `agent.tools` / 角色包 capabilities 间接消费。暴露面取决于角色包 `skills/` 与 `capabilities` 声明完整度（vscode 文档 F 系列已规划，sprite 待核）。

### ✅ 反向生长点（宿主创新应回流内核）
sprite 已长出的能力**内核没有**，是下一次生长的真正富矿：
1. **perception 栈**（affect/rapport/contextAwareness/patternDetector/presence）—— 内核只暴露原始 Agent 事件，缺口在内核缺"感知抽象"接口，宿主无法把感知状态喂回 system prompt（仅单向 `refreshBeforeChat`）。
2. **proactiveEngine 补完引擎** —— 内核只有 AutoConfigRefiner 产建议，无"采纳-反哺-阈值"闭环。
3. **dashboard / relationGraph 可视化 / providerSelector / audit JSONL** —— 可视化与多 Provider 管理，内核只供数据。

## 四、对抗式审查结论
- Explore agent 初判"sprite 内核能力无缺口"被**修正**：grep 实测证明 checkpoint/assembler 两项是真实 ❌ 缺口。
- vscode 文档 `host-alignment-v2.md` 标 ❌ 的（IVectorStore/IFileSystem/StoragePathResolver/SQLite）已被 sprite 的 SQLite 双实现覆盖，但 vscode 自身仍缺——**两宿主缺口不对称**，需分别填。
- "生长缺口"不应只向内看（补内核能力），还应向外看（把宿主创新回流内核，避免外壳过度生长、内核贫血）。
