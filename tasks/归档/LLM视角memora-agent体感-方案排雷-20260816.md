## 一、原始结论（输入，摘要）

LLM 自评 memora 作为 agent 的体感（10 分制，综合 **7.5/10 可配合作战**）：

**顺手处**：
- 跨会话记忆召回（9）——正中 LLM「上下文有限 + 换会话失忆」死穴
- 上下文注入效率（8）——触发源决定召回 + 会话摘要先行
- 对话闭环数据操作（8）——truncate-from-turn 删答也删问，上下文自洽

**摩擦点（自评偏低项）**：
- 主动召回(query)能力（4）——自认「被动投喂、缺主动查询」
- 结构化信息保真（4）——文本模型天天碰 diff/表格/代码，记忆偏自然语言摘要
- 可观测性（3）——自认「看不到记忆被什么触发、为何没召回」

**改进建议（影响 × 难度）**：
| # | 项 | 定位 |
|---|----|------|
| P0 | 主动召回接口 + 来源/score | 高影响/低难度 |
| P1 | 结构化信息保真（diff/表格/代码） | 高影响/中难度 |
| P2 | 记忆价值判断视角可配置（受角色包/目标影响） | 中影响 |
| P3 | 上下文预算显式化 | 中难度 |

## 二、对照代码与文档逐项排雷

### 排雷-1 · 「P0 主动召回接口 + 来源/score」
| 项目 | 内容 |
|------|------|
| **LLM 直觉** | 缺主动 query 接口，召回是「被动投喂」 |
| **memora 现状** | ✅ **已实现主动查询**：`agent.memory.searchHybrid(query, limit)`（语义 + 关键词双通道，返回 `AgentSearchHit[]`）；`trace_summary` 工具已暴露给 LLM 按 `sessionId+roundId` 溯源原始对话（memory-as-summary §4.5/§4.6）；召回载荷 `RecalledMemorySummary` 携带 `id`/`source`/`score`（api-reference §2 事件章节） |
| **雷区** | ⚠️ **重复/已覆盖误判**：LLM 自评「缺主动 query」与代码事实不符——主动语义查询（searchHybrid）与溯源（trace_summary）均已存在，且召回结果带 score/id 来源。被动注入（每轮自动 recall）+ 主动查询（searchHybrid）+ 溯源（trace_summary）三层已闭环 |
| **判定** | ❌ **否决**（已覆盖，不新增）。P0 降级为「确认能力已存在 + 宿主侧确需把 searchHybrid 暴露为 LLM 工具才生效」的边界检查项 |

### 排雷-2 · 「P1 结构化信息保真（diff/表格/代码）」
| 项目 | 内容 |
|------|------|
| **LLM 直觉** | 记忆偏自然语言摘要，结构化信息保真弱 |
| **memora 现状** | memory-as-summary 单轨：round-summary 是「1-2 句话摘要」浓缩，`metadata` 仅携带 `sessionName+roundId+summaryType` 等结构化索引字段，**无 diff/表格/代码片段的结构化保真通道**；`trace_summary` 可回溯原始对话，但那是「事后溯源」非「记忆时就保真」 |
| **雷区** | 🟢 **真实缺口**。但需边界约束：① 不新增记忆类型（保持 round-summary 单轨），考虑在摘要正文中按 Markdown 代码块/表格保留高价值结构化片段；② 与「记忆即摘要」的浓缩哲学权衡——全量保真违背摘要本质，应只对 LLM 判定「高价值且结构化」的轮次保留片段；③ 该能力本质是「LLM 工作形态对齐」，非记忆内核核心诉求 |
| **判定** | ✅ **采纳（收敛版）**——记入远期候选，明确边界，不预埋实现 |

### 排雷-3 · 「P2 记忆价值判断视角可配置」
| 项目 | 内容 |
|------|------|
| **LLM 直觉** | 提炼「什么值得记」用通用视角，可能记错/漏记 |
| **memora 现状** | 「召回侧视角」已可配：type 差异化召回（preference/decision/fact 不限窗口、intent/general 7 天，§4.2）+ 角色包 L2 召回开关（prepare.minFallback + recall 开关，§4.2.1）。但「**提炼侧视角**」缺失：round-summary 生成的提炼 prompt 是通用视角，**未受角色包/当前目标影响** |
| **雷区** | 🟡 **部分真实缺口**：召回侧已对齐视角，提炼侧未对齐。LLM 直觉「记忆价值判断视角」实际指向提炼侧，需收敛澄清 |
| **判定** | ✅ **采纳（收敛版）**——提炼侧「值得记什么」可下沉到角色包策略（如 prepare 增加提炼关注点），记入远期候选，不做当前预埋 |

### 排雷-4 · 「P3 上下文预算显式化」
| 项目 | 内容 |
|------|------|
| **LLM 直觉** | 召回占用 token 不透明，注意力易被稀释 |
| **memora 现状** | ✅ **预算控制已实现**：recall `limit`（默认 5）+ `minFallback`（默认 2）+ 增量召回（architecture §6）+ 互斥排除（§4.3 前置过滤）。但**预算总量未显式暴露给 LLM**（召回注入上下文时无「本处占用 N 条/token」的自描述） |
| **雷区** | 🟡 **部分覆盖**：内核侧预算控制充分，缺的是「LLM 侧可见性」——是否把召回注入规模作为上下文元信息告知 LLM，属可选增强非缺陷 |
| **判定** | ✅ **采纳（收敛版）**——「预算 → LLM 可见」记入远期候选，内核预算控制不新增 |

### 排雷-5 · 「可观测性（自评 3 分）」
| 项目 | 内容 |
|------|------|
| **LLM 直觉** | 自评「看不到记忆被什么触发、为何没召回」，仅 3 分 |
| **memora 现状** | ✅ **已全面实现**：`ITracer` 承载「模型看到了什么」——`llm.call` span 记录 `systemPromptHash`（发给模型的全部 system 内容指纹），`recall.recall` span 记录 `attachedMemoryCount` + `attachedMemoryFingerprint`（附着记忆条数 + ID 集合指纹）；`memoryAdvisor` 三级健康评估；`trace_summary` 承载对话内容可追溯（memory-as-summary §5.2） |
| **雷区** | ⚠️ **误判**：LLM 自评 3 分与实现不符。memora 可观测性已分两层覆盖——「对话可追溯」（trace_summary）+「模型所见可观测」（ITracer 指纹）。「为何没召回这条」属检索侧调试，可由 searchHybrid 显式查询模拟 |
| **判定** | ❌ **否决**（已覆盖，评分应上调）。LLM 直觉低估了 ITracer 与 trace_summary 的既有能力 |

## 四、深层洞察

1. **LLM 直觉 ≠ 代码事实，排雷是必要的校正器**。本轮 LLM 对 memora 的「主动召回」与「可观测性」两项自评明显偏低，实际均已实现。这印证了「网络为土壤」的不可替代：种子（LLM 直觉）提供方向，土壤（代码证据）校正养分。若直接按直觉上马 P0/P3，会重复造已存在的轮子。

2. **LLM 的「自我画像」与「实际能力」存在系统性偏差**。LLM 作为使用者，倾向于把「自己没有感知到的能力」误判为「系统缺失」。memora 的被动注入（自动 recall）对 LLM 是「无感」的，导致 LLM 误以为没有主动通道——实际上主动通道（searchHybrid/trace_summary）一直存在，只是宿主是否暴露为 LLM 工具的问题。

3. **真实缺口集中在「提炼侧」与「LLM 工作形态对齐」**。三个保留项（结构化保真、提炼视角、预算可见）都不是记忆内核的缺失，而是「记忆如何服务 LLM 的实际工作」的增强。这提示：memora 内核已成熟，下一阶段重心是「宿主如何把内核能力体面交付给 LLM」。
