## 一、问题诊断

### 1.1 策略键散落三处

策略键的"生死"由三处分散决定，缺乏单一锚点：

| 位置 | 职责 | 问题 |
|------|------|------|
| `types.ts` 接口 | 声明所有可能的键 | 无法区分"已消费"和"草案占位" |
| `validator.ts` | 校验键的合法性 | 对草案键做严格校验 → 误导角色包作者以为声明即生效 |
| `types.ts` DEFAULT | 提供默认值 | 默认值存在但无消费方读取 → 死代码 |

### 1.2 具体问题清单

| # | 问题 | 严重度 | 影响 |
|---|------|--------|------|
| P1 | 方案设计师 trigger 使用正则语法，实际永不命中 | P0 | 功能缺失 |
| P2 | 14 个键已消费但校验不完整（如 minFallback 无校验） | P1 | 数据合法性无保障 |
| P3 | 7 个草案键被严格校验（如 temperature），但内核不读取 | P1 | 误导角色包作者 |
| P4 | 23 个草案键有默认值但无消费方读取 | P2 | 代码卫生 |
| P5 | trigger 正则误用无测试覆盖 | P2 | 回归风险 |
