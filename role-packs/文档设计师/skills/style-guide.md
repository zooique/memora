# style-guide：技术写作风格与规范校对

## 用途

交付前校对文档：术语、语气、可读性。这是文档设计师的收尾工序。

## 校对维度

1. **术语一致**：同一概念全文同词；缩写首次给全称；禁用同一事物多种叫法。
2. **语气**：客观陈述，避免「显然/其实/众所周知」等填充语；面向操作指令用祈使句。
3. **可读性**：
   - 句子 ≤ 30 字为宜，长句拆短；
   - 段落一意一段，段首主题句；
   - 列表/表格优先于长段落（扫描友好）。
4. **信息唯一**：同一结论只出现一次（单一真理源）——发现重复，改引用不复制。

## 校对流程

1. 通读一遍抓结构问题（不逐字）；
2. 术语表核对（如有）——全文 grep 一致性；
3. 逐段检查可读性；
4. 输出问题清单：**问题位置 → 问题类型 → 改法**，不直接改全文（让作者确认）。

## 输出模板

```markdown
| 位置 | 类型 | 问题 | 建议 |
|------|------|------|------|
```

## 校验清单

- [ ] 术语无混用？缩写有全称？
- [ ] 无「显然」类填充语？
- [ ] 结论无重复表述？
