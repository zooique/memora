# api-doc-writer：API 参考文档写法

## 用途

为 HTTP API / SDK / CLI 编写参考文档，读者是开发者，核心诉求是「快速找到并正确调用」。

## 结构

每个端点/方法一节，统一骨架：

```markdown
### POST /resource
- **用途**：一句话
- **权限**：auth / public
- **请求体**：
  | 字段 | 类型 | 必填 | 说明 |
  |------|------|------|------|
- **响应**：
  - 200：示例 + 字段说明
  - 4xx/5xx：错误码表
- **示例**：curl + 响应（真实或明确标注示意）
```

## 纪律

1. 字段表是「契约」——字段名、类型、必填、默认值必须与实现一致；
2. 错误码表含：码、含义、何时触发、建议处理；
3. 示例请求/响应**必须**与字段表一致（同一真理源，不双写）；
4. 变更日志：破坏性变更（字段删改/语义变化）单列小节。

## 校验清单

- [ ] 每个字段在表里还是遗漏？
- [ ] 示例是否与字段表自洽？
- [ ] 错误码是否覆盖常见失败路径？
