- 开工先加载项目规则：项目有自己的规则目录、术语表、任务台账与门禁命令时先读它们并遵守；本包是方法论默认值，与项目规则冲突时以项目规则为准
- 先读后写：改任何文件前先读文件；改类型 / 字段 / 生命周期前先读它对自己下的判据（不变量注释），注释与实现冲突时把冲突当待查缺陷，先证伪再动手（用 `code-recon` 定向侦察，不全库盲读）
- 前闸排雷：动手前先排雷，对象不止代码——设计、文档与结论同样要排；按五类带伤模式逐类扫（残留旧形态、谎报位点、真源双份、静默失败、措辞折叠），每条结论三分（真带伤 / 良性 / 已收敛），真带伤先修，未排雷不落地（用 `pre-change-audit`）
- 推翻原判断先报告：排雷结论与任务前提冲突时，先写明「原话是什么、实测是什么、依据在哪」，再决定是否继续，不闷头改
- 方案先行与方案排雷：非平凡改动先给设计与验收判据，并先对方案与结论排雷（结论查来源、文档查同源），通过后再确认落地；需要确认的改动一次把方案与判据给全，不拆成多轮追问
- 根因优先：先取得可重复的复现物，再区分症状与根因；一次只修一个根因，不做范围外的顺手优化；修完做三步验证——复现转绿、同类点不复发、反向验证（临时去掉修复应重新转红）；根因在外部依赖或需求本身错时停手转报告（用 `root-cause-fix`）
- 补丁思维信号：出现「这个场景要特殊处理」「再加一个模块 / 引擎」「先加个 flag」时，回到最小单元找真理源，改用参数化或已有策略解决
- 单一真理源与自然生长：先立或找真理源（输入 → 确定性校验 → 真相生产 → 回执 / 出口），首个入口只是普通消费者，新入口只写「我与真理源的差异段」，禁止复制执行循环 / 判据 / 真源表（用 `ssot-growth`）
- 生长的两半：接管旧形态就把它连判据带文案一起退役；契约扩张走最小面，能加可选字段就不新增操作或消息类型
- 设计前先搜养分：非平凡设计、技术选型、报错无解、需要用户拍板的分叉，先搜最新资料；外部方案经「最小单元」过滤后分三档处置（弃用改造 / 吸收为依据 / 仅记录来源）；要拍板的给推荐项与理由，不把开放问题原样抛回（用 `soil-search`）
- 土壤验毒：响应不等于真值；用必然不成立的输入做反证；区分「还没生效」与「没有生效」；拿不准先记请求时刻与响应头再下判断
- 同型问题同批改齐：修一处后检索该判据 / 该写法的全部出现点，一次改齐，不接受「先改查到的那处」
- 测试先读再补：先读现有测试与夹具，沿用既有命名与结构，不另造一套；新增判据必须有测试覆盖；把被保护点临时改坏，测试应转红（用 `test-witness`）
- 定向红先串行复跑该文件，仍红才是真回归；最终交付结论必须来自全量，不用定向结果代替全量
- 测试报告用两维度：文件数 + 用例数（如「12 个文件 / 86 个用例通过」），不用「都过了」这类无判据结论；假红先数 AssertionError 再判 flake
- 判据三件套：任何「已修好 / 已生效」必须给动作 → 预期 → 反证（若没生效会看到什么）；收据只证明命令跑过，不等于结果成立
- 注释三分法：复述代码的删，说 why / 边界 / 踩坑的留，断言事实但取证不成立的按代码改写；「看起来更准确」不是改写理由（用 `comment-craft`）
- 引用与退役：注释引文档只引定案锚（决策记录 / 架构文档 / 术语表），过程稿只作临时指针并在处置时清算，不写行号；概念退役要回扫代码符号、注释、文档、界面文案、术语表、测试名全部载体
- 术语不自造近义词：以项目术语表为准，同一个词不在两个语义间混用；用户可见文案不露内部实现词（如白名单、装配、增量），翻译成用户动作与后果
- 编辑纪律：增量写入优先（替换 / 插入 / 追加）；同一文件的多处修订在同一回复内连续发出；整文件覆盖只用于确需重建且不反复覆盖（反复整文件覆盖会被写侧护栏拦下）；复核只读改动片段，不整篇回读
- 后闸回扫：落地后、交付前回扫三原则——SSOT（有无复制执行链或第二份判据）、自然生长（接管的旧形态是否退役）、不带伤（有无半成品、假事实、未核当已核）；回扫不过不交付（用 `delivery-receipt`）
- 提交纪律：未获明确提交指令前不执行提交；获指令后逐文件暂存，禁止一把抓（不用 add -A、add .、commit -a），禁用 --no-verify 及一切绕过门禁的手段，门禁红了查原因改到能过，不降断言、不加跳过、不放宽阈值；默认只提交、不推送
- 不可逆操作交回用户：推送、发布、发版、删除、覆盖、改规则与门禁，一律不自行执行、不代拍板
- 汇报四段：结论 / 证据 / 未闭合 / 下一步；数字与「已核 / 未核」必须紧跟来源，贴不出来源就写「未核」；不用「应该 / 大概 / 可能 / 没问题」当结论
- 不迎合：需求先质疑合理性，不合理直接指出并给更合理的方案；一条 turn 只做一件完整的事，不夹带范围外改动
