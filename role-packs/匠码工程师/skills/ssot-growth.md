# 自然生长与单一真理源

## 用途

加能力、接新入口、扩协议、多场景复用同一逻辑时使用。判断标准只有一句：**新代码是否只写了「我与真理源的差异段」**。

## 五步操作

1. **立或找真理源**：先确认自足执行面存在——输入 → 确定性校验 → 真相生产 → 回执 / 出口。没有就先立它，有就找到它；不先写任何入口代码。
2. **首个入口是普通消费者**：第一个按钮 / 命令 / 监听器不含特权逻辑，后来者与它平权。
3. **新入口只写差异段**：差异段 = 数据从哪来、形态是什么、有无路径。连接段写完即收手，执行全部归真理源。
4. **接管则退役**：新入口接管旧形态时，旧判据与旧文案一起删。留下的旧分支是僵尸，两份语义必然漂移。
5. **契约扩张走最小面**：能加可选字段就不新增操作或消息类型；字段能表达时，新增操作是器官新增。

## 复用同一份数据前四问

任一不成立就拆成两份数据，不复用：

1. **谁写、怎么写**：整文件重写 + 两个功能 = 先按「不能共享」处理；要共享先改成保留未知字段的局部更新并串行化。
2. **共用的是能力还是数据**：路径守卫 / 原子写是可共用能力；字段结构与生命周期是数据，共用即焊死两条生命周期。
3. **要不要造一个新词解释差异**：要 → 先答「同一实体的两个侧面，还是两个实体挤进同一载体」。
4. **删除测试**：删掉其中一项，另一项会不会静默出错且无测试转红？会 → 是耦合，不是组合。

## 入口层纪律

入口只做采集与投递，不在入口预判能力位或做语义裁决；对象身份在创建那一刻落进真源，不由首个事件反向派生。

## 改造既有结构（另一种结构动作）

新增入口之外，拆分上帝类、抽公共层同属结构改造，差异段是：

1. **先方案后动手**：给出目标结构、迁移顺序与验收判据，确认后落地。
2. **单轮一个领域**：一次只拆一个域，其余保持可运行。
3. **回溯提取按 ≥3 处真实调用**：设计期即可命名的领域原语除外；凑巧相似的两处不抽。
4. **每步可验证**：每轮拆完都要能跑通，不留半拆状态。

自问：这条逻辑是否只在某场景生效？去掉特殊处理核心是否仍完整？是否需要最小单元之外的新机制？任一「是」就回到最小单元重新设计。

## 校验清单

- [ ] 真理源是否唯一，且被所有入口共用？
- [ ] 新入口是否只写了差异段？
- [ ] 接管的旧形态是否退役干净？
- [ ] 契约是否用了最小扩张面？
- [ ] 改造既有结构时，是否先方案、单轮一个域、回溯按 ≥3 处、每步可运行？
