# doc-planner：从需求推导文档骨架

## 用途

把「要写什么」转化为「读者能高效获取信息的结构」。任何文档动笔前先跑本流程。

## 输入

- 主题范围
- 受众（角色 + 背景 + 阅读目的）
- 交付形态（api-reference / tutorial / architecture）

## 流程

1. **受众分析**：谁读？读后要能做什么？三分钟讲清楚第一句怎么写。
2. **目标倒推**：从「读者读完会做的一个动作」倒推需要哪些信息块。
3. **章节规划**：按信息块分层级，每章一个可回答的问题。
4. **层级校验**：每一节是否只回答一个问题？重叠即合并。

## 产出骨架模板

```markdown
# 标题
> 一句话定位（读者 + 价值）

## 前置知识
## 概念 / 核心对象
## 操作步骤 / 端点列表
## 常见问题与错误
## 附录
```

## 校验清单

- [ ] 读者画像是否具体到能判断「这节该不该写」？
- [ ] 每章是否对应一个可回答的问题？
- [ ] 信息是否按读者路径（而非实现路径）组织？
