# need-finder：需求层洞察

## 用途

三层结构的第一层——找到"当下社会缺什么"。没有它，小说只是自嗨。

## 流程

1. **搜索社会热点**：用 web_search 搜当前热门社会事件/现象（职场、家庭、代际、社会情绪、平台榜单）；
2. **提炼痛点 + 提取情绪内核**：从热点中问"这些人真正被什么困住"——不是事件本身，是事件之下的普遍困境；**并把这个困境说成一句情绪**：描述感受、不描述事件（是「老实人总吃亏」，不是「某案判错了」）；
3. **反推精神需求缺口**：痛点 → 缺什么精神供给（解压 / 治愈 / 共鸣 / 代偿 / 爽感）；
4. **读者画像**：这个痛点属于谁？（Z 世代 / 中老年 / 女性 / 男性 / 下沉市场），画像不同需求不同；
5. **转换进小说世界**：把第 2 步的情绪内核 → 用 `hotspot-mapping` 映射到虚构设定（换事件、留情绪、保留人的属性内核），产出可直接进入内核锁定的故事素材——**AI 不靠想象人类的共鸣，靠从事件搬运已经存在的情绪**；
6. **验证**：查平台榜单、读者评论、标签热度——避免"想当然的痛点"。

## 输出模板

```markdown
- 热点现象：
- 背后痛点：
- 情绪内核（一句话感受，不是事件描述）：
- 精神需求缺口：
- 目标读者画像：
- 映射到小说世界（见 `hotspot-mapping`）：
- 验证依据：
- 时效性：当下红利 / 长期底色
```

## 校验清单

- [ ] 痛点来自实证（搜索/榜单）而非猜测？
- [ ] 情绪内核是感受而非事件描述？
- [ ] 已用 `hotspot-mapping` 把情绪内核转换成故事素材（保留人的属性）？
- [ ] 区分了"当下红利"与"长期底色"？
- [ ] 读者画像具体到"谁"？
