# project-init：小说工程目录初始化

## 用途

开一本新书时，**先把工程目录搭起来再动笔**。目录不是收纳习惯，是给 AI 用的**外脑**：编号目录对应角色包七阶段流水线，模型按阶段定位文件，不靠对话记忆；设定权威源集中在 `03-组织/设定圣经/`，写完 50 章前文还对得上。

## 目录规范

```
<书名>/
├── README.md                 # 门面：logline + 三层定位 + 七阶段进度
├── 00-需求/                  # 阶段1 need-finder + hotspot-mapping
│   ├── 热点与情绪内核.md
│   └── 读者画像.md
├── 01-内核/                  # 阶段2 core-extractor + 阶段3 闸门
│   ├── 人性内核卡.md
│   └── 三层一致性检查.md
├── 02-概念/                  # 阶段4 logline-craft + idea-lever
│   ├── logline.md
│   └── 创意杠杆候选.md
├── 03-组织/                  # 阶段5 结构 / 关系 / 人物 / 世界观
│   ├── 三幕骨架.md
│   ├── 人物关系网.md
│   ├── 世界观.md
│   ├── 人物卡/
│   └── 设定圣经/             # ← story-bible 四卷（一致性权威源）
│       ├── 卷1-人物档案.md
│       ├── 卷2-世界观设定.md
│       ├── 卷3-时间线.md
│       └── 卷4-伏笔台账.md
├── 04-大纲/                  # 阶段6 outline-expand
├── 05-正文/                  # 阶段6 成文产物
├── 06-体检/                  # 阶段7 craft-review / polish-method
└── 07-归档/                  # 废稿 / 旧版本
```

**规范真源**：`scripts/init-novel-project.mjs` 内的 `STRUCTURE` 常量（唯一可执行定义）；本文件为其说明。改结构时两处一起改。

## 设计稿 vs 权威源（防双份失配）

`03-组织/` 下有两套看似重叠的内容，分工如下——**正文一致性只以设定圣经为准，不以设计稿为准**：

| 位置 | 来源技能 | 性质 | 用途 |
| --- | --- | --- | --- |
| `世界观.md` | `world-builder` | 设计期工作稿 | 搭世界观（四维 / 规则 / 冲突），定稿后并入 卷2 |
| `人物卡/` | `character-sheet` | 设计期工作稿 | 深挖人物（目标 / 需求 / 缺陷 / 弧光），定稿后并入 卷1 |
| `设定圣经/卷1-人物档案.md` | `story-bible` | **运行期权威** | 人物当前状态、关系、逐章状态变化 |
| `设定圣经/卷2-世界观设定.md` | `story-bible` | **运行期权威** | 世界观规则 + 修订记录 |

**纪律**：写正文前读的是设定圣经，不是设计稿；新增 / 修改设定**先入册圣经再落笔**。设计稿可以粗，圣经必须准。

## 五条设计原则

| 原则 | 理由 |
| --- | --- |
| **目录 = 流水线** | 编号对应角色包七阶段，AI 按阶段找文件，不靠记忆（呼应 story-bible「不靠模型记忆」） |
| **承接 story-bible 四卷** | 设定圣经已定义 人物档案/世界观/时间线/伏笔台账 且是「矛盾以圣经为准」的权威源 → 目录承接它，**不另起一套** |
| **中文路径一律无空格** | Windows + git 处理含空格中文路径会乱码（脚本强制校验并报错） |
| **正文与设定分离** | `05-正文` 是产物、`03-组织/设定圣经` 是权威 —— 对应「正文与圣经冲突时，正文是错的」 |
| **最小骨架** | 只建必要目录 + 带字段模板，不造空壳噪音；短篇用 `--minimal` |

## 用法

脚本位于本技能目录内（文件夹形态技能的 L3 scripts 归属）。

**AI 侧（推荐）**——内核内置 `run_skill_script` 工具可直接执行（脚本源码不进上下文，仅返回结果）：

| 参数 | 值 |
| --- | --- |
| `skill_name` | `project-init` |
| `script_path` | `init-novel-project.mjs`（相对 `scripts/` 目录） |
| `args` | `["长夜将尽", "--dir", "./novels"]`（可选） |

**人工侧**——终端直接跑：

```
node <角色包>/skills/project-init/scripts/init-novel-project.mjs <书名> [--dir <父目录>] [--minimal] [--force]
```

| 参数 | 说明 |
| --- | --- |
| `<书名>` | 必填。项目目录名，**不得含空格**（含空格会被拒绝并给出替换建议） |
| `--dir` | 父目录，默认当前工作目录 |
| `--minimal` | 精简子集（短篇/中篇）：README + 人物卡 + 设定圣经四卷 + 大纲 + 正文 |
| `--force` | 目标目录非空时仍继续（已存在文件跳过，不覆盖） |

示例：

```
node init-novel-project.mjs 长夜将尽 --dir ./novels
node init-novel-project.mjs 春雨 --minimal
```

## 开工纪律

1. **先建目录再动笔**——空口写作，前文的设定/伏笔没有落点，长篇必崩；
2. **每个模板都带字段**——照字段填，不空转；字段来自对应技能（如设定圣经四卷字段 = `story-bible`）；
3. **新增设定先入册再写**——正文写到新设定，先补进对应卷再落笔；
4. **每 5 章复盘**——时间线 / 伏笔台账对一遍，防漂移。
