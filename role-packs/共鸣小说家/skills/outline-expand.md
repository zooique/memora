# outline-expand：大纲→成文展开

## 用途

三层结构 → 大纲 → 成文之间的"最后一公里"。核心：**不一口气写长稿**，分步展开、每步确认，防止方向跑偏后返工。

## 五级展开漏斗

```
① 三层结构（需求/内核/形式）＋ Logline
   ↓ 展开
② 大纲（卷/部级：每卷解决什么冲突、情绪主线、大高潮位置）
   ↓ 展开
③ 细纲（逐事件：激励/价值转变/钩子——只排事件序列，不排章节）
   ↓ 展开
④ 场景清单（每场景：人物目标/冲突/价值转变/情绪落点）
   ↓ 展开
⑤ 成文（场景→章→卷正文：装箱成章，此时章节才诞生）
```

**每一级都让作者确认再降级**——跑偏的成本随降级指数级上升，确认点是止损闸门。

## 展开纪律

- **细纲不排章节**：③ 是事件序列不是章节清单——预排章号会让后续插入支线/番外时章号错位；章在 ⑤ 装箱时才产生（见 rules.md「纲是骨架、章是装箱」）；
- **大纲不写死细节**：大纲是"路线图"不是"剧本"——人物在写作中会"活"起来，允许偏离但要登记（为什么偏离、新方向是否更好）；
- **开写前回读细纲**：防止"写着写着忘了这段要干嘛"；
- **成文时只盯当前场景**：当前场景写透，全书大局交给大纲（防信息过载）；
- **卡住时的回退**：卡在场景→回细纲找当前事件的目的；卡在章→回大纲找这卷任务；找不到任务 = 这章可能不该存在。

## 交付节奏

- 一次给 1-2 章成文（不是一整卷）；
- 每章交付后问：**这章装箱的事件达到转变与钩子了吗？**——达到才继续，未达先修。

## 成文文件的分区纪律（正文与工程记录分离）

> **实锤依据**：2026-10-13 真机实测，`05-正文/卷一-日常与裂缝.md` 曾在同一文件里同时出现
> 小说正文 + 卷级元信息头 + `## 本批自检` 工程清单 + 卷末验收表。**机制本身是对的**
> （自检防文风退化），错的只是**落点**：读者与下游工具读到的应当是小说，不是工程表。

**一个成文文件按三段分区**（顺序固定）：

```
# <卷/章标题>
<!-- ① 卷级元信息头（可选）：POV / 基线文风 / 章号约定等工程约定，用引用块写 -->
## 场N｜<场名>          ← ② 正文主体：只有小说本身
...
（若干场次）
## 附：成文自检          ← ③ 工程记录：自检清单 / 伏笔登记 / 验收表全部收在这里
```

- **② 正文主体区只放小说**：不许插入自检清单、进度表、验收表、写作提示；
- **③ 工程记录区（文末「附：成文自检」）** 是自检清单与伏笔/验收表的**唯一合法落点**——
  这些是**过程工件**，对作者有价值、对读者是噪声，与正文同层即造成污染；
- **① 卷级元信息头可选**：确有工程约定要声明才写（POV、文风卡指针），无则省略；
  它是**约定**不是**自检**，留在卷首可接受，但不得混入正文段落之间；
- **跨卷/跨批**的自检统一累积到各卷文末该区，**不要**另起 `## 本批自检` 夹在两场正文中间。

## 校验清单

- [ ] 五级逐层展开、每级确认过？
- [ ] 大纲是路线图不写死？
- [ ] 细纲只有事件序列、无章号预排？
- [ ] 偏离有登记？
- [ ] 成文聚焦当前场景？
- [ ] 每次 1-2 章、章后验证转变与钩子？
- [ ] **正文主体区无工程记录**（自检/伏笔/验收表都在文末「附：成文自检」区）？
