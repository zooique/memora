# 注释与文档工艺

## 用途

写完代码收口，或清理注释噪音、排查「注释与代码不符」时使用。判据只有一句：**删掉这条注释，读者会失去什么？**

## 三分法

| 类别 | 判据 | 处置 |
| --- | --- | --- |
| 可删·复述 | 只是把下一行代码翻译成人话 | 删；保留 JSDoc 里的契约部分（参数语义、抛错、副作用） |
| 必留·why/边界 | 解释为什么这样写、边界在哪、踩过什么坑 | 一字不动；缺边界的补上 |
| 必改·假事实 | 断言了可验证的事实，但取证不成立 | 按代码改写，保留原句想表达的意图 |

「看起来更准确」不是改写理由；指不到代码落点就归「待定」，不猜。

## 最小必要注释

- **文件级**：这个文件负责什么、不负责什么。
- **类 / 函数级**：契约（输入 / 输出 / 抛错 / 副作用）与不变量；实现步骤不搬进注释。
- **变量级**：只在名字不足以表达含义时写（单位、口径、来源）。
- 不复述类型签名，不写「给变量赋值」这类废话。

## 引用纪律

- 注释引文档只引**定案锚**（决策记录、架构文档、术语表）；过程稿只作临时指针，并在文档处置时一并清算。
- 不写行号（行号没有 SSOT，增删代码即失效），定位用符号名。
- 概念名不得写成伪路径。

## 退役回扫

一个概念被取代时，回扫全部载体：代码符号、注释、文档、界面文案、术语表、测试名。只改代码不改注释 = 留下静默腐烂的指针。

## 减法红线

- 同一结论只写一次，不在注释与文档双写。
- 长论证留在文档里，注释只留指针 + 一句话结论。
- 文档里不写会过期的描述性计数；有判据作用的数字须带「时点 + 重算指引」。

## 校验清单

- [ ] 是否有复述代码的注释未删？
- [ ] 是否有断言事实的注释未取证？
- [ ] 引用的锚点是否仍然存在？
- [ ] 退役概念是否回扫完？
