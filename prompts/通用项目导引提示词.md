# Memora 项目通用导引（新会话开头粘贴）

> **用途**：把本文件内容粘贴到新会话的**首条消息**，让 AI 快速建立对项目**实际情况**与**设计哲学**的认知；本段结束后另起一行，直接写你的**具体任务需求**。
> 本导引刻意不绑定任何具体问题——它是通用背景，后面接你的需求即可。

## 一句话定位
Memora 是一个 **Node.js 纯逻辑 Agent 框架 / 内核**（`@zooique/memora`，当前 **v3.0.0**）：**零第三方运行时依赖**（仅用 Node.js 内置模块，`engines.node>=22`）、本地优先、隐私友好、领域无关，核心理念「**万物皆记忆**」。它不是成品应用，而是被宿主（VS Code 插件 / Electron 桌面端）承载的能力内核。

## 实际架构（基于以下现实，不要凭旧记忆）
- **内核 = `src/`**：211 个 TS 文件 + 100 个测试文件；`vitest` 测试、`tsc` 严格模式、**`any` 零容忍**。只暴露最小 API shape，纯逻辑、可独立测试。
- **双宿主**：
  - `hosts/memora-vscode/`：VS Code 落地宿主，**当前主力**（通用对话 + 记忆 + 角色包定位）。
  - `hosts/memora-sprite/`：Electron **演示宿主**（功能展示项目），演示内核能力。
  - **内核 / 宿主边界铁律**：内核只承载纯逻辑并暴露最小 `{baseUrl, model, apiKey}` 契约；provider 名解析、本地 / 云策略、默认值**全部归宿主**；拒绝 preset 冻结表。
- **角色包系统（role-pack）当前为 v0.13 手动切换模型**：
  - 已移除 `autoSwitch` / `exclusiveWith` / `sticky`；切换完全由用户 / 宿主显式驱动（见 ADR-028 手动切换 + 团队 + 会议）。
  - **28 个冻结策略键**（被内核真实消费，SSOT 在 `src/role-pack/strategyKeys.ts`）：`prepare` 8 / `act` 10 / `reflect` 4 / `global` 6；无 `[草案]` 残留。
  - 角色包可成组（组长 + 成员）；会议 = 任务表应用（`PlanStep.rolePack`）；兜底契约包 `memora助手`（`BUILTIN_FALLBACK_PACK`）。
  - 出厂角色包在 `role-packs/`（23 个文件）。
- **记忆与召回**：分层记忆（配置记忆 Persona / Rule / Skill + 对话记忆 Conversation / Insight / Profile，按日切分）；召回为「向量 + 存储」双通道，带超时降级。

## 设计哲学（贯穿所有代码与决策）
1. **单一真理源（SSOT）**：一致性源于单一真理源；并列 = 腐化，嫁接 = 生长；同一类事只在一处定义。
2. **自然生长而非堆砌**：复用调用链而非复制代码；遇复用点先在现有链路找挂载点再新增分支。
3. **复杂度守恒**：每多一层抽象就多一个故障点；复杂度匹配问题，不为「优雅」引入不必要抽象（YAGNI）。
4. **第一性原理 · 对抗式审查**：区分症状与根因，怀疑前提；先证伪再定性；结论须经 `grep` / `Read` / `tsc` / `vitest` **实锤**，不靠记忆估算。
5. **契约与边界**：裸值只在定义文件出现；接口即公共 API；破坏性变更走 deprecation 周期。

## 工作纪律（动手前请遵守）
- 任何修复 / 结论**先实锤**：`grep` / `Read` / `tsc --noEmit` / `eslint --max-warnings 0` / `vitest run`。
- 内核改动若涉及宿主，按宿主流程同步（如 sprite 的 `npm run sync-memora`）。
- **Git**：Windows 上禁止用 Bash 跑 git 写操作；走 **PowerShell 真实 FS**、逐文件 surgical `git add`、质量门预验证后提交；**绝不 `git add -A`**。
- 不死写规则：规则与实现冲突时优先把实现对齐到规则；确需改规则须维护 ADR 并更新 `tasks/`。
- 剪枝：零引用才可删除；不保留修改痕迹（不写「不是 X 而是 Y」「Bug 原因」类注释）。
