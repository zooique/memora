# Memora 发布衔接提示词

## 项目结构
- **内核**：`f:\zooique\memora\`（`@zooique/memora@2.0.2`）— 纯逻辑库，零依赖
- **宿主**：`f:\zooique\memora\hosts\memora-sprite\`（`memora-sprite@1.4.0`）— Electron 桌面应用
- 组合管理方式：内核作为本地包嵌入宿主，非 npm 发布依赖

## 版本号位置
- 内核版本：`package.json` → `"version": "2.0.2"`
- 宿主版本：`hosts/memora-sprite/package.json` → `"version": "1.4.0"`
- **两版本独立维护**，发布时只改宿主版本号（内核已达 2.0.2，无需同步）

## 发布流程（用户确认的标准流程）
1. 改 `hosts/memora-sprite/package.json` 的 `version`（如 1.4.0 → 1.5.0）
2. 本地验证：`npm run package:win` 打包 exe（Windows x64）
3. git tag 打标 + 提交 + 推送
4. **不建 GitHub Release** — 用户后续手动操作
5. GitHub Actions 的 Build workflow 会自动触发（多平台：Win/Linux/macOS）

## 内核同步机制（关键！极易遗漏）
- **sprite 不通过 `file:` 依赖引用内核**（避免 Junction 将全量仓库打入 asar）
- 由 `scripts/sync-memora.mjs` 负责：编译内核 → 复制 `dist/` + `package.json` + `LICENSE` + `README.md` 到 `hosts/memora-sprite/node_modules/memora/`
- **修改内核源码后必须执行两步**：
  1. 根目录 `npm run build`（编译内核 dist/）
  2. `node scripts/sync-memora.mjs --no-build`（同步到 sprite 的 node_modules）
- 或者一步完成：`npm run sync-memora`（编译 + 同步）

## 构建命令速查
| 命令 | 作用 |
|------|------|
| `npm run build` | 编译内核（根目录） |
| `npm run sync-memora` | 编译内核 + 同步到 sprite |
| `npm run build:electron` | 构建 Electron 主进程 + preload + 同步内核 + IPC 检查 + 图标生成 |
| `npm run build:web` | 构建 Web 模式（tsconfig.web.json） |
| `npm run package:win` | 打包 Windows x64（zip + nsis） |
| `npx tsc -p hosts/memora-sprite/tsconfig.web.json --noEmit` | Web 类型检查 |
| `npx tsc -p tsconfig.build.json --noEmit` | 内核类型检查 |

## 已知问题与注意事项
1. **GitHub Actions Build workflow 之前多次失败**：
   - 错误 1：`sync-memora` 时内核编译失败（`找不到模块 pino`）— pino 是 peerDependency，CI 环境可能未安装
   - 错误 2：`BackgroundConfig` 与 `ProviderConfig` 的 `baseUrl` 类型不兼容 — **已修复**（`src/llm/factory.ts` 中 `baseUrl` 改为可选）
2. **修改内核类型接口后，必须重新编译 + 同步**，否则 sprite 仍使用旧类型定义（node_modules/memora/dist/ 是独立副本）
3. **闭源项目的 GitHub Actions**：Build workflow 自动触发后，产物在 Actions artifacts 中，不自动创建 Release
4. **当前状态**：`tsconfig.web.json --noEmit` 编译已通过（exit 0），本地类型检查干净
