# Memora 项目起始提示词

> 粘贴此提示词到新对话的开头，让 AI 快速理解项目设计哲学与架构。

---

## 一、核心公理

> **单轮执行闭环是最小完整单元，一切复杂行为都是这个单元的自然生长，而非独立的新系统。**

```
外部输入 → [回答前 Prepare] → [回答中 Act] → [回答后 Reflect] → Handoff
```

## 二、设计哲学

### 2.1 单一真理源（SSOT）

**不是"只有一个文件/一个模块"，而是"只有一个设计原点"**：一套最小单元承载所有复杂行为，同一套逻辑在多种场景下复用，不做场景特化。

遇到复杂问题先回到最小单元——**能在单元层面解决，就不引入新机制。**

### 2.2 三个核心证明

| 证明 | 问题 | 真理源解法 |
|------|------|-----------|
| **Loop = 闭环的重复** | 需要独立引擎吗？ | 不需要。每轮都是完整闭环，Handoff 选 loop 即续跑 |
| **召回 = 输入触发** | Loop 每轮召回会很慢？ | 触发器决定——外部输入触发 recall，Loop 自循环不触发 |
| **摘要/记忆 = 后处理** | 需要独立后台系统？ | 不需要。闭环 Reflect 阶段天然承载 |

### 2.3 核心设计：触发源决定召回行为

| 触发源 | 角色包匹配 | recall() | 上下文组装 |
|--------|-----------|----------|-----------|
| **外部输入** | 触发 | 触发 | system prompt + 召回结果 + 全量消息 + 截断摘要 |
| **Loop 自循环** | 不触发（已固定） | 不触发 | 已有上下文 + 追加本轮结果 |

## 三、关键概念速查

| 概念 | 说明 |
|------|------|
| 单轮闭环 | 最基本的问答单元：Prepare → Act → Reflect |
| Trigger（触发源） | 外部驱动入口，分外部输入和 Loop 自循环两种 |
| Handoff（衔接决策） | 闭环出口：wait（等用户）/ loop（续跑）/ end（终止） |
| 角色包（Role Pack） | L1 内容 + L2 行为策略（+远期 L3 代码）的可插拔整体 |
| 角色包粘性 | 首次匹配成功后锁定，保留显式切换通道。不因无关输入而切换 |
| 行为策略 | 角色对三阶段行为的选择（47 个枚举维度，未声明用全局默认值） |

## 四、回答前两阶段设计（循环依赖解法）

理解输入需要角色包，角色包匹配需要输入——拆为两阶段，中间插入确定性匹配：

```
第一阶段：原始理解（分词、去噪、提取触发词）
  └→ 角色包匹配（触发词确定性匹配，不依赖语义）
      ↓
第二阶段：深度理解（在角色包视角下做意图识别、任务分类）
```
