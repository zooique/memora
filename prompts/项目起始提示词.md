# Memora 项目起始提示词

> 粘贴此提示词到新对话的开头，让 AI 快速理解项目设计哲学与架构。

---

## 一、核心公理

Memora 的一切设计围绕**一条公理**展开：

> **单轮问答闭环是最基础的单元，所有复杂功能都从这个单元自然生长。**

三个阶段构成闭环：

```
用户输入 → [回答前 Prepare] → [回答中 Act] → [回答后 Reflect] → Handoff
```

- **回答前（Prepare）**：理解触发、召回知识、装配上下文
- **回答中（Act）**：生成回答、执行工具、多步行动
- **回答后（Reflect）**：提炼记忆、生成摘要、衔接决策

**生长关系**：Loop（多轮串联）← 单轮闭环 ← 目标模式（对齐+差距分析）← 子 Agent（递归 fork）

## 二、设计哲学

1. **万物皆是记忆**：所有元素（规则、技能、历史、摘要）统一用 `source` 字符串区分，不引入独立子系统
2. **自然生长**：不拼凑功能，一切从单轮闭环长出。新功能前先问"它如何从闭环生长而来"
3. **零依赖内核**：memora 内核是 Node.js 纯逻辑库，`dependencies` 为空，零第三方运行时依赖
4. **分层架构**：三权分立——内容（L1）/ 行为（L2）/ 代码（L3），各层职责清晰不交叉
5. **插卡式角色**：角色包是固定范式的可插拔单元，L1 内容 + L2 策略 + L3 代码（远期）
6. **配置文件是真理源**：配置文件是持久化真理源，SQLite 仅作运行时索引
7. **严格串行**：闭环严格串行，任何时刻只有一个闭环在执行，用户输入在迭代边界挂起

## 三、关键概念速查

| 概念 | 说明 |
|------|------|
| 单轮闭环 | 最基本的问答单元：Prepare → Act → Reflect |
| 内循环 | 回答中工具调用的循环，决定"一轮有多深" |
| 外循环 | 回答间多轮闭环的串联，决定"一次任务有多长" |
| Handoff | 闭环出口：wait（等用户）/ loop（续跑）/ end（终止） |
| 角色包（Role Pack） | L1 内容 + L2 行为策略（+远期 L3 代码）的可插拔整体 |
| 行为策略 | 角色对三阶段行为的选择（如理解确认、工具权限、记忆模式） |
| 预检停顿 | 回答前的确认点：先总结输入→确认→进入回答中 |
| 验收锚点 | 目标文档中的确定性检查项（文件存在、测试通过、清单勾选） |

## 四、行为策略总览（L2 策略层）

角色包通过策略声明改变行为，未声明的维度使用全局默认值：

**回答前（Prepare）**：理解确认（off/echo/confirm）、上下文装配（fixed/query/hybrid）、记忆召回（full/limited/none）、任务分类（keyword/semantic/llm）

**回答中（Act）**：工具调用（allow/block）、工具批准（auto/confirm）、工具只读（readonly/full）、流式模式（streaming/non-streaming）、Provider 路由（auto/fixed）、多步推理（auto/manual）

**回答后（Reflect）**：结束衔接（wait/loop/end）、洞察提取（on/off）、记忆写入（auto/confirm）、用户追问（ask/silent）

**全局**：错误处理（retry/degrade/stop）、安全规则（inherit/override）

## 五、项目结构

```
memora/
├── src/                     # 内核源码（纯逻辑库）
│   ├── agent/               # Agent 核心：assembler / agent / loop / session
│   ├── role-pack/           # 角色包模块：types + RolePackManager
│   ├── persona/             # 角色管理（将被角色包替代）
│   ├── skill/               # 技能管理
│   ├── memory/              # 记忆系统：storage / inspector / advisor
│   ├── llm/                 # LLM 适配器
│   ├── security/            # 安全模型：pathGuard
│   ├── utils/               # 工具库：configResourceManager / scanner
│   └── logging/             # 日志
├── role-packs/              # 示例角色包文件
├── prompts/                 # 提示词目录（本文件所在）
├── docs/                    # 设计文档
│   └── agent-design/        # Agent 架构设计文档（核心参考）
├── hosts/memora-sprite/     # 精灵宿主（Electron 桌面应用）
└── .trae/
    ├── rules/               # 项目规则（12 个文件）
    └── decisions/           # ADR 决策记录（30 个文件）
```

## 六、编码约定

- **文件命名**：JS 小驼峰、CSS 连字符、HTML 连字符、Vue 大驼峰、Python 蛇形
- **变量命名**：变量/函数小驼峰，类大驼峰，常量全大写
- **注释风格**：文件级、类级、函数级、变量级均需注释
- **文件夹命名**：连字符命名法
- **ESM 模块**：所有 import 使用 `.js` 扩展名
- **类型导入**：`import type` 分离类型

## 七、关键决策（ADR）

- ADR-001：运行时栈（Node.js + TypeScript + ESM）
- ADR-002：存储层接口（IMemoryStorage 宿主注入）
- ADR-004：记忆统一模型（所有记忆共用 source 区分）
- ADR-006：安全模型（两级权限 + 路径白名单）
- ADR-017：自然生长重新定义（枝叶层 2 次提取）
- ADR-SP-019：消除模块级全局状态，用工厂函数注入
