## 提示词正文（从此处开始复制）

请加载并执行 `.trae/skills/big-tree-grower`（大树模型项目生长器）的 **「问诊：炼化归元」** 模式，并按"扩散执行"要求运行。

### 一、模式与链路（不可调整）
- 模式：问诊 → 炼化归元变体（见 `references/modes-guide.md`）。
- 固定串联链路，**严格按序执行**：**规则对齐 → 剪枝 → 提交前审查**。
- 第一步先评审合理性：确认当前项目确实需要炼化（如刚完成大量生成、或风格不一致/冗余堆积）。判定 ✅ 开始后按固定顺序执行；判定 ❌ 则说明原因与替代方案后终止。
- 结束后输出汇总报告：已对齐 X 项、已剪枝 Y 项、已审查修复 Z 项。

### 二、项目上下文
- 仓库：Memora（monorepo，Git 根 `F:\zooique\memora`）
  - `src/` + 根 `package.json`：memora 内核（纯逻辑库，零第三方运行时依赖）
  - `hosts/memora-vscode/`：VS Code 落地宿主，当前主力（独立 package）
  - `hosts/memora-sprite/`：Electron 演示宿主（功能展示项目，独立 package）
- 规则体系（执行前**必须先读**并建立"抽象术语 → 项目实现"的映射）：
  - `.trae/rules/project-rules.md`（总则：分层 / ADR / 配置文件真理源 / 零依赖内核 / Git 提交规范 §5 / DO·DON'T）
  - `.trae/rules/backend_layers_rules.md`（内核 / 宿主职责边界、分层与目录）
- 任务清单（如有变动须维护，完成须迁移、不可直接删除）：`tasks/待完成任务.md`、`tasks/已完成任务.md`

### 三、扩散范围（粘贴前请按实际情况填入/调整）
<扩散范围>：对**当前 Git 工作区所有未提交改动**（含 staged 与 unstaged，跨 `src/` 与 `hosts/*/`（memora-vscode / memora-sprite 两个宿主 package），排除 `.workbuddy/` 工具状态目录）**逐文件**执行炼化归元固定链路；每个改动文件独立走"规则对齐 → 剪枝 → 提交前审查"，最后汇总。若某改动已在前序轮次通过审查，则跳过以免重复劳动。

> 备选范围（按需替换上面 <扩散范围>）：
> - （A）仅 `hosts/memora-sprite/` 下未提交改动
> - （B）最近一次提交涉及的全部文件：`git show --stat HEAD`
> - （C）指定目录 / 文件清单（在此列出绝对路径）

### 四、各阶段执行要点
**规则对齐**
- 对照 `.trae/rules/` 检查每个改动文件是否违反分层 / 命名 / 注释 / ADR 等约定。
- **禁止单向修改规则**；发现规则与实现冲突时优先把实现对齐到规则，确需改规则须维护 ADR 并更新 `tasks/`。
- 输出：逐项列出"未对齐"问题及处置方式。

**剪枝**
- 清理冗余：死代码、过度注释、重复逻辑、临时调试残留。
- **DON'T（硬性）**：禁止在产出中保留修改痕迹——包括但不限于「不是 XX 而是 XX」句式、Bug 原因 / 修复思路类注释、变更说明类注释、任何暴露"这是某次修复 / 重构"的元叙述。剪枝后代码应如原生生长，无编辑瘢痕。
- 零引用才可删除；不触碰范围外代码。

**提交前审查**
- 确认改动经类型检查与测试：
  - 内核：`cd F:\zooique\memora && npx tsc -p tsconfig.json --noEmit` + `npx vitest run`
  - 宿主（memora-sprite）：`cd F:\zooique\memora\hosts\memora-sprite && npx tsc -p tsconfig.electron.json --noEmit && npx vitest run`
  - 宿主（memora-vscode）：参见其 `package.json` scripts（独立 tsconfig / vitest 配置）
  - 样式守卫（如涉及 CSS）：`npm run lint:css`
- 检查清单：分层合规、无新问题引入、风格一致、自然生长阈值（不足 3 次重复不提取）、修改痕迹已清理。
- 若准备提交：遵循 `project-rules.md §5`（`fix:` / `feat:` / `refactor:` + 简洁描述），必经 pre-commit（lint + typecheck + commitlint）。

### 五、收尾
- 输出汇总报告（已对齐 / 已剪枝 / 已审查修复 的数量与明细）。
- 若有新增待办，写入 `tasks/待完成任务.md`；已完成的从「待完成」迁移到 `tasks/已完成任务.md`（不得直接删除）。

## 使用说明（不复制此段）
1. 把上方「提示词正文」整体复制到新对话框首条消息。
2. 粘贴前确认第三章 <扩散范围>：默认=全工作区未提交改动遍扫；如只想审 sprite 宿主，改为备选 (A)。
3. 新对话框会自动读取 `.trae/skills/big-tree-grower/SKILL.md` 与 `references/modes-guide.md` 以加载完整流程；本提示词已内嵌关键约束，不影响其执行。
4. 「扩散执行」= 将单点问诊升级为「对所有待提交改动逐一跑一遍炼化归元链路」，属于范围扩大化解读（skill 本身无"扩散"概念，此处为自定义扩展）。
