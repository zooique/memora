# 四、已定论的 4 层因果链（含行号，已实锤 —— 抽查 1~2 条即可，勿全量重推）
1. **触发源**：模型 mimo-v2.5-pro（api.xiaomimimo.com 中转）未走原生 function calling，
   而是按 prompt 的文字指示输出 XML。
2. **根因 ⭐**：内核**宣告了「文本 tool_call」这条通道，却从未实现它** ——
   - src/agent/loop.ts:1749（buildSystemPrompt）：prompt += "## 可用工具\n\n你可以通过 tool_call 调用以下工具：…" ← 文本协议宣告
   - src/agent/loop.ts:1803-1812（buildChatOptions）：baseOptions.tools = […{type:'function', function:{name,description,parameters}}] ← 原生协议
   - src/ 内文本解析器**零命中**（TOOL_CALL_RE / parseTextToolCalls / extractToolCalls 均无）；
     src/llm/provider.ts:37 仅一句注释「Provider 不支持时静默跳过，fallback 到纯文本 tool_call」。
   - 原生侧解析在 src/llm/openaiCompatible.ts:397-414（只处理 delta.tool_calls）。
3. **放大器 ⭐**：解析不出 → 该文本当普通 assistant 内容 → turn 记 success=true，**零告警零兜底**。
   → 「AI 想干活却一步没干成」被系统记录为**成功**。
4. **显形器**：宿主 hosts/memora-vscode/src/webview/scripts/chatView.ts:2133 / 2743 / 2821
   = body.innerHTML = renderMarkdown(text, sanitize)；
   renderMarkdown（helpers/renderMarkdown.ts:57-61）= marked.parse() → DOMPurify（helpers/sanitizer.ts:25）。
   **脚本实证（真实 marked）**：marked 原样透传该 HTML；剥离标签后**剩余文本 = ""**、
   文本片段 = []（**零文本节点**）→ DOMPurify 移除未知标签后什么都不剩 → **渲染空白**。
   宿主生产代码 grep tool_call **零命中**（仅测试文件）。
