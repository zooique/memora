# 方案：写盘工具声明位与写串行闸收口（DIFF-4 / DIFF-5 发布前修复）

> 2026-09-26 · SSOT + 不带伤设计。发布前落地；先方案后代码（设计闭环）。

## 0. 一句话结论

**「谁会改盘」回归工具定义行内声明（单一真源）**，串行闸与改动追踪全部由声明**派生**（构造级单源，禁再独立枚举）；**目标不可静态定位的写（脚本类）升为屏障**——与一切写互斥；同目标写串行维持现状。宿主零代码改动。

## 2. 外部养分（土壤，来源可溯）

| 来源 | 吸收点 | 过滤结论 |
| --- | --- | --- |
| Flux 并行工具执行（`risk="read/write/exec/external"` 声明轴；「**只有 read 可并发，其余一律屏障**，按模型发出顺序单独执行」） | 工具**行内声明副作用等级**是主流范式；exec 类保守做屏障 | ✅ 吸收「声明位」与「不透明写 = 屏障」两个判据 |
| Shi Qiu《Ten Nuts, One Mouth》（读工具并行 / 写工具串行 / **按本次入参判定**；「参数解析不了就当作不安全、串行」） | 同目标写按入参串行（我们已有）；**不确定即保守串行** | ✅ 吸收「提取失败 → 降级屏障」规则（比「静默跳过」诚实） |
| AI Tools Guidebook（并行 agent 同文件丢编辑：「never let two parallel nodes write the same file path」；读盘必须在锁内） | 印证 DIFF-3 根因与修法（读-改-写必须在链内） | ✅ 佐证既有 writeChains 方向，不改 |

> 种子合理性过滤：Flux 的「非 read 全屏障」粒度比本方案粗（我们按目标路径保留跨文件并发），只吸收其**保守性原则**，不照搬全屏障。

## 3. 决策一：写盘声明位（SSOT 收口，DIFF-5 闭合）

**真源 = 工具定义行**（`builtinTools.ts` 的 `ToolDefinition`）：

```ts
/**
 * 改盘写声明（串行闸 / 改动追踪的判据真源）：
 * - 'path'：按 `args.path` 定位目标的落盘写 → 同目标写必须串行；
 * - 'opaque'：会改盘但目标不可静态定位（脚本执行类）→ 与一切写互斥（屏障）；
 * - 缺省：不改盘（读工具、内核数据工具如 task_table_*）。
 * 覆盖边界：串行闸与宿主改动追踪仅消费**内置工具**声明；自定义工具声明暂不生效（已登记边界）。
 */
diskWrite?: 'path' | 'opaque';
```

- **行内声明**：`write_file` / `delete_file` = `'path'`；`run_code` / `run_skill_script` / `run_project_script` / `register_work` = `'opaque'`。与 `readonly`（副作用轴）**正交**——`readonly` 管「只读模式放不放行」，`diskWrite` 管「写与写怎么排序」。
- **派生（构造级单源）**：`builtinTools` 导出 `ALL_BUILTIN_TOOL_DEFS`（全部内置定义合集，`toolExecutor.builtinDefinitions` 改为返回它——顺带收编该 getter 里第三处内联枚举）→ 派生 `PATH_WRITE_TOOL_NAMES` / `OPAQUE_WRITE_TOOL_NAMES`；`toolResultCache` 的 `WRITE_PATH_EXTRACTORS` 改为**由前者派生**（值 = 共用的 `args.path` 提取器——现有两个提取器本就是同一段逻辑），公开名与形状不变（`src/index.ts` 导出行、宿主 `Object.keys` 消费零改动）。**问诊追收一处**：loop 的「写后失效 read_file 缓存」分支原也手写 `'write_file' || 'delete_file'` + 内联 `JSON.parse` 提取（同事实第三份枚举）→ 改走派生集与同一提取器，顺带修掉 raw 路径失效台账不中的潜伏 miss（`fileExposure.invalidate` 不做归一，`./a.md` 式入参会打不中归一键）。
- **为何弃「两处 + 对拍守卫」**：对拍只能发现漂移，派生让漂移**不可构造**（与 `DISK_WRITE_TOOLS` 派生收编同一裁决口径）。守卫只留**契约钉**（见 §6）。
- **残余风险（如实记）**：新工具**整行忘声明** `diskWrite` 任何方案都拦不住（声明缺省 = 不改盘）——靠「声明就在定义行上、改行必见」+ 契约钉复审兜住，与 Flux/Shi Qiu 的声明式方案同寿。

## 4. 决策二：不透明写屏障（DIFF-4 串行半闭合）

`executeToolCalls` 现有 `writeChains`（按目标路径串行）之上加**屏障尾** `opaqueWriteTail`：

| 情形 | 排序语义 |
| --- | --- |
| path 写 × 同路径写 | 串行（现状不变） |
| path 写 × 不同路径写 | 并发（现状不变，反向守卫保绿） |
| opaque 写 × **任何**写（含 opaque） | **互斥**（屏障：目标未知，保守串行） |
| path 写但**提取失败**（坏参数等） | **降级为屏障**（土壤原则：不确定即保守串行；原先静默跳过 = 双盲） |

- 屏障等待面 = 当前全部在途写链尾（`Promise.all`）；path 写也须排在屏障尾之后。链尾 `catch` 吞失败的防毒化语义**原样保留**。
- 结果回填按 `toolCalls` 原序对齐（平行数组契约不动）；`tool_start` 仍批量先发。
- `register_work`（异步写 `work-projections.json`）**核查结论（实现期已定）**：其处理器是「`await refresh()` 读盘 → 追加 → 写盘」= DIFF-3 同型异步读-改-写竞态 → 一行声明 `'opaque'` 顺带纳入屏障保护。

## 5. 不带伤三条件（§7 口径）

1. **可追溯**：台账 DIFF-4/5 登记 + DIFF-3 两次真机同型实证 + §2 外部养分；每一动对应已登记缺口，无拍脑袋。
2. **可观测**：`loop.test.ts` 峰值活跃数断言（串行例恒 1 / 并发例 ≥2 / 屏障例恒 1）+ 契约钉测试；变异验证逐条对应（§6）。
3. **可退出**：改的只是 `executeToolCalls` 的批内排序 + 声明字段（可选、缺省无行为变化）；无 schema / 协议 / 落盘变更，单分支短路即回退，不留场景特判（无 `if (某工具)` 硬编码，一切走声明派生）。

## 7. 宿主与发布面影响

- **宿主零代码改动**：`WRITE_PATH_EXTRACTORS` 公开名/形状不变，`DISK_WRITE_TOOLS` 派生链不动，契约钉 `['write_file','delete_file']` 不变。内核 `npm run build` 重建 dist 后宿主 tsc 复验。
- **可视化盲区保持登记（DIFF-4 可视化半）**：脚本改盘哪些文件，内核与宿主都不可知（非声明可解）；真修复 = 宿主 FS watcher（新能力，触发驱动不做）。声明位已就位，届时接入零返工。
- **发布归属**：内核行为修复 → 随 3.0.0 出厂（与 DIFF-3 同口径：带守卫的 bug fix，不破坏契约）。

## 8. 台账联动

- **DIFF-5** → ✅ 闭合（声明位单一真源 + 派生 + 契约钉）。
- **DIFF-4** → 拆分口径：串行半 ✅ 闭合（屏障）；可视化半保留观察（触发 = 真机「脚本改了文件但可视化没显示」）。
- `restoreChange` 死分支注释虚述 → 随本批订正（不单立条目，归 W2 行内注记）。
