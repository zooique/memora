## P1-2：多模型路由基础

### 现状分析

当前 `factory.ts` 支持多 Provider 配置（`providers` 映射表 + `active` 选择器），但路由逻辑仅有一条——"当前激活的 Provider 处理所有请求"。

| 组件 | 文件 | 说明 |
|------|------|------|
| `ProviderConfig` | `factory.ts` | 单 Provider 配置接口 |
| `createProviderFromConfig()` | `factory.ts` | 从配置创建 Provider 实例 |
| `createLlmProvider()` | `factory.ts` | 根据 `active` 选择当前 Provider |
| `Agent.#provider` | `agent.ts` | 单 Provider 实例 |
| `Agent.#backgroundProvider` | `agent.ts` | 后台 Provider（可选） |
| `AgentLoop` 调用 `provider.chat()` | `loop.ts` | 所有 LLM 调用走同一 Provider |

**当前多 Provider 支持程度**：支持配置多个 Provider 定义，但仅能通过 `active` 切换"当前使用的 Provider"——所有请求（无论简单/推理/代码）都走同一个模型。

### 核心思路

在 `factory.ts` 中新增基于任务类型的模型路由选择器，支持以下任务类型：

```typescript
/** 任务类型（用于模型路由选择） */
export type TaskType = 'simple' | 'reasoning' | 'code' | 'summary';
```

默认降级：不配置路由时，所有任务类型使用同一个 Provider（与当前行为一致，完全向后兼容）。

### 详细变更

 * LLM 任务类型（P1-2 多模型路由基础）

#### 2. `src/llm/factory.ts` 新增路由函数

**新增** `ProviderRouter` 接口：

```typescript
/**
 * Provider 路由选择器（P1-2 多模型路由基础）
 *
 * 根据任务类型返回对应的 Provider 实例。
 * 不配置路由时，所有任务类型使用同一个 Provider（完全向后兼容）。

```

**新增** `createProviderRouter()` 工厂函数：

```typescript
/**
 * 创建 Provider 路由选择器
 *
 * 基于配置中的 providers 映射表 + taskRouter 映射，构建路由函数。
 * 不配置 taskRouter 时回退到统一的 active Provider（向后兼容）。
 *
 * @param config 完整配置
 * @returns Provider 路由函数
 */
export function createProviderRouter(config: Config): ProviderRouter {
  const { llm } = config;

  // 无多 Provider 配置 → 回退到旧格式，返回统一 Provider
  if (!llm.providers || Object.keys(llm.providers).length === 0) {
    const singleProvider = createLlmProvider(config);
    return () => singleProvider;
  }

  // 解析 taskRouter 配置
  const taskRouter = llm.taskRouter;
  if (!taskRouter || Object.keys(taskRouter).length === 0) {
    // 无 taskRouter 配置 → 所有任务类型使用 active Provider
    const activeProvider = createLlmProvider(config);
    return () => activeProvider;
  }

  // 预创建所有引用的 Provider 实例
  const providerCache = new Map<string, LlmProvider>();
  for (const providerName of new Set(Object.values(taskRouter))) {
    const providerConfig = llm.providers[providerName];
    if (providerConfig) {
      providerCache.set(
        providerName,
        createProviderFromConfig(providerName, {
          ...providerConfig,
          baseUrl: providerConfig.baseUrl ?? '',
        }),
      );
    }
  }

  // 兜底 Provider（taskRouter 中引用了不存在的 provider 名时使用）
  const fallbackProvider = createLlmProvider(config);

  return (taskType: TaskType): LlmProvider => {
    const providerName = taskRouter[taskType];
    if (!providerName) return fallbackProvider;
    return providerCache.get(providerName) ?? fallbackProvider;
  };
}
```

/**
 * 确定当前回合的任务类型（P1-2 多模型路由基础）
 *
 * 基于当前消息的特征做简单分类：
 * 1. 含系统提示词中的"代码"关键词 → 'code'
 * 2. 用户消息长且复杂 → 'reasoning'
 * 3. 其他 → 'simple'
 * 4. 摘要生成 → 'summary'（由 ContextManager 调用时显式传入）
 *
 * 此为初始实现，后续可扩展为更精确的语义分类。
 */
private determineTaskType(): TaskType {
  const messages = this.history?.getMessages() ?? [];
  const lastUserMsg = [...messages].reverse().find((m) => m.role === 'user');
  const content = lastUserMsg?.content ?? '';

  // 代码相关关键词检测
  if (/```(?:ts|js|py|go|rust|java|css|html|sql)\b/i.test(content)) {
    return 'code';
  }
  // 长文本复杂推理判定
  if (content.length > 500) {
    return 'reasoning';
  }
  return 'simple';
}
```
