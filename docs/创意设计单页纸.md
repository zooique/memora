## 一、核心矛盾

```
无状态的瞬时推理  ←→  连续演化的复杂任务
        (LLM 单次会话无记忆)        (跨会话/跨话题/跨项目的长期上下文)
```

**展开**：

- LLM 每次会话都是"失忆"状态——窗口结束则上下文清零
- 现实任务是连续的：今天写的代码需要昨天讨论的设计、用户偏好、历史决策的累积
- 简单 RAG（向量检索 + 注入）解决不了"该召回什么、何时召回、召回多少、是否被信任"的工程问题
- 主流方案（Claude Code / Cline / OpenClaw）各有缺陷（详见
  [agent横向对比分析.md §3](../docs/基础设计文档/agent横向对比分析.md)）

**解决方向**：以"永久性分级 + 统一召回管线"为核心，构建**本地、私有、领域无关的通用 Agent 架构**——把规则、技能、人格、对话历史统一视为"记忆"，按永久性等级（always
/ domain / topic / on-demand）控制召回的确定性和约束强度。

## 二、主要任务（≤5 个）

| #   | 任务                                                              | 服务矛盾的方式                                                                   | 验收标志                                 |
| --- | ----------------------------------------------------------------- | -------------------------------------------------------------------------------- | ---------------------------------------- |
| 1   | **5 层记忆体系落地**（工作 / 短期 / 中期 / 长期 / 归档）          | 解决"无状态"——任何层级的信息都有归属                                             | 用户说"我上周讨论过 X"，Agent 能跨周召回 |
| 2   | **上下文组装协议实现**（基础召回 + Agent Loop 增量召回）          | 解决"何时召、召多少"——启动只加载确定性 100% 的永驻+领域记忆，话题和能力按需召回  | 启动时间 < 1s，循环内召回 ≤ 1 次/轮      |
| 3   | **记忆永久性分级机制**（always / domain / topic / on-demand）     | 解决"召回确定性"——人格/规则 100% 必召，话题按相关度                              | 规则记忆可零误差还原 Agent 行为风格      |
| 4   | **本地记忆引擎**（SQLite 索引 + FTS5 全文 + 文件本体 + 冷热分离） | 解决"承载"——文件可读可编辑，数据库高性能检索                                     | 单项目数据 < 100MB 时查询 < 50ms         |
| 5   | **领域可插拔框架**（personality.md + rules/ + skills/ + tools/）  | 解决"通用 vs 专用"——同一套代码，加载不同配置即适配新领域（已用小说创作领域验证） | 切换领域 < 1 分钟，无需改代码            |

## 三、不做清单（≥3 条）

| #   | 不做                                          | 理由                                                                     |
| --- | --------------------------------------------- | ------------------------------------------------------------------------ |
| 1   | **不做云端 SaaS / 多用户协同**                | 隐私优先 + 单用户本地化定位；记忆是高度个人化的资产                      |
| 2   | **不做自研 LLM / 私有模型训练**               | 依赖第三方合规商用 API；不逆向任何软件私有接口                           |
| 3   | **不做 IDE 插件形态**                         | 独立 Agent 形态——通过 stdin/stdout 或 WebSocket 与宿主对接，宿主决定载体 |
| 4   | **不做实时多端同步**                          | 单机本地；如需多端由用户自己用 Git/Syncthing 同步记忆文件                |
| 5   | **不做"超长上下文"路线**（如百万 token 窗口） | 不与 GPT-4/Claude 的长窗口能力拼规模；坚持"精准召回 + 永久性约束"路线    |
| 6   | **不做"完美记忆"**                            | 接受"部分遗忘"是工程现实——通过剪枝、归档、权重衰减实现自然遗忘           |
