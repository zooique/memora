创意介绍

在 AI 上下文爆炸的时代，
我们选择让每一轮都重新开始

市面上的 AI 工具都在追逐多 Agent、多对话窗口、多线操作——但我们认为真正的答案恰恰相反：单窗口、单 Agent、每轮闭环。

💥

上下文污染

使用 Trae IDE 等 AI 工具时，单窗口问答越积越多。即使有压缩，早期对话的噪声仍会持续污染后续推理——模型开始"记混"或"答偏"。

🔀

多窗口碎片化

为避免污染被迫开多个窗口，但记忆被割裂在不同窗口中。上下文连贯性丢失，切换窗口反而增加了认知负担。

🧠

Agent 失忆症

LLM 本身无状态——每次推理都是"失忆"的。传统方案靠全量加载历史对话模拟记忆，浪费宝贵的上下文窗口，且随时间越来越不精准。

🎯

为什么不做单一窗口？

如果每轮问答都是独立闭环，每轮都动态组装上下文——那上下文就永远是精简、相关、高效的，永远不会膨胀污染。

产品全景

内核 + 宿主：缺一不可的双核架构

纯记忆引擎需要宿主才可落地，桌面精灵需要记忆引擎才能真正"懂你"。
Memora 提供记忆内核，Sprite 提供存在感——二者合一完成从"工具"到"伴侣"的跃迁。

记忆内核

Memora

Pure logic library · Zero native deps · Any host

  • 万物皆记忆：角色、规则、技能、对话全部统一为 Memory
  • 每轮闭环：启动时无所挂碍，开口时记忆按需浮现
  • 自然遗忘：衰减机制自动剪枝低价值记忆，拥抱不完美
  • 零 native 依赖：纯 TypeScript 逻辑库，可嵌入任何项目
  • 领域无关：换一套 .memora/ 目录就能切到完全不同的领域
  • 439 测试全量通过，Vitest + MSW Mock LLM
桌面宿主

Sprite

Context-aware · Not content-aware · Privacy-first

  • 热键召唤：规划中——Ctrl+Shift+M 即召唤即对话
  • 定时巡检：周期性检查用户洞察变化，主动分享
  • 文件感知：监听项目文件变化，知道你正在编辑什么
  • 窗口上下文：规划中——获取活跃窗口标题，不读取内容
  • 降级优先：感知能力不可用时静默降级，不打断使用
  • CLI → Electron：从命令行到桌面存在感
内核机制

Memora 三机制驱动的专注模式

1

按需召回 recall()

启动时只加载角色、规则、技能三类"硬记忆"。用户开口时，自动双通道（语义 + 关键词）召回相关记忆注入当前上下文。

2

自然遗忘 decayScores()

超过 7 天未被访问的记忆按周递减权重，被命中的记忆访问时间重置。不用的记忆逐渐淡出，常用的始终在线——像人脑一样，不是记住一切，而是记住重要的。

3

上下文截断 truncateMessages()

当工作记忆接近 Token 预算时，保留 system prompt 和最近对话，裁剪较早的消息并替换为摘要。保证上下文窗口永远精简高效，不被历史噪声污染。

隐私设计

上下文感知 ≠ 内容感知

在提供智能辅助的同时，严守隐私底线。以下是你永远不需要担心的——

✅ 可以感知

  • ✓ 活跃窗口的标题
  • ✓ 活跃窗口的进程名
  • ✓ 文件是否被修改
  • ✓ 用户是否有交互
  • ✓ 当前时间和日程

❌ 永远不碰

  • ✗ 全局键盘监听（keylogger）
  • ✗ 剪贴板内容读取
  • ✗ 屏幕截图 / OCR
  • ✗ 网络流量监听
  • ✗ 任意输入框内容读取

核心原则：感知上下文，不感知内容 — 纯本地运行，数据不出本机

目标用户及痛点

谁需要 Memora · 桌面精灵？

👨‍💻

程序员 / 开发者

场景：长时间使用 AI 编程助手

在 Trae IDE 中连续编码数小时，对话累积导致 AI 开始"答非所问"。Memora 让每轮对话独立闭环，AI 始终基于最相关的项目记忆回答。Sprite 在后台感知当前项目上下文。

✍️

内容创作者

场景：长篇小说 / 剧本创作

创作长篇作品时需要 AI 记住角色设定、剧情线索，但不想每次都手动提醒。Memora 自动召回相关创作记忆，保持角色一致性，拒绝上下文噪声。

🔬

研究人员

场景：跨天的深度研究对话

研究课题跨越多天多轮——传统对话窗口要么丢失上下文，要么被无关信息污染。Memora 按语义召回相关研究记忆，自然遗忘不相关的噪声。

🎓

学生 / 学习者

场景：持续学习某一领域知识

希望 AI 助教能记住自己的学习进度和薄弱点，但又不想每次重新解释。Memora 的用户画像功能自动跟踪学习状态，越用越精准。

价值与意义

为什么 Memora · 桌面精灵重要？

⚡

效率革命

Token 消耗固定预算，不随对话累积增长。用户无需手动管理上下文，专注思考而非"喂养"AI。每轮对话都是最优上下文，减少无效重试。

🏗️

架构范式

提出"每轮闭环 + 动态组装"的 Agent 记忆范式，可被任何 AI 应用复用。零 native 依赖的纯逻辑库，任何宿主项目都能接入——内核不绑定任何形态。

🔒

隐私范式

在 AI 桌面助手领域率先践行"上下文感知不内容感知"——精灵知道你在做什么，不知道你在打什么。纯本地运行，为行业提供隐私友好的技术参考。
