发现的问题

单窗口对话爆炸，上下文被污染

💥

上下文污染

单窗口问答越积越多，即使有压缩机制，早期对话的噪声仍会污染后续推理质量，导致模型"记混"或"答偏"。

🔀

多窗口碎片化

为避免污染开多窗口，但记忆被割裂在不同窗口中，切换时丢失上下文连贯性，增加认知负担。

🧠

Agent 无记忆

LLM 本身无状态，每次推理都是"失忆"的。传统方案靠全量加载历史对话模拟记忆，浪费上下文窗口且越来越不精准。

🎯

核心洞察

既然上下文会累积膨胀污染，为什么不让每一轮问答成为闭环，每一轮都动态组装上下文？

传统方案

上下文膨胀模型

  • ❌ 所有历史对话塞入上下文
  • ❌ Token 消耗线性增长
  • ❌ 早期噪声持续干扰推理
  • ❌ 压缩 = 信息丢失
  • ❌ 多窗口 = 记忆碎片化
→
Memora 方案

闭环动态组装模型

  • ✅ 每轮问答独立闭环
  • ✅ 上下文固定预算不膨胀
  • ✅ 按语义相关度召回记忆
  • ✅ 自然遗忘低价值记忆
  • ✅ 单窗口 + 跨会话连续体验
核心机制

三机制驱动的专注模式

1

按需召回 recall()

启动时只加载角色、规则、技能。用户开口时自动提取关键词，双通道（语义+关键词）召回相关记忆。

2

自然遗忘 decayScores()

未被命中的记忆按指数衰减自动淡出，被命中的权重重置。模拟人脑遗忘曲线——不用的自然忘，常用的始终在线。

3

上下文截断 truncateMessages()

接近 Token 预算时优先驱逐低权重记忆，保证上下文窗口永远精简高效，不被历史噪声污染。

在 Trae IDE 中连续编码数小时，对话累积导致 AI 开始"答非所问"。Memora 让每轮对话独立闭环，始终基于最相关的上下文回答。

内容创作者

场景：长篇小说 / 剧本创作

创作长篇作品时需要 AI 记住角色设定、剧情线索。Memora 自动召回相关创作记忆，保持角色一致性。

研究人员

场景：跨天的深度研究对话

研究课题跨越多天多轮，传统对话窗口丢失上下文或被污染。Memora 按语义召回相关研究记忆，自然遗忘不相关的。

🎓

学生 / 学习者

场景：持续学习某一领域知识

希望 AI 助教记住学习进度和薄弱点。Memora 的用户画像功能自动跟踪学习状态。

价值与意义

为什么 Memora 重要？

⚡

效率革命

Token 消耗固定预算，不随对话累积增长。用户无需手动管理上下文，每轮对话都是最优上下文，减少无效重试。

🏗️

架构范式

提出"每轮闭环+动态组装"的 Agent 记忆范式。零 native 依赖的纯逻辑库设计，任何 AI 应用都能接入。

🔒

隐私优先

"上下文感知而非内容感知"——感知工作状态但不窥探内容。不监听键盘、不读取剪贴板、不截屏。纯本地运行，数据不出本机。
