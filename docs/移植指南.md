## 一、安装

```bash
# 方式 1：npm 发布后（推荐）
npm install @memora/core

# 方式 2：本地开发（npm link）
cd memora
npm link
cd ../your-project
npm link memora
```

依赖项：Node.js ≥ 20 LTS。

---

## 二、最小接入（2 步）

### 步骤 1：一条命令生成全套配置

```bash
# 代码开发助手
memora init --domain code

# 或小说创作助手
memora init --domain novel

# 或只生成运行时骨架（不生成 agent-config/）
memora init
```

生成的目录结构：

```
your-project/
├── agent-config/
│   ├── personality/
│   │   └── code.md          # 人格设定（领域默认，只需微调）
│   ├── rules/               # 该领域的常用规则
│   ├── skills/              # 该领域的常用技能
│   └── tools/               # 该领域的工具定义
├── src/
│   └── agentBridge.js       # 接入代码骨架（含 LLM 配置占位符）
└── .memora/                 # 运行时目录（已可加入 .gitignore）
```

### 步骤 2：填入 API Key，运行

打开 `src/agentBridge.js`，找到第 18 行附近的
`YOUR_API_KEY_HERE`，替换为你的 LLM API Key：

```js
// 方式 1：从环境变量读取（推荐，不提交到 git）
apiKey: process.env.LLM_API_KEY,

// 方式 2：直接填入（仅本地开发）
apiKey: 'sk-xxxxxxxxxxxxxxxx',
```

然后运行：

```bash
node src/agentBridge.js
```

## 三、Agent API 参考

### 3.1 构造选项（AgentOptions）

| 字段          | 类型     | 必填 | 说明                                                        |
| ------------- | -------- | ---- | ----------------------------------------------------------- |
| `projectPath` | `string` | 是   | 宿主项目根目录的绝对路径                                    |
| `config`      | `Config` | 否   | Memora 配置对象，不传则自动加载默认配置                     |
| `configPath`  | `string` | 否   | 配置文件路径，与 `config` 二选一（`config` 优先）           |
| `configDir`   | `string` | 否   | 配置目录路径（personality.md/rules/skills/tools），建议设置 |

### 3.2 Config 结构

```ts
interface Config {
  llm: {
    provider: string; // 'mock' | 'deepseek' | 'doubao' | 'openai' | 自定义
    model: string; // 模型名
    baseUrl?: string; // 自定义 API 地址
    apiKey?: string; // API Key（建议用环境变量）
    temperature?: number; // 0-2，默认 0.7
  };
  memory: {
    dataDir: string; // 用户级数据目录，默认 '~/.memora'
    maxContextTokens: number; // 上下文窗口大小
  };
  security: {
    permission: 'owner' | 'guest'; // 权限级别
    confirmWrites: boolean; // 写入前是否确认
  };
  allowedPaths: string[]; // 路径白名单
}
```

### 3.3 Agent 方法

| 方法                    | 返回类型                 | 说明                              |
| ----------------------- | ------------------------ | --------------------------------- |
| `init()`                | `Promise<AgentContext>`  | 初始化：加载配置、索引、组件组装  |
| `chat(input)`           | `AsyncGenerator<string>` | 流式对话，逐 chunk yield          |
| `chatSync(input)`       | `Promise<string>`        | 非流式对话，一次性返回完整回复    |
| `switchTopic(newTopic)` | `string`                 | 切换话题，返回新话题全名          |
| `listAllTopics()`       | `Promise<string[]>`      | 列出所有话题文件                  |
| `close()`               | `Promise<void>`          | 释放资源（SQLite 连接、锁文件等） |

### 3.4 Agent 属性

| 属性          | 类型           | 说明                        |
| ------------- | -------------- | --------------------------- |
| `initialized` | `boolean`      | 是否已初始化                |
| `context`     | `AgentContext` | 运行时上下文（init 后可用） |

## 四、自定义工具

### 4.1 工具定义格式

在 `agent-config/tools/` 下创建 JSON 文件，每个文件定义一个工具：

```json
{
  "name": "my_tool",
  "description": "工具描述（LLM 根据此描述决定何时调用）",
  "requireMode": ["owner"],
  "parameters": {
    "type": "object",
    "properties": {
      "param1": { "type": "string", "description": "参数说明" },
      "param2": { "type": "number", "description": "参数说明" }
    },
    "required": ["param1"]
  }
}
```

或使用 Markdown frontmatter 格式（适用于技能定义）：

```markdown
---
name: 我的技能
description: 技能描述
keywords: [关键词1, 关键词2]
tools:
  - read_file
  - write_file
---

# 技能内容

...
```

### 4.2 内置工具

Memora 内置以下工具，无需额外配置：

| 工具名            | 功能         | 所需权限      |
| ----------------- | ------------ | ------------- |
| `read_file`       | 读取文件     | owner / guest |
| `write_file`      | 写入文件     | owner         |
| `list_dir`        | 列出目录     | owner / guest |
| `search_memories` | 搜索记忆索引 | owner / guest |

完整示例见
[小说创作示例 → tools/](./领域适配示例/小说创作.md#24-tools工具定义)。

## 五、目录结构约定

```
宿主项目/
├── agent-config/          # 配置目录（configDir 参数指定）
│   ├── personality.md     # 人格设定
│   ├── rules/             # 规则记忆（自动加载为 always permanence）
│   ├── skills/            # 技能记忆
│   └── tools/             # 工具定义
├── .memora/               # 运行时数据目录（自动生成）
│   ├── memora.db          # SQLite 索引
│   ├── topics/            # 话题文件
│   └── archive/           # 归档记忆
└── ...
```

如果未设置 `configDir`，配置也从 `.memora/`
下读取（personality/rules/skills/tools 子目录）。

## 六、常见问题

### Q1：如何配置 LLM API Key？

方式 1（推荐）：通过 Config 传入，值从环境变量读取：

```js
config: {
  llm: {
    apiKey: process.env.LLM_API_KEY;
  }
}
```

方式 2：在配置文件中使用 `${ENV_VAR}` 占位符：

```json
{ "llm": { "apiKey": "${MEMORA_LLM_API_KEY}" } }
```

### Q2：如何切换 LLM Provider？

修改 `config.llm.provider` 字段。内置支持：

| 值           | 对应服务            |
| ------------ | ------------------- |
| `mock`       | 本地 Mock（测试用） |
| `deepseek`   | DeepSeek API        |
| `doubao`     | 豆包 API            |
| `openai`     | OpenAI 兼容 API     |
| 自定义字符串 | 需同时指定 baseUrl  |

### Q3：配置目录（configDir）和运行时目录（.memora/）有什么区别？

- **configDir**：放你手写的配置（personality.md、rules/、skills/、tools/），由你维护和版本控制
- **.memora/**：放 Agent 运行时产生的数据（SQLite 索引、话题文件、归档），自动管理

分离后你可以把 `agent-config/` 纳入 git，而 `.memora/` 加入 `.gitignore`。

### Q4：如何更新配置后让 Agent 生效？

重新调用 `agent.init()` 即可。`init()` 会重新加载配置文件并重建索引。

### Q5：多个宿主项目能否共用一个 Memora 实例？

可以。每个宿主项目有独立的 `agent-config/` 和
`.memora/`，互不影响。全局规则可放在 `~/.memora/global/rules/` 下跨项目共享。

## 七、移植 Checklist

- [ ] 运行 `memora init --domain code`（或 `novel`）生成配置
- [ ] 编辑 `src/agentBridge.js` 填入 LLM API Key
- [ ] （可选）编辑 `agent-config/personality/*.md` 微调人格
- [ ] 运行 `node src/agentBridge.js` 发起首次对话，确认回复正常
- [ ] 将 `.memora/` 加入 `.gitignore`
- [ ] 将 `agent-config/` 纳入版本控制
