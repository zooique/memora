# 宿主本地化落地方案（HOST-I18N-1）

> **状态**：✅ 切片 1（package 面）已于 2026-10-30 落地；**决策已升级为 [ADR-042](../.trae/decisions/ADR-042-package-surface-localization.md)**，本稿自此降级为**切片 2-4 的落地操作手册**——决策口径以 ADR-042 为准，本稿只保留操作步骤、难度评估与风险清单
> **关联台账**：[待完成任务.md · HOST-I18N-1](../tasks/待完成任务.md)
> **一句话结论**：用 VS Code 原生 l10n，不自建语言设置；先把 UI 源码倒成英文，再按四个切片落地。

## 1. 结论

1. **能自然生长**：VS Code 已提供完整本地化管线，memora 只增加「内容」（翻译文件），不新增「机制」。
2. **语言真源 = VS Code 显示语言**（`vscode.env.language`）。中文环境自动读 `zh-cn` 翻译包，其他环境自动回落到默认英文。**不新增 `memora.language` 配置**——那会制造第二套语言真源，并与 VS Code 切语言（需重启）分叉。
3. **硬成本（不可绕过）**：源码里的中文 UI 文案必须倒成**英文原文 + `l10n.t()`**，中文译文放进 `bundle.l10n.zh-cn.json`。原生机制规定默认语言是英文；保留中文源码再补英文包是反的，英文环境拿不到翻译。
4. **难度分布**：package 面低；宿主面低-中；webview 静态 HTML 中；webview 动态脚本高（量最大、回归面最广）。技术难度不高，成本集中在文案迁移与真机验收。

## 2. 已核实事实（2026-10-22）

| 事实 | 证据 |
| ---- | ---- |
| `vscode.l10n.t()` 按 `env.language` 取译文；没有对应 bundle 时返回**原文** | 本地 `@types/vscode` 的 `l10n` 命名空间注释 |
| `vscode.l10n.bundle` / `vscode.l10n.uri` 在「默认语言」或「无 bundle」时为 `undefined` | 同上 |
| 使用运行时 l10n 必须在 manifest 声明 `"l10n": "./l10n"`，并提供 `bundle.l10n.<locale>.json` | 同上 |
| webview 拿不到 `vscode.l10n`，需用 `@vscode/l10n`；它**不得**用在扩展主进程 | [@vscode/l10n README](https://www.npmjs.com/package/@vscode/l10n) |
| `@vscode/l10n` 支持 `config({ contents / fsPath / uri })`，与 `l10n.bundle` / `l10n.uri` 配对使用 | 同上 |
| `package.nls.json` 是**默认英文**文件，不能把其他语言设为默认；当前 locale 缺翻译文件时回退默认文件 | [vscode-ext-localisation](https://www.npmjs.com/package/vscode-ext-localisation) |
| `package.nls.<locale>.json` 可本地化 displayName / description / 命令标题 / 视图名 / 配置描述 / 菜单标签 / walkthrough | [Project Manager 本地化实测](https://deepwiki.com/alefragnani/vscode-project-manager/6-localization) |
| 显示语言通过 Language Pack 切换，**切换后提示重启**；locale 含 `zh-cn` / `zh-tw` | [VS Code Display Language](https://code.visualstudio.com/docs/configure/locales) |
| Marketplace 详情页 README 没有随语言切换的原生机制（存在第三方翻译扩展侧证） | 检索结果与 VS Code Marketplace 文档 |
| 当前 `engines.vscode` 为 `^1.90.0`，已覆盖 l10n API，无需升版本 | [package.json](../hosts/memora-vscode/package.json) |

## 3. 三层机制

| 层面 | 文件 | 谁负责 | 源码语言要求 |
| ---- | ---- | ---- | ---- |
| 扩展元数据 | `package.nls.json` + `package.nls.zh-cn.json` | VS Code 自动按 locale 选择 | 默认文件 = 英文 |
| 扩展宿主运行时 | `l10n/bundle.l10n.json` + `bundle.l10n.zh-cn.json`，代码用 `vscode.l10n.t()` | VS Code 主进程自动加载 | 代码中的 key = 英文原文 |
| webview | 同一份 bundle，代码用 `@vscode/l10n` 的 `l10n.t()` | 宿主把 `vscode.l10n.bundle` 内联给 webview | 代码中的 key = 英文原文 |

**单一翻译目录**：`@vscode/l10n-dev` 一次扫描 `src/`，把宿主与 webview 的 `t()` 调用收进同一份 `bundle.l10n.json`。宿主与 webview 消费同一份译文，不复制第二套字典。

## 4. 落地切片

### 切片 0 · 拍板与三分类（前置）

先回答三个问题（见 §8），再把待翻译字符串分三类：

| 类别 | 是否翻译 | 例子 |
| ---- | ---- | ---- |
| 人类可见 UI | ✅ 翻译 | 设置描述、按钮、空态、通知、确认卡、状态条 |
| 模型可见内容 | ❌ 不翻译 | 工具描述、系统提示词、角色包内容（语言影响模型行为） |
| 内部事实 | ❌ 不翻译 | 日志、协议枚举值、存储键、CSS 选择器、测试名 |

> 不做三分类直接全量替换，会把 prompt 和协议键也翻掉，属于功能性伤害。

### 切片 1 · package 面（最小、可逆、立刻见效）

- 新增 `package.nls.json`（英文）与 `package.nls.zh-cn.json`（中文）。
- `package.json` 的本地化字段改为 `%key%`：`displayName`、`description`、命令 `title`、配置 `description`、枚举描述等。
- 不需要 `l10n` 字段，不需要动 webview。

示例：

```json
// package.nls.json（默认 = 英文）
{
  "description": "Sidebar AI assistant with cross-session memory, proactive questions, and role packs",
  "config.showMetrics.description": "Show activity metrics for debugging"
}
```

```json
// package.json
{
  "description": "%description%",
  "contributes": {
    "configuration": {
      "properties": {
        "memora.showMetrics": { "description": "%config.showMetrics.description%" }
      }
    }
  }
}
```

**验收**：`vsce package` 后 VSIX 内含两个 nls 文件；切英文/中文各重启一次，检查扩展描述、命令面板标题、设置项描述。
**风险**：`%key%` 拼错会在界面上直接显示 `%key%` 字样——用守卫兜住（§6）。

### 切片 2 · 宿主面

- `package.json` 增加 `"l10n": "./l10n"`。
- 新建 `l10n/bundle.l10n.json`（英文，由 `npx @vscode/l10n-dev export -o ./l10n ./src` 生成）与 `bundle.l10n.zh-cn.json`（中文译文）。
- 通知、错误、确认对话框文案改 `vscode.l10n.t('English source')`；日志保持中文。
- 支持参数占位：`l10n.t('Copied {0} diagnostics', count)`；复杂文案用 `{ message, args, comment }` 形态给译者留上下文。

**验收**：切语言后触发一条通知、一条错误、一条确认，三处均随语言变化；英文环境无中文残留。
**风险**：容易把日志/内部串也包进来，增加无意义翻译量——按切片 0 的三分类执行。

### 切片 3 · webview 静态 HTML

- `chatPanel.getHtml` / `settingsPanel` / `settingsSecurityHtml` 运行在宿主，模板里的静态文案直接 `vscode.l10n.t()`。
- 覆盖空态、按钮、标题、页签等大部分静态文本。

**验收**：切语言后打开对话面板与设置页，静态文案全部跟随；不出现中英混排。
**风险**：模板体积大，机械改动多；只改人类可见文案，不动 `id` / `class` / `data-*` 属性值。

### 切片 4 · webview 动态脚本（最大的一块）

- 依赖：`@vscode/l10n`（零依赖、体积小，由 esbuild 内联进 webview bundle）。
- 宿主把 `vscode.l10n.bundle` 内联进 HTML（默认语言时为 `undefined`，跳过即可）：

```html
<script type="application/json" id="memora-l10n-bundle">{"Copied":"Copied"}</script>
```

```ts
// webview 启动时
import * as l10n from '@vscode/l10n';
const el = document.getElementById('memora-l10n-bundle');
const contents = el?.textContent ? JSON.parse(el.textContent) : undefined;
if (contents) l10n.config({ contents });
l10n.t('Copied');
```

> 内联而不是走 postMessage：无协议新增、无首屏竞态；`type="application/json"` 不执行脚本，不触发 CSP。JSON 序列化时需转义 `<`，防止 `</script>` 截断。

- 按面板逐片迁移：设置页 → 角色页 → 对话区 → 状态条/活动抽屉。
- 动态拼接文案改为占位符：`` `${n} 个文件` `` → `l10n.t('{0} files', n)`。

**验收**：每个面板迁移后做一次 en / zh-cn 冒烟；重点看流式输出、确认卡、任务栏、错误提示。
**风险**：这是唯一「高」难度面——字符串量最大，且大量运行时拼接；必须按面板切片，禁止一次性全量替换。

## 5. 落地难度评估

**实测口径**（2026-10-22）：TypeScript AST 统计含 CJK 的字符串字面量，排除注释与 `__tests__`；每次大批改动后按同一方法重算。

| 面 | 候选字符串量 | 性质 | 难度 |
| ---- | ---- | ---- | ---- |
| package 元数据 | 32 | 纯静态、可机械替换 | 低 |
| 扩展宿主（`src/extension`） | 323 | 含大量日志；UI 子集更小 | 低-中 |
| webview（`src/webview`） | 977 | 含静态模板 + 动态脚本 + 少量非 UI 键 | 中-高 |
| 共享协议（`src/shared`） | 17 | 多为内部键，预计大部分不翻 | 低 |

**结论**：技术机制不难（原生 API + 内联 bundle），真正的工作量在 webview 的文案迁移与双语校对；回归风险集中在切片 3/4。建议按切片独立提交、独立验收，不做「一次性全量本地化」。

## 6. 守卫

1. **nls 键面一致**：`package.nls.json` 与 `package.nls.zh-cn.json` 的 key 集合完全相等。
2. **`%key%` 闭合**：`package.json` 中每个 `%key%` 都能在两个 nls 文件里找到；本地化字段不得残留中文字面量。
3. **bundle 键面一致**：`bundle.l10n.json` 与 `bundle.l10n.zh-cn.json` 的 key 集合完全相等（多一条少一条都红）。
4. **中文残留扫描**（可选，按面启用）：对已迁移的 UI 文件扫含 CJK 的字符串字面量，白名单放行「模型可见 / 内部事实」两类。
5. **打包检查**：`vsce package` 后确认 `package.nls*.json` 与 `l10n/` 未被 `.vscodeignore` 排除。
6. **真机冒烟**：Configure Display Language 切换 en / zh-cn，各重启一次，抽查命令面板、设置页、对话空态、确认卡。

## 7. 边界与不做

- **不做 `memora.language`**：语言真源只有一个。
- **`zh-tw` 不做**：只覆盖 `en` + `zh-cn` 两套（§8 拍板 ③ / §11.4 已定）。VS Code 按 locale 精确取 bundle、不回落，`zh-tw` 用户取默认英文文件——本轮接受的现状，不为它预留任何译文 / 占位键 / 守卫分支。
- **Marketplace README 不随语言切换**：原生不覆盖；需要时另维护多份 README，但无法自动切换。
- **角色包、提示词、工具描述不翻译**：它们是模型可见内容，语言影响行为。
- **AI 回答语言与 UI 语言分开**：前者由 prompt 决定，不在本方案范围。**2026-11-09 已独立落地**（`HOST-I18N-LLM-1` / `-2`）：宿主产出 `responseLanguageDirective` 随环境快照上报、内核原样转发；默认是**软默认**（界面语言锚点 + 让位给用户当轮语言），`memora.answerLanguage` 自由文本提供**硬指定**覆盖（空 / `auto` = 跟随）。`zh-cn` / `zh-tw` 各一条独立指令（**不是**自动回落，与上一条不冲突），未支持语言与取不到一律英文软默认。UI 文案仍全中文。
- **日志保持中文**：内部信息，不属于 UI。

## 8. 拍板项

**拍板结果（2026-10-22）**：本轮**不落、不进 0.2.0 范围**，HOST-I18N-1 保留在观察区，等下个版本再按切片推进。下列 3 项未随本轮拍板定案，**落地启动前必须先答**：

1. **目标**：只让 Marketplace 元数据对英文用户可读（只做切片 1），还是让英文用户真正可用（切片 1-4）？
2. **源码倒英文的改动量与回归面**是否接受？这是原生机制的前置条件。
3. **是否覆盖繁体中文**（`zh-tw` 单独 bundle）？

> 推荐：若目标只是「上架可读」，做切片 1 并**明确登记「半本地化」边界**；若目标是英文用户真能用，按 1-4 走完，否则进去仍是中文界面，属于误导性半成品。

**拍板答案（2026-11-09，用户确认「按推荐思路推进落地」）**：① **做全切片 1-4**（目标 = 英文用户真可用，摆脱误导性半本地化）；② **接受源码倒英文**（原生机制前置条件，不可逆但 git 历史可回溯，回归面由切片推进 + 每片真机冒烟控制）；③ **不覆盖 `zh-tw`**（2026-11-09 二次拍板收紧：形态**只做 `en` + `zh-cn` 两套**——不做 zh-tw 译文、不做繁体校对、`CHINESE_MESSAGES` 不出第二套、键面守卫维持两面对账不升三面）。

## 11. 后续迭代路线（2026-11-09 推演）

> 本节是**排批结论**，不新增决策口径（决策仍以 [ADR-042](../.trae/decisions/ADR-042-package-surface-localization.md) 为准）。
> 切片 2 已落地但**带伤**（三份只读审查在 HEAD `30cbcc21` 上定位到 6 条必须修），故路线在切片 3 之前先插一个前置批。

### 11.1 排批原则（三条，缺一则批次顺序不成立）

1. **先止血再铺量**。守卫盲区（窗口面只扫 `show*Message` 首参）不先补，后面每一批都是「在失明的判据下新增文案」——迁移面越大，台账里「已本地化」这句话越不可信。
2. **主体按面板垂直切，不按层水平切**。水平切（先全库 `showQuickPick` 再全库 `setStatusBarMessage`）会让每个面板长期停在「中英混排」态；而混排已被本仓判为撒谎形态（ADR-042 后果第 2 条、真机反馈批「面板中文语境下混排即撒谎」）。垂直切的验收单位 = 「一个面板整体翻完 = 一次可回退的形态切换」。
3. **两种运行时分批，不可混做**：
   - `src/webview/panels/*`（`chatPanel` / `settingsPanel` …）**跑在宿主进程**——模板里的静态文案直接 `vscode.l10n.t()`，零新增依赖、零内联成本（属切片 3）；
   - `src/webview/scripts/*`（`chatView` / `settingsView` / `worksView` …）是**真 webview 运行时**——拿不到 `vscode.l10n`，必须内联 `@vscode/l10n` 并由宿主把 `vscode.l10n.bundle` 塞进 HTML（属切片 4）。

### 11.4 `zh-tw` 覆盖口径（已拍板：本轮不做）

**事实（代码可查）**：`hosts/memora-vscode/l10n/` 与 `hosts/memora-vscode/package.nls*` 只有默认（英文）+ `zh-cn` 两份，**无 `zh-tw`**。此前 §8 拍板答案第 ③ 条与 ADR-042 记「覆盖 `zh-tw`」，与仓库事实相反——该口径已于 2026-11-09 二次拍板**废止**。

**拍板结论（2026-11-09，用户决定；不是待办、不是待拍板）**：**本轮不覆盖 `zh-tw`**。形态收紧为 **`en` + `zh-cn` 两套**——不做 `zh-tw` 译文、不做繁体校对、`CHINESE_MESSAGES` 不出第二套、键面守卫维持两面对账（不升三面）。

**`zh-tw` 用户的实际表现（如实登记，不修）**：英文菜单 + 英文窗口通知 + 简体内核标记（`CHINESE_MESSAGES` 对 `zh*` 一律供给简体）+ 繁体回答指令（`HOST-I18N-LLM-1` 独立指令）⇒ 四层四种语言。这是**本轮明确接受的现状**，不得在 CHANGELOG / 市场描述里声称覆盖繁中。

**为什么不选「补 `zh-tw` bundle」**：每个键要维护三份译文；繁简用词差异须人工校对（机械转换会出「檔案／文件」类错译）；`assemble` 语言分支与遗留清单同步 ×1。收益（繁中用户界面语言统一）与本轮成本不匹配，故不做。

> 处置边界：口径已定，**不再需要拍板**；后续任何一批都不得为「提前铺路」新增 `zh-tw` 译文、占位键、守卫分支或 TODO。
