§1全景：三轨一端口

记忆治理层不是「一个记忆模块加几个工具函数」，而是三条轨道共用一个存储端口：写入轨决定什么能进库，治理轨决定进库后新旧关系怎么处理，召回轨决定什么能出去。底部是 IMemoryStorage 注入端口（宿主持久化）与角色包边界（人格/规则/技能永不入库）。

写入轨 · 什么能进库

每轮对话结束后异步生成轮次摘要（fire-and-forget，不阻塞主对话），过三态门后才落库。摘要是唯一记忆单元，原始对话独立存储、可溯源。

治理轨 · 新旧关系

写路径取代检测（确定性加权 Jaccard）打 supersededBy 标记，打标不删；LLM 语义去重/冲突门面是预留扩展位（治理源列表当前为空）。

召回轨 · 什么能出去

LLM 按需调用 search_memories 工具，唯一入口 searchByKeyword，superseded 前置过滤 + 轮次互斥 + 溯源揭示。

端口 · 怎么存

内核只定义 IMemoryStorage 接口（CRUD + 关键词搜索 + touch），持久化由宿主注入（VS Code 宿主 = SQLite，库文件 .memora/memories.db；旧 JSON 仅一次性迁移）。软删进回收站，保留期由宿主策略决定（当前 30 天），物理清理须由宿主入口显式触发（无自动清理）。

锚点：src/memory/storageInterface.ts · src/agent/managers/roundSummaryGenerator.ts:1-4 · src/memory/types.ts:36-37

§2写入前三态门

RoundSummaryGenerator.generate() 不是直接调 LLM 写摘要。原料（输入原文 + 回复原文）先过三道关卡，各态日志可区分、杜绝静默跳过（2026-10-08 随 4.0.0「摘要写入前三态」审查 P1-5a 落地）。

三态各自的敌人

关卡判据治什么 / 怎么治成本
态① 原料指纹全等 治铁重复。sha256(输入 + NUL + 回复)，取原文全文、字符串全等才跳过；截断面外不同、回复略异一律放行——判据取严，宁可放行一条轻微重复，不误杀。全库比对（不限 session）：精确重复无跨会话例外。 确定性，零 LLM 调用
态② summary = null 治流水账噪音。2026-10-09 判断权归还：摘要契约允许 null，「本轮无值得沉淀的信息」是合法结论。此前强制非空，纯工具/后台轮被挤出摘要，是记忆库噪音根源（P1-5）。 LLM 调用后判断，零写入
态③ 正常沉淀 摘要类型（preference/fact/decision/intent/general）校验后落库，内容截断 500 字；触发 memoryAdded 事件（宿主「已沉淀」提示）；随后跑写路径取代检测（§3）。 1 次 LLM + 1 次 upsert

设计决策 · 两个「原料」口径刻意不同

指纹取原文全文（保证判据严格），喂给 LLM 的是截断值（输入 500 / 回复 2000 字符，控成本）。摘要生成器只吃这两个原料——上下文差异最终体现为回复差异，故原料全等 ⇒ 摘要无增量。另：摘要生成走 backgroundProvider 优先（可用更便宜的模型做沉淀），fire-and-forget 异步，异常只 warn 不阻塞主对话。

§3写路径取代检测：治理在写入时定，不留给检索时猜

新摘要落库后立即对同 session 最近 20 条未取代摘要跑取代判定——「记忆冲突消解从读时猜移到写时定」。这是生产链路上唯一的记忆冲突治理，且全程无 LLM。

要素定案
判定算法确定性启发式：新旧摘要提取增强关键词（动作词/实体词加权），加权 Jaccard 重叠率 ≥ 0.5 判取代。源码明载「确定性启发式代替额外 LLM 判断（零成本可测）」。
候选窗口仅同 session、未被取代、按 createdAt 倒序取最近 20 条。取代语义 =「本 session 内新决策替换旧同主题决策」；跨 session 长期历史不参与（无跨 session 覆盖语义），候选需全量读后过滤，窗口收敛的是重叠计算面。
取代动作给旧摘要打 supersededBy = 新摘要 id 标记，非删除——本条保留，供 traceSummary 回溯原文。
已知取舍不按 summaryType 做前置过滤：type 是纯语义标签，「同一主题不同类型是否算取代」需语义定夺 ⇒ 当前旁路（可能误取代），升级条件已写明（实测出现跨类型误取代困扰时加「type 相同」前置过滤，不预埋）。
与态①的分界态① 指纹全等 = 全库铁重复拦截（无跨会话例外）；取代检测 = 同 session 近似主题覆盖。两套判据，勿混。
锚点：roundSummaryGenerator.ts:33-41（阈值与窗口）· :251-272（候选构造）· :274-313（取代检测）· :238-240（与指纹的分界）
诚实登记 · 门面空转

MemoryGovernance.deduplicate() / detectConflicts()（LLM 语义去重/冲突检测）在生产链路空转：GOVERNANCE_SOURCES 当前为空数组——源码注释明载「唯一自动轨 = round-summary，其治理由 supersede 承担，不入本数组；空列表时 dedup/冲突检测空转（测试可显式注入治理源）」。即：生产的记忆治理 100% 走在确定性链上，LLM 门面是给未来第二写入源预留的扩展位。这是「能力已建、生产未用」的诚实姿态，也是 §9 张力之一。

§4召回治理：唯一入口 + 三道处理 + 工具层 touch

召回是工具不是注入：LLM 必须自己决定调 search_memories，内核不把记忆自动塞进上下文窗口（自动注入已退役——顺带根除了「查询→加权→更易被查询」的正反馈）。4.0.0 把入口收敛为 searchByKeyword() 唯一一个（同步 search() 移除，含其 5 条测试）。

三道处理的精确语义

处理语义
superseded 过滤 被 supersededBy 取代的摘要「不作为当前事实返回」，在截断前过滤——避免占据 top-N 槽位挤掉有效命中。条目仍保留，traceSummary 可精确回溯。
excludeRoundIds 互斥 排除「正文或摘要已在眼前」的轮次——由调用方按 loop.getExclusionRoundIds() 精确派生（= 视图内 ∪ 被替换 ∪ 在途），天然不含当轮。被排除者不补位：工具语义是「返回更聚焦的结果」，不强制凑满 limit。
溯源揭示 round-summary 命中项显式附 sessionId + roundId（与 trace_summary 参数直通，LLM 零解析直用）——不隐式编码进 name 字段，不从 metadata 读（metadata 不在存储契约保证范围内）。

纯关键词单通道的判据

无语义（向量）通道的理由写在源码里：① embedding 写端缺失导致语义通道在生产从未生效，属「宣称能力零消费」的僵尸；② 主流 agent（Anthropic Memory tool / Claude Code / Librarian Pattern）已实证「LLM 消费者 + 小语料」下纯关键词足用——LLM 会自主改述重试（工具描述已提示）。向量方案记入探索期候选，等真实「关键词搜不到」复现再按缓存重算形态补回。

§5排序哲学：单杠杆、无暗排序、无衰减

治理层的「宪法条文」在 src/memory/governance.ts 头部，原文照录：

排序单归语义分：使用轨迹唯一事实源为 accessedAt，无 score 写位/排序/clamp 位。

治理模型：supersede（写时取代）；无衰减——
摘要是事实记录无"过时"语义，记忆有效性由 superseded 写时取代判定，
低频记忆经相关性排序自然后移退出召回面，无"沉底/自然遗忘归档"语义。
锚点：src/memory/governance.ts:1-8

翻译成设计语言

条文落地形态
单杠杆 使用轨迹只有一根杠杆：accessedAt。命中即 touch（工具层 fire-and-forget，storage.touch 是唯一写位），只 touch 不加权——无 +score、无 clamp、无强化学习式的自反馈。score/boost 机制已整体退役。
accessedAt 是事实字段，不是排序键 检索入口不引入 accessedAt 时间主序（recency 定案 §5.2）：FTS 按相关性返回，accessedAt 只作为事实字段揭示给 LLM——「最近使用优先」由模型结合任务定夺，内核不替模型决定。
无衰减 摘要是事实记录，没有「过时」语义。记忆失效只有一条路：被新摘要 supersede 取代。低频记忆不删不归档，靠相关性排序自然后移退出召回面——没有「沉底」，也没有「自然遗忘」。
设计决策 · 可解释性优先

拒绝任何暗排序（score/boost）的代价是召回率小数点，换来的是可解释性：每条记忆为什么在结果里，因为关键词相关；为什么靠前，因为最近被想起——两个理由都经得起追问。配合溯源揭示（sessionId + roundId），LLM 和用户都能把结论回查到原始对话。

§6数据模型：Memory 基元

记忆即轮次摘要，source 是开放字符串（溯源标签，非封闭枚举）。所有治理字段都是顶层持久化字段——因为 metadata 不在存储契约保证范围内，而去重/取代/互斥须跨会话可靠生效。

字段治理角色说明
id / content / source / name基元id 格式 source:name；round-summary 规范 id = round-summary:{sessionName}:{roundId}（单一构造函数，禁散落字面量）。
createdAt / accessedAt时间双轨createdAt 落库时起算；accessedAt 创建时同值，工具命中即刷新（唯一使用轨迹事实源）。
supersededBy冲突治理非 undefined = 已被更新的摘要覆盖；值为取代者的 id，本条保留供回溯。召回时确定性过滤。
materialFingerprint精确去重sha256(输入‖NUL‖回复)，生成时随条目落盘；存量无此字段（不参与匹配，只管新增）。
summaryType / sessionName / roundId分类与溯源preference/fact/decision/intent/general（LLM 判，非法值兜底 general）；溯源三件套供分轨召回与 trace 回溯。
deletedAt软删除回收站机制：软删后进入回收站（保留期归宿主策略，当前 30 天），purgeExpired 由宿主入口显式触发物理清理（无自动清理）；恢复清标记。
isModified人工修改标记摘要被人工改过（可能与原始对话不一致）时置位。
metadata透传（不进契约）内核无生产写入方；不承载溯源/分类/治理字段——它们必须跨会话可靠读取。

连带治理

① 孤立轮回收：GCService 扫孤立问答闭环（宿主命令「立即执行孤儿回收」直达）；② 联动软删：Round 被物理删除（引用归 0）时，其摘要清空溯源字段后软删进回收站（恢复后即为「无需溯源的独立记忆」）——治理页单条软删则不清溯源（误删恢复保留关联）；③ 残留 source 标签（persona/rule/skill/work-projection）不写入记忆库，仅用于 typo 检测与存量识别，且不在治理源列表中。

§7五条第一性原理

  1. 记忆是结论，不是原料。唯一记忆单元是轮次摘要；原始对话独立存储、经 sessionName + roundId 溯源可回查。不把历史原样堆进上下文窗口。
  2. 治理在写入时解决，不留给检索时。三态门（指纹/null/沉淀）+ 写路径取代检测，把重复、噪音、冲突消灭在入库前；检索期只做确定性过滤（superseded/互斥），不猜。
  3. 拒绝暗排序。accessedAt 是唯一使用轨迹事实源，无 score 写位、无重要度加权；优先级判断归 LLM（揭示事实，不替模型决定）。
  4. 只拦新增，不伤存量。指纹匹配对无指纹旧条目零动作；宁可漏新不妄改旧；旧档经 parseMemory 白名单静默清洗（剥 score），不写迁移脚本。
  5. 人格与事实分离。角色包（人格/规则/技能）与记忆库是两条永不相交的轨道——换角色不丢记忆；设定记忆唯一归角色包，Bootstrap 层已空置。

教训

4 处错误全部来自同一个动作：把 CHANGELOG/注释的叙述重新排版时，丢失了时序与成本限定词。「写入前三态」在 docstring 里有确定顺序，转述时凭语感重排；「不调 LLM」在原文里只属于态①，转述时泛化到了 null。文档腐化不一定是结论过期，更多是转述即失真——所以本文所有断言带锚点，且把对质表本身写进文档。

§9对抗式观察：三处张力

  • 单杠杆是单瓶颈。库小无差；库大后「最近被命中」会经 LLM 的「最近使用优先」判断间接垄断召回面——accessedAt 既是唯一事实源，也是唯一失效模式，没有第二杠杆兜底。无衰减哲学在此付出代价。
  • 确定性链很强，但中间地带全交给 LLM 的一次判断。指纹只防铁重复；近似取代是确定性算法（稳）；但「本轮值不值得记」（态② null）是 LLM 一次性判断——误杀无补救链（原料还在、可溯源，但没有重试机制）。摘要质量 = 记忆质量，单点风险在 LLM 状态。
  • 门面空转是双刃。GOVERNANCE_SOURCES 为空让生产链路干净（无 LLM 误判风险），但「冲突检测」停在能力层——一旦未来真有第二写入源（如宿主主动记忆、MCP 外部 source），这套空转门面是即用资产还是腐烂代码，取决于有没有人接着建。建议：要么明确「多 source 治理」的启用路线图，要么在文档明标「预留位，勿当已交付能力引用」。

另注：取代检测不按 summaryType 前置过滤是已知取舍（跨类型可能误取代），升级条件已写在源码注释里——属于「有退出条件的取舍」，不计入张力。
