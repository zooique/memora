# 作品投影：AI 怎么"看懂"你的项目（极简设计）

> **定位**：极简实现（2026-08-26 剪枝重构）。作品投影 = 用户主动触发的「项目文件索引」，帮助 AI 快速了解项目结构。
>
> **设计哲学**：回归最小单元——它就是一张"项目地图"，告诉 AI 项目里有哪些关键文件，是什么内容。AI 根据名片自主决定要不要读原文。

---

## 一、它是什么

你在项目里写了一堆文档、代码、笔记。AI 帮你干活时，需要时间"探索"项目结构。

**作品投影，就是一个"项目索引"**：一张极简的清单，记录项目里关键文件的「名字」、「说明」和「位置」。

**核心字段**（只有三个）：
- **name**：文件名（自动提取，如 `architecture`）
- **description**：一句话说明（告诉 AI 这个文件是干什么的）
- **source**：文件路径（告诉 AI 去哪里找这个文件）

**存储格式**：单文件 JSON（`<memoraDir>/work-projections.json`）

```json
[
  {
    "name": "architecture",
    "description": "系统分层与模块边界",
    "source": "docs/architecture.md"
  },
  {
    "name": "api",
    "description": "RESTful 接口规范",
    "source": "docs/api.md"
  }
]
```

## 二、设计哲学：极简指针

### 为什么不用 Markdown？

我们最初的设计用了 Markdown + Frontmatter，引入了 `mode`（always/on-demand）、`body`（正文）、两级渐进披露等复杂概念。经过反思，我们认为：

> **作品投影的本质是"指针"，不是"内容"。**

如果把指针变成内容载体，就会产生：
- 格式冗余：为什么要 Markdown？JSON 更适合存储元数据。
- 维护负担：多文件管理、Markdown 解析、正文注入逻辑。
- 概念混淆：`mode`、`body` 让它看起来像一个"迷你文档系统"，偏离了"索引"的定位。

### 为什么不存储正文？

存储正文（`body`）违反了「**单一真理源**」原则：
1.  **过时风险**：缓存的正文会随时间过时。
2.  **冗余存储**：同一份内容在原文和投影中各存一份。
3.  **增加心智负担**：用户需要思考"什么时候用 always，什么时候用 on-demand"。

**正确的做法**：投影只存指针（元数据），原文是唯一真理源。AI 根据 `description` 判断相关性，自主 `read_file` 读取原文。

### 关于"必读"的实现

如果需要让 AI 必定读取某个文件（实现"指针模式"），**不通过增加新机制，而是通过 `description` 的语义约定**：

```json
{
  "name": "core-rules",
  "description": "[必读] 项目核心开发规范。在编写任何代码前，必须先读取此文件以对齐编码标准。",
  "source": "docs/rules.md"
}
```

AI 是指令遵循引擎。当 `description` 中包含 `[必读]` 标签和明确的行为要求时，AI 会遵循这个指令。

### 实战指南：用投影实现「规则」效果

**核心思路**：不需要复杂的规则引擎，只需要「作品投影 + VSCode 文本编辑」就能实现规则效果。

#### 步骤 1：写好你的 rules 文件

在项目里创建一个普通的 markdown 文件，比如 `docs/` 下的 `my-rules.md`：

```markdown
# 我的项目规则

## 代码规范
- 所有函数必须添加 JSDoc 注释
- 使用 2 空格缩进
- 变量命名使用小驼峰

## 安全红线
- 禁止在代码中硬编码密钥
- 文件上传必须验证后缀和 MIME 类型
```

#### 步骤 2：登记为作品投影

通过对话告诉 AI：「把 `docs/` 下的 `my-rules.md` 登记为作品」，或直接编辑 JSON：

```json
[
  {
    "name": "my-rules",
    "description": "[必读] 项目核心开发规范。在编写或修改任何代码前，必须先读取此文件以对齐编码标准和安全红线。",
    "source": "docs/my-rules.md"
  }
]
```

#### 步骤 3：AI 自动遵循

AI 每次开始对话时都会看到这个索引。当用户让它"写代码"时，它会：
1. 看到 `[必读]` 标签和明确指令
2. 自主调用 `read_file` 读取 `docs/` 下的 `my-rules.md`
3. 按照规则中的规范执行

#### 优势

- **零机制成本**：不需要规则引擎、不需要特殊解析、不需要新字段
- **用户完全控制**：直接用 VSCode 编辑 markdown 和 JSON，所见即所得
- **灵活性**：可以登记任何文件作为"规则"——代码规范、架构约束、安全红线、写作风格等
- **版本控制友好**：JSON 和 markdown 都是纯文本，完美支持 git diff

#### 进阶用法：按需加载规则

不是所有规则都需要每次必读。可以根据场景定制：

```json
[
  {
    "name": "code-rules",
    "description": "[必读] 编码规范。在编写或修改 TypeScript 代码前读取。",
    "source": "docs/rules/code.md"
  },
  {
    "name": "security-rules",
    "description": "[必读] 安全红线。在涉及用户输入、文件操作、API 调用前读取。",
    "source": "docs/rules/security.md"
  },
  {
    "name": "ui-rules",
    "description": "UI 设计规范。仅在编写前端组件时参考。",
    "source": "docs/rules/ui.md"
  }
]
```

AI 会根据 `description` 中的场景描述，自主判断什么时候读取哪个规则文件。

## 三、装配注入：极简清单

### 注入时机

AI 每次开始对话时，系统会读取 `work-projections.json`，将所有条目格式化成一段文本，注入到系统提示词中。

### 注入格式

```
【项目索引】
- architecture：系统分层与模块边界 (源: docs/architecture.md)
- api：RESTful 接口规范 (源: docs/api.md)

（项目关键文件指针。如需详细内容，请使用 read_file 读取对应 source 路径。）
```

### 工作流

1.  **装配**：将索引清单注入系统提示词。
2.  **AI 理解**：AI 看到项目有哪些关键文件，各自的用途。
3.  **AI 判断**：当用户提问涉及某个领域时，AI 检查索引中是否有相关文件。
4.  **按需读取**：若判断相关，AI 自主调用 `read_file` 读取 `source` 指向的文件。

## 四、与其他系统的关系

### 与记忆系统的区别

- **记忆**：对话的沉淀（"我们聊了什么"）。
- **投影**：项目的地图（"项目里有什么"）。

投影不参与记忆召回、不参与记忆治理。它是独立的第三轨。

### 与角色包的区别

- **角色包 Rules**：AI 的行为规范（"你应该怎么做"）。
- **作品投影**：项目的文件索引（"你应该知道什么"）。

投影始终是「文档入口」语义，不引入「规则/设定」等新语义类别。

---

## 五、核心 API

### `registerWork(sourcePath, description)`

登记一个作品索引。

- **参数**：
  - `sourcePath`：源文件路径（相对项目根，如 `docs/` 下的 `architecture.md`）
  - `description`：一句话说明（告诉 AI 这个文件是干什么的）
- **返回**：登记成功的条目，失败返回 `null`
- **行为**：向 JSON 数组追加/更新一条记录。相同 `source` 会被覆盖。

### `listWorks()`

获取当前所有作品索引。

- **返回**：`WorkProjectionEntry[]` 数组

### `contextBlock()`

获取装配注入文本块。

- **返回**：格式化的索引清单字符串；无投影时返回空串

## 六、安全与防御

### 路径穿越防御

登记时会验证 `sourcePath` 不越界项目根目录。尝试登记 `../../../etc/passwd` 等路径会被拒绝。

### 格式注入防御

`name` 和 `description` 字段会进行单行化处理（折叠换行为空格），防止换行注入破坏 JSON 格式。

---

## 七、一句话总判

> **作品投影 = 用户主动触发的「项目文件极简索引」（JSON 单文件：name + description + source）。它就是一张"项目地图"，告诉 AI 项目里有哪些关键文件。AI 根据 description 自主判断相关性，按需 read_file 读取原文。支持用 `[必读]` 标签实现「规则」效果——用户写好规则文件后登记到投影，AI 会自主读取并遵循。零机制成本，用户用 VSCode 直接编辑 JSON 和 markdown 即可。**
