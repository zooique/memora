# 任务驱动的多轮闭环收敛模型

> **定位**：本模型是"单轮问答闭环 = 种子"哲学的**外循环语义化**——它回答一个问题：**复杂的笼统问题，如何从一棵干净的种子长成"有条理、有起点、有终点"的多轮执行？**
>
> **状态**：设计愿景（探索中，未固化 ADR）。本文论证目标形态与现状的差距，不含实现承诺。
>
> **哲学真理源**：[agent-design-philosophy.md](./agent-design-philosophy.md)（闭环 = 最小单元）· [loop-design.md](./loop-design.md)（Loop = 闭环的重复）· [module-inventory.md](./module-inventory.md)（模块现状）

---

## 〇、核心命题

> **触发器分两态：简单问题一问一答（单轮闭环）；复杂问题通过"任务驱动外循环"收敛（多轮闭环 + 起始与收尾），直到问题收敛完毕。**

问答闭环是**单一真理源**——无论简单还是复杂，都是同一棵种子。复杂度不改变单元，只改变**如何串联单元**：

| 问题难度 | 行为 | 闭环数 |
|---------|------|--------|
| 简单 | 直接回答，一问一答 | 1 轮 |
| 复杂 | 编排任务链 → 逐个闭环执行 → 收敛汇报 | 多轮（loop） |

---

## 一、完整生命周期（目标形态）

```
外部输入（大问题）
  │
  ├─[LLM 判难度]──────────────┐
  │  简单                     │ 复杂
  ▼                           ▼
 直接回答               【第 1 个闭环】调查 + 编排任务链
    │（一轮 done）            │  task_table_write 建长任务链
    │                         ▼（本轮结束，进入 loop）
    │                  【loop 模式】任务链逐步驱动多轮闭环
    │                    ├─ 每轮解一个任务，task_table_update 标记
    │                    ├─ 过程中可主动提问 / 用户插话 / 暂停续跑
    │                    └─ 任务链全部 done → 收敛
    │                         ▼
    │                  【汇报闭环】汇总任务结果，产出总结汇报
    ▼                         ▼
   结束                    【摘要提炼】汇报 → round-summary（摘要即记忆）
```

## 二、五个阶段的落地映射（现状 vs 目标）

| # | 阶段 | 目标形态 | 现状 | 差距 |
|---|------|---------|------|------|
| 1 | **难度分级** | LLM 判简单/复杂，简单直接一轮 done | 无显式分级，靠 LLM 自主决定是否调工具 | 可增强为显式决策（但非新增机制，是闭环回答前的一次判断） |
| 2 | **调查** | 复杂时用 read_file/list_dir 等工具调查实情 | ✅ 内置工具已具备 | 无 |
| 3 | **编排任务链** | task_table_write 建长任务链，一轮闭环只干"编排" | ✅ 工具已具备；**但驱动力是"内循环"** | 需把驱动力接到"外循环" |
| 4 | **loop 执行** | 任务链逐步驱动多轮闭环到收敛 | ✅ loop 已有；**终止是无条件 while** | 需升级为"任务链驱动 + 有语义终止" |
| 5 | **汇报 + 摘要** | 独立汇报闭环 → 产出电话总结 → 提炼摘要 | ❌ 无独立汇报闭环 | **纯新增**，且高度契合"摘要即记忆" |

## 三、两个关键设计决策

### 决策 A：内循环 vs 外循环——双轨任务，非此即彼

> **背景**：task_table 驱动的"内循环"（单轮闭环内的工具调用继续）已存在；本模型引入的"外循环"（跨多轮闭环的任务链驱动）是不同形态。

| 任务类型 | 驱动对象 | 语义 | 现有性 |
|---------|---------|------|--------|
| **内部任务** | 单轮闭环内的工具循环（内循环 continue） | "一个闭环有多深" | ✅ 已实现，**必须保留** |
| **外部任务** | 跨多轮闭环的串联（外循环驱动下一个闭环） | "一次任务有多长" | ❌ 待增加 |

**判定**：两者正交互补，不是非此即彼——内部任务保留（复杂步骤在单轮内连续执行），外部任务新增（清单驱动多轮）。对照哲学 §7.3「内循环深 / 外循环长」配比。

### 决策 B：loop 的终止语义化——从"撞上限"到"任务收敛 + 汇报"

> **背景**：现状 loop 是 `while (iteration < maxIterations)` 无条件重复，靠"上限"兜底。本模型把它升级为"任务链驱动 + 收敛汇报"。

| 维度 | 现状 | 目标 |
|------|------|------|
| 触发 | 无条件进入 loop | LLM 判复杂后才进入 |
| 驱动 | 无任务语义，单纯重复 | 任务链逐步指导下一步 |
| 终止 | 撞 maxIterations/stepBudget | 任务链全部 done |
| 收尾 | 直接断开 | **独立汇报闭环**（汇总→产出→提炼摘要） |

---

## 四、汇报闭环 → 摘要记忆（决策 C，高价值纯增量）

> **核心洞察**：任务收敛后的独立汇报闭环，是**摘要记忆的最佳信息源**——它天然是一段自洽的"我做了什么"总结，直接可提炼为 round-summary（摘要即记忆单轨）。

**为什么这是良配**：
- 汇报闭环的产出 = 结构化总结（目标回顾 + 已完成步骤 + 结果），比零散对话更易提炼
- 符合"摘要即记忆"——汇报本身就是一条高质量摘要候选，无需新机制
- 落地即**纯新增**：在任务链收敛后，再编排一次"汇报"闭环，其产出走既有 round-summary 生成管线

---

## 五、loop 运行时的既有能力（现状已具备，无需新建）

> 用户记忆中的"loop 运行时能做什么"——**全部真实存在于代码**，是闭环迭代边界的天然能力，非 loop 补丁：

| 能力 | 真实实现 |
|------|---------|
| **主动提问** | `extractAskQuestions` 解析 `[ASK]` → `question_pending` 事件 |
| **用户插话** | `interject()` 立即中断 + 排队 `pendingInterjections`，迭代边界消费 |
| **申请暂停** | `requestPause()` → 迭代边界 `onPaused` 挂起 |
| **继续运行** | `continueAfterPause()` 从边界续跑 |

**结论**：这些是"闭环边界天然提供的交互点"，本模型只需在 loop 执行阶段**正常使用**它们，不新增机制。

## 六、与哲学的一致性验证

| 哲学论断 | 本模型 |
|---------|--------|
| 闭环 = 最小单元 | ✅ 简单/复杂都用一个种子 |
| Loop = 闭环的重复 | ✅ 外部任务 = 闭环的语义化重复 |
| 内循环深 / 外循环长 | ✅ 内部任务（深）+ 外部任务（长）双轨 |
| 摘要即记忆 | ✅ 汇报闭环 → round-summary，单轨不破 |
| 没有第二套引擎 | ✅ 任务链只是"闭环用什么顺序被调用"，不造新引擎 |

## 七、实施分期建议

| 阶段 | 内容 | 风险 |
|------|------|------|
| **第一版（推荐）** | 难度分级（简单直接回答）+ 独立汇报闭环 + 汇报→摘要提炼 | 低（纯新增，不破坏现有 loop） |
| **阶段 2** | 外部任务驱动 loop（task_table 驱动力从内循环接入外循环 + loop 终止语义化） | 高（动 Handoff 终止语义，建议并入 seed 收敛方案） |

> **决策建议**：第一版先落地"难度分级 + 汇报 + 摘要"，避免冒险动现有 loop 终止语义；外部任务作为 seed 收敛后的阶段 2 生长。
