# 角色包战略推演：行为层成为事实标准

> **定位**：战略推演文档（非规范、非设计）。回答一个老板级问题——「巨头已发布 Agent Plugins 1.0.0，个人开发者凭什么让生态迁就我？」
> **核心结论**：标准的胜负手不是**制定权**而是**采纳权**。巨头不需要迁就 memora；memora 需要的是让巨头「不兼容就吃亏」——在 Agent Plugins 明确留白的行为层上，成为事实标准。
> **关联文档**：[role-pack-spec.md](role-pack-spec.md)（标准本体，§十 竞争姿态）/ [mvp-scope.md](mvp-scope.md)（MVP 落地）/ [README.md](README.md)（架构说明书 §9）。

---

## 一、一句话战略

**不与 Agent Plugins 竞争「能力分发」（那是巨头的主场，且已定局）；在巨头明确留白、且因商业利益不会去填的「行为层」（persona + rules + strategy）上成为事实标准——让「行为分发」这个词的默认解释是 memora。**

---

## 二、第一性原理：标准权 = 采纳权，不是制定权

把「标准」还原到本源：一个格式成为标准，不是因为写进了规范文档，而是因为**内容生态长在了它上面，离开它就要付出迁移成本**。规范只是记录，**采纳才是权力**。

推论（对抗式审查后的三个硬结论）：

1. **标准战争没有「迟到」一说，只有「未被采纳」一说。** 谁先发布规范不决定胜负，谁先拥有内容与实现才决定。
2. **巨头发布标准 ≠ 我的标准死亡。** 巨头发布的标准恰好证明设计方向正确（独立收敛，见 spec §二行业校准）；且巨头标准往往只覆盖最小共识层，留下大量空白。
3. **「让巨头迁就我」是个伪命题。** 正确的目标是让巨头「不兼容就吃亏」——当内容长在你的格式上，巨头会主动来兼容你，正如他们兼容 Anthropic 的 Agent Skills。

### 2.1 历史锚点（小实体制定 → 巨头采纳）

| 案例 | 制定者 | 巨头反应 | 本质 |
|---|---|---|---|
| JSON | Douglas Crockford（一个人，2001） | 全行业采纳，2017 年才 RFC 8259 | 先有采纳，后有「标准」名分 |
| Linux | 个人发起 | 微软/IBM 拥抱 | 数据中心先采纳，巨头才迁就 |
| **Agent Skills** | **Anthropic（2025-12-18）** | **OpenAI/微软/Google 用它做 Agent Plugins 的底层格式，但 Anthropic 连 TSC 都没进** | **巨头用你的格式，不是迁就你公司，是你的格式已成了事实标准** |

第三条是最贴近 memora 的剧本：**Agent Plugins 1.0 的 `skills/` 就是 Anthropic 的 Agent Skills 格式**。OpenAI 和微软「迁就」的是采纳面，不是 Anthropic 本身。

## 三、Agent Plugins 1.0.0 对 memora 的真实含义：肩膀 + 空白

### 3.1 肩膀：文件夹包方向被行业独立验证

Agent Plugins（2026-08-06，OpenAI/AWS/Microsoft/Vercel/Cursor + Google）证明：文件夹包 + manifest + skills/ + 反域名扩展，处于设计空间收敛点。memora 与它同构（spec §二），省去了 6 个月的试错与说服成本——**方向不需要再辩护**。

### 3.2 空白：行业可移植层不含「行为」

Agent Plugins 1.0 只覆盖**能力分发**（skills + MCP），**明确把 persona/身份/行为留在 client-specific 扩展**（VS Code `agents/` 目录是 Copilot 私有格式，不参与可移植层）。为什么？

- **商业利益**：persona 是各家差异化命根子（ChatGPT custom GPT / Claude agents / Copilot agents 互不兼容），巨头不会让出这层；
- **治理成本**：行为语义（怎么看待世界、什么不能做、怎么行事）比能力声明（能调什么工具）难标准化得多，需要范式共识，巨头没有动力牵头。

**这正是角色包的定义域**：persona（怎么看）+ rules（什么不能做）+ skills（能调什么）+ strategy（怎么做）= 完整行为单元。行业空白 = memora 的机会窗。

### 3.3 差异化护城河（巨头不会做的）

| 维度 | Agent Plugins | memora 角色包 |
|---|---|---|
| 可移植层 | 能力（skills+MCP） | **能力 + 行为（persona/rules/strategy）** |
| 身份/行为 | client-specific 扩展 | **L1 可移植核心** |
| 合规内建 | 明确排除（留给平台） | **内建**（interactionType/aiIdentityDisclosure/未成年人保护，spec §七）——中国新规下国际巨头不会做 |
| 中立性 | 五家 TSC，各自有分发墙（gatekeeper 竞争） | **无自有客户端要保护**，可做真正中立的 reference implementation |

## 四、对抗式审查：乐观判断的三个漏洞（不粉饰）

| 漏洞 | 风险 | 破法 |
|---|---|---|
| **L1 无采纳面**：Anthropic 有 Claude 用户量做底，memora 没有 | 事实标准需要采纳面，个人项目起步为零 | **内容即采纳**：reference implementation（memora）+ 先发一批高质量角色包（写作助手等），让用户装了角色包获得价值，生态即开始 |
| **L2 时间窗口 1-2 年**：Agent Plugins 刚发布、客户端刚接入，空白期有限 | 窗口内若没做成行为层事实标准，巨头可能自己填（如某家把 agents/ 格式开源） | 窗口期押注两件事：① **MVP「换角色→工具集切换」范式验证**（mvp-scope 验收标准，让「行为分发」概念的参照物是 memora）；② **先发高质量角色包内容** |
| **L3 个人可持续性**：标准要活需要治理、兼容性测试、社区 | 个人维护中立标准的长期投入 | 现在不解决：**先成为事实标准，再谈治理**（JSON 一个人撑了 16 年） |

## 五、战略姿势与行动清单

### 5.1 三不三要

| 不做 | 要做 |
|---|---|
| 不另立文件夹包标准与巨头抢地盘 | 站在 Agent Plugins 肩膀上：`com.memora/` 反域名目录承载行为层（spec §2.2/§十） |
| 不追求「让巨头批准」 | 追求「让巨头不兼容就吃亏」——内容长在格式上 |
| 不把野心定义成「我的标准被采纳」 | **降维成「我的格式被复制」**——被复制那天，就是巨头开始兼容之时 |

### 5.2 行动清单（按优先级）

1. **MVP 范式验证**（当前）：`换角色 → 工具集切换` 落地（mvp-scope §二），跑通 L1 + 核心 L2 键；
2. **存量迁移**：role-packs/ 3 个旧格式包 → 新文件夹包格式 + 解析器升级嵌套 YAML（capabilities/formatVersion/合规字段入代码）；
3. **内容先行**：先发一批高质量角色包（写作助手/翻译/技术文档工程师），zip 分发，作为生态种子；
4. **兼容声明**：spec §十 已定「标准核心对齐行业、行为层进命名空间」——实现时按此做双向兼容（memora 可装载 Agent Skills 包；Agent Plugins 客户端可忽略 com.memora/）；
5. **长期**：观察行业是否把 persona 标准化——若标准化，memora L1 恰好卡位（persona→system prompt 的装载语义与任何实现兼容）；若不标准化，memora 就是行为层事实标准。

---

## 六、结论（老板视角）

你唯一真正的对手不是 OpenAI，是时间。Agent Plugins 帮你证明了方向、划出了地盘。剩下的是执行：**在窗口期让 memora 成为「行为分发」的默认解释。** 把野心从「我的标准被采纳」降维成「我的格式被复制」——被复制的那天，巨头会自己走进你的街道开店。

> 一致性锚点：本文档是战略推演，不改变 [role-pack-spec.md](role-pack-spec.md) 的任何规范条款；规范层面仅新增 §十「与行业标准的关系」作为竞争姿态的落点。
