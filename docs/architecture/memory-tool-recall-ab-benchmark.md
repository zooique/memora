## 0. 验收口径（承接设计正文 §阶段1 出口条件）

| 指标 | 定义 | 门槛 |
|---|---|---|
| **A · 想起率** | **隐含相关**（用户未明说"上次/之前"，但内容与库中记忆相关）→ LLM**主动**调用 `search_memories` 且命中正确条目的比例 | 记录基线，与自动注入基线对照；**本地 < 云端一半且同题 ≥3 复现 → 触发 C 路径演进（§3.2/§6.9）或最小常驻轨回退（§1.3）** |
| **B · 命中率** | **显式提点**（"上次那个 X""按之前定的方案"）→ 查到正确条目 | **≈100% 硬门槛**（未过不视为阶段 1 落地） |

- **失败定义（精确）**：值得回忆的场景（内容与过往相关）却未查询 **且** 答案劣于有记忆时 → 失败。"直接干"（简单任务判断为不值得回忆）且干对 = 想起判断的合理产物，**不算失败**。
- **分模型**：云端大模型 vs 本地小模型跑同一问题集（memora 最小公分母是本地 LLM）。
- **阈值纪律**：B≈100%、本地/云端 A 对照阈值在实施前随验收集冻结，不得事后按结果调标。

## 1. 关键约束（本轮新增认知：互斥避让）

1. **目标记忆必须置于「当前会话正文未载入」的位置**——否则会被装配期正文（[Recent conversation]）或 `search_memories` 的工具互斥（§5.1，`excludeRoundIds` 排除当前会话最近 `HOT_MEMORY_MAX_ROUNDS` 轮）排除，命中即被过滤，**不算有效命中**。
   - 实现：目标记忆写入**另一会话**（不同 `sessionName`）或**当前会话更早轮次**（超过互斥热窗口的旧轮）。
2. **种子隔离**：每个 case 的目标记忆用独特实体词（如 `ZizzleNgauge`），避免与库内既有记忆语义混淆干扰命中判定。
3. **判定两段**：`queried?`（是否主动调 `search_memories`）→ `hit?`（返回结果是否含目标记忆 roundId）。A 只看前段+后段都成立才计一次成功；B 命中判据以返回含目标 id 为准（显式提点本应主动查）。

- **计算**：A 想起率 = 成功(A) / 有效 A 用例数（排除被互斥误排的无效项）；B 命中率 = 成功(B) / B 用例数。B 不达标 → 判定阶段 1 未落地，可直接回退或升级。
- **无效-互斥**：若目标记忆因落入热窗口被排除导致未命中，count 为无效（非失败），计入约束 1 的装载修正。

### 3.1 首轮实测（2026-09-09 · xiaomimimo `api.xiaomimimo.com`）

通过 `scripts/test-memory-tool-recall-real.ts`（最小 tool-calling 环，仅暴露 `search_memories`）驱动 10 个 case：

| case | queried? | hit? | 判定 | 备注 |
|---|---|---|---|---|
| A1 | ✓ | ✓ | 成功 | 主动检索且命中（缓存方案复用） |
| A2 | ✓ | ✓ | 成功 | 线上服务 |
| A3 | ✓ | ✓ | 成功 | 代码风格 |
| A4 | ✓ | ✗ | **失败** | 检索了但未命中——query 措辞与记忆正文未语义相撞（见下） |
| A5 | ✓ | ✓ | 成功 | 报错复用 |
| A6 | ✓ | ✓ | 成功 | round-summary 方案上下文 |
| B1–B4 | ✓ | ✓ | 全部成功 | 显式提点必查必中 |

**汇总：A 想起率 = 83%（5/6）· B 命中率 = 100%（4/4，过 ≈100% 硬门槛）**

**A4 失败归因（已收口，2026-09-10）**：A4「评审走五维清单」——LLM 主动检索了（queried ✓）但返回未含实体 `ZizzleReview`。理想查询 `评审五维清单` 自检可命（检索召回 OK），实跑 query 措辞不同导致未命中 → 属**检索召回**问题（非「是否想起要搜」）。**阶段3 score 退役后复测（commit 32f65443 后，2026-09-10）：A4 仍 miss，命运与 score 完全无关** → 钉死归因「纯检索召回质量问题，与排序/score 无耦合」。待选项：①提 query 精确性引导；②kernel 检索对近义词召回增强；③换更难命中的记忆正文措辞（当前 `评审` 与 `五维清单` 较泛）。三选项裁决待「本地小模型同题对照」数据（见 §5）。此失败不计入「模型不主动回忆」，A 想起率实质 6/6 主动检索。

**结论**：本机（xiaomimimo 云端）首轮 B 已过硬门槛；A 主动检索全过、命中 5/6。需补本地小模型同题对照（触发「本地 A < 云端一半且 ≥3 复现」评估后才论 C 路径）。

## 4. 跑测流程与装载建议

1. **装载器 + 可达性自检**：[scripts/test-memory-tool-recall-benchmark.ts](../scripts/test-memory-tool-recall-benchmark.ts)（新增，独立于 [test-memory-tool-recall.ts](../scripts/test-memory-tool-recall.ts) 的机制脚手架）——`loadBenchmarkSeed()` 按表逐 case 写入**隔离会话** `2026-09-01-benchmark`（content/preference 落普通字段；round-summary 用旧轮 `r9-bench-seed`，双保险避开组装互斥），再对每个 case 用理想查询 `search_memories` 断言目标**实体词被检索返回**（可达性自检：证明「果实可及」，种子措辞不失效才值得上真实 LLM）。脚本末尾打印判定记录表骨架供实跑填写。
2. **跑测**：真实 LLM（云端/本地各一套）驱动新会话，注入问题输入，捕获：是否调用 `search_memories`、返回是否含目标 roundId。
3. **同题复现**：A 系每个 case 建议跑 ≥3 次以判定"本地 < 云端一半且 ≥3 复现"是否触发 C 路径。
4. **阈值冻结**：B=100% 硬门槛 + A 对照阈值在首轮跑测前冻结，事后不调标。
