## 1. 子会话可见性 = 进列表但归组（不是隐藏）

**口径**：子会话出现在历史会话列表里，但归入「子会话」组（或带标记的组），与用户会话可区分；
**不做**「隐藏不可见」。

### 1.1 依据是硬约束，不是 UI 偏好

写盘确认卡**只推前台会话**，且计时器**只在首次上屏后**才起；超时按 fail-closed 自动拒。
三条实测事实（均在宿主 `hosts/memora-vscode/src/extension/host/confirmCoordinator.ts`）：

- 按会话绑定、后台会话的确认**照常入队但不先上屏**，切到该会话才补推卡（类头注释）；
- 计时器**只在首次推出时**才启动（`timer` 字段注释：从未上屏的后台请求不烧超时额度）；
- 超时按 fail-closed **自动拒绝**（`CONFIRM_TIMEOUT_MS` 注释）。

**推论链（三条缺一不可）**：子会话若对用户不可见 ⇒ 它永远不是前台 ⇒ 确认卡永不上屏 ⇒ 计时器永不启动
⇒ 永不超时 ⇒ **父会话在等子会话结果时永久阻塞**（表现为「点了没反应」，且没有任何提示）。

> 因此「隐藏子会话」不是 UI 洁癖问题，是**死锁**问题。任何为「列表更干净」而隐藏子会话的提案，
> 必须先推翻这条推论链，不能只谈观感。

### 1.2 代价（一并记账）

- 列表会变长 ⇒ 需要分组 / 折叠，否则用户会话被淹没。
- 子会话的删除 / 归档语义需另定：用户删了子会话，父会话还在等它 ⇒ **必须有终止语义**。

## 2. 目标作用域 = 项目级

**口径**：目标（指导文档 + 它的推进状态）按**项目**作用域，不按会话，也不按工作区全局。

### 2.1 依据

「一个 Agent = 一个项目」（[agent-design-philosophy.md](./agent-design-philosophy.md) 的单 Agent 模型）。
按会话作用域会让「同一目标的推进」在换会话时断裂，而断裂点恰好是子会话最常发生的地方。

### 2.2 代价一：git 处置**未拍板**（❓ 落地前必须先定）

项目级文件落 `.memora/` ⇒ 会进 git 工作区。必须二选一并写进文档：

- **进版本库**：目标是团队共享的事实；
- **进 `.gitignore`**：目标是本地私有。

两种都合理，但不能不选——不选就等于每次 `git status` 都看到它，用户会以为是脏文件。
**当前状态：未定案**（本文件只登记这个待决点，不代替用户拍板）。

### 2.3 代价二：多根工作区只覆盖首根（既有口径的继承，不是新缺陷）

项目根恒取 `workspaceFolders[0]`：宿主侧 `chatPanel.ts` 的根目录解析与 `extension.ts` 同口径
（原文注明「伪多根支持，已删」）。多根场景下目标只落在第一个根目录，其余根看不到。

> 这是既有项目根口径的**继承**，不是目标功能引入的新缺陷；但目标功能会把它**放大**
> （用户会问「另一个根怎么没有目标」）。落地时需要预备一句对外口径，别让用户以为是 bug。
