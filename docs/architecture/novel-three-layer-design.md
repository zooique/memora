# 共鸣小说家：三层结构创作方法论设计（探索中）

> **状态**：探索中（2026-09-13）。未定案、未占 ADR 编号、未改 README 索引。经真实场景复现消费后按 S2 触发固化。
>
> **一句话**：小说创作 = **需求层（当下社会缺什么）→ 内核层（不变的人性故事）→ 形式层（内核与读者的纽带）**，三层自洽后逐层落为可写方案。
>
> **土壤来源**：本文设计前的行业搜索养分（网络为土壤）：2026 网文市场趋势（光明日报 / 中国作协网 / 平台数据分析）与经典故事理论（麦基《故事》等），详见 [§四 行业印证](#四-行业印证搜索养分)。

## 一、核心主张（用户理念沉淀）

小说不是"讲一个好听的虚构故事"，而是**用故事回应当下人的精神需求**。三层结构：

| 层 | 回答的问题 | 变化性 | 来源 |
| --- | --- | --- | --- |
| **① 需求层** | 为什么写：当下社会普罗大众的痛点痒点是什么、缺什么精神供给 | 随时代变 | 上网搜索当前社会热门事件/现象 → 分析 → 反推精神需求缺口 |
| **② 内核层** | 写什么：故事的精神内核（人性和人的故事） | 不随时代变 | 经典故事之所以经典，因内核底层是人性——社会形态变、人不变，社会关系/亲子关系/人际关系不变，只是表现形式变 |
| **③ 形式层** | 怎么表达：题材、文笔、故事设定、表达形式 | 服务内核 | 形式是搭建"精神内核 ↔ 读者"的纽带；**不同内核需配不同题材与设定** |

**创作顺序**：先需求 → 再内核 → 最后形式。需求是种子发芽的土壤，内核是种子本身，形式是长出来的枝叶。

## 二、发散：三层之外的完整创作地图

写小说远不止三层。三层解决"写什么方向"，其下还有决定"能不能写出来、写得好不好"的横向维度：

### A. 需求层的细化缺口

1. **读者群体画像**：痛点属于"谁"？Z 世代 / 中老年 / 女性 / 男性 / 下沉市场，不同群体的痛点与阅读习惯完全不同。例：2026 中老年情感题材搜索量上涨 280%，付费主力是 45 岁以上中老年 + 新就业体力群体——"沉默的大多数"被重新发现。
2. **需求验证**："热门事件 → 需求缺口"是**推测**，如何验证？搜索什么（社会事件、平台榜单、读者评论）、看什么数据（完读率/留存/标签热度）、如何避免"想当然的痛点"。
3. **情绪价值类型学**：2026 读者需求已从"单纯爽感"转向"情绪代偿/解压/共鸣"——反内卷、职场反击、中年救赎、精神内耗治愈、反抗规训。需求层要能区分**解压型 / 治愈型 / 共鸣型 / 代偿型 / 爽感型**，不同型对应不同内核与形式。
4. **时效性分级**：社会热点有保鲜期（3-6 个月），内核没有。需求层输出必须区分"**当下红利**"与"**长期底色**"。

### B. 内核层的细化缺口

1. **内核元库（原型库）**：经典内核能否类型化？麦基《故事》的"原型 vs 陈规俗套"——原型 = 挖掘普遍人性体验，以独特文化细节呈现。可沉淀的母题候选：身份认同、规则与自由、爱与牺牲、代际冲突、阶层跃升、自我救赎、亲密关系、孤独与连接……
2. **内核提取方法论**：如何从一部经典里"提炼内核"（去掉时代外壳，留下人性骨架）？需要一个可复用的提取步骤。
3. **内核 ↔ 需求适配规则**：不是任意内核都能承接任意痛点。需要规则判断"这个需求缺口该配哪类内核"——如"被规训的疲惫"配"规则与自由"、"孤独感"配"孤独与连接"。

### C. 形式层的细化缺口

1. **题材与内核匹配**：同一内核可配多种题材，但题材有限制力——"规则与自由"可配规则怪谈（制度异化）、职场文（体制牢笼）、仙侠（修行体系），不可配无冲突的日常流水。需要匹配规则。
2. **世界观四维**（麦基）：时代 / 期限 / 地点 / 冲突层面——世界越小、钻研越深，越自由，越能避免陈词滥调。
3. **叙事结构**：三幕式（1:2:1）、《救猫咪》15 拍、节拍-场景-序列-幕-故事弧光的最小单位体系（每场景必须有价值转变，无转变即删）。
4. **人物弧光**：欲望 → 障碍 → 代价 → 转变（现有 persona 的"故事三要素"雏形，需成体系）。
5. **节奏与钩子**：2026 网文短剧化、一章一个反转/钩子、前 10 页立人物。平台（阅文 vs 番茄）算法分发逻辑影响节奏设计。
6. **类型常规**：每种类型有读者期待的元素，满足常规是底线、超越常规才是原创。

### D. 横向全流程缺口

1. **流水线编排**：需求分析 → 内核锁定 → 题材匹配 → 世界观 → 人物 → 结构 → 章节 → 成文 → 打磨 → **验证**。现状角色包无此编排，作者从"帮我写小说"到成文缺少引导。
2. **连续性管理**：长篇连载的人物状态、伏笔、时间线一致性（现有 foreshadow 技能覆盖部分）。
3. **验证与反馈闭环**：写完如何自检？读者视角重读、留存思维（开头 3 章留人）、价值转变检查（每场景）、情绪价值是否达成（对照需求层）。
4. **AI 协作边界**：代笔 vs 辅助。现有 rules 已有"不代笔关键选择"，需扩展到：创作主权（内核/命运由作者拍板）、一致性义务（不擅自改设定）、场景感保留。

### 四-2. AI vs 人类写作差异与协同分工（第二波搜索养分，2026-09-13）

> 用户发起"先探索 AI 写小说的更多可能"后，本波搜索定位了 AI 与人类写作的底层差异与 AI 的结构性缺陷，结论进入角色包（协同分工 / 反 AI 特征治理 / 文风杂交 / 创意杠杆）。

**核心差异**（行业实证，非观点）：

| 维度 | 人类 | AI | 胜者 |
| --- | --- | --- | --- |
| 风格 | 一生 1-2 种声音，换风格需多年训练 | 任意风格秒切、可杂交出不存在的新风格 | AI |
| 真实体验 | 亲身经历、人生细节、幽微情绪 | 无"灵魂的阅历"，共情是模拟 | 人 |
| 叙事骨架 | 偏爱留白（开放式结局/支线/不点题） | 说教强迫（77% 点题）、闭环强迫（给每个角色交代）、无支线（79%） | 人 |
| 一致性 | 长文写到后面人物漂移、时间线对不上 | 设定圣经建立后全篇零漂移 | AI |
| 节奏 | burstiness：长短句天然参差 | 句长像节拍器均匀，一眼可辨 | 人 |
| 速度规模 | 日更万字是极限 | 几分钟几万字 | AI |
| 原创性 | 真创造：意想不到的连接 | 重组既有模式，无真正突破 | 人 |
| 文化广度 | 生活在一文化，异国异代靠想象补 | 语料横跨全球文化/历史/职业 | AI |

**扬长避短的协同分工结论**（角色包内落地）：

- **AI 负责广度（人做不到的）**：文风切换与杂交、创意穷举（1→N）、工程一致性（长篇零漂移）、全球语料与跨界混搭、读者模拟；
- **作者负责深度（AI 做不到的）**：真实体验注入、情绪真相（"心里有话要说"）、终极判断（定方向、选候选）、原创突破（0→1 灵感）；
- **协作定位（历经 3 轮演进定稿）**：~~不代笔关键选择~~（过绝对）→ ~~人机协同四步循环~~（过流程化）→ ~~直接产出完整成稿~~（过绝对）→ **目标产出完整成稿**：以完整成稿为交付目标，过程中方向性问题（内核锁定/转折走向/主角命运）主动提问、有更好的建议直接提出，与用户讨论推进——不闷头写完也不每题必问；成稿是候选稿，由用户审阅定稿；
- **明确排除**：交互式实时写作（连载引擎/读者投票续写/个性化版本）是**新系统**，超出角色包职责（角色包本质仍是"写一部文字小说"），记为未来系统方向。

**反 AI 叙事特征治理**（StoryScope 实证 → craft-review 落地）：AI 五大结构性缺陷可枚举、可检测、可清除——说教强迫（直接点题）、闭环强迫（全员交代结局）、无支线（单线直推）、节拍器句长（均匀无 burstiness）、主角驱动过度（每冲突主角亲手解决）。

**AI 独有优势落地**（扬长）：文风杂交（骨架+血肉：鲁迅×刘慈欣）+ 多文体 A/B（同场景 2-3 版候选，以量换最优）→ `style-weaver`；创意穷举（内核→N 个候选，每个带成本，作者挑选）→ `idea-lever`。

## 五、落地路径（探索中，不定案）

1. **先收敛方法论本身**：本文三层结构 + 缺口清单经用户确认后，才进入角色包改造。
2. **角色包演进落地**（按 G1-G9 优先级，2026-09-13）：
   - persona.md / rules.md / manifest.json：三层方法论 + `web:search` 已随 **共鸣小说家** 角色包落地（原小说助手收敛更名，4 技法技能 git rename 吸收）；

#### 技能可发现性双锚点（2026-09-13 探索结论，落地时复现实证）

敏感点：内置 skills 的"可发现性"有两个来源，二者分工不同、**可删一不可**：

| 锚点 | 机制 | 作用 |
|---|---|---|
| **L1 清单（系统兜底）** | `buildSystemPrompt` 从 skills/ 目录扫描 name+description 拼入 system prompt | 保证技能文件存在即可见，不依赖作者记得写——删了系统级兜底就没了 |
| **设定文本引导（叙述触发）** | persona 工作流程 / rules 纪律里高亮"什么情况用什么 skill" | 让 LLM 的调用决策由**场景契约**驱动，而非靠猜扁平 description |

**实证（反例即教训）**：共鸣最初 persona/rules 只引用 16/21 技能，`idea-lever` + 4 原技法（story-structure / character-sheet / dialogue-craft / foreshadow）**零引用**——若不借 L1 兜底，立即沦为"存在但永不调用"的僵尸技能。故达三条结论：

1. **保留 L1** 作系统可发现性兜底：零副本、实时生成，SSOT 仍是技能文件；
2. **设定文本只承载「何时用」的时机引导**、不复述能力：能力定义以技能文件为唯一真理源，文本引用仅是技能文件的"使用时机副本"，属合理叙述、非能力级二源；
3. **覆盖完整性强制自查**：每个内置 skill 须在 persona/rules **至少一处**标注使用时机。补全后共鸣覆盖达 **21/21**（2026-09-13 落地）。

## 六、已知风险（对抗式自查）

| 风险 | 说明 |
| --- | --- |
| 需求层变"追热点" | 热点是土壤不是答案：三层结构要求内核不变，防止"什么火写什么"的短视——需要规则约束（形式可追热点，内核不可） |
| 内核层变"抄经典" | 提取内核是借鉴人性骨架，不是复制故事：需规则防抄袭式借鉴（换时代、换人物、换冲突具象） |
| 三层自洽的复杂度 | 三层各自能跑通不难，难在互相匹配：G5 一致性检查是质量闸门 |
| AI 边界 | 需求分析/内核建议可 AI，创作主权（内核拍板、命运选择）归作者：协作定位"目标产出完整成稿 + 方向性问题主动提问/建议直接提出"，成稿是候选稿、作者是定稿人 |
