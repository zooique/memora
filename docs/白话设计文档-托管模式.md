# 白话设计文档 · 托管模式

> **本文讲什么**：托管模式这套用法长什么样、边界在哪、哪些事明确不做。**读者不需要懂代码。**
>
> **一句话**：托管模式 = 自助模式 + 一层代理。会话还是那些会话，操作还是那些操作，历史还是那些历史；只是「谁来开会话、谁来写提示词」换成了代理。
>
> **术语**：「自助 / 托管」的唯一定义在[术语锚点](../.trae/rules/terminology-anchor-rules.md)，本文不另立定义。界面上不出现「托管」这个词，对用户说的是「让助手替我干」「我自己聊」。
>
> **分工**：本文讲**体验**；技术事实与判据见[子会话与目标模式路线](./评估-子会话与目标模式路线-20261108.md)，两稿不互相复制同一段话。本文只写模型、决策、边界与已知限制，实现细节与分期不复述。

## 一、它是什么：在自助上面套一层代理

### 1. 两种用法，同一台机器

- **自助**：用户自己开会话、自己协调各会话推进，用户是信息的汇总处。
- **托管**：用户只提需求和拍板；代理理解需求、写提示词、开会话、追问、推进。

这两种不是两台机器，也不是两套功能。**托管是在自助上面套了一层代理**：底下跑的还是原来那套东西。

### 2. 三样东西不变

- **会话本身不变**：代理开的会话就是普通会话，不是另一种会话类型。
- **操作方式不变**：里面照样跑、照样停、照样看历史，和用户自己开的会话一样用。
- **历史记录不变**：不因为「这轮是代理代发的」就换一种存法，仍然按原来的方式落盘和回放。

### 3. 代理只做一件事

代理理解用户的意图，然后**代替用户在会话里开会话、写提示词**。

它不转发消息，也不新建消息通道。它用的就是原来那套通路——**只是说话的人换了**：原来那句提示词是用户敲的，现在由代理代写。

所以代理自己的工作发生在它自己的对话里；它开的会话是另外的会话。两边靠「代写提示词」连起来，不靠一条新管道。

## 二、本质只有两样东西

把上面的说法收干，托管模式只多了两样：

1. **一层代理**——解决「谁来开、谁来写」。
2. **一个标记**——解决「事后认不认得出这是代理干的」。

其余的东西都不需要新造：不需要新对象、不需要新通道、不需要新会话类型。凡是要「先造一个系统」才能成立的写法，都不是这套模型。

## 三、标记：两条不同的事实

标记分两级。**它们是两条不同的事实，不是同一件事存两遍。**

### 1. 会话级：这个会话是谁开的

只要是代理创建的会话，就打上标记。用途只有一个：**让用户一眼看出「这个不是我开的」**。

### 2. 轮级：这一句是谁说的

只有代理代发的那一句打标记；用户自己说的话不打标记。**同一个会话里两种可以并存**——代理开了一个会话，用户中途进去亲手补一句，这一句就是用户说的，不该被算到代理头上。

### 3. 为什么必须分两级

因为「会话是谁开的」和「这一句是谁说的」不是同一件事。只留一层，必有一半场景读错：

- 只看会话级：托管会话里用户亲手说的话，会被误认成代理说的；
- 只看轮级：代理开的会话本身，用户看不出「这不是我开的」。

### 4. 标记永久保留

标记记的是**历史事实**，不是**当前状态**。所以：

- 撤掉代理、用户接手继续用，历史记录上的标记**不消失**；
- 也不能拿标记来判断「这个会话现在还在不在托管」——**当前状态要看运行态，不看历史标记**；
- 旧数据不做回填：没有标记的，按「用户创建 / 用户输入」看待，不按今天的猜测改写过去。

## 四、两个窗口：左边说话，右边看活

### 1. 左边说话，右边看活

托管模式里有两个窗口，各干各的：

- **左边**：你和代理说话的地方。提需求、拍板、追问，都在这里。
- **右边**：看活的地方，叫**工作台**。它不陪你聊天，只让你看清代理此刻在替你干什么。

### 2. 工作台只有两块（本轮）

1. **代理是谁**：现在是谁在替你安排。
2. **最近在办什么**：它开出去的会话，各自在做什么。

第三块「交出了什么」**本轮不做**。理由不是没时间：产物登记表已经退役，仓库里唯一沾边的是「文件变更视图」，那是**编辑级**的改动记录，不是产物级的事实。硬凑一块出来，等于拿不可靠的数据充数。没有可靠数据源，就不摆那一块。

两块之外不再加板块。工作台是**汇总视角**，不是第二个对话区。

### 3. 任务要能看懂状态

每一项活的状态，都从**既有的运行态与终态**里读，能读出四档之一：**在跑、等你、完成、被中止**。

- 「等你」是代理停下来等你拍板（提问、确认、或已暂停等继续），不是你不在；
- 「被中止」必须带上**已经落地**的原因：你停的 / 请求超时 / 异常终止（附原始错误）/ 原因不可知；
- 取不到原因就直说「原因不可知」，**不补一个好看的理由**；
- 四档套不上的边缘事实也照实说，不塞进四档里冒充：最后一轮没正常收场（崩了但还没被打捞）写「上次未正常结束」；已交给助手但还没有任何一轮写「已交给助手，还没开始」；状态确实读不到写「状态不可知」。

界面上不许用占位符或破折号糊过去；没有数据就直说「暂无」，不要让用户猜。

### 4. 知情不是监视

工作台是让用户**知道**，不是让代理**盯着**用户。用户随时可以自己动手：直接进某个会话，或者直接把某个会话停掉。不需要先问代理，也不需要等代理空下来。

停掉之后，代理必须知道，而且必须知道**是谁停的**：

- **用户终止**：人主动叫停的；
- **异常终止**：会话自己出事了。

两种后续处置不一样，不能混成一句「会话已结束」。任何中断都要通知代理，并说明原因。

### 5. 不是第二个聊天对象

工作台只回答「它开了哪些会话、在干什么」，**不承接聊天**。想改变代理的做法，回到左边代理的对话里说；不要在这里再开一条对话线。

把调度器伪装成一个人来一问一答，看似省了一层界面，实际会把「它到底在干什么」这个缺口留给用户用追问去补。

### 6. 点一下就回到会话本身

代理只有一层。工作台里的每一项活，都是它开出去的一个**普通会话**；每一项都有「去这个会话」，点一下就切回那个会话本身，看到的就是它和会话的对话、它的历史。

没有「任务页」这样的中间层，也没有「任务 → 子页签 → 会话」的三级跳。工作台只是入口，活本身在会话里。

### 7. 隐藏再打开会重建

工作台不保存界面现场：标签页隐藏或关闭后，界面上下文就销毁了；再打开时按宿主此刻的事实**整份重画**。所以你看到的不会是上一次的残影——要么是最新的，要么还没画出来。代价是每次显示多读一次数据，换来「屏上的就是事实」这一条。

「它开过哪些会话」这份清单也不另存一份账本。代理每次开会话，工具调用的入参和返回（sid、标题）本来就落在**代理自己那条会话的历史**里；重开工作台（包括重启编辑器后）时从这段历史里读出来即可。这是读已有事实，不是另造一份真源。

读历史有代价，所以定了个上限：**一次最多看最近 60 轮**。超了就明说「只读了最近 60 轮，更早的没读」，不把读了一半的清单当完整清单。

**「读不到」和「没有」是两件事。** 历史读不出来时，工作台写「历史读不到」，绝不写「还没有交给助手的活」——后者是在说「一条活都没有」，那是谎报。历史里有记录、但那条会话已经被删掉或找不到时，清单跳过它，并在上面标一句「有 N 条会话找不到了」，不静默丢弃。只有真的一条都没开过，才写「还没有交给助手的活」，不摆空表格、不显示 0、也不放破折号。

## 五、明确不做的事

| 不做 | 为什么 |
| --- | --- |
| 不造「任务」对象 | 真源是会话。再造一个任务实体，就要维护它和会话的对应关系、生命周期和一致性，会话状态一变就得写两处，迟早有一处是错的。 |
| 不建父子树 | 代理只有一层，深度恒为 1。不做「代理再派代理」的多级结构。 |
| 不转发消息、不新建消息通道 | 代理是「代写提示词」，不是「中转站」。消息走原来的通路，只是说话的人换了。 |
| 不加深度限制闸 | 既然只有一层，就没有可递归的深度，不需要为此加一道闸。 |
| 不把代理的会话做成特殊会话类型 | 它就是普通会话，只是带了来源标记。特殊类型会让所有既有逻辑都要分叉。 |

## 六、已知限制（照实写）

- **只有一层**：不能让代理再派代理。更复杂的任务在会话内部逐步推进，不在代理层继续分包。
- **标记不是状态**：标记永久保留，所以它回答不了「现在还在不在托管」。当前状态要看运行态。
- **窗口不实时**：不在前台的会话，输出不会实时推到你眼前，切回该会话才补齐。这是既有的消息投递方式，不是托管模式新加的。
- **窗口不是聊天入口**：知情窗口只做查看和会话操作，不能在里面和代理对话。
- **重启后代理自己的上下文会断**：历史标记还在，工作台也能从历史把「开过哪些会话」重建出来，但代理**对话上下文里**对「我还管着哪些会话」的记忆不会自动续上，需要重新建立。
- **工作台清单靠读历史重建，有两个已知缺口**：其一，只读代理会话的**最近 60 轮**，更早开过的子会话可能不在清单里（界面会说明读不全）；其二，工具结果摘要在内核落盘时会被截到 100 字符，sid 在摘要前部能稳定解析，但**标题不保证完整**——所以标题优先取创建调用的入参（完整），入参没给时才用会话自己的名字，两者都没有才显示时间占位标题。另外**不**拿「托管通道出生」当判据把别人的会话算到代理头上（用户自己选的托管新建也是同一个出生来源）。
- **找不到的会话只计数、不保留占位**：历史里记着 sid、但会话已经被删掉时，清单跳过它并显示「有 N 条会话找不到了」。理由是占位行没有任何可点的去处、也答不出它原本叫什么，摆一行死数据比说明「找不到」更容易让人误以为还能进去。
- **工作台第三块缺席**：本轮只有「代理是谁」和「最近在办什么」；「交出了什么」没有可靠数据源，不做，也不拿文件变更记录冒充产物。
- **存量不回填**：旧会话和旧轮次没有标记，一律按「用户创建 / 用户输入」看待。

## 七、一句话合起来

> **托管 = 自助 + 一层代理 + 两级标记。** 代理只代写提示词、代开会话，不转发、不换通道；用户看得见、能终止，终止有回声；标记永久保留，记历史不当状态用；不造任务、不建树、不加深度闸、不做特殊会话。
