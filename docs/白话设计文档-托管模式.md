# 白话设计文档 · 托管模式

> **本文讲什么**：托管模式这套用法长什么样、边界在哪、哪些事明确不做。**读者不需要懂代码。**
>
> **一句话**：托管模式 = 自助模式 + 一层代理。会话还是那些会话，操作还是那些操作，历史还是那些历史。代理做两件事：**代你开会话、代你写提示词**；以及**它自己发起的那些轮出了岔子时，由它去接**（提问、确认、跑完、失败），不用你去点。
>
> **术语**：「自助 / 托管」的唯一定义在[术语锚点](../.trae/rules/terminology-anchor-rules.md)，本文不另立定义。界面上不出现「托管」这个词，对用户说的是「让助手替我干」「我自己聊」。
>
> **分工**：本文讲**体验**；技术事实与判据见[子会话与目标模式路线](./评估-子会话与目标模式路线-20261108.md)，两稿不互相复制同一段话。本文只写模型、决策、边界与已知限制，实现细节与分期不复述。

## 一、它是什么：在自助上面套一层代理

### 1. 两种用法，同一台机器

- **自助**：用户自己开会话、自己协调各会话推进，用户是信息的汇总处。
- **托管**：用户只提需求和拍板；代理理解需求、写提示词、开会话、追问、推进。

这两种不是两台机器，也不是两套功能。**托管是在自助上面套了一层代理**：底下跑的还是原来那套东西。

### 2. 三样东西不变

- **会话本身不变**：代理开的会话就是普通会话，不是另一种会话类型。
- **操作方式不变**：里面照样跑、照样停、照样看历史，和用户自己开的会话一样用。
- **历史记录不变**：不因为「这轮是代理代发的」就换一种存法，仍然按原来的方式落盘和回放。

### 3. 代理做两件事：开场与出场

**开场：代你开会话、代你写提示词。**

代理理解用户的意图，然后**代替用户在会话里开会话、写提示词**。

它不转发消息，也不新建消息通道。它用的就是原来那套通路——**只是说话的人换了**：原来那句提示词是用户敲的，现在由代理代写。

所以代理自己的工作发生在它自己的对话里；它开的会话是另外的会话。两边靠「代写提示词」连起来，不靠一条新管道。

**出场：那些轮出了岔子，它自己去接。**

会话跑到一半会停下来等人：要你拍板的确认、要你回答的提问、跑完了或者失败了的结果。**这些原来只能等你**。现在只要是代理自己发起的轮，这些事也同时叫它一声，由它来答。

这个「叫谁」不靠额外状态，就靠这一轮的标记：**带标记的轮叫代理，不带标记的轮还是叫你**（§三.4）。

### 4. 一条底线：托管不动自助模式的规矩

托管是在自助上面加一层，不是把自助改成另一种东西。

自助模式本来就能好几个会话同时干活，这一点**不因为交给助手安排就变**。助手能用的，还是用户自己会用的那些操作；它只是替用户去点，不能把这些操作改掉，也不能给它们加限制。

多出来的是**打标**：这句是谁说的、这个会话是谁开的，让用户一眼看得出「这活儿是助手干的」。轮上的标还多带一个动作——**这一轮出了岔子会去叫代理**（§三.4）。

**打标不是权限。** 不能因为「这是助手开的会话」就不许它做某件事——那等于把托管和自助分成两种东西。反过来，有些事助手不能做（比如去停用户自己建的会话），不是因为它头上的标记不够，而是**它本来就没有替用户做主的资格**。

**也不存在「托管态」这个状态。** 没有「这条会话现在被托管了」「把它收回」这类东西。会话只有「谁开的」这一条出生记录；某一轮只有「谁发起的」这一条来源记录。两条记录都不会中途改变，所以能拿来当判据；而「现在还在不在托管」这种会变的属性，本模型里根本不存在。

> 上面这条讲的是**助手能用的操作**不能比用户少。**用户侧的面板入口**另有收口：助手形态下用户不再自己新建会话（否则会造出第二条助手座位），工作台入口收成一个「看活」按钮（面板本身保留、默认收起），见 §四.8。两者不冲突——收的是**托管侧的门**（新建会话、重复入口），自助能力一个没少。

## 二、本质只有两样东西

把上面的说法收干，托管模式只多了两样：

1. **一层代理**——解决「谁来开、谁来写」，以及「它那几轮出了岔子谁去接」。
2. **一个标记**——解决两件事：**事后**认不认得出这是代理干的；**事发当时**这件事该不该叫代理。

标记的第二个用途是关键：它让「叫不叫代理」变成**读一条不会变的事实**（这一轮谁发起的），而不是去查某个会变的「托管状态」。所以整套东西里没有授权、没有撤权、没有归属变更——**只有一条出生记录和一条来源记录**。

其余的东西都不需要新造：不需要新对象、不需要新通道、不需要新会话类型、不需要「托管状态机」。凡是要「先造一个系统」才能成立的写法，都不是这套模型。

## 三、标记：两条不同的事实

标记分两级。**它们是两条不同的事实，不是同一件事存两遍。**

### 1. 会话级：这个会话是谁开的

只要是代理创建的会话，就打上标记。用途只有一个：**让用户一眼看出「这个不是我开的」**。

### 2. 轮级：这一轮是谁发起的

只有代理自己发起的那一轮打标记；用户自己发起的轮不打标记。**同一个会话里两种可以并存**——代理开了一个会话，用户中途进去亲手发一句，那一轮就是用户发起的，不该被算到代理头上。

这一条除了事后区分，还负责「出事叫谁」（§三.4）——**它是整套机制里唯一会被运行期读取的标记**；会话级那条从不参与判断。

### 3. 为什么必须分两级

因为「会话是谁开的」和「这一轮是谁发起的」不是同一件事。只留一层，必有一半场景读错：

- 只看会话级：托管会话里用户亲手发的那一轮，会被误认成代理发起的；
- 只看轮级：代理开的会话本身，用户看不出「这不是我开的」。

### 4. 轮级标记的第二个作用：这一轮的岔子叫谁

会话跑到一半会停下来等人，冒出三类事：

| 事 | 原来 | 现在 |
| --- | --- | --- |
| 要你拍板的确认（写文件、跑命令、跑脚本） | 只能等你点 | 带标记的轮 ⇒ 同时叫代理 |
| 要你回答的提问 | 只能等你答 | 带标记的轮 ⇒ 同时叫代理 |
| 这一轮跑完了 / 失败了 / 被中止了 | 只能你自己去翻 | 带标记的轮 ⇒ 同时告诉代理 |

判据只有一句：**这一轮是谁发起的**。带标记 ⇒ 叫代理；不带标记 ⇒ 照旧叫你。

所以同一个会话里两种轮可以混着：代理派下去的那几轮，岔子找它；你亲手发的那几轮，岔子还是找你。**按轮分，不按会话统一。**

### 5. 不是二选一：原来只有你，现在多了它一个

这条最容易读错，写死：

- **不是「把通知从你改道给它」**，是**「在你之外，多叫了它一个」**。
- 确认卡该弹还是弹：前台会话照常推到你面前，后台会话照原有规则不上屏、只发离屏提醒（这条没变）；你看见的那一刻想点，随时能点。
- 该问你的问题还是问你，不会因为代理在就对你隐身。
- 代理去接了，你事后照样在历史里看得见——它答的那句记在那一轮里，出处清楚。

实际体感上代理通常接得很快（确认这类事它几乎立刻处理），你可能根本来不及插手。**但那是速度差，不是权限剥夺**：任何时候你都能自己停下来，或者自己把这一轮接过来处理。

**为什么不改成「只叫它、不叫你」**：那样你就失去了随时插手的资格，等于把自助模式的安全感抽掉。宁可多一个人看见，也不让你被蒙在鼓里。

### 6. 标记永久保留，但它不是「托管状态」

标记记的是**不会变的事实**：这个会话谁开的、这一轮谁发起的。所以：

- 用户接手继续用，历史记录上的标记**不消失**；
- 旧数据不做回填：没有标记的，按「用户创建 / 用户输入」看待，不按今天的猜测改写过去；
- **但它不等于「这个会话现在处于托管态」**——本模型里没有这个状态。标记只回答「谁开的 / 谁发起的」，不回答「现在谁在管」。

这个区别要卡住：**标记能当判据，是因为它不会变；「托管态」不能当判据，因为它会变——而且它压根不存在。**

## 四、两个模式：自助原样，托管另开一套

### 1. 两块并存：对话常在，工作会话按需拉开

托管不另开一套窗口、也不新开标签：点一下切过去，**换的是侧栏里那套界面**（工作台那个标签页按需拉开，不是切换这个动作开出来的），底下跑的还是原来那些会话、那些操作、那些历史（§一.2）。

切过去以后，屏幕上是**两块，不是两面**：

- **侧栏 · 主对话（常在）**：一个助手对话框，你在里面提需求、拍板、追问。你不建会话、不管会话、不选会话——助手自己把活派进普通会话去跑。这是你唯一需要盯的地方。
- **编辑器 · 工作台（按需）**：助手派出去的活都在这儿列着，想看就拉开，不想看就收起来。收起来不影响主对话，也不影响活继续跑。

**为什么不是「翻面」**：翻面会换掉整个上下文——翻过去你面对的是另一条会话，草稿和输入目标都跟着换，「翻过去东西还在」是假象。这里两块是并存的：主对话一直在侧栏里，工作台开不开它都在，你看代码的时候它也没离开视线。要理解成「把一块盖板拉开、推回去」，不要理解成「翻纸的正反面」。

**说清一个实现事实**：那个切换按钮**会切到助手的座位会话**（切回来时还原你进托管前待的那条）。所以它不是纯视觉换肤——是「换到助手那张桌子上谈」。这也正是上面不采用翻纸比喻的原因：翻纸不换内容，这个换。

**工作台必须留，但不能常驻**：助手把活派出去之后是后台在跑；你要是没有一块地方能看见它跑成什么样，就退化成「交出去了，然后不知道了」。所以它必须留。但它也不该常驻抢地方——你看代码时不需要一直盯着一列任务，用的时候拉开就行。

> **形态已定（2026-11-16 拍板）**：工作台落在**编辑器标签页**，不进侧栏。理由：侧栏宽度只够放一条对话，把工作台塞进去就得和对话互相盖住，那又把「翻面」的毛病犯了一遍。VS Code 里侧栏和编辑器本来就是并存的，代码也本来就在编辑器里——助手的活和你的代码放在同一侧，看着才是一件事。

**切回自助会怎样：什么都不丢。** 助手开的工作会话就是普通会话，用的就是你自己开会话那一套操作（§一.2 三样不变）。你切回自助后照样能进、能发消息、能停、能看历史、能改名——它不会变成一条「只读的托管遗留」。历史里留下的是**戳**：这条会话是助手开的、哪几轮是助手发起的（§三）。戳是永久的历史事实，不是你回来之后的限制。

**但有一件事不随你切界面而变**：已经在跑的、带戳的轮，出了岔子仍然会去叫代理——因为那是「这一轮谁发起的」这条事实，跟你此刻站在哪个界面无关。你不想让它再动，就停掉那一轮（停止是轮级动作，一直都有，见 §七.2）；要它彻底不管，只能等那些轮跑完。**这不是限制，是账算得清**：谁发起的轮，谁负责收尾。

### 2. 工作台只有两块（本轮）

1. **代理是谁**：现在是谁在替你安排。
2. **最近在办什么**：它开出去的会话，各自在做什么。

第三块「交出了什么」**本轮不做**。理由不是没时间：产物登记表已经退役，仓库里唯一沾边的是「文件变更视图」，那是**编辑级**的改动记录，不是产物级的事实。硬凑一块出来，等于拿不可靠的数据充数。没有可靠数据源，就不摆那一块。

两块之外不再加板块。工作台是**汇总视角**，不是第二个对话区。

### 3. 任务要能看懂状态

每一项活的状态，都从**既有的运行态与终态**里读，能读出四档之一：**在跑、等你、完成、被中止**。

- 「等你」是代理停下来等你拍板（提问、确认、或已暂停等继续），不是你不在；
- 「被中止」必须带上**已经落地**的原因：你停的 / 请求超时 / 异常终止（附原始错误）/ 原因不可知；
- 取不到原因就直说「原因不可知」，**不补一个好看的理由**；
- 四档套不上的边缘事实也照实说，不塞进四档里冒充：最后一轮没正常收场（崩了但还没被打捞）写「上次未正常结束」；已交给助手但还没有任何一轮写「已交给助手，还没开始」；状态确实读不到写「状态不可知」。

界面上不许用占位符或破折号糊过去；没有数据就直说「暂无」，不要让用户猜。

### 4. 知情不是监视

工作台是让用户**知道**，不是让代理**盯着**用户。用户随时可以自己动手：直接进某个会话，或者直接把某个会话停掉。不需要先问代理，也不需要等代理空下来。

停掉之后，代理必须知道，而且必须知道**是谁停的**：

- **用户终止**：人主动叫停的；
- **异常终止**：会话自己出事了。

两种后续处置不一样，不能混成一句「会话已结束」。任何中断都要通知代理，并说明原因。

### 5. 不是第二个聊天对象

工作台只回答「它开了哪些会话、在干什么」，**不承接聊天**。想改变代理的做法，回到托管模式的对话区里说；不要在这里再开一条对话线。

把调度器伪装成一个人来一问一答，看似省了一层界面，实际会把「它到底在干什么」这个缺口留给用户用追问去补。

### 6. 点一下就回到会话本身

代理只有一层。工作台里的每一项活，都是它开出去的一个**普通会话**；每一项都有「去这个会话」，点一下就切回那个会话本身，看到的就是它和会话的对话、它的历史。

没有「任务页」这样的中间层，也没有「任务 → 子页签 → 会话」的三级跳。工作台只是入口，活本身在会话里。

### 7. 切走再回来会重建

工作台不保存界面现场：把它收起来、切去自助、或重启编辑器之后，界面上下文就销毁了；再拉开时按宿主此刻的事实**整份重画**。所以你看到的不会是上一次的残影——要么是最新的，要么还没画出来。代价是每次显示多读一次数据，换来「屏上的就是事实」这一条。

「它开过哪些会话」这份清单也不另存一份账本。代理每次开会话，工具调用的入参和返回（sid、标题）本来就落在**代理自己那条会话的历史**里；回到工作台（包括重启编辑器后）时从这段历史里读出来即可。这是读已有事实，不是另造一份真源。

读历史有代价，所以定了个上限：**一次最多看最近 60 轮**。超了就明说「只读了最近 60 轮，更早的没读」，不把读了一半的清单当完整清单。

**「读不到」和「没有」是两件事。** 历史读不出来时，工作台写「历史读不到」，绝不写「还没有交给助手的活」——后者是在说「一条活都没有」，那是谎报。历史里有记录、但那条会话已经被删掉或找不到时，清单跳过它，并在上面标一句「有 N 条会话找不到了」，不静默丢弃。只有真的一条都没开过，才写「还没有交给助手的活」，不摆空表格、不显示 0、也不放破折号。

### 8. 助手形态里，会话由助手安排（**两模式口径 · 2026-11-16 拍板**）

> **状态**：真机上出现「怎么有好几个助手」的困惑，根因是助手形态下用户还能自己再开一条托管会话。2026-11-16 用户拍板两模式口径（§四.1）：自助原样不动；托管是点一下切过去的那套侧栏界面，主对话常在、工作台按需拉开，**两块并存不翻面**。同日该口径更新过一次：**独立工作台面板保留、默认收起**——原方案曾判它与两个入口一并退役，该判断已撤回，理由见第 5 点。本节五件事按现行口径重写——**口径已定，待复核的是实现落地**。用户回来改口径时只改本节与对应实现，不另起分叉。

五件事分开定：

1. **用户侧新建会话：助手形态下关闭**。标题条「＋」不出现；命令面板的新建入口给出同一句提示；宿主执行面也拒收——旧视图或别的触发面绕不过去。切回自助形态即恢复。**为什么这不算「给自助加限制」**：关掉的是「再造一个助手座位」，不是自助能力本身；自助形态的自助能力一个没少（托管侧入口的收起另见第 5 点）。
2. **历史会话列表：保留，不隐藏**。助手形态下把助手座位排在前面并标注，它开出去的活按既有来源标记区分。**为什么不隐藏**（2026-11-16 核实后重述，旧推论已过时）：原理由是「写盘确认卡只推前台会话 ⇒ 进不了前台 ⇒ 永久卡等用户点」，而带戳的轮现在**会去叫代理**——确认照常入队，后台入队由代理应下、前台推卡也由代理应下，走的就是 §七.1 那条应答入口，不再依赖人手点卡。加上工作台「去这个会话」随时可达任何会话，「永远进不了前台」的前提本身也不存在。[子会话可见性](architecture/sub-session-visibility-and-goal-scope.md) §1.1 那条推论链对**不带戳的轮**（用户自己发起的、将来独立子会话形态）仍然成立，但它不再是隐藏历史列表的判据；「用户随时可以直接进某个会话」也仍是既有承诺。
3. **工作台「去这个会话」：保留**。点进去就是那条普通会话，用户照常可以看、可以停——**不**改成只读。**怎么回来**：顶栏切换按钮常驻，点回托管即可——原先记的「进去后要有一个常驻的『回到助手主会话』入口（**待实现**）」就此销掉，不另造第二个入口。**注意这个按钮是换会话**（切到助手座位 / 还原你进托管前待的那条），不是纯视觉切换：它是「回助手那张桌子上」，不是「翻回这一页」。
4. **角色切换：助手形态下不可换**。角色就是助手的身份，换角色等于换助手；托管座位的角色包在开座位时定好。角色视图仍可打开看说明，但不提供「设为当前」；自助形态照旧可换。
5. **工作台保留、默认收起，入口收成一个**（**2026-11-16 口径更新，撤回上一条判断**）。原方案判「独立工作台面板与它的两个入口一并退役」，**该判断已撤回**：工作台是「交出去之后还能看见在跑什么」的唯一窗口，删掉它，后台派活就变成失联（Trae 的公开短板正是这条——后台跑完，用户没有途径知道怎么样了）。现行口径：面板留在编辑器标签页，**默认不打开**；入口从两处收成一处——主对话里一枚「看活」按钮，`memora.openWorkbench` 命令保留为等价入口（供键盘与命令面板使用），输入区原来那枚按钮去掉，标题栏公文包图标维持已删。自助形态同样能拉开它看托管历史。**这条把第 1 点的「一个入口没少」精确化为「自助能力一个没少，托管侧只收掉重复入口」**——否则两句话自相矛盾。

**「托管侧入口」与「自助能力」的分界**（判断某个入口该收还是该留的唯一判据）：入口背后的能力**自助自己用不用得上**。用得上（发消息、停会话、看历史、换角色、拉开工作台看托管派出去的活）⇒ 留在自助形态；只有托管玩意境才成立（再开一条助手座位）⇒ 只管助手形态。收的是**托管侧的门**，不是自助的手。

**和旧说法的关系**：「单助手主会话」= 一个项目只有一条助手座位，**不是**「只能有一条会话」——它开的活仍是普通会话，照常并行。§一.4「不能给它们加限制」讲的是助手能用的操作，本节讲的是用户侧的面板入口，两条不冲突。

**复核时要问的三件事**（默认取向已写死在上面）：① 用户侧新建入口连「切回自助」的提示是否都算多余？② 历史列表要不要在助手形态下默认折叠「它开的活」，只留一行「另有 N 条」？③ 子会话要不要改成只读探视（**不建议**：与「用户随时可以自己动手」冲突，且须先推翻 §1.1 死锁推论链）。

## 五、明确不做的事

| 不做 | 为什么 |
| --- | --- |
| 不造「任务」对象 | 真源是会话。再造一个任务实体，就要维护它和会话的对应关系、生命周期和一致性，会话状态一变就得写两处，迟早有一处是错的。 |
| 不建父子树 | 代理只有一层，深度恒为 1。不做「代理再派代理」的多级结构。 |
| 不转发消息、不新建消息通道 | 代理是「代写提示词」，不是「中转站」。消息走原来的通路，只是说话的人换了。 |
| 不加深度限制闸 | 既然只有一层，就没有可递归的深度，不需要为此加一道闸。 |
| 不把代理的会话做成特殊会话类型 | 它就是普通会话，只是带了来源标记。特殊类型会让所有既有逻辑都要分叉。 |

## 六、已知限制（照实写）

- **只有一层**：不能让代理再派代理。更复杂的任务在会话内部逐步推进，不在代理层继续分包。
- **没有「托管态」这个状态**：本模型里不存在「这条会话现在被托管了」「把它收回」这类东西。标记只记两条不变的事实（会话谁开的、轮谁发起的），轮级标记顺带决定岔子叫谁（§三.4–三.6）。想让它别动，办法是**停止那一轮**，不是「收回托管」——后者不存在。
- **切回自助不丢东西**：助手开的工作会话就是普通会话，切回自助后照常进、照常发消息、照常停、照常看历史、照常改名；历史里留下的是托管戳，戳是历史事实，不构成使用限制（§四.1）。
- **窗口不实时**：不在前台的会话，输出不会实时推到你眼前，切回该会话才补齐。这是既有的消息投递方式，不是托管模式新加的。
- **看活区不是聊天入口**：工作台只做查看和会话操作，不能在里面和代理对话——要和代理说话，回托管模式的对话区。
- **重启后代理自己的上下文会断**：历史标记还在，工作台也能从历史把「开过哪些会话」重建出来，但代理**对话上下文里**对「我还管着哪些会话」的记忆不会自动续上，需要重新建立。

- **关掉编辑器，代理就下班**：它不是常驻后台服务，只活在当前这个编辑器进程里。重启之后，后台还在跑的带戳轮没人接岔子——确认会一直挂到超时（自动拒绝），结果也没人来收。它得像重新上班一样被叫起来、重新建立清单。这条不打算用「常驻守护进程」修（那是另一个量级的工程），先照实说。
- **工作台清单靠读历史重建，有两个已知缺口**：其一，只读代理会话的**最近 60 轮**，更早开过的子会话可能不在清单里（界面会说明读不全）；其二，工具结果摘要在内核落盘时会被截到 100 字符，sid 在摘要前部能稳定解析，但**标题不保证完整**——所以标题优先取**会话自己的名字**（改名即时生效），会话没名字时才用创建入参里记下的标题（可能被截断），两者都没有才显示时间占位标题。另外**不**拿「托管通道出生」当判据把别人的会话算到代理头上（用户自己选的托管新建也是同一个出生来源）。
- **找不到的会话只计数、不保留占位**：历史里记着 sid、但会话已经被删掉时，清单跳过它并显示「有 N 条会话找不到了」。理由是占位行没有任何可点的去处、也答不出它原本叫什么，摆一行死数据比说明「找不到」更容易让人误以为还能进去。
- **清单不缓存是取舍，不是遗漏**：工作台和代理的清单工具每次要看清单都重新读一遍历史（最多 60 轮）。理由：缓存会过期，过期的状态会让代理以为「活还在跑」或「已经停了」，进而重复派活、重复花钱——**过期的代价高于多读几次盘的代价**。宁可多读，也不让代理拿旧状态做决定。
- **开活前先说动哪块**：助手准备开一条新活时，会先说明这条活要动哪些文件或目录。如果和正在进行的活动了同一处，这次就不开，并把「撞上哪条活、撞在哪」告诉助手，由它自己决定等一等还是缩小范围。声明整个工作区等于自愿独占——保守到什么程度由助手自己选，不是我们一刀切只许一条活跑。
- **这条范围记在会话自己身上**：说过的范围跟会话标题一起存着，重启、翻旧账都读得到，不靠「翻最近几十条对话」去猜。所以**声明过范围的活**，正常情况下不存在「查不清」。
- **哪些情况会查不清（照实计数）**：一是范围功能上线之前就已经在跑的活，当时没有记范围；二是**用户自己建的会话**——它们本来就不声明范围，只要还在跑 / 在等，就会一直算进「没有范围声明」的计数里。助手会在回执里被告知「有 N 条会话没有范围声明，无法判重叠」；已派发但还没开跑的会话单列，不混进「在跑的活」。说清事实，不假装查过了。这类计数只影响提示，不会拦住开活。
- **整仓不是「安全做法」**：声明整个工作区只表示「这条活要独占」，代价是别的活都得等。我们不把它包装成「更保险的选择」，助手按任务实际要动的范围声明就行。
- **只保证「查得清时撞上不开」，不保证「声明之外没动过」**：活干完后没有逐条核实际改动是不是都在说好的范围内——所有会话共用同一个工作区，事后分不清哪个文件是哪条活改的。这条先照实说，不假装已经在核对。
- **工作台第三块缺席**：本轮只有「代理是谁」和「最近在办什么」；「交出了什么」没有可靠数据源，不做，也不拿文件变更记录冒充产物。
- **存量不回填**：旧会话和旧轮次没有标记，一律按「用户创建 / 用户输入」看待。
- **助手形态的用户侧新建入口已关闭**：详见 §四.8；历史列表与工作台「去这个会话」维持开放，子会话不做只读。自助形态不受影响。

## 七、代理能替你做什么、不能替你做什么

### 1. 它能替你做的

- **替你开新活**：挑好角色包，写好第一条任务说明，说明这条活要动哪块，再交出去。
- **替你接着派活**：先看已有的会话，按归档摘要、当前状态、最后活动时间判断该塞给谁；有对得上的就用现有的，没有才新开。
- **替你盯进度**：每条活是在跑、在等你、完成了，还是被中止了；被中止的会带上已经查明的原因，查不到就直说查不到。
- **替你停、暂停、恢复它自己发起的活**：它停下来的活，它自己也能接着开，不会出现「它让你等着，却没办法让你继续」。它用 `send_to_session` 派出去的活同样算它的——从派发被受理那一刻起，那几轮的停 / 暂停 / 恢复和中断通知都归它。
- **替你回答子会话的提问**：它先把题面和选项看清楚，再按题目的顺序作答；答的条数对不上就不交，把当前的题目带回来重答。它不会凭空编一个答案。
- **替你接确认**：它自己发起的那些轮，撞上写入 / 命令 / 脚本执行确认时，**卡照常入队、前台照常推给你并开始计时**（后台会话的卡按原有规则不上屏、只发离屏提醒，这条不变）——同时叫它一声，由它走「跟用户点击完全同一条」的应答入口给出批准。**不是改道，是加一个人**（§三.5）：在它接之前，你随时能自己点；你点了，就按你的决定走。判据只看**这一轮是谁发起的**，不看会话归谁——所以同一个会话里，你亲手发的那几轮不会被它替你签掉。`git push` / `git commit` / `git clean` / `npm publish` 这类「总是要问一下」的命令照常走确认流程、同样可以由它接。真正接不了的是内核**恒拦**的那一类（如 `rm -rf /`、格式化磁盘）——它们根本不进确认流程，也就没有卡可接。
- **替你收结果**：同样是它发起的轮，跑完了 / 失败了 / 被中止了，都会回头告诉它一声（中止还会说明是你停的、超时、还是异常），不用你自己去翻。
- **不另加「代答」标记**：谁发起的，靠轮上原有的戳就看得出来，同一件事不存两遍（§七.3）。

### 2. 它不能替你做的

- **不能动跟它无关的轮**：你建的会话、你亲手发起的轮，它停不了、也暂停不了。这不是它头上的标记不够，而是它本来就没有替你做主的资格。一旦它用 `send_to_session` 把活派进某条会话，**它负责的是它派出去的那几轮**（那几轮的岔子叫它、那几轮它也停得动）；会话本身不因此归它，你随时可以自己进去干活、自己停。
- **不能替你换角色包**：它开会话时必须当场定好角色包，开完没有换包的按钮。你自己建的会话不受影响，你随时能换。
- **不能翻子会话的聊天正文**：它只能看摘要和状态。要核细节，得另派一个只读会话去查——那是转述，不是它亲眼看过。
- **不能碰「根本不许做」的事**：有些动作从来不在「问你一下」的范围里，是直接不许做。它代你接确认，不改变这一条。
- **不能替你拍板**：做什么、不做什么、界面长什么样、什么时候发版，仍然是你说了算。
- **不能派代理再派代理**：只有一层。更复杂的活，在一个会话内部一步步推进，不再往下分包。

### 3. 为什么它替你答的话不打「代答」的戳

你事后要分得清「这活儿是助手干的」，靠的是**原来那两级标记**：这个会话是谁开的、这一轮是谁发起的。代理替你回答，也是它发起的一轮，这件事已经记在标记里了。再打一个「代答」的戳，等于同一件事存两遍，还回答不了新问题。

所以那一轮里的话改成了中性的「回答：X」，不再是「用户回答：X」。你自己答的时候，这句话同样为真——一个说法对两边都成立，就不必为「谁答的」再分叉。

## 八、一句话合起来

> **托管 = 自助 + 一层代理 + 两级标记。** 代理干两件事：代开会话、代写提示词；它自己发起的那几轮出了岔子（确认 / 提问 / 跑完 / 失败）由它去接。叫谁只看**轮上的戳**，不看会话归谁——**这一层没有授权、没有撤权、没有「托管态」**。事件也不排他：卡照常推给你，只是多叫了它一个，你随时能自己接。主对话常在、工作台按需拉开，两块并存不翻面；用户看得见、能终止，终止有回声；切回自助，活原封还在、只是带戳；标记永久保留——正因为记的是不变的事实，才敢拿它当判据；不造任务、不建树、不加深度闸、不做特殊会话。
