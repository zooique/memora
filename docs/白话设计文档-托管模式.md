# 白话设计文档 · 托管模式

> **本文讲什么**：托管模式这套用法长什么样、边界在哪、哪些事明确不做。**读者不需要懂代码。**
>
> **一句话**：托管模式 = 自助模式 + 一层代理。会话还是那些会话，操作还是那些操作，历史还是那些历史；只是「谁来开会话、谁来写提示词」换成了代理。
>
> **术语**：「自助 / 托管」的唯一定义在[术语锚点](../.trae/rules/terminology-anchor-rules.md)，本文不另立定义。界面上不出现「托管」这个词，对用户说的是「让助手替我干」「我自己聊」。
>
> **分工**：本文只记**模型、决策、边界、已知限制**；实现细节、分期与缺口见[子会话与目标模式路线](./评估-子会话与目标模式路线-20261108.md)，本文不复述。

## 一、它是什么：在自助上面套一层代理

### 1. 两种用法，同一台机器

- **自助**：用户自己开会话、自己协调各会话推进，用户是信息的汇总处。
- **托管**：用户只提需求和拍板；代理理解需求、写提示词、开会话、追问、推进。

这两种不是两台机器，也不是两套功能。**托管是在自助上面套了一层代理**：底下跑的还是原来那套东西。

### 2. 三样东西不变

- **会话本身不变**：代理开的会话就是普通会话，不是另一种会话类型。
- **操作方式不变**：里面照样跑、照样停、照样看历史，和用户自己开的会话一样用。
- **历史记录不变**：不因为「这轮是代理代发的」就换一种存法，仍然按原来的方式落盘和回放。

### 3. 代理只做一件事

代理理解用户的意图，然后**代替用户在会话里开会话、写提示词**。

它不转发消息，也不新建消息通道。它用的就是原来那套通路——**只是说话的人换了**：原来那句提示词是用户敲的，现在由代理代写。

所以代理自己的工作发生在它自己的对话里；它开的会话是另外的会话。两边靠「代写提示词」连起来，不靠一条新管道。

## 二、本质只有两样东西

把上面的说法收干，托管模式只多了两样：

1. **一层代理**——解决「谁来开、谁来写」。
2. **一个标记**——解决「事后认不认得出这是代理干的」。

其余的东西都不需要新造：不需要新对象、不需要新通道、不需要新会话类型。凡是要「先造一个系统」才能成立的写法，都不是这套模型。

## 三、标记：两条不同的事实

标记分两级。**它们是两条不同的事实，不是同一件事存两遍。**

### 1. 会话级：这个会话是谁开的

只要是代理创建的会话，就打上标记。用途只有一个：**让用户一眼看出「这个不是我开的」**。

### 2. 轮级：这一句是谁说的

只有代理代发的那一句打标记；用户自己说的话不打标记。**同一个会话里两种可以并存**——代理开了一个会话，用户中途进去亲手补一句，这一句就是用户说的，不该被算到代理头上。

### 3. 为什么必须分两级

因为「会话是谁开的」和「这一句是谁说的」不是同一件事。只留一层，必有一半场景读错：

- 只看会话级：托管会话里用户亲手说的话，会被误认成代理说的；
- 只看轮级：代理开的会话本身，用户看不出「这不是我开的」。

### 4. 标记永久保留

标记记的是**历史事实**，不是**当前状态**。所以：

- 撤掉代理、用户接手继续用，历史记录上的标记**不消失**；
- 也不能拿标记来判断「这个会话现在还在不在托管」——**当前状态要看运行态，不看历史标记**；
- 旧数据不做回填：没有标记的，按「用户创建 / 用户输入」看待，不按今天的猜测改写过去。

## 四、知情权：看得见、能动手、有回声

### 1. 看得见

用户能看到代理开了哪些会话、各自在干什么。这个窗口是**知情权的出口**。

### 2. 不是第二个聊天对象

这个窗口只回答「它开了哪些会话、在干什么」，**不承接聊天**。想改变代理的做法，回到代理的对话里说；不要在这里再开一条对话线。

把调度器伪装成一个人来一问一答，看似省了一层界面，实际会把「它到底在干什么」这个缺口留给用户用追问去补。

### 3. 能动手

用户可以直接操作这些会话，例如**直接终止**。不需要先经过代理同意，也不需要等代理空下来。

### 4. 任何中断都要通知代理，并说明原因

代理要继续安排后面的活，就必须知道会话为什么停了。所以任何中断都要通知代理，而且**原因必须分开写**：

- **用户终止**——是人主动叫停的；
- **异常终止**——会话自己出事了。

这两种后续处置不一样，不能混成一句「会话已结束」。

## 五、明确不做的事

| 不做 | 为什么 |
| --- | --- |
| 不造「任务」对象 | 真源是会话。再造一个任务实体，就要维护它和会话的对应关系、生命周期和一致性，会话状态一变就得写两处，迟早有一处是错的。 |
| 不建父子树 | 代理只有一层，深度恒为 1。不做「代理再派代理」的多级结构。 |
| 不转发消息、不新建消息通道 | 代理是「代写提示词」，不是「中转站」。消息走原来的通路，只是说话的人换了。 |
| 不加深度限制闸 | 既然只有一层，就没有可递归的深度，不需要为此加一道闸。 |
| 不把代理的会话做成特殊会话类型 | 它就是普通会话，只是带了来源标记。特殊类型会让所有既有逻辑都要分叉。 |

## 六、已知限制（照实写）

- **只有一层**：不能让代理再派代理。更复杂的任务在会话内部逐步推进，不在代理层继续分包。
- **标记不是状态**：标记永久保留，所以它回答不了「现在还在不在托管」。当前状态要看运行态。
- **窗口不实时**：不在前台的会话，输出不会实时推到你眼前，切回该会话才补齐。这是既有的消息投递方式，不是托管模式新加的。
- **窗口不是聊天入口**：知情窗口只做查看和会话操作，不能在里面和代理对话。
- **重启会丢「正在托管」的现场线索**：历史标记还在，但代理对「我还管着哪些会话」的记忆会断，需要重新建立。这是当前阶段的限制。
- **存量不回填**：旧会话和旧轮次没有标记，一律按「用户创建 / 用户输入」看待。

## 七、一句话合起来

> **托管 = 自助 + 一层代理 + 两级标记。** 代理只代写提示词、代开会话，不转发、不换通道；用户看得见、能终止，终止有回声；标记永久保留，记历史不当状态用；不造任务、不建树、不加深度闸、不做特殊会话。
