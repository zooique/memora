# 方案：角色包编辑 UI——键面查看与编辑（RP-EDIT-1）

> **状态**：探索稿（S1 无 ADR · 验证期载体）
> **来源**：2026-10-01 用户命题「点击角色卡弹窗看配置，中文渲染，未设置的留空，内置只展示、用户包可编辑，悬停显示含义」；同日方案演进——用户提议「内核维护键清单随包发布，宿主抽取」，经核实**命中既有 SSOT 数据**（`strategyKeys.ts`），方案由「宿主自维护清单」修正为「内核导出既有键面」。
> **前置阅读**：现状实锤（角色页只读 UI 全景 / 用户包目录 / 来源判据）见 [方案-宿主打磨两项-20261001.md §3](./方案-宿主打磨两项-20261001.md)，本文不重复，只写增量。

## §1 命题一句话

点击角色卡 → 弹窗查看键配置（中文标签 + 悬停含义提示）；用户包可编辑（表单保存回 manifest 原文），内置包只读。键面数据单源内核既有清单，宿主零清单维护。

## §2 架构：四层分工

| 层 | 职责 | 单源判据 |
| --- | --- | --- |
| **内核** `strategyKeys.ts` | 键名 / 枚举值域 / 数值区间——**加 `describeStrategyKeys()` 导出**（`src/index.ts` export），校验逻辑零改动 | `STRATEGY_KEY_RULES` 文件头自证「SSOT：validator + resolver + 文档共用」，宿主 UI 是第四消费者 |
| **宿主 extension** | import 键面 → 协议下发；保存 handler：读 manifest 原文 → 仅替换 strategy 段 → `validateManifest` 校验 → 写回 → `rpm.reload()` → 下发刷新；**内置包真拒绝在此层** | 校验复用已导出 `validateManifest`（`src/index.ts:86`），宿主不重写判据 |
| **宿主 webview** | 详情弹窗（复用队伍编辑弹窗形态）+ 表单控件 + **中文标签/tooltip 映射常量**（键名 → `{label, tip}`） | 渲染归界面；内核领域无关不背中文文案；标签缺失兜底显示英文键名（降级安全） |
| **manifest 原文** | 表单初值只读它、保存只写它 | 用户配置唯一真相源 |

### 数据流

- **查看流**：点卡片 → 上行 `roles_detail {name}` → extension 读 manifest 原文 strategy 段 → 下行 `roles_detail_data {name, strategy}` → 弹窗「有啥渲染啥」（manifest 声明了的键才出现，未声明键不渲染 = 走默认，不是留空）。
- **键面下发**：`roles_loaded` 条目**扩可选字段** `keyface`（纯数据，全局一份几百字节；先例 = FD-3-A `session_list_data` 扩字段不加通道）。
- **编辑流**：编辑模式 = 全键格子表单（枚举 → 下拉、数值 → 数字框带区间提示、`summaryFocus` → 文本框、`askOn` → 多选 checkbox、`selfReview` → **开关**见 §4-4）。保存 → 上行 `roles_save {name, strategy}` → extension 校验 + 写回 + `reload()` → 下行复用 `roles_detail_data` 回发新原文 + `roles_loaded` 刷新。
- **通道数**：上行 +2（`roles_detail`/`roles_save`）+ 下行 +1（`roles_detail_data`），`roles_loaded` 扩字段不计——**102 → 105**，距 130 阈值余量 25，protocolGuard 与 `project-rules.md` §7.6 同步重算。

### 悬停提示

webview 端 `STRATEGY_KEY_META` 常量：每个键的中文名 + 一句话含义（如「步数预算：这轮对话最多跑多少次『思考+用工具』，留空默认 50」）。渲染用原生 `title` 属性起步（零依赖），真机反馈不够再升级 CSS tooltip。降级保护：内核新键宿主未配标签 → 格子照常出现（数据来自键面），标签/提示兜底显示键名原文。

## §3 保存语义（防数据丢失与语义固化）

1. **全量保真写回**：保存 = 读 manifest 原文全量对象 → **只替换 strategy 段** → 写回。skills / capabilities / name / description 等字段原样保留——禁止从表单数据重建整个 manifest（会丢非 strategy 字段）。
2. **空格子 = 不写入该键**（不是写 0）——保持「未声明」语义；`stepBudget`/`outputLimit`/`contextLimit` 的 `0` 与「不写」同义（内核注释实锤），表单 placeholder 提示「留空 = 用默认值」。
3. **初值读原文禁读装配值**：`rpm.get().strategy` 是合并默认值后的完整策略（`types.ts:266-267` 实锤），回填保存会把默认值固化成显式声明。
4. **写回格式**：JSON.stringify 2 空格缩进——手编排版会被归一（可接受边界，文件本为机器读；如实记录不隐藏）。

## §6 测试与守卫（先写守卫，后写实现）

1. **键面一致性守卫**（本批核心新守卫）：`describeStrategyKeys()` 输出的键集合 ↔ webview `STRATEGY_KEY_META` 键集合**双向相等**——内核加键宿主漏翻译 → 测试红（提示补标签）；宿主映射拼错键名 → 测试红。这是「键名拼错静默失败」（内核对未知键只 warning，`validator.ts:272-274` 实锤）唯一能抓住的网。
2. **保存链路测试**：全量保真（非 strategy 字段保留）/ 空格子不写入 / 内置包拒绝（extension 侧，直接发 `roles_save` 也被拒）/ 校验失败不写盘。
3. **变异验证**：M1 写回丢 skills 字段 → 红；M2 保存后不调 `reload()` → 红（断言 reload 被调或装配值更新）；M3 内置包保存被放行 → 红；M4 键面映射删一个键 → 守卫红。
4. **protocolGuard**：通道计数重算同步 `project-rules.md` §7.6（101→102→105 链）。

## §7 红线继承（宿主打磨方案 §3 已立，此处钉进实现 checklist）

1. 表单初值读 manifest 原文，禁用装配值（防默认值固化）
2. 键面守卫测试先写（防键名拼错静默失败）
3. 内置包只读判据落 extension 侧（webview 隐藏按钮 = 假拒绝）

## §8 边界与不做的事（D6：无真实痛点不立项）

- 不做键面元数据自动渲染框架（UI 职责不进内核）
- 不做编辑弹窗打开期间的外部修改检测（mtime 比对）——低频场景，保存以表单为准，真实冲突反馈出现再立项
- 不做非 strategy 字段（name/description/skills）的表单编辑——本批只开 strategy 键面，其余字段维持「打开角色包目录」手编
- 不在本批收敛 schema 双副本（§4-6 留观察）
