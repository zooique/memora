# 匠码体系 · 触发词速查

## 大树播种机 → 播种（一次性）

### 模式 A：从零开始

**触发词：**
> `播种新项目` `初始化项目` `启动项目` `创建项目` `我要开始一个新项目` `基于大树模型启动新项目` `大树播种` `我要开发一个系统` `我要开发一个XX系统`

**干什么：**
- 矛盾分析：找到核心矛盾（需求冲突/技术债务）
- 土壤分析：团队规模、目标用户量、部署环境
- 项目适配：技术栈选型（运行时/框架/数据库/前端/样式/认证）
- ADR 记录：关键决策留痕
- Rules 生成：编码规范 + 分层架构 + 错误处理 + 安全策略 + 数据库操作 + API 规范
- 样板验证：第一个 CRUD 模块走通全链路

### 模式 B：已有项目接入

**触发词：**
> `已有代码项目需要大树管理` `代码项目接入大树` `接入大树` `已有项目接入`

**干什么：**
- 扫描现有代码库 → 识别分层模式/命名约定/编码规范 → 提炼规则 → 补录 ADR → 生成 Rules → 验证一致性

**产出：**
- `.trae/rules/` 代码项目规则（~12 个文件，由 seeder 基于技术选型定制生成）
- `docs/创意设计单页纸.md` 核心矛盾和系统方向
- `decisions/` ADR 年轮记录

**快捷触发词：**
> `我的技术栈是 Node+Express+SQLite` → 跳过项目适配，直接进入 ADR → Rules
> `只生成 Rules` → 基于已有技术选型直接生成规则文件

## 大树生长器 → 日常迭代

**触发词：**
> `方案更新` `基于方案更新` `执行方案` `方案落地` `排雷` `沙盘推演` `方案排雷` `速修` `快速修复` `修复bug`

**干什么：**
- 方案更新：需求 → 分步方案 → 写代码 → 审核 → 清理
- 排雷：对方案做沙盘推演 → 识别遗漏/重复/冗余/覆盖缺口 → 产出优化方案
- 速修：单点 bug → 定位根源 → 最小化修复

---

## 大树生长器 → 质量保障

**触发词：**
> `补测试` `测试覆盖` `补充测试` `测试回归` `提交前审查` `审查本轮更新` `代码审查` `审查代码` `有没有问题`

**干什么：**
- 补测试：扫描代码变更 → 自动生成/补充单元测试
- 测试回归：运行全量测试 → 修复失败用例 → 输出报告
- 提交前审查：对当轮修改做质量把关 → 修复 → 清理

**触发词：**
> `规则对齐` `对齐规则` `交叉检查` `模块重思` `重新设计` `聚焦模块`

**干什么：**
- 规则对齐：规则 vs 代码双向对齐，哪个好以哪个为准
- 模块重思：某模块需求层面重新审视 → 产出设计方案文档

## 大树生长器 → 数据库变更

**触发词：**
> `数据库迁移` `加字段` `改表`

**干什么：**
- 分析需求 → 编写幂等迁移脚本 → 更新全量建表脚本 → 验证迁移正确性

> 所有迁移必须幂等。触发此流程会同时更新全量建表脚本。

## 大树生长器 → 健康度与诊断

**触发词：**
> `检查大树健康` `健康度诊断` `项目体检` `剪枝` `清理代码` `删除死代码` `去重` `剪枝：去痕` `安全审计` `体验评审` `前端体验评估` `交互质量检查`

**干什么：**
- 健康度诊断：根系/躯干/枝叶三层全量体检 → 产出综合健康报告
- 剪枝：识别枯枝（废弃代码）+ 徒长枝（重复抽象）+ 躯干升级判断
  - `剪枝：去痕`：聚焦清理 AI 修改痕迹（"不是XX而是XX"句式、Bug修复注释等），还原原生无痕产出
- 安全审计：对照安全策略审计 → SQL 注入/XSS/密钥泄露/越权漏洞检测 → 修复建议
- 体验评审：交互流畅度/视觉美学/UI 一致性 → 体验报告

> 所有诊断入口发现的问题直接写入 `tasks/待完成任务.md`。

**触发词：**

**干什么：**

## 底层质量收敛循环

```
底层质量收敛循环

目标：通过反复迭代，将项目代码底层质量收敛到高质量形态。

每轮循环执行以下流程：
1. 质量扫描：执行「神木回天」逻辑，扫描底层代码质量（重复造轮子、代码风格不统一、分层违规、命名不一致、未使用的产出）
2. 自动修复：对扫描发现的问题逐个修复，遵循自然生长修改原则
3. 质量审核：执行「翠幕天罗」逻辑，审核本轮修复的质量（是否引入新问题、是否符合分层规范、是否自然生长）
4. 归档记录：将无法自动修复的问题归档到 tasks/待完成任务.md

收敛条件：
- 连续 2 轮扫描无新的 P1/P2 问题 → 输出收敛报告，停止循环
- 每轮结束后输出本轮摘要：扫描发现 N 个问题，修复 M 个，归档 K 个

安全边界：
- 每个修复必须可独立回滚
- 不修改 .trae/rules/ 下的规则文件
- 不确定的问题归档而非强修

开始循环：
```

## 功能设计收敛循环

```
功能设计收敛循环

目标：通过反复迭代，审核并优化项目功能设计的合理性，让功能设计收敛到用户心智匹配、操作路径顺畅、功能完整一致的高质量形态。

前置条件：项目代码底层质量已通过「底层质量收敛循环」收敛。

每轮循环执行以下流程：
1. 功能设计扫描：
   - 心智模型匹配：功能逻辑是否符合用户预期？命名是否匹配用户语言？
   - 操作路径效率：核心任务是否 ≤5 步？是否有"死胡同"页面？
   - 功能完整性：是否缺少必要的状态处理（加载/空/错误/边界）？
   - 功能一致性：同类功能在不同模块的行为是否一致？
   - 信息架构：功能入口是否容易找到？导航层级是否合理？

2. 问题分类：
   | 类型 | 判断标准 | 处理方式 |
   |------|---------|---------|
   | 设计缺陷 | 功能逻辑不合理、操作路径冗余 | 修改功能逻辑 |
   | 功能缺失 | 应有但没有的状态处理/边界处理 | 补充功能 |
   | 功能冗余 | 有但不影响核心流程的冗余功能 | 剪枝删除 |
   | 交互不一致 | 同类功能在不同模块行为不同 | 统一行为 |

3. 自动修复：对设计缺陷和交互不一致逐个修复，功能缺失归档待办
4. 质量审核：审核本轮修复是否引入新的设计问题

收敛条件：
- 连续 2 轮扫描无新的设计缺陷和交互不一致 → 输出收敛报告，停止循环
- 每轮结束后输出本轮摘要：扫描发现 N 个设计问题，修复 M 个，归档 K 个

安全边界：
- 功能删除前必须确认零引用
- 设计变更不破坏已有数据
- 不确定的设计问题归档而非强改

开始循环：
```

## 卡点速查

**问自己：现在卡在哪了？**

| 卡点 | 表现 | 用这个 |
|------|------|--------|
| **不知道做什么系统** | 有模糊想法但理不清 | 大树播种机 |
| **不知道怎么选技术栈** | Node/Go/Python 不知道选哪个 | 大树播种机 → 项目适配 |
| **不知道怎么组织代码** | 分层/命名/目录不知道怎么定 | 大树播种机 → Rules 生成 |
| **日常写代码** | 有需求要实现 | 方案更新 |
| **发现 bug** | 代码跑不通 | 速修 |
| **不确定代码质量** | 写完了但心里没底 | 提交前审查 |
| **缺测试** | 没有测试覆盖 | 补测试 → 测试回归 |
| **规则和代码不一致** | 规范写了但没遵守 | 规则对齐 |
| **模块设计有问题** | 某个模块越写越乱 | 模块重思 |
| **要改数据库** | 加字段/改表结构 | 数据库迁移 |
| **项目健康状况不明** | 不知道整体质量如何 | 检查大树健康 |
| **代码太乱** | 死代码/重复代码太多 | 剪枝 |
| **有安全风险** | 担心漏洞 | 安全审计 |
| **依赖过期** | 依赖审计报漏洞 | 依赖审计 |
| **要发版** | 功能完成要上线 | 提交前审查 → 依赖审计 → 发布版本 |
| **方案拿不准** | 方案写好了但怕执行时踩坑 | 排雷 → 方案更新 |
