Memora 内核接口职责

基于 src/index.ts 全部导出的 12 大接口域分析 · 2026-08-08

📋 概览

Memora 内核是一个纯逻辑库（零 native 编译依赖），通过接口抽象实现宿主与内核的解耦。
全部对外接口集中在 src/index.ts，划分为 12 个职责域，涵盖：

宿主必接 🟡

  • IMemoryStorage
  • ISessionStore
  • IMemoryRelationStore

宿主可选 🟣

  • LlmProvider
  • IVectorStore
  • ITracer
  • ILogger

内核内置 ⚪

  • Agent 门面类
  • ToolDefinition
  • TypedEventEmitter
  • 工具函数

① Agent 核心门面 内置

宿主入口，一行代码接入。负责组件组装和核心对话编排。

const agent = new Agent({ projectPath, provider, sessionStore, memoryStorage });
await agent.init();
for await (const chunk of agent.chat('你好')) { ... }
await agent.close();
方法职责
init()组件组装 + 配置加载 + 项目初始化
chat(text)核心对话编排 → LLM 调用 → 工具执行 → 记忆召回 → 循环
forkSession(name)分叉当前会话为新分支
pause() / resume() / recover()不中断工作模型的状态管理
close()优雅关闭，释放资源
registerTool()注册自定义工具（如 web_search）

Agent 内部委托给各专职 Manager：Composer（四级补全）、ToolExecutor（工具执行）、SessionManager（状态机）、MemoryGovernance（记忆治理）等。

② 存储抽象层 宿主必接

最核心的解耦边界。4 个接口 + 1 个工具类，宿主必须实现才能持久化数据。

接口职责方法数
IMemoryStorage记忆索引的 CRUD + 衰减 + 搜索 + 软删除16
ISessionStore会话消息持久化 + 检查点6
IMemoryRelationStore记忆关系图谱（矛盾/支持/跟随）5
IVectorStore向量存储（语义搜索）2

核心接口：IMemoryStorage 最常用方法：

interface IMemoryStorage {
  upsert(memory: Memory): void;                    // 写入/更新记忆
  search(query: string, limit?: number): Memory[];  // 关键词搜索
  decayScores(sources: string[], now: Date): number;  // 批量衰减
  incrementScore(id: string, delta: number, now: string): boolean;  // 原子加分
  delete(id: string): void;           // 软删除
  restore(id: string): void;          // 恢复
  purge(id: string): void;            // 物理删除
}

不注入则使用 InMemoryStorage 内存模式，数据重启后丢失。

③ LLM 提供者体系 可选

导出职责
LlmProviderLLM 调用抽象接口（chat / streamChat）
OpenAICompatibleProviderOpenAI 兼容 API 实现（自定义 baseUrl / model）
EmbeddingProvider嵌入模型实现（/embeddings 端点）
EmbeddingService嵌入服务接口（宿主可自定义）
createLlmProvider()工厂函数

宿主可注入自定义 LlmProvider，或使用内置 OpenAICompatibleProvider 配置任意模型。

④ 工具系统 可扩展

类型职责
ToolDefinition工具定义（name + description + parameters）
ToolHandler工具处理器签名 (args, ctx) => Promise<string>
ToolContext执行上下文（guardPath 安全校验）
WriteExtensions写入前回调（onBeforeWrite diff 确认）

内置 4 工具：read_file / write_file / list_dir / search_memories。
宿主通过 agent.registerTool() 注册自定义工具（如 web_search、run_tests 等）。

⑤ 事件系统 可监听

agent.on('memoryAdded', (e) => console.log(`新记忆: ${e.name}`));
agent.on('conflictDetected', (e) => notification.warn('检测到记忆冲突'));

28 种事件类型，覆盖：记忆变更、角色切换、会话状态、冲突检测、衰减完成、技能匹配等。

事件名载荷
memoryAdded{ id, source, name }
personaSwitched{ from, to }
conflictDetected{ newMemoryId, targetId, ... }
sessionPaused / Resumed / Error / Recovered会话状态变更
goalDriftDetected目标漂移检测

⑥ 可观测性 可选

接口职责

宿主可注入 OpenTelemetry 等实现，不注入时自动降级。

⑦ 安全层 可接入

类型职责
AuditEvent审计事件类型
Permission权限模型（owner / guest）
WriteDecision写入决策（allow / deny / confirm）
WriteConfirmationRequest写入确认请求（含 diff 信息）

路径白名单 + 28 类禁止规则。写入需二次确认（宿主注入 UI 确认弹窗），fail-closed 拒绝。

⑧ 日志抽象 可选

import { setLogger } from 'memora';
setLogger({
  info:  (msg) => winston.info(msg),
  error: (msg) => winston.error(msg),
});

只需实现 ILogger 接口（4 方法：debug / info / warn / error），不注入时默认使用 pino。

📌 总结：宿主接入三层次

🟡 宿主必须实现的（否则数据不持久）

IMemoryStorage + ISessionStore + IMemoryRelationStore

🟣 宿主可以根据需要注入的（可选）

自定义 LlmProvider、IVectorStore、ITracer、ILogger
注册自定义 ToolDefinition、监听 AgentEventMap 事件

⚪ 内核直接可用的（无需宿主实现）

内置 OpenAICompatibleProvider、InMemoryStorage、EvalRunner
全部工具函数（分词、时间、安全定时器等）
