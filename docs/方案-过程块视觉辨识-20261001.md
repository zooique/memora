# 方案 · 过程块视觉辨识（UI-BLOCK-ICON：块类型 icon + 光标状态条 + 任务项完成态）

- **日期**：2026-10-01
- **状态**：**已定案（2026-10-01 用户逐项拍板：H 方案 / 挂起态并入 / active 复用靶心 / 存量诚实降级）→ 待实施**
- **性质**：会话过程展示「视觉可辨识度」三合一收口——**块类型 icon**（扫一眼认出块类型）+ **光标状态条**（运行态/挂起态/终态语义化）+ **任务项完成态**（绿勾）。含**内核一处最小落盘改动**（`plan_snapshot`），其余纯宿主。
- **输入**：用户命题「会话过程文字太多糊成一片，分不清哪块是什么」（登记 → `tasks/待完成任务.md` UI-BLOCK-ICON）；外部实证 → §附录（Claude Code todo 流内结构化状态 / Trae SOLO 折叠形态）；术语 → `→ 术语锚点`（`.trae/rules/terminology-anchor-rules.md`，本方案用词已按其校准：任务项 N = planItem 阵营、思考 · 第 N 步 = step 阵营）

## 一、问题与根因（真源盘点结论）

用户真机感受：finalize 后过程区一长串 10–11px 灰白文字行，扫一眼分不清哪块是什么。代码层三个实锤根因：

1. **叙述块与思考块近乎同构**：`chatStyles.ts` 中 `.round-block__narrate` 与 `.round-block__thought` 同为 11px、同色、body 同样式（2px 左缘线），唯一区分是 summary 开头有无「思考 ·」二字——扫读全靠认字，零形状锚点。
2. **折叠箭头三副面孔**：narrate/thought 用默认 `::marker`、plan-item/tool-batch `list-style:none` 隐藏、tool 行又带默认 marker——连「这是可折叠的」信号本身都不统一。
3. **动态指示器三处各闪各的**：正文光标 `is-streaming::after`（闪 ▋，**不说话**）、相位行 `.round-block__phase`（呼吸点 + 相位文字，藏在折叠区顶）、工具行旋转环；靠 `:has` 互斥规则（工具在途熄灭正文光标）避免双动画打架。任务项完成态则完全无标识。

## 二、定案 A · 块类型 icon（类别级收敛）

**红线：icon 只给类别级，数量收敛，不给 13 种块人手一个**（图标泛滥 = 给「糊」添新料）。QA 输入（已有文字 tag）、五个小节（已有文字标题）**不加**。

| icon | 状态 | 消费点 | 语义 |
| --- | --- | --- | --- |
| `circle-check` | **新增（本轮唯一新形状·批次一）** | 任务项组 done 态 + 光标终态「已完成」 | 完成（一个语义两个视图） |
| `target` | 已有，复用 | 任务项组 active 态 + plan-tag「正在执行任务项 N」 | 正在执行（同语义扩展消费点） |
| `thought` | **新增（批次三）** | 思考块 summary 前置 | 思考 |
| `tool` | **新增（批次三）** | 工具行 + 工具批 summary 前置（行批共用一个） | 工具执行 |

- **叙述块明确不加 icon（2026-10-01 用户拍板，收敛为「思考/工具 2 个类型标」）**：裸文本形态本身成为类别信号——判读逻辑 = 有勾/靶心 → 任务项、有思考标 → 思考、有工具标 → 工具、**无标 → 叙述**。🔴 此为防泛滥定案：后续不得以「补齐」为由给叙述块/QA/小节加 icon。
- **文件改动不设独立 icon**：write 类文件改动本就走工具行/批（工具标覆盖）；底部 `file-changes-bar` 是全局操作条，不属块体系。
- **形状守恒**：新 icon 一律走 `icons.ts` 现有链路（`ICON_PATHS` + `SVG_BASE_ATTRS`：16 viewBox、stroke 1.5、round cap/join、`currentColor`），禁混入填充风格新范式；注入只经 `getIconSvg`/`applyIcon`/`populateIcons` 既有入口。icon 具体 path 落地时按此范式绘制，语义名（`thought`/`tool`/`circle-check`）先占位。
- **折叠箭头统一（批次三连带定案；2026-10-05 形态迭代为行内随文）**：全部折叠块统一隐藏原生 marker（`::marker` + `::-webkit-details-marker`），CSS 自绘 chevron 随 `details[open]` 旋转（纯 CSS 零 JS）——summary 行内流式：类型标（或无）+ 文本 + chevron（行内衔接文字末尾；曾右缘钉死，因短标题留白断裂废弃）。
- **字形双层**：思考块除 icon 外 summary 加斜体/降饱和（「非正文」信号）——icon 解决认出类型，字形解决「别当正文读」，单加 icon 是半个补丁。
- **真机截图降级为落地后验收对照**（2026-10-01 用户拍板：不看截图直接定案，截图不再阻塞任何批次）。

## 三、定案 B · 光标状态条（turn 全生命周期语义化）

**状态机（八态，单一合成函数的输出域）**：

| 段 | 态 | 文案 | 可见度 |
| --- | --- | --- | --- |
| 运行 | 思考中 / 运行工具中 / 正在回答中 | 文字 | 呼吸动画（淡色，`prefers-reduced-motion` 遵守 `.round-block__phase` 先例） |
| 挂起 | 等待输入（ask 预检停顿）/ 已暂停（paused） | 文字 | 静态淡色（2026-10-01 用户拍板并入） |
| 终态 | 已完成 / 已停止 / 异常中断 | 已完成 = 静默 `circle-check` 淡勾；已停止 = 中性；异常中断 = `--danger` 红 + 原因摘要 | **可见度分级：正常必须安静**（绝大多数轮是正常完成，亮眼终态 = 新噪音） |

**实现契约**：

1. **形态 = 保留 `::after` + `content: attr(data-status)`**，JS 只写 `.msg-body` 父元素一个 data 属性。🔴 禁改真实 span——增量 markdown 渲染反复重写 body 内部内容会吃掉 span；`::after` 挂容器上不受影响（现状已验证）。
2. **状态合成单点**：chatView 内单函数，优先级固定 = 工具在途 > 思考相位 > 默认回答；挂起/终态由消息分支（`paused`/ask 挂起/`done`/`interrupted`/`error`）切换。所有写入点（实时流 + 重放）**共用此函数**，禁三处各写一份。
3. **终态定格**：finalize/中断/异常收尾时切终态并去动画；重放路径直接落终态（同一函数）。
4. **减法**：工具在途时光标由「熄灭」改「切运行工具中」→ **删除 `:has(.round-block__tool.is-tool-running)` 熄灭规则**（双闪烁动画打架的前提消失，净减一条 CSS 和一处隐性联动）。
5. **不双写**：终态条不放耗时（round-block summary 已有），不做按钮（操作入口是另一命题）。

## 四、定案 C · 任务项完成态（H 方案：内核收尾快照）

### 4.1 为什么必须动内核（排雷结论，2026-10-01 定案）

- `plan_item_boundary` 事件 payload 仅 `{planItemId, title}`，**无状态字段**；任务表状态（`PlanItem.status`）是 turn 内瞬态，`clearPlanOnTurnEnd` 收尾即清（内核测试契约「turn 结束后任务表已清空」）；turn 结束后宿主还会推空 `plan_update` 清看板；webview 无 `retainContextWhenHidden`，重建是常态 ⇒ **历史回看时完成态没有任何结构化真源**。
- **外部实证**（§附录）：Claude Code 生态回看有勾的前提 = 状态以结构化形式在会话流里；Trae SOLO 的「已完成任务折叠摘要」memora 已有对等形态。**绕开「流里有数据」的第三方方案不存在**；从 `task_table_update` 的 args/summary 考古 = 依赖 LLM 参数完整性的文本考古，判否。
- **H = 在清 plan 前拍张照贴进行车记录仪**：动内核但恰恰是不带伤——带伤的是考古，H 消除猜测。

### 4.2 设计契约

1. **内核（唯一动内核点）**：`clearPlanOnTurnEnd` 之前落一条 `plan_snapshot` `ProcessEvent`（payload = items 全量 `{planItemId, status}`），落点单点挂 **finally 兜底**（中断轮也拍）；`ProcessEvent` union 扩展该成员 + protocolGuard 切片守卫同步登记。
2. **宿主单一写入点**：`applyPlanItemStates(root, items)`——按组上已有的 `data-plan-item` 匹配切换图标/类。消费点**恰好两个**：`plan_update` 分支（实时）+ finalize/重放渲染（从快照建 map）。禁第三处内联更新；🔴 **禁 UI 从标题/时序/工具文本推断状态**。
3. **样式**：绿色复用既有 `--status-pass` token（write-confirm ok 按钮、看板 `.plan-item-done` 已在用），**不新造颜色 token**。🔴 本轮只新增「完成 = `--status-pass`」一个颜色语义，禁给叙述/思考/工具块彩虹化。
4. **诚实降级（2026-10-01 拍板）**：存量历史轮无快照事件 = 组不显示状态图标（数据缺失的自然投影，不迁移、不伪造绿勾）；自快照落地的轮起，重放 = 实时。

## 七、真机反馈后口径升级（2026-10-01 晚 · PLAN-ICON-FIX）

真机实测（mimo-v2.6-pro 小说项目长任务）暴露两问题：**①运行中任务项无 active 靶心**（收尾直接蹦绿勾）；**②重放后完成图标消失**。根因与修复：

- **运行期零快照**：内核收尾才拍 plan_snapshot（G3/G4 契约），LLM 未调 task_table_update 时实时状态恒空；且组由 narrate/tool 消费 planItemContainerFor 触发创建，boundary 先到时组不存在。
- **修复**：a) livePlanStates 实时累加（boundary 置 active / plan_update·snapshot 全量重建）+ renderProcessFlow 尾部统一投影（防 plan_update done 被事件序推导抹掉——变异 M3 锁）；b) renderRoundBlock finalize/重放补建组循环（尾部无内容跟随的 boundary 也建组）；c) planItemStatesFromEvents 口径升级：**无快照 → 最后 boundary 项亮 active**（中断轮定格现场，不再全程裸奔；不伪造的是 done 绿勾，诚实原则不变）。消费点两→三（注释同步「禁第四处内联」）。
- **§四 口径修订**：4.2「存量轮无快照不显示（诚实降级）」自本节起升级为「最后 boundary 项 active，其余无图标」——boundary 是内核结构化「开始执行」宣告，最后宣告且未见完成宣告的项亮进行中是数据支持的诚实表达。
- 验证：chatView.test 279→284 全绿（含 3 组变异 M1/M2/M3 红→绿）；tsc 0 / eslint 0；全量 902 passed（1 failed 为 projectSearchProvider 500 文件用例 30s 超时，沙箱 I/O 假红零 AssertionError，隔离态 0.9s）。
