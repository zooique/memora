# memora 的白话运行机制

> **本文讲什么**：从"插一张卡"开始，到一次对话怎么跑、到东西最终存在哪，把 memora 这台"插卡机"的完整链路用大白话讲一遍。**读者不需要懂代码。**
>
> 颗粒口径（2026-09-04 收敛定案）：**turn（问答闭环）** = 一次「用户输入 → 最终回答」的最小完整单元（一个 roundId）；**step** = turn 回答中阶段的一次 LLM 调用 + 可选工具执行；**loop（step 循环）** = 单个 turn 回答中阶段对 step 的编排（把"想一步 → 调工具 → 看结果 → 再想一步"串起来，收敛后所有复杂度在这里生长）；~~**多 turn 任务编排** = 一个复杂目标拆成多个 turn 串联（规划 turn → 步 turn 序列 → 收尾 turn）——已废弃，复杂任务在一个 turn 内的 step 循环里驱动。~~ 白话里尽量说"一次问答 / 一步思考-行动 / 一次回答内部 / 复杂任务在一次回答里逐步推进"，避免术语歧义。
>
> **链路全景**：第零步（角色包=插卡）→ 第一步（装配台子）→ 第二步（一次回答内部 loop 推进）→ 第四步（空间三级管理）→ 第七步（记忆沉淀）→ 第八步（物理落盘），旁及第五步（怎么停）、第六步（怎么收场）。

## 第零步：角色包——这台机器插的是"卡"

上面第一步说"装常驻设定"。但**常驻设定从哪来？** 答案是**角色包**。先把这台机器的形状说清楚：

**memora 是一台"插卡机"。** 内核（memora 本身）是一块**通用的 agent 底座**——它会想一步做一步、会管上下文、会查记忆、会调工具，但它**不认识任何具体专业**。专业能力全靠**插卡**：插一张"白话方案设计师"卡，它就是帮你把想法梳理成方案的；插一张"小说助手"卡，它就是写小说的。**同一个内核，换卡换人。**

**一张"卡"就是一个文件夹**（放在 `role-packs/` 目录下），可以独立制作、拷贝、流通——你把文件夹发给别人，别人放进目录，就装上了一张新卡。

### 卡里装什么？三样东西，全是"数据"不是"代码"

这张卡里能写三类东西：

1. **描述性内容（最重要、也是唯一必需的）**——这个角色是谁（`persona.md`）、守什么规矩（`rules.md`）、会哪些技能（`skills/`）。**这部分就是纯文字**，是你写给它的人设与知识。
2. **行为策略键（可选，一整套现成的旋钮）**——调它的"脾气"：工具能不能写文件、一次回答最多想几步、回答多大、温度多高、要不要自审查……**这些键内核都预先定义好了，有参考范围，也都有兜底值**。
3. **能力声明（可选，只是"声明"）**——比如"我需要联网搜索"。**注意：这只是告诉系统"我想用这个能力"，不是自带一个新能力。**

> **一个关键澄清（别误会成"插卡 = 装新工具"）**：**角色包不能带代码，也不能自己造新工具。** 它能做的只有两件事——**①换内容**（人设、规矩、技能文档）；**②调旋钮**（在内核已提供的键里选）。工具本身（读文件、搜网页、跑脚本……）都是**内核出厂就带的**，卡片只能"选用 / 声明"，不能"增添"。
>
> 所以插卡的准确意思是：**同一个内核，换一种"行为方式 + 知识范围"**，而不是换一套新本领。

### 最省事的卡：啥都不设置也能用

**一张卡可以什么都不设置**——不写任何策略键，只写描述性内容（甚至只有 persona），照样能插、能用。因为：

- 每个策略键都有**兜底值**：你不设 `temperature`，它就自动用默认的 0.7；你不设步数上限，就用默认值。**缺什么补什么，不会因为没设置就报错。**
- 唯一的"必填"只有卡的**名字**（`name`）——那是它的身份证，不能没有。

> **这带来一个很舒服的制作体验**：想做个新角色，**先只写一段人设文字就够了**，插上去马上能用；等发现它"话太多 / 太快下结论 / 老爱问问题"，再回头去调对应的旋钮。**从最简的卡开始，按需要慢慢加旋钮。**

### 旋钮一览（都有范围 + 兜底值）

| 什么时候管 | 管什么 | 例子（默认值） |
|---|---|---|
| 回答前 | 要不要先跟你确认理解、摘要记什么角度 | 理解确认默认**关** |
| 回答中 | 能不能动工具、步数上限、回答多大、温度、路由 | 步数上限默认 **20**、温度默认 **0.7**、回答上限默认 **4096** |
| 回答后 | 要不要自审查、要不要沉淀摘要、要不要追问 | 自审查默认 **关**、摘要默认 **开** |
| 全局 | 整轮 token 上限、总步数上限、出错怎么办、什么时候主动问你 | 出错默认**重试**、主动提问默认**最多 3 次** |

> 表中每个键都是**在预定义选项里"选一个"或"填一个范围内数值"**——角色包做的是"选择"，不是"定义"。键的意思和范围由内核规定，卡片照着填即可。

### 插卡的具体链

```
你（或卡片作者）把文件夹放进 role-packs/ 目录
        ↓
宿主启动时扫这个目录（内置的卡 + 用户自己放的卡，两处都扫）
        ↓
内核读取 manifest.json + persona.md + rules.md + skills/
        ↓
"常驻设定"（第一步说的那层）就被这张卡填好了
        ↓
这次对话里，它就是这张卡定义的那个角色
```

> **两张来源**：一类是**内置卡**（跟着程序一起来的，比如"memora 助手"）；一类是**用户卡**（你自己放进用户目录的）。两者平级，都能用。
>
> **卡还能"组队"**（小组会议）：多张卡可以组成一个"小组"，指定一个组长 + 若干组员。发起"小组会议：主题"时，系统会预置一个流程骨架（组长开场 → 每个组员各说一步 → 汇总），**每一步切换到对应组员的视角**（相当于临时插上那张卡）。**但要说清楚：目前"组队"就只做了这一件事——让不同角色的文字视角轮流上场分析问题。** 没有更复杂的编排、没有投票、没有交叉质询，就是"轮流以各自的文字规范发言 + 组长收尾"。**别把它想成一套多智能体协作引擎，它只是"文字视角轮播"。**

> **尚未定义、先记录在案（等正式发布前再定）**：插卡这条链还有两个边界没画，**目前按"先不做、先记下"处理**——
>
> 1. **卡的权限信任模型**：卡片可以"声明"要什么能力（如联网），但"声明 ≠ 授予"——谁批准、什么时候批准，还没定。
> 2. **卡的版本契约**：卡片是独立制作的，将来内核的键若变动，老卡怎么办（兼容 / 报错 / 自动迁移）——还没定。
>
> 这两条都是**卡片生态变大之后才会真正咬人**的问题，现在系统尚未正式发布，**先记录，不提前设计**（避免为想象中的问题预支复杂度）。

## 一次完整对话，从用户敲下一句话开始

### 第一步：对话前的装配（外部输入触发）

你发一句话进来，系统开始**搭台子**，装三样东西：

1. **常驻设定**——这个角色是谁（persona）、规矩是什么（rules）、会哪些技能、能用哪些工具。**这层就是第零步那张卡填进来的**，角色没换就不变。
2. **本轮你的输入**——就是你刚打的那句话。**它是整件事的"根"，从预算里独立划走一块空间，永不压缩**（稍后细说）。
3. **完整对话记录**——当前会话聊过的话。从最近往回装，能装几轮装几轮（装到预算满为止）。**其中第一条问答必然在场**（它是这次会话的起点背景）。

> **记忆去哪了？** 记忆现在**不自动装了**。它变成了"**可查询的资源**"——需要时由 LLM 自己调 `search_memories` 工具去查，而不是每轮硬塞一批进来（原因见第二步）。装配阶段只保证一件事：**桌上已经摊着的东西，工具召回时不会再装第二遍**——召回范围与在场内容互斥，同一件事不会在上下文里出现两遍。所谓"已经摊在桌上"包含三类：**正文还在的轮、被换成摘要的轮（摘要也算在场）、以及正在进行中的这一轮**。

> **两条铁律，先说清楚：**
> - **完整对话永远优先装**：装得下多少轮就装多少轮，从最近往回装，装到预算满为止。**第一条问答必然在场**（会话的起点背景），若它不在最近轮里，会专门补进来。
> - **触发输入和它触发的第一段回答是顶级锚点**：从预算最上游独立划走空间，同一次问答怎么推进都不压它。如果输入本身大到连这点空间都留不住，那系统在装配前就先拦住（下面第五步会说）。

> **「预算」到底多大？——不是固定几轮，是现算的**
>
> 桌子的大小 = **模型自己的上下文上限**（你在 LLM 配置里填的那个数；不填按 120K 兜底）。系统不数轮，而是**用公式现算**：
>
> 1. 先扣掉给模型回答留的一份（不然它没地方写答案）；
> 2. 再扣掉常驻设定的固定开销（persona / rules / 技能 / 工具说明）；
> 3. 再划走"你这句输入 + 它引出的第一个回答"（锚点，永不压缩）；
> 4. **剩下的九成，才是"最近对话"能装的空间**——能装几轮算几轮。
>
> 所以：**轮数是算出来的结果，不是规定**。窗口大装得多，窗口小装得少——这就是"不能拿一个固定轮数（比如"最近 20 轮"）当限制"的根本原因。
>
> **会不会撑爆？不会。** 每次真正发给模型之前还有一道硬闸：只要总量超过窗口，就从最近往回装、把中间剪掉，硬压到窗口的九成（留一成给回答）。**唯一的例外是：你把上下文上限填得比模型的真实上限还大**——系统按你填的数算，不替你兜底（有意为之：你对自己填的参数负责）。

### 第二步：一次回答内部怎么推进（loop：想一步 → 做一步 → 再看一步）

你一句话进来，系统先回答。**一次回答（一个问答闭环/turn）内部**，往往不是一口气说完的：先想一步、可能需要调工具、看到工具结果、再想下一步……

- **每一步 = 一次"想 + 可选行动"**：LLM 推理一次，必要时调用一个工具（读文件、搜网页、执行代码……），拿到结果再继续。这就是 **step**。
- **串起这些 step 的就是 loop**：loop 在"这次回答"内部反复拉起 step——推理 → 工具 → 回填 → 再推理，直到该收尾。**loop 只存在于一次回答内部，它不是"一轮接一轮地做多个任务"。**

关键点：**同一次回答内部的 step 循环，不再重新装配台子**，只在拼好的上下文物件后面继续追加"这一步刚干完的事"。**需要旧记忆时，LLM 在循环里随时调 `search_memories` 去查——查什么、查几次，由它按需自己决定**，系统不预先替它装一批。

> **为什么记忆改成"工具现查"？** 因为"每轮自动塞一批记忆"塞不准——该想起的没想起、想起的又太多。改成工具后，LLM 自己知道"我现在缺什么背景"，去查比系统瞎猜准。代价是要多花一次工具调用的功夫，换来的是记忆不再无脑占上下文。

**多 step 的目标锚定**：触发这次问答的那句用户输入 + 第一个回答，是整件事的"根"，**永不压缩**，还独立占一块空间。因为 loop 里的每个 step 都在朝它定义的目标推进，目标不能被吃掉。

> **收敛后的现状（2026-09-04）**：复杂任务不再拆成多个独立问答闭环串联。**所有复杂度（含任务表、会议多角色、动态进度追踪）在一个回答内部的 step 循环里自然生长**。步骤循环（想一步 → 调工具 → 看结果 → 再想一步）就是承载一切复杂任务的引擎——LLM 在循环里自主决定要不要建任务表（调 `task_table_write`）、要不要切换角色包（会议机制）、要不要暂停等用户输入。没有强制前置规划，没有跨 turn 串联，**一次外部输入 → 一个 turn → 一条摘要**。任务表工具全部保留，只是从"跨 turn 编排驱动"变为"单 turn step 循环内的动态进度追踪"。

### 第四步：三级空间管理（先替换，再压缩，最后裁掉）

无论一次回答内跑多少个 step，上下文总量有限，跑多了会满。空间的自我维护分**三级**，有明确的先后顺序：

**第一级 · 替换（内核自动做，几乎零成本）**
- 每个**走完收尾**的问答闭环，都会存下一条记忆摘要。所以空间不够时，**系统自己按"最早的先换"的顺序，把最旧的一轮对话正文，换成它自己那条已存好的摘要**——不是重新写，是从库里拿现成的，几乎不花算力。
- **这是系统的机械动作，不用 LLM 出手**，也不用把它变成工具暴露给 LLM。最早的先换，纯按时间顺序来，确定、快。只有当某轮被替换后摘要太短、可能让上下文有点断时，系统才提示一句"细节可回溯"。

**第二级 · 压缩（没有现成摘要可换时，LLM 才捡起）**
- 作用对象是**还没有摘要可换的东西**——一次问答中途还没收尾的 step 现场、超大号的工具结果，**以及被中止/断电打断的那一轮**（它天生没有摘要，见第六步）。
- 先把超长工具结果悄悄换成一句话占位（比如"之前用过 read_file"），这是**微压缩层**。
- 还不够，就由 LLM 主动调**压缩工具**，把这些中途内容**现场压成一条临时摘要**。这叫**压缩摘要**，是当前问答闭环里的**临时产物**，**这次问答一结束就扔掉**，进不了记忆库。

**第三级 · 裁掉（压不动就丢）**
- 如果连现场压都不划算（或压了还不够），就由**预算裁切**直接丢——从上往下裁，只保最近的一批。
- **第一轮问答永远不被裁**（它是会话起点，见第一步）。

> **一句话分清楚**：能换的，系统用现成摘要**替换**（LRU，最早先换，内核自动）；没得换的（含中断轮），LLM 现场**压缩**；都压不动了，直接**裁掉**。三级是同一个目标（腾空间）的层层兜底。真正的记忆摘要，是在一次问答闭环收尾后，由系统后端偷偷沉淀的那一条（见第七步）——压缩摘要和它不是一回事。

> **顺带说一句替换的脾气**：替换不是"一满就换"，而是"**最近的几轮先原样留着**——具体留几轮看上下文预算（预算够就多留、不够才换最老的），最老的那些再按先来后到换掉"。这样对话开头的连续性有保障，又不至于让旧内容无限占地方。另外，如果上下文被系统**截断**过（把中间剪掉重排），替换就暂时歇手——因为这时"哪轮对哪份摘要"的账目容易对乱，宁可不换，也别换错。

> **顺带说一句边界**：替换和压缩都**只碰"你刚说的话之前"的旧内容**——你当前发的那句输入是整件事的"根"，永远不动。极端情况（比如你一句话刚发出去、回答才刚开始，上下文就满到要压缩了）下，系统**不会**把你那句"根"压掉，而是直接说"没得压了"——这时它走的是"收尾"（见第五步软上限）：让模型把当前能给的结论交付出来，然后等你下一句。也就是说：**压不到根的时候，就该收尾了，不会硬压着根继续跑。**

> **顺带说一句互斥**：也许你担心"被替换成摘要的那轮，会不会下次又被工具召回一遍"？不会。工具召回时会先把"已经在场的东西（原文或替换后的摘要都算）"剔掉——已经在你上下文里的内容，不会重复装第二遍。这套是代码里天然保证的，不用额外加机制。
>
> **（2026-09-10 补记 · 已收口）**：上一条说的是**意图**；实现里"已经在场"原先拿的是"**最近 20 轮**"这个**近似值**——窗口大会漏剔（该剔的没剔，摘要重复进来）、窗口小会多剔（本来能查的也查不到）。现**已改成精确名单**：直接问"**桌上此刻实际摊着哪几轮**"，把三类内容一并剔掉——
>
> - **正文还在桌上的那几轮**（你眼前看得到，不用再查一遍）；
> - **已被换成摘要的那些轮**（正文虽撤了，但摘要就摊在桌上，同样不用再查）；
> - **正在进行的这一轮**（你的话刚进库、还没摆上桌的那一瞬）。
>
> 那个固定的 20 已经删掉了。属实现对齐意图——**意图本身没变**，是代码从"近似"回到了"精确"。

### 第五步：回答/任务什么时候停

一次回答什么时候停？看几个信号，哪个先到按哪个：

1. **软上限**——上下文一路替换/压缩，压到最后，**除了顶级锚点，正文基本都变摘要了，摘要层也装满了**。这时候系统主动注入一个"收尾信号"，让 LLM 收敛，给出最终结论，停下来等用户。**这是"空间被摘要塞满"这个物理条件触发的，不是数段数数出来的。**

   > 注：这里的"摘要层"指**压缩产物**（旧轮正文被换成摘要后占的那块空间），**不是**"自动注入的记忆"——记忆早就不自动装了（见第一步），装配里没有"记忆层"这个概念。
2. **单轮内的步数上限**——一次回答内部不能无限地"想一步调一次工具"，到顶了就让它收尾交付（防死循环烧钱）。
3. **自然结束**——任务自己干完了，LLM 交付就停。

**还有一个"还没开始就拦下"的判负**，比较特殊：

- 你贴了一大段特别长的内容当输入。大厂的做法是**输入框限长度**，超长就让你放文件里，用 `read_file` 读（**源头第一道防线**）。
- 就算没拦，系统**装配前会用公式算一遍**：输入勾起的一块空间 + 标准开销，够不够跑至少一段（一次问答闭环）？不够 → 直接提示"内容太大，建议放进文件读"，而不是让它硬跑起来然后误报成"摘要满了"（**装配前判负**，第二道防线）。输入端过大和"上下文把空间跑没了"，是两码事，分两条路处理。

### 第六步：暂停与中断——一次回答怎么收场

一次回答除了"正常停"，还可能被中途打断。这里分**两种**，处理方式完全不同：

**第一种 · 运行时暂停（自愿，原地续跑）**
- 你点"暂停"、插句话补充，或 LLM 主动提问（`ask_user`）——这些都是**"申请"**，不是硬切。
- 系统不会当场把正在跑的 step 砍掉，而是**等当前这一步做完，在 step 边界上介入**。
- 介入后**这一轮还是同一个问答闭环**，内存里的一切（正在做的事、说过的话）都还在。你补一句话、或点"继续"，它就在原处接着往下跑——**像没暂停过一样**。
- 这是**唯一**需要"续跑"的场景。

**第二种 · 中止 / 断电（非自愿，补全收场）**
- 崩溃、断电、关闭程序……进程一死，内存里的一切都没了，"在原地接着跑"从物理上就不成立了。
- 所以系统**不试图恢复**。它做的事很简单：**把这个没跑完的问答闭环，补全成一个完整的闭环身份**（标上"已中断"，如果已经输出了半截就一并附上），登记进会话历史。
- 这样它就成了一段**普通的历史记录**——下一次你打开程序、接着聊，它和其他历史一样被装进上下文。LLM 看到"上次这事没做完"，自然接着帮你做。
- **不搞"断点续跑"那套**。

**两种的唯一差别**：中止/断电的那一轮**没有记忆摘要**（它没走完收尾，见第七步）。所以当空间紧张、系统想把它换成摘要时，换不了——跳过去，交给 LLM 现场压成临时摘要，或者干脆被预算裁掉（见第四步）。**不会因为"缺摘要"就卡住。**

> **为什么不做"跨程序恢复暂停态"？** 因为代码分不清"你是优雅暂停后关的程序"还是"断电时恰好停在暂停态"。既然分不清，就一律按最坏情况（断电）处理：**补全收场、下次当普通历史接着聊**。这样模型最简单，也不会出现"程序偷偷帮你恢复了一个你不想要的暂停"这种意外。

### 第七步：记忆系统的沉淀（问答闭环收尾之后）

一次问答闭环结束，进入**收尾**：

- 系统在**这次用户输入对应的整段问答闭环结束**时，产出一条**记忆摘要**（一两句这个任务干了啥）。这条是**跨会话持久态**，真正存进记忆库，下次别处能召回。
- 记忆摘要在"问答闭环"级产出（**一个闭环一条**）；一次回答内部的每个 step **不单产记忆**，避免历史垃圾。
- **中止/断电收场的那一轮不产摘要**（它没走完收尾）——这就是第六步说的那个"唯一差别"。

### 第八步：东西到底存在哪（物理落盘）

前面说了那么多"存下摘要""补全成历史"，**这些到底落在磁盘哪里？** 说清楚，不然"断电不续跑"会显得悬空。

程序在你**工作区**里建了一个隐藏文件夹 `.memora/`，所有持久化的东西都在这里：

```
.memora/
  rounds/
    index.json          轮次索引（id → 状态 + 引用计数）
    {roundId}.json      一个"问答闭环"一个文件，装它的完整数据
  sessions.json         会话清单：每个会话的标题 + 它包含哪些轮（只存"指针"，不存正文）
  memories.json         记忆库：沉淀下来的记忆摘要都在这
```

关键点：

- **一轮对话 = 一个文件**。每个走完的问答闭环，最终都会落成 `rounds/{roundId}.json`；轮与轮之间互相独立，不靠一个大文件串起来。
- **会话只是"指针列表"**。`sessions.json` 里一个会话只记"标题 + 这轮属于哪个会话"，正文都在各自的轮文件里。**所以删会话、改标题都很轻，不会动到正文。**
- **记忆单独一处**。`memories.json` 是记忆库，第七步沉淀的摘要进这里。

### 一堵重要的墙：内存态 vs 落盘态

理解第八步，才能理解第六步为什么"断电不续跑"：

- **落盘的**（写到磁盘、关机也在）：走完的轮、会话清单、记忆库。
- **只在内存的**（程序一关就没了）：**正在进行的这一轮**，包括"你点了暂停"这个状态本身。

> **暂停态为什么不在磁盘里？** 因为它压根没被存下来。暂停只是"这一轮在内存里停了一下"——**程序还活着，它就在；程序一死，它就不存在了**。所以第六步说"断电就当普通历史接着聊"，不是系统"选择"不恢复，而是**它物理上无处可恢复**。这也是为什么不需要"断点续跑"——没有可续的那个点。

## 延伸到真正长久的会话（20、30 轮）

上面讲的是"一次输入的处理"。但对话可能连续聊 20、30 轮，每轮都是独立问答，**根本没有一个"触发整个任务的输入"**——这时锚点分级退场，靠的是**第一步的装配 + 第四步的替换**自然运转：

- 每轮进来照常装：最近的完整对话（尽量多装）。聊得越多，**装不下的旧轮次就自然被"替换"成它自己那份摘要**，让较新的对话始终优先在场。
- 于是体验是**渐变**的：前面十几轮原文都在（好），中间十几轮开始有些被换成摘要（还行，需要细节时 LLM 可以调 `trace_summary` 回溯原文），到了 30 轮，早前细节基本摘要化了（能跑，但早期代码 diff、具体数值这种细节会模糊）。
- 这是所有"摘要即记忆"系统的**物理极限**，不是 bug——它换来的是"永远装得下、不会突然崩"，代价是"早期细节逐渐变摘要"。真正重要的东西（用户偏好、结论、决策）被摘要保住了；极强的过程细节本来就不该占死上下文。

## 一句话合起来

> **插一张卡（角色包：只有内容 + 旋钮，不带代码；最省事的卡只写人设也能用）→ 一句话进来 → 搭好台（常驻设定 + 你的输入[顶级锚点独立划块] + 尽量多塞的最近对话，首轮必在场；记忆不再预装，需要时 LLM 自己查）→ 一次回答内部由 loop 反复推进（想一步→做一步→再看一步，只追加不重装配）→ 空间满了三级走：先替换成现成摘要、没得换就现场压、压不动就裁掉（首轮永在场）→ 该停时停（软上限收尾 / 步数到顶 / 干完交付，输入太大则预先拦下）→ 中途被打断分两种：你主动暂停就原地续跑（同一个闭环，只在内存里），崩溃断电就把这轮补全成一个完整闭环、下次当普通历史接着聊（这一轮没有摘要）→ 每个走完的闭环沉淀一条真记忆 → 落盘进工作区的 `.memora/`（一轮一文件、会话存指针、记忆单独一处；暂停态只在内存，所以断电无处可续）。长会话就反复用第一、四步自然运转，体验从"全原文"平滑退化成"摘要对话"。**
