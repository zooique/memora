# Trae Work 会话展示设计调研 —— 面向用户的对话 UI 对比参考

> 调研日期：2026-09-02 | 目的：聚焦 Trae Work 官方文档中「会话/对话展示」的面向用户的 UI 设计，整理为 Memora 会话记录展示的对比参考稿。
> 性质：外部土壤调研（网络为土壤思维模型），非设计定案；吸收与否另走种子合理性过滤。所有内容以官方文档记载为准，来源见文末；图片位置仅文字描述，未内嵌截图。

***

## 一、总体界面形态：三栏布局，对话只是"中栏"

TraeWork（Work/Code/Design 三种工作模式）桌面版/网页版的界面从左到右为 **任务管理面板、AI 对话面板、工具面板**。对话展示并非孤立的聊天窗口，而是与任务侧栏、工具侧栏联动的一站式工作台：

| 栏            | 职责                                                                    |
| ------------ | --------------------------------------------------------------------- |
| 左栏 · 任务管理面板  | 多任务列表；任务按标题/对话内容可搜索、可置顶；右键任务可分享                                       |
| 中栏 · AI 对话面板 | Query（用户提问）与答复（AI 回答）的对话流主体；本调研焦点                                     |
| 右栏 · 工具面板    | 多页签：任务摘要（待办 Todos / 任务产物 / 参考信息 或 上下文）、浏览器（产物预览）、终端（Code）、画布（Design）等 |

**核心观察**：Trae Work 把「AI 做了什么（过程）」与「AI 交付了什么（产物/待办）」从中栏对话流剥离到右栏工具面板，中栏对话流保持相对干净；而「用户问了什么 / AI 答了什么」始终完整呈现在对话流中。

## 二、对话流（中栏）的展示设计

### 2.1 基本单元：Query + 答复

- 对话流以 **Query（用户提问）与 答复（AI 回答）** 为基本条目，鼠标悬浮任一条底部出现操作图标（如**分享**、\*\*创建会话副本（Fork）\*\*等）。

- 悬浮操作是主要交互入口，界面默认保持干净、无按钮堆叠。

### 2.2 过程透明：任务过程可见性（对齐「任务时 / 结论」）

在 TraeWork 相关展示中，AI 执行时的思考/工具调查等过程性内容 **统一折叠进「任务过程」**，最终给用户一份干净的结论/报告；用户想翻细节时再展开折叠区。配合对话流中的实时反馈，实现"执行时能看到 AI 在做什么、结论干净收口"。

### 2.3 待办清单（Todos）与对话流节点自动折叠（关键设置项）

官方「对话流」设置（设置 > 对话流 > 待办清单）明确提供：

- **待办清单**：允许智能体使用待办清单跟踪任务进度；复杂任务时 AI 在右栏任务摘要页签列出任务计划（Todos），实时追踪每个子任务进度。

- **对话流节点自动折叠**（仅 SOLO/Work 类模式）：开启后 **已完成的任务在对话流中被自动总结并折叠**，折叠态只有摘要，**展开后展示全部细节**。

> 这正是 Memora 已落地的「任务过程折叠区 + 报告」展示形态的对标项：**进行中自动展开实时可见、完成自动收起只留摘要**。

### 2.4 产物与参考信息：右栏承载，不污染对话正文

- **任务产物**：右栏任务摘要页签存放 AI 为该任务生成的文件（Web 产物可预览、可"选择元素"点评、可"添加/评论到对话"回传给 AI 修改）。

- **参考信息 / 上下文**：实时显示 AI 执行时引用的所有上下文（技能、文件、联网搜索内容等）；Code 模式若上下文超出预期，提供 **压缩** 按钮。上下文用途透明可追溯，但不混入对话正文流。

### 2.5 代码变更展示（Diff 视图）

- 对话面板中有 **查看变更** 入口，打开代码变更窗口：变更涉及的文件数量、变更行数、文件列表，逐文件以 **diff 视图** 展示。

- 结合代码审查设置（审查所有变更 / 仅最近一轮 / 无需审查），用户对 AI 落盘改动有明确把关路径。

### 2.6 主动提问的对话呈现

官方设置项「智能体主动提问」：开启后 AI 在执行任务遇到多种可行方案或需要了解用户偏好时，会**主动暂停并向用户提问**，确保结果符合预期。与 Memora 的 `[ASK] → 暂停 → 回答续跑` 是同一交互范式（官方文档明确记载该开关）。

## 三、对话的复用与流转：Fork / 分享 / 搜索置顶

| 能力                    | 表现                                                                    | 官方记载来源                              |
| --------------------- | --------------------------------------------------------------------- | ----------------------------------- |
| **创建会话副本（Fork Chat）** | 多轮对话中可从任意一条 AI 回复创建新独立对话，继承该回复前全部上下文并自动切换进入，原对话不变                     | docs.trae.cn/ide\_chat（TraeCode 对话） |
| **分享对话**              | 对话流中悬浮任一 Query/答复点分享图标，或左栏任务右键"分享"；进入"选择对话"面板可**只选择部分 Query 和答复**生成分享 | 快速开始（TraeWork 网页/桌面）                |
| **历史搜索与置顶**           | 按任务标题和发出的对话内容搜索历史任务/对话；任务可置顶/取消置顶                                     | 更新日志（2026-07-14）                    |
| **引用历史对话 / 导出对话**     | 输入框用 `#` 引用历史对话；历史对话可导出                                               | TRAE CN 更新日志（2026-03-26）            |
| **对话流图片预览**           | 对话流及语音讨论记录中图片支持缩略图预览、大图查看、左右滑翻阅（移动端）                                  | 更新日志（2026-07-14 / 2026-07-07）       |
| **一键到底**              | 向上阅读离开底部时出现"一键到底"按钮，点击立即回到最新内容                                        | TRAE 移动端更新日志（2026-07-21）            |

## 四、对 Memora 的可吸收点（对比参考）

> 对照 Memora 现状（内核 RoundStore/SessionMeta 存储 + VS Code 宿主 webview 展示）。以下仅为"可吸收养分"，是否落地由 Memora 种子合理性过滤后决定。

| #  | Trae Work 设计                             | Memora 现状                                           | 差距 / 可吸收点                                     |
| -- | ---------------------------------------- | --------------------------------------------------- | --------------------------------------------- |
| T1 | 对话流节点自动折叠（完成→折叠摘要，展开看细节）                 | 已落地：round-block「任务过程折叠区 + 报告」，进行中展开、完成收起            | ✅ 已对齐，无需动作                                    |
| T2 | 右栏工具面板承载 任务摘要（Todos/产物/参考信息）、浏览器预览、终端、画布 | 工具调用细节在 round-block 内折叠，无独立右栏                       | 可选：考虑"查看变更/Diff"与"产物预览"独立面板，降低中栏密度（**最值得吸收**） |
| T3 | 待办清单（Todos）实时子任务进度追踪                     | checkpoint.plan + plan 状态在过程折叠区展示；宿主有 task table 渲染 | 子任务进度展示粒度可对齐：折叠摘要面显示"N/N 完成"                  |
| T4 | 参考信息/上下文 独立展示 + 可"压缩"                    | 召回记忆在过程折叠区展示                                        | 上下文来源展示位置可选独立化                                |
| T5 | 创建会话副本（Fork Chat）继承上下文                   | 已有 `forkSession`（roundIds 指针复制 + 上下文继承）             | ✅ 语义等价，无需动作；宿主 UI 可补"从任意回复 Fork"入口            |
| T6 | 分享对话（可选择部分 Query/答复）                     | 无                                                   | 可选增强：按 roundId 范围导出/分享                        |
| T7 | 对话流图片缩略图/大图预览                            | webview 支持图片输入展示                                    | 细节增强，暂缓                                       |
| T8 | 悬浮操作（分享/Fork）保持对话流干净                     | 已用 footer 操作区（复制/分叉/删除）                             | ✅ 已对齐交互密度原则                                   |
| T9 | 历史搜索/置顶/引用历史对话/导出对话                      | SessionMeta 持久化 + 会话列表；无全文搜索/导出                     | 可选增强：按 roundIds/摘要检索、`#` 引用历史                 |

## 五、核心结论（一句话）

Trae Work 会话展示的强，不在某一块 UI 花哨，而在 **"任务过程可折叠透明 + 对话正文干净收口 + 产物/上下文右栏剥离 + 对话可 Fork/分享/搜索复用"** 这一整套面向用户的展示闭环；Memora 的「问答闭环 + 任务过程折叠区 + 报告」已抓住其中最核心的折叠收口思想，剩余差距主要在中栏密度与对话复用能力（T2/T5/T6/T9）。
