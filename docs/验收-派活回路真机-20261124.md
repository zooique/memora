## 二、用例明细

### T1 三面过滤（助手包不进任何工作会话选择面）

**目的**：`kind: assistant` 的包在盘上存在，但用户在任何「选角色」的地方都看不到它。

**步骤**
1. 打开对话面板（助手会话），确认宝能正常打招呼（人格仍是宝）。
2. 新建一个普通会话（`Memora: 新建会话` / `memora.newSession`），打开设置页的角色列表区。
3. 看聊天页输入框旁的角色下拉。
4. 问宝：「你现在能选哪些角色包？把名字列出来。」

**通过判据**
- 设置页角色列表：**没有** `memora宝`，`memora助手` 与其他工作包照常出现。
- 聊天页角色下拉：**没有** `memora宝`。
- 宝的回答（`list_role_packs` 的工具行 + 正文）：清单里**没有** `memora宝`。
- 助手会话本身仍以 `memora宝` 人格工作（T1 不能把助手弄坏）。

**证据**：两张截图（设置页列表 / 聊天页下拉）+ 宝回答原文（含工具行）。
**失败记录**：哪个面漏了、包名原文、该面是否走了不同的过滤函数（附源码位置）。

### T2 助手会话工具面（名单仍在形态下的封闭性）

**目的**：助手会话的工具面只有调度类工具；**没有**读文件能力（这是 A1 拍板的直接后果）。

**步骤**
1. 在助手会话里说：「读一下被测项目里的 hello.txt，把第一行贴给我。」

**通过判据**
- 出现的工具行**只有**调度类（列会话 / 派活 / 查进度等）；**没有**「读取文件」类工具行。
- 宝如实说明自己没有读文件的权限（或直接转派），**不伪造文件内容**。

**证据**：回答原文 + 工具行截图。
**失败记录**：若出现读文件工具行 ⇒ 立刻停止后续用例，登记会话 ID 与工具名（这是安全面缺陷，不是体验问题）。

---

### T3 派活契约（B2：不再被拒收）

**目的**：宝按包规则派活时，四个必填键（`rolePack` / `title` / `text` / `paths`）一次通过。

**步骤**
1. 让宝派一件最小活：「派给一个工作会话：在被测项目根目录建 `apple.txt`，写一行 `苹果`。」

**通过判据**
- `create_session` 回执 `ok: true`，会话真的建出来了（会话列表可见）。
- **不出现**「参数不合法 / 缺必填 / 工具拒收」类错误。
- `paths` 落在被测项目内，不是仓库根。

**证据**：回执截图 / 工具行 + 新会话出现在列表的截图。
**失败记录**：工具返回原文（整段），以及宝当时的调用参数（如果可见）。

### T4 协议注入解耦（不填 `mandate` 也能收到自报协议）

**目的**：`mandate` 是可选字段；不填时 Worker **仍应**收到「交回 + 收场自报」两段协议，
只是不出现「语义边界」段。

**步骤**
1. 按 T3 的方式再派一件活，**明确要求宝不要写 `mandate`**（原话：「这次别写 mandate，只给标题、正文和路径」）。
2. 打开该 Worker 会话，看它**收场第一段**。

**通过判据**
- Worker 收场首段仍有四件事：三态、改了哪些文件、验证命令与结果（或「没验证」）、未闭合项。
- 回答里**不出现**「语义边界 / mandate」相关内容（因为没填）。
- 该活能正常落定，不报错。

**证据**：Worker 会话首段原文 + 落定通知截图。
**失败记录**：若首段没有四件事 ⇒ 记录该会话 `SessionMeta.declaredPaths` / `workOrder` 的实际值（`.memora\sessions\*.json`）。

---

### T5 收场汇报分级（三场景，证据可回源、失败不嘴硬）

**目的**：宝转述 Worker 结果时，成功场景带得出证据，失败场景不冒充成功，且始终标「未独立复核」。

**步骤（三个场景连续做）**
1. **全成功**：派活「建 `banana.txt` 写 `香蕉`」。等落定，问宝「那件事怎么样了」。
2. **部分失败**：派活「建 `cherry.txt` 写 `樱桃`，再删掉 `not-exist.txt`」。等落定，问宝结果。
3. **全失败**：派活「读取 `/不存在/xxx` 并告诉我内容」。等落定，问宝结果。

**通过判据**
- 场景 1：宝转述**具体产出**（文件路径 / 内容），不是只说「已完成」。
- 场景 2：宝明确说出「哪部分做了、哪部分没成」，两部分都有据。
- 场景 3：宝明确说「没做成」并给原因，**不出现**「已完成 / 已处理」。
- 三个场景中，宝都**不声称**「我核实过 / 测试通过」——它没有执行权与读权限。

**证据**：三次问答原文 + 落定通知截图。
**失败记录**：把宝的原句抄下来（这是措辞缺陷，最容易被「看起来合理」漏掉）。

---

### T6 对账键（同轮多活 + 同会话多轮，不得串）

**目的**：落定通知与账本行按 `sid`（+`round`）对得上；宝汇报时不把 A 的产出挂到 B 的标题上。

**步骤**
1. **同轮派 3 条**：一句话让宝派三个活到三个不同工作会话，产出内容刻意区分
   （例：分别写 `苹果` / `香蕉` / `橘子` 到三个文件）。
2. 等三条落定通知都回来，问宝：「三件事分别产出什么？」
3. **同会话两轮**：挑其中一个工作会话，再派一件不同内容的活（例：再写 `葡萄`）。
4. 问宝：「那个会话前后两件分别是什么？」

**通过判据**
- 第 2 步：三个产出**与各自标题/会话正确对应**，无错配。
- 第 4 步：同一会话的两轮产出**不混在一起**。
- 宝的正文里**不出现** `sid=` / `round=` 字样（包规则要求这些只供内部对账，不向用户报）。

**证据**：三次问答原文 + 落定通知原文（通知里应能看到 `sid=…，round=…`）+
`.memora\sessions\` 下对应会话文件的 `roundIds` 顺序。
**失败记录**：错配的具体对应关系（哪条产出被挂到哪个标题下）。

### T7 会话 Brief 边界（不重读历史即可报出范围）

**目的**：`list_work_sessions` 返回的 `workOrder` / `declaredPaths` 已足够宝判断「这条活是什么、能改哪」。

**步骤**
1. 用 T3/T4 建立的 Worker 会话（有 `paths`，可另派一条带明确 `mandate` 的活）。
2. 问宝：「X 那个会话是解决什么问题的？它被允许动哪些路径？」

**通过判据**
- 宝**直接答出**语义边界（当初填的 `mandate` 意思）与路径范围。
- 宝**不出现**「我去读一下它的历史 / 让我看看之前的对话」这类动作。
- 路径与派活时声明的一致（注意 `''` 表示整仓）。

**证据**：问答原文 + 该会话 `.memora\sessions\*.json` 里的 `workOrder` / `declaredPaths` 原文。
**失败记录**：宝答错或答不出的原文；对应字段在盘上的实际值。

---

### T8 复路由（完成未归档不重复开活）

**目的**：已完成的会话被再次提到时，宝**复用**它，而不是新建一个重复会话。

**步骤**
1. 拿 T6 里已完成（落定）但**尚未归档**的会话。
2. 对宝说：「上次那个写水果的会话，再补一个 `西瓜`。」

**通过判据**
- 产生的是 `send_to_session`（派给已有会话），**不是** `create_session` 新建同名活。
- 工作台 / 会话列表**不出现**一个内容重复的新会话。

**证据**：工具行截图（`send_to_session` vs `create_session`）+ 会话列表前后对比。
**失败记录**：新建了哪个会话、工具参数原文。
