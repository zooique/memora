## 一、测试分层

Memora 采用三层测试金字塔，与传统测试金字塔略有不同——**集成测试比例较高**（因为 Agent 是大模型 + 记忆引擎的耦合体）：

| 层级           | 范围                      | 工具              | 占比目标 | 运行频率    |
| -------------- | ------------------------- | ----------------- | -------- | ----------- |
| **单元测试**   | 纯逻辑模块（无 LLM 调用） | Vitest            | 50%      | 每次提交    |
| **集成测试**   | 多模块协作 + Mock LLM     | Vitest + Mock LLM | 35%      | 每次提交    |
| **端到端测试** | 真实 LLM API（少量）      | Vitest + 真实 API | 10%      | 每周/发版前 |
| **基准测试**   | 性能、Token 消耗、压缩    | 自定义 benchmark  | 5%       | 每周        |

**为什么集成测试比例高**：Agent 的核心价值在"记忆引擎 + 大模型"的协作——单元测试覆盖了纯逻辑，但**"记忆召回是否正确"必须靠集成测试**。Mock
LLM 是关键手段。

### 3.2 测试结构（Given-When-Then）

```javascript
import { describe, it, expect, beforeEach, afterEach } from 'vitest';
import { loadPermanence } from './permanenceLoader.js';
import { mockFs } from './test-utils/mockFs.js';

describe('permanenceLoader', () => {
  describe('loadPermanence', () => {
    it('should load always memory directly without retrieval', async () => {
      // Given
      const mockFiles = {
        '~/.memora/global/personality.md': '# Personality\n...',
        '~/.memora/global/rules/universal.md': '# Rules\n...',
      };
      mockFs(mockFiles);

      // When
      const result = await loadPermanence({
        permanence: 'always',
        projectId: 'test-project',
      });

      // Then
      expect(result).toHaveProperty('personality');
      expect(result).toHaveProperty('rules');
      expect(result.tokenCount).toBeGreaterThan(0);
    });

    it('should skip non-existent files gracefully', async () => {
      // Given
      mockFs({}); // 空文件系统

      // When
      const result = await loadPermanence({ permanence: 'always' });

      // Then
      expect(result.personality).toBeNull();
      expect(result.errors).toHaveLength(0); // 优雅降级，不报错
    });

    it('should throw on permission denied', async () => {
      // Given
      mockFs(
        { '~/.memora/global/personality.md': null },
        {
          permissionDenied: true,
        },
      );

      // When/Then
      await expect(loadPermanence({ permanence: 'always' })).rejects.toThrow(
        'EACCES',
      );
    });
  });
});
```

### 3.3 关键工具与 Mock

```javascript
// test-utils/mockFs.js
// 用于 mock 文件系统，避免真实 IO

import { vi } from 'vitest';
import { vol } from 'memfs';

export function mockFs(files = {}, options = {}) {
  vol.reset();
  vol.fromJSON(files);
  vi.mock('fs', () => vol);

  if (options.permissionDenied) {
    vi.spyOn(vol, 'readFileSync').mockImplementation(() => {
      throw new Error('EACCES: permission denied');
    });
  }
}

export function unmockFs() {
  vol.reset();
  vi.unmock('fs');
}
```

## 四、集成测试规范

### 4.1 Mock LLM 策略

**核心原则**：集成测试不调用真实 LLM
API，使用确定性 Mock——保证测试可重复、CI 友好。

```javascript
// test-utils/mockLlm.js
// Mock LLM 客户端：返回预设响应

export class MockLlmClient {
  constructor(responses = []) {
    this.responses = responses;
    this.callHistory = [];
  }

  async chat(messages, options = {}) {
    this.callHistory.push({ messages, options });

    // 匹配预设响应
    const match = this.responses.find((r) => r.match(messages, options));

    if (!match) {
      throw new Error(
        `No mock response for: ${JSON.stringify(messages.slice(-1))}`,
      );
    }

    return match.response;
  }

  // 验证调用历史
  assertCalledTimes(times) {
    expect(this.callHistory).toHaveLength(times);
  }

  assertLastCall(messages) {
    const lastCall = this.callHistory[this.callHistory.length - 1];
    expect(lastCall.messages).toMatchObject(messages);
  }
}
```

## 五、端到端测试规范

### 5.1 范围

端到端测试**严格控制数量**——只测核心场景，避免 API 成本爆炸和测试不稳定。

| 场景             | 触发频率 | LLM 真实调用 |
| ---------------- | -------- | ------------ |
| 启动 + 简单对话  | 每次提交 | ✓            |
| 多轮工具调用     | 每周     | ✓            |
| 真实话题报告炼化 | 每周     | ✓            |
| 跨会话记忆恢复   | 每月     | ✓            |

**触发频率原则**：端到端测试不是 CI 必需——只在**重要节点**（发版前、合并到 main）跑。

### 5.2 实现方式

```javascript
// e2e/agent.e2e.test.js
import { describe, it, expect } from 'vitest';
import { Agent } from '../src/index.js';

describe('Agent E2E', () => {
  // 只在 E2E 环境变量存在时运行
  if (!process.env.RUN_E2E) {
    it.skip('E2E tests are skipped', () => {});
    return;
  }

  it('should complete a real multi-turn conversation', async () => {
    const agent = new Agent({
      projectId: 'e2e-test',
      llm: {
        provider: 'openai',
        apiKey: process.env.OPENAI_API_KEY,
        model: 'gpt-4o-mini', // 用便宜模型
      },
    });

    await agent.init();

    // 多轮对话
    const r1 = await agent.chat('你好');
    expect(r1.content).toBeTruthy();

    const r2 = await agent.chat('记住我的名字是张三');
    expect(r2.content).toBeTruthy();

    const r3 = await agent.chat('我叫什么名字？');
    expect(r3.content).toContain('张三'); // 验证记忆

    await agent.close();
  }, 60000); // 60 秒超时
});
```

### 5.3 成本控制

- 端到端测试**只用便宜模型**（如 `gpt-4o-mini`）
- 每月端到端测试成本控制在 ¥50 以内
- 任何失败的端到端测试**不重试**——直接失败

### 8.1 上下文压缩测试

```javascript
describe('Compressor 5 层管道', () => {
  it('层级 1：单次 tool 结果 > 2000 字时截断', () => {
    const longResult = 'A'.repeat(3000);
```

## 九、测试反模式（禁止）

| 反模式                   | 原因                 | 替代方案                          |
| ------------------------ | -------------------- | --------------------------------- |
| **测试依赖真实 LLM API** | 不稳定、慢、成本高   | 用 Mock LLM（除少量 E2E）         |
| **测试共享状态**         | 一个测试失败影响其他 | 每个测试独立 setup/teardown       |
| **过度 Mock**            | 失去集成价值         | 只 Mock 外部依赖（LLM、文件系统） |
| **忽略时间相关测试**     | 间歇性失败           | 用 `vi.useFakeTimers()`           |
| **测试实现细节**         | 重构时易碎           | 只测试公开 API                    |
| **长测试用例**           | 难调试               | 一个测试一个断言                  |
| **跳过失败的测试**       | 技术债积累           | 不允许 skip 失败的测试            |
