## 1. 核心哲学（8 条）

### 1.1 万物皆记忆 — 人格/规则/技能/工具/历史全部是"记忆"

- 代码体现：MemoryType 枚举（6 种）+ 单一 memories 表

### 1.2 永久性分级 — always > domain > topic > on-demand

- always(100%启动加载) → domain(按领域加载) → topic(按相关度召回) →
  on-demand(显式调用)

### 1.3 冷热分离 — 文件(.md)承载本体 · SQLite(FTS5)承载索引

### 1.4 代码与模型分工 — 代码管确定性(查询/预算/IO) · 模型管不确定性(理解/生成/决策)

### 1.5 领域无关 — 核心代码零耦合领域，切领域只换 agent-config/ 不改 src/

### 1.6 增量召回 — 启动只加载 always+domain，其余 Loop 中按需检索

### 1.7 降级优先 — 归档失败不阻塞对话，3s 超时兜底

### 1.8 自然遗忘 — 接受"部分遗忘"，剪枝/归档/权重衰减是核心机制

## 2. 启动流程（Agent.init()）

### Step 1: 加载 Config

- 优先级：opts.config > opts.configPath > 默认配置
- 来源：loadConfig() → expandEnvVars → JSON 解析

### Step 2: 初始化项目上下文（ProjectManager.initProject()）

- 解析路径 → .memora/（运行时数据）+ agent-config/（配置目录，可选）
- 创建 FileStore(configDir) — 读写配置的 markdown 文件
- 创建 MemoryIndex(memora.db) — SQLite + FTS5 全文索引

### Step 3: 记忆加载（MemoryLoader.bootstrap()）

- 扫描 agent-config/ 下 personality.md / rules/ / skills/ / tools/
- 写入 SQLite 索引（memory_type + tags + segments + weight）
- 返回 bootstrapMemories（always + domain 永久性记忆）

### Step 4: 组件组装

- createLlmProvider(config) — LLM 适配层（DeepSeek/OpenAI/Doubao）
- createTopicSummarizer(provider) — 话题摘要生成器
- new MessageHistory(topicStore, summarizer) — 消息历史 + 话题管理
- new ToolExecutor(projectPath, security, index) — 工具执行器
- new AgentLoop(provider, bootstrapMemories, toolExecutor) — 核心执行引擎

### Step 5: 返回 AgentContext（宿主项目可访问内部组件）

## 3. 对话流程（Agent.chat() → AgentLoop.processUserInput()）

### 3.1 用户消息写入历史

- MessageHistory.appendUser() → 写话题文件（fire-and-forget）

### 3.2 Agent Loop 执行（最多 20 轮迭代）

#### [每轮] 组装 system prompt

- bootstrapMemories(永驻+领域) → 拼成 system message

#### [每轮] 调用 LLM（流式）

- 普通文本 → yield chunk 给用户（流式输出）
- tool_calls → 进入工具执行分支

#### [工具分支] 执行工具调用

- ToolExecutor.execute(name, args)
  - SecurityGuard.checkPath() — 路径白名单校验
  - 写操作 → SecurityGuard.confirmWrite() — owner 权限确认
  - 审计日志 → logger 记录（M-105）
- 工具结果注入 messages → 继续下一轮 LLM 调用

#### [退出条件] 纯文本回复 / 达到 maxIterations / 错误

### 3.3 Agent 回复写入历史

- MessageHistory.appendAssistant() → 写话题文件 + 触发归档检查

## 4. 记忆系统（5 类 + 统一管线）

### 4.1 记忆类型（MemoryType 枚举）

- personality — "我是谁"人格设定（永久性: always）
- rule — 行为约束规则（永久性: always/domain）
- skill — 领域能力技能（永久性: on-demand）
- tool — 工具定义（永久性: on-demand）
- topic — 对话历史（永久性: topic，每轮召回）
- archive — 归档精华（永久性: topic，按需搜索）

### 4.2 存储架构（冷热分离）

- 热层（文件）: .md/.json 文件 → 人类可读可编辑
  - FileStore.read() / write() — frontmatter 格式
- 冷层（SQLite）: memora.db → 程序高性能检索
  - memories 表 — 统一存储（id/type/permanence/name/content/tags/weight）
  - memory_fts 虚表 — FTS5 全文索引（触发器自动同步）

### 4.3 召回管线

- 启动时：MemoryLoader.bootstrap() → always + domain（确定性 100%）
- Loop 中：search_memories 工具 → MemoryIndex.search() → FTS5 MATCH

## 5. 上下文组装（每轮提交给 LLM 的 prompt）

### 公式：上下文 = 用户输入 + 记忆召回 + 工作记忆

### 第一层 · 用户主动输入 — 每轮刷新

- 用户 prompt 文本

### 第二层 · Agent 记忆召回结果 — 见永久性分级

- 永驻记忆(always) — 人格 + 安全规则（永不刷新）
- 领域记忆(domain) — 领域规则（领域切换时刷新）
- 话题记忆(topic) — 当前话题历史（每轮刷新）
- 能力记忆(on-demand) — 工具/技能定义（任务切换时刷新）

### 第三层 · Agent Loop 工作记忆（瞬时态，Loop 结束后转为话题记忆）

- 模型中间回复 — Loop 内的推理产物
- 工具调用结果 — read_file/write_file 等执行结果
- 增量召回上下文 — 模型中通过 search_memories 检索到的记忆

## 6. 归档流程（记忆归档原则 v0.3）

### 触发时机：话题切换时 / MessageHistory.switchTopic()

### Step 1: 收集完整对话（user + assistant），截断 800 字

### Step 2: LLM 结构化提取

- Prompt 要求输出 JSON：{"约束":[], "偏好":[], "决策":[]}
- 三个过滤原则：
  - 信息不对称 — 大模型不知道的信息吗？
  - 决策持久性 — 会影响未来交互吗？
  - 用户独特性 — 是用户独有的场景吗？
- 低价值 → 返回 SKIP → 跳过归档（返回 null）

### Step 3: 解析 JSON → 格式化存储

- {"约束":["Windows"], "偏好":["小驼峰"]} → "约束：Windows | 偏好：小驼峰"

### 降级策略：JSON 解析失败 → 降级为原始文本（兼容 v0.2）

## 7. 安全模型（ADR-006）

### 7.1 两级权限

- owner — 可读写（需确认敏感操作）
- guest — 只读（写操作自动拒绝）

### 7.2 路径白名单

- 允许：项目目录 + 用户配置的 allowedPaths
- 禁止：.ssh/ .aws/ .env System32/ etc/passwd

### 7.3 审计日志（M-105）

- 所有允许/拒绝 + 写入确认/拒绝 记录到日志

## 8. 宿主接入（Agent 门面 → 领域模板）

### 8.1 安装：memora init --domain code|novel

- 生成 agent-config/ + agentBridge.js + .memora/

### 8.2 代码接入

- new Agent({ projectPath, configDir, config })
- await agent.init()
- 流式：for await (chunk of agent.chat(input))
- 非流式：await agent.chatSync(input)
- 话题：agent.switchTopic(name) / agent.listAllTopics()
- 释放：await agent.close()

### 8.3 领域切换

- 不改 src/ 一行代码 → 只换 agent-config/ → 切领域

## 优化方向思考

基于以上运作逻辑，以下是几个值得关注的优化切入点：

1. **召回精度**（路径 4.3）— 当前 topic 记忆靠 FTS5 关键词匹配，可引入向量搜索（sqlite-vec 已在 ADR 中预留）做语义召回
2. **Token 预算自动化**（路径 5）— 当前召回结果拼入 prompt 无配额上限，可加 tokenizer 实时统计 + 截断策略
3. **归档升级为 ADR**（路径 6）— 记忆归档原则 v0.3 已有结构化提取，待实战验证后升级为正式 ADR
4. **领域模板生态**（路径 8.1）— 当前只有 code/novel 两个模板，可开放模板注册机制让社区贡献
5. **工具安全分级**（路径 7）— 当前是二分（owner/guest），可扩展为三级（owner/editor/viewer）细粒度控制
