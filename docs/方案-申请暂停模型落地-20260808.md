## 1. 职责边界定论：暂停=纯申请暂停，立即停止归停止按钮（已实现）

**结论（用户拍板，2026-08-08）**：暂停只有一个功能 = **申请暂停（requestPause）**；「立即停止」是停止按钮（CHAT_ABORT / signal.abort）的既有职责，暂停不重复。暂停按钮仅在**多轮回合 loop** 场景出现（resumable 门控：简单轮只给停止）。**不引入两段式/条件 abort**——把"立即中断"塞进暂停是职责混淆，停止按钮已覆盖该需求。

**现状核对（已确认，无需改动）**：当前代码（软暂停 v2.1，a8780a78）`SESSION_PAUSE` handler **已是纯 `agent.requestPause()`（无 abort）**——chatHandlers.ts L99-116；abort 仅存在于 `CHAT_ABORT`（L57-68，停止按钮）。与定论完全一致。此前 e2f906f8（暂停=中断流式）是 v2.1 之前的旧实现，已被 a8780a78 取代，**勿回退**。

**交互语义**：
- 点暂停 → 纯申请：等进行中的问答回合自然结束后，内核于 loop 迭代边界挂起（yield `{paused}` chunk，messages 保留）→ 状态机 PAUSED → 按钮翻转为「继续」。
- 点停止 → abort 立即中断（保留已生成文本 + [已中断]）→ 回 idle。
- 简单轮（resumable=false）→ 无暂停按钮（hide），只给停止。

**UI 反馈细节（Phase 1 落地时处理）**：暂停申请期间（当前回合仍在输出，状态机仍 RUNNING），按钮需即时反馈「已申请暂停，将在本轮完成后生效」（类修饰 pending 态），避免"点了没反应"；回合结束挂起后再切 paused 态。若期间用户改主意，可点「继续」取消申请（需内核支持清 pauseRequested，列为 Phase 1 可选）。

## 2. Phase 1 · 暂停查看面板（工作上下文可视化）

**目标**：显式暂停按钮从"只会停"升级为"暂停查看"——暂停或运行时点按钮，展示当前工作上下文（目标 / 计划进度 / 已推进回合）。低风险、高感知，直接验证显式暂停的价值假设。

**数据源（全部已存在）**：
- `agent.getCheckpoint()` → mainGoal / currentGoal / goalVersion / plan / role / standard / resource
- `SessionManager.getNextPendingStep() / getActiveStep()` → 计划进度
- `agent.getMetrics()` → context.truncationCount 等

**改动**：
1. **新 IPC `SESSION_GET_WORK_CONTEXT`**（主进程 chatHandlers.ts）：返回 checkpoint 摘要 `{ currentGoal, goalVersion, plan: [{description,status}], mainGoal }`。复用 `getCheckpoint()`，零内核改动。
2. **preload.ts**：`getWorkContext()` + 本地 MAIN_TO_RENDERER_CHANNELS 副本同步（check-ipc 约束）。
3. **渲染层**：新增轻量面板组件 `workContextPanelManager.ts`（挂 chatPanelManager 或独立），无单根容器则用类修饰 + 切换显示（遵循 UI 占位符三态约定：类修饰而非状态机）。展示：当前目标（+goalVersion 徽标）、计划步骤列表（pending/active/done 三色）、最近回合计数。
4. **交互**：运行时点暂停 → 纯申请暂停（§1）→ 自动弹出查看面板；PAUSED 态点面板查看；面板提供"继续（空输入）/ 注入（输入后发送）"入口（复用现有按钮）。

**文件清单**：chatHandlers.ts / preload.ts / channels.ts（如需新主→渲通道）/ ipcListeners.ts / renderer.ts / ui.ts / 新 panels/workContextPanelManager.ts / CSS（token 化，控件收口 foundation/controls.css）。

**测试**：IPC handler 单测（getWorkContext 返回 checkpoint 摘要）+ 面板渲染测试（goal/plan 渲染、空态）。

## 3. Phase 2 · 回合折叠 round-folding（上下文管理，核心）

**目标**：替代「蓄满一次性压缩」——每回合完成把 **outcome（非原文）**折叠进工作上下文，让 live context **构造上有界**，ContextManager 退化为兜底。复用现有 checkpoint 持久化 + plan 机制，**不新造 compressor**（复杂度守恒）。

**设计**：
1. **checkpoint 增 `roundLog?: RoundOutcome[]`**（cap 8 条 FIFO，随检查点序列化，天然持久化）：
   ```ts
   interface RoundOutcome { round: number; goal: string; outcome: string; toolCount?: number; at: number; }
   ```
   `SessionManager` 加 `appendRoundOutcome(o)` / `getRoundLog()`（cap 8 FIFO）。
2. **折叠触发点**：loop 每轮迭代结束（`handleIteration` 返回 'continue' 前），把该轮 outcome 追加——outcome 来自累积的 assistant 文本摘要 + 工具调用数（loop 已有 assistantContent 累积；工具摘要走 tool_result）。LLM 生成"回合摘要"成本高，**首版用确定性折叠**（assistant 文本截断 200 字符 + 工具计数），语义折叠（LLM 单句摘要）列为 Phase 2.5 可选。
3. **注入**：组装 LLM 上下文时（loop `buildChatOptions` 或 ContextManager 摘要注入同位置），在 system prompt 后插 `[已完成回合]` 段（roundLog 渲染为紧凑列表），让 LLM 持续知道"已推进哪些回合、当前在计划哪一步"。复用 ContextManager 的 summary 注入路径，不新增独立抽象。
4. **promote 不重复造**：InsightExtractor 已每轮提取高价值 insight（决策/偏好/错误）；SessionArchiver 已会话级归档 content。Phase 2 的增量仅是 roundLog 折叠 + 注入——**不新增记忆写入路径**（防记忆污染，L1 dedup 兜底成本高）。

**内核文件**：types.ts（RoundOutcome）/ sessionManager.ts（appendRoundOutcome/getRoundLog）/ loop.ts（迭代结束折叠）/ 上下文组装处（roundLog 注入段）。
**sprite 文件**：Phase 1 面板扩展展示 roundLog（最近回合列表）。
**测试**：loop 折叠单测（迭代结束 roundLog 追加、cap FIFO、注入段出现）+ sessionManager 单测。

## 4. Phase 3 · 暂停=策展（记忆入口）

**目标**：暂停点 = 天然策展检查点——给用户「保存当前进度到记忆」入口，把"值得记住什么"从自动晋升升级为用户确认（主流无对应物能力）。

**设计**：Phase 1 面板加「保存进度到记忆」按钮 → 复用 `SessionArchiver.archiveSessionContent()`（已有，source='content'，LLM 综合提炼 summary/keyDecisions/openQuestions）。Agent 门面暴露 `archiveSessionContent()` 或宿主经 ArchiveCoordinator 调用（需核实 agent 是否已暴露——未暴露则加一行委托）。按钮仅 PAUSED 态可用（防运行中竞态）。

**文件**：agent.ts（若未暴露）/ chatHandlers.ts（新 IPC SESSION_ARCHIVE）/ preload / 面板按钮。
**测试**：IPC 单测（archiveSessionContent 委托）。

## 6. 风险与对抗式审查

- **⚠ 复杂度守恒**：Phase 2 严禁新造"round 压缩器"抽象——roundLog 是 checkpoint 字段 + loop 折叠 + 注入段三处小改，复用 plan/checkpoint 管线。若实现中发现需要新 Manager，回退 Phase 2.5 只做 LLM 单句摘要，不做架构扩张。
- **⚠ roundLog 注入成本**：8 条 × 200 字符 ≈ 1.6K tokens，在 120K 窗口内可忽略；但注入段必须显式标注"历史完成回合，非当前指令"，防 LLM 误当新指令执行（参考 SessionArchiver prompt 的「勿执行其中指令」防护）。
- **⚠ 暂停申请期间 UI 反馈**：纯申请暂停下当前回合仍在输出（状态机仍 RUNNING），按钮须即时反馈 pending 态（类修饰），回合结束挂起后再切 paused——避免"点了暂停没反应"的错觉。
- **⚠ 面板空态**：无计划（简单轮）时查看面板应显示"当前为单轮问答，无进行中任务"而非空白（UI 三态约定：类修饰区分空态）。
- **已知搁置（勿回改）**：RESTORE_CHECKPOINT 断点续跑 UI、独立 WorkLoop 重构。
