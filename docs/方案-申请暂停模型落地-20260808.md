## 1. 任务表模型（核心概念，用户设计 2026-08-08）

**任务表 = 以 loop 回合为单位的任务清单**，两类任务：

| 任务类型 | 行为 | 说明 |
|---|---|---|
| **普通任务** | 单轮问答直接闭环 | 默认形态；简单 → 不生成任务表 |
| **难度任务** | 单轮问答**演化出 loop 任务表**，逐条推进 | 复杂 → 渐进升级；loop 不是独立模式，是单轮问答的自然叠加 |

**三条铁律**：
1. **渐进式**：单轮问答是基础，loop 是渐进设计（能力分级而非模式切换，与 v2.1 收敛一致）。
2. **任务可实时追加**：本轮问答中发现更复杂 → 继续向任务表添加条目（`SessionManager.updatePlan` 已是载体，需支持追加语义）。
3. **简单轮无任务表 → 无暂停按钮**：暂停/继续按钮是**任务表专属**控件（resumable 门控已实现：`streaming && !resumable → hide`，只给停止）。

**暂停/继续按钮的落点 = 任务表上的「暂停点」**：
- 用户可在**尚未推进的任务前**点击暂停（如任务 3 前打暂停点）；
- loop 继续跑前面的任务，**推进到被标记的任务时挂起**（预约式暂停，非即时暂停）；
- 也可点击继续（取消暂停点 / 确认后继续推进）。

## 2. 交互语义（输入通道与暂停互不干扰）

**待定输入区 = 全局概念，两个行为分支**（用户拍板 2026-08-08）：

| 状态 | 输入去向 | 行为 |
|---|---|---|
| **RUNNING（未暂停）** | 进待定输入区 | **自动注入**：立即排队到下一轮问答前面（自然生效） |
| **PAUSED（已暂停）** | 进待定输入区 | **不注入**：留在待定区（可自由添加/删除/编辑草稿），**点「继续」才提交注入** |

- 待定输入区载体 = **输入框本身**（输入通道永不冻结，现有 inputAreaManager 已保证可编辑）；差异仅在"提交时机"——RUNNING 发送即注入，PAUSED 发送仅标记待定、点继续才注入。
- **与当前代码的差异（行为变更点）**：当前 `inputAreaManager` paused 分支是"有输入 → emitSendMessage → processEvent → 内核 auto-resume 注入"（阶段 0 语义，提交 0820d0ae）。**需改为：PAUSED 发送 = 内容保留待定（不触发 processEvent），点「继续」→ `resumeExecution(待定内容)` 提交注入**。
- 停止按钮（CHAT_ABORT / signal.abort）仍为唯一"立即中止"路径，与暂停职责互不重叠。

## 3. Phase 1 · 任务表面板（工作上下文可视化）

**目标**：把暂停/继续按钮从"会停"升级为"任务表操作"——展示任务表（目标 / 任务进度 / 暂停点位置）+ 待定输入区，让用户看到"暂停将停在哪里、输入将注入哪里"。

**数据源（全部已存在）**：
- `agent.getCheckpoint()` → mainGoal / currentGoal / goalVersion / **plan（即任务表）** / role / standard / resource
- `SessionManager.getNextPendingStep() / getActiveStep()` → 任务推进位置
- `agent.getMetrics()` → context.truncationCount 等

**改动**：
1. **新 IPC `SESSION_GET_WORK_CONTEXT`**（主进程 chatHandlers.ts）：返回 `{ currentGoal, goalVersion, plan: [{id,description,status}], mainGoal, hasPausePoint }`。复用 `getCheckpoint()`，零内核改动。
2. **preload.ts**：`getWorkContext()` + 本地 MAIN_TO_RENDERER_CHANNELS 副本同步（check-ipc 约束）。
3. **渲染层**：新增 `taskTablePanelManager.ts`（挂 chatPanelManager 或独立），类修饰 + 切换显示（UI 三态约定：类修饰而非状态机）。展示：
   - 当前目标（+goalVersion 徽标）；
   - 任务表（plan 列表：pending/active/done 三色 + 暂停点标记位置）；
   - 待定输入区状态（是否有待定内容、待定内容可编辑预览）。
4. **交互**：
   - 点暂停 → 纯申请（§2，等进行中的回合结束挂起）→ 自动弹出任务表面板；
   - PAUSED 态输入 → 进待定区（输入框保留，面板显示"已待定"）→ 点「继续」→ `resumeExecution(待定内容)`；
   - 面板提供"继续（空输入）/ 注入（输入后发送）"入口（复用现有按钮逻辑，仅提交时机不同）。
5. **UI 反馈细节**：暂停申请期间（当前回合仍在输出，状态机仍 RUNNING），按钮须即时反馈 pending 态（类修饰「已申请暂停，将在本轮完成后生效」），避免"点了没反应"。

**文件清单**：chatHandlers.ts / preload.ts / channels.ts（如需新主→渲通道）/ ipcListeners.ts / renderer.ts / ui.ts / inputAreaManager.ts（paused 发送改待定语义）/ 新 panels/taskTablePanelManager.ts / CSS（token 化，控件收口 foundation/controls.css）。

**测试**：IPC handler 单测（getWorkContext 返回 checkpoint 摘要）+ inputAreaManager paused 分支改测（发送保留待定、继续提交）+ 面板渲染测试（goal/plan/暂停点/空态）。

## 4. Phase 2 · 回合折叠 round-folding + 预约暂停点（内核为主）

**目标 A（回合折叠）**：替代「蓄满一次性压缩」——每回合完成把 **outcome（非原文）**折叠进工作上下文，让 live context **构造上有界**，ContextManager 退化为兜底。复用现有 checkpoint 持久化 + plan 机制，**不新造 compressor**（复杂度守恒）。

**设计 A**：
1. **checkpoint 增 `roundLog?: RoundOutcome[]`**（cap 8 条 FIFO，随检查点序列化，天然持久化）：
   ```ts
   interface RoundOutcome { round: number; goal: string; outcome: string; toolCount?: number; at: number; }
   ```
   `SessionManager` 加 `appendRoundOutcome(o)` / `getRoundLog()`（cap 8 FIFO）。
2. **折叠触发点**：loop 每轮迭代结束（`handleIteration` 返回 'continue' 前），把该轮 outcome 追加——outcome 来自累积的 assistant 文本摘要 + 工具调用数。首版用**确定性折叠**（assistant 截断 200 字符 + 工具计数），LLM 单句摘要列 Phase 2.5 可选。
3. **注入**：组装 LLM 上下文时（loop `buildChatOptions` 或 ContextManager 摘要注入同位置），在 system prompt 后插 `[已完成回合]` 段（roundLog 紧凑列表），让 LLM 持续知道"已推进哪些任务、当前在任务表哪一步"。复用 ContextManager 的 summary 注入路径。
4. **promote 不重复造**：InsightExtractor 已每轮提取高价值 insight；SessionArchiver 已会话级归档 content。**不新增记忆写入路径**（防记忆污染）。

**目标 B（预约暂停点）**：任务表上打暂停点 → 推进到该任务时挂起。
- checkpoint 增 `pauseBeforeStepId?: string`（预约暂停点的任务 id）；loop 迭代边界检查：`getActiveStep()` 命中 pauseBeforeStepId → 触发 requestPause 等效行为（挂起 + 清标记）。
- 支持"取消暂停点"：用户点继续取消 → 清 pauseBeforeStepId（无暂停点则继续推进）。
- 任务实时追加：`SessionManager.updatePlan` 支持 append（现有 plan 已含 status，追加 = push + 重排 order）。

**内核文件**：types.ts（RoundOutcome / pauseBeforeStepId）/ sessionManager.ts（appendRoundOutcome / getRoundLog / setPauseBeforeStep）/ loop.ts（迭代结束折叠 + 边界检查暂停点）/ 上下文组装处（roundLog 注入段）。
**sprite 文件**：Phase 1 面板扩展（暂停点标记点击交互、roundLog 展示）。
**测试**：loop 折叠单测（roundLog 追加、cap FIFO、注入段出现）+ 预约暂停点单测（命中挂起、取消恢复）+ sessionManager 单测。

## 5. Phase 3 · 暂停=策展（记忆入口）

**目标**：暂停点 = 天然策展检查点——给用户「保存当前进度到记忆」入口，把"值得记住什么"从自动晋升升级为用户确认（主流无对应物能力）。

**设计**：任务表面板加「保存进度到记忆」按钮 → 复用 `SessionArchiver.archiveSessionContent()`（已有，source='content'，LLM 综合提炼 summary/keyDecisions/openQuestions）。Agent 门面暴露 `archiveSessionContent()` 或宿主经 ArchiveCoordinator 调用（需核实 agent 是否已暴露——未暴露则加一行委托）。按钮仅 PAUSED 态可用（防运行中竞态）。

**文件**：agent.ts（若未暴露）/ chatHandlers.ts（新 IPC SESSION_ARCHIVE）/ preload / 面板按钮。
**测试**：IPC 单测（archiveSessionContent 委托）。

## 7. 风险与对抗式审查

- **⚠ 复杂度守恒**：Phase 2 严禁新造抽象——roundLog/pauseBeforeStepId 都是 checkpoint 字段 + 小改，复用 plan/checkpoint 管线。若实现中发现需要新 Manager，回退 Phase 2.5 只做 LLM 单句摘要，不做架构扩张。
- **⚠ 待定区语义迁移**：PAUSED 发送从"auto-resume 注入"改为"留待定、点继续提交"是**行为变更**——须同步更新阶段 0 相关测试与文档（0820d0ae 语义被取代，勿混淆）。
- **⚠ roundLog 注入成本**：8 条 × 200 字符 ≈ 1.6K tokens，120K 窗口内可忽略；注入段须显式标注"历史完成回合，非当前指令"，防 LLM 误当新指令执行。
- **⚠ 预约暂停点边界**：暂停点命中检测须与 `getActiveStep()` 状态同步；取消暂停点须幂等（无暂停点时 no-op）。
- **⚠ 面板空态**：无任务表（简单轮）时面板显示"当前为单轮问答，无进行中任务"而非空白（UI 三态约定）。
- **已知搁置（勿回改）**：RESTORE_CHECKPOINT 断点续跑 UI、独立 WorkLoop 重构。
