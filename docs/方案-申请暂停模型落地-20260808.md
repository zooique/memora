## 1. 任务表模型（概念）

- 任务表 = 以 loop 回合为单位的任务清单：**普通任务**（单轮闭环，默认）/ **难度任务**（单轮演化 loop 任务表逐条推进）。
- 渐进式：单轮问答是基础，loop 是自然叠加；**任务可实时追加**（本轮发现更复杂 → 追加条目）。
- 简单轮无任务表 → 无暂停按钮（resumable 门控天然吻合）。
- **双通道原则（评审建议 6）**：任务表 = **LLM 可见的上下文**（LLM 可读写状态）+ **用户可操作的 UI**——对标 Claude Code TODO / Cursor plan mode / OpenAI Task。任务表不是 UI 装饰，是 LLM 工作记忆的一部分。

## 1.5 任务表生命周期（评审建议 1，v2 核心新增）

**四环节闭环**：生成 → 注入 → 推进 → 归档。

1. **生成**：LLM 复杂度判定——composer 补全链在 `resolveChatTaskSlot` 或独立判定点，输出 `needsLoop: boolean`；`needsLoop=true` 时首次调用 `SessionManager.updatePlan` 写入任务表（**首个生产调用点**，激活死机制）；简单轮不生成（plan 保持空，UI 不显示任务表）。
2. **注入**：组装 LLM 上下文时注入两段——**任务表态**（待办 pending + 当前 active + 已完成 done 的紧凑列表，对标 TODO/Plan）+ **roundLog**（已完成回合 outcome，§5）。任务表让 LLM 持续知道"我在任务表第几步、下一步是什么"；实时追加的任务随之出现在注入段（LLM 感知追加）。
3. **推进**：每轮迭代完成 → `completeStep`（**第二个生产调用点**）；用户/LLM 追加任务 → `updatePlan` append + 重排 order；`advancePlan` 由 loop 迭代边界驱动（当前步 active）。
4. **归档**：会话 content 归档（`SessionArchiver`）扩展为**包含 plan 快照 + roundLog**（关键发现③的缺口）——任务表随会话沉淀为记忆，跨会话可召回（万物皆记忆）。

**接线影响**：`hasPendingPlan` 从恒 false 变真实——多轮任务（含无工具调用纯问答推进）resumable 正确为 true，暂停按钮正确出现。**这是任务表接线最直接的行为修复**。

## 2. 交互语义 · 待定草稿区（评审建议 2，v2 修正）

**待定草稿区 = 独立的可累积多条列表**（非单行输入框），与输入框分离：

| 状态 | 输入去向 | 行为 |
|---|---|---|
| RUNNING | 输入框 → 发送 | **立即注入**：清空输入框，排队到下一轮问答前 |
| PAUSED | 输入框 → 发送 | **追加到草稿区**：不清空输入框，草稿区可自由添加/删除/编辑多条 |
| PAUSED | 点「继续」 | **批量提交**：草稿区内容合并 → `resumeExecution(合并内容)`；空草稿 → `resumeExecution(undefined)` 原路径续跑 |

- 渲染层新组件 `pendingDraftArea`（草稿区列表：每条可删、可编辑、可清空）；输入框在 PAUSED 发送后保留内容（用户可继续追加新草稿，或清空输入框）。
- **与当前代码差异（行为变更点）**：`inputAreaManager` paused 分支从"发送 → emitSendMessage → processEvent → 内核 auto-resume 注入"（阶段 0）改为"发送 → 追加草稿区（不触发 processEvent）"；「继续」→ `SESSION_RESUME` 携带草稿合并内容。
- **分层契约（评审建议 5）**：内核 `processEvent` 的 PAUSED auto-resume **保留**（P4 澄清回答依赖，agent.ts L821 路径是内核 API 契约）；sprite 层改走"留待定 + resumeExecution"是**宿主 UI 策略**——两者并存，互不干扰（sprite 不再走 processEvent 的 PAUSED 分支，P4 回答仍走）。

## 3. 暂停语义统一 · 单一「预约点」模型（评审建议 3）

**统一语义**：暂停 = 在任务表**下一个未推进任务前**打暂停点；loop 推进到该任务时挂起。

| 场景 | 行为 |
|---|---|
| 运行中（任务 N 正在跑）点暂停 | 预约在任务 N+1 前（当前任务完成即命中挂起） |
| 暂停点命中 | loop 迭代边界检测 `getActiveStep()` == pauseBeforeStepId → 挂起 + 清暂停点标记 |
| 点「继续」 | 清暂停点（幂等，无点时 no-op）+ 提交草稿区 → 继续推进 |
| 简单轮（无任务表） | 无暂停按钮（resumable=false 时 hide，只给停止）——"即时申请"是预约点的特例（无任务表时不存在） |

**实现**：checkpoint 增 `pauseBeforeStepId?: string`；`SessionManager` 加 `setPauseBeforeStep(id?)` / `getPauseBeforeStep()`；loop 迭代边界（`handleIteration` 入口，与 `pauseRequested` 检查同位置）命中即等效 requestPause 挂起。

## 5. Phase 2 · 回合折叠 roundLog + 任务表接线（内核为主）

**roundLog（评审建议 4 错峰）**：
- checkpoint 增 `roundLog?: RoundOutcome[]`（cap **挂钩窗口余量**而非固定 8：`roundLogTokens ≤ maxContextTokens × 2%`，即 120K 窗口 ≈ 2.4K tokens，约 10-12 条 × 200 字符）。
- **roundLog 常驻**：每回合确定性折叠（assistant 截断 + 工具计数），随任务表注入段一起注入（LLM 感知已完成回合）。
- **summary 兜底**：`ContextManager` 的 LLM 摘要**仅保留截断时触发**（遗忘补偿）——与 roundLog 错峰，不双份注入：roundLog 负责"进程内回合记忆"，summary 负责"窗口溢出后的早期遗忘补偿"。

**任务表接线（激活死机制）**：
- loop 迭代边界：`advancePlan()` 推进当前步 → 迭代完成 `completeStep()` → 检查 `pauseBeforeStepId` 命中挂起（§3）。
- 上下文组装：注入任务表态 + roundLog 段（显式标注"任务表/历史回合，非当前指令"防误执行）。
- 追加：宿主或 LLM 经新 IPC `SESSION_APPEND_TASK`（chatHandlers）→ `updatePlan` append（第三个生产调用点）。

**内核文件**：types.ts（RoundOutcome / pauseBeforeStepId）/ sessionManager.ts（appendRoundOutcome / getRoundLog / setPauseBeforeStep / appendPlanStep）/ loop.ts（迭代边界 advance/complete/暂停点命中 + 迭代结束折叠）/ 上下文组装处（任务表 + roundLog 注入段）。
**测试**：roundLog 折叠与 cap（挂钩余量）单测 + 预约暂停点命中/取消单测 + plan 接线回归（hasPendingPlan 生效、resumable 正确）。

## 8. 风险与对抗式审查

- **⚠ 任务表接线面大**：plan 从"死机制"变活涉及 loop 迭代边界 + 上下文组装 + hasPendingPlan 回归三处——**最小接线先行**（Phase 1 先只做 updatePlan 首次写入 + 面板只读展示，advance/complete 留 Phase 2），避免一次改爆。
- **⚠ 待定区语义迁移**：PAUSED 发送从 auto-resume 改草稿区是行为变更——须同步更新阶段 0 相关测试/文档（0820d0ae 语义被 sprite 层取代，但内核 auto-resume 保留为 API 契约，勿删）。
- **⚠ 复杂度守恒**：任务表生命周期四环节全部复用 checkpoint/plan/SessionArchiver 管线，**不新增 Manager/存储**；roundLog/pauseBeforeStepId 都是 checkpoint 字段。若发现需新抽象，回退 Phase 2.5（仅 LLM 单句摘要），不做架构扩张。
- **⚠ 注入防误执行**：任务表 + roundLog 注入段须显式标注"状态/历史信息，非当前指令"（防 LLM 当新任务执行）。
- **⚠ 双通道一致性**：任务表 LLM 可见版本与 UI 展示版本须同源（都来自 checkpoint.plan），禁止两处独立维护（并列=腐化）。
- **已知搁置（勿回改）**：RESTORE_CHECKPOINT 断点续跑 UI、独立 WorkLoop 重构。
