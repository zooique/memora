## 1. 任务表模型（概念）

- 任务表 = 以 loop 回合为单位的任务清单：**普通任务**（单轮闭环，默认）/ **难度任务**（单轮演化 loop 任务表逐条推进）。
- 渐进式：单轮问答是基础，loop 是自然叠加；**任务可实时追加**（本轮发现更复杂 → 追加条目）。
- 简单轮无任务表 → 无暂停按钮（resumable 门控天然吻合）。
- **双通道原则**：任务表 = **LLM 可见的上下文**（LLM 可读写状态）+ **用户可操作的 UI**——对标 Claude Code TODO / Cursor plan mode / OpenAI Task。
- **SSOT 铁律**：任务表数据**唯一真理源 = `checkpoint.plan`**；LLM 注入版与 UI 展示版**同源渲染**（见 §1.5 环节 2 的 `renderTaskTable`），禁止任何第二份任务表数据。

## 1.5 任务表生命周期（四环节闭环，SSOT 收口）

1. **生成**：LLM 复杂度判定——composer 补全链输出 `needsLoop: boolean`；`true` 时首次 `updatePlan` 写入（**首个生产调用点**）；简单轮 plan 保持空。
2. **注入（单一渲染函数）**：`renderTaskTable(plan, roundLog)` 导出为**唯一渲染函数**——loop 组装上下文（任务表态 + roundLog 段）与 UI 面板**都调它**，保证注入版与展示版永不漂移（SSOT：一处渲染逻辑）。注入段显式标注"状态/历史信息，非当前指令"防误执行。
3. **推进（单一原子入口）**：`SessionManager.completeRound(stepId, outcome)`——**任务完成的唯一写点**：一次调用 = `plan.status='done'` + roundLog 追加 + heartbeat（原子，杜绝"completeStep 成功但 roundLog 失败"的不一致）。`advancePlan` 由 loop 迭代边界驱动；追加任务 = `updatePlan` append + 重排 order。
4. **归档**：会话 content 归档（`SessionArchiver`）扩展为**包含 plan 快照 + roundLog**（关键发现③缺口）——任务表随会话沉淀为记忆。

**接线影响**：`hasPendingPlan` 从恒 false 变真实——多轮任务（含无工具纯问答推进）resumable 正确为 true，暂停按钮正确出现。

## 2. 交互语义 · 待定草稿区（SSOT：草稿区=唯一真理源）

**待定输入的真理源 = 草稿区列表（渲染层组件）**；输入框只是**编辑暂存**（发送时被消费，自身不是真理源）——主从关系明确，禁止"输入框内容"成为第二份待定数据。

| 状态 | 输入框 → 按钮 | 行为 |
|---|---|---|
| RUNNING | 输入框 → **发送** | 立即注入：清空输入框，排队下一轮问答前 |
| PAUSED | 输入框 → **加入待定**（按钮语义变化，见 §3 文案矩阵） | 追加到草稿区列表（可自由增删/编辑/清空），输入框保留可继续编辑 |
| PAUSED | 草稿区 → **继续** | 批量提交：草稿合并 → `resumeExecution(合并内容)`；空草稿 → `resumeExecution(undefined)` 原路径 |

- **草稿计数反馈**：面板/按钮显示草稿条数徽标，PAUSED 点「加入待定」后立即可见，杜绝"以为发了实际没发"的心智断裂。
- **与当前代码差异（行为变更点）**：`inputAreaManager` paused 分支从"发送 → processEvent → 内核 auto-resume 注入"（阶段 0）改为"发送 → 追加草稿区（不触发 processEvent）"。
- **分层契约**：内核 `processEvent` 的 PAUSED auto-resume **保留**（P4 澄清回答依赖，agent.ts L821 是内核 API 契约）；sprite 改走"留草稿 + resumeExecution"是宿主 UI 策略——双入口并存，互不干扰。

## 3. 暂停语义统一 · 单一入口 + 可反悔（SSOT + 心智对齐）

**暂停唯一入口 = `SESSION_PAUSE`**，内部统一分发（消除"即时暂停 vs 预约点"双机制）：

```
SESSION_PAUSE(reason):
  if 存在未推进任务（plan 有 pending）:
    setPauseBeforeStep(下一 pending 任务 id)   # 预约：当前回合结束即命中挂起
  else:
    requestPause()                            # 无任务表/计划完成：回退即时申请
```

| 场景 | 行为 |
|---|---|
| 运行中（任务 N 正在跑）点暂停 | 预约在下一 pending 任务前（当前回合完成即命中挂起） |
| 任务表某未推进任务前点暂停 | 同一入口参数化：`setPauseBeforeStep(该任务 id)` |
| 暂停点命中 | loop 迭代边界检测 `getActiveStep()` == pauseBeforeStepId → 挂起 + 清标记 |
| 点「继续」 | **清暂停点（幂等）** + **`cancelPauseRequest()`（若申请中）** + 提交草稿区 → 继续推进 |
| 简单轮（无任务表） | 无暂停按钮（resumable=false 时 hide），只给停止 |

- **内核新增 `cancelPauseRequest()`**：清 `loop.pauseRequested`（申请暂停后、回合未结束前点继续 = 反悔取消，必须可用，否则用户被卡"停了停不下来"）。幂等：无申请时 no-op。
- **实现**：checkpoint 增 `pauseBeforeStepId?: string`；`SessionManager` 加 `setPauseBeforeStep(id?)` / `getPauseBeforeStep()`；loop 迭代边界（`handleIteration` 入口，与 `pauseRequested` 检查同位置）命中即挂起。

**按钮四态文案矩阵（心智模型对齐，实施时落 UI）**：

| 状态 | 主按钮 | 副按钮 | 草稿区 |
|---|---|---|---|
| idle | 发送 | — | 隐藏 |
| RUNNING（可续跑） | 暂停（预约） | 停止 | 隐藏 |
| RUNNING（简单轮，resumable=false） | —（hide） | 停止 | 隐藏 |
| PAUSED | **继续**（确认草稿+推进） | 停止 | **可见：草稿列表 + 条数徽标 + 逐条删除** |
| PAUSED 输入后 | 主按钮文案变「**加入待定**」（非发送） | 停止 | 追加计数即时反馈 |
| 暂停申请中（回合未结束） | 继续（=取消申请+反悔） | 停止 | 待定 |

## 4. Phase 1 · 任务表面板（常驻可开合，支持提前打点）

**关键心智修正**：面板**运行中即可见**（常驻可开合，悬浮/侧栏），非"暂停后才弹"——用户必须先看到任务表，才能"在未推进任务前打暂停点"（逻辑顺序：先见 → 后打点）。

**数据源**：`agent.getCheckpoint()`（plan = 任务表）/ `getNextPendingStep()` / `getActiveStep()` / `getMetrics()`。

**改动**：
1. **新 IPC `SESSION_GET_WORK_CONTEXT`**（chatHandlers.ts）：返回 `{ currentGoal, goalVersion, plan, mainGoal, pauseBeforeStepId, draftCount }`。复用 `getCheckpoint()` + 草稿计数（渲染层）。
2. **preload.ts**：`getWorkContext()` + 本地 MAIN_TO_RENDERER_CHANNELS 副本同步（check-ipc 约束）。
3. **渲染层**：`taskTablePanelManager.ts`（**常驻可开合**，类修饰切换，UI 三态约定）——当前目标（+goalVersion 徽标）、任务表（pending/active/done 三色 + 暂停点标记 + 每条前可点「暂停」打点）、roundLog（最近回合，经 `renderTaskTable` 同源渲染）、草稿区（列表 + 计数 + 逐条删除）。
4. **交互**：任意时刻开合面板 → 提前在任务前打暂停点；运行中打点 → 当前回合完成即命中挂起；PAUSED 输入 → 「加入待定」→ 草稿区；「继续」→ 提交草稿 + 续跑。

**文件**：chatHandlers.ts / preload.ts / channels.ts（如需）/ ipcListeners.ts / renderer.ts / ui.ts / inputAreaManager.ts（paused 分支改「加入待定」+ 按钮文案）/ 新 panels/taskTablePanelManager.ts / 新 pendingDraftArea 组件 / CSS（token 化）。
**测试**：IPC 单测 + inputAreaManager paused 分支改测（加入待定、继续提交、反悔取消）+ 面板渲染测试（goal/plan/暂停点/草稿/空态）。

## 5. Phase 2 · 回合折叠 + 任务表接线（内核为主）

- **roundLog**：checkpoint 增 `roundLog?: RoundOutcome[]`（cap 挂钩窗口余量 2% ≈ 10-12 条）；**每回合确定性折叠（assistant 截断 200 字符 + 工具计数）**，经 `completeRound` 原子追加；roundLog **常驻**注入，`ContextManager` LLM 摘要**仅截断时兜底**（错峰，不双份注入）。
- **任务表接线**：loop 迭代边界——`advancePlan()` 推进 → 完成时 `completeRound(stepId, outcome)`（**唯一写点**）→ 检查 `pauseBeforeStepId` 命中挂起（§3）；追加任务 = 新 IPC `SESSION_APPEND_TASK` → `updatePlan` append。
- **内核文件**：types.ts（RoundOutcome / pauseBeforeStepId）/ sessionManager.ts（completeRound / appendRoundOutcome / getRoundLog / setPauseBeforeStep / appendPlanStep）/ loop.ts（迭代边界 advance/complete/暂停点命中 + 折叠）/ agent.ts（cancelPauseRequest 委托）/ 上下文组装处（`renderTaskTable` 注入段）。
- **测试**：completeRound 原子性单测（plan+roundLog 同写、失败回滚）+ roundLog cap 单测 + 预约暂停点命中/取消/反悔单测 + plan 接线回归（hasPendingPlan 生效、resumable 正确）。

## 6. Phase 3 · 暂停=策展（记忆入口）

- **文件**：agent.ts（若未暴露）/ sessionArchiver.ts（payload 扩展）/ chatHandlers.ts（新 IPC SESSION_ARCHIVE）/ preload / 面板按钮。

## 8. 风险与对抗式审查

- **⚠ 任务表接线面大**：plan 从死机制变活涉及 loop 边界 + 上下文组装 + hasPendingPlan 回归三处——**最小接线先行**（Phase 1 先只做 updatePlan 首次写入 + 面板只读展示，advance/complete 留 Phase 2）。
- **⚠ 待定区语义迁移**：PAUSED 发送从 auto-resume 改「加入待定」是行为变更——同步更新阶段 0 测试/文档（内核 auto-resume 保留为 API 契约勿删）。
- **⚠ SESSION_PAUSE 统一是行为变更**：现有"即时 requestPause"将变为"预约优先 + 回退即时"——软暂停测试断言（requestPause 直接调用）需同步更新为 setPauseBeforeStep/回退分支断言。
- **⚠ 复杂度守恒**：生命周期四环节全部复用 checkpoint/plan/SessionArchiver 管线，**不新增 Manager/存储**；completeRound/renderTaskTable 是收口非新抽象。若发现需新抽象，回退 Phase 2.5（仅 LLM 单句摘要）。
- **⚠ 双通道一致性**：注入版与 UI 版必须同源 `renderTaskTable`，禁止两处独立渲染（并列=腐化）。
- **已知搁置（勿回改）**：RESTORE_CHECKPOINT 断点续跑 UI、独立 WorkLoop 重构。

## 9. 执行顺序建议

§1.5 任务表生成/注入最小闭环（激活 plan + renderTaskTable）→ Phase 1 面板 + 草稿区 + 按钮文案（含 SESSION_PAUSE 统一 + cancelPauseRequest）→ Phase 2 completeRound + 暂停点 + 推进接线 → Phase 3 归档扩展。每阶段独立提交（PowerShell，LEFTHOOK=0 门已验），不打 tag、推送由用户指示。
