## 一、问题

### 1.1 核心矛盾

```
Memora Agent 能"谈论"小说，但不能"生产"小说
→ 因为 Agent 只有 4 个内置工具（read_file / write_file / list_dir / search_memories）
→ 没有小说领域的工具（创建章节 / 追加正文 / 角色卡片 / 大纲管理）
→ 而且没有工具注册机制——宿主项目无法扩展工具集
```

### 1.2 根因

`ToolExecutor` 的 `execute()` 方法用 `switch(name)` 硬编码了 4 个工具，`default`
分支直接抛错：

```typescript
default:
  throw toolError('未知工具', `agent 调用了未注册的工具：${name}`, [
    `已注册工具：${BUILTIN_TOOLS.map((t) => t.name).join(', ')}`,
  ]);
```

**没有扩展点**。宿主项目无法注册 `create_chapter` 等领域工具。

### 1.3 职能边界原则

| 职能                       | 核心库 | 宿主项目 |
| -------------------------- | :----: | :------: |
| LLM 对话 + 记忆 + 安全     |   ✅   |    —     |
| 通用文件 I/O（4 工具）     |   ✅   |    —     |
| **工具注册机制**           |   ✅   |    —     |
| 领域工具（章节/角色/代码） |   —    |    ✅    |
| UI 界面                    |   —    |    ✅    |

## 二、方案设计

### 2.1 核心：工具注册 API

```typescript
// src/agent/tool-executor.ts 新增

export type ToolHandler = (args: Record<string, unknown>) => Promise<string>;

export interface CustomToolEntry {
  definition: ToolDefinition;
  handler: ToolHandler;
}

export class ToolExecutor {
  private readonly customTools = new Map<string, CustomToolEntry>();

  /**
   * 注册自定义工具
   *
   * 宿主项目在 agent.init() 后调用，注册领域工具。
   * 工具名不能与内置工具重复。
   */
  registerTool(definition: ToolDefinition, handler: ToolHandler): void {
    if (BUILTIN_TOOLS.some((t) => t.name === definition.name)) {
      throw new Error(`不能覆盖内置工具：${definition.name}`);
    }
    if (this.customTools.has(definition.name)) {
      throw new Error(`工具已注册：${definition.name}`);
    }
    this.customTools.set(definition.name, { definition, handler });
  }

  /**
   * 获取所有工具定义（内置 + 自定义）
   */
  getToolDefinitions(): ToolDefinition[] {
    return [
      ...BUILTIN_TOOLS,
      ...[...this.customTools.values()].map((e) => e.definition),
    ];
  }
}
```

**execute() 修改**：

```typescript
// 当前：
switch (name) {
  case 'read_file': ...
  case 'write_file': ...
  case 'list_dir': ...
  case 'search_memories': ...
  default: throw toolError('未知工具', ...);
}

// 优化后：
switch (name) {
  case 'read_file': ...
  case 'write_file': ...
  case 'list_dir': ...
  case 'search_memories': ...
  default: {
    const custom = this.customTools.get(name);
    if (custom) {
      return custom.handler(args);
    }
    throw toolError('未知工具', `agent 调用了未注册的工具：${name}`, [
      `已注册工具：${this.getToolDefinitions().map((t) => t.name).join(', ')}`,
    ]);
  }
}
```

### 2.2 Agent 层暴露

```typescript
// src/agent/agent.ts 新增

class Agent {
  /**
   * 注册自定义工具
   *
   * 必须在 init() 之后调用（因为 ToolExecutor 在 init 时创建）。
   * 注册后，下一轮 chat() 时 LLM 将看到该工具的定义。
   */
  registerTool(definition: ToolDefinition, handler: ToolHandler): void {
    if (!this._toolExecutor) {
      throw configError('Agent 尚未初始化', '请先调用 agent.init()');
    }
    this._toolExecutor.registerTool(definition, handler);
  }

  /**
   * 获取所有工具定义（内置 + 自定义）
   */
  getToolDefinitions(): ToolDefinition[] {
    return this._toolExecutor?.getToolDefinitions() ?? [...BUILTIN_TOOLS];
  }
}
```

### 2.3 Loop 层适配

当前 `AgentLoop` 的 system prompt 中没有注入工具描述——LLM 通过 OpenAI function
calling 的 `tools` 参数获取工具列表。

**检查**：`provider.chat()` 的调用方式。

```typescript
// loop.ts:67
for await (const chunk of this.opts.provider.chat(this.messages)) {
```

**问题**：当前 `chat()` 没有传 `tools`
参数——LLM 是通过 personality.md 中的工具描述来决定调用哪个工具的。

**两种路径**：

| 路径                       | 做法                                 | 优点                        | 缺点                        |
| -------------------------- | ------------------------------------ | --------------------------- | --------------------------- |
| A：OpenAI function calling | `provider.chat(messages, { tools })` | LLM 原生支持，格式严格      | 需要改 provider 接口        |
| B：personality 注入        | 在 system prompt 中追加工具描述      | 不改 provider，兼容所有 LLM | 格式不严格，依赖 LLM 理解力 |

**选择路径 B**——与当前架构一致（personality.md 中已有工具使用说明），不改 provider 接口。

**实现**：`AgentLoop` 构造时接收 `toolDefinitions: ToolDefinition[]`，在
`buildSystemPrompt()` 末尾追加工具描述：

```typescript
private buildSystemPrompt(memories: Memory[]): string {
  const sections = memories.map((m) => `## ${m.name}\n\n${m.content}`).join('\n\n---\n\n');
  const toolSection = this.buildToolSection();
  return `# Memora Agent\n\n${sections}\n\n---\n\n${toolSection}\n\n你是 Memora Agent。基于以上人格、规则和领域知识，回应用户的问题。`;
}

private buildToolSection(): string {
  const tools = this.opts.toolDefinitions ?? BUILTIN_TOOLS;
  if (tools.length === 0) return '';
  const lines = tools.map((t) => {
    const params = Object.entries(t.parameters.properties)
      .map(([k, v]) => `    - ${k} (${v.type}): ${v.description}`)
      .join('\n');
    const required = t.parameters.required.join(', ');
    return `- ${t.name}: ${t.description}\n  参数：\n${params}\n  必填：${required}`;
  });
  return `## 可用工具\n\n${lines.join('\n\n')}\n\n调用工具时，输出 JSON 格式：{"tool_calls":[{"name":"...","arguments":{...}}]}`;
}
```

      name: 'update_character',

### 3.2 工具实现策略

**关键决策**：小说工具的 handler 内部**不直接操作文件系统**，而是委托给
`write_file` / `read_file` / `list_dir` 的逻辑。

**原因**：

1. 复用路径白名单校验（SecurityGuard）
2. 复用写入确认机制（WriteExtensions）
3. 避免绕过安全层

**实现方式**：工具 handler 通过 `ToolExecutor.execute()` 间接调用内置工具：

```typescript
// 方案 A：handler 直接调 ToolExecutor（需要传入引用）
agent.registerTool(definition, async (args) => {
  // 通过 agent 内部的 toolExecutor 调用 write_file
  const result = await agent.executeTool(
    'write_file',
    JSON.stringify({ path, content }),
  );
  return result;
});

// 方案 B：handler 自行实现（绕过安全层）—— ❌ 不推荐
agent.registerTool(definition, async (args) => {
  await fs.writeFile(path, content); // 绕过了 SecurityGuard！
  return 'ok';
});
```

**选择方案 A**——新增 `agent.executeTool(name, argsJson)`
方法，让自定义工具能安全地委托内置工具：

```typescript
// src/agent/agent.ts 新增
async executeTool(name: string, argsJson: string): Promise<string> {
  if (!this._toolExecutor) throw configError('Agent 尚未初始化', '请先调用 agent.init()');
  return this._toolExecutor.execute(name, argsJson);
}
```

| 设计原则          | 一致性                                                      |
