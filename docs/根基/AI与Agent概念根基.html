01 · 概念层级

先纠正一个边界：AI ≠ 大模型

AI 是学科（含符号主义、机器学习、强化学习等多种范式）；大模型（LLM）只是它当前的主流实现之一。Agent 更不是层级里的一层——它是包在大模型外部的控制系统。

LLM 的三个本质性质（Agent 存在的第一性原因）

  1. 无状态——每次调用独立，不记住任何历史（→ 需要 Agent 补记忆）
  2. 只出符号——只生成 token（多模态时代含图像/音频 token），不执行任何动作（→ 需要 Agent 补手脚）
  3. 知识冻结——训练时快照，存在幻觉风险（→ 需要 Agent 补约束与检索）

02 · 五个命题的审查结论

萧然的原始理解逐条对抗式审查
命题判定说明
① 大模型是核心✅ 成立Agent 架构下 LLM 是唯一推理核；但「AI = 大模型」需修正——AI 是学科，大模型是其中一种实现
② 核心交互是最简单的一问一答✅ 成立API 层面即「输入文本 → 输出文本」；内部机制是 next-token 预测，一问一答只是外在形态
③ Agent 基于这个模式开发✅ 成立Agent 不是另起炉灶，是把「一问一答」包进循环里反复调用
④ 交互是文本形式✅ 基本成立本质是 token 序列；工具调用走结构化 JSON 协议；多模态时代不限于纯文本
⑤ 解析文本、作出行为都是 Agent 职责⚠️ 方向对，顺序错「解析」只是 Agent 职责的一小块；真实结构是循环，不是「输入→解析→行为」的直线
关键修正：LLM 输出不只是「答案」，它输出的是「行动意图」（tool_call）。Agent 解析意图 → 执行 → 把结果作为新输入喂回 LLM → LLM 继续问答。不是「一问一答」结束后解析，而是「问答」嵌在循环的每一跳里。

03 · Agent 循环结构与职责边界

把「问→答」变成「感知→思考→行动→观察」闭环
职责谁干为什么
推理（输入变输出）LLM模型的天职
状态（历史/目标/记忆）AgentLLM 无状态，每次调用都是「失忆的」
动作解析 / 契约解析（tool_call JSON → 工具调用）AgentLLM 输出的是文本/JSON 意图，不会自己动。解析对象 = LLM 的输出（tool_call），执行者 = Agent；与《输入管道与触发链架构》的「输入解析/意图解析」（解析对象 = 用户输入，执行者 = LLM）区分
执行（调工具/写文件/发请求）AgentLLM 不接触外部世界
循环（回填结果/决定继续）AgentLLM 只答一次，Agent 决定要不要再问一轮

04 · 工具调用的真实链路（对抗式修正）

澄清误区：LLM 从不直接调用外部世界
上一版图把「LLM → 外部世界」画成了直接箭头，这是误导。真相：LLM 只能输出 token；工具调用（function calling）本质是 LLM 输出一段结构化 JSON 文本（工具名 + 参数），这段 JSON 是「写给 Agent 看的指令」，真正执行的是 Agent 代码。

为什么会有「LLM 直接调用工具」的错觉

主流框架（OpenAI function calling、Claude tool use 等）在开发者 API 层做了封装：你写 llm.chat(..., tools=[...])，框架自动完成「解析 tool_call → 执行 → 回填」三步。所以框架用户看起来像「LLM 自己调了工具」，但拆开看：

  • LLM 的输出永远是 token，无论它「看起来」在调工具
  • tool_call JSON 是 LLM 与 Agent 之间的结构化契约——LLM 通过它表达意图，Agent 通过它执行动作
  • 契约断了（JSON 不符合 schema）Agent 就解析不了——是契约断裂，不是 LLM 坏了；解析失败走降级/重试，不视为系统故障（降级优先）

05 · 一句话心智模型

大模型 = 无状态的问答核（只读 token、只出 token）
Agent = 给它装上记忆、手脚和循环的控制系统

与 memora 的联系

memora 项目规则里的核心矛盾——「无状态推理 ←→ 连续演化任务」正是这个概念在工程上的投影：

  • 无状态推理 = 大模型的一问一答
  • 连续演化任务 = 用户期望 Agent 像有记忆、能持续干活的实体
  • memora 的解法 = 万物皆记忆——用记忆给无状态的问答补上状态，让每一次「问→答」都站在上一次的积累上继续演化

与体系文档的关系（桥接）

本文的 Agent 四职责与《道生万物输入框架》四元组（角色 × 任务 × 标准 × 资源）分属两个视角，映射如下：

  • 状态 ↔ 资源维度 + 记忆回流：Agent 维护的状态（历史/目标/记忆）沉淀为四元组的「资源」，并随「复归于道」回流为下一轮资源（见《道生万物输入框架》「记忆覆盖四元组全集」）
  • 动作解析 / 契约解析 ↔ 四元组的「任务」生成：LLM 输出 tool_call（意图）→ Agent 解析为动作；而用户输入 → 四元组骨架由 LLM 完成（「输入解析」，见《输入管道与触发链架构》§03 触发链）
  • 执行 / 循环 ↔ 动作维度与触发链/分级路径：Agent 执行动作、决定继续与否，对应《输入管道与触发链架构》的触发链与《不中断工作模型演进》的执行循环
