## 一句话定论

**不中断不是新功能，是把大厂已实现的能力显式化**——不中断原则作用于 **loop 任务内**；memora 的增量 = 在既有 loop 能力之上，增加显式的「暂停（申请暂停）」与「继续」按钮。

## 1. 大厂已有的（现象观察）

- loop 本质 = 一串问答回合的编排，回合之间存在**间隙**。
- 大厂（Trae / WorkBuddy 等）在这个间隙里已实现：
  1. **Agent 侧**：收集问题主动弹窗提问（这是 loop 的问答回合切换间隙，不是真正的"暂停问答"，而是**暂停 loop 的回合间隙**）；
  2. **用户侧**：直接输入内容（此时停止按钮变为发送），输入进入**待输入形态**，**等 loop 最近一轮任务结束后自然衔接进去**。
- 即：**隐式的"暂停 + 继续"大厂已经有了**——用户靠"直接输入文本"隐式表达插入，无需任何按钮。

## 2. 大厂没做的

- 用户**主动的、显式的控制权**：暂停按钮、继续按钮。
- 原因：单轮即答时暂停是伪需求；显式按钮徒增心智负担，故被隐藏。

## 3. memora 的增量 = 把控制权显式化

| 能力 | 语义 | 内核落地 API |
|---|---|---|
| **暂停** | **申请暂停**：提交申请后，**等进行中的问答回合自然结束**，才于 loop 迭代边界挂起（messages 保留，可续跑）——软暂停，非霸道中止 | `requestPause(reason?, by?)` → loop 置 `pauseRequested` → 边界挂起 + `return` + `{type:'paused'}` chunk |
| **继续（空输入）** | 直接继续原路径：`resumeExecution()` 续驱 loop，热窗口在内存 | `resumeExecution(input?, signal?)` → `loop.continueAfterPause` |
| **继续（注入）** | 携带补充输入 = 自动恢复 + 融合继续（等效大厂"待输入→下轮衔接"的显式化） | `resumeExecution(input)` |
| **可续跑信号** | 暂停态优先 true；否则 `isInAutonomousStep \|\| hasPendingPlan`——宿主据此决定暂停按钮显隐，**简单轮（无续跑可能）只给停止** | `canContinueWithoutInput()` |
| **硬停止** | **唯一霸道中止路径**：杀生成器、不可续跑 | `signal.abort` |

## 4. 已落地实现映射（2026-08-08 软暂停 v2.1，提交 a8780a78）

- **内核 `src/agent/`**：`loop.ts`（`requestPause`/`continueAfterPause`/`isInAutonomousStep`）、`agent.ts`（`requestPause`/`resumeExecution`/`canContinueWithoutInput`）、`types.ts`（`AgentChunk` 增 `{type:'paused'}`）。
- **Sprite 接线 `hosts/memora-sprite/src/`**：`chatHandlers.ts`（`SESSION_PAUSE → agent.requestPause`；`SESSION_RESUME → handleResume`）、`chatStreamHandler.ts`（抽离 `forwardStream` 共用转发 + `handleResume`）、`preload`/`ipcListeners`/`renderer`/`ui`（透传 `resumable` 信号）、`inputAreaManager.ts`（仅当 `resumable && streaming` 显暂停按钮，简单轮 `hide` 只显停止；`paused` 显继续）。

## 5. 机制张力（诚实记录，待决策）

- **定论**：申请暂停 = 等进行中的回合自然结束才挂起（纯软语义）。
- **现状**：sprite 层 `SESSION_PAUSE` 当前实现为**先 `abort` 中断流式、再 `requestPause`**（2026-08-08 上午定"暂停=中断流式，对标 Claude interrupt"，提交 e2f906f8）——与定论不完全一致。
- **待决策**：把 sprite 层改为"纯申请暂停、等回合自然结束"，还是保留"立即中断"作为 UI 层实现细节。

## 6. 后续迭代（待排优先级）

- **Phase 1 · 暂停查看面板**（低风险高感知）：暂停按钮接「查看工作上下文」（当前 plan / progress / 上一回合），直接验证显式暂停的价值假设。
- **Phase 2 · 回合折叠 round-folding**（核心）：替代「蓄满一次性压缩」——每回合完成把 outcome（非原文）折入已有 `planList`/`goalVersion` 进度追踪器 + 高价值回合即时 promote insight（接 `InsightExtractor` 触发点到 loop 回合完成）。复用现有管线，不新造 compressor。
- **Phase 3 · 暂停=策展**：暂停点给「存进度到记忆」入口，汇合 Phase 1 + 2。
- **已搁置**：`RESTORE_CHECKPOINT` 断点续跑 UI、独立 WorkLoop 重构（伪需求判定，勿回改）。
