- 「双向暂停 + 断点续跑 + 常驻会话」范式契合 memora 核心矛盾「无状态推理 ←→ 连续演化任务」。

### 技术硬伤（代码层实证，共 6 处）

1. **锁机制自相矛盾**：`agentSelfPause()`（§6.1）直接 load+save **无锁**，违反自述「所有状态修改先获取锁」；乐观锁失败返回值被全部调用点（心跳、标记步骤完成、目标更新）**忽略**，写入静默丢失。
2. **锁必然过期**：锁 TTL 5000ms < 单原子步骤上限 10s（§4.1 风险2）——步骤执行期间锁已过期，竞态保护失效，且无续期机制。
3. **恢复执行时序窗口**：`setImmediate(runTaskLoop)` 在 finally 释放锁之前调度，锁释放后循环才真正读检查点——用户此时再暂停则恢复指令被静默吞掉，无重试。
4. **超时悬挂副作用**：`Promise.race` 超时后 `executeSingleStep` 内部工具调用**无法取消**（Node 无通用取消机制），副作用已发生但任务标记异常；幂等键兜不住「工具本身非幂等」场景。
5. **热截断数字不一致**：`maxHotMessages`=20 / `getTaskStatus` 返回 slice(-30) 与 slice(-20) / §8 表「10 条工具记录」——四处不齐。
6. **事件溯源只说不做**：风险4 声称改「事件溯源 + 定期快照」，但 §5 类型定义只有单一 `AgentCheckpoint`，无任何事件/增量结构——该规避方案无法落地。

## 1. 项目概述与核心定义
### 1.1 背景
当前主流企业级 Agent 均为「单轮指令触发 + 内部循环执行」的增强问答模式，用户侧交互本质仍是一次性问答闭环。长任务场景下存在黑盒感强、中途干预成本高、需求对齐滞后等核心痛点。

### 1.2 核心设计规则
本方案将 Agent 会话生命周期从「单次请求-响应闭环」升级为「持久化任务会话」，以「暂停态」替代「终止态」，核心规则如下：
1. 任务一经创建永久存续，仅存在 `RUNNING`（运行中）与 `PAUSED`（已暂停）两种状态，无销毁/终止态
2. 暂停权限双向开放：用户可手动暂停，Agent 遇到信息缺失、高风险操作、任务完成时可主动暂停
3. 暂停时完整保存执行检查点，恢复后从断点续跑，无需重复执行已完成步骤
4. 暂停态支持用户注入澄清信息、修正目标、新增约束，恢复后自动触发重规划
5. 任务完成后 Agent 主动暂停并询问后续需求，无操作时进入休眠常驻，零算力消耗

## 2. 新旧交互范式横向对比
| 对比维度 | 传统问答式 Agent | 双向暂停常驻 Agent |
|---------|------------------|--------------------|
| 会话生命周期 | 单次问答闭环，结束即销毁上下文 | 持久任务会话，状态永久留存 |
| 核心状态 | 空闲、执行、已结束 | RUNNING / PAUSED |
| 暂停发起方 | 仅用户可终止，无暂停概念 | 用户、Agent 双向均可触发 |
| 中途干预 | 终止任务后重新下发完整指令 | 断点暂停，补充信息后续跑 |
| 用户心智 | 一次性说清需求，等待最终结果 | 人机协同推进，中途动态对齐 |
| 算力模型 | 单次请求对应一次算力消耗 | 运行态消耗算力，暂停态仅存储开销 |
| 风险特征 | 单次任务风险可控，上下文隔离 | 常驻会话权限持续，需额外合规管控 |

## 4. 全链路风险排查与规避方案
### 4.1 架构与工程实现类风险
#### 风险1：并发修改导致状态竞态损坏
**问题描述**：用户同时触发暂停与恢复、或前端重复点击按钮，多个请求并发修改同一任务状态，导致检查点数据覆盖、状态错乱（如任务实际在运行但标记为暂停）。
**规避方案**：
- 引入 Redis 分布式锁，以 `taskId` 为锁粒度，所有状态修改操作必须先获取锁，执行完成后释放
- 采用乐观锁机制，检查点中增加 `version` 版本号，每次更新时校验版本，不一致则拒绝修改
- 前端做按钮防抖，同一操作 1s 内仅允许触发一次

#### 风险2：长原子步骤导致暂停响应延迟
**问题描述**：若单个执行步骤耗时较长（如批量数据导入、大文件处理），用户点击暂停后需等待步骤结束才会响应，用户会误以为暂停失效，体验严重下降。
**规避方案**：
- 强制约束单原子步骤最大执行时长不超过 10s，超长任务必须拆分为多个可中断子步骤
- 长耗时工具内部增加中断检查点，每处理一个批次（如每 100 条数据）检查一次暂停信号
- 前端点击暂停后给出「正在安全暂停中...」的状态提示，明确告知用户当前步骤结束后会暂停

#### 风险3：异常崩溃导致任务僵尸化
**问题描述**：执行过程中进程崩溃、LLM 超时、工具调用异常，任务状态会卡在 `RUNNING`，无法自动恢复，也无法被用户暂停，变成僵尸任务。
**规避方案**：
- 引入心跳机制：运行中任务每完成一个原子步骤更新一次心跳，超过 30s 无心跳的任务自动标记为异常并暂停
- 全链路异常捕获：任务循环外层包裹 try-catch，任何未处理异常均触发自动暂停，并记录异常原因
- 增加任务巡检脚本，定时扫描异常任务，触发告警并支持手动重置状态

#### 风险4：检查点持续膨胀导致性能下降
**问题描述**：长周期任务的聊天记录、工具历史、执行日志持续累积，检查点体积可达数十 MB，序列化/反序列化与 Redis 读写开销急剧上升。
**规避方案**：
- 热记忆截断：检查点中仅保留最近 20 条对话与 10 条工具记录，更早数据自动归档至冷存储
- 增量存储：不再全量保存检查点，改为事件溯源模式，仅记录每次状态变更的增量事件
- 定期快照：每执行 50 个步骤生成一次全量快照，中间通过增量事件还原，兼顾加载速度与存储成本

#### 风险5：单实例任务循环阻塞
**问题描述**：单 Node.js 实例内同步 while 循环执行任务，多任务并发时会阻塞事件循环，导致 API 响应变慢、暂停信号无法及时处理。
**规避方案**：
- 采用任务队列架构（如 BullMQ），任务执行交给独立 Worker 进程，与 API 服务物理隔离
- 每个原子步骤执行后释放事件循环，使用 `setImmediate` 调度下一步，避免阻塞主线程
- 支持多 Worker 水平扩展，不同任务分发到不同 Worker 执行，互不干扰

### 4.2 LLM 与业务逻辑类风险
#### 风险6：多次重规划导致目标漂移
**问题描述**：用户多次中途修改需求，每次恢复都触发重规划，LLM 会逐渐偏离初始核心目标，出现执行路径前后矛盾、遗漏原始需求的情况。
**规避方案**：
- 每次重规划前强制注入「原始核心目标」作为顶层约束，重规划结果必须与原始目标做一致性校验
- 设置目标变更阈值：若新需求与原始目标偏差超过 70%，主动提示用户「该变更属于新任务，建议创建新会话」
- 保留完整目标变更链路，执行步骤与对应目标版本绑定，支持回溯

#### 风险7：Agent 频繁主动暂停，反而增加用户负担
**问题描述**：LLM 过度谨慎，遇到轻微不确定就触发暂停询问用户，导致用户频繁被打断，体验不如传统一问一答模式。
**规避方案**：
- 设置暂停置信度阈值：仅当信息缺失导致下一步完全无法推进、或操作涉及高风险（如写入生产库、发送外部通知）时才允许暂停
- 限制单轮执行暂停次数：连续 2 次暂停后必须输出可执行方案，禁止无限追问
- 低风险决策允许 Agent 自行兜底，事后在日志中标注「已按默认方案处理，如有异议可暂停修正」

#### 风险8：用户输入歧义导致上下文污染
**问题描述**：暂停态用户输入闲聊、吐槽、模糊评价（如「刚才做的不好」），LLM 无法准确对应到具体步骤，错误解读为任务指令，导致执行跑偏。
**规避方案**：
- 暂停态输入增加意图识别：区分「任务修正」「问题咨询」「闲聊」，仅任务修正类内容注入执行上下文
- 模糊输入主动澄清：若识别到用户反馈无明确指向，回复时列出最近 3 个执行步骤，让用户明确指出修正点
- 闲聊内容单独存放，不混入任务执行上下文

### 4.3 产品与用户心智类风险
#### 风险9：「暂停≠结束」认知偏差
**问题描述**：用户受传统聊天软件心智影响，关闭页面误以为任务停止，或误以为暂停就是任务结束，导致后台任务持续运行消耗资源，或长期闲置占用存储。
**规避方案**：
- 状态强提示：运行态页面顶部常驻醒目状态条，关闭页面前弹窗提示「任务仍在运行，是否暂停？」
- 自动休眠机制：连续 7 天无任何操作的任务自动进入深度休眠，再次访问时需手动唤醒
- 闲置通知：任务暂停超过 3 天未操作，发送通知提醒用户，确认是否继续或归档

#### 风险10：多任务并行管理混乱
**问题描述**：用户同时创建多个常驻任务，无法快速区分各任务状态与进度，管理成本急剧上升。
**规避方案**：
- 任务列表页统一展示所有任务的状态、最后活跃时间、核心目标摘要
- 支持任务分组、标签、置顶，重要任务单独标识
- 同一时间仅允许一个任务处于运行态，避免算力争抢与注意力分散

### 4.4 企业级合规与安全类风险
#### 风险11：常驻会话权限放大风险
**问题描述**：传统单次会话结束后权限即失效，常驻任务会持续保留工具调用权限，账号被盗用后风险远高于单次会话。
**规避方案**：
- 高风险工具操作每次执行前必须二次鉴权，不可因任务常驻而豁免
- 任务权限与用户账号权限实时绑定，用户权限变更后同步限制任务操作范围
- 支持设置任务有效期，到期后自动冻结高风险操作权限，仅保留查看权限

#### 风险12：数据留存合规风险
**问题描述**：任务永久存续，所有对话、执行记录、业务数据长期留存，不符合数据最小化原则与 GDPR 等法规的被遗忘权要求。
**规避方案**：
- 分级存储策略：热数据保留 30 天，冷数据归档保留 180 天，超期自动删除
- 提供任务彻底删除功能，删除后所有关联数据不可逆清除
- 审计日志单独留存，满足合规审计要求，与业务数据生命周期隔离

#### 风险13：操作溯源能力缺失
**问题描述**：双向暂停模式下，用户、Agent 均可触发状态变更，出问题后无法追溯是谁修改了需求、谁触发了暂停、哪一步出的错。
**规避方案**：
- 全操作审计日志：所有状态变更、指令输入、工具调用均记录操作人、时间、操作内容
- 支持操作回放：可回溯任务任意时间点的状态与执行内容
- 关键操作（如修改核心目标、调用高风险工具）强制留痕，不可删除篡改

```typescript
import { v4 as uuidv4 } from "uuid";
import {
  AgentCheckpoint,
  AgentTaskStatus,
  PauseTriggerSource,
  ChatMessage,
  AgentEngineConfig,
} from "./types";
import { LLMService } from "./services/LLMService";
import { ToolExecutor } from "./services/ToolExecutor";
import { AuditLogger } from "./services/AuditLogger";

export class PersistentAgentEngine {
  private readonly redis: Redis;
  private readonly llmService: LLMService;
  private readonly toolExecutor: ToolExecutor;
  private readonly auditLogger: AuditLogger;
  private readonly config: Required<AgentEngineConfig>;
  private readonly lockPrefix = "agent:lock:";
  private readonly checkpointPrefix = "agent:checkpoint:";

  constructor(config: AgentEngineConfig) {
    this.redis = new Redis(config.redisUrl);
    this.llmService = new LLMService(config.llmBaseUrl, config.llmApiKey);
    this.toolExecutor = new ToolExecutor(this.redis);
    this.auditLogger = new AuditLogger(this.redis);
    this.config = {
      maxHotMessages: 20,
      stepTimeoutMs: 30000,
      heartbeatTimeoutMs: 30000,
      ...config,
    };
  }

  /** 获取分布式锁 */
  private async acquireLock(taskId: string): Promise<boolean> {
    const result = await this.redis.set(
      `${this.lockPrefix}${taskId}`,
      "1",
      "NX",
      "PX",
      5000
    );
    return result === "OK";
  }

  /** 释放分布式锁 */
  private async releaseLock(taskId: string) {
    await this.redis.del(`${this.lockPrefix}${taskId}`);
  }

  /** 创建常驻任务 */
  public async createTask(initGoal: string, operator: string): Promise<string> {
    const taskId = uuidv4();
    const checkpoint: AgentCheckpoint = {
      taskId,
      version: 1,
      status: AgentTaskStatus.PAUSED,
      mainGoal: initGoal,
      currentGoal: initGoal,
      goalVersion: 1,
      planList: [],
      chatHistory: [],
      toolHistory: [],
      hotMemory: "",
      lastHeartbeat: Date.now(),
      createdAt: Date.now(),
      lastModified: Date.now(),
    };

    await this.saveCheckpoint(checkpoint);
    await this.auditLogger.log(taskId, operator, "create_task", `创建任务，目标：${initGoal}`);
    return taskId;
  }

  /** 保存检查点（带乐观锁校验） */
  private async saveCheckpoint(cp: AgentCheckpoint): Promise<boolean> {
    const key = `${this.checkpointPrefix}${cp.taskId}`;
    const existing = await this.redis.get(key);
    
    if (existing) {
      const oldCp = JSON.parse(existing) as AgentCheckpoint;
      if (oldCp.version !== cp.version - 1) {
        return false; // 版本冲突，保存失败
      }
    }

    cp.lastModified = Date.now();
    await this.redis.set(key, JSON.stringify(cp));
    return true;
  }

  /** 加载检查点 */
  public async loadCheckpoint(taskId: string): Promise<AgentCheckpoint> {
    const raw = await this.redis.get(`${this.checkpointPrefix}${taskId}`);
    if (!raw) throw new Error("任务不存在");
    return JSON.parse(raw) as AgentCheckpoint;
  }

  /** 用户手动暂停 */
  public async userPause(taskId: string, operator: string, reason?: string): Promise<boolean> {
    const lock = await this.acquireLock(taskId);
    if (!lock) return false;

    try {
      const cp = await this.loadCheckpoint(taskId);
      if (cp.status === AgentTaskStatus.PAUSED) return true;

      cp.status = AgentTaskStatus.PAUSED;
      cp.pauseSource = PauseTriggerSource.USER;
      cp.pauseReason = reason ?? "用户手动暂停";
      cp.version++;

      const success = await this.saveCheckpoint(cp);
      if (success) {
        await this.auditLogger.log(taskId, operator, "user_pause", reason ?? "手动暂停");
      }
      return success;
    } finally {
      await this.releaseLock(taskId);
    }
  }

  /** Agent 主动暂停 */
  private async agentSelfPause(taskId: string, reason: string): Promise<boolean> {
    const cp = await this.loadCheckpoint(taskId);
    cp.status = AgentTaskStatus.PAUSED;
    cp.pauseSource = PauseTriggerSource.AGENT;
    cp.pauseReason = reason;
    cp.version++;

    const success = await this.saveCheckpoint(cp);
    if (success) {
      await this.auditLogger.log(taskId, "agent", "agent_pause", reason);
    }
    return success;
  }

  /** 暂停后注入用户输入并恢复执行 */
  public async resumeWithInput(taskId: string, operator: string, userInput: string): Promise<boolean> {
    const lock = await this.acquireLock(taskId);
    if (!lock) return false;

    try {
      const cp = await this.loadCheckpoint(taskId);
      if (cp.status !== AgentTaskStatus.PAUSED) return false;

      // 意图识别：区分任务指令与闲聊
      const intent = await this.llmService.classifyIntent(userInput);
      const message: ChatMessage = {
        id: uuidv4(),
        role: "user",
        content: userInput,
        type: intent,
        createdAt: Date.now(),
      };
      cp.chatHistory.push(message);

      // 仅任务类指令更新目标并触发运行
      if (intent === "task") {
        cp.currentGoal = userInput;
        cp.goalVersion++;
        cp.status = AgentTaskStatus.RUNNING;
        cp.version++;

        await this.saveCheckpoint(cp);
        await this.auditLogger.log(taskId, operator, "resume_task", `输入指令：${userInput}`);
        
        // 异步启动任务循环，不阻塞接口
        setImmediate(() => this.runTaskLoop(taskId));
      } else {
        cp.version++;
        await this.saveCheckpoint(cp);
        // 非任务类输入直接生成回复并保持暂停态
        await this.generateClarifyReply(taskId, userInput);
      }

      return true;
    } finally {
      await this.releaseLock(taskId);
    }
  }

  /** 核心任务执行循环 */
  private async runTaskLoop(taskId: string) {
    while (true) {
      try {
        const cp = await this.loadCheckpoint(taskId);
        if (cp.status === AgentTaskStatus.PAUSED) break;

        // 更新心跳
        cp.lastHeartbeat = Date.now();
        cp.version++;
        await this.saveCheckpoint(cp);

        // 1. 动态重规划
        await this.rebuildPlan(cp);

        // 2. 获取下一步
        const nextStep = cp.planList.find((s) => !s.finished);
        if (!nextStep) {
          await this.agentSelfPause(taskId, "当前任务已全部完成，请下达后续指令");
          break;
        }

        // 3. 执行单步骤，带超时控制
        const result = await Promise.race([
          this.executeSingleStep(cp, nextStep),
          new Promise<{ needPause: boolean; pauseReason?: string }>((_, reject) =>
            setTimeout(() => reject(new Error("步骤执行超时")), this.config.stepTimeoutMs)
          ),
        ]);

        // 执行后再次校验状态，防止中途被用户暂停
        const latestCp = await this.loadCheckpoint(taskId);
        if (latestCp.status === AgentTaskStatus.PAUSED) break;

        if (result.needPause) {
          await this.agentSelfPause(taskId, result.pauseReason!);
          break;
        }

        // 标记步骤完成
        nextStep.finished = true;
        cp.currentStepId = nextStep.stepId;
        cp.version++;
        await this.saveCheckpoint(cp);

        // 释放事件循环，避免阻塞
        await new Promise((resolve) => setImmediate(resolve));
      } catch (error) {
        // 异常捕获，自动暂停并记录
        const errMsg = error instanceof Error ? error.message : "未知错误";
        await this.agentSelfPause(taskId, `执行异常：${errMsg}，已自动暂停`);
        break;
      }
    }
  }

  /** 动态重规划（带原始目标约束） */
  private async rebuildPlan(cp: AgentCheckpoint) {
    const newPlan = await this.llmService.rebuildPlan({
      mainGoal: cp.mainGoal,
      currentGoal: cp.currentGoal,
      finishedSteps: cp.planList.filter((s) => s.finished),
      history: cp.chatHistory.slice(-this.config.maxHotMessages),
    });
    cp.planList = newPlan;
  }

  /** 执行单个原子步骤 */
  private async executeSingleStep(
    cp: AgentCheckpoint,
    step: PlanStep
  ): Promise<{ needPause: boolean; pauseReason?: string }> {
    // 高风险步骤先触发暂停，等待用户确认
    if (step.riskLevel === "high") {
      return {
        needPause: true,
        pauseReason: `下一步操作风险较高：${step.description}，请确认后继续执行`,
      };
    }

    const result = await this.llmService.executeStep(step, cp);
    
    if (result.needHumanClarify) {
      return { needPause: true, pauseReason: result.askContent };
    }

    // 调用工具（自动幂等校验）
    if (result.toolInvoke) {
      const toolResult = await this.toolExecutor.invoke(
        result.toolInvoke.toolName,
        result.toolInvoke.params,
        cp.taskId,
        step.stepId
      );
      cp.toolHistory.push({
        recordId: uuidv4(),
        toolName: result.toolInvoke.toolName,
        params: result.toolInvoke.params,
        result: toolResult,
        success: true,
        timestamp: Date.now(),
        idempotentKey: this.toolExecutor.getIdempotentKey(result.toolInvoke),
      });
    }

    cp.chatHistory.push({
      id: uuidv4(),
      role: "agent",
      content: result.stepSummary,
      type: "task",
      createdAt: Date.now(),
    });

    return { needPause: false };
  }

  /** 生成澄清回复（不触发执行） */
  private async generateClarifyReply(taskId: string, userInput: string) {
    const cp = await this.loadCheckpoint(taskId);
    const reply = await this.llmService.generateClarifyReply(userInput, cp);
    cp.chatHistory.push({
      id: uuidv4(),
      role: "agent",
      content: reply,
      type: "clarify",
      createdAt: Date.now(),
    });
    cp.version++;
    await this.saveCheckpoint(cp);
  }

  /** 获取任务日志与状态 */
  public async getTaskStatus(taskId: string) {
    const cp = await this.loadCheckpoint(taskId);
    return {
      taskId: cp.taskId,
      status: cp.status,
      pauseSource: cp.pauseSource,
      pauseReason: cp.pauseReason,
      currentGoal: cp.currentGoal,
      planList: cp.planList,
      chatHistory: cp.chatHistory.slice(-30),
      toolHistory: cp.toolHistory.slice(-20),
      lastModified: cp.lastModified,
    };
  }
}
```

### 6.2 工具执行器（幂等封装）`ToolExecutor.ts`
```typescript
import Redis from "ioredis";
import { BaseAgentTool } from "./tools/BaseTool";

export class ToolExecutor {
  private readonly redis: Redis;
  private toolMap = new Map<string, BaseAgentTool>();

  constructor(redis: Redis) {
    this.redis = redis;
    // 注册工具实例
    // this.registerTool(new SearchTool());
    // this.registerTool(new DatabaseTool());
  }

  public registerTool(tool: BaseAgentTool) {
    this.toolMap.set(tool.toolName, tool);
  }

  public getIdempotentKey(toolInvoke: { toolName: string; params: Record<string, unknown> }) {
    const tool = this.toolMap.get(toolInvoke.toolName);
    if (!tool) throw new Error("工具不存在");
    return tool.getIdempotentKey(toolInvoke.params);
  }

  public async invoke(
    toolName: string,
    params: Record<string, unknown>,
    taskId: string,
    stepId: string
  ) {
    const tool = this.toolMap.get(toolName);
    if (!tool) throw new Error(`工具 ${toolName} 未注册`);

    const idempotentKey = `tool:idempotent:${taskId}:${stepId}:${tool.getIdempotentKey(params)}`;
    const cached = await this.redis.get(idempotentKey);
    
    if (cached) {
      return JSON.parse(cached);
    }

    const result = await tool.run(params);
    await this.redis.set(idempotentKey, JSON.stringify(result), "EX", 86400 * 30);
    return result;
  }
}
```

## 7. 工具层原子性与幂等性规范
1. **原子性约束**：所有工具必须保证单次调用为原子操作，要么完全成功要么完全失败，禁止中间状态；暂停信号仅能在工具调用前后触发，禁止打断调用过程。
2. **幂等性要求**：所有写操作类工具必须支持幂等调用，通过业务唯一键保证重复调用不产生副作用。
3. **风险分级**：工具按风险等级分为三级，高风险工具强制触发人工确认，中风险工具可配置是否确认，低风险工具自动执行。
4. **超时熔断**：所有工具调用设置超时时间，超时自动失败，不阻塞任务循环。

## 10. 前端交互规范与心智引导
1. **状态强感知**：页面顶部常驻状态条，明确区分「运行中」「已暂停」「异常」三种状态，配色差异显著
2. **操作一致性**：运行态仅显示「暂停」按钮，暂停态显示「输入框 + 继续执行」按钮，避免状态混淆
3. **暂停反馈**：点击暂停后按钮变为「暂停中...」，明确告知用户正在安全收尾，避免重复点击
4. **引导文案**：首次使用弹出引导说明「任务启动后会持续运行，关闭页面不会停止，可随时暂停调整」
5. **执行透明化**：实时展示当前执行步骤、已完成步骤、下一步计划，降低黑盒感

## 11. 部署运维与企业级合规
1. **部署架构**：API 服务与任务 Worker 分离部署，Worker 支持水平扩展，避免单点故障
2. **监控告警**：监控任务数量、运行时长、失败率、暂停频次，异常任务自动告警
3. **数据备份**：检查点数据定期备份，支持误操作回滚
4. **权限管控**：对接企业统一身份认证，任务按部门/角色隔离，高风险操作二次审批
5. **合规审计**：全操作留痕，审计日志保留不少于 180 天，支持合规导出

## 12. 落地路线与优先级建议
### 第一阶段（MVP 验证，2-3周）
- 实现核心状态机、双向暂停、断点续跑基础能力
- 接入 2-3 个低风险工具，验证交互范式可行性
- 覆盖单用户场景，暂不做复杂权限与归档

### 第二阶段（生产级加固，4-6周）
- 补充分布式锁、异常熔断、心跳巡检等稳定性能力
- 完善工具幂等封装与风险分级
- 增加审计日志、权限控制、自动休眠等企业级特性

### 第三阶段（体验优化，持续迭代）
- 优化重规划准确性，降低目标漂移概率
- 完善分层记忆，支持超长周期任务
- 扩展多任务管理、协作共享等高级功能
