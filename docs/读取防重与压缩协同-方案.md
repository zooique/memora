## 一、根因（第一性原理）

### 症状 1 · 无限重读 —— 两个作用相反的机制，无仲裁者

| 机制 | 位置 | 意图 | 副作用 |
| --- | --- | --- | --- |
| 防重缓存 | `toolResultCache.ts` + [loop.ts#L1502-1519](file:///f:/zooique/memora/src/agent/loop.ts#L1502-L1519) | 结果仍在上下文 → **拦住**重读 | 判据耦合了"占用" |
| 压缩链 | `compaction.ts` `ResultReplacementStrategy` | 旧 tool_result 换空占位 `[Previous: used x]` → **腾空间** | 唯一职责就是移出上下文 |

**冲突**：`isCachedResultStillInContext`（[loop.ts#L2451-2456](file:///f:/zooique/memora/src/agent/loop.ts#L2451-L2456)）要求「结果**仍**在上下文 + 指纹一致」才拦；而压缩链的**唯一职责**就是把结果换成占位符 → 指纹恒失配 → 拦截前提**恒为假** → 防重**结构性失效**。重读再填回空间 → 再压缩 → 再放行 → **永动机**。

**这不是 bug，是设计缺口**：把「读过什么」（账本）与「结果还在不在上下文」（占用）**耦合成了同一个判据**。压缩属占用管理，本不该动摇账本。业界收敛结论高度一致：**账本记"发生过"，占用只管"给不给原文"**——两者解耦（见 §二 Promptise / AutoGPT 工具台账）。

**放大器（实测同时命中）**：
- `read_file` 去重主体含 `offset`/`limit`（[toolResultCache.ts#L99-108](file:///f:/zooique/memora/src/agent/toolResultCache.ts#L99-L108)）→ 同文件不同区间 = 不同 key（分段续读合法，但让「同文件多区间」绕过防重）。
- 失败读取**无硬上限**——唯一刹车的 `MAX_WEB_SEARCH_CALLS` 只护 `web_search`。
- 角色包 `白话方案设计师` `tokenBudget:0` + `stepBudget:100` → 足可跑满上述循环。

### 症状 2 · 思考碎片化 —— 展示侧未聚合

内核为忠实记录，**每条** reasoning delta 生成一个 `thought` ProcessEvent（round 记录逐条可见："用户想要理解""项目并生成""白"…）。UI 的 [chatView.ts#L1354-1372](file:///f:/zooique/memora/hosts/memora-vscode/src/webview/scripts/chatView.ts#L1354-L1372) 对**每个** `thought` 事件生成**一个** `<details class="process-flow__thought">` → 几十个碎句 = 几十个折叠块。**这是展示层缺"聚合"层**，与压缩链无关；reasoning 须保留进 ProcessEvent（供 replay），故不动内核记录，只在展示层聚合。

## 二、主流设计调研（2026 吸收的养分）

| 来源 | 做法 | 对本方案的关键启示 |
| --- | --- | --- |
| **Promptise**（[工具循环失败与去重台账](https://docs.promptise.com/blog/agent-stuck-in-tool-loop/)） | 收敛角建**去重台账**：`tool(args) = result` 一行一条、**last value wins、同参自动折叠**；台账挂在**模型回合前最显眼位置** | 账本就是**结构化台账**，不是自由文本；判据 = 发生过 + 同参 |
| **AutoGPT / MemoryLake**（[为何遗忘工具历史](https://www.memorylake.ai/en/blogs/autogpt-forgets-tool-history)） | 独立**结构化工具台账**，与对话转写分开；"精确去重需要结构化日志，不是 embedding" | 账本必须**独立于上下文转写**（正是耦合的解药） |
| **Claude Code**（[Microcompact 白名单](https://blog.csdn.net/Igtq8PpWg/article/details/162393936)） | 每条 API call 前轻量清理；**保守白名单**只八类工具结果可进候选池；不进模型对话骨架 | 压缩**不该一视同仁** —— 豁免/特化要有白名单式判断 |
| **Claude Code read dedup**（[harness 上下文管理](https://arize.com/blog/context-management-in-agent-harnesses/)） | **同 `(file, range, 未变时间)` 重读返回 stub**，而非全文 | 重读判据挂在**文件/区间/时间**上，**与"内容还在不在上下文"无关** |
| **LLM 工具预算**（[停止死循环的工具 API](https://lilting.ch/en/articles/llm-tool-use-api-agent-loop-silent-failure)） | 预算在**协调层强制**而非 prompt；`is_complete` 收尾；**同参重复**返回 `duplicate_blocked` **并回显上次结果**；实际约 **8%** 工具调用是不必要重复 | 确定性硬上限（协调层）；block 要**同参匹配**且**回显替代物**，不是空拒绝 |
| **Claude Context Editing** | `clear_tool_uses_20250919` 清最旧 tool result；`exclude_tools` 保护持久事实；`clear_at_least` 下限 | 不是所有结果都该清 —— 持久事实要豁免/持有替身 |
| **Hermes Agent**（[工具加载与结果存储](https://blog.csdn.net/LOUISLIAOXH/article/details/161561603)） | 工具返回前自裁 → `maybe_persist_tool_result`（PINNED 阈值优先）→ preflight 压缩 → 治理孤儿 tool_call | 分层兜底：先规则删、再落盘托、最后才 LLM 摘要（成本阶梯） |
| **MUI X Chat**（[推理块](https://mui.org.cn/x/react-chat/ai-and-agents/reasoning/)） | **每轮应答一个** `reasoning` part：`state='streaming'(展开)/'done'(自动收起)`，delta 直接**累加**进同一块 | 思考块 = **单块累加式折叠**（streaming 开 / done 收），非每 delta 一块 |

**四条收敛原则**（吸收自上述，直接决定落地方案）：

1. **账本与占用解耦 —— 记"发生过"，不管"在不在"**。判据 = 台账里该 subject 是否已读取 + 是否同参，**不依赖**内容是否仍在上下文。占用只决定"给全文 / 给摘要 / 放行"。
2. **账本是结构化台账，不是自由文本笔记**。以 `(tool, subject)` 与 `(path, coverage)` 为键；同参自动折叠、last value wins。情报区 `intelNote`（自由文本、参与截断淘汰）**不承担此职**。
3. **摘要替代，而非空占位**。压缩把 read_file 结果换成**它自己的台账摘要**（覆盖度+出处），可回读；摘要**只产一次**（拦截文案、压缩占位、覆盖度元信息三处复用同一份 = SSOT）。
4. **确定性硬上限，且 block 只拦"无可挽回"**。同参失败 / 同参在场复读 → 硬拦（协调层强制）；**绝不拦合法顺序续读**（不同 offset = 合法）。预算在协调层，不在 prompt。

## 三、落地方案（不带伤版）

> 原则：**不新增预算维度、不引入 AST/tree-sitter**（内核零三方依赖 ADR-002）、**保守方向不变**（无替代物一律放行 —— 误放行 = 多读一次，误拦 = 死锁，两者不对称）。以下 P0/P1/P2 治症状 1，P3 治症状 2。

### P0 · 工具台账（唯一账本）—— 治永动机 · 最小改动

**新增结构化台账 `ToolLedger`**，与 `toolResultCache` **同生命周期**（闭环内存活，`resetTurnState` 清）。两个视图：

| 视图 | 键 | 存什么 | 治什么 |
| --- | --- | --- | --- |
| **精确调用台账** exact-call | `(tool, subject)`，subject 用 `DEDUP_SUBJECT_EXTRACTORS`（read_file = `(path, offset, limit)`） | 是否已读 + 结果是否原文在场 | **同参重复** 13 次 |
| **文件覆盖度摘要** file-coverage | `(path, totalLines)` | 已覆盖行区间 + 摘要（带覆盖度元信息）= P0-1b 结论 | **跨区间狂读** 148 次 |

**关键：拦截判据解耦**。现 `isCachedResultStillInContext` 把"占用"塞进"拦/放"决定。改为：
- **拦/放**由**台账**决定：该 subject 本 turn 已读 → 拦（返回摘要代替重读）；未读 → 放行。
- **给什么**由**占用**决定：原文仍在上下文 → `[ALREADY_READ] 已在上下文`；已被压缩 → 给**台账摘要 + 回读指引**；两者都没有 → 放行（保守）。

### P0-1 · 拦截三分支（以台账为真源）

接口不变，就地址不变（[loop.ts#L1502-1519](file:///f:/zooique/memora/src/agent/loop.ts#L1502-L1519) 拦截处，每工具执行**前**）：

```
① 台 records 该 subject → 原文仍在上下文（指纹一致）→ [ALREADY_READ] 无需重取（现状，正确）
② 台 records 该 subject → 全文已被压缩 → 返回台账摘要 + 覆盖度 + 回读指引（新，破死锁）
③ 文件被 write/delete 改动 → 台账 invalidate → 放行（现状，正确）
```

分支②文案（**不空拦**）：`[ALREADY_READ] 该文件已读过（第 N 步）已覆盖第 X–Y 行；要点：<摘要>。如需其它区间，用 read_file offset=Y+1 指定。`

**为何成立**：即使原文被压缩移走，台账摘要仍在 → 模型不必重读才记得这份内容；想读细节就指定新区间（新 subject = 合法放行，且更小 → 不易再触发压缩）。**永动机被台账记"读过"这一个事实就剪断**——因为它已不再依赖"内容还在不在上下文"。

### P0-1b · 覆盖度摘要（写放文件台账）

- **触发锚点** = `read_file` 返回**分段脚注**时（[builtinToolHandlers.ts#L356](file:///f:/zooique/memora/src/agent/builtinToolHandlers.ts#L356) `needFooter` = `wantedEnd < total || tailTokens > budget`）。脚注出现 ⇔ 文件确实大、确实被截断 —— 才是正确的"按需"信号。
  > **勘误（R1）**：原稿写"offload 触发时生成，阈值天然筛选"是**错误锚点** —— `read_file` 结构性不 offload（[toolResultOffload.ts#L63-64](file:///f:/zooique/memora/src/agent/toolResultOffload.ts#L63-L64)），用"永不因它触发"的机制当筛子 = 内部矛盾。
- **摘要形态**：`总行数 + 已覆盖区间 + 前 K 行 + 结构标题`（轻量启发式，零 LLM 成本，内核零三方依赖）；**覆盖度元信息必带**：「已覆盖第 X–Y 行共 N 点；文件共 M 行，其余未纳入」 —— 防"LLM 只看摘要 -> 不知道自己不知道 -> 永不回读 -> 静默信息缺失"。
- **生命周期**：P0 已定为**闭环内**（跨 turn 复用留观察，见 §五）；膨胀护栏不用 intelNote 的「裁最旧」——台账按文件分条、各条自限，超限丢弃最早文件条目（守住上下文占用量，即遵守"摘要层不新增预算维度"红线）。

### P0-2 · 升级 `DuplicateCallInterceptor`（不新建计数器）

排雷实证：三态 `ok/warn/block` 接口**早已存在**（[duplicateInterceptor.ts#L36-70](file:///f:/zooique/memora/src/agent/duplicateInterceptor.ts#L36-L70)），loop 已消费（[loop.ts#L1181-1244](file:///f:/zooique/memora/src/agent/loop.ts#L1181-L1244)），默认 threshold=3 —— **新建计数器 = 重复造轮子**。改为升级：

1. **判据细化为同参**：`DefaultDuplicateCallInterceptor.hash` 现为**整轮联合哈希**（[duplicateInterceptor.ts#L81-105](file:///f:/zooique/memora/src/agent/duplicateInterceptor.ts#L81-L105)）→ 换文件/区间即哈希变、计数归零 → 实测 148 次从未触发（**N2**）。改用 `(tool, subject)` 同参匹配（复用 `DEDUP_SUBJECT_EXTRACTORS`）。
2. **判定前移到执行前**：block/warn 注入点与 `toolResultCache` 拦截**同址**（[loop.ts#L1502](file:///f:/zooique/memora/src/agent/loop.ts#L1502)），而非事后（现状在 [loop.ts#L1181](file:///f:/zooique/memora/src/agent/loop.ts#L1181)，**工具已执行完**）。
3. **阈值 SSOT**（顺带修 **N3**）：`duplicateToolCallThreshold` 取 interceptor 的 threshold，不再硬编码 3。
4. **block 语义**（顺带修 **N1 假 block**）：当下 `block` 分支只在事后注入「…已自动阻止」（[loop.ts#L1220-1234](file:///f:/zooique/memora/src/agent/loop.ts#L1220-L1234)），**工具实际已执行、文案撒谎**。前移后 block 才有真实阻止力；**只拦"无可挽回"**：同参失败 `≥2` 次（治幻觉文件 10 次）或同参在场复读；**绝不 block 合法顺序续读**（不同 offset = 新 subject = 放行）。

### P1 · read_file 压缩 → 摘要替代（不等同空占位）

`ResultReplacementStrategy`（[compaction.ts#L78-86](file:///f:/zooique/memora/src/agent/compaction.ts#L78-L86)）对 read_file 结果**特化**：替换为**该文件的台账摘要**（含覆盖度），**而非空 `[Previous: used read_file]`**。
> **勘误（R3）**：两级策略都注册（[loop.ts#L333-346](file:///f:/zooique/memora/src/agent/loop.ts#L333-L346)），单 turn 场景第一级 `ReplaceRoundsStrategy` 不触发（1 轮 ≤ keepRecentRounds），**作恶的只有第二级** —— 特化精确落在 `compaction.ts:78`。

**为什么"摘要替代"而非"完全豁免"**：完全豁免 → read_file 结果永不压缩 → 多文件会话轰爆上下文；摘要替代则既腾空间（Claude Code Microcompact 成本阶梯：先规则删而非先 LLM 摘要）、又因**与拦截文案同源**（SSOT，摘要只产一次）让"压缩后仍可被台账救回"。这正对应 Claude Code 的**保守白名单 + read dedup stub**：可重新读，但读回有累账句柄。

### P2 · 失败即给证据（增强，可选）

read_file ENOENT 时附带该目录实际内容清单（内部 `list_dir` 一次）→ 模型自查优于单纯拒绝。可与 P0-2 的失败硬拦配合：前几次给证据、达硬上限后拒绝。

### P3 · 推理块聚合（治症状 2 · 展示层）

**不动内核**（`thought` 事件按 delta 保留，保 replay 保真）；在 chatView 展示层把**同一轮助手应答的 `thought` 碎片聚合为一个累加式折叠块**：

- **一个折叠块**，而非每 fragment 一个 `<details>`；delta 文本**累加**进同一块正文；
- `state='streaming'` → 默认展开（"思考中…"呼吸反馈）；`done/finalize` → 自动收起（对齐 [chatView.ts#L1202-1205](file:///f:/zooique/memora/hosts/memora-vscode/src/webview/scripts/chatView.ts#L1202-L1205) 已有的 thinking 聚合先例与 MUI X / OpenWebUI 主流做法）；
- reasoning 正文用 `<pre>` 纯文本展示（草稿感），**不做 Markdown 渲染**（防止断句/半成品被渲染成错乱标题）。

## 四、SSOT 设计要点

- **摘要只产一次**：首次 read_file 被截断（脚注）时生成 → 存台账 file-coverage → 压缩占位复用 → 拦截分支②复用。三处引用**同一份**，禁各写各。
- **不放情报区**：`intelNote`（自由文本、`MAX_INTEL_PREFIX_LEN` 裁最旧、且参与 `truncateMessages` 尾部淘汰 [loop.ts#L2426](file:///f:/zooique/memora/src/agent/loop.ts#L2426)）**不承担台账职责** —— 上下文越紧（正是本 bug 触发条件）替代物越先被淘汰，是错配仓库（排雷结论，本版已收敛到结构化台账）。
- **不新增预算维度**：台账体量管控走"放弃最早文件条目"，摘要层仍作为尾部消息参与淘汰。
- **不引入 AST / tree-sitter**（ADR-002 零三方依赖）→ 摘要用"总行数 + 覆盖区间 + 前 K 行 + 结构标题"轻量启发式，复用已有分段能力。
- **保守方向不变**：无替代物一律放行 —— 误放行 = 多读一次，误拦 = 死锁，不对称。

## 六、验收 / 自检

- **P0/P0-1**：用例须**先断言压缩确已发生**（前置事实成立），再断言同参重读被台账摘要拦截 —— 防"因错误原因通过"；分支②退回"放行"→ 用例须红（变异验证）。
- **P0-2**：构造"同参连续失败"断言第 3 次**不再执行**且回填 `[READ_FAILED_LIMIT]`；构造"不同 offset 顺序读"断言**照常放行**（不误伤合法续读）。
- **P1**：压缩后 read_file 结果=台账摘要（非空占位），且拦截文案/占位/覆盖度三处同源。
- **P3**：单轮 N 个 thought 碎片 → **1** 个折叠块，内容累积，finalize 自动收起。
- **回归**：内核 `tsc --noEmit` + `vitest run`；若涉预算口径跑 `npm run eval:budget:check`。
