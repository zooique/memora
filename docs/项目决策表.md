## 一、运行时栈

| 决策项       | 选择                       | 推荐度     | 理由                                                 | 替代方案与放弃原因                                              |
| ------------ | -------------------------- | ---------- | ---------------------------------------------------- | --------------------------------------------------------------- |
| **运行时**   | Node.js ≥ 20 LTS           | ⭐⭐⭐⭐⭐ | 设计文档大量 LLM 集成经验；npm 生态成熟；TS 原生支持 | Deno（生态不成熟）、Bun（生产稳定度待验证）、Python（生态割裂） |
| **类型系统** | TypeScript ≥ 5.x（strict） | ⭐⭐⭐⭐⭐ | 强类型 + 记忆体系层级清晰 + IDE 提示                 | JavaScript（无类型保护）、Flow（生态已死）                      |
| **模块系统** | ESM（"type": "module"）    | ⭐⭐⭐⭐⭐ | Node.js 20 原生支持；与 TS 配置一致；顶层 await 可用 | CommonJS（旧生态，async 限制）                                  |
| **包管理器** | npm                        | ⭐⭐⭐⭐   | 跨平台一致；与 Node 同源；零额外安装                 | pnpm（符号链接在某些场景有问题）、yarn（无显著优势）            |

## 二、数据层

| 决策项                 | 选择                                                                              | 推荐度     | 理由                                                                                                                 | 替代方案与放弃原因                                          |
| ---------------------- | --------------------------------------------------------------------------------- | ---------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| **数据库**             | better-sqlite3                                                                    | ⭐⭐⭐⭐⭐ | 同步 API 简单；性能高；FTS5/JSON1/sqlite-vec 全支持                                                                  | node:sqlite（实验性）、libsql（多一层抽象）、DuckDB（重）   |
| **索引表设计**         | 单一 SQLite 索引表（详见 [agent设计.md §4.3](../docs/基础设计文档/agent设计.md)） | ⭐⭐⭐⭐⭐ | 5 种记忆类型共享索引；检索时按 `memory_type` 区分                                                                    | 按类型分表（破坏"万物皆记忆"统一性）                        |
| **向量库（阶段三）**   | sqlite-vec                                                                        | ⭐⭐⭐⭐⭐ | 与 SQLite 同库；零运维；倾向性已在 [agent上下文组装协议.md §4.4.2](../docs/基础设计文档/agent上下文组装协议.md) 明确 | ChromaDB（独立服务）、LanceDB（生态弱）、本地文件（无索引） |
| **中文分词（阶段二）** | @node-rs/jieba                                                                    | ⭐⭐⭐⭐   | Rust 实现性能好；离线可用                                                                                            | nodejieba（维护弱）、hanlp（重）                            |

## 三、LLM 适配层

| 决策项           | 选择                                           | 推荐度     | 理由                                                     | 替代方案与放弃原因                                |
| ---------------- | ---------------------------------------------- | ---------- | -------------------------------------------------------- | ------------------------------------------------- |
| **接口协议**     | OpenAI Chat Completions 兼容                   | ⭐⭐⭐⭐⭐ | 国产模型（豆包/通义/DeepSeek）+ OpenAI + Ollama 全部支持 | Anthropic 原生协议（需独立适配；投入产出比低）    |
| **HTTP 客户端**  | 原生 fetch（Node.js 20+）                      | ⭐⭐⭐⭐⭐ | 零依赖；流式响应原生支持（SSE）                          | axios（重）、undici（直接用 Node 18+ fetch 即可） |
| **流式处理**     | SSE（Server-Sent Events）                      | ⭐⭐⭐⭐⭐ | OpenAI 协议标准；逐字打印体验                            | WebSocket（不必要的长连接）                       |
| **适配器抽象**   | `LlmProvider` 接口 + 多实现                    | ⭐⭐⭐⭐⭐ | 符合设计哲学"代码与模型分工"；模型可热切换               | 硬编码单一厂商                                    |
| **首期实现**     | DeepSeek（API 兼容好；价格低）+ 豆包（中文强） | ⭐⭐⭐⭐   | 双备份；不同场景不同模型                                 | 单家厂商（可用性风险）                            |
| **API Key 管理** | 环境变量 + cosmiconfig 二级回退                | ⭐⭐⭐⭐   | 不入 Git；配置文件不进 Git（.gitignore 强制）            | 加密存储（投入产出比低）                          |

## 六、运行时基建

| 决策项       | 选择                                                   | 推荐度     | 理由                                     | 替代方案与放弃原因                            |
| ------------ | ------------------------------------------------------ | ---------- | ---------------------------------------- | --------------------------------------------- |

## 九、阶段一切分（重述）

### 阶段一·极简版（MVP）

**目标**：能对话、能记 1 个话题、能调用 1 个工具。

**包含**：

- 项目骨架（package.json / tsconfig / 目录结构）
- CLI 启动 + REPL 基础交互
- LLM 适配（OpenAI 兼容协议）
- Agent Loop（while tool_call 循环）
- 永驻记忆 + 话题记忆（文件存储 + SQLite 索引）
- 1 个工具：读取文件
- 1 个单元测试范例

**不包含**（明确推迟）：

- FTS5 中文分词（用文件名匹配）
- 冥想归档（手动触发）
- 向量检索
- 多项目并发
- ink 终端 UI
- 工具调用白名单（仅 1 个工具无需白名单）

### 阶段二·增强版

**新增**：

- FTS5 + jieba
- 冥想归档（手动 + node-cron 自动）
- 工具白名单（5 个工具）
- 5 种能力记忆
- 多话题管理
- 领域切换

### 阶段三·完备版

**新增**：

- sqlite-vec 语义检索
- 多项目并发
- 性能优化
- ink 终端 UI
- 完整的安全审计
- 100% 测试覆盖
