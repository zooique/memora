## 一、问题与原则

### 1.1 问题

Memora 核心库当前是**纯库**（无 UI 依赖），但用户的核心关切是：

> 基础 agent 最后落地还是需要到具体项目（小说工程化管理 / 代码编写工具 / 其他形态），**是否需要开发一个基础的 WebUI？**

### 1.2 核心原则

| 原则 | 含义 |
|------|------|
| **核心库是发动机** | 通用、与领域无关、不沾 UI |
| **示例是装车指南** | 演示如何把发动机装到具体车型 |
| **发动机不改** | core 包不增加 UI 依赖 |
| **装车指南多写几份** | examples/ 覆盖多个领域 |

### 1.3 核心决策

**核心库不引入 WebUI**。理由：

```
1. ADR-005 已定 CLI-first 定位
2. 核心库零 UI 依赖 → 任何项目都能无负担 import
3. 不同项目需要的 UI 差异巨大（小说要章节管理，代码要 diff，助手要聊天）
4. core 加 WebUI 必然被每个宿主项目 fork → 等于没加
```

```typescript
// examples/code-tool/src/agentBridge.ts
import { Agent } from 'memora';
import type { Config } from 'memora';

export async function createCodeAgent(config: {
  llmApiKey: string;
  llmBaseUrl: string;
  llmModel: string;
  configDir: string;
  projectPath: string;
}) {
  const memoraConfig: Config = {
    llm: config.llmApiKey
      ? { provider: 'openai-compatible', apiKey: config.llmApiKey,
          baseUrl: config.llmBaseUrl, model: config.llmModel, temperature: 0.2 }
      : { provider: 'mock', model: 'mock-coder', temperature: 0.2 },
    memory: { dataDir: '.memora', maxContextTokens: 16000 },
    security: { permission: 'owner', confirmWrites: true },
    allowedPaths: ['.'],
  };

  const agent = new Agent({ config: memoraConfig, configDir: config.configDir, projectPath: config.projectPath });
  await agent.init();
  return agent;
}
```

```typescript
// examples/code-tool/src/cli.ts
import * as readline from 'node:readline/promises';
import { stdin, stdout } from 'node:process';
import { fileURLToPath } from 'node:url';
import { dirname, resolve } from 'node:path';
import { createCodeAgent } from './agentBridge.js';
import { loadDemoConfig } from './config.js';
import type { Agent } from 'memora';

const __dirname = dirname(fileURLToPath(import.meta.url));
const CONFIG_DIR = resolve(__dirname, '..', 'agent-config');
const PROJECT_PATH = resolve(__dirname, '..', '.code-data');

async function main() {
  const config = loadDemoConfig();
  const agent: Agent = await createCodeAgent({ ...config, configDir: CONFIG_DIR, projectPath: PROJECT_PATH });
  console.log('✓ Code Agent 已启动\n');

  const rl = readline.createInterface({ input: stdin, output: stdout });
  while (true) {
    const input = (await rl.question('code › ')).trim();
    if (!input || input === '/exit') break;
    process.stdout.write('agent › ');
    for await (const chunk of agent.chat(input)) process.stdout.write(chunk);
    console.log('\n');
  }
  await agent.close();
  rl.close();
}

main().catch((err) => { console.error('Error:', err); process.exit(1); });
```

## 五、详细对比

### 5.1 两个示例的对照

| 维度 | novel-writer | code-tool |
|------|--------------|-----------|
| 领域 | 创意写作 | 软件工程 |
| 模板来源 | `memora init --domain novel` | `memora init --domain code` |
| 形态 | CLI + Web（双形态） | CLI（单形态） |
| 形态选择理由 | 演示"WebUI 参考实现" | 证明"工程场景同样一行接入" |
| LLM 温度 | 0.7（创造性） | 0.2（确定性） |
| 上下文窗口 | 8K（对话简短） | 16K（代码长） |
| 演示命令 | `/memories` 查看挂载 | `/code` 触发代码生成 |
| agent-config | personality + 2 rules + 1 skill | personality + 1 rule + 1 skill |

### 5.2 与"通用 WebUI"的关系

| 场景 | 是否复用 novel-writer 的 web.ts |
|------|-------------------------------|
| 创意对话（小说/随笔/对话练习） | ✅ 可直接复用 |
| 个人助手 | ✅ 复用 + 改 personality |
| 代码工具 | ❌ fork 后加 diff 组件 |
| 数据分析 | ❌ fork 后加图表组件 |
| 嵌入式（终端 IDE） | ❌ 不需要 WebUI |

**原则**：novel-writer 的 web.ts 是**写作场景的参考实现**，不是**通用 WebUI 组件库**。其他场景 fork 后改即可，不应该从 core 抽。

## 七、判定

✅ **接纳执行**。本方案：

1. **严格不碰核心库**（`src/` 零改动）
2. **充分利用已有基础设施**（`memora init --domain code` 一键生成领域配置）
3. **改动量小、风险低**（1 新目录 + 2 README 改动 + 1 模板补充）
4. **验证可移植性**（创意 vs 工程两个领域对照）

**核心理念**：Memora 的可移植性不需要 WebUI 来证明——只需要"换 personality + 换领域模板 + 5 行接入"就够了。WebUI 是宿主项目的责任，不是核心库的责任。
