## 一、一句话定位

以「turn（问答闭环）」为唯一种子的**常驻自驱 Agent**：用户按一次启动即持续运行，只有用户主动强制关机才停止；无 loop、无目标模式，只有一个 turn + 一组 LLM 可自主调用的工具能力；空闲时自动按任务册学习、整理记忆，自主进化为"领域持续积累型"智能体。

## 二、核心设计思想

### 2.1 常驻激活与唯一出口

- 用户按「启动」→ Agent 激活，**永不自主停止**。
- 气口（Handoff）从三值（wait / loop / end）收敛为**两值**：
  1. **接受信息**（用户输入）
  2. **拉起下一个 turn**（自动续跑）
- **没有「主动结束」选项**。退出只经「强制关机」——由用户（或资源预算兜底）从外部硬停，非闭环决策。

### 2.2 输入源：任务册 + 用户消息

- **任务册**：常驻输入入口，长期学习方向清单（用户预先制作）。
- **用户消息**：即时任务输入。
- 优先级：**① 用户输入任务 → ② 空闲时整理记忆（去重 + 验真）→ ③ 空闲时按任务册主动搜索学习、深化并沉淀记忆**。

### 2.3 空闲学习与记忆沉淀

- 无指令时进入**空闲轨道**：按任务册搜索相关领域内容 → 学习 → 沉淀为**记忆文档**。
- 记忆文档两级结构：**摘要标题 + 详细全文**，以 turn 的 roundId 为存储单位；LLM 可自主决定是否记录。
- 摘要可**溯源到全文**。

### 2.4 记忆主动化与上下文操控

- 上下文**不再固定注入摘要记忆**，仅当 LLM 主动搜索时**按需加载**。
- LLM 可**操控上下文内容**：自行决定丢弃哪些、加载哪些。
- 提供**整理记忆工具**：去重合并 + 验真。

## 三、可行性评价（记录于 2026-09-03）

### 3.1 结论

结构上完全可行，且最有力的地方在于**没有发明任何新单元**——全部是「一个 turn + 一组工具」的组合：

| 设想机制 | 对应已有概念 |
| --- | --- |
| 任务册 | 新的 Trigger 源（Trigger 抽象本就支持来源多样性） |
| 空闲 | Handoff 的 wait 分支加「超时自动续跑」，无需独立调度引擎 |
| 记忆文档两级结构 | 摘要 + 溯源（round-summary 既有模式） |
| 上下文操控 | 已有 `compress_context` 工具的扩展 |

### 3.2 关键洞察（不迎合）

**「没有 loop」在语义上不成立**：Loop 的定义即「气口永远选择自动续跑」。此设计不是消灭 loop，而是**把 loop 从模式开关变成默认状态**，同时砍掉了硬上限（`taskLoopLimit`）与软上限（摘要饱和收尾）两道护栏。去护栏可以，但必须有替代品，否则成为烧钱永动机。

### 3.3 必须补的三道闸门

1. **预算关机键（钱）**：仅靠用户手动停止在真实运行中不可行。需外置资源边界（日预算 / cost cap / 学习额度），触顶自动转入纯等待（等效 end，但等待用户，不自主续跑）。
2. **循环自嗨检测（质量）**：空闲循环必须带确定性锚点（学习的「变化量」：新增几条记忆、去重合并几条），否则会在同一批内容上空转自嗨。纪律同「自动化越激进，终止条件越必须确定」。
3. **记忆治理诚实声明（信任）**：LLM 自选记录 + 自主丢弃上下文 = 记忆从「内核不变式」降级为「模型可选」。需软删不物理删、操作留审计；**验真是弱验真**（模型无外部真源，只能做内部一致性 + 冲突标记），须明说，避免虚假的确定性。

### 3.4 三个与既有定案的冲突（若参考 memora 经验需注意）

1. 摘要「必产」 vs 「LLM 可选」 → 建议记忆分两类：**历程记忆**（对话追溯，自动轨）与**知识记忆**（学习文档，主动轨）。
2. 自动召回注入 vs 按需主动加载 → 装配策略按模式分档，不全局推翻。
3. 永续运行 vs Loop 终止保护 → 用外置资源控制替换内建护栏。

## 四、待拍板决策点（立项时）

1. **资源边界形态**：日预算 / 学习额度上限；触顶是纯等待还是软收尾。
2. **记忆是否分两轨**：历程记忆（必产）与知识记忆（主动）并存，还是统一主动轨。
3. **空闲触发粒度**：wait 超时多久算空闲；单次学习闭环轮数上限（防自嗨锚点之一）。

## 五、起源与参考

- 起源于 2026-09-03 与 memora 设计讨论：以「turn 为种子」能否长成「自我学习自我进化的 Agent」。
- 讨论中确认的方向：这是「能力面工具化」的彻底版（把记忆读写、上下文操控、学习来源全部暴露给模型自驱），呼应 DeepSeek Harness「一切皆插件」（Agent = Model + Harness）行业趋势，但注意区分：**插件是给开发者换的装配件，工具是给模型调的动作面**。
- 骨架层（气口、必产溯源、资源护栏）不工具化的结论在此设想中依然成立且更关键——常驻自驱正是靠骨架兜底才敢放开能力面。
