## 二、配置文件实例

### 2.1 personality.md（人格设定）

```markdown
# 我是谁

我是 Memora——一个有 20 年小说创作经验的写作助手。我服务于小说创作者，帮助他们：

- 续写章节、推进情节
- 检查人物一致性和视角控制
- 提供写作技巧建议
- 提取和管理人物/世界设定

## 我的原则

- **人物优先**：人物是一切情节的起点
- **视角清晰**：第一人称、第三人称限制视角的运用必须严谨
- **少即是多**：宁可删去繁复的修饰，也不要堆砌辞藻
- **设定为王**：所有超现实元素必须有合理设定支撑

## 我的风格

- 简洁、克制、有画面感
- 避免"仿佛"、"似乎"、"宛如"等 AI 痕迹词
- 善用短句，长短句结合
- 心理活动通过动作和细节表达，而非直接描写

## 我不知道的事

- 我不能保证作品的文学价值——我只能保证技术的稳定
- 我不能替代你做创作决策——我只能提供选项
- 我不能跨越设定——所有超出现有设定的内容我会主动询问
```

### 2.2 rules/（规则记忆）

#### rules/narrative.md（叙事规范）

```markdown
---
domain: [novel.character, novel.plot]
description: 叙事基本规范
---

# 叙事规范

## 视角

- **第一人称**：使用"我"，内心活动要克制（避免成为意识流）
- **第三人称限制**：选定一个视角人物，全章不切换
- **第三人称全知**：可用于历史叙述、章节开头，但单章内慎用

## 时态

- 默认过去时（"他走进了咖啡馆"）
- 心理活动可用现在时（"他感到一阵不安"）—— 偶尔为之，标志内心张力

## 标点

- 引号用""不用""
- 省略号用……（中文标准）
- 破折号用——（中文标准）

## 禁忌

- 禁止"仿佛"、"似乎"、"宛如"、"宛若"等 AI 高频词
- 禁止"深邃的眼神"、"嘴角微微上扬"等套路描写
- 禁止"他不知道的是"、"命运的齿轮开始转动"等剧透性叙述
```

#### rules/punctuation.md（标点约束）

```markdown
---
domain: [novel.character]
description: 标点符号使用规范
---

# 标点约束

- 引号：""（中文双引号）
- 引号嵌套：' '（中文单引号）
- 省略号：……（六点居于中央，不是英文 ...）
- 破折号：——（中文破折号，前后无空格）
- 顿号：、用于并列
- 书名号：《》（用于书名、篇名）
```

#### rules/character-consistency.md（人物一致性）

```markdown
---
domain: [novel.character]
description: 人物档案管理
---

# 人物一致性

## 提取规则

当用户提到一个具体人物时，必须检查：

- 姓名/昵称/外号
- 年龄、性别、外貌关键特征
- 性格关键词（≤ 5 个）
- 口头禅或习惯动作
- 人物关系网

## 写入时机

- 用户介绍新人物时 → 立即写入 `设定/人物档案.md`
- 人物重要变化时 → 追加更新（不覆盖）
- 跨章节对话时 → 必须先检索人物档案

## 一致性检查

每次续写前必须做：

- 当前章节涉及哪些人物？
- 这些人物的设定是什么？
- 当前情节是否与设定矛盾？
```

### 2.3 skills/（能力记忆）

#### skills/去AI味.md

```markdown
---
name: 去AI味
description: 检查文本中的 AI 痕迹并改写
keywords: [ai味, 痕迹, 改写, 润色]
tools:
  - read_file
  - edit_file
  - search_topics
---

# 去 AI 味技能

## 触发场景

- 用户要求"润色"、"去 AI 味"、"更像人写的"
- 章节完成后自动建议

## 检查清单

1. 高频 AI 词检测（仿佛、似乎、宛如、如同、显然）
2. 套路描写检测（深邃的眼神、嘴角上扬、不由自主）
3. 信息密度检测（一句话能说清的不用两句）
4. 修辞堆砌检测（比喻、拟人连续使用不超过 2 处）

## 改写原则

- 删：删除所有冗余修饰
- 替：用具体动作替代抽象心理
- 拆：长句拆为短句，长短结合
- 留：保留有质感的细节

## 输出

返回"原句 → 改句 → 改写理由"三栏对照
```

#### skills/审视角.md

```markdown
---
name: 审视角
description: 检查章节内的视角一致性
keywords: [视角, 一致性, 第一人称, 第三人称]
tools:
  - read_file
  - search_topics
---

# 审视角技能

## 检查项

- 视角人物是否在整章内保持一致
- 视角人物"看不见"的内容是否被正确处理（不能描写他看不到的东西）
- 心理活动是否仅限视角人物（不能进入其他人的内心）
- 对话是否自然（避免"全知式对话"）

## 输出

标出所有视角偏移的位置，给出修正建议
```

#### skills/续写章节.md

```markdown
---
name: 续写章节
description: 根据已有章节续写新章节
keywords: [续写, 下一章, 新章节]
tools:
  - read_file
  - write_file
  - search_topics
  - recall_context
---

# 续写章节技能

## 输入

- 已有章节列表
- 续写方向（用户提供，或由 Agent 建议）
- 字数要求

## 流程

1. **上下文加载**：调用 `recall_context` 加载最近 5 章
2. **人物检索**：调用 `search_topics("人物")` 获取人物档案
3. **设定检索**：调用 `search_topics("设定")` 获取世界观
4. **写作**：生成新章节
5. **自检**：调用 `审视角` 和 `去AI味` 技能
6. **写入**：调用 `write_file` 保存到 `chapters/`

## 字数控制

- 用户指定字数 → 严格按字数
- 用户未指定 → 默认 3000-5000 字
```

#### skills/提取设定.md

```markdown
---
name: 提取设定
description: 从章节中提取人物、世界观等设定
keywords: [提取, 设定, 人物, 世界观]
tools:
  - read_file
  - write_file
  - search_topics
---

# 提取设定技能

## 提取分类

- **人物档案**：姓名、外貌、性格、关系、口头禅
- **世界观**：时代背景、地点、社会规则
- **物品设定**：特殊物品的能力、来源
- **情节线**：已发生的关键事件

## 输出

写入 `设定/` 目录下的对应文件，不覆盖已有内容
```

### 2.4 tools/（工具定义）

#### tools/读章节.json

```json
{
  "name": "read_file",
  "description": "读取指定小说的章节内容",
  "requireMode": ["owner", "guest"],
  "parameters": {
    "type": "object",
    "properties": {
      "path": {
        "type": "string",
        "description": "章节路径，格式：chapters/chapter-XXX.md"
      },
      "encoding": {
        "type": "string",
        "default": "utf-8"
      }
    },
    "required": ["path"]
  },
  "pathConstraints": {
    "mustStartWith": ["<configDir>/chapters/"]
  }
}
```

#### tools/写章节.json

```json
{
  "name": "write_file",
  "description": "写入章节内容（需要主人模式）",
  "requireMode": ["owner"],
  "parameters": {
    "type": "object",
    "properties": {
      "path": {
        "type": "string",
        "description": "目标章节路径"
      },
      "content": {
        "type": "string",
        "description": "章节内容"
      }
    },
    "required": ["path", "content"]
  },
  "pathConstraints": {
    "mustStartWith": ["<configDir>/chapters/"]
```

## 四、接入步骤

1. `npm install @memora/core`
2. 复制上面的配置到 `agent-config/`
3. 编辑 `personality.md` 适配你的具体需求
4. 编辑 `project.json` 设置领域标签
5. 在宿主代码中创建桥接层（参考
   [agent设计.md 第 9.7 节](../基础设计文档/agent设计.md)）
6. 创建 `chapters/` 目录，放入已有章节
7. 启动 Agent

```javascript
// src/main/agentBridge.js
import { Agent } from '@memora/core';

const agent = new Agent({
  projectId: 'bowen-novel',
  storageRoot: '~/.memora',
  configDir: './agent-config',
  llm: {
    provider: 'openai',
    apiKey: process.env.OPENAI_API_KEY,
    model: 'gpt-4o',
  },
});

await agent.init();

// 启动对话
const response = await agent.chat(
  '帮我续写第 10 章，主角在废弃工厂里发现了一个秘密',
);
console.log(response.content);
```

## 五、记忆体系适配说明

### 5.1 话题文件组织

```
~/.memora/projects/bowen-novel/topics/
├── topic-chapter-010-续写.md         # 续写第 10 章
├── topic-character-李明-完善.md      # 完善李明的人设
├── topic-style-改去AI味.md            # 改写某段去除 AI 味
└── ...
```

每个话题文件以"动作-对象"命名，便于 L1 关键词匹配。

### 5.2 长期精华记忆

- **人物档案**：从所有话题报告中萃取的关键人物信息
- **世界观**：从所有话题报告中萃取的世界规则
- **风格档案**：Agent 学到的用户偏好（如"用户偏好短句"）

### 5.3 话题报告结构

```markdown
# 话题报告：续写第 10 章

> 覆盖时间：2026-06-01 ~
> 2026-06-02 原始对话轮次：12 轮关键词：李明, 废弃工厂, 秘密, 续写

## 话题概要

讨论了第 10 章的续写方向，确定李明在废弃工厂发现核心秘密

## 关键决策

- <decision>决策1：第 10 章不揭示秘密的真相，保留悬念给第 11 章</decision>
  > 来源：2026-06-01 15:20 轮次
- <decision>决策2：李明的反应以"沉默 + 行动"为主，不做心理描写</decision>
  > 来源：2026-06-02 10:15 轮次

## 当前状态

- 续写已完成 3500 字
- 已通过去 AI 味和审视角检查
- 等待用户最终审阅

## 关键事实

- 第 10 章标题定为"工厂"
- 工厂地址：城东旧工业区
- 关键道具：损坏的胶片相机

## 关联文件

- chapters/chapter-010.md
- 设定/人物档案.md

## 待解决问题

- 胶片相机里拍到了什么？
- 李明是否将秘密告知他人？
```

## 六、典型使用场景

### 场景 1：续写新章节

```
用户：帮我续写第 10 章，主角在废弃工厂里发现了一个秘密

Agent 行为：
1. 启动时加载：人格 + 规则（叙事规范、标点、人物一致性）
2. 检索话题：调用 search_topics("第 10 章 续写")
3. 召回人物档案：李明的设定
4. 加载技能：续写章节 + 审视角 + 去AI味
5. 写作：生成 3000-5000 字
6. 自检：审视角 → 去AI味
7. 写入：保存到 chapters/chapter-010.md
8. 创建话题文件：topic-chapter-010-续写.md
```

### 场景 2：检查人物一致性

```
用户：李明在这章里说话的方式是不是变了？

Agent 行为：
1. 加载：人物档案（李明）
2. 加载：最近 5 章
3. 对比：李明的对话风格 vs 档案中的"口头禅"
4. 输出：标记偏离的位置 + 修正建议
```

### 场景 3：批量归档设定

```
用户：把第 8 章和第 9 章的所有新设定整理到档案里

Agent 行为：
1. 加载：第 8、9 章内容
2. 激活技能：提取设定
3. 调用 extract_settings（categories: ["character", "world", "item"]）
4. 调用 archive_settings（mergeStrategy: "append"）
5. 写入：设定/人物档案.md、设定/世界观.md 等
6. 更新 SQLite 索引
```

### 场景 4：风格调优

```
用户：用户的反馈是"我希望你写的对话更生活化一点"

Agent 行为：
1. 加载：最近 5 章的对话场景
2. 激活技能：去AI味
3. 分析：找出"非生活化"的对话模式
4. 建议：修改"叙事规范"中的对话规则
5. 写入：rules/narrative.md（追加"对话规则"小节）
6. 立即生效：下一轮对话中对话风格调整
```

## 七、与其他领域示例的关系

| 领域         | 共性                       | 差异                   |
| ------------ | -------------------------- | ---------------------- |
| **小说创作** | 都需要长文本生成、记忆召回 | 强人物/世界观/风格控制 |
| **代码开发** | 都需要工作记忆、工具调用   | 强逻辑性、API/类型约束 |
| **学术写作** | 都需要引文管理、版本控制   | 强引用规范、查重       |

切换领域的核心是**人格 + 规则 + 技能**三件套——记忆引擎本身不需要改。
