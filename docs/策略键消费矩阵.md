## 阅读约定

- **解析函数**：`strategyResolver.ts` 中的 `resolveXxx`（非法值归位内核默认，SSOT 兜底）。
- **内核消费落点**：解析值**真正改变行为**的位置（非仅解析）。三类流向：
  1. `L2RuntimeStrategy` → `resolveL2Strategy()` 聚合注入 `AgentLoop`，loop 经 `this.strategy.<field>` 读取（act 多数键 + reflect.selfReview + 部分 global）。
  2. `contextPreparer` / `recall` / `roundSummaryGenerator` / `orchestrator` / `prepare` 经 `resolveActiveStrategy()` 直接取 `BehaviorStrategy` 消费（prepare 键 + reflect 键）。
  3. `agent.ts` 直接映射 `act.temperature/outputLimit/streaming` → `ChatOptions`（**不经 `resolveL2Strategy`**）。
  4. `assembleRolePack()` 注入 persona prompt 行为指令（understandingConfirm / userFollowup / askOn / askLimit）。
- **UI 侧**：VS Code 宿主 `rolesView.ts` 经 `strategyHint` 渲染策略 chip。当前仅 6 键有 UI 呈现（见下表）。

## 关键翻案与边界澄清

### 1. `toolReadonly` / `toolApproval` 不是「无宿主执行方」

早期 T4 草稿误述「`preExecutionCheck` 恒放行致 `toolApproval`/`toolReadonly` 无宿主侧执行拦截」。**实锤推翻**：

- 内核 `toolRunner.ts:119-152` 是**三重闸**：
  - **闸①** `toolReadonly==='readonly'` → 阻止非只读工具执行（L126-135）——**内核已执行**。
  - **闸②** `toolApproval==='confirm'` → 触发 `onToolApproval` 通知宿主征询（L141-143）——**内核已执行**（通知，决策权交宿主）。
  - **闸③** 宿主 `preExecutionCheck`（L146-152）——当前 VS Code 宿主恒放行 `() => ({ skip: false })`（T6 已文档化：`assemble.ts:267`），是**第三重闸的让行**，表达单用户本地天然信任模型，**并非缺执行方**。
- 正确表述：**`toolReadonly`/`toolApproval` 的内核执行方（闸①②）始终在场**；宿主恒放行只是单用户信任下的显式让行决策（关联设计纪律 **D5** 与接入指南 十.5），未来多用户/服务端须替换真实审批策略。

### 2. `capabilityLabels.ts` 不是策略键消费者（纠正原误述）

VS Code 宿主 `capabilityLabels.ts` 是**角色能力名映射**（`file:read` → 「读取文件」等），与 26 个策略键（2026-09-06 实测 `STRATEGY_KEY_RULES`）**无关**。原 T4 草稿将其列入「消费策略键的 9 文件」属过度陈述，已纠正。UI 侧真实消费策略键的文件只有 `rolesView.ts`（6 个 chip：toolReadonly / toolApproval / summaryFocus / outputLimit / temperature[tempGroup] / multiStepReasoning[reasoningMode]）。

### 3. 流向收敛，无镜像双写

- act 6 键（toolMode/toolStepLimit/providerRouting/multiStepReasoning/toolReadonly/toolApproval，temperature/outputLimit/streaming 由 agent.ts 直映射）+ reflect.selfReview（旧键 loopContinue 回退）+ global 4 键（errorHandling/tokenBudget/stepBudget/askLimit）统一经 **`resolveL2Strategy` 单一聚合**注入 `L2RuntimeStrategy`，loop 统一经 `this.strategy.<field>` 读取——无跨模块镜像。
- prepare 键经 **`resolveActiveStrategy` 单一真理源**取 `BehaviorStrategy`，`contextPreparer` 与 `orchestrator` 据此消费，杜绝重复解析。
- persona 指令类（understandingConfirm/userFollowup/askOn/askLimit）由 **`assembleRolePack` 单一收口**注入，无第二处副本。
