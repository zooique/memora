## 一、原始方案（用户提出）

| 编号 | 原始表述                                                          |
| ---- | ----------------------------------------------------------------- |
| P1   | 问答闭环（用户提问 + 大模型回答）是最小单元                       |
| P2   | 问答窗口只保留"用户问答记录"，上下文提交和归档种子交给隐性复制    |
| P3   | 隐性复制一份给 agent 当临时记忆，承担上下文提交 + 归档种子        |
| P4   | 临时记忆保留最近 2-3 轮完整问答闭环                               |
| P5   | 实时归档：特殊词汇触发直接归档                                    |
| P6   | 3 轮后对最早闭环强制归档 + 删除临时记忆（不管是否提取到有用内容） |
| P7   | 归档记忆以"归档记忆"形式挂载到记忆挂载                            |

## 二、问诊补充（评审后修正）

| 编号 | 修正内容                                       | 理由                                                            |
| ---- | ---------------------------------------------- | --------------------------------------------------------------- |
| A    | "2-3 轮"改为"动态窗口 + 3 轮最低保障"          | 128K 窗口 3 轮只占 1-2%，8K 窗口 3 轮可能占 30%——窗口大小自适应 |
| B    | "不管是否提取到有用内容都删除"改为"封存不删除" | 原文从上下文移除（减法达成），文件系统保留备份（安全网）        |
| C    | 归档失败时保留原文                             | LLM 超时/错误时不丢失数据                                       |

## 三、排雷发现（6 个风险）

### L1：步骤 3 — "隐性复制"语义不清

**风险**：用户说"隐性复制一份给 agent"，但现有代码中 `MessageHistory` 是从
`TopicStore` 读数据组装
`messages[]`，不是独立数组。如果引入独立数组，需要额外的同步逻辑。

**修正**：不引入独立数组。"临时记忆"是一个**概念标签**——它仍然是 `TopicStore`
的一个视图（最近 N 轮原文），不改变底层存储。代码上：

- `TopicStore` 仍是 source of truth（写入 topic-\*.md）
- `MessageHistory` 仍从 `TopicStore` 读取，但标注为"临时记忆层"
- 删除"临时记忆"操作 = 从上下文中卸载对应轮次，不删除 TopicStore 中的原文

### L2：步骤 4 — 2 轮窗口过短

**风险**：如果窗口只有 2 轮，第 3 轮时第 1 轮已滑出。用户在第 3 轮说"刚才说的那个角色叫什么？"时，Agent 上下文中没有第 1 轮的角色设定原文，只能靠归档记忆召回——而归档记忆的摘要粒度可能丢失细节。

**修正**：最小窗口固定为 3 轮，可配置（`minWindowRounds`，默认 3）。同时扩大对话快照从 3-5 句到 5-8 句——临时记忆减掉的原文，归档记忆的快照部分要更丰富来补偿。

### L3：步骤 4 — 归档记忆覆盖不全

**风险**：用户 P6
"不管是否提取到核心有用的内容，都会删除临时记忆"。但 LLM 炼化的摘要和快照的选择标准是"最有信息量"，不等于"用户下一轮会需要"。一个看起来不重要的细节（"青石板路"）可能在 5 轮后被问到。

**修正**：

- ✅ 已由 修正 B（封存不删除）兜底——原文移到 archive/，极端情况可通过文件扫描恢复
- ✅ 对话快照从 3-5 句扩大为 5-8 句——提高"覆盖不全"的概率缓冲
- ✅ 兜底扫描（[00-记忆归档原则 §8.2](./基础设计文档/00-记忆归档原则-v1.0.md#L678-L683)）已设计：TopicMount 未命中 → 扫描最近 N 个 topic 文件的前 500 字

### L4：步骤 5 — "特殊词汇"定义模糊

**风险**：用户提到"特殊词汇触发直接归档"，但没有定义哪些是特殊词汇。现有
`SIGNAL_PATTERNS`
正则白名单只覆盖用户画像写入（"我叫"/"我喜欢"等），不覆盖话题摘要触发。

**修正**：沿用现有正则白名单不变。如果需要扩展"特殊词汇"体系（如"总结一下"触发话题摘要），作为 P2 增强在后续迭代中完成。当前阶段正则白名单已覆盖实时归档的核心场景。

### L5：步骤 6 — 按"轮次"归档信息密度太低

**风险**：如果每轮独立触发归档，像"帮我写玄幻小说开头"这种信息密度极低的轮次会产生低质量归档记录，污染 SQLite 索引。现有设计按**话题**粒度归档（话题切换时一次性炼化整个话题的所有轮次），信息密度远高于逐轮归档。

**修正**：归档粒度从"逐轮强制归档"改为"话题级检查归档"：

- 3 轮后触发的是**检查**："当前话题是否应该归档？"
- 使用话题漂移检测（TopicMount 的 Jaccard 相似度）判断是否达到归档时机
- 话题结束时（切换/关闭）一次性归档整个话题的所有轮次
- 超长话题（>30 轮）在中途触发一次中间归档（层级 4 实时炼化）

### L6：步骤 6 — LLM 不可用时的未归档堆积

**风险**：如果 LLM 持续不可用，修正 C
"归档失败保留原文"导致临时记忆永远无法释放旧轮次。3 轮窗口会在第 4 轮溢出。

**修正**：

- 归档失败重试 3 次（间隔递增：1s / 3s / 9s）
- 3 次全失败 → 跳过该轮归档，标记为"原文已封存，未炼化"
- 原文移到 archive/，索引中不创建记录（避免低质量索引）
- 下次启动时，`archiveMissingTopics()` 扫描"未炼化"标记，重新尝试归档

## 四、优化后的完整方案

### 4.1 临时记忆模型

```
┌─────────────────────────────────────────────────────────────┐
│  问答窗口（用户可见）                                          │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  R1: 用户"..." → Agent"..."                           │  │
│  │  R2: 用户"..." → Agent"..."                           │  │
│  │  R3: 用户"..." → Agent"..."                           │  │
│  │  [仅作对话记录展示，不参与上下文逻辑]                      │  │
│  └───────────────────────────────────────────────────────┘  │
│                           ↓                                  │
│  持久化层（TopicStore）                                       │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  topic-*.md：R1/R2/R3/R4 完整原文（追加写）             │  │
│  │  archive/：已封存的旧轮次原文                            │  │
│  └───────────────────────────────────────────────────────┘  │
│                           ↓                                  │
│  临时记忆层（概念标签，实际从 TopicStore 读取）                 │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  动态窗口（≥ 3 轮）：R2/R3/R4                          │  │
│  │                                                        │  │
│  │  ★ 上下文提交：每次 API 调用的 messages[] 来源           │  │
│  │  ★ 归档种子：3 轮后话题检查归档时，原文作为炼化输入       │  │
│  │  ★ 窗口自适应：上下文利用率 < 85% 时保留更多轮次          │  │
│  └───────────────────────────────────────────────────────┘  │
│                           ↓                                  │
│  归档记忆层（SQLite 索引 + TopicMount 召回）                   │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  话题摘要（第 2 层）+ 对话快照（第 2.5 层，5-8 句）       │  │
│  │  → 进入 SQLite 索引                                     │  │
│  │  → TopicMount.focus() 按需召回                          │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 窗口策略

| 参数         | 值                                             | 说明                                       |
| ------------ | ---------------------------------------------- | ------------------------------------------ |
| 最小窗口轮次 | 3                                              | 保证基本上下文连贯性                       |
| 最大窗口轮次 | 动态（≤ 上下文窗口 85%）                       | 128K 窗口可容纳远超 3 轮                   |
| 窗口溢出策略 | 上下文压力感知                                 | pressureMonitor 触发卸载，而非固定轮次强删 |
| 归档触发     | 话题级检查（3 轮后启动 + 话题切换 + 用户显式） | 不逐轮归档                                 |

**自适应逻辑**：

```
每轮对话后：
  1. 计算上下文利用率 = 当前 messages[] tokens / maxContextTokens
  2. 如果 < 85% → 保留所有轮次（即使超过 3 轮）
  3. 如果 ≥ 85% → 触发 pressureMonitor，卸载最早的轮次
  4. 卸载 = 原文从 messages[] 移除，原文从 TopicStore 移到 archive/
  5. 最小保留 3 轮（minWindowRounds = 3，不可突破）
```

### 4.3 归档管线

```
┌─────────────────────────────────────────────────────────────────┐
│  实时归档（每轮）                                                 │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  正则信号检测 → 命中 → 即时写入 profile.md                │  │
│  │  正则信号检测 → 未命中 → 跳过                              │  │
│  │  ★ 不依赖 LLM，< 10ms                                     │  │
│  └───────────────────────────────────────────────────────────┘  │
│                                                                  │
│  话题归档（话题切换 / 3 轮后检查 / 用户显式）                      │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  触发条件：                                                │  │
│  │    a. 话题切换（TopicMount 检测 Jaccard < 0.25）            │  │
│  │    b. 3 轮后每轮检查话题漂移                                │  │
│  │    c. 用户说"总结一下""归档"等显式触发                      │  │
│  │    d. 超长话题 > 30 轮中途归档                             │  │
│  │                                                            │  │
│  │  执行流程（一次 LLM 调用，两输出）：                         │  │
│  │    输入：话题内所有轮次的对话原文（800 字截断）              │  │
│  │    输出 1：话题摘要 JSON {约束/偏好/决策}                   │  │
│  │    输出 2：对话快照 5-8 句用户原文                          │  │
│  │                                                            │  │
│  │  后处理：                                                   │  │
│  │    → 摘要 + 快照写入 topic-*.md frontmatter                 │  │
│  │    → 摘要 + 快照写入 SQLite 索引                            │  │
│  │    → 原文移到 archive/（封存）                              │  │
│  │    → 临时记忆：卸载已归档轮次                                │  │
│  └───────────────────────────────────────────────────────────┘  │
│                                                                  │
│  失败降级                                                        │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  重试 3 次（1s/3s/9s）→ 全失败 → 跳过归档                   │  │
│  │  标记原文为"已封存，未炼化" → 下次启动补归档                 │  │
│  │  未炼化的原文不删除，不移出窗口（保留在临时记忆中）            │  │
│  └───────────────────────────────────────────────────────────┘  │
│                                                                  │
│  启动补归档                                                      │
│  ┌───────────────────────────────────────────────────────────┐  │
│  │  agent.init() 时扫描 archive/ 中"未炼化"标记的原文           │  │
│  │  → 重新调用 LLM 炼化                                         │  │
│  │  → 成功 → 写入索引 + 清除标记                                │  │
│  │  → 失败 → 保留标记，下次启动再试（最多保留 7 天）             │  │
│  └───────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────┘
```

### 4.4 关键参数表

| 参数                     | 默认值 | 可配置 | 说明                                      |
| ------------------------ | ------ | ------ | ----------------------------------------- |
| `minWindowRounds`        | 3      | 是     | 临时记忆最少保留轮次                      |
| `maxContextUtilization`  | 85%    | 否     | 触发上下文压缩的利用率阈值                |
| `archiveCheckRounds`     | 3      | 是     | N 轮后启动话题归档检查                    |
| `snapshotCount`          | 5-8    | 否     | 对话快照提取句数（排雷修正：从 3-5 扩大） |
| `archiveRetryMax`        | 3      | 否     | 归档失败最大重试次数                      |
| `unrefinedRetentionDays` | 7      | 否     | 未炼化标记保留天数                        |
| `topicDriftLower`        | 0.25   | 是     | 话题漂移阈值（Jaccard < 此值触发切换）    |

## 五、与现有设计的关系

### 5.1 保留不变的部分

- ✅ 四层记忆体系（作品/角色/心得/助手记忆）
- ✅ 两速归档（即时画像 + 异步摘要）
- ✅ 话题文件格式（frontmatter + 消息列表）
- ✅ TopicMount + RecallPipeline 召回链路
- ✅ 上下文压力感知 + weight 衰减
- ✅ 信号检测正则白名单
- ✅ DialogueSnapshot + TopicSummarizer LLM 调用

### 5.2 改变的部分

| 现有设计                                | 优化后                              | 变化程度                         |
| --------------------------------------- | ----------------------------------- | -------------------------------- |
| 归档触发 = 话题切换 + 强信号 + 启动补执 | + "3 轮后每轮检查话题漂移"          | 小（新增一个检查条件）           |
| 对话快照 = 3-5 句                       | → 5-8 句                            | 小（数字调整）                   |
| 话题原文 = TopicStore 读写              | + archive/ 封存目录                 | 小（现有设计已有 archive/ 目录） |
| 上下文窗口 = 动态（85% 利用率）         | + minWindowRounds=3 保底            | 小（加一个下限）                 |
| 归档失败 = 跳过 + 下次补执              | + "原文保留在临时记忆 + 标记未炼化" | 小（增强降级逻辑）               |
| 逐轮概念 = 无                           | + "临时记忆"概念标签                | 概念新增，代码变化极小           |

### 5.3 无需改动的部分

- ❌ 不引入独立的内存数组——`TopicStore` 仍是 source of truth
- ❌ 不改 TopicStore 的读写接口
- ❌ 不改 MessageHistory 的组装逻辑
- ❌ 不改 TopicMount 的召回链路
- ❌ 不改 SQLite 索引结构
- ❌ 不改 topic-\*.md 文件格式
