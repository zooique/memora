## 二、Memora 核心卖点提炼（差异化竞争策略）

### 2.1 反潮流定位：单 Agent 专注模式

**大厂都在做什么：**
- OpenAI: GPTs + Multi-agent 协作
- Anthropic: Computer Use + 多工具链
- 字节 Trae IDE: 多 Agent 并行（Builder + Chat + 其他）
- 其他: 多对话窗口、多线程操作

**Memora 的选择：**
> "应无所住，而生其心"——启动时无所挂碍，开口时记忆自然浮现。

**核心差异：**
| 维度 | 大厂多 Agent 模式 | Memora 单 Agent 专注模式 |
|------|------------------|------------------------|
| 架构 | 多 Agent 并行协作 | 单 Agent + 记忆驱动 |
| 上下文管理 | 分窗口、分线程 | 每轮闭环 + 动态组装 |
| 记忆方式 | 会话隔离或有限共享 | 全局统一记忆库，跨项目持久 |
| 用户体验 | 复杂、需要学习 | 简单、专注、无感知 |
| Token 消耗 | 随对话累积增长 | 每轮固定预算 |

### 2.2 核心卖点一：「每轮闭环 + 动态组装」记忆引擎

**问题：** 传统 AI 助手历史问答不断累积，早期对话噪声污染后续推理。

**Memora 方案：**
- 每轮对话结束后，关键信息提取为记忆（insight）
- 下一轮启动时，从记忆库动态召回最相关的记忆
- 上下文永远是精简、相关的，永远不会膨胀
- Token 消耗固定预算，不随对话累积增长

**技术亮点：**
- 双通道召回（语义搜索 + 关键词匹配）
- 记忆衰减机制（>7天未访问 score 降 0.02/周）
- 记忆生命周期管理（存储 → 召回 → 衰减 → 归档）

### 2.3 核心卖点二：「越用越懂你」的用户画像

**问题：** AI 助手每次都是"第一次认识你"。

**Memora 方案：**
- 自动提取用户偏好、习惯、知识背景
- 形成用户画像（profile）记忆
- 跨会话、跨项目持久化
- 角色自动匹配（根据对话内容自动切换角色）

### 2.4 核心卖点三：「上下文感知而非内容感知」的隐私保护

**问题：** 桌面 AI 助手需要感知用户状态，但容易侵犯隐私。

**Memora 方案：**
- 精灵通过定时巡检和文件变化监听感知工作状态
- **不监听键盘、不读取剪贴板、不截屏、不监听网络流量**
- 窗口感知仅读取窗口标题，不读取内容
- 纯本地运行，数据不出本机

### 2.5 核心卖点四：「零 native 依赖」的纯逻辑内核

**问题：** AI 项目依赖复杂，难以集成。

**Memora 方案：**
- 内核纯 TypeScript，零 native 模块
- 不依赖 better-sqlite3、不依赖 CLI 框架
- 所有持久化、UI、native 能力由宿主注入
- 可被任何宿主项目集成（IDE 插件、桌面应用、Web 服务）

## 三、参赛形式建议

### 3.1 推荐方案：交互式 HTML Demo（Zip 打包上传）

**原因：**
- 初赛要求三选一：部署链接 / HTML 文件 / 演示视频
- HTML 文件最可控，无需服务器，评审可直接打开体验
- 可以展示内核的交互式特性（记忆召回、角色切换、记忆搜索等）

**Demo 内容规划：**

```
Memora-Demo/
├── index.html          # 主页面：项目介绍 + 导航
├── demo/
│   ├── memory-engine.html    # 记忆引擎演示（核心卖点）
│   ├── persona-system.html   # 角色系统演示
│   ├── sprite-preview.html   # 桌面精灵预览（概念展示）
│   └── api-playground.html   # API 交互 playground
├── assets/
│   ├── css/
│   ├── js/
│   └── images/         # 截图、架构图
└── README.md           # 说明文档
```

### 3.2 Demo 核心页面设计

#### 页面 1：记忆引擎演示（memory-engine.html）

**目标：** 让评审直观理解「每轮闭环 + 动态组装」

**交互设计：**
1. 左侧：模拟对话界面
2. 右侧：实时显示「记忆快照」
   - 工作记忆（当前对话历史）
   - 引导记忆（规则/角色/技能）
   - 归档记忆（insight / profile / work-projection）
3. 每轮对话后，展示「记忆提取」过程
4. 下一轮展示「记忆召回」过程
5. 可视化记忆权重变化（衰减效果）

**技术实现：**
- 使用 InMemoryStorage（纯内存，无需后端）
- 模拟 Agent.chat() 的流式输出
- 使用本地存储保存演示数据

#### 页面 2：角色系统演示（persona-system.html）

**目标：** 展示角色自动匹配 + 手动切换

**交互设计：**
1. 预设几个角色（程序员、作家、学生）
2. 用户输入不同领域的问题
3. 展示角色自动匹配过程
4. 展示角色切换后的回复差异

#### 页面 3：桌面精灵预览（sprite-preview.html）

**目标：** 展示精灵的主动行为概念

**交互设计：**
1. 模拟桌面精灵的 UI（浮动窗口）
2. 展示精灵的几种状态：
   - 静默观察（后台运行）
   - 主动提醒（检测到文件变化）
   - 热键召唤（Ctrl+Shift+M）
3. 展示精灵配置面板（偏好设置）

**注意：** 这是概念预览，非真实桌面应用（避免评审期望过高）

#### 页面 4：API Playground（api-playground.html）

**目标：** 展示内核的 API 设计

**交互设计：**
1. 提供几个预设的 API 调用示例
2. 用户可以修改参数，查看返回结果
3. 展示事件系统（memoryAdded / personaSwitched 等）

### 3.3 备选方案对比

| 方案 | 优点 | 缺点 | 推荐度 |
|------|------|------|--------|
| **HTML Demo** | 无需服务器、评审可直接体验、可控性强 | 需要前端开发工作 | ⭐⭐⭐⭐⭐ |
| 部署在线链接 | 更真实、可展示实时功能 | 需要服务器、维护成本 | ⭐⭐⭐⭐ |
| 演示视频 | 制作简单、可展示完整流程 | 无法交互、评审体验差 | ⭐⭐⭐ |

### 4.2 正文结构

#### 1. Demo 简介

**是什么：**
Memora 是一款桌面端 AI 助手系统——纯逻辑记忆内核提供「每轮闭环 + 动态组装」的 Agent 记忆引擎，桌面精灵宿主将其落地为可感知工作上下文、越用越懂你的 AI 伴侣。

**面向谁：**
- 长期使用 AI 编程助手的开发者
- 需要跨天连续深度对话的内容创作者
- 进行跨时段研究的知识工作者
- 希望 AI 记住学习进度和薄弱点的学生

**主要功能：**
1. **记忆引擎**：每轮对话闭环，动态组装上下文，Token 消耗固定
2. **角色系统**：自动匹配 + 手动切换，越用越懂你
3. **桌面精灵**：上下文感知（非内容感知），适时主动提供帮助

#### 2. Demo 创作思路

**灵感来源：**
使用 Trae IDE 时发现，多 Agent 和多对话窗口虽然强大，但单窗口的上下文污染问题始终存在。为什么不能让每一轮问答成为闭环，每一轮都动态组装上下文？

**想解决的问题：**
- 单窗口长时间对话中，历史问答噪声污染后续推理
- AI 助手无法跨会话积累对用户的理解
- 用户需要手动管理上下文，打断工作流

**为什么做这个方向：**
大厂都在追逐多 Agent、多线协作，但「单窗口专注模式」才是大多数用户的真实需求。Memora 选择反潮流，做减法而非加法。

## 七、总结

Memora 的核心竞争力在于**反潮流的「单 Agent 专注模式」**，这与大厂的多 Agent 多线协作形成鲜明对比。初赛的关键是：

1. **清晰传达差异化定位**——为什么单 Agent 更好
2. **用 HTML Demo 直观展示核心机制**——记忆引擎的动态组装过程
3. **强调真实场景和痛点**——上下文污染是真实存在的问题
4. **展示完整的开发过程**——截图 + Session ID 证明使用 TRAE 开发
