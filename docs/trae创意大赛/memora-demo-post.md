### 1. Demo 简介

**是什么**：Memora Sprite 是一款运行在你桌面上的、会记忆的本地 AI 助手。它不是又一个通用 Agent 平台，而是一个能持续积累关于你的记忆、越用越懂你的持久化智能体。纯本地优先，隐私安全。

**面向谁**：
- 长期在 IDE 中连续编码数小时的开发者
- 需要跨天持续深度对话的创作者
- 希望 AI 记住个人偏好、工作习惯的知识工作者

**核心功能**：

**① 每轮记忆闭环**
对话结束自动提取关键信息，下一轮对话动态召回最相关记忆。上下文永远精简、永远相关，不会越聊越"失忆"。每条记忆有置信度评分，不常用的记忆自然衰减，避免记忆库膨胀。

![记忆面板截图](需要补充：记忆面板列表+图谱双视图截图)

**② 三态自然交互**
不打断工作流的桌面精灵设计：
- 🪟 完整窗口：深度对话、查看记忆、调整设置
- 💫 浮动图标：随时待命，不占屏幕空间
- 🔽 系统托盘：后台静默运行，记忆持续积累，有需要时主动出现

![三态切换截图](需要补充：三态切换演示截图)

**③ 默契度成长系统**
精灵和你的默契度会随对话真实成长：👋 初识 → 🤝 熟悉 → 😊 默契 → 💖 知己。每条记忆积累、每次对话，都在让精灵更懂你。

### 2. Demo 创作思路

**灵感来源**：
使用 Trae IDE 编程时发现一个问题——主流 AI 都在做多 Agent、多窗口、多线协作，但是单窗口长时间对话的「上下文污染」问题没人解决。对话越长，AI 越容易"记混"或"答偏"。要么忍受质量下降，要么手动清空窗口打断工作流——为什么不能让每轮对话都成为闭环，自动管理记忆呢？

这就是 Memora 的起点：「应无所住，而生其心」。启动时无所挂碍，开口时记忆自然浮现。

**想解决的问题**：
大厂的 AI 每次对话都从零开始，你需要反复告诉它你的偏好、你的项目背景、你的编码风格。Memora 让 AI 真正"记住"这些——不是靠无限拉长上下文窗口，而是靠结构化的记忆管理：存储 → 衰减 → 召回 → 组装，形成记忆闭环。

**为什么做这个方向**：
大厂做通用 Agent 平台，我们走专精路线。在"记忆驱动的持久化智能体"这个方向上深耕：
- 记忆拓扑：记忆之间支持矛盾、佐证、时序、细化等关系，形成记忆网络（规划中，Demo 已展示图谱预览）
- 情感系统：基于记忆自动调整语气风格，默契度真实成长
- 桌面壁垒：三态交互 + 热键召唤 + 工作状态感知，真正融入桌面工作流
- 隐私底线：不监听键盘、不截屏、不读剪贴板内容，数据完全本地

大厂要做的是大而全的平台，我们要做的是一个真正懂你、陪你很久的 AI 伴侣。

### 3. Demo 体验地址

**交互式 HTML Demo 已作为附件上传**（`memora-demo.zip`），下载解压后打开 `index.html` 即可体验完整流程：

2. 内置引导步骤：发消息 → 观察记忆自动积累 → 切换三态 → 探索记忆面板和设置

### 4. TRAE 实践过程

本项目完全基于 Trae IDE 开发完成。Memora 记忆内核（TypeScript）+ Sprite 桌面宿主的整体架构设计、记忆系统实现、Demo 交互原型均在 Trae 中完成。

**开发关键步骤**：

**步骤一：项目扎根——使用大树播种机搭建项目骨架**
基于 Memora 的设计哲学（万物皆是记忆）和核心矛盾（无状态推理 ↔ 连续演化任务），在 Trae 中通过交互式引导完成项目 Rules 框架和 ADR 决策记录的搭建，确立了单 Agent 模型、三层架构、零依赖内核等核心设计约束。

![步骤一截图](需要补充：项目初始化/Rules框架截图)

**步骤二：记忆内核核心实现**
在 Trae 中完成 Memora 记忆引擎的核心开发：IMemoryStorage 接口抽象、InMemoryStorage 测试实现、记忆召回双通道（关键词+语义向量）、记忆衰减机制、事件系统、LLM 适配层等。通过 Trae 的代码审查能力，识别并修复了记忆关系设计侵入 Memory 类型的架构问题，采用了独立侧车（sidecar）结构符合 ADR-004 记忆统一模型约束。

![步骤二截图](需要补充：核心代码/测试通过截图)

**步骤三：Demo 交互原型迭代**
在 Trae 中完成交互式 Demo 的设计与开发：首页差异化定位、三态切换交互、记忆面板+图谱预览、默契度成长系统、引导层设计等多轮迭代。通过 Trae 的多文件编辑和重构能力，从评审视角发现并修复了硬编码用户名、记忆面板搜索/过滤无功能、侧边栏数据硬编码等问题，确保 Demo 体验流畅。
