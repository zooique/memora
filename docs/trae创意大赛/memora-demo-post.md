## 【正文】

---

> **一句话介绍**：当所有大厂都在做多 Agent、多窗口、多线协作时，我们选择了相反的方向——**单 Agent + 记忆闭环**。启动时无所挂碍，开口时记忆自然浮现。每轮对话都形成闭环，Token 消耗固定，永不"失忆"也永不"记混"。

---

### 1. Demo 简介

**是什么**：Memora Sprite 是一款运行在你桌面上的、**真正会记忆**的本地 AI 助手。

它不是又一个"接了 API 的聊天窗口"，也不是"套了 Electron 壳的网页版 ChatGPT"。Memora 从内核层面重新设计了 AI 的记忆机制：每轮对话结束后，关键信息被结构化提取为记忆；下一轮对话开始时，最相关的记忆被动态召回注入上下文。记忆不是聊天记录的堆叠，而是有生命周期、有置信度、有关系网络的结构化知识。

| 维度 | 大厂多 Agent 模式 | Memora 单 Agent + 记忆 |
|------|---------|--------|
| 架构 | 多 Agent 并行、多窗口切换 | 单 Agent 专注、记忆驱动 |
| 上下文 | 线性累积，越长越混乱 | 每轮闭环，永远精简相关 |
| Token 消耗 | 随对话长度线性增长 | **固定预算，永不膨胀** |
| 跨会话记忆 | 无或有限，需手动管理 | 全局持久，自动召回 |
| 隐私 | 数据上传云端 | **纯本地优先** |

**面向谁**：
- 长期在 IDE 中连续编码数小时、不希望被窗口切换打断心流的开发者
- 需要跨天持续深度对话、希望 AI 记住项目背景和创作风格的创作者
- 对隐私有要求、不希望键盘输入/剪贴板/屏幕被监听的用户
- 受够了"每次都要重新介绍一遍自己"的 AI 用户

**核心功能**：

**① 每轮记忆闭环（核心创新）**
对话结束自动提取关键信息（身份画像/偏好洞察/作品投影），下一轮对话通过「关键词匹配 + 语义向量」双通道召回最相关的记忆。每条记忆有置信度评分，不常用的记忆随时间自然衰减，避免记忆库膨胀。这不是简单的历史记录持久化——这是一个有生命周期的记忆引擎。

【截图位置：记忆面板列表+图谱双视图截图】

**② 三态自然交互（桌面壁垒）**
不打断工作流的桌面精灵设计：
- 🪟 **完整窗口**：深度对话、查看记忆网络、调整精灵配置
- 💫 **浮动图标**：热键召唤，随时待命，不占屏幕空间
- 🔽 **系统托盘**：后台静默运行，记忆持续积累，有需要时主动出现

【截图位置：三态切换演示截图】

**③ 默契度真实成长**
精灵和你的默契度基于**真实记忆积累**而非虚假数值：👋 初识 → 🤝 熟悉 → 😊 默契 → 💖 知己。每次信息提取、每条记忆沉淀，都在让精灵更懂你。这是一个会"越用越顺手"的 AI，而不是永远一成不变的聊天机器人。

【截图位置：侧边栏默契度卡片+记忆健康统计截图】

**④ 隐私本地优先（底线设计）**
- 不监听键盘输入
- 不读取剪贴板内容
- 不截屏、不录屏
- 不监听网络流量
- 两级权限 + 路径白名单，文件操作严格受限
- 所有记忆数据 100% 存储在本地设备

### 2. Demo 创作思路

**灵感：一个被所有人忽略的痛点**
在用 Trae IDE 编程的过程中，我发现了一个反直觉的问题：**对话越长，AI 越傻**。

当你和 AI 连续聊 2 小时以上，它开始记混你之前说过的话、开始重复回答、开始遗漏关键上下文。要么你忍受质量下降，要么手动清空窗口、重新介绍背景——这打断了心流。

所有人都在解决"怎么让上下文窗口更大"，但没人解决"怎么让上下文永远精简而相关"。

**为什么我们选择反潮流？**
大厂在做多 Agent、多窗口、多专家协作——但这解决的是"复杂任务拆解"问题，不是"持续对话记忆污染"问题。对于每天在电脑前工作 8 小时的知识工作者来说，我们需要的不是"10 个专家在不同窗口等你"，而是"一个懂你的伙伴一直在你身边，记得你说过的一切"。

**核心理念：应无所住，而生其心**
这句话来自《金刚经》，也是 Memora 的设计哲学：
- **无所住**：启动时上下文为空，不携带冗余历史，Token 消耗固定
- **生其心**：开口时相关记忆自然浮现，AI 永远知道你在说什么、你是谁

记忆系统的四步闭环：
1. **存储**：对话结束自动提取结构化记忆（profile/insight/work-projection/persona 等）
2. **衰减**：不常用记忆 score 逐渐降低，遗忘也是记忆的一部分
3. **召回**：下轮对话通过关键词+语义向量双通道召回相关记忆
4. **组装**：召回的记忆注入系统提示，上下文永远保持精简相关

**我们不做什么（边界清晰）**：
- 不做通用 Agent 平台（那是大厂的战场）
- 不做无限长上下文（那是算力竞赛，不是产品设计）
- 不做云端服务（隐私是底线）
- 不做多 Agent 协作（专注才能把一件事做到极致）

我们只做一件事：**让 AI 真正记住你，而且不打扰你**。

### 4. TRAE 实践过程

**本项目 100% 在 Trae IDE 中开发完成**。从项目架构设计、记忆内核编码、445 个测试用例编写，到交互式 Demo 原型的多轮迭代，全程使用 Trae 完成。

这不是"用 AI 生成了一个 Demo"——这是"用 Trae 作为开发环境，完成了一个有严谨架构设计、有完整测试覆盖、有产品思考的工程项目"。

**阶段一：项目扎根——用大树播种机建立工程规范**
基于 Memora 的设计哲学，在 Trae 中通过交互式引导完成：
- 13 份 ADR（Architecture Decision Record）决策记录，从运行时栈选型到存储层设计，每个决策都有追溯
- 项目 Rules 框架，确立了零依赖内核、三层架构、单 Agent 模型等硬约束
- 目录结构和命名规范，确保后续开发一致性

【截图位置：项目 .trae/rules/ 目录截图，展示 ADR 和规则文件】

**阶段二：记忆内核开发——445 个测试全通过**
在 Trae 中完成 Memora 核心库开发（纯 TypeScript，零 native 依赖）：
- **IMemoryStorage 接口抽象**：持久化层完全解耦，内核不依赖 better-sqlite3 等 native 模块，可嵌入任何宿主
- **InMemoryStorage 实现**：用于测试的内存存储，零 IO 速度快
- **记忆召回引擎**：关键词匹配 + 语义向量注入接口，支持双通道召回
- **记忆衰减机制**：启动时首次执行 + 每小时定时衰减，模拟人类遗忘曲线
- **事件系统**：TypedEventEmitter，6 种核心事件（memoryAdded/personaSwitched/decayCompleted 等）
- **LLM 适配层**：OpenAI 兼容协议，支持多 Provider 运行时切换
- **安全模块**：两级权限 + 路径白名单 + 输入输出护栏
- **精灵主动行为**：事件累积 + 上下文感知提示 + 冷却保护 + 静默模式

通过 Trae 的代码审查和重构能力，识别并修复了多个架构问题：
- 修正了记忆关系设计侵入 Memory 基类的问题，采用独立 sidecar 结构符合 ADR-004 记忆统一模型
- 完善了工具错误反思机制（10 种错误码 + 重试判断 + Reflection 循环）
- 增加了 chat() 并发锁超时保护（5 分钟自动释放）

最终测试结果：**445 个测试用例全部通过**，使用 Vitest + MSW Mock LLM，InMemoryStorage 零 IO。

**阶段三：Sprite 宿主与 Demo 迭代——从评审视角自我审查**
内核完成后，开始桌面宿主 Sprite 的设计和交互式 Demo 的开发。这一阶段在 Trae 中进行了多轮自我审查和迭代：
- 从评审视角发现问题：首页只罗列功能，没有差异化定位 → 增加"反潮流"对比表格

- 发现空状态引导不足 → 增加 5 个体验建议按钮，引导用户完整体验记忆闭环

### 5. 技术实现亮点（评审可能关心的细节）

**工程严谨性**：
- 13 份 ADR 决策记录，每个架构选择都有理由和约束
- 445 个自动化测试，核心逻辑覆盖率高
- 零 native 依赖内核，纯 TypeScript 编写，可移植性极强
- 分层架构清晰：agent/memory/persona/skill/llm/security/config/logging/utils 职责分明

**产品差异化**：
- 反潮流定位：大厂做多 Agent，我们做单 Agent 记忆闭环
- 记忆不是聊天记录：结构化提取、置信度评分、自然衰减、双通道召回，形成真正的记忆生命周期
- 三态交互设计：完整窗口/浮动图标/系统托盘，真正融入桌面工作流
- 默契度真实成长：基于记忆积累而非虚假数值

**隐私设计**：
- 上下文感知而非内容感知：只通过文件变化、窗口标题等元数据感知状态
- 四不原则：不监听键盘、不读剪贴板、不截屏、不监听网络
- 纯本地存储，数据不上云
