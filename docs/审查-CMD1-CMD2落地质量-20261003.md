## 一、🔴 P0：CMD-2 向模型上报了**与内核行为矛盾的 shell**（新引入的假事实）

这是本次审查最重的发现，**由 CMD-2 自己引入**。

| claim（代码说的） | evidence | conclusion |
| --- | --- | --- |
| 宿主上报 `shell: 'PowerShell'` | `environmentProvider.ts:81`：`process.platform === 'win32' ? 'PowerShell' : ...` | Windows 上无条件写死 PowerShell |
| 内核 `run_command` 实际派发 `cmd /c` | `skillScriptRunner.ts:360-363` `resolveShellCommand`：win32 → `{command:'cmd', args:['/c',...]}` | **与上报值不一致** |
| 工具描述也自认 `cmd /c` | `builtinTools.ts:807-809`「Windows 经 cmd /c，类 Unix 经 sh -c」 | 描述与上报互相矛盾 |

**为什么这是 P0 而非文案瑕疵**：
- `HostEnvironmentInfo.shell` 字段注释写「供模型避免跨平台命令误用」——**这正是它唯一的用途**。
- 模型据此写 PowerShell 语法（`&&`、`$env:`、`Select-Object`），而实际执行器是 `cmd` ⇒
  **每一次这样的命令都失败**。这是 CMD-2 想消灭的那类谎报（「对模型说了假话」）的**新变种**：
  CMD-1 消灭了「run_code 支持哪些语言」的假话，CMD-2 却往同一位置塞进了「shell 是什么」的假话。
- 与 §10.1 引用 mainstream 的立意直接冲突：Claude Code 上报的是**它自己实际用的那个 shell**，不是「集成终端默认那个」。

**正解（判据归位，不新造机制）**：
`shell` 字段的语义应收窄为「本会话命令执行器实际使用的 shell」，其值必须与内核 `resolveShellCommand` 同源。
两个可选形态：
- (a) 内核在 `AgentOptions` 注入面暴露一个「实际派发形态」的只读描述（内核已知真相，宿主零猜测）——但会新增公共接口面；
- (b) 宿主不猜：win32 侧直接上报 `cmd`（与 `resolveShellCommand` 一致），PowerShell 属「集成终端的事」，
  与本执行器无关 ⇒ 零新增接口、纯事实订正。

**推荐 (b)**：`resolveShellCommand` 已把「平台 → shell」收成单点纯函数，宿主只需镜像同一条映射，
并在两处（内核 `resolveShellCommand` / 宿主 `environmentProvider`）互相加注释互指，避免再次漂移。

## 二、🟡 P1：环境段缺 `cwd`，模型无法定位项目根

| claim | evidence | conclusion |
| --- | --- | --- |
| 方案 §10.1 立意：对齐 Claude Code「每轮注入 cwd 绝对路径 + git 分支 + 操作系统和 shell 类型」 | `assembler.ts:86-97` `buildEnvironmentContextBlock` | 只格式化 `os` / `shell` / `runtimes` **三字段** |
| cwd 全库零注入 | grep `assembler.ts` + `seed/*.ts` 命中 0（仅 `builtinTools` 描述里出现「相对项目根」这类**相对**表述） | 模型知道"相对项目根"，但**不知道项目根在哪** |

**用户可感知的后果**：
1. 模型写 `cd src && npm test` 这类命令时，`run_command` 的 `cwd` 参数缺省=项目根，
   `cd` 一旦执行就**不跨命令保留**（每次 spawn 都是新进程，`cwd` 参数是唯一续接手段）⇒
   模型不知道绝对路径就**无法在子目录执行**，只能全在根目录跑。
2. 报错信息里的绝对路径模型没见过 → 定位失败时容易编造路径。

**判定**：属**真实 UX 缺口**，但**不在本刀应做**——`cwd` 归宿主上报（内核零解析），
是 CMD-2 的自然延伸项而非本刀带伤。**登记为 CMD-2 剩余项**，不构成对已落地的指控。

## 八、方法论沉淀

1. **「消灭谎言」是一类，不是一处**。CMD-1 消灭了「支持哪些语言」的假话，CMD-2 立刻在同一位置
   造了「shell 是什么」的假话 ⇒ **审查谎报时必须按"谎报位点"扫全，不是按"已修的那条"验收**。
2. **新增 prompt 注入段必须做「三方对照」**：段内每个字段 ↔ 内核实际行为 ↔ 工具描述文案。
   三者任一不一致 = 假事实。本刀 shell 字段正是三者的三方矛盾。
   **推广判据**：凡「宿主上报给模型看」的事实，值必须与**内核实际执行路径**同源，
   上报的是「执行器用什么」而非「用户环境里有什么」。
3. **销项时把「未做项」和「已做项」写进同一个括号 = 折叠**。今天立的纪律，
   同一天自己违反了一次 ⇒ 说明**纪律需要落到"写台账时的固定检查动作"**，而不是"写下来"。
   本轮已把折叠处按「未做项独立成行」重写。
4. **守卫测试不能在测试里重算一份映射**。初版守卫写成 `platform === 'win32' ? 'cmd' : 'sh'`——
   这就是**复制第二份判据**：内核改映射而测试期望值不变 ⇒ 全绿而谎报已存在。
   正解 = 读真源文本提取（沿用 `toolNameMap` 双向闭合守卫的既有范式）。
