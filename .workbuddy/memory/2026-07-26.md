## 记忆面板 3 项 UI 修正（视觉语言 v2 收尾·续）

### 请求 1：健康度「AI 治理」取消折叠，直接展开
- 根因：原用 `<details class="health-llm-group">` 折叠，需点击展开。
- 改动：`index.html` 将 `<details>/<summary>` 改为 `.panel-section`+`.panel-section-head`（标题「AI 治理」）+ 内部 3 按钮（id `health-llm-dedup/-timeliness/-conflicts` 不变 → 绑定零改）；`health.css` 删除 `.health-llm-group`/`.health-llm-summary`/`::before` 等 details 专属规则，`.health-actions-llm` 精简为 `flex; flex-wrap:wrap; gap:var(--space-1-5)`（分隔改由 head 提供）。
- 结果：常驻展开，3 治理按钮可见即用。

### 请求 3：记忆面板首进空白（需切 rail 才显示）
- 根因：`PanelRouter.switchPanel('memories')` 仅加 `.active`+聚焦搜索框，**从不显式同步视图容器显隐**；若默认视图容器处于 hidden/加载态未清，首进即空白，需切 rail 触发 `switchView→showDisplayView` 才显示（数据已 `onAgentReadyCallback` 预加载，故非数据问题）。
- 改动：`memoryPanelManager.ts` 新增 `ensureActiveSectionVisible()`（依 `activeSection` 调 `showDisplayViewHelper` 或移除对应 bar 的 `.hidden`，对默认 list 已可见场景为无操作）；`panelRouter.ts` 在 `if(panel==='memories')` 分支聚焦后调 `host.activateMemoryPanelView()`；`memoryDelegations.ts` 接口+实现透传 `ensureActiveSectionVisible`。
- 质量门：typecheck 0 / `lint:css` 0 / 3 渲染器测试 72 passed（未 `build:electron`，按用户约定手动测试）。

### 请求 2：侧边栏导航点击后残留「提示小标」
- 定性（AskUserQuestion 澄清）：左侧栏每个入口点击后弹出的**导航名称气泡**（显示「对话/记忆/设定/剪贴板/设置」），非剪贴板红色 `nav-badge` 角标。
- 触发机制（第一性原理）：`.nav-btn::after { content: attr(data-tooltip); opacity:0 }` + `.nav-btn:hover::after { opacity:1 }`，**纯 hover 驱动，无 focus/active 规则**。点击后光标仍悬停按钮→`hover` 为真→气泡显示；移到别处（任意点击）才消失。CSS 无法区分「即将点击的 hover」与「点击后未移开的 hover」，故任何「保留气泡」的修法都会在每次点击闪现——与用户「不需要」诉求冲突。
- 修复：`sidebar.css` 删除 `.nav-btn::after` + `.nav-btn:hover::after` 整块（保留 `.nav-btn{position:relative}`，因 `.nav-badge` 角标绝对定位于它，误删会破坏剪贴板角标）；`index.html` 移除 6 个 `nav-btn` 的 `data-tooltip`（保留 `aria-label`/`aria-labelledby` 无障碍标签 + `#clipboard-nav-badge`）。
- 排除项（不误伤）：`.token-usage::after`（chat 输入区 token 拆解提示，`chat-messages-input.css` + `inputAreaManager.ts`）、`#graph-tooltip`（图谱 hover 提示）均为独立组件，用户未抱怨，保持不动。
- 质量门：`lint:css` 0 错误（exit 0）；无 TS 改动。
