## 暂停/恢复用户视角细节（2026-08-08 全链路核实）
- **点暂停**：按钮→播放图标 + 横幅「会话已暂停：用户主动暂停」；内核 stateMachine.pause + createCheckpoint()（角色/标准/目标/热记忆/计划快照）+ 持久化 + 连续暂停计数+1；**暂停期间发消息被拒**（agent.ts L384 configError「会话已暂停，无法接收新消息」→ SPRITE_STREAM_ERROR 渲染层报错）；**30 分钟超时**（PAUSE_TIMEOUT_MS=30min）后检查点被清理、恢复被拒。
- **点恢复**：按钮→暂停图标 + 横幅移除；内核 stateMachine.resume + 心跳刷新 + persistCheckpoint（status→running）；**无恢复协议**（不执行 warmRecall/契约重注入——热窗口在内存未丢，直接继续）。
- 正在流式输出时点暂停：不 abort 流（停止回答是 btn-stop 的职责），回答继续完成。
- 对抗式结论：暂停的「检查点」在当前 sprite 无消费方——断点续跑入口（RESTORE_CHECKPOINT）渲染层未接，重启后会话靠 resetSessionIfNeeded 的「当天 main 会话 restoreSession」恢复（与检查点无关）。暂停的实质价值（冻结输入+状态保留）对普通问答用户吸引力低。

## Finding A 澄清语义重定 + 超时自动择优续跑（2026-08-08 收尾后继，已实现并验证）
- **用户重定义 Finding A**：原「超时暂停按新会话续跑」是误读。正确语义= agent 主动询问（澄清暂停）超时未响应 → **直接继续，咨询问题择优决策，把本轮回答收敛完毕到结束**。两类暂停：① agent 询问（P4 needClarify）；② 用户手动查看/补充。手动不会超时（用户在场）。
- **对抗式核实关键事实**：`composer.ts` 两条澄清路径（resolveSlot / resolveStalledTaskSlot）推 `{slot, question}`，**不带 options** → "择优"在原系统无现成选项；但 `SYSTEM_DEFAULTS.role/standard/resource` 均非空（P3 兜底），`task` 在 clarify→chat 后延续 currentGoal 或取回答文本 → **只要回答非空，agent 不 re-pause，直接走 LLM 收敛本轮**。故超时解法=喂一段非空自动决策文本。
- **范围天然正确**：`needClarify` 仅由内核 agent 补全链卡住时发射（agent.ts pause('agent')）；用户手动暂停走 SESSION_PAUSE 不发 needClarify → 超时计时器自然只命中 agent 询问型，手动豁免。
- **实现（主进程 chatHandlers.ts）**：① 顶部 `export const CLARIFY_AUTO_RESOLVE_MS = 5*60*1000` + 模块级 `clarifyTimeout` 句柄；② `needClarify` 监听发送 IPC 后 `setTimeout` 武装计时器；③ 超时回调 `autoResolveClarify()`：有 `options` 取首选项、否则按 slot 生成中性自动决策文案（task=「沿用当前目标…超时自动继续」，其他=「由 Agent 自主决策（超时未响应，已自动继续）：<问题>」）→ 复用 `processEvent({type:'clarify', content:JSON.stringify(answers), delta:{}})` 注入；④ 计时器清除点两处（防御）：`SESSION_CLARIFY_ANSWER` handler 开头显式 `clearTimeout` + `sessionResumed` 监听（覆盖显式/手动/超时所有恢复路径）再清一次。
