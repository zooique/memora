## 暂停/恢复用户视角细节（2026-08-08 全链路核实）
- **点暂停**：按钮→播放图标 + 横幅「会话已暂停：用户主动暂停」；内核 stateMachine.pause + createCheckpoint()（角色/标准/目标/热记忆/计划快照）+ 持久化 + 连续暂停计数+1；**暂停期间发消息被拒**（agent.ts L384 configError「会话已暂停，无法接收新消息」→ SPRITE_STREAM_ERROR 渲染层报错）；**30 分钟超时**（PAUSE_TIMEOUT_MS=30min）后检查点被清理、恢复被拒。
- **点恢复**：按钮→暂停图标 + 横幅移除；内核 stateMachine.resume + 心跳刷新 + persistCheckpoint（status→running）；**无恢复协议**（不执行 warmRecall/契约重注入——热窗口在内存未丢，直接继续）。
- 正在流式输出时点暂停：不 abort 流（停止回答是 btn-stop 的职责），回答继续完成。
- 对抗式结论：暂停的「检查点」在当前 sprite 无消费方——断点续跑入口（RESTORE_CHECKPOINT）渲染层未接，重启后会话靠 resetSessionIfNeeded 的「当天 main 会话 restoreSession」恢复（与检查点无关）。暂停的实质价值（冻结输入+状态保留）对普通问答用户吸引力低。

## 任务表模型确认（2026-08-08 傍晚，用户设计细化）
- **任务表 = 以 loop 回合为单位的任务清单**：普通任务（单轮直接闭环，默认）/ 难度任务（单轮演化出 loop 任务表逐条推进）。渐进式：单轮问答是基础，loop 是渐进叠加；**任务可实时追加**（本轮发现更复杂 → 继续添加任务表条目）。简单轮无任务表 → 无暂停按钮（resumable 门控天然吻合）。
- **暂停/继续按钮落点 = 任务表上的「暂停点」**：用户可在尚未推进的任务前点击暂停（预约式），loop 推进到该任务时挂起；也可点击继续。
- **待定输入区 = 全局概念，双行为分支**（用户拍板）：RUNNING 输入 → 进待定区但**自动注入**（立即排队下一轮）；PAUSED 输入 → 留待定区（可自由增删编辑草稿），**点「继续」才提交注入**。待定区载体 = 输入框本身，差异仅在提交时机。
- **行为变更点**：当前 inputAreaManager paused 分支是"有输入→emitSendMessage→processEvent→auto-resume 注入"（阶段 0，0820d0ae）——需改为"PAUSED 发送=内容留待定（不触发 processEvent），点继续→resumeExecution(待定内容)"。须同步更新阶段 0 测试与文档。
- **方案文档重写**：`docs/方案-申请暂停模型落地-20260808.md` 融入任务表模型（§1 概念/§2 交互语义/§3 Phase1 任务表面板/§4 Phase2 回合折叠+预约暂停点 pauseBeforeStepId/§5 Phase3 策展/§6-8 验收风险执行）。预约暂停点 = checkpoint 增 `pauseBeforeStepId`，loop 迭代边界检查 getActiveStep 命中即挂起。
