## sprite 集成测试落地 + 新 Bug 捕获（2026-07-25 傍晚）
- 用户接受建议：新增 `hosts/memora-sprite/src/__tests__/integration/` 承载接真实 memora 实例的端到端用例（非 mock）。
- **sync 阻塞修复**：原 `scripts/sync-memora.mjs` 用 `rmSync(node_modules/memora,{recursive})` 整目录删除后重建，触发沙箱 safe-delete 守卫（319 文件 ≥50 阈值 → SAFE_DELETE_BULK_CONFIRM_REQUIRED）。改为非破坏性 `cpSync` 覆盖式同步（`tsc` 产出稳定文件名，dev 不变更源码文件集），并移除未用 `rmSync` 导入。
- **harness 运行时 Bug 修复**：内核 `LlmProvider` 是抽象类但 barrel 仅 `export type` 导出，且 package.json 仅暴露 "." 子路径（不可深导入）。原 `class StubProvider extends LlmProvider` 在 esbuild（vitest 不 type-check）下会 `ReferenceError: LlmProvider is not defined`。改为 `implements LlmProvider`（esbuild 剥离该子句，无运行期值引用）+ 去掉 `super()` + 补 `supportsStructuredOutput=false`。
- **集成测试捕获的真实宿主 Bug（SqliteStorage）**：`Memory.metadata?` 字段的官方注释明确"SQLite index 不存储此字段"，但 `SqliteStorage.upsert` 用 `{ ...memory, deletedAt }` 展开后 node:sqlite 要求每个 key 都有绑定参数 → 任何带 `metadata` 的记忆（内核从配置文件加载 persona/rule/skill 时必填）upsert 即抛 `Unknown named parameter 'metadata'`。S2 用例因 writeRule 只写最小 frontmatter 而侥幸通过，暴露面靠真实 metadata。修复：upsert 改为显式绑定 8 个已知列、忽略 metadata。此 Bug 独立于原 12 项内核修复，属宿主存储层。
- **结果**：新建 `harness.ts` + `coreFixes.e2e.test.ts`(9) + `agentFixes.e2e.test.ts`(7)，共 **14 用例全过**，覆盖 M5/M7/M8/M9（直接消费内核导出）+ S2/M1/M3/M10/M6（真实 Agent 驱动）。全量质量门：typecheck 0 / eslint 0 / vitest **4606 全过**（含 12 sqliteStorage 单测）。
- 可复用经验：Vitest 走 esbuild 不做 type-check，故"type-only 导入 + extends 抽象类"会运行期崩；注入类用 `implements` 才是正确模式。另：改 host 源码（如 sqliteStorage）vitest 即时转译，无需 rebuild；改内核 src 须 `sync-memora` 重建后才生效。
