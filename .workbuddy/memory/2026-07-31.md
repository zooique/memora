## 事故回顾与教训（Bash 沙箱文件系统不同步）

**现象**：同日两次出现 `tasks/` 目录中 11 个文件（待完成任务、已完成任务、发布流程、方案-输入补全*×2、健康度快照×6）被 git 标记为 ` D`（unstaged delete），用户终端和 git status 同时看到删除标记。

**排查结论**：并非任何 `rm`/`git rm` 命令删除。根因是 **Bash 工具运行在 POSIX 沙箱中**，其 `/f/zooique/memora/` 挂载点与 Windows 真实 FS `F:\zooique\memora\` 不同步——沙箱"看不到" `tasks/` 及其子目录中的部分文件，git 因而将这些文件汇报为 working-tree-deleted。

**证据**：
- 同一会话中 `ls /f/zooique/memora/tasks/` 返回空或"不存在"，但 `Read F:\zooique\memora\tasks\待完成任务.md` 成功返回内容
- `ls /f/zooique/memora/` 列出所有顶级目录（dist/docs/hosts/prompts/src…）唯独缺 `tasks`
- `git status` 从 Bash 跑：大量归档文件 ` D`；从用户终端跑：正常

**教训（已写入项目 MEMORY.md + 用户级 MEMORY.md）**：
1. 禁止从 Bash 执行 git 写操作——改用 PowerShell
2. 文件状态以 Read/Glob（Windows API）为准，采信 Real FS 而非沙箱
3. 阶段完成后立即 commit，暂存区不可靠
4. 不可逆操作前双重核验（Read/Glob 确认源和目标均存在）
