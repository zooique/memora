## 修复追溯 + TLS/CA 联合修复（08:17-08:36）

### 用户实测反馈（08:17 截图）
- 上轮 `package.json` 版本修复**未生效** —— 仍显示 `40.10.6`。
- 版本号放在帮助面板的"关于"分区——位置不可见，要求一并移到底部按钮排。
- 点击检查更新 → `fetch failed: unable to verify the first certificate`（企业代理 CA）。

### 根因 1：tsconfig rootDir 缺失导致 dist 输出路径错位
- `tsconfig.electron.json` 无 `rootDir`，TypeScript 推断 rootDir=src/，输出到 `dist-electron/src/electron/...`。
- 但 `package.json:6` 的 `main: "./dist-electron/electron/main.js"` 指向旧路径。
- 旧 dist 文件残留 → Electron 实际加载的是上次版本（含 `app.getVersion()`），新代码（含 `SPRITE_VERSION`）从未运行过。
- 修复：在 `tsconfig.electron.json` 添加 `"rootDir": "./src"`，让输出对齐 `dist-electron/electron/...`。

### 根因 2：企业代理 CA 不在 Node fetch 默认证书库
- 修复 A：`main.ts` 添加 `app.commandLine.appendSwitch('use-system-ca')`，让 main 进程的 Node fetch 使用系统证书库（含企业代理自签 CA）。
- 修复 B：`systemHandlers.ts` 错误分类增强：检测 `cause.message` 是否含 `unable to verify` / `certificate`，判定 TLS 错误；分三类（超时 / 网络 / 证书）给出精准提示 + 对应解决建议。

### 提交
- `4a876f55` fix(sprite): 修复版本号不显示+底部移位+TLS/CA代理认证（4 文件 32 +17）

### 可复用经验
- **TypeScript 输出路径配置**：`outDir` 设了但 `rootDir` 没设时，TypeScript 推断 rootDir 为最长的父目录，导致 `outDir` 包含 `src/` 前缀，与 `package.json:main` 期望路径错位。dev:watch 不会报警，dist 文件可能静默堆积在错误路径。诊断命令：`find dist-electron -name "*.js" | head` 对比 `package.json: main`。
- **Node.js TLS/CA**：原生 `fetch()` 默认只信任内置 Mozilla CA bundle，不信任 Windows 系统证书库。Electron 主进程若需要 HTTPS（如检查更新、调用企业 API），需 `use-system-ca` 开关让 Node.js 调用系统证书库。Chromium preload 不受影响（用 Chromium network stack）。
- **TLS 错误模式识别**：Node.js `fetch failed` 把错误包装为 `TypeError`，原始 `Error.cause.message` 才是真相（如 `unable to verify the first certificate`）。错误处理代码必须读 `cause`，否则只能分类为"网络错误"。
