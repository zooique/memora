## 1. 为什么「删除」不是正确动作（三条实证）

### 1.1 45/45 docs 全部 git 跟踪

无 untracked 过程产物 —— `docs/` 层是干净的（与 `tasks/` 混有 untracked 诊断文档的形态不同）。

> ⚠️ 复核过程中一度误判「45 个 docs 只有 29 个跟踪」——**虚警**：`git ls-files` 把中文名转成八进制转义（`"tasks/\345\276..."`），被 `.endsWith('.md')` 静默丢掉。改用 `-z` 重取后 **45/45**。

### 1.2 项目**已存在**「指针文档」归档形态（5 个实例）

| 文档 | 行数 | 失效缘由 |
| --- | --- | --- |
| `architecture/external-task-pause-resume-design.md` | 12 | 2026-09-04 整体废弃 |
| `architecture/memory-recall-recency-design.md` | 9 | 被 `memory-tool-recall-design.md` 取代 |
| `architecture/mvp-scope.md` | 9 | 落地已偏离，不作现行依据 |
| `architecture/novel-three-layer-design.md` | 10 | 内容已迁 `role-packs/共鸣小说家/` |
| `architecture/task-driven-closed-loop.md` | 14 | 2026-09-04 整体废弃 |

**共同结构（高度一致）**：

```
# <标题>
> **状态/废弃声明**（含日期与缘由）
> **现状真理源**：[新文档]（+ 代码落点）
## 历史说明
本文为 <什么> 的 <什么记录>，已随 <事件> 被 <新文档> 取代……
```

**含义**：这些文档**不是残留物，而是剪枝后的产物** —— 正文已移出（留在 git 历史），只留「曾有此设计 + 现状去哪找」的追溯指针。

→ **物理删除它们 = 主动切断追溯链**：后人不会去 git 历史里捞一份自己不知道存在过的设计。

> ⚠️ **我在本轮的自我纠正**：初判曾把 `novel-three-layer-design.md`（零入引用 + 内容已迁角色包）定为**强删除候选**。读完全文才看清：**它正是这个形态的第 6 个实例**，已合规。**若当时直接动手删，就破坏了一个既有约定。**

### 1.3 零入引用的 7 个文档，逐个核实无一符合删除条件

| 文档 | 行数 | 判定 | 依据 |
| --- | --- | --- | --- |

| `architecture/skills-tool-rag-exploration.md` | 70 | **保留** | 未实施的休眠设计（「技能规模未到阈值，不写代码」）——按 `exploration-decision-sedimentation-rules` S1，探索期文档**允许存在** |
| `qa-折叠块收敛-设计.md` | 128 | **保留** | 实施记录已迁台账 G31，但**§3.0「step = LLM+用户混合产物流」的设计决策无新家**；且它是「已实现」类（§3.2） |

## 2. 真问题 1 · 孤儿 SSOT（已修）

**事实**：

| 文档 | 行数 | 入引用 | 说明 |
| --- | --- | --- | --- |
| `docs/白话设计文档.md` | 246 | **8**（含 3 处 src 注释） | 按**链路**讲（第零步→第八步） |
| `docs/白话设计文档-模块篇.md` | 692 | **0** | 按**模块**讲（逐模块职责） |

搜索 `模块篇` 全仓 → **只命中它自己的标题行**。两份文档讲**同一套设计真相的两个视角**，却在仓库里**彼此不可达**。

**处置（已落地）**：建立双向引用，并在两侧写明同步约束。

- 主文档 L9：`> **分册**：… 见 白话设计文档-模块篇.md —— **两者是同一套设计真相的两个视角，改动一方须同步复核另一方**`
- 模块篇 L5：`> **与主文档的关系**：主文档 白话设计文档.md 按链路讲；本文按模块讲。**同一套设计真相的两个视角，改动一方须同步复核另一方**`

> 这是 `docs:links` 闸门的**结构性盲区**：闸门只校验「已写的链接是否可达」，**不校验「该有的链接是否缺失」**。本次是本轮第三次遇到「闸门有实现 ≠ 覆盖该类问题」。

## 3. 真问题 2 · 归档形态未成文（待拍板）

指针文档形态有 **5~6 个实例且形态高度一致**，但：

| 规则 | 管什么 | 是否覆盖本形态 |
| --- | --- | --- |
| `comment-doc-slimming-rules.md` | 注释与代码文档的减法（三分法 能删/压缩/必留） | ❌ 管 `.ts` 注释与「文档 vs 代码」分工 |
| `exploration-decision-sedimentation-rules.md` | ADR 何时诞生（S2 固化）+ 零消费 ADR 进僵尸档 | ❌ 管 ADR 生命周期，**不管失效 docs 文档如何处置** |
| `cross-document-reference.md` | 跨文档引用形式 | ❌ 管引用写法 |

→ **空白**。后果是**每次审查都要从零推演**（本轮即证：我先推出「零引用 → 删」，再被既有实例推翻）。

**待拍板**：是否补写该形态的规则条文（触发条件 / 最小结构 / 与 git 历史的分工）。

## 5. 判据的自我修正（本轮方法论增量）

两处判据**先跑出假阳性、再被修正**：

| 判据 | v1 结果 | 问题 | v2 修正后 |
| --- | --- | --- | --- |
| **入引用** | 按 `basename` 精确匹配 | 引用者常写「去扩展名」形式 → 15 个文档被低估 | 按 `basename` + `stem` 匹配：`work-projection.md` 2→23 · `memory-tool-recall-design.md` 5→20 · `tool-exposure-model.md` 4→11 |
| **文档级失效声明** | 全文正则 | **11 个全假阳性** —— 把内容里记录的「某字段已删除」当成了**文档自身**失效 | 收窄到元信息区（前 25 行）→ **2 个**（`host-plugin-alignment` / `memory-tool-recall-design`） |

外加一次**结构性假阳性**：md 表格体检首版未把**表格分隔行**当块边界 → 报 16 处异常**全是假阳性**，修正后 4 处（详见本轮表格体检）。

**归纳（本轮第三次同型）**：**自动判据只能分诊，结论必须人工实锤**。三次假阳性的共性 = 「判据取了一个**与语义无关的表面特征**」（首次出现行 / 关键词出现 / 竖线计数）。
