# memora 内核 · 生长点清单（新枝破土心智模型扫描）

> 扫描对象：`src/`（内核 `@zooique/memora` 5.0.0）
> 扫描口径：`.trae/skills/big-tree-grower` 的「新枝破土」模式——只取它的**发现缺口**子步，不落地、不写代码。
> 生成日期：2026-10-22
> 真相基线：5.0.0 终审（2026-10-19）= **GO ✅ 可发版**，内核代码已封顶，未结项全是触发制观察。

## 〇、先把话说在前头（对抗式审查，对请求本身的质疑）

1. **"5.0.0 发布前落地"不是开放工程工作量。** 内核 5.0.0 的全部实质性改动已 ✅ 落地，终审已判 GO。剩下的只是发版机械动作（npm publish / 打 tag / 双远端 push / 台账归档）。所以本清单里"发布前落地"那一栏 = **已落地、待发射**，不是待开发。
2. **记忆里"5.0.0 = 两 MCP 前置"已过时。** 实证：`MCP-SERVER-1` 已于 2026-10-19 封存作废；`D1-MCP` 仍挂观察区，升档条件是"宿主 0.1.0 发版 + 内核 5.0.0 落完后拍板"。它**不属** 5.0.0 落地项，已挪到"未来落地"。
3. **新枝破土本身是"直接实装、不写文档"的自动模式。** 本次只用它的"发现缺口"眼睛，清单产出正好是其"不产出文档"约束的反向——这是按你"整理清单"的显式要求执行的，不是模式原意。
4. **内核侧"数据已存在但没暴露给外层"这类缺口，已基本收敛。** `src/index.ts` 公开面收口很成熟（占用/标签/状态词表/存储工厂都导出了）。剩下的同类缺口几乎都是**宿主要不要消费**的决策（台账 D4：内核 API 存在 ≠ 宿主必须消费），不在"聚焦内核"的清单范围内。
5. **真正的内核生长点几乎都在"观察区"。** 这符合自然生长纪律（触发才升档）。强行把观察项塞进 5.0.0 才是预支复杂度（D6）——所以"未来落地"才是本清单的真实重量所在。

### 新枝破土三问（本次扫描的筛法）
- **A. 数据层已有、展示/外层未用**：内核算出了、存下了，但没接出去给人看/给宿主用。
- **B. 同类模式未覆盖**：某个模块有正确范式，另一模块却还在用旧的/漏的。
- **C. 操作流中断点**：流程在某个节点断掉、不对称、或静默丢东西。

## 一、5.0.0 发布前落地（已落地、待发版；终审 GO）

> 代码已封顶，用户装上 5.0.0 即可感知。每条标注它对应新枝破土三问里的哪一类。

### 1. 目标漂移自动暂停能力整体退役（GOAL-DRIFT-1）
- **大白话**：以前有个"发现目标跑偏就自动暂停"的能力，实测区分能力为零、暂停方向还倒错。直接把整个能力删了。
- **改了什么**：删 `updateGoal` 方法本体；它的"第二个暂停入口"物理消失。
- **用户感知**：少了一个会错误打断你的悬停能力；暂停只剩唯一一条正确通道。
- **缺口类型**：C（操作流中断点——多了一条错的暂停路径）。

### 2. 检查点减法（CHKPT-1/2/3）—— 顺带触发 5.0.0 major
- **大白话**：清理了三处"假装在干活"的僵尸代码：一个早已不读写的 schema 版本字段、两个名字叫"flush（落盘）"但其实只清内存垃圾的方法、一个无外部消费者的"脏标记"。
- **改了什么**：删 `flushNow`/`flushOnShutdown`（公开方法，删 = 编译期破坏 = **major**）+ `checkpointDirty` + `schemaVersion`。
- **用户感知**：无直接功能变化；但这是 4.0.0→5.0.0 升 major 的**真信号**（公开契约被改）。
- **缺口类型**：A（数据层僵尸，存在但无人消费）。

### 3. 上下文占用真实化（CTX-OCC-1）
- **大白话**：以前界面上那个"已用百分比"圆环会骗你——它把系统提示（任务表、情报区、反思提示等）偷偷算进"剩余"，让你以为还剩很多，其实早满了。
- **改了什么**：内核新增 `dynamicSystemTokens` 段，把消息[0]之外的全部系统注入都计入占用；宿主圆环从 5 段变 6 段（新增"动态注入"，标红）。
- **用户感知**：圆环数字变"实"了，快超窗时能真报警。
- **缺口类型**：A（数据已算出但展示层从不计入）。

### 4. 记忆召回可观测（MEM-EVENT-1）
- **大白话**：以前内核知道"本轮召回了哪些记忆"，但没告诉界面；现在把命中的记忆条目（标题/ID/来源）传出去，界面能展开"本轮参考了 N 条记忆"。
- **改了什么**：`memoryRecalled` 事件载荷加可选 `hits` 字段（数据真源是现成的搜索结果，零新增查询）；全链路（内核→宿主→webview→反馈）已通。
- **用户感知**：能看见 agent 到底"想起来"了什么，还能点开/反馈。
- **缺口类型**：A（数据已存在，未暴露给外层）。

### 5. 归档模式接线上（ARCH-GAP-1 / ARCH-GAP-2）
- **大白话**：以前承诺"可切换归档模式"，但切换动作半途而废（只暂存不补执行）；手动归档也根本没有入口。现在两处都接上了。
- **改了什么**：① `setArchiveMode` 对齐 `reloadConfig` 契约（忙时暂存 + 轮终补执行，不丢用户的最后表态）；② 手动归档嫁接到历史浮层"移入留存区"手势，并加了跨进程防重（重启 VS Code 也不会重复烧）。
- **用户感知**：切换归档模式真的生效了；手动归档"点一次烧一次、再点不重复烧"。
- **缺口类型**：C（操作流中断点——暂存后没补执行 / 有模式没入口）。

### 6. 技能脚本 / 内联代码 的工作目录对称化（SKILL-CWD-1 + run_code 同族）
- **大白话**：以前跑技能脚本、跑内联代码，工作目录会偷偷变成 VS Code 安装目录——脚本相对路径一写，就在"C:\Program Files\Microsoft VS Code\…"里建出 29 个文件。现在和"跑项目脚本"对齐，统一用项目根目录。
- **改了什么**：assembler 给 `run_skill_script` 注入 `projectPath`；`run_code` 的 execOptions 恒设 `cwd: projectPath`。四执行面 cwd 判据至此对称。
- **用户感知**：技能/代码不再越界污染安装目录。
- **缺口类型**：B（同类模式未覆盖——`run_project_script` 有 cwd 而另两个漏了）。

### 7. 搜索护栏可调 + 结果质量（GUARD-SEARCH-1 / SEARCH-QUALITY-1）
- **大白话**：以前"每轮最多搜几次"是内核写死的 6 次，你想调都调不了；而且搜回来的常是百度词条页、微博登录页这类废结果。现在次数能配，质量也修了。
- **改了什么**：① `webSearchLimit` 升为角色包策略键（和 `askLimit` 同构，宿主设置页自动出输入框）；② 加了搜索观测留痕；③ 识别"登录墙"页面不再把登录表单当正文；④ 修 Bing 解析器的标题/摘要错位（嫁接自家百度解析器的正确范式）。
- **用户感知**：角色作者能按场景调搜索预算；废结果（登录页/词条页）被拦或标注。
- **缺口类型**：B（模式未覆盖——`askLimit` 早已键化，`webSearchLimit` 却硬编码）+ A（结果质量无观测，补了留痕）。

### 8. ask 提问超时对齐 30 分钟（ASK-TIMEOUT-1）
- **大白话**：以前你被问一个问题，2 分钟不答就自动"继续"了——长文还没读完就被代选。现在改成 30 分钟，和确认框一致。
- **改了什么**：`ASK_TIMEOUT_MS` 120s→30min。注意：确认框超时是"自动拒绝"（fail-closed 安全），提问超时是"自动继续"——两个常量值巧合相同但语义相反，**刻意不合并**。
- **用户感知**：被问"细纲/文风要不要继续"这类长决策时，否决窗口变长了。
- **缺口类型**：C（操作流中断点——超时偏短丢否决窗）。

### 9. 术语门禁写手反馈环 + 台账销项同步闸门（TERM-FDBK-1 / LEDGER-RECEIPT-1）
- **大白话**：以前写文档/落地代码和台账销项不在同一批时，没有任何东西拦你——feature 提交了，台账还挂着"待排期"。现在加了两道闸：写手反馈秒级提示 + 提交时核对台账 ID 是否真的销项。
- **改了什么**：① 术语门禁写手反馈（含中文路径漏扫修复）；② `git` 提交前扫描台账 ID，代码落地但台账未销项就告警。
- **用户感知**：（开发者侧）台账和代码不会再悄悄脱节。
- **缺口类型**：C（操作流中断点——反馈环/销项不同批，无闸门）。

### 10. 公开面剪枝 / 降噪（PUB-API-PRUNE-5 / PROMPT-1 / 脚本安全 ADR-040）
- **大白话**：清掉了一批"挂着但没人用"的公开符号和过时提示；把脚本运行安全设计固化成 ADR（改即破坏契约的不可逆约束）。
- **改了什么**：砍 `canContinueWithoutInput`（零消费）；`PROMPT-1` 软提示与硬 nudge 判为分层非重复、保留；脚本安全设计补 ADR-040。
- **用户感知**：无直接功能变化；内核公开面更干净、契约更稳。
- **缺口类型**：A（公开面僵尸符号）+ 降噪。

## 二、未来落地（观察 / 暂缓 / 待拍板 —— 触发驱动，D6 不预支）

> 这些是内核真正的"待长新枝"。全部是触发制：没到触发条件就不动，到了再升档落地。强行现在做 = 预支复杂度。

### 存储切片：SQLite 落盘升级（C3 / D2·1 万条触发线）
- **大白话**：现在记忆库是单个 JSON 文件，实测 1 万条时加载已超 50ms、文件 2.8MB——这是台账里**唯一已实测越线**的条目。Node 24 已内置 `node:sqlite`，架构接缝（IMemoryStorage 等）早为它留好。
- **状态（2026-10-22 订正）**：**内核切片 + vscode 宿主接入已于 2026-10-16/17 落地**（git `2468be83`/`2053cc3b`，台账 line 1832/1836），JSON→.db 迁移与降级分档已就位；**仅 memora-mcp 宿主接入仍待触发**（§八 三启动触发未满足）。原台账观察条目已销项订正。

### 记忆治理层接线契约（MEM-GOV-1）
- **大白话**：内核记忆系统当前无架构级缺陷，但"接入第二信息源（persona/rule/skill）时，什么算一个 source、谁负责写、从哪激活"还没定案。现在没第二源需求，不动；将来接之前必须先补激活契约，否则就是第二个断链事故。

### 记忆召回触发式兜底（MEM-RECALL-2）
- **大白话**：现在记忆是"LLM 主动搜"模式（有实证，想起率 6/6）。但证据面窄——只在大模型上测过。换便宜/本地小模型时想起率可能塌方，届时没有兜底。修法不是改回"每轮自动注入"（那是否定一个有实证的设计），而是连续 N 轮没搜记忆时，注入一条中性提示"可能有相关记忆，可检索"。
- **红线**：不得改成"每轮自动注入记忆正文"。

### 异常收场证据回喂（EVID-FEED-1）
- **大白话**：空响应等异常收场的"证据"落盘了，但下一轮装配不消费——你重试说"继续"时，agent 面对空白上下文从零探索。接线是"检测到未消费的异常证据 → 注入中性系统摘要（中断位置/已做动作数/任务表进度）"。无真实复现前不动（D6）。

### 上下文窗口校验（CTX-WIN-1 / CTX-CLAMP-1）
- **大白话**：你若填个"100 万 token"的失真窗口，三处刹车（截断/软上限/压力预警）会同时被推后到失灵——因为全部基于失真前提算。根因不是"该加封顶"（内核不该假定 provider 窗口），而是"失真配置无校验/兜底"。ADR-029 已关闭"内核轻修 clamp"方向；待量化真实事故占比再拍板。

### 工具选择准确率可观测（R4）
- **大白话**：内核有 26 个独立工具，超业界 15–20 阈值。方向（Skill 优于 Agent）可信，但**无本地实测数据**。建议先补"选择准确率"的可观测（调用计数+命中率），把赌注变数据，再决定是否收窄工具面。缓解手段（L1/L2/L3 渐进披露、角色包裁剪）已在位，不是缺口。

### 暂停竞态 / 对称化（PAUSE-RACE-1 / PAUSE-RESUME-1）
- **大白话**：① 暂停申请在途时恰好超时，取消来不及撤销（竞态窗口）；② `resumeExecution` 对非 paused 态静默 return，和 error 分支不对称（可观测性缺口）。都是低风险对称化，触发=真实复现。

### 降级显式化 / 上下文 O(N²) / 隐式过期 / T4 step 落盘 / P-4 / K-1·K-2
- **大白话（打包）**：一批"正确但可优化/可显式"的潜伏项——
  - 降级分级现在是散在 catch 注释里的隐式策略，无真实事故不显式化；
  - 上下文每轮全量估算是 O(N²)（30 轮 17ms、120 轮 126ms），绝对值百毫秒级、不破坏，维持观察；
  - 隐式过期（TTL）无机制，已补显式论证，待真实反馈复评；
  - `checkpointRound` 写性能、loop.done chunk 带 planItemId、ISessionStore 改收 sessionId 等，均是"拆装互换非去债净减"，勿当小债重启。

### 记忆蒸馏 / 淘汰（P1-5b）/ 零主动记忆（P1-5c）
- **大白话**：现在 38 条记忆 100% 是自动摘要、用户零主动记忆。蒸馏（LLM 重写存量）= 破坏溯源；淘汰 = 不可逆删数据。38 条规模下造清理机制 = 杀鸡用牛刀。触发 = 库存破万条或"该想起没想起"的真实反馈。

### 本地档 / 环境类（OLL-1 / TEST-FLAKY-1 / TS-13）
- **大白话**：Ollama 本地运行时端到端实测（无环境阻塞，挂观察）；内核全量偶发 1 例 flaky（代码零改动结果漂移，抓身份即可，不拦发版）；中止信号残留收敛已落地、多次迭代未复现（仅记录）。

### 三大战略方向（来自 `docs/未来迭代方案-探索.md`）
- **方向 1 · 连接生态（MCP）**：`D1-MCP`——MCP 客户端全归宿主，内核只认"工具壳"（宿主经工具壳注册只读工具，不新增 `IDiagnosticsProvider` 之类接口，防双轨）。**现状：观察区，MCP-SERVER-1 已封存，不随 5.0.0 发。**
- **方向 2 · 可观测 / 评测**：把"预算归因 / 工具命中率 / 召回质量"做成可量化面板，先有测量再有优化（与 R4、SEARCH-QUALITY-1 观测留痕同源）。
- **方向 3 · 协同（真实多 agent 边界）**：当前单 Agent 定案（一项目一实例），跨重启恢复已退役。多 agent 协作是明确的产品层未来方向，非内核缺陷。

## 三、结论（一句话版）

**5.0.0 内核已封顶待发**：本次"发布前落地"栏里 10 组改动**全部已落地**，用新枝破土三问回看，它们正是"数据算出不暴露 / 模式漏覆盖 / 流程断点"三类缺口的已修案例。

**真正的内核新枝在未来**：存储切片、记忆治理接线、召回兜底、异常证据回喂、窗口校验、工具可观测、暂停对称化、MCP 生态——全部挂在观察区，等触发，不预支。

**你这次要的"清单"本身不落地**：我只做了 discovery 扫描与分类，未改 `src/`、未动台账 SSOT；本文件是唯一的产出物。
