## 二、逐项明细

### ① P1-1 占用快照漏计动态注入（🔴 用户可见误导）

**伤**：`ContextOccupancy` 原只算 rolePackBase + dialogue + inputAnchor + outputReserve。`messages[0]` 之外**全部** system 注入（最近对话块 / 情报区 / 任务表 / 软上限与压力提示 / 搜索收敛提示 / 反思与自审查提示）**不计入任何分段**，被静默算进 `free`。宿主圆环 `usedPct = (total − free)/total` ⇒ 偏小 ⇒ 用户以为"还剩很多空间"。且不实声明「各段真实用量拼满窗口」被**复制到宿主 `protocol.ts`**。

**落地**：
- 内核 `budget.ts`：`ContextOccupancy` + `EstimateOccupancyInput` 增 `dynamicSystemTokens`（**均必填**——漏填编译期即红，杜绝静默归零复现原伤）；`estimateOccupancy` 计入 `usedBeforeFree`；订正接口 JSDoc 声明。
- 内核 `loop.ts`：新增 `getDynamicSystemTokens()`（单一真理源 = `messages[0]` 之外 system 消息）；`refreshOccupancyDialogue` → `refreshOccupancyFromMessages`（同时刷 dialogue + dynamicSystem）；`appendSystemMessage` / `injectIntelNote` 触发刷新（system 注入即时反映）。
- 内核 `contextPreparer.ts`：接线 `dynamicSystemTokens` + 更新占用段 JSDoc。
- 宿主 `protocol.ts`：shape 同步 + 订正两处不实声明 + 增 N2 守卫指针注。
- 宿主 `chatPanel.ts`：历史会话重算显式传 `dynamicSystemTokens: 0`（无系统注入）。
- webview `chatView.ts` + `chatStyles.ts` + `tokens.ts`：构成条 5 段 → 6 段（新增"动态注入"）、hover 明细行、空态补字段、`--occ-dynamic` 令牌（`--vscode-charts-red`）。

### ② N1 协议注释与实现矛盾（文档漂移）

`protocol.ts` 原写 `dialogueTokens` = "最近轮次注入正文"，实现是 `loop.getConversationMessages()` = **全量** user+assistant ⇒ 订正为"**全量**问答闭环 token（非最近轮次）"。成本近零。

### ③ N2 占用契约跨包复制无守卫（🟡）

三处手写 shape 且零守卫（内核加/删段，宿主静默漏渲染）。**新增** `hosts/memora-vscode/src/shared/__tests__/occupancyContract.test.ts`：
- 沿 `protocolGuard.test.ts` 范式做**源码对账**（读真理源源码，不用复制品）；
- 内核 `ContextOccupancy` 字段集 与 宿主 `protocol.ts` occupancy 字段集**双向求差**，任一方向非空即红；
- **失效防护**：两集均须非空且含 `freeTokens`（防切片/正则失配双空假绿）；
- 大括号配对切片（锚点缺失/不配对**抛错**，非静默空集）。

**变异验证（红→绿）**：临时删除宿主 `protocol.ts` 的 `dynamicSystemTokens` ⇒ 用例红并精确报出 `[dynamicSystemTokens]` ⇒ 还原 ⇒ 绿。

**过程中自证**：守卫首版因 `extractBraceBlock('occupancy: {')` 未定位到 `{`（从令牌首字符切片）而误报 `[ccupancy]` ⇒ 已修为"开括号 = 令牌内 `{` 的位置"。

### ④ P2-4 截断超窗（🟡）

**伤**：截断产物 = `system + summary + keyMessages + placeholder + tail`。其中 summary（来自 `roundSummaryLoader`，最多 5 条已存摘要、**不受 `SUMMARY_MAX_TOKENS` 约束**）/ keyMessages / placeholder **均不计入 `availableTokens`** ⇒ 组装产物可能超 `maxContextTokens`（超窗 = 一次注定失败的 LLM 调用）。

**落地（观测 + 源头封顶，不改造结构）**：
- `truncateMessages`：组装后若 `estimateTokens(truncated) > maxContextTokens` ⇒ `logger.warn`（含 `summaryTokens`），**保持结构不变**。
- `getOrCreateSummary`：复用 `roundSummaryLoader` 产物时经 `capSummary` 按 `maxContextTokens × REUSED_SUMMARY_BUDGET_RATIO(0.2)` 封顶（保头部 + 省略标记）。
- **首版误判留痕（重要）**：初版实现为"丢弃 keyMessages/summary 的二次收敛"，实测破 `contextManager.test.ts` 的结构契约用例（`system→summary→keyMessages→placeholder→tail` 被锁定，5 red）⇒ 按「**改判据 = 造伤**」回退为"观测 + 源头封顶"。**结构契约是既有判据，不可为修 P2-4 而破。**

### ⑤ P1-2 `actualInputTokens` 有采集无消费者（🔴 观测断链）

**伤**：估算器纯启发式（3 字符/token、CJK 1.5），对代码/JSON 高密度文本**低估** ⇒ 截断判定"没超"而服务端实际超窗；而服务端实测 `actualInputTokens` 有采集有透出却**零消费者**。

**落地**：`llmCaller.callWithRetry` 每次调用比较估算（`contextManager.estimateTokens(safeMessages)`）与 usage 实测，比值 > `INPUT_TOKEN_DRIFT_ALERT_RATIO(1.5)` 即 `logger.warn`，并把 `inputTokenEstimateRatio` 写入 span（每次调用至多一次，防多 chunk 刷屏）。
**用例**：ratio=30 → span 记 `inputTokenEstimateRatio: 30`；ratio=1 → 仍记比值但阈值不触发。

## 四、⚠️ 环境坑留痕（非本次改动面，供后续复用）

宿主对 `@zooique/memora` 的依赖是 pnpm 本地依赖的**硬链接副本**：`hosts/memora-vscode/node_modules/.pnpm/@zooique+memora@file+..+../node_modules/@zooique/memora/`。硬链接**传播已存在文件的内容**，但**不会新增新文件**。

本轮宿主全量首轮 **32 文件 red**，全部是 `Error: Cannot find module .../dist/memory/supersedeResolve.js`（**导入期失败，非断言失败**）——根因 = 用户未提交 WIP（`src/memory/supersedeResolve.ts` 为 `??` 未跟踪，`gcService.ts` 已改 import），主 dist 有新文件、store 硬链接副本没有。补齐 4 个产物（`.js/.js.map/.d.ts/.d.ts.map`）到 store 副本后复跑即 **66/66 全绿**。

**结论**：宿主全量前须 `pnpm install`，或核对 `store 副本 dist 文件数 == 主 dist 文件数`。**判红前先区分"导入期模块解析失败"与"断言失败"**——前者与本次改动面无关。
