**手册 §十六 自 1196 行起，逐行镜像 `src/index.ts` 的 export 语句**（原文即 `export { escapeLike, escapeLikeSnippet, validateSource } from '@zooique/memora';`）。

**另**：原方案「零引用 ≠ 冗余」仍成立，但结论应**反向收窄**——不是「几乎都不能删」，而是「**能删的刚好是这批无实义承诺的通用工具**」。

## 2. 判定（四类）

### A 类 · 零引用 —— **空集**（无动作）

### B 类 · 重复入口 —— **1 项**

判据：同能力有规范入口，且 `index.ts` 注释**自证**该出口为「便利 / 非推荐」。

### C 类 · 通用工具泄漏 —— **11 项（主战场）**

判据（三条全中）：① 宿主 + 脚本零 import；② 非消费者须实现/命名的类型（是**函数 / 常量对象**）；③ 能力属**通用小工具**（字符串 / 对象 / 定时器 / 分词 / 转义 / 日志包装），**与 memora 领域**（Agent 编排 / 记忆 / 会话 / 角色包 / 安全裁决）**无关**。

> 判据演进的关键：这类符号**内核内部仍在调用**（如 `toError` 内部 96 处），所以**不是死代码、也不适用 no-op 直删豁免**——删的是**公开面那一行**（`index.ts` 导出行 + §十六 镜像行），**代码保留内部用**。

### D 类 · 契约词汇 —— **39 项，明确保留**

`interface` / `type`（`AgentOptions` `AgentContext` `ToolDefinition` `SessionCheckpoint` `IWebSearchProvider` `IFetchProvider` …）+ `ToolErrorCode`（内部 152 处）：外部消费者按名引用 / 实现接口必需，删除破坏契约。**不进入候选池。**

### E 类 · 保留但登记观察（16 项）—— 不删

宿主零消费、但属**领域实现 / README 实义承诺 / SSOT 锚点**：`InMemorySessionStore`、`createNodeSqliteStorage`、`loadConfig`、`NOOP_TRACER`、`LOCKManager`、`ProjectRegistry`、`MemoryGovernance`、`TypedEventEmitter`、`safeFetch`、`safeExecuteCode`、`safeSearchProjectFiles`、`safeSearchProjectText`、`isRetryableErrorCode`、**`AGENT_CONSTANTS`**（删前复核撤销）等。**无外部消费者证据前不删**（这类是各包不同 provider 的领域实现 / 命名锚，非重复）。

## 3. 最终清单 + 大白话（「是什么」/「为什么能删」）

| 符号 | 大白话：它是干什么的 | 今天谁在用 | 为什么能删 |
| --- | --- | --- | --- |
| **`createLlmProvider`** | 从整份配置文件里挑出「当前激活的 provider」再建实例 | 宿主零 import（宿主自建 provider 后调 `createProviderFromConfig`）；`scripts/test-*.ts` 5 个经**源路径** `../src/llm/factory.js` 用（不经包入口） | 同能力已有规范入口 `createProviderFromConfig`；内核注释自己写明「须经工厂校验后创建」——文档自认的**非推荐入口** |
| **`truncate`** | 字符串太长就截断加省略号（`slice(0,n)+'…'`） | 宿主零 import（宿主侧自带截断） | 通用字符串小工具，与 Agent 领域无关，宿主自持 |
| **`isPlainObject`** | 判断值是不是「普通对象」（非 null / 非数组） | 宿主零 import | 一行类型守卫，宿主要用自己写 |
| **`safeSetTimeout` / `safeSetInterval` / `clearSafeTimeout` / `clearSafeInterval`** | 包一层原生定时器，把 timer ID 记进一张表便于统一清理、防泄漏 | 宿主零 import | 通用定时器管理，与内存 / 会话 / Agent 无关；VS Code 宿主本有 disposable 机制 |
| **`segmentText`** | 调 `Intl.Segmenter` 做中英文分词（**原形**，不小写） | 宿主零 import（宿主只 import `segmentLower`） | 公开面该给宿主在用的 `segmentLower`；`segmentText` 由它内部调用，收回公共面即可 |
| **`escapeLike` / `escapeLikeSnippet`** | 把 `%`、`_` 转义，供拼 SQL `LIKE` 用 | 宿主零 import | 记忆层内部 SQL 转义细节，不是宿主契约——宿主根本不碰 SQL |
| **`serializeFrontmatter`** | 把对象写回 `--- … ---` YAML 头 | 宿主零 import（宿主只 import `parseFrontmatter`） | 宿主只**读**技能 / 角色文件的 frontmatter（读用 parse），从不写回，**写侧无人用** |

## 5. 处置机制（已选定路径）

这批项**非 no-op / 谎报**（内核内部真在用），**不适用**「no-op 直删豁免」。两条合法路径：

1. **严格守法 · DEPRECATE-1 三件套**：① 代码标 `@deprecated` ② `tasks/待完成任务.md` `DEPRECATE-1` 登记 ③ 守卫基线保留 → 下个 major（6.0.0）按单删符号 → 守卫红 → §3.2.1 定性 → 更新基线。**代价**：预警期一轮，见效慢。
2. **随下个 major 直接收面（历史先例）**：台账 `DEPRECATE-1` 已有多笔先例（restore 族 / compensate 族等）**于 5.0.0 直接删除**，理由 = 「5.0.0 未发（npm 最新 4.0.0）· 零外部破坏窗口」+ CHANGELOG Breaking 段告知。本批**风险更低**（通用工具非领域能力、§十六 仅镜像非实义承诺）。

> **已执行 = 路径 2**（2026-10-17，用户拍板「确认可以删除后直接删」）。**breaking 告知义务不变**：CHANGELOG `[5.0.0]` Breaking 段逐项列出。

## 6. 风险与边界（诚实登记）

1. **外部消费者不可观测**：本仓消费面只含 `hosts/` + `scripts/`；npm 真实依赖方不可见。删 = 对**不可见外部使用者**做 breaking。§1.3 已证 §十六 是镜像 —— 但它毕竟公开发布过（4.0.0 面），**不能当「无承诺」处理**，须走 CHANGELOG 告知。
2. **代码不删，只收面**：本清单符号内部仍在调用，删错即内核编译失败——**删前须确认该符号在 `src/`（非 index.ts）仍有内部 import**（脚本已核：`truncate` 19 · `isPlainObject` 25 · `safeSetTimeout` 32 等，均为内部真用）。
3. **`segmentText` / `serializeFrontmatter` 的「姊妹保留」**：各自保留 `segmentLower` / `parseFrontmatter`（宿主在用）——删一半需确认内部调用链不经公开面。
4. **守卫盲区**（引自 `publicMemberSurfaceGuard` 头注 + 本次实测）：守卫只管 `hosts/` + `scripts/`；**`src/__tests__` 内部测试经 `@/index.js` 的导入不在其扫描面**（本次 `llmIntegration.test.ts` 即此类，靠 `tsc` 拦）。本方案 §1 是一次性人工补盲，**不新增常驻守卫**（自然生长：同类复发再提抽象）。
