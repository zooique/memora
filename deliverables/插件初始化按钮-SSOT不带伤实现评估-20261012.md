# 插件「初始化按钮」SSOT 不带伤实现评估

> 日期：2026-10-12 ｜ 状态：**评估完成；4 项拍板已定（§7），待实现**
> 需求原文：插件宿主增加一个初始化按钮。一件清空插件宿主的所有用户级别存储信息，恢复到第一次使用插件的状态。项目级别的数据保留。

## 0. 结论先行

**可以做，且应当做。** 全部用户级存储面已实测盘点完毕（4 类存储、8 个 settings 键、4 个 globalState 键、2 个目录、1 类 SecretStorage 键），没有任何隐藏存储点。核心方案一句话：

> **清空清单不手写第二份，全部从现有真源派生**（globalState 按前缀枚举、settings 键从 package.json 声明派生、secret key 复用 providerStore 构造点）；**清理完成后必须 reload window**，否则只是清了数据、没回首装态。

四个拍板项已定（§7）。两个 P0 级坑（顺序、前缀过滤）见 §5，实现前必须读。~~三个 P0~~ 中的 K2（workspace 残留复活）经排雷已撤销，复盘见 §5-K2。

## 2. 实现方案（SSOT 落地）

### 2.1 新模块：`hosts/memora-vscode/src/extension/host/userDataReset.ts`

依赖注入（Memento / SecretStorage / 目录路径），纯逻辑可单测。四条清理通道，每条的真源依据：

| 通道 | 清法 | SSOT 依据（为什么不手写清单） |
|------|------|------------------------------|
| globalState | `keys()` 枚举 → 只留 `memora.` 前缀 → 逐个 `update(key, undefined)` | 前缀常量入 `shared/constants.ts`（现有 4 键全是该前缀）。**以后加新 globalState 键自动跟随**，零清单维护 |
| globalStorageUri | 删 `skills/` + `role-packs/` 两目录后重建空目录 | 目录名在 `extension.ts:226/238` 创建，两处常量共享 |
| settings.json | 键清单 = `package.json.contributes.configuration.properties` 派生 + 显式补 `backgroundProvider`（K7 缺口） | package.json 是配置声明真源；逐键 `update(key, undefined, Global)` |
| SecretStorage | **先**读 `providers` 拿全部 name → 逐条 `secrets.delete('memora.provider.{name}.apiKey')` → **然后**才清 configuration | key 构造必须复用 providerStore 的 `secretKey`（改为导出，不拼第二份字面量） |

### 2.2 顺序硬约束（K1）

SecretStorage **没有枚举 API**，key 只能按 name 构造，name 只在 configuration 里。
⇒ **必须先删 secret、后清 configuration**。反了 = name 丢失 = secret 成永久孤儿，用户换供应商后旧 key 仍躺在系统钥匙串里。这一条要有断言级测试锁死（mock 调用时序）。

### 2.3 重启是功能的组成部分，不是可选项

清落盘数据 ≠ 回首装态。已装配 agent 的内存态没有同步机制：

- `activeRolePack` / `rolePackTeams`：装配期读一次，之后 globalState 清了内存不跟着变
- `confirmWrites` / `confirmScripts`：`agent.security` 内存态
- SkillManager / RolePackManager 缓存：用户技能/角色包文件已加载进内存

（唯一会自动同步的是 `disabledSkills`——配置监听在，但不覆盖其余。）

⇒ 流程定为：**确认 → 清理（await 全部完成）→ 提示 → 自动 `workbench.action.reloadWindow`**。清理失败则不 reload、保留现场报错。若对话进行中，确认文案明示「将重载窗口，进行中的对话会中断」，不拒绝执行（用户主动要恢复首装态，busy 拒绝反而添堵；清理本身不碰 chatLock，无死锁风险）。

### 2.4 UI 挂载与消息（拍板：按钮放「安全」tab）

- 命令：`memora.resetUserData`（入 package.json `contributes.commands`，命令面板可达）
- 按钮：**设置面板「安全」tab**（拍板定位）。webview 落点 = `settingsView.ts` 的 `createSecurityView`（root `#security-root`，与写入审批/脚本执行两个确认开关同视图——「清空用户级安全偏好」与安全设置同 tab，语义自洽）
- webview → host 新增 1 条 IPC 消息（如 `reset_user_data`）。当前 IPC 111 条，+1 不触闸，但按 §7.6 规矩登记
- 确认形态：**host 侧 modal**（`showWarningMessage({ modal: true })`，对齐 `cleanupMemories` 既有模式）。webview 禁原生 confirm（`configView.ts:358` 实证），文案列明：将删除（用户技能、用户角色包、大模型配置与 API Key、角色选择、安全开关、用户级设置）/ 将保留（当前项目的记忆、会话、问答记录、项目设置——记忆与会话是项目的一部分）

### 2.5 批次拆分（独立可回滚）

1. `refactor(host)`：`providerStore.secretKey` 私有方法提为导出（SSOT 嫁接点，reset 复用）
2. `feat(host)`：`userDataReset.ts` + 单测（前缀过滤 / secret 先行 / 只清 Global target / 删除不越出 globalStorage）
3. `feat(host)`：命令注册 + 设置面板按钮 + IPC + package.json contributes
4. 台账登记 `tasks/待完成任务.md`（未发布件只进台账，不进 CHANGELOG）

## 4. 已识别并规避的既有 SSOT 缺口（不混修，仅登记）

- **K7 🟡** `memora.backgroundProvider` 被 `providerStore.ts` 写入但 **package.json 无声明**——reset 清单若只从 package.json 派生会漏掉它。处置：reset 清单显式补这一个键并注释指向缺口；补 package.json 声明作为独立小修另行提交（一锅炖会模糊批次边界）。

## 7. 拍板决议（2026-10-12 萧然定，4/4 已定）

3. **自动 reload window**：确认。清理完成后自动重载，确认文案预告「进行中的对话会中断」。
4. **不备份**：确认。「恢复首装态」语义与备份互斥，modal 列明删/留两份清单即可。
