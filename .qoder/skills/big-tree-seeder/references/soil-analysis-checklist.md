# 土壤分析检查清单

> 用于第 2 步"土壤分析"，帮助全面了解新项目的"土壤条件"。

> **什么是"土壤分析"**：搞清项目所处的环境和约束，为第 3 步项目适配和第 4 步 ADR 决策提供事实依据。不是技术方案、不是架构设计——只是描述"现状是什么"。

---

## 必问维度（6 项全部必问）

### 1. 项目类型

> **通用提问**："这个项目做什么类型的事？它产出什么？"

根据用户回答，理解项目的基本性质并记录。

### 2. 领域约束

> **通用提问**："这个领域有什么特殊规则或约束？"

引导用户思考本项目的专有约束（如特定规范要求、行业标准、平台限制等）。

### 3. 团队规模

| 选项    | 对后续决策的影响                 |
| ------- | -------------------------------- |
| 1-3 人  | 流程尽量简单，减少学习成本       |
| 4-10 人 | 需要更规范的分层和审查机制       |
| 10+ 人  | 需要严格的模块边界、完整的 CI/CD |

### 4. 目标受众/用户量

| 选项     | 对后续决策的影响       |
| -------- | ---------------------- |
| 小范围   | 精工细作，不追求规模   |
| 中等规模 | 需要考虑基本的结构优化 |
| 大规模   | 需要考虑分发/传播策略  |

### 5. 部署/分发方式

> **通用提问**："怎么交付给目标受众？"

根据项目类型理解交付方式（本地部署、云服务、平台发布等）。

### 6. 特殊约束

| 选项         | 对后续决策的影响           |
| ------------ | -------------------------- |
| 合规要求     | 可能需要额外的审计或脱敏   |
| 已有领域绑定 | 必须使用特定工具链/平台    |
| 时间限制     | 需要简化方案，优先核心功能 |
| 无特殊约束   | 自由选择                   |

---

## 两种播种模式对土壤分析的影响

**模式 A（从零开始）**：第 2 步土壤分析时，项目类型尚未确定。分析完通用 6 维度后，在第 3 步项目适配时确定项目类型，然后补充土壤分析报告。

**模式 B（已有项目接入）**：项目内容已存在。第 2 步土壤分析直接基于现有项目结构和内容，识别已有的约束和环境。

## 土壤分析报告模板

> **占位符约定**：`[xxx]` = 必填 | `{auto:xxx}` = AI 根据对话自动填充

```markdown

## 项目画像

- 项目名称：[项目名称]
- 项目类型：{auto:第1步判断的类型}
- 一句话描述：[用一句话说清楚这个项目做什么]

## 关键约束

- 团队规模：[人数]人
- 目标受众：[预估规模]
- 部署/分发方式：{auto:第1步选择}
- 特殊约束：{auto:第1步选择，无则为"无"}

## 项目决策的潜在影响

- [基于以上信息，分析对后续决策的关键影响]
- [例如：小团队 → 简化流程，减少规则文件数量]
- [例如：有合规要求 → 需要额外生成审计相关规则]

## 风险点

- [基于以上信息，识别潜在风险]
```
